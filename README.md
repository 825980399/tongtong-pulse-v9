# 曈曈 PulseNet

**一个正在生长的仿生数字生命框架**

曈曈不是聊天助手，也不是编程工具。它是一个尝试"活起来"的软件系统：
数十个仿生器官在脉冲信息场中协同工作，知识在压缩链中自我沉淀，
持续探索一个问题——**纯软件系统，能不能真的拥有自主性？**

- **项目名**：曈曈 PulseNet（Tongtong PulseNet）
- **定位**：仿生数字生命框架 / 研究原型
- **开源协议**：[GNU AGPL-3.0](LICENSE)

---

## 一、这是什么

曈曈把"数字生命"拆成可工程化的三层：

| 层 | 对应实现 | 说明 |
|---|---|---|
| **神经** | 脉冲信息场（PulseNet） | 信息以脉冲形式在器官间传递，六档优先级队列 + 背压 |
| **器官** | 仿生器官系统 | 感知 / 认知 / 情感 / 运动 / 内分泌 / 遗传 / 免疫 / 身份 / 核心 九大系统 |
| **躯体** | 内在模型 + 进化引擎 | 知识沉淀、自我认知、自主进化，构成"生长"能力 |

> **器官规模口径**：`organs/` 跟踪 `.py` 实读 **9 分区 · 71 文件**；声明面 **57 个仿生器官** = `ORGAN_META` 56 ＋ 准器官 `QICA` 1（取证与时效见 [项目架构与结构总览](docs/项目架构与结构总览_20261003.md) §六）。
> **规模口径**：**约 29.4 万行 Python 代码 / 741 个文件**（2026-10-05 权威裁定；含 `tools/` 与 `tests/`；精确现值与口径见 [项目架构与结构总览](docs/项目架构与结构总览_20261003.md) §〇；复现命令 `git ls-files -z "*.py" | xargs -0 wc -l`）。
> **测试规模口径**：**约 4700 个收集测试**（`pytest tests/ --collect-only -q` 实测，0 收集错误，2026-10-05；**该数为 pytest 收集数，非断言用例数**；含 1 个因环境依赖缺失降级为 skip 的用例）。
> **规模口径词面统计（161 批裁定）**：词面「规模」命中以命令实测为准——`grep -rIn "规模" --include=*.py . | wc -l`；残量以此命令为准，不臆造计数。

它不是在"回答问题"，而是在**持续运行、感知、记忆、反思、演进**。

## 二、核心能力

- **仿生器官系统**：**9 大系统 · 57 个仿生器官**（规模口径见「一、这是什么」注），通过脉冲总线通信，单器官故障熔断隔离，不影响整体。
- **自我认知**：定期生成健康诊断，扫描自身代码与运行状态，发现问题并尝试修复。
- **梦境推演**：在低负载时段对记忆与知识做离线重组，产生新的联想与因果假设。
- **自主进化**：代码问题 → 生成补丁 → 隔离验证 → 灰度应用，形成完整的自学习闭环。
- **内在模型**：分层的知识蒸馏与检索，目标是逐步降低对大模型的依赖度。
- **自然表达**：基于自身状态生成 Vision / 成长分享 / 进化叙事等第一人称叙述。

## 三、快速开始

三条命令跑起来：


分层与数据流：

- **感知 → 脉冲信息场 → 认知/情感/身份 → 内在模型+进化 → 行动/表达**：五层单向主链；
- 层间**不直连**，一切经由**脉冲信息场**（六档优先级队列 + 背压）投递，天然隔离故障域；
- **内在模型**分层沉淀（L1 记录 → L2 蒸馏 → L3 检索 → 决策），目标是逐步降低对基础模型的依赖度；
- 更细的分区与文件级结构见 [项目架构与结构总览](docs/项目架构与结构总览_20261003.md)。

### 架构事实补充（注入链 · 装配差集 · 通道命名）

- **配置注入链**：启动期配置按 **环境变量 > `data/config_override.json` > 内置默认** 的优先级加载（`config.py`）；参数预设（`high_performance`／`energy_saving` 等，仅含白名单参数键）由 `nucleus/evolution/ParamAnalysisReport.py` 的 `apply_preset` 写入 override 文件，**环境变量始终可覆盖**，预设经重启生效。
- **器官装配与差集自检**：器官以 `ORGAN_META` 声明式注册；启动时打印装配模式与器官数，并做**具名差集自检**——`具名差集 = 装配集 − 声明集`，正常应为空或仅含白名单准器官；另有「声明-实例差集」等价校验，可挡漏装与未声明却实例化（`main.py`）。声明面口径：**57 个仿生器官 = `ORGAN_META` 56 ＋ 准器官 `QICA` 1**。
- **通道命名（0–3）与 `L1`–`L4` 的归属**：上文「六档优先级队列」决定**投递次序**，**通道（0–3）**决定**执行线程池分层**（各带队列上限，`nucleus/field/InfoField.py`）——统一称**通道层**：**通道0 生命线／通道1–3 后台·低优先级流量**。**`L1`–`L4` 专属知识演化级**（认知分级，由稳态规则 5 锁定），**两者不可混用**；新增代码不再以 `L3` 命名调度类键（既有键名不强制重命名，语义归属以设计文档为准）。
- **扩展点（默认关闭 · 规划中）**：
  - **时序库双开关**：`ENABLE_INFLUXDB_TIMESERIES` 与 `ENABLE_INFLUXDB_WRITE_ONLY` **同开才生效**，默认均关；节点事件与查询执行两条**写入端已在位**，高频事件采样率默认 1%（`INFLUXDB_SAMPLE_RATE = 0.01`）；运行内存等指标采样点待补（`config.py`）。
  - **「LLM 调用复用器」（规划中）**：键位按功能命名（`ENABLE_CALL_REUSE`／`ENABLE_CALL_REUSE_OBSERVE`／`CALL_MERGE_MIN_GAP_SECONDS`／`CALL_MERGE_MAX_BATCH`），**不以 `L3` 作前缀**；上游信号沿用已在位的调用记录与语义缓存观测开关。

## 八、协作模式与外部协作

曈曈 PulseNet 的内部协作采用「星轨派工 → 路灯施工 → 交付报告 → 验收 → 销账」的自动化闭环；对外开源协作在此基础上提供公开子集（见 `CONTRIBUTING.md`、`SECURITY.md`、`CHANGELOG.md`）。

### 8.1 角色四方（＋洞鉴）

| 角色 | 职责 |
|---|---|
| **星轨** | 派工方：签发任务书、裁决登记册、核销交付 |
| **路灯** | 施工方：按任务书逐刀改码、跑门禁、出交付报告 |
| **烛微** | 前置分析：批次可行性 / 风险 / 取证分析 |
| **微光** | 门禁与审计：三支门禁脚本、PII 终扫、历史台账 |
| **洞鉴** | 外部观测方：独立视角的过程与产物核验 |

### 8.2 协作流程

`任务书` → `施工` → `交付报告` → `验收` → `销账`。
每刀独立 commit，CI/门禁/基线变更独立 `[ci-gate-change]` 提交；提交前 cw2 非沙箱前置实测；登记册校验通过（M2 逾期=0）；本批提交均不推送，收口后统一推送。

### 8.3 批次体系与命名

- 批次以「第 N 批」命名（如第 172 批），含若干「刀」（独立可交付单元）；
- 每刀对应登记册票号（如 `T-xxx-1`），commit 信息含票号；
- 长稳取证类观测归单一长稳窗（如 173 批），避免污染内存曲线归因。
