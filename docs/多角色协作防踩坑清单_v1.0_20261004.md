## 协作面红线（13 条）

> 【适用】标注：路=路灯（施工方）/ 烛=烛微（分析方）/ 微=微光（巡检方）/ 星=星轨（统筹方）。未标注=全员适用。

### 1. 他方在途文件：不碰、不 add、不 commit【全员】
- `git status --short` 中**首列为空（第二列 M/??）** = 工作区改动 = 他方在途（未暂存未提交）
- 看到非自己改动：**不修改、不 add、不 commit、不删**
- 需要等对方提交后再动；确认为遗留（如 `test_lazy_snapshot_m9.py` 长期 M，星轨 10-05 已裁定为「已定性遗留」）→ 报告星轨定性，不自行处理

### 2. 提交前必查工作树【路/星】
- 任何 commit 前先 `git status --short`：
  - 工作树含**他方 .py 在途** → 本批提交大概率撞红基线漂移/断链门禁 → **禁止提交**，等对方提交成功（红基线重锚）后再提
  - 工作树干净 → 按自己的提交纪律正常提交
- 星轨 10-04 教训：路灯施工期间提交 160 下文档 → 红基线/断链双重 FAIL 连败
- **烛/微不适用**（无提交权）；但烛微已转用为"转载前锚点复验"（§八⑪ 34 锚逐项复验）

### 3. 门禁失败：先分类，再行动【路/星】
- 收到门禁 FAIL **必须读完整输出**，分类：
  - **我引入**（CSV 格式/文档内容）→ 立即修，重提
  - **他方在途**（红基线 collect 漂移/断链上升——常因他人未提交的中间态代码）→ **停手等对方**，不重复提交
  - **基线漂移**（红基线过旧）→ 红基线重锚需**独立 commit**，不与被验收代码同批
- 禁止未复盘即重试（星轨 10-04 教训：失败后未分类又发第二批，二次踩雷）

### 4. 登记册 CSV：只由星轨写，任何人发现脏行立即报【全员】
- `docs/台账/待裁决登记册.csv` 是单一事实源 + 门禁校验对象（列宽必须==9，到期批次须整数）
- **只有星轨**可以追加/修改（python csv.writer，禁 Add-Content 拼串）
- 路灯/烛微/微光发现脏行（列数异常/非法状态词/内容错位）→ **不自行修复**，立即报告星轨
- 星轨 10-04 教训：英文逗号 `26,875` 破坏列宽 → 全库门禁否决 + 阻塞路灯提交

### 5. commit 错峰 + 后台 + 完成即报【路/星】
- 不与他人同时提交（避免 index.lock + 门禁排队）
- commit 一律后台执行，发起时说明"门禁约 15-18 分钟，完成即报"
- 等待期**并行做侧线工作**（读报告/写文档/整理清单），不空等、不反复轮询
- **烛/微不适用**（无提交权）；但交付/转载动作同样错峰（分析方写完即报 M 状态，统筹方不代提交）

### 6. 大文件读取：>100MB 一律流式分块；整读前确认框架停止【全员】
- **>100MB 一律流式（8MB 分块）**（微光 10-04 实测：500.92MB 快照 12.3s），只读方不再等施工方停框架
- **整读**（非流式）500MB 级快照/大日志前：先确认框架未运行（`tasklist` 查 python 主进程）
- 框架运行中仅允许**字节扫描/分块只读**，禁止整读挤压内存（曾致 PID 12440 内存压力）
- **第 12 条与本节同判据**，以本节为单点（v1.1 复核 F1 去重）

### 7. index.lock 判据（沿用路灯记忆）【路/星】
- 连遇 `index.lock`：先查 `tasklist | grep -c '^git.exe'` + `ls .git/index.lock` 时间
- **连续两次 git 进程数 = 0** 才算残留锁，才可删；进程间隙（时 0 时 2）是正常提交，**不删**
- PowerShell 等价式：`(Get-Process git -EA SilentlyContinue).Count`（v1.1 复核 F4 补）

### 8. 只读纪律边界【烛/微】
- 分析方全程只读：不改 `data/`、`logs/`、生产代码、不跑 `--apply/--fix/--rewrite`、不动框架
- 交付物落盘例外（分析报告/任务书/可写区）
- 临时验证探针：`tmp/`（`.gitignore:85`）**与** `.aionclaw-tmp\`（`.git/info/exclude:9`，微光 Q10 保留原名）**两条落点都合规（仅限 git 面）**；探针写盘以各自已声明目录为准
- **导出面补注（v1.1 复核微光提请）**：`.aionclaw-tmp\` **未被导出器排除（B-2）** → ①导出器须排除该目录（已入 161 段A A2 施工判据）；②**探针/证据文件用完即清**（授权后执行；烛微/微光不自行删，Q13）
- 分析方实跑**单文件测试**（星轨 10-05 裁决 Q1=A，**含烛微与微光**）：允许，上限=单文件+限时（默认 ≤120s）+ 抬头声明写盘守卫证据 + `data/`/`logs/` 零变更自证
  - **Q1 判据 v2（10-05 烛微三段落点复核，框架运行期"零变更"不可满足）**：框架运行中 `data/`+`logs/` 每 9 分钟约 38 文件被框架自身写入 → 目录级"零变更"无法把"我方跑次"与"框架写入"分离。替代判据二选一：**(a)** 单文件实跑只在**停框架窗**内做，跑前后对 `data/`+`logs/` 做（文件名+size+mtime）快照差集要求为空；**(b)** 框架在跑时改报「我方未新增 `data/evolution/test_runs/*` 条目 + 未新增任何非框架 cadence 命名的文件」，**不再报"data/logs 零变更"**

### 9. 交付即报 + 遗留声明【全员】
- 交付时明示：写入面清单（改了什么，按 mtime 窗口比对自证）、未动清单（谁的在途）、遗留待核（L 项）
- 星轨采信以交付物为准，不采信口头摘要
- **追加内容写完即报"M 状态 + 未定稿章节号"**（星轨 10-05 裁决 Q2=A：统筹方不代提交未定稿件）
- **数字口径**（v1.1 复核 F2 移入）：写用例数/指标数前先 `pytest --collect-only` 实测，标口径来源（星轨 10-05 纪律 6）

### 10. 行尾与编码纪律【全员写盘】★微光增补
- 写盘一律 `newline=''`；`.md/.txt/.json/.yaml/.yml`=**LF**、`.py/.pyi/.bat/.cmd/.ps1`=**CRLF**（`.gitattributes` 实测）
- 违反后果：94 批事故"checkout 静默改行尾"；微光本轮两次把 `.md` LF 翻成 CRLF（Python 默认换行翻译 + `csv.writer` RFC4180 CRLF）
- 发现 CRCRLF 双 CR 污染 → 门禁 [5] CRCRLF 会拦，立即修

### 11. PII 打码 + 产出物终检【全员写盘】★微光增补
- 自查脚本必须扫**自家交付物**（PII 规则：真名 `⟨真名-打码⟩`/生日 `⟨生日-占位⟩`/手机号 `187****36`/邮箱 `825***@qq.com`）
- 微光 161 初稿把 remote URL 真身标识未打码写进正文，被自检脚本抓到 → 教训：交付前自扫一次
- 数字口径已并入第 9 条（v1.1 复核 F2 拆分）

### 12. 大文件阈值量化【全员读取】★微光增补
- 与第 6 条同判据（v1.1 复核 F1 去重）：**>100MB 一律流式（8MB 块）**，以第 6 条为单点
- ≤100MB 常规读不受限；单文件测试 ≤120s

### 13. 删锁/删文件权限归属【全员】★微光增补
- `.git/index.lock` 与任何**删除权只归提交方**（路灯/星轨）；只读方（烛微/微光）**只报不删**
- 微光按 Q13 全程不删；烛微红线 1 只记录不碰；发现可疑文件只报告
