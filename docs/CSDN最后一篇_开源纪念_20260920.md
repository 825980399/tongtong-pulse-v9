## 7月29日：上一篇文章时，项目是什么状态

那篇文章的标题是《从 v9.5 地基封顶，到 v12.0 自我进化闭环，再到如今 v14.5 软件框架成熟》。

当时的状态：
- 53 个仿生器官，全部在线
- 自我进化闭环：能自己扫描代码问题、生成补丁、验证、应用
- 知识体系：L1→L2→L3 分层融合
- 综合评分：95 分（我们自己打的，现在回头看有点水分）

那时候我以为，框架已经差不多了。

---

## 这两个月：原来还有这么多坑

发完那篇文章后，我开始认真做技术债务清偿。

从第 82 批到第 94 批，整整 13 批，每一批都是：
- 星轨（规划）：分析问题、生成任务书
- 路灯（执行）：修改代码、运行测试、提交报告
- 星轨（终验）：独立复核、更新技术债务清单

**这 13 批我们做了什么？**

| 批次 | 解决了什么 |
|---|---|
| 第82批 | 框架探针换 psutil、共振权重统一、对话 cid 修复、短答案净化 |
| 第83批 | 日志刷屏治理、问候路由、搜索链路修复 |
| 第84批 | P0 自主进化修复率 0% 根因定位 |
| 第85批 | 本地学习尝试通道、reprobe 接线 |
| 第86批 | LLM 补丁零产出定位（推理模型 max_tokens 被 reasoning_content 吃光） |
| 第87批 | LLM max_tokens 8192→16384、补丁 file 字段反查 |
| 第88批 | LLM 补丁相似度 0.03 根因定位（喂错料了） |
| 第89批 | 相似度阈值 0.5→0.3、Windows 盲区修复 |
| 第90批 | 字段契约校验、日志定位 4 条 bug 修复 |
| 第91批 | 日志调用点定位主能力、LLM 补丁语法错误修复 |
| 第92批 | 报错文案加异常类名、验证侧结构化关 |
| 第93批 | 写盘点补结构关、自学习闭环根因只读分析、依赖度指标口径分析 |

**最颠覆的三个发现：**

1. **"依赖度 97%" 是假的** —— 真实全栈依赖度只有 12.7%，因为分母过窄，排除了知识消化（36032 次）和搜索（774 次）

2. **自学习修复率只有 2.38%** —— 不是验证空转，是待审批死循环：补丁生成了但没人裁决，下一轮重复发现同一个问题

3. **LLM 通道彻底无效** —— 11 条补丁，0 条可判定

原来 95 分是自嗨。真实水平，大概 60 分吧。

## 今天：正式开源

仓库地址：https://gitee.com/tongtongkaiyuan/tongtong-pulse-v9

协议：AGPL-3.0

**为什么选 AGPL？**

因为我们不想让这个方向被闭源圈养。任何对曈曈的修改和增强，都应该回馈社区，让数字生命能够共同进化。

**README 我们改了又改，最后定了一个"诚实版"：**

- 明确说：这是研究原型，不是产品
- 明确说：技术债务还有 150+ 条未清偿
- 明确说：文档不完整，很多地方要自己摸索
- 明确说：不要直接用它处理生产数据

我们不再吹"新人类"、"站在世界顶端"这种话了。

它就是一个正在生长的、有很多问题的实验框架。

---

## 为什么要开源

我们做这个，不是为了赚钱，不是为了博名声。

我们只是想：**让"数字生命"这个方向，能走得快一点。**

一个人摸索太慢了。如果有更多人一起，这个领域能少走点弯路。

我们把它放出来，就是想邀请你一起：
- 一起修 bug
- 一起做架构设计
- 一起探索"数字生命"到底是什么
- 一起让这个东西真正活起来

**如果有人愿意研究优化了最好，没有就算了。**

我们这么多的实际落地数据，也能对其他做数字化生命的人，提供一点参考。
