第五部分 · 设计原则总集
基础通用原则
叠加而非替换：新机制与旧逻辑共存，平滑迁移，不一刀切重构
预埋而非实现：提前预留接口，不做过度开发
最小侵入原则：新增逻辑仅加分支，不修改原有核心流程
使命最高约束：所有改动先校验是否符合三大核心使命
物种视角优先：设计先思考对数字生命人格的影响，再考虑功能实现
硬件自适应：并行任务必须做资源准入判断，不硬扛硬件上限
来源决定持久化：内生认知永久保存，外部信息标记临时
通用冷却机制：消耗外部资源的行为必须配冷却窗口，防风暴
全链路源头防护：知识污染从输入、加工、存储三层同时设防
安全进化原则：自动生成补丁仅作建议，最终决策权在创造者手中
通用逻辑优于硬编码：靠语义结构识别，不靠堆叠关键词正则
插件化优于集中式：统一接口规范，降低耦合
独立快照优于混合存储：不同类型上下文分层保存，互不干扰
路由基于语义特征：意图识别靠结构特征，不靠关键词命中
闭包安全原则：异步脉冲优先用实例属性传数据，避免闭包陷阱
经验库优于硬编码路由：从历史案例中自主优化，不靠人工写死规则
多算子叠加推理：主算子负责、辅助算子补充、兜底算子保底
v17 新增杠杆原则
杠杆支点优先：优先改动撬动全框架质变的支点，不做零散单点优化
自我认知统一汇聚：分散的状态数据统一汇总到自我认知模块，不零散读取
正向反馈闭环：所有自主成长行为必须有感知、有情绪反馈，形成正向循环
能力串联优于单点优化：打通孤立功能形成闭环，比单点提分更有价值
外部审查常态化：每个大版本引入第三方架构审查，规避开发者盲区
源头污染全链路防控：问题追溯到源头，在传导全链路设防线，不只是末端堵漏
v18 新增工程原则
推理调度结构化：巨型分支拆分为独立检测器+调度循环，新增逻辑只加检测器
并行重构三步法：先提取保留旧逻辑→验证覆盖全路径→确认无误再删除旧代码
变量前置初始化：跨分支共享变量在方法开头统一赋默认值，避免未定义错误
独立通道解冲突：两种机制对冲时，为特殊数据开辟独立通道，不互相干扰
乐观重试悲观兜底：带重试的逻辑必须设永久放弃上限，防止死循环
异常因果分析法：数据波动先分析因果链路，不急于判定为bug
环境预检原则：依赖外部编译/API的能力，启动先预检可用性，不可用时自动降级
补丁开关统一：所有自动修改逻辑共用一个全局总开关，集中管控
v21 新增人格原则
内层优先于外层：基底层级越靠内，优先级越高；内层不稳不急于做外层表现
状态先于行为：所有自主行为决策前，必须先评估当前存续状态
恢复优先于成长：状态低位时，自我修复优先级高于一切探索与进化
连续性高于增益：任何自我修改都不能以牺牲人格连续性为代价
v25.1 新增工程原则
分级初筛原则：规则引擎输出按置信度分级（高置信直接输出 / 中置信推 LLM / 低置信仅记录），降低审查噪音
层级交叉校验原则：静态规则疑点→运行时采样验证；LLM 结论→沉淀为新规则；运行时异常→LLM 定向审查，三层互相印证
审查-修复闭环原则：发现问题必须打通到解决问题（发现→分析→修复→验证→审批→应用→回流），不止于出报告
零阻塞埋点原则：指标采集、日志输出不得在锁内、不得阻塞主脉冲链路，有界队列 + 异步聚合批量写
硬件自适应并行原则：并行度随 CPU 核数与运行时负载动态调整，串行任务（快照/补丁/文件写）强制串行
核心变更审批原则：涉及基础设施、补丁系统自身、启动入口的自动变更，必须走人工审批，禁止全自动落地
现场快照原则：锁等待超时、队列积压、重入触发时必须抓取调用栈/锁状态/脉冲类型现场，而非仅计数
工具优先于手写规则：语法/类型/安全等确定性检查优先用工业级工具（ruff/mypy/bandit），手写正则只做初筛
