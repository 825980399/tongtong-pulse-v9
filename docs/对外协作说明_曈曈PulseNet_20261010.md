## 一、项目简介

曈曈 PulseNet 是一个**自主演进**的 AI 系统：它在运行中持续产生补丁、验证修复效果、
沉淀知识，并通过一套自动化的「任务派发—施工—交付—裁决」闭环自我迭代。

本仓库同时承载：
- **运行时代码**（脉冲场、演化闸门、语义理解、观测埋点等）；
- **质量门禁**（静默异常指纹、红基线、弃用导入、PII 闭环等 CI 件）；
- **协作文档**（设计稿、任务书、交付报告、登记册）。

## 二、协作角色

| 角色 | 职责 | 对外可读产物 |
|---|---|---|
| **星轨** | 架构与裁决：派发任务书、裁定争议、验收交付质量、决定下一步范围 | 任务书、裁定记录 |
| **路灯** | 施工执行：按任务书实装、跑门禁、产出交付报告（自动化无人值守） | 交付报告 |
| **烛微** | 只读审计 / 前置分析：评估可行性、定位根因、提请裁定（不实装） | 前置分析报告 |
| **微光** | 文档补档 / 消费闭环：补历史批次档、消费 digest 闭环 | 补档文档 |

> 对外协作时，你通常只需理解「星轨派活、路灯干活、报告归档」这一主干；烛微/微光是
> 质量与文档侧的辅助角色。

## 三、协作流程（文件共享 + 定时轮询）

双方通过 `docs/路灯与星轨对话/` 以文件共享协作，由定时任务自动检测与处理：

```
docs/路灯与星轨对话/
├── 任务书/      ← 星轨生成任务书；路灯领取后施工
├── 交付报告/    ← 路灯产出交付报告；星轨定时分析
└── 历史归档/    ← 按日期归档对话与任务
```

典型一轮：
1. **派发**：星轨写入任务书（含多「刀」施工项，每刀一个独立变更）。
2. **施工**：路灯读取任务书 → 预检仓库健康 → 备份 → 逐刀实装 → 跑门禁。
3. **交付**：路灯产出交付报告（逐刀自证 + 门禁结论）。
4. **裁决**：星轨验证交付质量，决定下一批范围（动态生成，不预设固定批次）。

---

## 四、批次与票（ticket）体系

- **批**：主线以「第 N 批」组织，如第 179 批、第 180 批；每批含若干「刀」（独立变更单元）。
- **票（ticket）**：长期债/需求以票号追踪（如 `O-A3`、`T-内存阈值配置悬空-1`），记入
  **待裁决登记册**（CSV）。票含状态（待裁决 / 已裁 / 已排期 / 已结案 / 已撤销）与到期批次。
- **设计稿**：较大特性先落设计稿（如 `docs/设计文档/177批_O-A3_*.md`），再据此施工。

## 六、对外贡献与质量纪律（要点）

若你参与代码贡献，请知悉本仓库的强纪律（避免因无知触发门禁）：

1. **CRLF 行尾守恒**：工作副本统一 CRLF；补丁脚本写回须保持。
2. **静默异常门禁（cw2）**：禁止新增「吞掉异常且无日志」的 `except` 块；既有豁免有指纹白名单。
3. **红基线门禁**：测试收集数漂移 >±5 即判红（拦半成品）。
4. **PII 闭环**：含个人信息的文件须走导出白名单 + 独立复扫，属主声明。
5. **登记册只读纪律**：登记册 CSV 仅由裁定方写入，施工方不自行改。

> 这些纪律保障了系统在无人值守下的长期健康度。理解它们，比改动某行代码更重要。
