### 维度3 · 压测设计（定义／SOP／指标／基线／观测点）
- **定义**：一圈 := 发现 → 入池 → 分诊 → 派单 → 执行 → 验证 → 沉淀（蒸馏＋applier）七段各留下**一条可 grep 留痕**且**至少一段产出非零**；"无人推" := 该圈**不含任何人工触发动作**（含重启、手动拍、改开关）。
- **SOP（六步，全用现成件）**：①在**隔离根**（`.bak_batchNNN`/`tmp/p3xx_root` 先例已有）或影子开关下跑，避免污染 `data/`；②把钩子节拍调为可配（G-1），**保留 `_HARD_CAP=1` 与 `max_blast_radius=1`**（吞吐靠圈数不靠单圈量，避免安全闸放宽被混进压测）；③固定基线快照（台账/池/待复核/覆盖率/`graph_file`）；④连跑 N 圈，逐圈记七段留痕与产出；⑤任何一段出现"需要人"（如 `requires_confirmation` 未被消费、WARNING、异常）即记一次"人推"；⑥压测结束出一份"每段自动化率＋人推次数＋产出率"。
- **指标（建议就 4 个，别多）**：`环节自动化率 = 自动完成段数/7`；`单圈耗时`；`圈/天`；`人推次数`（**必须为 0**）＋`产出率`（防 G-8）。
- **基线（本窗实测，可直接抄进 317 验收表）**：台账 84（approved 71／runtime_verified 13）、`pending_patches` 0、待复核 533、覆盖率 57.7%、图 `graph_20261019_181955.json`（nodes 6779／edges 7666／kind static 7414·byname 11·event 217·entry 24）、今日蒸馏 5 次（末次 21:27:27，200→2 条规则→应用 2 条）、growth 入库 18/20、重启后分诊 0 次、子进程 149 次（118 次零产出）。
- **观测点（现成，零新增）**：`[307刀1]`、`[308刀2]`、`[304刀4]`、`[309刀1] 存量高危回扫完成`、`[316刀2][蒸馏跨阈] status=… applied_organs=[…]`、`自动分诊池: 命中 N 条`、`[入队哨兵] 本周期 新补丁/被拦/M92/pending`、`[311刀2] 结构变化→重扫`。**需新增 2 个**：分诊触发计数（含钩子未到时的"未触发"显式留痕）与子进程产出率。
- **与掌握度断言（316 刀1）的关系**：A1（入度≥1）与 A4（覆盖一致）**适合当压测的"自检裁判"**——它们零新数据源、可自动判定；但**先修 G-6 的口径**，否则 A4 每圈都 failed，压测会被自己的尺子判死。
