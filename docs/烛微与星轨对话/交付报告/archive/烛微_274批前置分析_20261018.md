## §2 任务2 · 安全边界：NO_MESSAGE_TOOL 从"准入位"变成"真隔离"

### 2-1 它现在怎么生效的（一处，且只是准入）

`subagent_runner.py:194—199`：`if not ENABLE_SUBAGENT_NO_MESSAGE_TOOL: return refused`。⇒ **这个布尔位只决定"允不允许真起"，不决定"能不能发消息"**；worker 里没有任何 `Mouth/SPEAK/消息工具` 拦截实现（本窗 grep 空）。现阶段"够用"是因为 worker 不调模型、不发事件、不做额外 IO——**因为它无能，不是因为闸有效**。

### 2-2 接模型后保证"不发消息"的三层真隔离（三层都有现成件）

| 层 | 做法 | 现成件锚 | 状态 |
|---|---|---|---|
| L1 进程边界 | 子进程**天生拿不到父进程 EventBus/Mouth 单例**——只要 worker 不 import 器官链即成立 | `sandbox_limits.build_child_wrapper:244—300`（`allow_full_builtins`）；runner 现传 **True**（`:249`） | **抓手已在、未启用**：改为传受限 `allowed_builtins` 白名单（`:260/:511 DEFAULT_ALLOWED_BUILTINS` 已备好），并让 worker 的 import 面锁在 `stdlib + nucleus.reasoning.channel_client` |
| L2 出口白名单 | worker 只允许访问**本次解析出的那一个渠道 host**，其它一律拒 | `_resolve_cheap_model:133—154` 已把 `channel` 写进 input（含 `api_url`）⇒ 用它当唯一出站目标 | 需新写（小）；这是接模型后**新增的最大风险面**（凭证＋网络） |
| L3 能力面收缩 | 子代理返回只当**数据**处理：禁 exec/eval/import 副作用、结果只进 output_file，**不得由 worker 自己写节点池**（写盘由主进程在戊步做） | `worker:108—115` 只写 output_file（保持）；节点池写入在 `PulseCodeLearner:1826—1835` 主进程侧 | 现状已符合，接模型后必须守住这条边界 |

⇒ **另两条必须一起修的安全细节（本窗实锚）**：
- **凭证进临时文件**：`_resolve_cheap_model` 返回的 `channel` dict 字段含 `api_url`/`api_key`（`config.py` 渠道池结构字段名实测，本档不抄任何值），而 `:233—236` 把整个 `channel` 写进 `input_file`；且四个临时文件全用 `tempfile.mktemp`（`:226/:228/:230/:252`——**已知不安全 API，存在竞态**）⇒ 改 `NamedTemporaryFile(delete=False)`＋0600 权限＋用后必删＋**input 里只放 host/路径，密钥走进程环境继承或单独句柄**。
- **产物写盘无 fsync/清理**：`worker:108—115` 与 `DataAccessLayer:101—123` 同一类模式，本窗已见其后果（§0-2 全零文件）⇒ 补 fsync ＋ 读侧校验（键存在才认成功）＋ 失败保留 tmp 供取证。
- **Windows 资源防线仍未解**（271 §6⑥）：`sandbox_limits:196` win32 返回空串；接模型后风险从"资源占用"升级为"网络与凭证"，所以**Job Object 之外还要 L2 出口白名单**；两者不冲突，建议同期定案。

### 2-3 哪些够用、哪些要补（一张表）

| 边界 | 判定 |
|---|---|
| 预算控制（4000/次） | **够用**（271 实测 0% 超限），但它只挡"单次"，**不挡当日累计**（见 §3） |
| 超时（300s） | **够用**（单渠道历史 max 139.1s），前提是补上渠道健康度／轮询，否则坏首渠道直接吃满 300s |
