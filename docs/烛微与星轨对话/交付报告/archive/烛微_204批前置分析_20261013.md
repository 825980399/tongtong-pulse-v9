## §2 A类相位等价口径（结论：精确相位不可得，改建周期语义口径）

- **A类逐个实锚**（本窗 grep 全清单）：CodeLearner——`≤30拍热身+%50`（:349）、`%200`×2（:395/:414）；SelfAwareness——`%100+node_pool依赖`（:1036）、`%150`（:1052）、`%30`（:1066）、`%60`（:1086）、`%200`（:1098）、`%100`（:1121）。六值 **30/50/60/100/150/200 的 LCM=600 拍≈8,100s≈2.25h** 对齐巨周期（仅注释级观察，未见显式对齐需求）。
- **两个硬数学事实**：① `60s tick / 13.5s 拍 = 4.444 非整数比`——tick 无法整数倍模拟拍；② **拍间隔本身是负载自适应的**（心率随负荷浮动，13.5s 只是瞬时观测值）——**"整百拍"语义从来不是精确时刻，是"大致每 N×间隔"的周期近似**。
- **口径建议（三选一取①）**：① **时效闸主案**——A类件迁移目标语义="距上次执行 ≥ N×标称拍长 秒"（tick 驱动＋`last_run` 时效判定，TimeCore 托管任务现有 `interval` 字段天然承载），拍号降级为日志注记；② 拍号计数事件案（tick 内转发累计拍数近似）——受②自适应漂移困扰，复杂化不荐；③ 保持拍号不迁——零风险零收益。
- **例外不迁（相位真语义）**：`_jitter` 错峰与 warmup 型（`≤30拍热身` 是"起步期"语义，时效闸可近似但首拍定义漂移）——**热身件列 A类最后迁或不迁**。
- **顺序建议**：SelfAwareness 纯周期件（%60/%30/%150）→ %100/200 重件（含 node_pool 状态依赖——**双条件：时效闸＋状态谓词**，属书§2"需改造后迁"正身）→ CodeLearner 热身件缓迁。
- **风险**：迁移期双触发（旧拍号＋新时效并行窗）——按 203 窗灰度条款：每批一件＋≥1 自然日＋先迁日志后迁执行；**双写对照期必须显式互斥锁**（新件触发则旧闸跳过），防"家务执行两遍"。
