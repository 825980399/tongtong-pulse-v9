## 二、PyMuPDF 替代品功能评估（T-PyMuPDF开源合规-1，P1）

### 2.1 用途盘点（全仓检索 `fitz|PyMuPDF|pymupdf`）

**生产命中仅 1 个文件**：`organs/senses/visual_engines/pdf_engine.py`（66 行）。其实际能力面只有：

| 用到的 API | 行 | 语义 |
|---|---|---|
| `import fitz` | `:39`（函数内延迟 import，`:61 except ImportError` 有降级文案） | 可选依赖 |
| `fitz.open(file_path)` | `:41` | 打开文档 |
| `len(_doc)` / `_doc[i]` | `:43/:47` | 页数 + 取页 |
| `page.get_text()` | `:48` | **整页纯文本**（无版面/坐标/块级参数） |
| `_doc.close()` | `:52`（在 `finally`，关闭稳健） | 释放 |

调用方唯一：`organs/senses/PulseVisualCortex.py:526-535`（`task_type == "pdf"` 时转 `process(file_path)`，取 `text/pages/confidence/error`）。输出结构 `pdf_engine.py:36/:54-59`：有文本 `confidence=0.95`，无文本 → `error="PDF中未提取到文字内容"`。

### 2.2 任务书两个"重点评估项"的前提核对

| 重点项 | 实测 |
|---|---|
| 扫描件 OCR 前的图像提取 | **未实现**。PDF 与 OCR 是两条互不调用的独立任务类型：`PulseVisualCortex.py:401 if _task_type in ("ocr","pdf")` 只是分流放行；`ocr_engine.py:41/:87/:90` 只吃图像（`pytesseract.image_to_string`），**从不接 PDF**；`pdf_engine.py` 内无 `get_pixmap`/`get_images`/`extract_image`（检索 0 命中）⇒ 扫描件 PDF 目前直接落到"未提取到文字"错误分支 |
| 复杂版面文本抽取 | **未使用**。`:48` 是无参 `get_text()`，未用 `blocks/words/rawdict` 等版面模式，输出也无坐标 |

⇒ **这两项对替代评估不构成约束**；替代只需覆盖"按页取纯文本 + 页数"。

### 2.3 `pypdf`（BSD-3）逐场景对照

| 场景 | pypdf 支持度 | 理由 |
|---|---|---|
| 打开 / 页数 | ✅ 支持 | `PdfReader(path)`、`len(reader.pages)` |
| 按页取整页文本 | ✅ 支持 | `page.extract_text()` |
| 上限页数截断（`max_pages=10`） | ✅ 支持 | 与 `pdf_engine.py:43` 同一写法即可 |
| 文档关闭 | ✅ 语义等价 | pypdf 无需显式 close（现 `finally` 可留可删） |
| **CJK 复杂版面/子集字体** | ⚠️ **部分支持** | pypdf 依赖 PDF 内 `ToUnicode`/标准编码；缺表或自定义 CID 字体时中文可能出乱码或空串，PyMuPDF 在此类文档上更鲁棒 ⇒ **本项是唯一真实行为差异** |
| 页面渲染为图像 / 图像提取（扫描件 OCR 前置） | ❌ 不支持 | 官方能力面外；但见 §2.2——**本仓当前不依赖** |
| 版面坐标/块结构 | ❌ 不支持（仅基础） | 本仓不依赖 |

### 2.4 迁移成本

| 项 | 估算 |
|---|---|
| 改动文件 | **1**（`pdf_engine.py`）；另 `requirements.txt:42`（`PyMuPDF>=1.23.0` → `pypdf>=4.0.0` 区间，带上界）与 `:62` 提示文案 |
| 改动行数 | **约 10-14 行**（import、open、页取、`get_text()`→`extract_text()`、close） |
| 行为风险 | 中文复杂 PDF 抽取质量下降（§2.3 ⚠️ 项）；建议在 `:54-59` 增加"空/乱码文本 → 明确 error 并降 confidence"分支，别让 0.95 变成假信号 |
| 回归测试面 | `tests/test_visual_engine_contract_t153.py`（64 行）只测**契约形状**：`:34` 传不存在路径、`:45` `tempfile.mkstemp(suffix=".pdf/.tmp")`，文件内**不含 fitz、不读真实 PDF** ⇒ 替换后该测试仍会绿，**真实 PDF 抽取质量零覆盖**；若在意，需新增 1 个含中文的最小 PDF fixture（或明确记为"不覆盖"） |

### 2.5 结论建议（二选一，给倾向）

**建议 ①：整体替换为 `pypdf`。** 理由：AGPL-3.0 传染面只有 1 文件 2 API，替换成本 ≈1 人时，且被担心的两大场景本仓根本未实现，替换后不丢任何现有能力。
**风险与兜底**：若日后真要做扫描件 OCR 或版面抽取，届时以**专项票**评估 `pdfium2`（Apache-2.0/BSD 系）或 PyMuPDF 商业授权，而不是现在就为不存在的功能背上 AGPL 义务；若星轨选择"暂不替换"，则必须在开源 README/LICENSE-THIRD-PARTY 里**显式声明 PyMuPDF 的 AGPL-3.0 及其对分发物的传染范围**，并加一条许可证清单门禁（本仓已有 `tools/ci/` 惯例可挂）。
