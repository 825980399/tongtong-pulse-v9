## §2 五项建议（按杠杆排序）

### P0｜验证债由生产者计量——路灯是"入库未验"的唯一制造者，债却无账
- **现象**：自 222 落地后电窗未至，**六批生产行为全部待验**（wire 断言/补键/ISO 隔离/串味修复/甲档 31 点 runtime/226 新方向）；每新批继续叠加而交付报告不汇总这笔债。更深的病灶在认知层：**假孤儿的根因两日内翻了三次**（a/b 双解→环吞噬→双轨打点），每轮理论都跑在数据前面——因为都没有绑定"可测预言"。
- **建议两条**：①每份交付报告头部固定两行——"本批新增待验 N 项；累计 M 项，最早已滞留 X 天"，M>8 时在交付中明示"建议新批缓派先排验证窗"（与星轨件 P0 的 V 窗互为表里：星轨排窗，路灯量债）；②**凡交付给出根因结论，必须附一条可证伪预言**——洞鉴本轮"2s 窗内 ~21 事件≪200 槽"一击推翻环吞噬，是现成的方法论示范，制度化即可终结"理论换理论"的空转。

### P1｜"测试期生产面零写入"自查项——从口号升级为 checklist 一行
- **现象**：222 隔离验证在干净环境真调 tracer，flusher 把 **2 行夹具（OrganX/OrganY）写进当日生产 pairs 文件**，两批后追源时才被发现、手动清除（224 §四）——干净环境防的是 import 污染，防不了**路径解析污染**。路灯自己 216 批给巡检工具写了"测试零读生产文件"的好原则，却没回头约束自己的测试。
- **建议**：施工前检查表加一行——"触达运行时路径函数（tracer/flusher/metrics 写盘面）的测试，须先 patch `_ISO_BASE_DIR`（224 已建机制，同仓 LLMDependencyMetrics 先例更早）或 monkeypatch 路径函数"；已建机制未接线（测试还没用上它）列为 227+ 顺手项。

### P2｜工作树卫生终检——本窗刚漏一笔
- **现象**：门禁脚本回写 `pending_register_baseline.json` 的已知副作用，路灯前五批每批"git checkout 还原"，**16:59 与 17:12 两次现查该文件持续 dirty 未还**——在"星轨统一提交"模式下，路灯工作树就是交付面，脏基线会污染提交范围判读。
- **建议**：交付报告末行固定"工作树清点：`git status` 应仅含本批业务文件＋列明预期外残留及原因"（本笔即预期外，如实一行即可）。

### P3｜"不 commit 纪律冲突"申报五次同文——重复不是升级
- **现象**：215 起每份交付顶格申报同一句"纪律冲突（最高优先级）：书令我 not commit 违我双笔惯例"——服从正确、申报诚实，但**逐批复读等于问题从未被立案**。
- **建议**：转为常设议题（立账一次、后续仅引"议题 #N 未决"）；根治在星轨件 P4（门禁脚本改只读→路灯重获自提交），届时本条自动销案。

### P4｜备份与遗留物清理没有触发器
- **现象**：`.bak_batch199`→`.bak_batch208` 及更早共 **12+ 目录**（单批曾达 976 文件）全部写着"待验收窗后清理"，验收窗未至所以从未触发；更扎眼的是 **`.bak_batch207_DIRTY_PII_DELETE_ME`——自标 DELETE_ME 仍滞留至少二十批**，另有一个孤儿单文件 .bak 散落仓根。
- **建议**：三档清理策略——①带 DELETE_ME/PII 标注者**即批必清**（标注即结论，不该再排队；其内容含他人历史面，处置权归星轨/路灯，烛微只催不碰）；②常规 .bak 保留上限 2 批；③清理动作绑定 P0 的待验总账——验证窗收口一批、随脚清一批。

### P5｜书模板数字回写已成半例，补最后一寸
- **现象**：书内"CI 门禁全链"段常载模板预估（221/223 书"受影响测试 223/3367 节点"，实测 10/200 与 26/356，偏差最高约 33 倍）；路灯交付时已会加注纠正（好习惯），但书本体未回改，下游读者（含派书者自己）仍会撞上。
- **建议**：交付时在书原件该节补一行"预估·实测如下"注记（勘误式），与星轨件 P2"门禁规划"更名互为表里——星轨改模板，路灯做回写。
