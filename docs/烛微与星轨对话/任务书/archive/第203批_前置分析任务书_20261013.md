## 分析范围

### 1. 纯计时轮询件盘点
**目标**：找出所有"每拍线性扫描定时任务表"的纯计时轮询件。

**已知锚点**：
- `organs/body/PulseHeart.py:493-511, 708-840`：`_check_scheduled_tasks`每拍线性扫描21个定时任务表
- `nucleus/chronos/TimeCore.py:25,43,96-119`：每60s广播time.tick并触发托管任务
- `SurvivalOrchestrator.py:189-195`：on_heartbeat每5拍触发

**需要烛微分析**：
1. 全仓还有哪些纯计时轮询件？（不只是PulseHeart，还有其他器官/核的定时任务）
2. 每个轮询件的触发频率是多少？（每拍/每5拍/每60s/每天）
3. 每个轮询件扫描的任务数量是多少？（1个/21个/更多）
4. 这些任务的依赖关系是什么？（是否互相依赖？是否依赖其他器官的状态？）

### 2. 事件驱动迁移可行性评估
**目标**：评估每个纯计时轮询件迁移成事件驱动的可行性。

**需要烛微分析**：
1. **哪些任务可以直接迁移**？（比如：只依赖时间触发、不依赖其他状态的任务）
2. **哪些任务需要改造**？（比如：依赖其他器官状态的任务，需要先改成事件驱动）
3. **哪些任务不能迁移**？（比如：必须定时扫描的任务，比如内存清理/GC）
4. **迁移的风险是什么**？（比如：事件丢失、时序错乱、竞争条件）

### 3. 迁移优先级排序
**目标**：给出迁移优先级排序建议。

**需要烛微分析**：
1. **P0（高价值低风险）**：哪些任务可以先迁？（比如：只依赖时间触发、不依赖其他状态的任务）

3. **P2（低价值高风险）**：哪些任务暂不迁移？
4. **迁移的顺序建议**：先迁哪个后迁哪个？为什么？

### 4. 迁移方案设计
**目标**：给出迁移的技术方案建议。

**需要烛微分析**：
