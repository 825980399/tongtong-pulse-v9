## 二、任务一　全量开关穷举与台账建立（P0，核心）

### 1. 扫描口径（一条不漏，三类形态全覆盖）
- **顶层布尔**：`NAME = True/False`（T0 已粗扫 312 条，逐条复核行号与默认值）；
- **环境变量包裹**：`os.environ.get("X", "False")` 后接 `.lower()=="true"/in ("1","true")` 等字符串比较，以及 `bool(os.environ.get(...))` 形态；登记环境变量名、默认值、覆盖语义；
- **函数/类体内局部开关**：器官或模块函数内定义、带默认参数的布尔开关；只登记「影响生产行为」者，测试内局部开关不列；
- **重复定义**：同名常量在 config.py 内多次赋值的，标明行号顺序与最终生效值（后定义覆盖前定义）；
- **开关型阈值对照**：默认 0 / 空串 / None 等效关闭的阈值或额度，单列线索表，不展开开启建议（施工归在册对应条目）。

### 2. 每条开关台账字段（机读 JSON + 报告表格双份）

| 字段 | 要求 |
|---|---|
| 开关名 | 常量名，大小写照抄源码 |
| config 行号 | 开工 T0 实测 HEAD 行号；漂移允许标注「行号漂移」 |
| 默认值 | True / False；环境变量覆盖默认值一并记录 |
| 环境变量名 | 无则填「无」 |
| 所属功能面 | 内存/快照/渠道付费/子代理/知识图谱/审计观测/并发线程/存储后端/日志脱敏/安全闸/其他，可多选 |
| 接线证据 | 生产面引用点 `文件:行号`（import 处、判断分支、调用点）；区分「实装接线在位」「仅定义无消费」「接线半成品」 |
| 决策留痕 | git log / 既往任务书 / 裁决件 / config 注释 / 共窗验证记录；查不到留痕写「无留痕」，禁止编日期与批次 |
| 现状影响面 | 关闭时该功能是完全不执行 / 走兜底分支 / 仅缺观测；附日志或运行态佐证（可读 HEAD 代码推断，不下活体结论） |
| 开启风险面 | 资源增长 / 行为变更 / 兼容性 / 依赖缺失 / 事故面（心跳冻结、写盘、起进程、网络），逐条说明 |
| 分类 | **A 应开未开** / **B 合理关闭** / **C 待复核**（口径见下） |
| 建议 | 开启 / 维持关闭 / 先接线再开启 / 转 shadow 观察窗 / 转长期项 / 补决策留痕归档 |
| 严重度 | P0/P1/P2/P3（判据见下） |
| 状态标注 | 静态接线已核实 / 需活体实测 / 需外部环境具备（三态如实，不提前宣称闭环） |

### 3. 分类口径
- **A 应开未开**：代码实装接线在位、活体功能需要、关闭导致功能空转 / 观测缺失 / 安全兜底缺失，且开启风险可控、依赖环境已具备；须同时给出「接线在位证据」与「开启后回归面」。
- **B 合理关闭**：硬件强制（如 faiss-cpu 不支持 GPU）、外部依赖实例缺失（Neo4j/InfluxDB/分布式）、历史决策有意关闭且留痕可溯、共窗验证后有意翻回、生产安全闸默认关闭合理（须人工同意类）；逐条补齐留痕，无留痕的降级转 C。
- **C 待复核**：证据不足——接线半成品、依赖条件临界、注释与代码不一致、shadow 与正式开关口径不清；给出复核路径（先补接线 / 先跑 shadow 窗 / 先确认外部依赖），不直接建议开启。

### 4. 严重度判据
- **P0**：安全兜底 / 付费止血 / 数据一致性关键开关关闭，且接线在位、风险可控；
- **P1**：关键观测链缺失、慢性功能空转、内存/资源治理手段未启用；
- **P2**：体验/效率/口径/冗余开关；
- **P3**：文档、注释、历史遗留可归档项。
