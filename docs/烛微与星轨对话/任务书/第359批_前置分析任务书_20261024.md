## 二、分析任务（四问＋一建议）

### 问1（P0）21条 pass-only 逐条定性
- 逐条给出：**位置、捕获的异常类型、所处路径（写盘/IO/状态机/并发锁/网络/探针/清理/测试工具）、静默后果、处置建议**
- 三档分类：
  - **A 必须留痕**（故障被掩盖，如 logger.py:664 截断、PatchManager 写盘、ReasoningWorkerPool 并发、DataAccessLayer 数据访问）→ 建议改 `silent_exc(..., level=...)` 或具体异常类型收窄
  - **B 可降级留痕**（debug 级即可，不必 warning）
  - **C 合理静默**（如纯清理路径、CI 工具自身的预期异常）→ 保留但建议加注释说明"为何静默"
- **判据要显式给出**（什么路径必须 warning、什么可以 debug、什么可以 pass），供后续门禁指纹化复用

### 问2（P1）45条"静默 return 默认值"
- 重点：调用方拿到 None/False/[] 时能否区分"真没有数据"与"异常被吞"？是否存在"故障伪装成空结果"导致上层误判（如语义层 VectorStore/VectorEncoder 静默返None→上层以为无召回；write_guard 静默返默认值→写保护失效）
- 输出：A 必须留痕清单 / B 合理降级清单（每条理由）

### 问3（P1）112条"静默 continue/break"
- 重点：**数据条目静默丢失**风险——池消费/对账/回灌/批量处理循环中跳过一条，该条目是否永远不再被处理（如 audit_problem_pool_consumer:163、audit_problem_pool:712/1268 这类闭环路径）
- 输出：A 必须计数+留痕（跳过量可观测）/ B 合理跳过清单
- 与 self_inspector 大批量 continue 区分：自检扫描类的跳过通常合理，闭环数据处理类的跳过通常危险

### 问4（P1）ci-gate 白名单42条复核＋门禁扩展建议
- 42条豁免逐条：仍合理 / 已过期可销账 / 理由不充分
- 门禁指纹化扩展建议：当前 cw2 主要认 pass-only，**是否应把"return 默认值""continue/break 静默"两类纳入指纹**（给出可落地的 AST 判据草案，避免误伤合理降级）
- 评估误伤面：若纳管，45+112 中预计多少进豁免、多少必须改，给路灯的施工量预估

### 问5（P2）与356刀12的边界划分
- logger.py 6条中，刀12（356批）已修轮转相关（:664 截断兜底+告警、风暴防护、树外bridge）；其余条目（:584/:595/:602/:614/:620 等）是否与刀12重叠，**重叠的不重复排施工**，未覆盖的给清单
