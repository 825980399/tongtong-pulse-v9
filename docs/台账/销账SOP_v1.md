# 销账 SOP v1（第120批成文）

> 成文：路灯　｜　审计：烛微　｜　批准：星轨
> 生效：2026-09-24　｜　适用：曈曈 PulseNet 技术债务台账（`docs/分析报告/技术债务台账_代码实查_20260919.csv`）
> 配套：`tools/check_debt_ledger.py`（双轨计数机检）、MD §1.2（同源四数）、本 SOP 与工具 classify 口径必须一致

## 1. 三态判定规则

债务票生命周期严格四态推进，**不可逆回退**（除非 §4 合规回退）：

```
未动/施工中  →  码级已清(批号)  →  runtime已验(R4/MM-DD)  →  已清
```

- **未动/施工中**：代码层无修复证据，或修复在开发中。计「开放」（诚实口径）。
- **码级已清(批号)**：静态/单元证据达清（如 `py_compile`、单测、AST 判据），引用批次号（如 `T-117a`）。**不算已清**——仅表示"码级层面可清"，待 runtime 判据。
  - 关键陷阱（第120批 T-120c 修复）：`码级已清` 含 `已清` 二字子串，旧 `classify` 会误判为清。**修正口径：码级已清 必须叠加 `runtime已验✅` 才算清**，否则诚实计开放。
- **runtime已验(R4/MM-DD)**：进化框架在 R4 重启后实际跑通对应判据（如心跳对账过 N 拍、冲突降为 0）。标注 R4 日期。
- **已清**：runtime 判据稳定通过 + 星轨批准销批。终态。

判定优先级（与 `check_debt_ledger.classify` 一致）：**销 > 清 > 开**。

## 2. 旁路状态

非主线生命周期状态，独立计数不污染两轨分母：

- **回炉**：已清票因新证据需重判，退回码级已清/开放。须在「最后对账」列记回炉原因 + B 号。
- **注销**：非债（如 `HOT_COLD_LOAD` 保护 D190）、重复票、误录票。记「注销(非债)·第N批」。
- **无样本**：判据物理不可达或观察窗不足（见 §6）。**禁判失败、禁判通过**，计开放。终判随后续窗口（W5 等）或装库激活。

## 3. 熔断机制

任一批次触发即暂停该批销账动作，复盘后再续：

- **熔断A**：单批池票转清 > 2 张 → 疑似批量误销，冻结，人工复核每张 B 号判据。
- **熔断B**：完成率单批跳升 > 5pp → 疑似计数口径漂移或假销，冻结，比对 MD §1.2 与工具 `TARGET`。
- **恢复**：出具逐票判据清单（行内引 B 号 + runtime 已过证据）经星轨批准。

## 4. 防误销

- **已清 → 开放 机检 reject**：任何把「已清」票改回「开放 / 码级已清·待验」的 CSV 写回，若无同票「最后对账」列记载的星轨 B 号批准，工具/脚本应拒绝并报错。
- **合规回退（带 B 号）**：仅在三要件齐全时允许——① 行内引 B 号判据；② runtime 判据确实未过/不可达；③ 星轨批准销批（B 号）。第120批 T-120b 的 D186/D193/D198/D201/D205 即此类合规回退（5 张由"已清"回退）。
- **反方向（开放 → 已清）** 同样须 B 号 + runtime 已过，否则视为假销。

## 5. infra 第三轨

四类白名单死定义，**不占池/现场两轨分母**（计为独立 infra 轨，不计入完成率）：

- **账本类**：台账自身结构性修正（如 D 号重排、列定义）。
- **工具类**：`check_debt_ledger.py` 等计数/机检工具本身的改动。
- **测试类**：`test_*.py` 新增/修正（验证脚手架）。
- **勘误类**：前置分析/审计报告的数据勘误（如烛微报告修正）。

规则：每批 infra 类改动 > 1 件须批注；site 净流入比 > 2（单批现场票增加 > 池票增加×2）触发失衡预警。

## 6. B1.5 短窗规则

- 观察窗长不足判定阈值（如 face R2 仅 5.4min、身份链短窗）→ **无样本**，禁判失败、禁判通过。
- 终判随后续长窗（W5 等）或装库激活后重做 runtime 判据。
- 短窗证据仅可作「码级已清」支撑，不得直接跳「已清」。

## 7. CSV 回写规范

- **允许动的三列**：`实查状态` / `处置建议` / `最后对账`（轨列入账时定，补录时填）。
- **每票行内引 B 号**：任何状态变更须在「最后对账」列标注批次号与判据（如 `T-120b·第120批`、`R4已重启 2026-09-24 11:21`）。
- **无引用禁改**：无 B 号/判据佐证的单元格修改一律拒绝（防静默漂移）。
- **改前 git diff 白名单**：仅上述三列 + 补录新行的指定列允许变更，其余列（如问题简述、代码证据）冻结，除非单独批次裁决。

## 8. 状态位语法规范（第121批 T-121a②）

`✅` / `⏳` 是**隐性状态位**，必须作为 `runtime已验` 的强制后缀，不得裸用：

- **强制后缀**：`runtime已验✅`（已过）/ `runtime已验⏳`（待观察窗）。裸 `✅` 一律禁止——单独的 ✅ 不携带「哪项 runtime 判据已过」的语义，且机检 `check_debt_ledger.classify` 因不含 `runtime已验` 前缀而**不会**判清，会造成「看着像清、计数却开」的漂移。
- **机检一致性**：`classify` 仅在 `码级已清` 叠加 `runtime已验` 或 `✅` 时才判清；裸 `✅` 缺 `runtime已验` 前缀 → 被判开放。故 SOP 语法与工具口径必须一致：写 `runtime已验✅`，不写裸 `✅`。
- **历史票校正**：D189/D194 等已用 `runtime已验✅` 写法，保持一致即可；新票若见裸 `✅` 须先补 `runtime已验` 前缀再计。
- **⏳ 用法**：runtime 判据已设计、待长窗（W5 等）复判时写 `runtime已验⏳`，与 `✅` 并列，均含 `runtime已验` 前缀，机检可识别。
