### 1.3 R-6 编号冲突裁定（P0-2 / P0-3 双义）

**冲突事实**：

- §2 池票体系内，P0-2 / P0-3 出现在**来源列**作「第三方 P0-2 / 第三方 P0-3」（微光 §2.1：P0-10 来源=第三方P0-2，P0-11 来源=第三方P0-3）——即第三方报告对 §2 P0-10/P0-11 的旧编号**别名**，并非 §2 自有独立 ID。
- 底部待办总览区（现场票，09-28）内部另用 P0-1~P0-5 标 6 张现场票，其中 P0-2 = runtime_state_writer 静默、P0-3 = NodePool O(n)——与上方第三方别名**同号异义**。

**裁定（命名空间隔离）**：

1. §2 体系内，P0-2 / P0-3 **仅作第三方别名**使用，永久绑定到 P0-10 / P0-11，禁止当作独立债务 ID。
2. 现场票（09-28 待办总览区）的 P0-1~P0-5 内部标签**退役**，改以既有稳定现场票 ID 引用：W153-α（config 空行膨胀）、D148-1（PII 扫描器自豁免）、O1–O4（导出复扫 / 密钥 / 快照 / 仓库私有化）；其中「P0-2 runtime_state_writer 静默」「P0-3 NodePool O(n)」属现场运行态，归入 **site 轨**（三轨账本 site=13），不进入池票 P 级序列。
3. 后续任何新票如需 P0-2 / P0-3 字面，一律加前缀 `现场-` 或 `site-` 以消歧。
