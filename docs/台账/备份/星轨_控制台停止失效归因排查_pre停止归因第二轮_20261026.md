> **触发**：小林反馈「在控制台中停止曈曈，停止不了」。星轨按只读口径排查进程链、指令文件、日志痕迹、开关现值与退出机制源码；本轮**未改生产代码、未写 data/、未发任何停止指令**，停机/重启动作均由小林掌握。

## 一、结论先行（白话）

1. **停止信号根本没送到曈曈进程本体**——不是「收到信号后卡在退出清理段」，也不是「停了又被自动拉起来接班」。
2. 实证：pid25948 从 12:25:05 连续跑到探针时刻 19:11:19，日志每分钟节拍持续在写；近 4MB 日志内 `KeyboardInterrupt / SIGTERM / SIGINT / 优雅退出 / 进程退出 / shutdown_request / EXIT_BLOCKED / 紧急保存 / WATCHDOG_DUMP / 假死 / 停止框架` 关键词 **0 命中**；崩溃日志最近一条 `WATCHDOG_DUMP` 停在 **2026-10-22 09:12:57**，本代次零新 dump（看门狗未判假死）。
3. **本代次不存在自重启接班条件**：approved 补丁 0 条；`ENABLE_MEMORY_AUTO_RESTART=False`；看门狗线程只 dump 堆栈、不重启不拉进程；进程无子进程；`_apply_pending_patches_and_restart` 仅处理 approved，applied=0 时返回 False 不重启。
4. 最可能成因（按概率排序，待小林对照自己当时的操作确认，见 §四）：
   - **A 信号发到了错误窗口/错误父进程**：曈曈由独立 PowerShell 窗口（pid36328，10:49:17 由 explorer 拉起）前台 `python main.py` 启动；在其他终端、豆包对话框、IDE 内置终端里按 Ctrl+C 或执行停止命令，信号送不到 25948。
   - **B `taskkill` 未带 `/F`**：Windows 上 `taskkill /PID 25948`（不带 /F）对控制台进程只发 WM_CLOSE，Python 默认不映射为 SIGINT，进程不退；必须 `/F` 才是强制终止。
   - **C 关闭窗口 × 的 CTRL_CLOSE_EVENT 未被进程接收/未注册**：代码仅注册 `SIGINT`、`SIGTERM`（main.py:4035–4036），未注册 `SIGBREAK`；关闭父控制台窗口时若进程已脱离控制台焦点，事件可能不送达。
   - **D（低概率，未排除）信号送达后卡在 finally 关闭段**：当前日志零退出痕迹，本轮不支持此说；若小林确认自己在正确窗口按了 Ctrl+C 且看到进程仍在跑，需第二轮现场复抓线程堆栈定位卡点（§七）。

## 三、退出机制链路（源码现状回读，行号以 HEAD 为准）

### 3.1 信号面（Ctrl+C / SIGTERM 路径）

- `main.py:4030–4033` `signal_handler`：收到信号**只置位** `exit_requested=True`、`user_quit_requested=True`，不直接杀进程；`main.py:4035–4036` 仅注册 `SIGINT`、`SIGTERM`（未注册 `SIGBREAK`）。
- `main.py:4380` 主循环 `while not exit_requested`；`main.py:4383` 每拍 `wait_heartbeat_pulse(1)`（`MAIN_LOOP_PULSE_ENABLED=True`），标志位要等当前拍结束才被检查，理论延迟 ≤1 拍。
- 信号送达后进入 `finally` 段（`main.py:4537–4581`）顺序关闭：function_loader.stop_all → health_ui.stop → web_chat.stop → 0.3s 释放 socket → param_patch_manager.stop_auto_apply／config.stop_config_watcher → 语义内核 shutdown 显式落盘 → framework.stop()。
- 退出确认 `main.py:3877–3936`：**TTY 下无 approved 补丁直接 `return False`**（3907–3908），不弹提示、不重启；非 TTY 须同时满足「通道已注册＋stdin 非 TTY」才放行自重启（`_quit_patch_gate_allow` 3866–3874）。本代次 approved=0，即便信号送达也不会卡在确认提示、不会触发自重启。

### 3.2 数据文件指令面（不依赖控制台焦点的优雅通道）

- `main.py:4396–4433`：每拍检测 `data/shutdown_request.json`；`consumed=False` 即消费指令、置 `exit_requested=True` 并 `break` 进入优雅退出。
- 补丁闸门 `main.py:4409–4426`：`NIGHT_ORCH_PATCH_GATE_ENABLED=True` 时若存在 approved 补丁，跳过退出并留痕 `EXIT_BLOCKED_BY_PATCH`；当前 approved=0，**不拦截**。
- 通道实现 `nucleus/evolution/night_orchestration.py:60–108`：`request_shutdown / has_shutdown_request / consume_shutdown_request` 三件套；指令文件格式 `{"requested_at": <epoch>, "reason": "...", "requester": "...", "consumed": false, "timeout": null}`。

| 操作方式 | 信号是否送达 25948 | 进程行为 | 判定 |
|---|---|---|---|
| 在 **pid36328 那个独立 PowerShell 窗口**内按 `Ctrl+C`，焦点在窗口内 | 是（SIGINT） | ≤1 拍内置位 → finally 优雅关闭；approved=0 直接退出不重启 | 正常应能停；若此操作仍无效，属 §1-D 低概率卡点，需现场复抓堆栈 |

### 姿势乙 · 强制停止（退路；仅当姿势甲无效时使用）

```powershell

```

- 代价：跳过 finally 显式落盘段，内存中未落盘向量、未持久化状态可能丢失；与优雅关闭相比不保证快照一致性。
