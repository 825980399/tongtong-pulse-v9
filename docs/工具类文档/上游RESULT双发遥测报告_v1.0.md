## 二、三次样本的定量对比

| 指标 | 样本1（19:58:14） | 样本2（23:09:22） | 样本3（23:47:59） |
|---|---|---|---|
| `_on_inference_result` 执行次数 | 2 | 2 | 2 |
| 两次「策略选择」参数 | 完全相同 | 完全相同 | 完全相同 |
| 两次「B2策略接线」实际值 | `search_with_lung_fallback` / `none` | 同左 | 同左 |
| cid | `ctx:3:…` | `ctx:2:…` | `ctx:5:…` |
| **时间差** | **同一秒（毫秒级）** | **同一秒（毫秒级）** | **同一秒（毫秒级）** |
| 第二次是否被抑制 | 否（第25批修复前） | **是** | **是** |
| 肺被调用次数 | **2** | **1** | **1** |
| 大模型调用次数 | **2**（119 字 / 139 字） | **1**（139 字） | **1** |
| 用户可见输出 | **2 条** | **1 条** | **1 条** |

**结论：上游双发是稳定现象（非偶发），与「是否触发深度搜索」强相关；两次 RESULT 几乎同时（毫秒级）到达皮层。**

**payload 差异（由两次不同分支反推）**
- 第 1 次：`实际=search_with_lung_fallback` → 走 `PulseCortex.py:846`（`ctx is None` 的**对话兜底**分支，日志「内在世界回退…直接尝试调用肺模型」）；
- 第 2 次：`实际=none` → 走 `PulseCortex.py:1315`（`inner_world_no_answer` 分支，**无日志**，故此前难以察觉）；
- 二者 `correlation_id` **相同**，prompt 相同 → 所以第25批的幂等闸门（key = cid + prompt 指纹）能够精确识别并抑制第 2 次。

## 三、根因链（已定位到文件 + 方法 + 分支）

```
ChatEvent.MESSAGE（1 次）
 └ 语义理解器 → CLASSIFY_RESULT（1 次，实测「语义理解:」×1）
    └ PulseCortex._route_by_intent（1 次，实测「QICA意图路由」×1）
       └ InferenceEvent.REQUEST（1 次）
          └ PulseInnerWorld._on_inference_request（实测「路径前缀推断」/「全局语义检索结果」重复 ≥2 次）
             └★ 同一轮产生 2 个 InferenceEvent.RESULT
                · 主推理兜底路径（answer=None → 交由肺）
                · 深度搜索/工具触发路径（实测「元认知决策: 触发深度搜索」后异步提交）
             └ PulseCortex._on_inference_result 执行 2 次
                ├ :846  对话兜底      → SELECT_MODEL ①
                └ :1315 inner_world_no_answer → SELECT_MODEL ②（★无日志，隐蔽）
                   └ 肺 ×2 → 大模型 ×2 → 输出 ×2
```

**★本批新补充的证据**：内在世界的**检索子流程日志成段重复**
（「ResonanceEngine 关联扩展」「全局语义检索结果」「语义关系扩展质量」「路径前缀推断」在同一秒内各出现 2~3 次，内容相同），
表明重复并非只在 RESULT 发送侧，而是 **`_on_inference_request` 的执行/检索流程本身被跑了不止一遍**。

| **收益估算** | 消除约 11% 轮次的重复推理（本批 9 轮中触发 1 次）与相应的重复检索开销；减少一次无谓的 RESULT 处理。 |

## 五、下一步：取回确切发布行号（需一次重启）

第25批已内置遥测开关，**默认关闭、零开销**：

```powershell
$env:PULSE_DUP_TRACE = "1"     # Windows PowerShell（当前会话）
python main.py
```

开启后，`InfoField.publish` 会对「同 `event_type` + 同 `correlation_id`」在
5 秒窗口内的重复发布输出 **WARNING + 两条调用栈**（含文件名与行号），
直接定位第二个 `InferenceEvent.RESULT` 的确切发布点。

可调参数（`config.py`）：
`DEBUG_DUP_EVENT_TRACE`（默认 False）/ `DUPLICATE_EVENT_WINDOW_SEC`（5.0）/
`DUPLICATE_EVENT_STACK_DEPTH`（12）/ `DUPLICATE_EVENT_WATCH`（含 `inference.result`）。

> 本批未做该重启，原因同第25批：**不为验证而启动第二个框架实例**
> （生产实例在写 318MB 快照，双进程会争抢）。建议在低负载时段做一次即可闭合。
