## 五、口径说明与已知偏差（引用前必读）

1. **`python_files=756` 含临时目录**：`measure_baseline.py:35-42` 的 `EXCLUDE_DIR_NAMES` 有精确名 `tmp`，但**不含 `.aionclaw-tmp`**，致该目录 **31 py / 1,799 行**被计入。扣除后**生产口径 = 725 文件 / 291,480 行**。`core_lines=210,357` 不受影响（三前缀白名单不含该目录），故建议对外引用**优先用 210,357**。
2. **历史口径与本次现测并存**：两者同源同脚本，差异为期间新增文件与行数。本文取**现测值**并注明时刻，禁止跨时点混用。
3. **`organ_files=69` ≠ 器官数 57**：前者是 `organs/` 下非 `__init__` 的 .py 计数（实测 71 含 2 个 `__init__.py`，脚本扣除得 69，已复算吻合）；后者是 `ORGAN_META` 声明计数 56 + 准器官 1。**一个文件可声明 0/多个器官，两数不可互换。**
4. **两个 models 目录并存**：顶层 `models/` 仅有语音模型 `vosk-model-small-cn-0.22`；**嵌入模型缓存在 `data/models/`**（fastembed 缓存，`config.py:775 cache_dir="data/models"`）。旧文档"models/ 离线模型（语音/人脸）"未区分，易误判体积归属。
5. **`organs/immune/` 4 文件 + `senses/` 4 文件模块 docstring 为模板占位**（形如「PulseWhiteCell —— PulseWhiteCell 相关实现」），无实质职责描述。本树中 immune 的职责栏标「待人工补」，senses 沿用旧文档表述。
6. **`nucleus/gpu/` 是空目录**（0 py）：GPU 逻辑实际在根级 `nucleus/GPUCore.py`。属结构残留，非缺陷，但目录树若照抄会误导。
7. **`hardware/robot_body/servo_controller/` 为 ESP-IDF C 工程**（`app_main.c` 605 行、`sdkconfig` 2,214 行，且 `sdkconfig.old` 与 `sdkconfig` 等长重复），不计入 Python 规模口径。
8. **`distributed/routing.py`、`sharding.py` 自述「只做设计与接口定义，不实施」**，`distributed/*` 整体标注"第一阶段：单机模拟" → 计数入代码规模但**不得视为已具备分布式能力**。
9. 所有目录/行数由脚本遍历实读生成（排除 `__pycache__/.bak_*/.git/tmp`），采集时框架**活体运行中**；`data/` 内运行时数值（节点数、快照体积）为瞬时值，本文只引用其文件体积。
