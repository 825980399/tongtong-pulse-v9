## 任务1 · T-微光门禁脚本-1（P2/172，星轨 Q21 已授权）★核心

**背景**：登记册票 `T-微光门禁脚本-1`：星轨已授权微光产出三支门禁脚本——`trace_source_gate.py` / `observe_marker_gate.py` / `ledger_consistency_check.py`；`tools/` 下实测**均不存在**（2026-10-08 星轨核实）。

**内容**：产出三支门禁脚本（写入 `tools/ci/`），功能定义：
1. **`trace_source_gate.py`**——溯源门禁：校验交付报告/任务书中的"来源声明"（票号、提交 SHA、文件路径）是否可被 git 历史/登记册反查验证；悬空引用即 FAIL
2. **`observe_marker_gate.py`**——观测标记门禁：校验观测类交付（快照/指纹/采样）是否带观测窗标记（时间窗起点、HEAD、工具调用数）；缺失即 FAIL
3. **`ledger_consistency_check.py`**——登记册一致性门禁：校验登记册状态分布（已结案/已撤销/已排期/已裁决待排期）与基线 JSON 一致；与 `tools/ci/check_pending_register.py`（M2，已入库）互补不重复

**依赖**：参考既有门禁范式 `tools/ci/check_*.py`（现 15 件，如 check_delivery_settle.py 双源扫描、check_pending_register.py 基线校验）
**验收**：
- 三支脚本各自 `--selftest` 通过；独立跑通正反例（有悬空→FAIL / 无悬空→PASS）
- 不与其他门禁脚本撞名/撞功能（登记册校验与 M2 互补：M2 管逾期，本脚本管一致性）
- 挂门禁链方式（pre-commit 或独立调用）给出建议，**是否实际挂链由星轨裁定**（不擅自动 pre-commit 配置）
- 脚本 CRLF 达标（.py 文件仓规）、PII 扫描自身通过

**★纪律**：不 add / 不 commit / 不删移；脚本产出后报文件清单（路径 + 行数 + selftest 结果），由星轨代提交；如与路灯 171 施工撞文件（tools/ci/ 若路灯触碰）→ 报星轨错峰

**内容**：对 git 全历史提交内容做 PII 只读扫描（复用 `tools/ci/check_pii_final_scan.py` 的 10 组 PII 模式：邮箱/身份证/手机号等）：
- **范围**：全历史提交（`git log -p` 或逐提交 blob 扫描），分类统计：真身邮箱（`%ae` 面）/ 手机号 / 身份证 / 其他

**依赖**：`tools/ci/check_pii_final_scan.py`（现存，163 批修复假阳性后）；读远端需 git 本地缓存（勿新增网络依赖）
**验收**：
