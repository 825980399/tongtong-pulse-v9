## 刀1：Step5a叙事落盘（核心）

**做什么**：PulseNarrativeSelf现在has_persist=false、has_load=false、data/narrative/不存在——重启即断。这一批加上持久化。

**怎么做**：
- 新增 `data/narrative/` 目录，格式 `narrative_YYYYMMDD.jsonl`，append-only每天1条摘要
- PulseNarrativeSelf增 `persist()` 和 `load()` 方法：
  - persist：每日04:00（挂night_orchestration现有段，不新建调度器）把当日narrative_events摘要写jsonl
  - load：启动时回放最近7天jsonl，恢复 `_narrative_events`（≤300条cap不变）
- 连续天数计数器：从jsonl里数连续有记录的天数，存内存+落盘
- 阶段判定改锚点：`_generate_life_plan` 的 `narrative_events<20/<50` 阈值改用"落盘条数+连续天数"
- 行格式：`{date, version, headline, delta{nodes,llm_ratio,patches}, intent, prev_intent_verdict, evidence_refs, generated_at}`——headline/delta/intent字段先留空（下一批413再填）

**验收**：
- data/narrative/目录存在；jsonl格式与ledger同构可审计
- 重启两次，叙事条数与连续天数不归零
- 阶段判定不再用内存阈值，改用落盘条数

## 刀2：经验池治理（content字段补全）

**做什么**：411批发现——经验池379条，但 `content` 字段一条都没有，369条是"已摘要"（只有summarized_text没有原始content）。这种数据拼进prompt只会更空。

**怎么做**：
- 先查清楚：经验入库时content字段应该存什么？为什么全空？是设计如此还是bug？
- 如果是设计如此（只存摘要）：那检索时用summarized_text做语义匹配就够了，不需要补content——确认即可
- 如果是bug：补入库时的content写入逻辑
- 同时治模板污染：125条不同文本里最热那段模板占19%（template_ratio=0.19）——模板类经验标记 `is_template=true`，检索时降权
- 验收：经验池content字段非空率>50%（如果是设计如此就跳过这步，确认即可）；模板类经验有标记

## 刀3：effect_verify perf_delta_ms供给补全

**做什么**：411批新发现——`verify()` 判 `passed=True` 要求 `problem_gone/function_ok/perf_ok` 三维全知，但 `PatchManager` 固定传 `perf_delta_ms=None` ⇒ 即便apply恢复，也只会落 `unverifiable`，判不出passed。

**怎么做**：
- 在PatchManager apply前后，加一次简单性能采样（比如该补丁涉及的模块导入时间/函数调用耗时）
- 把采样结果作为 `perf_delta_ms` 传给 `EvolutionEffectVerifier.verify()`
- 不需要精确——只要有数值就行，正负0.5ms内算perf_ok
- 验收：手动触发一次apply，effect_verify结果不再是恒unverifiable，能出passed或failed
