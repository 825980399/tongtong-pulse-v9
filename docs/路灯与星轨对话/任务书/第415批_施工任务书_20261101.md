## 刀1：O3开闸前A抽验（核心）

**做什么**：414批算出440条eligible、真死率98.9%。但路灯自己也说还有3类盲区（注册表dict value/裸Name/命名式线程入口）。开闸前先抽20条A类样本，逐条人工复核，确认真死率是不是真的这么高，盲区到底有多少。

**怎么做**：
- 从440条eligible里随机抽20条（固定seed=415，可复现）
- 逐条静态分析：
  - 有没有被注册表dict value引用？
  - 有没有被当值传递给线程/线程池？
  - 有没有被getattr动态调用？
  - 有没有在注释/docstring里被提到（不算引用）？
- 出报告：20条样本里真死/假死/存疑各多少？真死率实测是多少？
- 如果实测真死率>95%：说明判据够准，下一批可以考虑真开闸
- 如果实测真死率<90%：说明盲区比预想的大，开闸再等等

**验收**：
- 20条样本逐条有结论+理由
- 实测真死率与414报告的98.9%对比
- 不真apply任何O3补丁

## 刀2：O3三类盲区清单

**做什么**：414批列了3类已知盲区（故意没补判据的），现在把这三类各有多少条摸清楚，评估影响面。

**怎么做**：
- **盲区1：注册表dict value**——全库扫一遍`{"k": "方法名"}`这种dict，值是字符串且像方法名的，有多少条？这些方法被判死的话会不会误删？
- **盲区2：裸Name值引用**——全库扫一遍`staticmethod(calc_xxx)`、`threading.Thread(target=self._xxx)`这种把方法名当值传的，有多少条？414的value_ref判据已经覆盖了一部分，还剩多少漏网的？
- **盲区3：命名式线程/循环入口**——那些靠名字匹配的线程入口（比如`if name == "_watchdog_loop"`），静态调用图看不见的，有多少条？
- 出一份盲区清单报告：三类各多少条、影响面多大、要不要补判据

**验收**：
- 三类盲区各有精确条数
- 每条盲区有代码坐标
- 结论：这三类盲区会不会导致真删的时候误删？

## 刀4：经验命中开拼prompt（核心）

**做什么**：之前经验池有检索工具、有降权治理，但一直没真的拼进对话主链路——曈曈跟你聊天的时候，根本没用到之前的经验。这一批把经验检索真的接到对话prompt里。

**怎么做**：
- 对话主链路在生成回复前，先调经验池检索：
  - 用用户输入的问题当query
  - 取top3命中的经验（带降权）
  - 拼成一段"相关经验参考：..."放在system prompt后面
- 开关默认关（`ENABLE_M415_EXPERIENCE_IN_PROMPT = False`），先跑一周dry-run看效果，没问题再开
- dry-run模式：只记录"如果开了会拼哪些经验进prompt"，不真拼
- 注意：经验内容可能很长，要截断——每条经验最多取summary前100字，三条加起来不超500字

**验收**：
- dry-run模式下，每次对话都记录"命中了哪几条经验、权重多少、会拼多少字进去"
- 开关默认关，不影响现有对话
- 单测：query→检索→拼prompt的完整链路
