## 审计任务

### T-Audit-1（P0）：进化闭环效果审计

#### 审计目标
第99批修复假成功口径后，进化闭环是否真的恢复正常？

#### 审计要点
1. **修复率真实性**
   - 第99批修复前：修复率 0%（连续11轮 < 10%）
   - 第99批修复后：修复率是否回升
   - 用真实代码验证：随机抽 10 条已批准补丁，检查是否真的修复了问题

2. **B 级假成功重测结果**
   - 第100批重测 23 条 B 级补丁
   - 重测后：真修复多少 / 假成功多少
   - 假成功的根因是什么（是 LLM 生成的补丁无效，还是验证器口径问题）

3. **进化通道接入渠道池效果**
   - 第96批接入渠道池后，LLM 调用成功率是否提升
   - 额度消耗是否合理（免费额度优先用）
   - 有没有渠道切换失败的情况

4. **自学习闭环空转根因**
   - 第93批定位了自学习闭环空转根因
   - 第95~99批修复后，自学习是否真的开始工作
   - 本地学习尝试通道是否正常运行

#### 产出
- 进化闭环效果评分（0~10）
- 修复率真实数据
- 发现的新问题清单

### T-Audit-2（P1）：技术债务清偿进度审计

#### 审计目标
从第82批到第100批，技术债务清偿了多少？剩余多少？

#### 审计要点
1. **总账核对**
   - 读 `docs\完整进化路线与技术债务清单_v1.0.md`
   - 统计：已清偿 / 待清偿 / 新增
   - 对比第1期审计时的技术债务数量

2. **代码实查**
   - 随机抽样 20 个技术债务项
   - 用代码验证：是否真的清偿了
   - 有没有"账面清偿、实际没改"的假成功

3. **新增技术债务**
   - 第95~100批有没有引入新的技术债务
   - 静默 except 回潮（第95~97批新增 9 处）是否已修复
   - 有没有其他回潮现象

4. **剩余技术债务优先级**
   - 剩余技术债务中，哪些是 P0 / P1 / P2
   - 预计还需要多少批次才能清偿完
   - 有没有可以合并或延后的

#### 产出
- 技术债务清偿进度（百分比）
- 剩余技术债务清单（按优先级排序）
- 预计剩余批次估算

## 审计方法要求

1. **全程可复现**
   - 所有判据必须可复现
   - 不要凭印象下结论
   - 证据路径必须明确

2. **引用准确**
   - 引用代码时必须注明文件和行号
   - 引用日志时必须注明时间戳
   - 不要把"观察值"当成"判据"（第1期校准教训）

3. **分级标准**
   - P0：严重问题，影响框架稳定性
   - P1：重要问题，影响功能或性能
   - P2：一般问题，代码质量或文档
