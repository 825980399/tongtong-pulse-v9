## 背景

453+453R收口完成，注入基础设施就绪。本批进入P1阶段——把"多步推理"从"每一步都是检索"改成真正的推理算子。

烛微前置分析说454要拆成4段，本批先做最安全的两段：**454a（计划v3只生成不执行）+ 454b（本地三算子）**，外加证据源补充（人工种子+KAL提炼）。

hypothesize（LLM算子）和意图handler放下一批（455）。

## 刀1 · P1-1a：计划生成v3（只生成不执行）

**白话**：现在"多步推理"的每一步都是"检索一下"——改成每步带个算子标签（比较/排除/量化/检索），先只打标不执行，看看计划长得对不对。

| 项 | 内容 |
|---|---|
| 改动 | `PulseInnerWorld.py:_generate_task_plan`：保留原`{name,prompt,fallback}`，**加法扩展**新增`step_id/op/goal/depends_on/expected_evidence` |
| op枚举 | `retrieve / compare / exclude / quantify`（hypothesize下一批） |
| 规则 | `op=retrieve`时行为与现在完全一致；`op!=retrieve`时先记trace不执行 |
| 兼容 | v1/v2/`_synthesize_step_results`/`_m35_entry_probe`全部只读原字段，忽略新字段 |
| 验收 | 生成的计划里至少1步op!=retrieve；回答路径不变；trace里能看到op标签 |

---

## 刀2 · P1-1b：本地算子compare（第一步）

**白话**：第一个真算子——比较。给两个东西，逐维对照，找相同点和不同点。没有证据就说"证据不足"，不瞎编。

| 项 | 内容 |
|---|---|
| 新建 | `nucleus/reasoning/local_ops.py`：`compare(operands, dimensions, evidence) → {similarities, differences, evidence_ids, confidence}` |
| 实现 | 关键词/数值/属性抽取；集合差；逐维对照 |
| 失败语义 | 证据不足 ⇒ `insufficient_evidence`，不编造 |
| 验收 | 单测：两组数据比较正确；证据不足时显式标记，不瞎编 |

---

## 刀3 · P1-1b：本地算子exclude（第二步）

**白话**：第二个算子——排除。给一堆候选和标准，按标准一条条筛掉不符合的。全被排除就返回原集合+告警，不静默清空。

| 项 | 内容 |
|---|---|
| 函数 | `exclude(candidates, criteria, evidence) → {kept, dropped:[{item,reason}], evidence_ids}` |
| 实现 | 关键词命中 + 否定词 + 阈值过滤 |
| 失败语义 | 全被排除 ⇒ 返回原集合 + 告警，不静默清空 |
| 验收 | 单测：正确筛掉不符合项；全排除时不返回空 |

---

## 刀4 · P1-1b：本地算子quantify（第三步）

**白话**：第三个算子——量化。从证据里抽数字，算总和/均值/比例。找不到数字就说"缺数据"。

| 项 | 内容 |
|---|---|
| 函数 | `quantify(metric, values, unit) → {value, unit, formula, evidence_ids}` |
| 实现 | 复用`_evaluate_numeric_condition`/数值解析；求和/均值/比例 |
| 失败语义 | 缺数值 ⇒ `insufficient_numbers` |
| 验收 | 单测：正确计算；缺数值时显式标记 |

---

## 刀5 · trace落plan+step_results（454必须落地）

**白话**：现在trace里`steps=[]`是空的——454要把每一步的算子、输入摘要、输出摘要、证据id、耗时都记下来，这样才能验收"真多步"。

| 项 | 内容 |
|---|---|
| 改动 | `pulse_inner_world_support.py`：trace schema加`plan`和`step_results` |
| plan | `[{step_id, op, goal, depends_on, expected_evidence}]` |
| step_results | `[{idx, step_id, op, status, input_digest, output_digest, evidence_ids, confidence, source, elapsed_ms, fail_reason}]` |
| 要求 | `input_digest/output_digest`只存摘要，不存用户原文；`steps`非空才算"真多步" |
| 验收 | 跑一个多步问题，trace里plan和step_results都有内容 |

## 刀6 · 人工种子证据库第一批（30条）

**白话**：现在注入候选只剩2条——因为经验池里都是模板和自问自答。先人工写30条高质量经验，覆盖8个维度，注入效果才能看出来。

| 项 | 内容 |
|---|---|
| 新建 | `data/eval/human_seed_evidence.json`（~30条） |
| 格式 | `{question_pattern, method, outcome, caveat, confidence, source="human_seed", reward=1.0, timestamp}` |
| 覆盖 | 8个维度各3-4条；优先补D1多步、D3证据、D6批判 |
| 质量 | 写"什么情况下用什么方法、哪里容易错"，不写万能答案 |
| 准入 | `evidence_source.py`的白名单加`human_seed`；入库时打`source=human_seed` |
| 验收 | 30条落盘；注入候选数从2条涨到≥15条 |
