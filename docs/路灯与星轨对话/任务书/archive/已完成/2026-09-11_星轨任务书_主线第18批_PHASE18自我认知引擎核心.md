## 一、任务1：新建SelfAwarenessEngine核心框架 + 自我认知画像数据模型

### 文件
`nucleus/self_awareness/SelfAwarenessEngine.py`（新建目录`nucleus/self_awareness/`和文件）

### 功能要求

#### 1.1 自我认知画像数据模型（SelfAwarenessProfile）

使用`@dataclass`定义统一数据结构，参考设计文档4.3节：

```python
@dataclass
class SelfAwarenessProfile:
    timestamp: str
    code_health: dict          # 语法错误/ruff错误/死代码/循环依赖等
    runtime_health: dict       # 错误数/警告数/器官健康/性能基线
    knowledge_health: dict     # 总节点数/矛盾/污染/覆盖缺口/老化
    evolution_health: dict     # 修复率/补丁成功率/复发率/ROI
    production_consumption: dict  # 产出-消费配对结果（任务2产出）
    fake_loops: dict           # 虚假闭环检测结果（任务3产出）
    summary: str               # 一句话总结
```

要求：
- 所有字段有默认值（空dict/空字符串），确保向后兼容
- 提供`to_dict()`和`from_dict()`方法，支持JSON序列化
- 提供`merge(other)`方法，支持多份画像合并

#### 1.2 SelfAwarenessEngine核心类

- **单例模式**：`get_self_awareness_engine()`函数返回单例，`reset_self_awareness_engine()`用于测试隔离
- **分析器注册机制**：`register_analyzer(name, analyzer_func)`，分析器函数签名`(engine) -> dict`，返回该维度的分析结果
- **统一调度**：`run_all_analyses(scope: str = "all")`，按注册顺序执行所有分析器，结果汇总到SelfAwarenessProfile
- **报告生成**：`generate_report(output_path: str | None = None) -> str`，生成可读的文本报告，可选保存到文件
- **画像持久化**：`save_profile(path)` / `load_profile(path)`，JSON格式
- **与现有模块整合**：提供`integrate_log_analyzer()` / `integrate_code_review()`等方法，调用现有模块获取基础数据（第一阶段可先留接口，返回空dict，后续批次填充）
- **性能保护**：所有分析操作加超时保护（单个分析器超过30秒打WARNING并跳过），避免卡死
- **线程安全**：使用`threading.Lock`保护画像数据

#### 1.3 灰度开关

```python

SELF_AWARENESS_TIMEOUT_SEC = 30       # 单个分析器超时
```

- SelfAwarenessEngine可正常实例化和单例获取
- 注册分析器后run_all_analyses()能正确执行并汇总结果

## 二、任务2：产出-消费配对器（ProductionConsumptionMatcher）

### 文件
`nucleus/self_awareness/ProductionConsumptionMatcher.py`

### 功能要求

#### 2.1 静态分析：识别产出方和消费方

使用`ast`模块扫描项目中所有Python文件（排除tests/、tmp/、.bak_*/、__pycache__/）：

**产出方识别**（写入文件的调用）：
- `open(path, 'w'/'a'/'wb'/'ab')`
- `json.dump(obj, f)` / `json.dumps`（需配合写入）
- `np.savez(path, ...)` / `np.save(path, ...)`
- `pandas.DataFrame.to_csv(path)` / `to_json(path)` / `to_parquet(path)`
- `shutil.copy(src, dst)`（dst为产出）
- 类方法名包含`save`/`write`/`dump`/`persist`/`store`

**消费方识别**（读取文件的调用）：
- `open(path, 'r'/'rb')`
- `json.load(f)` / `json.loads`
- `np.load(path)` / `np.loadtxt(path)`
- `pandas.read_csv(path)` / `read_json(path)` / `read_parquet(path)`
- 类方法名包含`load`/`read`/`fetch`/`retrieve`

#### 2.2 建立文件级映射

- 对每个数据文件路径（提取ast中的字符串字面量路径），记录：
  - 产出方：模块名.类名.方法名 + 文件路径 + 行号
  - 消费方：模块名.类名.方法名 + 文件路径 + 行号
- 路径归一化：相对路径转绝对路径，消除`../`、`./`
- 动态路径（含变量/格式化）标记为"动态路径，无法静态确定"

#### 2.3 分类标记

对每个数据文件：
- **疑似无消费**：消费方数量=0 → 高优先级关注
- **疑似无产出**：产出方数量=0但有消费 → 可能是外部输入或遗留代码
- **动态路径**：路径含变量 → 需运行时验证
- **正常**：有产出有消费 → 低优先级

#### 2.4 输出报告

- 按文件大小排序（大文件无消费最浪费）—— 文件大小通过`os.path.getsize`获取（文件存在时）
- 按产出模块分类
- 给出处理建议：删除/归档/找消费方/需运行时验证
- 持久化到`data/self_awareness/production_consumption.json`
- 文本报告格式：`data/self_awareness/production_consumption_report.txt`

#### 2.5 灰度开关

```python

PRODUCTION_CONSUMPTION_SCAN_DIRS = ["nucleus", "organs", "functions", "main.py"]  # 扫描范围
```

## 三、任务3：虚假闭环检测器（FakeLoopDetector）

### 文件
`nucleus/self_awareness/FakeLoopDetector.py`

### 功能要求

#### 3.1 静态识别候选模块

扫描所有Python文件，识别"应该有闭环"的模块：
- 类中同时定义了`save`和`load`方法（或`save_*`/`load_*`、`write`/`read`、`dump`/`fetch`）
- 类的`__init__`中包含`storage_path`/`save_path`/`data_path`/`cache_path`等属性
- 模块级变量包含`_STORAGE_PATH`/`_SAVE_PATH`等

#### 3.2 静态验证（本阶段只做静态，不触发运行时）

对每个候选模块，进行以下静态检查：

**a. 保存空操作检测**：
- `save()`方法体中是否有真正的文件写入调用（open('w')/json.dump/np.savez等）
- 如果只有`self._log(INFO, "保存成功")`但没有实际写入 → 标记"保存空操作"
- 如果`save()`方法体只有`pass`或`return True` → 标记"保存空操作"

**b. 加载空操作检测**：
- `load()`方法体中是否有真正的文件读取调用（open('r')/json.load/np.load等）
- 如果只有日志但没有实际读取 → 标记"加载空操作"

**c. 路径一致性检测**：
- 提取`save()`中使用的文件路径（字符串字面量或属性引用）
- 提取`load()`中使用的文件路径
- 如果两者引用不同的属性/变量 → 标记"路径可能不一致"
- 如果save用`self.path`，load用`self.file_path` → 高风险

**d. 异常静默检测**：
- `save()`或`load()`中是否有`except Exception: pass`或`except Exception: return None/False/{} `
- 异常被静默吞掉 → 标记"异常静默，可能掩盖真实失败"

**e. 返回值校验缺失**：
- `save()`是否检查写入结果（如`f.write()`返回值、文件是否存在）
- `load()`是否检查加载结果非空（如`if data is None`、`if not data`）

#### 3.3 闭环健康度评分

对每个候选模块：
- **100分**：save有真实写入 + load有真实读取 + 路径一致 + 无异常静默 + 有返回值校验
- **80分**：有1项小问题（如缺少返回值校验）
- **60分**：有1项中问题（如路径可能不一致、异常静默）
- **30分**：有1项严重问题（保存空操作或加载空操作）
- **0分**：多项严重问题

#### 3.4 输出报告

- 按健康度升序排列（问题最严重的排最前）
- 每个模块列出：模块名、类名、问题类型、具体行号、健康度评分、修复建议
- 持久化到`data/self_awareness/fake_loops.json`
- 文本报告：`data/self_awareness/fake_loops_report.txt`

#### 3.5 灰度开关

```python
ENABLE_FAKE_LOOP_DETECTOR = True
FAKE_LOOP_SCAN_DIRS = ["nucleus", "organs", "functions", "main.py"]
```

### 验收标准
- 能正确识别同时有save/load方法的类
- 对已知的虚假闭环模式（如EvidenceCalibrator历史问题）能正确检测
- 保存空操作、加载空操作、路径不一致、异常静默四类问题能正确标记
- 健康度评分合理
- 报告包含具体行号和修复建议
- 扫描排除tests/、tmp/、.bak_*/目录
- 开关关闭时零开销
- **不触发任何运行时保存/加载**，纯静态分析
