## 二、任务清单

### 任务1：L3扩缩容震荡修复（P1-67，优先级最高，45-60分钟）

#### 问题描述

重启后5分钟内发生13次扩缩容，worker变化序列：
```
4→3→2→5→4→3→2→5→4→3→5→4→3→2
```

每次扩缩容都触发池重建，池重建时`cancel_futures=True`导致并发计数泄漏，S5修复累计重置116个计数。

#### 根因分析

1. **burst检测太敏感**：队列18%、21%、44%就触发burst直接扩到上限5
2. **扩容冷却太短**：5秒，刚扩容完队列清空就开始缩容
3. **下限太低**：worker降到2，稍微有任务就触发burst扩容
4. **缩容太快**：队列一空立即缩容，没有缓冲期

#### 修复要求

1. **提高burst阈值**：`l3_burst_growth_threshold` 从0.30提高到0.50（10秒窗口增长>50%才触发）
2. **增加扩容冷却**：`l3_scale_up_cooldown` 从5秒增加到15秒
3. **设置最小worker数**：新增`l3_min_workers`配置，默认3（不允许降到2）
4. **缩容增加延迟**：队列深度≤0.50后，等待30秒再缩容（避免震荡）
5. **平滑扩缩容**：burst时不要直接扩到上限5，而是扩到`min(current+2, max)`

#### 验收标准

- [ ] 重启后运行10分钟，扩缩容次数≤3次
- [ ] worker数量稳定在3-5之间，不出现2
- [ ] 无S5池重建重置WARNING（或≤1次）
- [ ] 队列深度峰值时不出现拒绝分发
- [ ] 新增测试用例：模拟震荡场景，验证不会频繁扩缩

#### 修改文件

- `config.py`：新增/修改L3扩缩容配置
- `nucleus/field/InfoField.py`：修改`_auto_scale_l3_by_depth`方法
