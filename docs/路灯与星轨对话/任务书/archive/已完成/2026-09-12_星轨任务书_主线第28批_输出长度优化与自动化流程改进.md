## 二、任务清单

### T1：大模型输出长度优化（P2-171）⚠️ 需重启框架验证

**优先级**：P2
**预估工时**：3-4小时
**问题背景**：第26批运行时验证发现，要求大模型输出400-500字，实测仅99-119字。非截断问题，是模型/prompt侧问题。用户体验差，长问题回答过于简短。

**任务内容**：
1. **根因定位**：
   - 检查各渠道（zhipu/deepseek/doubao）的max_tokens配置
   - 检查prompt中是否有明确的长度要求（"400-500字"）
   - 分析模型输出长度分布（采集10-20个样本统计）
   - 定位是配置问题、prompt问题还是模型本身倾向简短
2. **优化方案**：
   - 如为配置问题：调整max_tokens至合理值（如1024-2048）
   - 如为prompt问题：增强长度要求的prompt工程（如"请详细展开，至少400字"）
   - 如为模型倾向：增加输出长度后处理（如检测过短则触发追问补充）
3. **配置化**：
   - 将输出长度目标提取为config配置项（`LLM_TARGET_OUTPUT_LENGTH`）
   - 灰度开关（`ENABLE_OUTPUT_LENGTH_OPTIMIZATION`，默认True）
4. **验证**：
   - 采集优化前后的输出长度对比
   - 确保不影响短问题的快速回复

**验收标准**：
- [ ] 根因定位明确（配置/prompt/模型倾向）
- [ ] 优化方案实施，配置项已提取到config.py
- [ ] 灰度开关默认True，关闭后回退到原行为
- [ ] 运行时验证：长问题输出长度显著提升（需重启框架）
- [ ] pytest新增输出长度相关测试用例≥3例
- [ ] 不影响短问题的快速回复

**注意事项**：
- 不要盲目增大max_tokens，需平衡响应时间和输出质量
- 不要修改核心推理逻辑，只优化输出长度相关配置和prompt
- 确保各渠道配置一致

### T2：自动化定时任务流程优化（P2-173）✅ 无需重启

**优先级**：P2
**预估工时**：2-3小时
**问题背景**：第27批实测发现，自动化定时任务"领取即空转"——巡逻定时任务在01:23将任务书移入"处理中"，但此后6次触发（01:22-06:22）未产生任何代码改动。单次自动化运行的时间/步数预算无法承载一个既定工时为10小时的批次。

**任务内容**：
1. **分析空转根因**：
   - 检查定时任务的执行流程（领取→分析→生成→通知）
   - 定位哪个环节导致空转（是领取后未执行？还是执行后未产出？）
   - 分析单次运行的时间/步数预算限制
2. **优化方案（二选一，推荐方案A）**：
   - **方案A（推荐）**：任务书按"单任务粒度"拆分，每个定时任务只处理1个子任务
   - **方案B**：自动化只做"领取+报告待办"，不承诺整批交付，由用户手动触发路灯执行
3. **实施优化**：
   - 如选方案A：将第28批任务书拆分为4个子任务，每个子任务独立可执行
   - 如选方案B：修改定时任务流程，增加"待办报告"输出
4. **文档更新**：
   - 更新自动化管理流程文档
   - 记录优化后的执行流程和预期产出

**验收标准**：
- [ ] 空转根因定位明确
- [ ] 优化方案实施（方案A或B）
- [ ] 自动化管理流程文档已更新
- [ ] 代码审查通过（不修改框架核心逻辑）
- [ ] 不影响现有的定时任务功能

**注意事项**：
- 这是流程优化任务，不修改框架核心代码
- 优先选择方案A（单任务粒度拆分），更符合自动化理念
- 如方案A实施复杂，可退化为方案B

**任务内容**：
1. **分析m19夹具**：

3. **实施优化**：
   - 选择最优方案实施（推荐方案A，效率最高）

4. **验证**：
   - 运行m19测试，确认不再触发删除配额限制
   - 确保测试结果与优化前一致

**验收标准**：
- [ ] m19夹具优化完成，不再触发删除配额限制
- [ ] 测试用例全部通过（pytest）
