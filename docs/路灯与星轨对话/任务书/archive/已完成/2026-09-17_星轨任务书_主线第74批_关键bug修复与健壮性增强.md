### T1 · P0 修复双腿模块 dict.append bug

**问题描述**：框架运行日志中反复出现：
```

```

**根因定位**：
- 模块：`nucleus/legs/` 或相关数据处理模块

- 触发时机：数据处理流程中

**修复要求**：
1. 定位所有调用`.append()`但目标是dict的代码位置
2. 修复：要么把数据结构改成list，要么改用dict的正确操作方式（赋值/合并）
3. 添加防御性检查：如果数据结构不对，记录WARNING而不是抛异常
4. 确保修复后不影响正常的数据处理流程

**验收标准**：
- 修复后不再出现`AttributeError: 'dict' object has no attribute 'append'`
- 双腿模块正常工作

### T3 · P1 胃JSON解析容错增强

**问题描述**：框架运行日志中反复出现：
```
[胃] WARNING: PulseStomach JSON策略2(正则提取)失败: JSONDecodeError: Expecting ',' delimiter
```
大模型返回的JSON格式不标准（缺少逗号、冒号等），导致解析失败。

**根因**：
- 大模型返回的JSON经常有格式问题：尾随逗号、缺少引号、多了逗号等
- 当前正则提取策略对格式要求严格
- 失败后没有更好的降级策略

**修复要求**：
1. 增强JSON解析容错能力：
   - 自动修复尾随逗号
   - 自动修复缺少引号的键
   - 自动修复多余的逗号
   - 使用更宽松的解析策略
2. 添加JSON修复工具函数：输入不标准JSON字符串，输出标准JSON
3. 解析失败时的降级策略：提取关键内容（功能描述、步骤等），不完全丢弃
4. 记录失败样本，用于后续优化

**验收标准**：
- 常见JSON格式错误（尾随逗号、缺引号、多逗号）都能自动修复
- 解析成功率提升（对比修复前后）
- 新增单元测试覆盖各种JSON格式错误场景
- 解析失败时不再直接丢弃，而是提取关键内容

### T4 · P1 Windows文件占用问题修复（日志轮转+冷存compaction）

**问题描述**：Windows系统下反复出现：
```
PermissionError: [WinError 32] 另一个程序正在使用此文件，进程无法访问。
```
影响两个地方：
1. **日志轮转失败**：pulse.log → pulse.log.1 时文件被占用
2. **冷存compaction失败**：parquet文件被占用无法compaction

**根因**：
- Windows的文件锁机制比Linux严格
- 多个进程/线程同时打开同一个文件
- 日志轮转时，旧的日志文件还被其他进程/线程写入

**修复要求**：
1. 日志轮转增强：
   - 轮转前先检查文件是否可写
   - 如果被占用，延迟重试（指数退避）
   - 重试N次后仍失败，记录WARNING但不崩溃
   - 考虑使用更好的日志轮转策略（如按大小+按时间）

2. 冷存compaction增强：
   - compaction前检查文件是否被占用
   - 被占用时跳过本次compaction，下次再试
   - 记录哪些文件被跳过了
   - 添加compaction成功率统计

**验收标准**：
- 日志轮转时不再崩溃，被占用时优雅降级
- 冷存compaction被占用时跳过而不是报错
- 新增单元测试模拟文件被占用的场景
- 重试机制有合理的退避策略
