### T1 · P0 L3动态扩缩策略优化（滞回+冷却+平滑）

**问题描述**：
- 6分钟内扩缩10次，平均36秒一次
- worker在3-5之间来回波动
- 每次扩缩都触发池重建，进一步加剧消费不稳定
- 根因：没有滞回区间、没有冷却时间、一次调整跳变太大

**修复要求**：

1. **添加滞回区间（hysteresis）**：
   - 上升阈值：队列 > 30% 才考虑扩容（原来10%就扩）
   - 下降阈值：队列 < 10% 才考虑缩容（原来7%就缩）
   - 中间区间（10%-30%）保持worker数量不变
   - 目的：避免在临界点来回震荡

2. **添加冷却时间**：
   - 上次扩缩后至少60秒内不再调整
   - 目的：给系统稳定下来的时间，避免连续抖动

3. **平滑调整**：
   - 一次只调整1个worker（+1或-1）
   - 不要从3直接跳到5，也不要从5直接跳到3
   - 目的：消费能力平滑变化，不忽高忽低

4. **L2同步检查**：
   - 检查L2是否有同样的扩缩逻辑
   - 如果有，应用同样的优化策略
   - 如果没有，记录说明

5. **配置开关**：
   - 所有新参数都要可配置（config.py）
   - 出问题能一键回退到旧策略

**验收标准**：
- 10分钟内扩缩次数 ≤ 2次（原来10次）
- worker数量波动 ≤ 2（原来3→5→4→3来回跳）
- 冷却时间生效，刚扩完不会马上缩
- 滞回区间生效，中间区间不调整
- 新增单元测试覆盖：上升阈值、下降阈值、冷却时间、平滑调整

### T2 · P1 肝模块异步优化任务类型bug修复

**问题描述**：
```
[肝] ERROR: 异步优化任务异常: '<' not supported between instances of 'float' and 'dict'
```

**根因定位**：
- 模块：organs/body/PulseLiver.py
- 错误：代码在比较大小，但一个值是float，另一个是dict
- 发生时机：异步优化任务执行时

**修复要求**：
1. 定位所有比较操作，确认两边的类型
2. 修复类型不匹配：要么把dict转成数值，要么用正确的比较方式
3. 添加防御性类型检查：比较前先验证类型
4. 记录异常详情：出错时打印两个值的类型和内容，方便排查

**验收标准**：
- 不再出现`'<' not supported between instances of 'float' and 'dict'`
- 异步优化任务正常执行
- 新增单元测试覆盖类型不匹配场景

### T3 · P1 self_inspector方法体定位精度优化

**问题描述**：
- 近500次调用：精确匹配0次 / 偏移试探498次 / 方法名兜底2次
- **精确匹配率0%**
- 说明方法定位能力很差，几乎全靠猜偏移量

**根因定位**：
- 模块：self_inspector相关代码
- 问题：精确匹配逻辑可能有bug，或者方法签名匹配条件太严格

**修复要求**：
1. 分析为什么精确匹配率为0%
2. 修复精确匹配逻辑：
   - 方法名匹配条件放宽（比如支持前缀匹配）
   - 参数数量匹配逻辑修正
   - 装饰器处理（@property、@staticmethod等）
3. 目标：精确匹配率提升到 ≥ 50%
4. 偏移试探作为降级方案保留，但减少使用频率

**验收标准**：
- 精确匹配率 ≥ 50%（原来0%）
- 偏移试探次数减少 ≥ 50%
- 新增单元测试覆盖各种方法签名场景

### T4 · P1 队列消费稳定性优化

**问题描述**：
- 队列深度过高（峰值2045）
- RSS采集太慢（阮一峰54.7s / Solidot 18.9s）
- L3扩缩抖动导致消费能力不稳定

**修复要求**：

1. **RSS采集优化**：
   - 给RSS采集设置超时（比如15秒），超时就跳过
   - 不要等阮一峰那种54秒的，超时直接放弃
   - 记录超时的源，下次降低优先级

2. **消费者并发度提升**：
   - 评估当前worker数量是否够用
   - 如果队列经常积压，适当提高基础worker数量
   - 配合T1的滞回策略，不要频繁抖动

3. **队列优先级**：
   - 对话相关事件优先级最高
   - RSS采集、后台任务优先级低
   - 高峰期先保证对话流畅，后台任务可以排队

4. **积压告警阈值调整**：
   - 当前阈值是多少？是否合理？
   - 调整到更合理的水平，避免误报

**验收标准**：
- RSS采集超时生效，不再等54秒
- 队列深度峰值降低 ≥ 30%
- 对话相关事件不被后台任务堵塞
- 新增单元测试覆盖超时、优先级场景
