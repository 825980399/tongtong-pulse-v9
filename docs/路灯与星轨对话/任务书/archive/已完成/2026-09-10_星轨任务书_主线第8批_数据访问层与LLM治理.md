## 二、任务清单

### 任务1：P2-62 统一数据访问层（核心任务，1.5-2小时）

**问题**：97个文件直接用`open()`读写JSON，84个用`json.dump()`，没有统一的数据访问层。已导致`WinError 32`文件占用错误（ExperiencePool保存失败）。

**要求**：
1. 新建`nucleus/data/DataAccessLayer.py`（或`utils/data_io.py`），提供统一接口：
   - `safe_read_json(path, default=None)`：带异常处理、编码容错、文件锁
   - `safe_write_json(path, data, backup=True)`：原子写（tmp+replace）、自动创建目录、备份
   - `safe_read_text(path, default="")`：文本读取
   - `safe_write_text(path, text)`：文本写入
2. 优先改造**高频写入文件**（至少10处）：
   - `data/experience/experience_pool.json`
   - `data/knowledge/pulse_knowledge_snapshot.json`
   - `data/stream/eye_stream_log.json`
   - `data/qica/*.json`
   - 其他每小时写入超过1次的文件
3. 原子写必须用`tmp + os.replace()`，避免半截写入
4. 写入失败时返回False，不抛异常（与VectorStore的flush一致）
5. 保留原文件的备份（`.bak`），最多保留3个版本

**验收标准**：
- [ ] DataAccessLayer模块创建完成，语法通过
- [ ] 至少10处高频写入改为统一接口
- [ ] 原子写（tmp+replace）实现
- [ ] 异常处理完整（文件不存在/权限错误/磁盘满）
- [ ] 新增至少5个测试用例

### 任务2：P2-71 json.load异常处理补全（45-60分钟）

**问题**：112处`json.load()`没有异常处理，数据文件损坏可能导致崩溃。

**要求**：
1. 扫描全库`json.load()`调用，筛选**核心路径**（配置文件、知识快照、经验池、向量库元数据等）

3. 非核心路径（tmp/、测试脚本）可以不处理
4. 损坏文件备份到`data/corrupted/`目录，文件名加时间戳

**验收标准**：
- [ ] 至少30处核心路径json.load()加了异常处理
- [ ] 损坏文件自动备份

**要求**：
1. 在`config.py`中新增`LLM_CALL_CONFIG`配置块：

   ```python
       "default_model": "deepseek-v4-flash",
       "default_timeout": 30,
       "timeout_by_purpose": {
           "evolution": 60,      # 自主进化（生成补丁）
           "reasoning": 30,      # 推理/对话
           "summary": 15,        # 摘要/压缩
           "classification": 10, # 分类/简单判断
       },
       "enable_rate_limit": True,
       "rate_limit_per_minute": 20,
   }
   ```
2. 改造SafeEvolutionExecutor的3处硬编码model名，改为读配置
3. 统一超时：所有LLM调用方使用`LLM_CALL_CONFIG["timeout_by_purpose"]`，按用途选择
4. 8个不走`api_rate_limiter`的调用方接入限流（至少接入5个核心调用方）
5. 保留`REMOTE_API_CONFIG`原有配置，不破坏现有调用

**验收标准**：
- [ ] LLM_CALL_CONFIG配置块创建完成
