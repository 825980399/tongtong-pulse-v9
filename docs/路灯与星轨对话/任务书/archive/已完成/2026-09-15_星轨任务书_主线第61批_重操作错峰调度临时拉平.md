## 一、批次背景

### 1.1 问题描述

框架运行日志监测发现**负载尖峰明显**，队列深度频繁达到1000+，锁等待平均59.9ms，性能告警集中在T+20-40分钟。

星轨对框架全部定时任务进行深度分析，定位到根因：**心跳驱动任务的公倍数重叠**。

### 1.2 根因分析

#### 心跳驱动任务清单（6个）

| 任务 | 心跳周期 | 实际周期 | 资源消耗 |
|------|----------|----------|----------|
| 血管健康巡检 | 3次 | 30秒 | 低 |
| 肾脏遗忘扫描 | 5次 | 50秒 | 中 |
| 动机循环 | 6次 | 60秒 | 中 |
| 代码学习 | 15次 | 150秒 | 高 |
| 定期测试 | 100次 | 1000秒 | 高 |
| 代码审视 | 500次 | 5000秒 | 高 |

#### 公倍数重叠问题

6个任务的周期最小公倍数是**1500次心跳**（T+250分钟），此时所有任务同时触发。

**重叠频率统计（每小时）**：
- 3个及以上任务同时触发：**24次**（平均每2.5分钟一次）
- 4个及以上任务同时触发：**12次**（平均每5分钟一次）
- 5个任务同时触发：每50分钟一次（第300、600、900...次心跳）

#### 代码学习内部三任务同步问题

代码学习（PulseCodeLearner）内部有三个任务共用同一个`_heartbeat_count`：
- 代码学习：每15次心跳
- 定期测试：每100次心跳
- 代码审视：每500次心跳

虽然`_heartbeat_count`有随机初始值（1-499），但三个任务共用计数器，导致在第500次心跳时三个任务同时触发。

#### 独立线程任务固定首跑问题

| 任务 | 周期 | 首跑延迟 | 问题 |
|------|------|----------|------|
| 参数补丁自动应用 | 5分钟 | 立即（0秒） | 恰好与第30次心跳（4个任务重叠）重合 |
| 自主进化循环 | 30分钟 | 固定1800秒 | 恰好与第180次心跳（4个任务重叠）重合 |
| 记忆验证闭环 | 6小时 | 立即（0秒） | 与启动高峰期重叠 |

#### 典型灾难性重叠场景

```
第180次心跳（T+30分钟）：
  ├── 血管健康巡检（3×60）
  ├── 肾脏遗忘扫描（5×36）
  ├── 代码学习（15×12）
  ├── 动机循环（6×30）
  └── 自主进化第一轮（独立线程，固定30分钟首跑）
  → 5个重操作同时进行！
  → 这正是日志中T+20-40分钟性能告警集中的直接原因
```

### 1.3 长期架构思路（用户提出，本批次仅实施阶段1）

用户提出三层架构的长期重构方向：

1. **第一层：本能运行任务** —— 按框架启动时间线平滑安排（代码学习、自主进化、记忆验证等）
2. **第二层：生命特征任务** —— 由心脏驱动，情绪不同心跳频率不同，处理时间速度不同（动机循环、血管巡检、肾脏扫描等）
3. **第三层：统一调度协调器** —— 总体平衡，负载感知、优先级分层、动态调整

**实施路线图**：
- 阶段1（第61批，本批次）：临时拉平 —— 为重任务添加随机初始计数/偏移
- 阶段2（第62-63批）：本能任务时间线平滑 —— 统一启动时间线分配
- 阶段3（第64-65批）：心跳驱动生命特征 —— 情绪→心跳频率→任务频率联动
- 阶段4（第66批以后）：统一调度协调器 —— 全局统一调度

**本批次仅实施阶段1**，改动小、风险低、效果明显，不改变现有架构。

## 二、任务清单

### T1 · P1 代码学习内部三任务分离偏移（核心修复）

**债务ID**：P1-新（重操作错峰调度）

**问题描述**：
- PulseCodeLearner内部三个任务（代码学习、定期测试、代码审视）共用同一个`_heartbeat_count`
- 虽然`_heartbeat_count`有随机初始值（1-499），但三个任务同步触发
- 在第500次心跳时，代码学习（15×33=495，第500次时是第34轮）、定期测试（100×5）、代码审视（500×1）同时触发
- 三个都是高资源消耗任务，同时触发导致严重负载尖峰

**修复要求**：

1. **为定期测试添加独立随机偏移**（`organs/brain/PulseCodeLearner.py`）：
   - 新增实例变量：`self._test_heartbeat_offset = random.randint(0, 99)`
   - 触发条件从 `self._heartbeat_count % self._test_run_interval == 0`
   - 改为 `(self._heartbeat_count + self._test_heartbeat_offset) % self._test_run_interval == 0`
   - 偏移范围0-99次心跳（0-16.5分钟），确保与代码学习错开

2. **为代码审视添加独立随机偏移**：
   - 新增实例变量：`self._review_heartbeat_offset = random.randint(0, 499)`
   - 触发条件从 `self._heartbeat_count % self._code_review_interval == 0`
   - 改为 `(self._heartbeat_count + self._review_heartbeat_offset) % self._code_review_interval == 0`
   - 偏移范围0-499次心跳（0-83分钟），确保与代码学习、定期测试都错开

3. **代码学习保持现有随机初始**：
   - `self._heartbeat_count = random.randint(1, 499)` 保持不变
   - 代码学习触发条件 `self._heartbeat_count % _learn_interval == 0` 保持不变

4. **添加灰度开关**（config.py）：
   - 新增配置：`ENABLE_CODE_LEARN_TASK_OFFSET = True`（默认开）
   - 关闭时偏移量=0，复现旧行为（三任务同步触发）
   - 在PulseCodeLearner.__init__中读取配置，关闭时offset设为0

5. **添加启动日志**：
   - 日志格式：`[代码学习] 任务错峰偏移: 代码学习=随机初始{heartbeat_count}, 定期测试=偏移{test_offset}次心跳, 代码审视=偏移{review_offset}次心跳`
   - 便于运维确认偏移是否生效

**验收标准**：
- 定期测试和代码审视有独立的随机偏移
- 三个任务不再在同一心跳点同时触发
- 灰度开关关闭时复现旧行为
- 启动日志显示偏移量

### T2 · P1 独立线程任务随机首跑延迟（核心修复）

**债务ID**：P1-新（重操作错峰调度）

**问题描述**：
- 参数补丁自动应用：立即首跑（0秒），恰好与第30次心跳（4个任务重叠）重合
- 自主进化循环：固定1800秒首跑，恰好与第180次心跳（4个任务重叠）重合
- 记忆验证闭环：立即首跑，与启动高峰期重叠
- 固定首跑时间导致与心跳驱动任务的灾难性重叠

**修复要求**：

1. **参数补丁自动应用随机首跑延迟**（`main.py`第429行附近）：
   - 当前：`self.param_patch_manager.start_auto_apply(interval=300)`
   - 修改为：先sleep随机时间，再启动自动应用
   - 实现方式：在`start_auto_apply`调用前添加`time.sleep(random.uniform(60, 240))`（1-4分钟随机延迟）
   - 或者修改`ParamPatchManager.start_auto_apply`方法，添加`initial_delay`参数
   - 推荐方式：修改`start_auto_apply`方法签名，添加`initial_delay=0`参数，在main.py调用时传入随机值

2. **自主进化循环随机首跑延迟**（`main.py`第2099行附近）：
   - 当前：`_time.sleep(1800)`（固定30分钟）
   - 修改为：`_time.sleep(random.uniform(1200, 2400))`（20-40分钟随机延迟）
   - 随机范围 centered on 30分钟，±10分钟波动
   - 确保不会与第180次心跳（T+30分钟）精确重合

3. **记忆验证闭环随机首跑延迟**（`main.py`第315行附近）：
   - 当前：`self.node_pool.start_memory_verification_loop(interval_hours=...)`立即启动
   - 修改为：添加随机初始延迟
   - 实现方式：修改`start_memory_verification_loop`方法，添加`initial_delay_hours=0`参数
   - 在main.py调用时传入`initial_delay_hours=random.uniform(5/60, 30/60)`（5-30分钟随机延迟）
   - 或者在方法内部首跑前sleep随机时间

4. **添加灰度开关**（config.py）：
   - 新增配置：`ENABLE_RANDOM_INITIAL_DELAY = True`（默认开）
   - 关闭时所有首跑延迟=0，复现旧行为
   - 在main.py中读取配置，关闭时使用固定延迟（参数补丁0秒、自主进化1800秒、记忆验证0秒）

5. **添加启动日志**：
   - 参数补丁：`[参数补丁] 自动应用线程已启动（首跑延迟{delay:.0f}秒，每5分钟检查）`
   - 自主进化：`[自主进化] 循环已启动（首跑延迟{delay:.0f}秒，每30分钟一轮）`
   - 记忆验证：`[记忆验证] 闭环已启用（首跑延迟{delay:.0f}秒，每{interval}小时自检）`

**验收标准**：
- 三个独立线程任务都有随机首跑延迟
- 自主进化不再固定在T+30分钟首跑
- 参数补丁不再立即首跑
- 灰度开关关闭时复现旧行为
- 启动日志显示首跑延迟
