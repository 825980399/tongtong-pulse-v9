## T-85a：本地学习尝试通道（核心）

**现状**（`SafeEvolutionExecutor._cooldown_classify` L1542-1550）：
```python
if _t not in _local_fixable_types:
    return "本地无规则·转LLM"  # 直接转，本地零参与
```

**问题**：Traceback/ERROR/cross_module_singleton_call/long_method 等类型，本地完全不参与，直接转LLM。本地机制失去学习机会。

**目标**：对未分类问题，本地先尝试**低风险保守修复**，验证通过才应用，不通过再转LLM。形成"尝试→验证→学习→提升"闭环。

**改法**：
1. 在 `_cooldown_classify` 的"本地无规则·转LLM"分支前，增加**本地学习尝试通道**：
   - 对未分类问题，本地生成**保守低风险修复方案**（不是文本替换，而是：
     - 加 WARNING 日志（bare except 里补日志）
     - 加 try-except 包裹（裸调用加保护）
     - 加 timeout 保护（无超时调用加 timeout）
     - 加 None 检查（可能 None 的调用加保护）
   - 生成后跑本地验证（语法检查 + 简单 smoke test）
   - 验证通过 → 标记为"本地学习尝试"，走审批/应用流程
   - 验证不通过 → 转LLM，同时记录尝试结果到学习日志
2. **学习记录**：每次尝试（无论成功失败）都记录到 `data/patches/local_learning_attempts.jsonl`，字段：`issue_type/file/method/attempted_fix/result(success/failed)/llm_fallback(bool)`
3. **不直接应用**：本地学习尝试的补丁，默认不自动应用（走审批），但标记为 `learning_attempt=true`，便于长期跟踪学习效果

**先红后绿**：
- 新增测试：构造一个 Traceback 类型问题，断言本地尝试通道被触发（生成保守修复方案 + 记录学习日志）；
- 新增测试：本地尝试失败时，断言正确转LLM且记录 `llm_fallback=true`；
- 改前：未分类问题直接转LLM（红）；改后：先尝试再转（绿）。

## T-85b：D84-1 reprobe 接线

**现状**：第51批设计的最高优先级判据 `reprobe_verdict` 在运行时从未写入——`active_reprobe()` 的调用方只有 `tools/reprobe_patches.py` 与只读的 `quality_score_v2.py`；history 60条字段在、值全 null。

**改法**：
1. 在补丁**应用后**（`apply_split` 成功后），触发一次 `active_reprobe`：
   - 重新跑补丁位置的错误计数
   - 对比 baseline_errors 和 post_apply_errors
   - 把结果写入 `reprobe_verdict`（true/false/None）
2. 触发时机：补丁应用后、下一轮 evolution round 开始前
3. 不阻塞主流程：reprobe 失败不影响补丁应用，只记录 None

**先红后绿**：
- 新增测试：应用一个补丁后，断言 `reprobe_verdict` 被写入（不再恒 null）；
- 改前：`reprobe_verdict` 恒 null（红）；改后：正确写入（绿）。

## T-85c：D84-2 口径调整——不可判定补丁移出分母

**现状**：`real_fix_rate = problem_fixed=True的补丁数 / 总数`，不可判定（None）补丁计入分母，导致指标永远接近0%。

**改法**：
1. `real_fix_rate` 计算时分母改为 `problem_fixed in (True, False)` 的补丁数（即可判定补丁数）；
2. 同时新增 `verifiable_rate = 可判定补丁数 / 总数`，单独展示有多少补丁是可判定的；
3. 不改 `fix_rate`（PatchAutoApprover 用的口径），只改 `real_fix_rate` 的计算。

**先红后绿**：
- 新增测试：构造64条补丁，其中1条 problem_fixed=True、1条 False、62条 None；
- 改前：real_fix_rate = 1/64 ≈ 1.6%；
- 改后：real_fix_rate = 1/2 = 50%，verifiable_rate = 2/64 ≈ 3.1%。

## T-85d：D84-4 放开本地补丁自动应用（LLM补丁仍人工审批）

**现状**：`auto_apply_enabled=False`，所有补丁都不自动应用，包括本地生成的低风险补丁。

**改法**：
1. **只放开本地生成补丁的自动应用**：`source="local" && confidence>=0.9 && risk_level="low"` 的补丁，自动应用；
2. **LLM生成的补丁仍需人工审批**：`source="llm"` 的补丁，即使 auto_approved=true，也不自动应用；
3. 应用前自动备份（已有机制，PatchManager.py:1849-1860）；
4. 应用后自动触发 reprobe（T-85b）。

**先红后绿**：
- 新增测试：本地低风险补丁，断言自动应用；
- 新增测试：LLM生成补丁，断言不自动应用（仍待审批）；
- 改前：所有补丁都不自动应用（红）；改后：本地低风险自动应用、LLM仍审批（绿）。
