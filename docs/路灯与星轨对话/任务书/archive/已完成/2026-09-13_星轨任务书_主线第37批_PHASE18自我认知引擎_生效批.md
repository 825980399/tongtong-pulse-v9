### T2（P0）★ P2-211 产出-消费配对器磁盘枚举通道

**预估工时**：3-4小时
**需重启框架验证**：否（可通过单元测试+独立脚本验证）

**任务描述**：
当前ProductionConsumptionMatcher只解析源码AST中的路径字面量，导致磁盘2321个数据文件仅覆盖17个（0.73%）。需增加磁盘枚举通道，与现有源码通道求并集。

**具体要求**：
1. 增加`_iter_disk_data_files()`方法，按扩展名枚举磁盘数据文件（.json/.jsonl/.npz/.db/.log/.txt等）
2. 排除规则：__pycache__/、.bak*/、tmp/、.git/、node_modules/等
3. 与现有源码通道（`_iter_scan_files()`）求并集，去重
4. 磁盘枚举的文件标记为`source="disk"`，源码解析的标记为`source="source"`
5. 报告中区分显示："源码路径X个 / 磁盘文件Y个 / 并集Z个"
6. 性能控制：磁盘枚举应快速（仅文件名，不读内容），大目录可配置深度限制
7. 配置项：`PRODUCTION_CONSUMPTION_SCAN_DISK=True`（默认True），`PRODUCTION_CONSUMPTION_SCAN_EXTENSIONS`（可配置扩展名列表）

**验收标准**：
- [ ] 磁盘枚举通道可正常枚举data/目录下的数据文件
- [ ] 与源码通道求并集后覆盖率>80%（以data/目录为基准）
- [ ] 排除规则生效（__pycache__/.bak/tmp等不被枚举）
- [ ] 报告中区分源码路径和磁盘文件
- [ ] 配置项存在且可通过开关关闭磁盘枚举
- [ ] 单元测试：临时迷你工程验证磁盘枚举正确性
- [ ] pytest全量通过，ruff F=0

**风险提示**：
- 磁盘枚举可能发现大量"有产出无消费"的文件，需确保报告可读性（可按大小/目录分组）
- 性能：data/目录可能较大，枚举应控制在1秒内

### T3（P1） P2-212 路径解析与误报收敛

**预估工时**：2-3小时
**需重启框架验证**：否（可通过单元测试验证）

**任务描述**：
当前配对器11条"疑似无消费"中7条指向不存在的文件（动态命名模板/相对路径偏差），误报率64%，超任务书20%阈值。需修复路径解析逻辑，降低误报率。

**具体要求**：
1. 路径解析：将源码中的相对路径解析为绝对路径（基于项目根目录）
2. 动态路径模板识别：对包含`{ts}`/`{timestamp}`/f-string时间戳等动态命名的路径，标记为"动态路径"，不直接判定为"无消费"
3. 不存在路径单列类别：对解析后仍不存在的路径，标记为"路径未命中"（path_not_found），而非"疑似无消费"（no_consumer）
4. 有效"无消费"判定：仅对**实际存在且确无消费**的文件标记为no_consumer
5. 误报率目标：修复后误报率<20%（以第36批发现的11条为基准重新评估）
6. 日志中增加路径解析统计："解析路径X个 / 动态路径Y个 / 路径未命中Z个 / 有效无消费W个"

**验收标准**：
- [ ] 相对路径可正确解析为绝对路径
- 动态路径模板被正确识别并标记
- 不存在路径被标记为"路径未命中"而非"疑似无消费"
- 修复后误报率<20%（以第36批11条为基准）
- 日志中包含路径解析统计
- 单元测试：各种路径形态（相对/绝对/动态/不存在）的正确分类
- pytest全量通过，ruff F=0

**风险提示**：
- 路径解析需考虑Windows/Linux路径分隔符差异
- 动态路径识别可能漏判某些复杂的路径拼接方式，保守策略是"无法判定则标记为待确认"
