## T-88a（P0）：LLM补丁相似度 0.03 根因定位

### 任务
定位 LLM 生成的补丁为什么和原文相似度只有 0.03。

### 需要定位的问题
1. **输入素材是什么**：LLM 修复调用时，输入的"原始代码"是什么？
   - 是真实方法体代码？
   - 还是只有 ERROR 消息文本？
   - （之前日志显示"方法体为空 → 改用文件/ERROR消息作为对比输入"）

2. **LLM prompt 要求什么**：prompt 是要求"生成完整修复后的代码"，还是"生成 diff 补丁"？
   - 如果要求生成完整代码，但验证时用相似度对比，那格式不匹配

3. **补丁格式是什么**：PatchManager 期望的补丁格式是什么？
   - 是 unified diff？
   - 还是整个方法的替换代码？
   - 相似度对比的是哪两段代码？

4. **为什么相似度这么低**：0.03 意味着几乎完全不匹配
   - 是 LLM 生成了全新代码？
   - 还是输入素材本身就不对？

### 改法方向（定位后定）
根据定位结果选择：
- 如果是输入素材问题：把真实代码片段喂给 LLM
- 如果是 prompt 问题：调整 prompt，要求输出补丁格式而非完整代码
- 如果是格式不匹配：调整验证逻辑，或调整 LLM 输出格式

### 验收
- 至少 1 个 LLM 补丁通过验证（相似度 ≥ 0.5）
- [进化健康] 修复率 脱离 0.0%
