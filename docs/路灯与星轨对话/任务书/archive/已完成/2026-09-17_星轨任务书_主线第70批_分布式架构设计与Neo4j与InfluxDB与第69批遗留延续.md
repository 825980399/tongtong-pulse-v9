**问题描述**：
- 当前节点关联网络存储在每个节点的`linked_nodes`字段（列表）
- 查询多跳关联（如A→B→C→D）需要逐个加载节点，效率极低
- 12295节点时关联查询尚可接受，1000万节点时将完全不可用
- Neo4j是专业图数据库，支持Cypher查询语言，亿级节点毫秒级多跳查询
- 第70批先做设计和基础封装，不立即迁移生产数据（渐进式）

- `config.py`（新增Neo4j配置）

**具体修改点**：

#### 1.1 Neo4j连接与基础封装

1. **Neo4jStore类**：
   - `connect(uri, user, password)`：连接Neo4j数据库
   - `close()`：关闭连接
   - `is_available()`：检查连接状态
   - 连接池管理（复用连接，避免频繁创建）

2. **节点CRUD**：
   - `add_node(node_id, properties)`：添加节点（带属性）
   - `update_node(node_id, properties)`：更新节点属性

3. **关系CRUD**：
   - `add_relationship(from_id, to_id, rel_type, properties)`：添加关系
   - `update_relationship(from_id, to_id, rel_type, properties)`：更新关系属性
   - `remove_relationship(from_id, to_id, rel_type)`：删除关系
   - `get_relationships(node_id, direction)`：获取节点的所有关系

#### 1.2 图查询接口

1. **多跳关联查询**：
   - `query_multi_hop(node_id, max_depth, top_k)`：查询N跳关联节点

2. **Cypher查询**：
   - `execute_cypher(query, parameters)`：执行自定义Cypher查询

   - 查询优先使用Neo4j，不可用时回退到节点内linked_nodes

2. **批量同步工具**：
   - `sync_from_nodes()`：从现有节点批量同步关联网络到Neo4j
   - 增量同步：节点变更时自动同步到Neo4j
   - 同步进度监控和断点续传

**债务ID**：P1-InfluxDB时序库（当前节点访问/激活/修改等时序数据无专门存储，无法做趋势分析和异常检测）

**问题描述**：
- 当前节点的访问次数、激活时间、修改时间等时序数据存储在节点字段内（activation_count, last_activated等）
- 无法查询历史趋势（如某节点过去7天的访问频率变化）
- 无法做异常检测（如某节点访问量突然激增）
- InfluxDB是专业时序数据库，支持高吞吐写入、高效时间范围查询、自动降采样
- 第70批先做设计和基础封装，不立即迁移生产数据

**修改文件**：
- 新增：`nucleus/timeseries_store/influxdb_store.py`（InfluxDB时序存储封装）

- `nucleus/knowledge_access_layer.py`（KAL增加时序查询接口）
- `config.py`（新增InfluxDB配置）

**具体修改点**：

#### 2.1 InfluxDB连接与基础封装

1. **InfluxDBStore类**：
   - `connect(url, token, org)`：连接InfluxDB
   - `close()`：关闭连接

   - `query_count(measurement, tags, start, end)`：统计数量

**问题描述**：
第69批完成了冷热分离、FAISS集成、降频接线、KAL迁移的基础框架，但有3个实际接入点需完善：

2. fast_ops.py/GPUCore.py FAISS对接——T2实现了faiss_store.py，但实际向量检索路径（fast_ops.fast_vector_search）仍用暴力余弦
3. KAL实际调用点替换——T4只添加了helper方法，实际业务代码仍直接访问node_pool

**修改文件**：
- `nucleus/mnemosyne/PulseSnapshot.py`（冷热加载完善）
- `nucleus/fast_ops.py`（FAISS对接）
- `organs/body/PulseStomach.py`（KAL实际调用点替换）
- `organs/body/PulseLiver.py`（KAL实际调用点替换）
- `organs/body/PulseKidney.py`（KAL实际调用点替换）
- 可能涉及：`nucleus/GPUCore.py`（GPU路径FAISS对接）

**具体修改点**：

#### 4.1 PulseSnapshot冷热加载完善

1. **load()方法改造**：
   - 优先加载L1热节点到内存（快速启动）
   - L2/L3节点只加载元数据（node_id+evol_level+文件位置）
   - 后台异步预加载高频L2节点到PulseNodePool的温缓存
   - 记录加载来源和加载耗时

2. **save()方法改造**：
   - L1热节点：高频保存（每10分钟）
   - L2温节点：中频保存（每30分钟）
   - L3冷节点：低频保存（每小时或变更超过阈值）
   - 变更跟踪：只保存有变更的节点

3. **与PulseNodePool协同**：
   - PulseSnapshot负责持久化（Parquet读写）
   - PulseNodePool负责内存管理（冷热缓存）
   - 两者通过KAL或直接调用协同

#### 4.2 fast_ops FAISS对接

1. **fast_vector_search()改造**：
   - 优先使用FAISSVectorStore.search()
   - FAISS不可用或索引未构建时，回退到暴力余弦（_brute_force_cosine）
   - 检索结果后处理：过滤已删除节点、按相似度排序、返回TopK

2. **索引初始化**：
   - 框架启动时，从Parquet加载所有节点向量，构建FAISS索引
   - 索引构建在后台线程执行，不阻塞启动
   - 索引构建完成前，检索回退到暴力余弦
   - 索引定期保存到磁盘，启动时快速加载

3. **增量更新**：
   - 新节点创建时，自动编码并添加到FAISS索引
   - 节点内容更新时，自动重新编码并更新FAISS索引
   - 节点删除时，自动从FAISS索引移除
   - 批量更新支持（减少索引更新开销）

4. **GPU路径对接（可选）**：
   - 如果有GPU且faiss-gpu可用，自动使用GPU加速
   - GPU不可用时回退到CPU
   - 与现有GPUCore.py的batch_cosine_gpu方法集成

#### 4.3 KAL实际调用点替换

1. **胃模块**：
   - 知识消化时的节点查询：从直接访问node_pool改为调用kal.get_node()
   - 关键词搜索：从直接遍历改为调用kal.search_by_keywords()

## 三、技术要求和约束

### 3.1 不破坏现有逻辑

1. **向后兼容**：所有修改必须向后兼容，不破坏现有功能
2. **配置开关**：所有新功能有配置开关，可关闭回退到旧机制
   - `ENABLE_NEO4J_GRAPH_STORE=False`可关闭Neo4j
   - `ENABLE_INFLUXDB_TIMESERIES=False`可关闭InfluxDB
   - `ENABLE_DISTRIBUTED=False`可关闭分布式
   - `ENABLE_KAL_MIGRATION=False`可关闭KAL迁移

4. **双写过渡期**：启用新存储时，同时写旧存储和新存储，查询优先新存储，不可用时回退

### 3.2 性能要求

1. **PulseSnapshot冷热加载**：启动时间降低50%以上（只加载L1热节点）

3. **KAL调用点替换**：性能不低于直接访问（有LRU缓存，应该更快）

### 3.3 代码质量要求

1. 所有新增代码有详细注释
2. 所有公共方法有docstring
3. 遵循现有代码风格和命名规范
4. 新增测试覆盖率>80%
5. 不引入新的重依赖（neo4j/influxdb客户端是轻量级库，默认不安装）

### 3.4 安全要求

1. 不硬编码任何密钥或敏感信息（Neo4j/InfluxDB密码从环境变量读取）
2. 文件操作有异常处理
3. 数据库连接有超时和重试机制
4. 配置开关默认关闭，避免意外启用
