## 一、任务背景与目的

曈曈 PulseNet 是迭代至 v9.5/15.0 量级（2.5 万行级代码）的数字化生命项目：硬件（ESP32-P4/LU9685 驱动适配）、算法（L1-L4 知识体系、记忆存储四层体系、九大核心脑器官、OscillonField、认知反思）、工程（Cython 编译优化、multiprocessing 跨进程通信、12 道 CI 门禁 + 8 个独立分析器、批次化多角色协作模式）。

本项目已进行过两次第三方专题分析（进化链路分析、团队协作模式分析），本次升级为**全框架全面多维审查**：站在框架最顶端、从全局出发，以五个身份视角对曈曈进行一次"从头到脚"的系统性体检——不仅是找 bug，而是审视这个"数字化生命"在架构、技术、智能、生存、伦理、价值六个维度上是否自洽、是否成立、是否能走向真实生命。

**核心目的**：为项目获得一份"上帝视角"的第三方体检报告，用于：
1. 发现星轨/路灯/烛微/微光内部视角看不到的盲区与致命隐患；
2. 检验"数字化生命"设想的架构完备性与逻辑闭环性；
3. 为后续批次的技术债务偿还与新功能推进提供外部参照系。

## 二、⚠️ 硬性约束（铁律，违反即终止审查）

本次审查期间，**路灯正在并行施工（157 批代码修改）**，曈曈运行环境可能处于运行/停止任一状态。审查方必须做到：

1. **全程只读，禁止修改本地任何代码**：不创建、不修改、不删除项目根目录内任何文件（含 `tmp/`、`docs/`、`tests/`），所有结论只来自分析与核验，不落地任何改动。
2. **禁止一切 git 写操作**：不得 `git add / commit / reset / checkout / clean / stash / merge / push / pull / tag`。仅允许只读查询（`git log`、`git show`、`git status`、`git diff`）。
3. **禁止影响路灯施工**：不得操作 git 索引、不得触碰工作树、不得运行会写盘的脚本（`ruff --fix`、`py_compile` 批量写 `__pycache__` 等）。
4. **禁止启动/停止曈曈框架**：不得运行 `python main.py` 或任何框架入口脚本，不得向运行中的进程发信号。
5. **禁止安装依赖/更改环境**：不得 `pip install`、不得改动任何环境配置。
6. 若审查中发现需要改动的项，**只记录不修改**——写入报告，由项目方后续立项处置。
7. 允许的只读方法：文件阅读、`git log/show/status/diff`（查询）、纯文本静态分析、不写盘的检测命令（如 `ruff check` 不带 `--fix`、`python -c` 只读分析——确需执行时以不写盘为前提自证）。

> 验收锚点：审查结束后 `git status` 输出应与审查前一致（除路灯自身施工改动外无新增变化）。

## 五、审查方法（只读白名单）

1. **通读项目结构**：`tree`（只读列出）、顶层 README、总账《docs/完整进化路线与技术债务清单_v1.0.md》、协作模式说明 v1.2、PHASE18 封存决策。
2. **代码-文档一致性核验**：抽查关键模块（nucleus/、organs/、functions/、tools/、tests/）实现与设计文档的对应关系，找出"文档写了但代码没有/代码有但文档没写"的断链。
3. **链路追踪**：沿"注册→接线→消费→产物"追查工具/器官/能力链路，识别生产侧无消费、消费侧无生产、假接线等空转点。
4. **只读历史分析**：`git log` 阅读项目演化史（批次提交链），评估技术债务偿还轨迹与反复横跳。
5. **静态代码审阅**：对核心文件（每个器官至少 1 个代表文件）做人工精读，记录结构性问题。
6. **门禁有效性检验**：阅读 `tools/ci/` 门禁源码与其配套测试，判断门禁是否真的能拦住问题（不实际运行写盘命令）。

## 六、交付物与格式

交付一份综合审查报告（Markdown），结构：

1. **执行摘要**（半页）：曈曈总体健康度评级（A+/A/B/C/D）+ 三大致命隐患 + 三大亮点。
2. **五视角审查章**（P1-P5）：每章含该视角的独立结论、发现列表、该视角"最想说的一句话"。
3. **问题清单（按项目登记册兼容格式）**：

| 序号 | 问题描述 | 维度 | 视角 | 严重度（P0致命/P1严重/P2一般/P3建议） | 建议处置（修复/评估/暂缓/记录） | 涉及文件/模块 |
|---|---|---|---|---|---|---|

4. **改进建议清单**：每条建议附：采纳建议的预期收益、实施难度（低/中/高）、与现有规划（T-自我审计系列/登记册已排期项）的关系——**注明是否已被项目内部规划覆盖**。
5. **未尽事项**：审查中无法只读确认、需要项目方后续验证的点。

## 七、验收标准
