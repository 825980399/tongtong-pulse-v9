> 性质：运行态核验（趁框架活体期采集真实运行数据）——补静态分析覆盖不到的运行态盲区

---

## 一、为什么现在做

第三方独立复核 §8 局限明确：**运行态/数据面不可判**（依赖 data/、活体窗、日志、真实 token/网络的项无法静态证实或证伪）。当前框架**正在活体运行**（小林已启动，活体窗开启）——这是 148-154 批以来难得的真实运行窗口，静态分析标"待活体核验"的项，此刻可以拿到真证据。

## 二、执行纪律（硬约束）

1. **全程只读采集**：不写 `data/`、不重启/停止框架、不手动改配置；只读进程/日志/指标/内存
2. **与路灯 T155-3 共享同一活体期**：不干扰其观测；采集时标注**观测时段起止**（如 `09-30 13:2x~13:5x`）
3. **双轨独立**：烛微与微光**各自独立**完成分析报告（互不参考），然后**互相阅读对方报告**，输出差异表（哪些判断不同、证据谁硬）
4. 数字附证据（命令/文件路径/行号/采样时刻）

## 三、分析范围（各节点核对）

### A · 运行态基础指标
- 进程/线程数、内存占用（工作集）、CPU（如有）
- 队列深度实态：NodePool / experience_pool / Stomach / CodeLearner 等节点队列，对照 `QUEUE_DEPTH_THRESHOLD_MEDIUM/HIGH/CRITICAL = 500/1500/3000`
- 心跳/告警/消费率：ReportBus、告警消费者触发实态、报告落盘 `data/reports/`

### B · 运行态契约核对（静态标"待活体"项逐件取证）
- **P2-43 ANN**：faiss 大规模召回实态（还是只走小规模/懒加载路径？）
- **Parquet**：boot 物化是否成功（141 批 D141-5"boot#6 物化失败"是否复现/已愈）
- **InfluxDB**：真实落库 or 仍 mock（`ENABLE_INFLUX*` 实态）
- **KAL / 语义缓存 0.85 阈值 / face_welcome / 自适应降频**：活体期是否有真实触发证据
- **经验库防污染 / 静默 except 治理**：运行日志是否有污染告警/残留
- **LLM 留存**：call_recorder 留存率/依赖度实态

### C · 红数复测（Q155-5 合并）
- 若路灯 T155-3 已覆盖则引用其口径；否则在当前 HEAD 上做一次全量 pytest 复测（记录环境/污染说明）

### D · 第三视角新观察（每轨 ≥1 条）
- 各自独立发现一个"静态分析看不出来"的运行态问题/异常（如线程泄漏、告警风暴、队列堆积特征）
