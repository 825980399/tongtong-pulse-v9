## 〇、批次背景

第14批新建了EventBus.py（582行，28例测试），但**生产代码中没有任何事件发布调用**（所有publish都在测试文件中），`ENABLE_EVENT_BUS=False`，事件总线处于"建而不用"状态。

本批次做**旁路监听试点**：在关键器官的关键路径上添加**只读旁路事件发布点**（不改变现有逻辑，只在节点发出事件），同时创建**EventTap旁路监听器**（订阅全部事件，只记录/统计，不产副作用）。

这是P2-63（事件总线）的**真正完成**，也是PHASE18器官关联图谱的**动态数据源铺垫**。

### ★红线（必须遵守）

1. **不改变器官现有通信方式**：InfoField / 直接调用照旧，事件发布是**额外旁路**，不参与业务逻辑
2. **不改变现有业务逻辑**：只在关键节点插入1-2行事件发布代码，不修改任何条件分支、返回值、状态变更
3. **EventTap只记录不产副作用**：监听器只做统计/计数/可选导出，绝不调用任何器官方法、不修改任何状态
4. **最小侵入**：每个器官的修改控制在5行以内（不含import和守卫）
5. **灰度开关**：所有新增能力必须有独立开关，默认True但可随时关闭回退

## 一、任务1：创建旁路监听器 EventTap（新建文件）

### 文件
`nucleus/events/EventTap.py`（新建）

### 功能要求

1. **订阅全部事件**：调用 `get_event_bus().subscribe("**", self._on_event, priority=EventPriority.LOW)`
   - 使用LOW优先级，确保业务处理器先执行，EventTap最后接收
2. **事件统计**：
   - 按事件名分组计数（`dict[str, int]`）
   - 按来源(source)分组计数
   - 按优先级分组计数
   - 总事件数、最近100条事件的环形缓存
   - 事件时间间隔统计（最小/最大/平均间隔）
3. **可选导出**：`export_stats(path: str)` 导出统计到JSON文件（默认不自动导出，由调用方触发）
4. **性能保护**：
   - `_on_event` 只做轻量级计数，不做任何IO操作
   - 环形缓存上限1000条，超出丢弃最旧
   - 统计字典无界增长保护：事件名超过500种时打WARNING并停止新增分类（归入`__other__`）
5. **线程安全**：所有统计操作加锁（`threading.Lock`）
6. **单例获取**：`get_event_tap()` 函数返回单例
7. **开关**：`ENABLE_EVENT_BUS_TAP`（读config，默认True），关闭时`_on_event`直接return

### 验收标准
- EventTap能正确订阅并统计事件
- 1000次事件发布后统计准确，无内存泄漏
- 开关关闭时零开销（直接return）
- 导出的JSON格式正确、可解析

## 二、任务2：PulseCortex 旁路事件发布点

### 文件
`organs/brain/PulseCortex.py`

### 事件发布点（2个）

1. **对话开始**：在对话处理入口（`_process_dialog`或等效方法的开头）发布
   ```python
   if ENABLE_CORTEX_EVENT_TAP:
       get_event_bus().publish(
           "cortex.dialog.start",
           payload={"correlation_id": cid, "question_len": len(question)},
           source="PulseCortex",
           priority=EventPriority.LOW,
       )
   ```

2. **对话结束**：在对话处理返回前发布
   ```python
   if ENABLE_CORTEX_EVENT_TAP:
       get_event_bus().publish(
           "cortex.dialog.end",
           payload={"correlation_id": cid, "duration_ms": duration_ms, "answer_len": len(answer)},
           source="PulseCortex",
           priority=EventPriority.LOW,
       )
   ```

### 要求
- 只发布，不改变任何现有逻辑
- 发布代码放在try/except中，任何异常只记DEBUG不影响业务（`_CORE_FILES`静默pass护栏要求记日志）
- 开关：`ENABLE_CORTEX_EVENT_TAP`（默认True）
- import：`from nucleus.events.EventBus import get_event_bus, EventPriority`（放在文件头部import区，注意E402）

### 验收标准
- 对话开始/结束时EventTap能收到对应事件
- 关闭开关后零发布、零影响
- 发布异常不影响对话正常返回

## 八、注意事项

1. **PulseInnerWorld.py的"不要碰"标注**：本批不涉及PulseInnerWorld.py，只碰PulseCortex/PulseLiver/PulseStomach。如果PulseCortex.py也有类似标注，按最小侵入原则处理并在交付报告中显式标注
2. **事件命名规范**：统一使用 `器官名.动作.阶段` 格式（如 `cortex.dialog.start`），全小写，用`.`分段
3. **payload规范**：只放轻量级可序列化数据（字符串、数字、布尔、字典、列表），不放对象引用
4. **性能**：同步发布实测<1ms，EventTap的`_on_event`只做计数，总开销应<0.1ms/事件
5. **PHASE18铺垫**：本批发布的事件将作为PHASE18器官关联图谱的动态数据源，事件命名和payload设计要考虑后续可扩展性
6. **不要过度设计**：本批是"试点"，只做3个器官6个事件点，验证可行性后再扩展。不要一次性给所有器官加发布点
