## 二、刀1 · 丙-1主路（P0）

### 刀1.1 定位
- **问题**：主路的坑在锁上——丙-1主路若照"复用log_receive回填结构"来写，会给publish热路径加一次锁内O(n)遍历。全仓没有任何pulse_id索引（本窗grep空）。

### 刀1.2 改动（四处）
1. **pulse_id O(1)索引（甲案，~14行）**：
   - utils/pulse_tracer.py新增模块级_EMIT_INDEX: dict[str, dict]
   - log_emit在:286追加event后写_EMIT_INDEX[pulse_id] = event
   - 环pop（:287—288与log_receive同款两处）时同步pop(该事件pulse_id, None)
   - 红利：log_receive:319—338的三段反向扫描可全部改走同一索引（O(n)→O(1)，含未命中时的二次启发式扫描），这是117批留下的同一处欠账

2. **mark_route_matched带status（第5参）**：
   - utils/pulse_tracer.py新增mark_route_matched(pulse_id, real_matched, universal_matched, dispatched, status)
   - 早退三类（expired/duplicate/storm_blocked）计入dispatch_loss归因
   - 否则"风暴限流丢包"永远看不见

3. **publish收尾调用mark_route_matched（~3行，带DEBUG_PULSE_TRACE门）**：
   - nucleus/field/InfoField.py在publish收尾（:848之前）调用它
   - 落点选publish而非BasePulseOrgan:328：publish是轨A/轨B唯一汇聚处，一处覆盖全部发射路

4. **判据升四态＋心跳线加_hb_R/_hb_L两数**：
   - _detect_orphans:376—385由"三态"改"四态优先"：
     1) evt有route_matched且real_matched > 0 → 平反（发射当场权威，不等1.5s）
     2) evt有route_matched且real_matched == 0 → 真孤儿候选；universal_only时单独标记（价值最高的一格）
     3) 无route_matched（早退/未打点/已出环）→ 走现264红线：matched_organs剔_UNIVERSAL_ONLY_ORGANS
     4) 再往下才subscription_provider（已剔observer）＋白名单
   - 心跳线加两数：
     - _hb_R = 有route_matched的emit条数（主路自证覆盖率（健康线））
     - _hb_L = sum(max(real_matched - 实际到达数, 0))（dispatch_loss，并按status分桶）

### 刀1.3 验收
- 重启后pulse_id O(1)索引落地——log_receive回填从O(n)降O(1)
- 重启后mark_route_matched带status——早退三类计入dispatch_loss归因
- 重启后判据升四态——发射当场权威，不等1.5s
- 重启后心跳线加_hb_R/_hb_L两数——主路自证覆盖率＋dispatch_loss
