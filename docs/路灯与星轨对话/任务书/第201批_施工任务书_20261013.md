## 背景
200批3刀全完（判定撤销机制/真孤儿补注册/离线件排程刀）。201批定位=**前置刀：tracer环窗扩容**——防类脑改造加密脉冲流导致的观测面吞噬。

**烛微200前置关键发现**：
- **观测面吞噬风险**：200窗刚定案的pulse_tracer伪孤儿机理＝**200槽事件环＋1s判定窗**——类脑改造（②④⑤任一）都会**加密脉冲流**，环窗竞争加剧 → **假孤儿爆发、观测面被新脉冲淹没**。
- **结论**：六项第一刀不应是任何类脑件，而是先把200在途撤销刀落地并扩容判定窗（环200→随脉冲频率参数化）——否则改造越成功，监控越失明。

## 施工刀（1刀，全零停窗）

### 刀1：tracer环窗扩容（零停窗）
**内容**：pulse_tracer.py的_MAX_ORPHANS（100条）和事件环容量（200槽）改为参数化配置，随脉冲频率动态调整。

**依据**：烛微200前置§3.1——观测面吞噬风险：200窗刚定案的pulse_tracer伪孤儿机理＝200槽事件环＋1s判定窗——类脑改造（②④⑤任一）都会加密脉冲流，环窗竞争加剧→假孤儿爆发、观测面被新脉冲淹没。

**具体改动**：
1. `_MAX_ORPHANS`（100条）改为config.py可配置项，默认100，建议200-500
2. 事件环容量（200槽）改为config.py可配置项，默认200，建议500-1000
3. 判定窗（1s）改为config.py可配置项，默认1s，建议2-5s
4. 新增config.py三键：`PULSE_TRACER_MAX_ORPHANS`/`PULSE_TRACER_EVENT_RING_SIZE`/`PULSE_TRACER_MIN_AGE_SEC`

**不做**：
- 不改pulse_tracer的判定逻辑（200批刚落地的判定撤销机制）
- 不改孤儿检测的算法
- 不加白名单（白名单降为最后手段）

**验收**：pulse_tracer.py的_MAX_ORPHANS/事件环容量/判定窗改为config.py可配置项；隔离单测过（含参数化配置断言）。
