## 二、必做6项审计内容（全部输出文件:行号/可复现命令）

### T148-1 147批拆分等价性全量核验
**必查项**：
1. 逐方法核对拆分后的9个阶段方法+编排器：
   - 每个方法的输入输出、出口数量、return语义和拆分前基线逐一比对
   - 所有emit事件的顺序、参数、计数和拆分前基线完全一致
   - 异常处理、超时中断、兜底路径无遗漏、无错位
2. 自动扫描：
   - 所有新拆方法行数实测，确认全部≤200行，无超长告警
   - 主函数最终行数、CC值实测，确认达标
   - `InferenceContext`所有字段读写一致性，无漏槽、无意外覆盖
3. 金标测试9用例之外，额外抽3条边缘路径（空payload/超长问题/无网环境）做探针验证，确认返回和拆分前一致
4. 核对30分钟活体验证日志：无新增异常、无热路径报错、推理延迟无显著劣化（劣化>10%要标注）
**输出**：拆分等价性核验表，列出所有偏差点（若有），确认是否可以收口。

### T148-2 开源新仓首发全流程就绪度审计（核心）
对照待办总览区开源硬阻塞项逐项审计，输出一步到位的操作施工图：
1. **导出包最终验证**：
   - 拆分完成后重新跑一次`export_public.py`，实测最终文件数/体积
   - 独立二次复扫：PII/弱PII/内部文档/敏感文件/失效链接，必须全绿
   - 确认发布包不含任何本地缓存、运行时data、历史密钥、个人信息
2. **旧仓处置审计**：
   - Gitee旧仓、OpenI旧镜像的转私有操作步骤，确认权限、路径
   - 旧仓历史中泄露的密钥清单：确认智谱/火山方舟等历史密钥是否已全部吊销，给出吊销检查方法
3. **新仓创建方案**：
   - 新公开仓命名、初始化步骤、首个提交内容清单
   - 发布日干净快照重建方案：确认如何避免常驻框架运行时缓存污染发布包
   - README/开源协议/演示文档/快速启动指南的完整性检查，列出缺项
4. **积压提交预检**：
   - 盘点当前所有待推送提交（136-147批），确认哪些进新仓首发、哪些仅保留本地
   - 确认新仓首个版本的版本号、功能说明、比赛提交可用状态
**输出**：新仓首发一步一步操作清单，标注高风险点和回滚方案。
