## 刀1：内存器官级RSS埋点（P0）

**做什么**：现在只知道总RSS 11.1GB，不知道哪个器官吃的。加个埋点，每300秒采一次各器官RSS，输出top10。

**怎么做**：
- 在 `PulseMetricsCollector` 每次心跳时，遍历器官表，用 `tracemalloc` 或 `psutil.Process().memory_info()` 采各器官RSS
- 输出 `data/monitor/memory_by_organ_YYYYMMDD.json`，每300秒一条，含top10器官的rss_mb
- health_snapshot 加 `memory_by_organ_top3` 字段（只放前3名，避免快照膨胀）
- 验收：重启后第一次心跳就能看到各器官RSS排名；连续跑1小时能看到谁在涨

**风险**：低。只加采样不改动现有逻辑。注意：tracemalloc单次837s不能加密（已知死路），用psutil或gc.get_objects()近似即可。

## 刀2：effect_verify恢复触发（P0）

**做什么**：effect_verify.json有50条verdict（40条生产补丁全passed=True），但10-25后停更了。恢复apply后的自动验证触发。

**怎么做**：
- 在 `PatchManager` 的 apply 成功后（applied=True处），异步调一次 `EvolutionEffectVerifier.verify(...)`
- 现在这段在try/except里且异常被吞——加日志，异常时打WARNING不静默
- 给patch_history补派生字段 `effect_verify_state ∈ {passed, failed, unverifiable, missing}`（由verdicts反查，不改既有字段）
- effect_verify.json的updated若超过24h未变，在health_snapshot打 `world_model.effect_verify_stale=true`
- 验收：手动触发一次apply，effect_verify.json的updated时间戳更新；patch_history里对应补丁的effect_verify_state有值

**风险**：低。异步调用不阻塞apply。注意别把验证做成同步阻塞（验证里有子进程/超时）。

**风险**：低。只加写入不改动现有逻辑。

- 验收：DEBUG日志能看到经验命中次数；search_experience字段不再恒None

**风险**：低。先只记不拼，不会导致token暴涨。

## 刀6：410批遗留收口（P2）

**做什么**：410批交付报告里的5条遗留，顺手修了。

**怎么做**：
1. **周期档案自动重建**：把 `tools/m410_build_profile.py --build` 挂到04:00夜间摘要段（与hit_rate日报表同一处），一行调用即可
2. **容差表按σ复核**：现在tol/σ从1.02到9.18，心跳类9σ几乎必中、触觉类1σ七成命中就告警——按σ重算容差表（目标：每类tol≈2σ），写进periodic_profile.json
3. **no_coverage覆盖率进报表**：hit_rate日报表加coverage字段（覆盖预测数/总预测数），低覆盖下的高命中率不算健康
4. **_periodicity_cache样本数**：从50提到100（内存增量KB级），让每类预测样本多一倍

**验收**：04:00夜间摘要里能看到档案自动重建；容差表tol/σ≈2；hit_rate报表有coverage字段。
