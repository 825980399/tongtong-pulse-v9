## 刀1：approval_bridge接进repair之后

**修什么**：现在approval_bridge.maybe_approve只在pilot脚本里调用过，生产主循环里没接——补丁保存后没人审批。

**怎么改**：
- 在`SafeEvolutionExecutor.py`的repair_with_distillation每保存一条runtime_verified后，调用`approval_bridge.maybe_approve(patch, patch_manager)`
- **不改八闸判据**，只把决策落`auto_approved.json`
- **★ 安全边界（小林拍板）**：
  - 先只对`risk=低 + 非核心文件 + 单文件 + blast≤1`开
  - 每天最多自动批准1条
  - 失败自动回滚
  - 所有决策都留痕

**★ 留痕要求（小林硬性要求）**：
- 每次审批必须记录：补丁id、八闸每闸的判定结果、最终决策（approve/reject）、决策理由
- 落盘到`data/patches/approval_trace.jsonl`
- 修改前/修改后完整内容都要有

**验证**：
- 审批桥真的接进repair之后了吗？
- 今天有没有补丁走到审批这一步？
- 八闸每闸的判定都记录了吗？

## 刀2：apply管道最后一跳

**怎么改**：
- 每轮repair结束后，若`approved>0`，调用一次`apply_all_pending(only_approved=True)`
- 走既有备份/回滚/landed机制，不要直接写源码
- 加`_apply_lock`防止并发apply
- 不要在repair线程里并发apply——用周期tick（5分钟）统一走

**★ 留痕要求**：

- 落盘到`data/patches/apply_trace.jsonl`
- **修改前/修改后完整内容100%留痕，就算改错了也能追溯**

**验证**：
- 审批通过的补丁真的被apply了吗？
- apply前真的备份了吗？
- 修改前/修改后内容都记录了吗？
