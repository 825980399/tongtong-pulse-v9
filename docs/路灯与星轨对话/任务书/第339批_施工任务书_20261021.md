## 刀1 · ★审批分道：O3类"确认后自动派单"（E裁决落地）

**背景**（烛微338前置§2.2）：O3入池条目一律 `requires_confirmation=True`、`risk=高` ⇒ "不入自动审批"；人工入口存在但**无裁决人＋时限关着**（`ENABLE_PENDING_QUEUE_AGING=False`，280批刀3关闭理由="aging 对 source=llm 队列空转，明写 llm 永不自动"）；94批自陈空转主因"已有待审批"48次占28.6%。真实断点="没裁决人＋时限关着"。

**改动**：
- **分池分策**：`source=o3`（判死类）与 `source=llm`（生成类）分池分策；O3类走"**确认后自动派单**"显式通道——人工确认（approve落 `approved_signer/approved_at/approved_source`）后**不再要求二次审批**自动派单；llm类维持"永不自动"（280批刀3，一字不动）
- **SLA留痕**：审批动作必须落四字段 `{signer, at, judged_by(人/机), basis}`；超时未裁决 ⇒ **老化只降级不删除**（`pending → expired_pending`，保留可回滚），`ENABLE_PENDING_QUEUE_AGING` 对 O3 类单独开启（对 llm 类保持关闭）
- **审什么固定四项**：evidence_tier／图外 probe 四类／抽验 misjudge 样本行／是否上帝文件（PulseInnerWorld.py 只加严不放松）
- **时限**：24h（沿用 `_M94_AGING_DEFAULT_MAX_COUNT=20/MAX_HOURS=24.0`，不新增数）；每周汇总"未裁决条数/最老时长"进日报（复用 `publishers.py` 的 `verifiable_rate` 打印口同型）

**验收**（隔离注入为主＋重启后活体补验）：
①O3条目 approve 后自动派单（注入确认⇒dispatched≥1，无二次审批）②llm条目确认后**仍不自动派单**（注入反例⇒blocked，语义零变化）③SLA四字段留痕完整（signer/at/judged_by/basis 全落）④超时⇒`expired_pending` 降级不删除（注入24h+⇒状态迁移可回滚）⑤`ENABLE_PENDING_QUEUE_AGING` O3开/llm关（grep 实证）⑥审核面四项固定（注入四项边界样本）⑦`[339审批]` 留痕行可grep
