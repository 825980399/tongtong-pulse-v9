## 刀1：片段按语句块抽取（禁止try内截断）

**修什么**：`nucleus\reasoning\PatchManager.py` 里的片段抽取器
现在LLM生成补丁时，抽取目标代码片段经常在try块内部就截断了——original_code只有4行，末尾停在`try:`里面，这样的片段怎么改都不可能平衡。

**怎么改**：
- `get_method_body()` 拿到方法全文后，用AST找目标语句的起止行
- **不允许在try/except/finally体内截断**——必须抽到整个try块结束
- 32/45条带markdown围栏的问题421刀4已经修了，这刀修"截断位置"的问题

**验证**：
- 用45条2a拒收标本重放：应该产出完整try块的片段
- 2a拒收数应该明显下降（原来45条，修完应该降到个位数）
- 不能放水——原来该拒的还是要拒，只是拒的理由从"try不平衡"变成真缺陷

## 刀2：同(file,method)失败3次冷却24h

**修什么**：`patch_fail_counts.json` 现在按patch id计数，换个id就绕过了。
同一个方法`_compress_group`，四天被派单44次，每次都失败。

**怎么改**：
- 失败计数改为按`(file, method)`二元组计数，不再按patch id
- 同一个(file, method)连续失败3次 → 24小时内不再给这个方法派单
- 冷却期内派单器看到就直接blocked，reason="cooldown_24h"
- 24小时后自动解锁，允许再试

**验证**：
- 构造一个方法失败3次，第4次应该被冷却
- 冷却日志里能看到reason="cooldown_24h"
- 24小时后（单测里可以模拟时间快进）自动解锁

## 刀3：周期apply（5分钟一次）

**修什么**：`main.py` 现在apply只在两个时刻发生：
- 进化器主动请求
- 进程退出

跑一夜不重启，pending里有approved件也永远不落地。18天0 apply就是这么来的。

**怎么改**：
- 加一个5分钟一次的节拍：有approved件就自动apply
- 参考`ParamPatchManager.start_auto_apply`的现成模式（main.py:532已有先例）
- apply前先检查防循环闸：`_self_modify_forbidden_until` 和 `restart_count.txt`
- apply失败的件进重试队列，最多重试3次

**⚠️ 注意**：
- apply成功后会自动重启框架——所以加周期触发等于增加重启次数
- 必须先确认防循环逻辑有效，不然会无限重启
- 重启间隔不能太短，至少留10分钟运行窗口

**验证**：
- pending里有approved件，5分钟内自动apply
- apply触发重启，restart_count.txt计数+1
- 失败的件进重试队列，3次后标记dead

## 刀4：叙事catch-up + 每6h flush

**修什么**：叙事persist()现在只挂在04:00夜间编排。
错过窗口就不补跑，而且一天只落盘一次。

**怎么改**：
- 启动时检查：今天叙事没落盘且当前时间<12:00 → 自动补跑一次
- 除了04:00，再加每6小时一次flush（10:00/16:00/22:00）
- last_run_ymd天然幂等，补跑不会重复

**验证**：
- 模拟今天04:00错过了，启动后应该自动补跑
- data/narrative/目录下一天能出现多个时间点的flush记录
- 补跑不会重复写同一条
