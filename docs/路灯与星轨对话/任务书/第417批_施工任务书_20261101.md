## 刀1：L0心跳锁路径修复（核心）

**做什么**：416发现L0看门狗8s超时的真凶不是self_inspector抢CPU，是`_on_heartbeat_observe`持`_cache_lock`做缓存刷新+观测快照，把心跳线程堵死了。

**怎么做**：
- 找到`_on_heartbeat_observe`里做`_refresh_organ_cache()`和`_build_observability_snapshot()`的位置
- 这两个操作太重了，不能放在心跳线程里同步跑
- 改成：心跳线程只发个信号，把缓存刷新挪到后台低优先级线程里异步跑
- 心跳线程本身只做最轻量的事：发心跳、记时间戳，不做重活
- 加个开关：`ENABLE_M417_HEARTBEAT_ASYNC_CACHE = True`，出问题可以秒关

**验收**：
- 启动后跑10分钟，`logs/heartbeat_stall/`目录不新增文件
- `pulse.log`里不再出现`heartbeat_guard_takeover`
- 心跳间隔稳定在10s±1s，不再跳30s+

## 刀2：主扫描让出点补全

**做什么**：416的`_m416_coop_tick()`只挂在`get_method_body()`，但主扫描`detect_code_issues()`走的是`_scan_all_organs()`的并行文件解析，没覆盖到。补上。

**怎么做**：
- 在`_scan_all_organs()`的文件循环里加让出点：每扫10个文件sleep 1ms
- 注意：这是并行扫描，每个worker线程都要加
- 不要影响扫描速度太多——实测加了之后扫描耗时增加<5%

**验收**：
- 主扫描118s期间，心跳最大超期<1s
- 扫描总耗时增加<5%
- 单测：让出点在并行路径上真的触发了

## 刀4：手动提前验证deferred项（不等04:00）

**做什么**：415的deferred验证脚本首跑0/5全FAIL，是因为04:00前框架没活着跑过。现在手动调一遍那些函数，提前验证接线是不是真的通了。

**怎么做**：
- 写个手动验证脚本`tools/m417_manual_deferred_verify.py`：
  1. **叙事落盘**：手动调`narrative_store.persist_daily()`，看能不能真的写出`data/narrative/narrative_20261101.jsonl`文件
  2. **经验池模板标记**：手动调`experience_governance.mark_templates()`，看`is_template`字段能不能真的写上
  3. **O3 dry-run进夜摘要**：手动调`o3_delete_dryrun.report(sample=8)`，看输出格式对不对
  4. **叙事回放**：手动写一条叙事记录，然后调`load_recent()`看能不能读回来
- 每一项输出PASS/FAIL+实测值
- 有FAIL的就当场修，不用等明天
- perf_delta那项跳过——得有真实补丁apply才会触发，手动验证不了

**验收**：
- 4项手动验证全PASS
- 有FAIL的当场修掉
- 验证通过后，04:00夜摘要跑的时候就不会出问题了
