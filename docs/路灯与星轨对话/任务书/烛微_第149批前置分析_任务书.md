## 二、必做6项审计（全部带文件:行号/可复现命令）

### T149-1 148批施工项全量等价核验（首发前第一道关）
逐项独立复算，不采信施工方自报结论：
1. **CI指纹化改造有效性验证**：
   - 23条旧白名单迁移后双轨结果是否完全一致，有无豁免丢失
   - 5项验收测试是否真的能正确拦截（改代码/加新文件/删handler时是否真的变红）
   - 未跟踪新文件盲区是否真的消除，全量指纹幂等校验是否生效
   - 验证插入代码后是否不再需要人工调整白名单，行号漂移问题是否根治
   - 确认CI改造提交未夹带任何业务代码改动，符合验收器独立性要求
2. **待裁决登记册核验**：
   - 45条历史沉底项是否100%回填，状态标注是否准确，有无遗漏
   - 登记册脚本是否能正确输出到期未裁项，ID唯一性校验生效
   - 抽查10条历史项，对照原始报告确认状态标注正确，没有随意结案/作废
3. **止血项真实性核验**：
   - export_public自豁免是否真的移除，源码内明文真名是否全部清干净
   - 独立旁路复扫（不复用导出脚本自身扫描）：导出包含扫描器自身在内PII 0命中
   - 死链是否全部修复，quality_score_v2公开环境降级兜底是否生效、不抛错
   - 部署指南、SECURITY/CONTRIBUTING/CHANGELOG是否齐套，内容无内部敏感信息
   - 小债务（eureka消费/死函数处置/TaskPipeline标注）是否全部落地
4. **最终导出包核验**：
   - 实测最终文件数/体积/目录结构，独立复扫PII/内部文件/死链/假密钥全项
   - 确认data/tmp/缓存/历史备份/内部台账全部不在包内
**输出**：148批施工项核验表，所有不达标项红标，未清零则首发NO-GO。

### T149-2 30分钟活体验证效果独立复核
1. 核对148批活体验证日志：
   - 启动过程无报错、器官装配完整、金标9场景真实对话全部通过
   - 30分钟运行窗内无ERROR/热路径异常/返回结构错误
   - 推理延迟、内存占用与拆分前基线对比，无显著劣化（劣化>10%需说明）
2. 额外抽3条边缘场景探针：超长问题/无网环境/空输入，确认公开包运行兜底正常
3. 检查是否有测试全绿但活体暴露的隐藏问题，若有立刻阻断首发
**输出**：活体健康结论，确认公开版本可稳定运行。

### T149-3 新仓首发全流程终版审计（核心交付）
输出零歧义、可直接照做的首发操作施工图，每一步带校验点和回滚方案：
1. **旧仓处置核验**：
   - Gitee旧仓、OpenI旧镜像转私有操作步骤，确认权限、入口、生效校验方法
   - 确认旧仓转私有后，公开访问404、仅账号本人可见
   - 旧仓历史中真实邮箱/身份内容的风险是否随转私有彻底隔离，无需额外清理历史
2. **本地refs清理核验**：
   - 列出所有待清理旧旁支ref（pre-rebase-keep/anon-rewrite/old-102/stash等）
   - 给出安全删除步骤，确认删除后不影响当前主干、可通过reflog恢复
   - 确认新仓推送时仅推送干净主干，不会误带旧ref/旧历史
3. **新仓初始化方案终核**：
   - 新仓命名、公开许可、基础设置（议题/PR/安全功能）配置清单
   - 首发squash初始提交的内容清单、提交信息规范
   - 推送后校验项：文件完整性、页面展示、克隆可用性、文档链接
   - 双远端（Gitee主仓+OpenI镜像）同步方案，确认OpenI镜像自动同步配置正确
4. **首发风险与回滚方案**：
   - 每一步操作失败的处置方式，首发出现问题如何快速回滚（重新转私有/撤回提交）
   - 明确禁止的操作：强制推送覆盖公开仓、推送全refs、携带历史
**输出**：15步以内首发操作SOP，每步带「操作+校验+失败回滚」，路灯可直接执行。

2. **设计文件落地状态**：

   - 剩余未落地文件的优先级、工作量、排期建议
