## 一、刀1：T-InfluxDB连接接线-1（唯一刀）

### 背景（173 批段B 实测，路灯原判）
`get_influxdb_store()` 只建单例**不连接**；**全仓零 `connect()` 调用** ⇒ `is_available()` 恒 False ⇒ `_m71_influx_write` 在 `if not _s.is_available(): return` 处**静默返回** ⇒ bucket `pulse_metrics` 运行 10.5h 仍 0 measurement / 0 点。
环境齐备性已确认：`influxdb_client` 1.50.0 已装 ／ `localhost:8086/ping`=HTTP 204 ／ `INFLUXDB_TOKEN` 已注入(88) ／ bucket `pulse_metrics` 存在 ／ 双开关 `ENABLE_INFLUXDB_TIMESERIES` + `ENABLE_INFLUXDB_WRITE_ONLY` 均已 True——卡在"连接"一步。

### 落点与要求
1. **补连接接线**：`get_influxdb_store()`（定位单例工厂）增加**启用时连接**（或首次写**惰性连接**），连接成功后才让 `is_available()` 返回 True。连接失败须记日志（不静默）。
2. **RSS 采样点**（联动洞鉴 172 票 T-InfluxDB接线含RSS-1 的取证面）：现有 4 写方法无内存/RSS 点——补 `process_rss` 采样写入（复用 `InfoField.py:1133-1135` 取数口径），供后续内存长稳取证。
3. **不得静默吞错**：连接异常/写失败必须走框架既有告警通道（参照同类 `_m71_*` 写方法的错误上报惯例），禁止裸 `pass` / `except: return`。

### 验收（可自动化）
- 框架启动后（或 mock 服务下）`is_available()` 返回 True（连接成功路径）；连接失败路径返回 False 且日志有明确原因。
- bucket `pulse_metrics` 出现真实 measurement（含 `process_rss` 点，非 0）。
- 门禁全绿：cw2 非沙箱前置实测（静默 except 指纹）+ 红基线 + 断链 + 登记册校验。
