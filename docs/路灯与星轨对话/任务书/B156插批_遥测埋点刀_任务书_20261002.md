## 一、背景与为什么现在做

1. **P0-253（数据前提失实，已实测）**：内在模型方案声称"LLM 调用历史 2103 次含输入输出对"，但**真实留存仅 50 条（留存率 2.4%）**；第 44 批做过"LLM 留存字段补全"，但**落盘管道未闭环**——字段有了，数据没写下来。
2. **P0-262（依赖度口径错位，已实测）**：97% 大模型依赖度中 98.8%（2077 次）来自自主进化循环；**对话类调用 SCENE_LUNG 埋点全库为 0**——依赖度基线失真，后续所有相关决策都是错靶。
3. **为何现在**：数据积累需要时间（按 ~500 次/天速率，2 周可积累 ~7000 对）。**现在埋点，2 周后内在模型批（P0-250/251）启动时数据就绪**；晚一天埋就晚一天有数据。这是全项目唯一"时间就是瓶颈"的票。

## 二、施工目标

- A. 打通 **LLM 调用全程留存管道**：每次 LLM 调用落盘一条完整记录（含输入/输出/prompt 版本/渠道/来源标记），留存率从 2.4% → **100% 落盘**（调用即记录）
- B. 补 **SCENE_LUNG 对话类依赖度埋点**：全库 0 → 对话类调用可被依赖度统计区分，双口径基线真实化
