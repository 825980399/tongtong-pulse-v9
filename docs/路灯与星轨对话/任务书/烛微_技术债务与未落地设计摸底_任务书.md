### Task-5：器官沉默告警刷屏根因分析（新发现，优先级最高）

**背景**：
最新运行日志发现，企业微信器官沉默告警已刷 **1037次**，每40秒一次，持续不断。这是新发现的问题，之前的分析没有覆盖。

**现象**：
- 企业微信器官每40秒巡检一次，发现沉默
- 每次都发告警，已经刷了1000多次
- 从心跳#981到#1005，持续了至少10分钟
- 日志刷屏，淹没真正重要的信息

**分析要点**：
1. **复现与定位**：
   - 企业微信器官为什么沉默？
   - 是配置问题？还是真的没启动？还是心跳检测逻辑有问题？
   - 沉默了多久？从什么时候开始沉默的？

2. **告警刷屏根因**：
   - 为什么同一个沉默器官会反复告警？
   - 告警去重逻辑在哪里？为什么失效了？
   - 有没有"已知沉默就不重复告警"的机制？
   - 这是不是也是"只写不读"缺陷的一种？

3. **影响评估**：
   - 日志刷屏占了多少比例？
   - 有没有淹没真正重要的告警？
   - 告警疲劳的风险有多大？

4. **修复建议**：
   - 短期止血：如何快速降低告警频率？
   - 中期修复：如何修复告警去重逻辑？
   - 长期治理：如何改进器官健康检测机制？

**产出**：根因定位 + 修复方案建议（短期止血 + 长期治理）
