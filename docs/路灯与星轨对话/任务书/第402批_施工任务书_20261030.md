## 刀1（P1）L2事件字典生成（只落台账不阻断）

### 背景

洞鉴400+烛微401：223条事件常量但无schema、无payload形状、无producers/consumers。现在发方misspelling一个key，接收方永远收不到，且没有任何机制会报错。

### 施工要求

1. **生成`data/contracts/event_dictionary.json`**：
   - 从`const.py`提取223条事件名+类名
   - AST扫`.emit(...)`提取payload key
   - `register_condition`反向补consumers
   - 每个事件包含：class/version/payload/producers/consumers/required_keys
2. **只落台账不阻断热路径**：不强制校验，不报错，只生成JSON文件。
3. **同名值合并检查**：223→219唯一值（4组重复），标注出来。
4. **never_emitted清单**：223-85=138条"定义了没人发"，拆三类：预留未接线/废弃未清/仅测试发。

### 验收标准

- event_dictionary.json有223条事件
- 每条有payload/producers/consumers
- never_emitted清单拆三类

## 刀2（P1）三处死信合并为三列并存

### 背景

烛微401修正：三处死信口径不能合成一条记录（会丢维度），应合成一张表三列（subscribed/routed/delivered）。

### 施工要求

1. **三处死信口径**：
   - EventBus（结构面）：有没有订阅方
   - InfoField（路由面）：有没有命中条件
   - tracer（运行面）：有没有投递
2. **合并成一张表三列**：`data/monitor/dead_letters_YYYYMMDD.jsonl`
   - 每条记录：event + subscribed + routed + delivered + ts
   - 三列并存，不合成一条
3. **每5分钟落一条新记录**：低频计数，不阻塞热路径。

### 验收标准

- dead_letters每5分钟一条新记录
- 三列口径并存，不丢维度
