## 刀1：top3 issue_type补静态检测器

**修什么**：现在`periodic_task_no_reentry`、`non_atomic_write`、`cross_module_singleton_call`这三类issue_type没有检测器，所以baseline_probe跑code_repro时拿不到命中数⇒baseline=0⇒审批闸必拒。

**怎么改**：
- 在`nucleus/evolution/patch_active_reprobe.py`的`detector_for`里补三个检测器：
  1. **periodic_task_no_reentry**：AST查`_schedule_*`定时器方法有没有重入保护（比如有没有`if self._busy: return`之类的判断）
  2. **non_atomic_write**：AST查`open(...,'w')`有没有用tmp+replace模式（非原子写风险）
  3. **cross_module_singleton_call**：AST查模块级单例有没有被跨模块直接调用
- 每个检测器先对历史87条patch_history回放校准——确认只命中目标类型，不误报
- 取不到检测器的issue_type，仍返回None（不强行判）

**★ 留痕要求**：
- 每次检测器命中必须记录：issue_type、file、method、命中规则、baseline计数
- 落盘到`data/patches/detector_trace.jsonl`

**验证**：
- 三个检测器都写出来了吗？
- 对历史87条回放，误报率多少？漏报率多少？
- 现在`periodic_task_no_reentry`能拿到baseline>0了吗？

## 刀2：baseline_probe持久化 + effect_verify口径修正

**修什么**：现在baseline_probe接了（438刀2），但结果被284作废时一起丢掉了，没随patch落pending/history。而且effect_verify的passed=True里有20条是problem_gone=None的自证。

**怎么改**：
- 在`PatchManager.save_pending_patch`的`pending.append`之前，确保`baseline_errors`/`baseline_source`/`baseline_window_sec`/`baseline_shadow`这四个字段随patch落pending
- `approval_bridge`的`baseline_positive`保持>0要求（baseline=0的件判runtime_undecidable，不放行——这是正确行为，不要为数字放宽）
- `EvolutionEffectVerifier`的`passed=True`只允许`problem_gone=True`——`problem_gone=None`的旧逻辑自证要改掉
- 补丁应用时把`baseline_source`带入patch_history

**★ 留痕要求**：
- 每次effect_verify判定必须记录：patch_id、verdict、problem_gone、baseline_errors、判定理由
- 落盘到`data/patches/effect_verify_trace.jsonl`

**验证**：
- baseline_errors/baseline_source真的随patch落pending了吗？
- effect_verify的passed=True里还有多少条problem_gone=None？
- 现在审批八闸里baseline_positive这一闸，真的能读到baseline_errors了吗？
