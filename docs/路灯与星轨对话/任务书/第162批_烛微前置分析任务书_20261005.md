## A 类 3 项

### A1｜T-内存告警静默失效修复-1（P1）施工前置定位
- **背景（烛微已立票）**：生产 psutil 失败降级返 0.0（非 9999，9999 为测试 mock）→ `InfoField.mem_percent=0` → heavy/critical 告警**永不触发**（静默失效，比告警失真更严重）
- **要求**：
  1. 定位 mem_percent 采集点（psutil 调用处）与告警判定链（heavy/critical 阈值判断处）精确锚点
  2. 给出修复方案落点：0.0 哨兵处理（区分"真实 0% 内存"与"psutil 采集失败"）+ 告警链可信度校验（采集失败不得静默通过）
  3. 验收断言：采集失败场景→告警链输出明确失败标记（非 0.0 静默）；正常场景行为不变
  4. 判定是否需要停窗（若只改采集/判定函数且可单测覆盖→不停窗备选；若涉及运行时循环/调度→停窗确认）

### A2｜T-快照增量写盘接管-1（P1）施工前置定位

- **要求**：
  1. 定位快照写盘主循环（30s 周期）与增量/全量切换开关现状（`SNAPSHOT_USE_INCREMENTAL` 配置与运行期路径）
  2. 给出接管方案落点：增量日志追加入口 + 全量基线写盘时机 + 崩溃恢复（增量回放）
  3. 验收断言：增量模式 30s 周期仅追加增量（写盘量可测）；重启后增量回放=全量等价（对齐 `test_lazy_vs_full_equivalence` 判据）
  4. 判定是否需要停窗（大概率需停窗验证回放链）
