## 六、针对本框架的专项检查要求

### 专项1：委托链完整性检查（针对Mixin架构）
检查所有 PulseInnerWorld 及其 Mixin 子类的方法委托：
1. 主类中保留的方法签名，实际逻辑是否已迁移到子模块？
2. 如果子模块未注入（为 None），委托方法是否有兜底？
3. 是否存在"主类调子模块，子模块又回调主类私有方法"的循环依赖？
每个发现标注 `文件:行号`。

### 专项2：异常吞噬热区检查
扫描所有 `except Exception` 块，按以下维度分类：
1. 日志级别为 DEBUG 且无后续补偿逻辑 → 静默失败高风险
2. 日志级别为 WARNING 但异常类型为 ImportError/AttributeError → 可能掩盖真实 bug
3. 同一方法内连续 3 个以上独立 try-except → 过度防御信号
输出：`文件:行号` + 异常类型 + 风险评估。

### 专项3：配置分散检查
搜索以下模式：
1. 同一配置项在多处用 `getattr(config, "...", default)` 读取，且 default 值不一致
2. 硬编码的魔法数字（如超时 45.0、重试 3 次）在多处重复
3. 配置项定义了但从未被读取（死配置）
输出：配置项名 + 所有引用位置 + 不一致详情。

### 专项4："只写不读"横向债务检查
检查所有"判据/标记/配置/回退"被写入了，但消费侧不存在或永不回头再看的情况：
1. 写入了状态标记，但没有任何地方读取这个标记
2. 定义了开关，但开关只写不读
3. 生成了审计日志，但没有任何地方消费这些日志
输出：`文件:行号` + 写入点 + 消费点缺失说明。
