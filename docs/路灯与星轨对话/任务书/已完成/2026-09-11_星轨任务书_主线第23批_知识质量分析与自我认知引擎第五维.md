## 一、批次背景

### 1.1 现状

自我认知引擎（SelfAwarenessEngine）目前已有**四维分析**：
1. 代码静态健康度（CodeReviewEngine，ruff问题）
2. 数据文件健康度（ProductionConsumptionMatcher，产出-消费配对）
3. 运行时动态健康度（LogAnalyzer + EventTap，日志+事件）
4. 代码结构健康度（CallGraphAnalyzer，调用图五维分析）

**缺失的第五维：知识质量分析**。曈曈的核心资产是知识体系（L1→L2→L3压缩链，知识节点池），但目前没有任何机制评估：
- 知识是否自洽（有无矛盾/冲突）
- 知识是否完整（有无盲区/未覆盖领域）
- 知识是否过时（有无老化/失效节点）

### 1.2 为什么现在做

- PHASE18阶段二原规划方向，第22批因日志问题临时改向，现在回归主线
- 知识体系是曈曈的"大脑内容"，代码健康是"大脑结构"，两者缺一不可
- 第三方深度分析正在进行，知识质量分析可以为第三方报告提供自查基线
- 为后续"知识自动修复/更新"奠定基础（发现问题→修复问题的闭环）

### 1.3 知识体系现状（先核实再动手）

动手前必须先核实以下事实，禁止凭印象开发：
- 知识节点池的实际存储格式和位置（`nucleus/knowledge/` 或 `data/`）
- L1/L2/L3知识的实际数据结构和字段
- 知识节点的数量、大小、更新频率
- 是否已有知识时效性字段（如last_updated/timestamp/expires_at）
- 是否已有知识分类/标签体系
- 知识压缩（L1→L2→L3）的实际实现位置和逻辑

## 二、6项任务

### T1 · 知识一致性分析 ✅必须

**目标**：检测知识节点间的矛盾、冲突、不一致，建立知识一致性评分。

**具体要求**：
1. 新建 `nucleus/self_awareness/KnowledgeQualityAnalyzer.py`（本批核心文件，T1-T4都在此文件中实现）
2. 实现 `analyze_consistency()` 方法：
   - 检测**直接矛盾**：同一主题下存在互斥结论（如"A是B"和"A不是B"）
   - 检测**数值冲突**：同一指标存在不同数值（如"CPU使用率80%"和"CPU使用率50%"）
   - 检测**因果矛盾**：因果链中存在逻辑冲突（如"A导致B"和"A导致非B"）
   - 检测**定义不一致**：同一概念在不同节点中有不同定义
3. 一致性评分：0-100分，矛盾节点数/总节点数加权计算
4. 输出：矛盾节点对列表（含矛盾类型、严重度、涉及节点ID）
5. 实现策略：基于关键词/实体匹配+规则检测（不依赖大模型，保证可复现）；复杂语义矛盾标记为"待人工确认"

**验收**：能在测试知识集上检测出至少3种类型的矛盾，评分逻辑可解释。

---

### T2 · 知识覆盖率分析 ✅必须

**目标**：检测知识盲区、未覆盖领域、知识点密度分布，建立知识覆盖率评分。

**具体要求**：
1. 实现 `analyze_coverage()` 方法：
   - **领域覆盖分析**：按知识分类/标签统计各领域节点数，识别低密度领域（<阈值的领域标记为"知识盲区"）
   - **深度覆盖分析**：L1/L2/L3各层级节点数比例，识别"只有原始知识(L1)没有提炼知识(L2/L3)"的领域
   - **关联覆盖分析**：知识节点间的关联密度，识别"孤岛节点"（无任何关联的节点）
   - **时间覆盖分析**：各时间段的知识更新量，识别"长期无新知识注入"的领域
2. 覆盖率评分：0-100分，领域覆盖/深度覆盖/关联覆盖/时间覆盖加权计算
3. 输出：盲区领域列表（含领域名、节点数、建议补充方向）
4. 领域分类：如果已有知识分类体系则复用；如果没有，基于节点标签/关键词自动聚类（简单规则，不依赖大模型）

**验收**：能识别出至少3个低密度领域和至少5个孤岛节点，覆盖率评分逻辑可解释。

---

### T3 · 知识老化分析 ✅必须

**目标**：检测过时知识、长期未更新节点、知识时效性评分，建立知识老化评分。

**具体要求**：
1. 实现 `analyze_aging()` 方法：
   - **时效性检测**：基于last_updated/timestamp字段，计算节点年龄，超过阈值（如180天）标记为"可能过时"
   - **版本关联检测**：引用旧版本号/旧API/旧路径的节点标记为"可能失效"（如引用v9.0但当前是v9.5）
   - **访问频率检测**：长期未被检索/引用的节点（如果有访问统计）标记为"休眠知识"
   - **矛盾驱动老化**：与T1检测出的新矛盾节点冲突的旧节点，优先标记为"待更新"
2. 老化评分：0-100分，过时节点数/总节点数加权计算（分数越低表示老化越严重）
3. 输出：老化节点列表（含节点ID、年龄、老化类型、建议操作：更新/归档/删除）
4. 如果知识节点没有时间戳字段：基于文件修改时间/快照时间推断，并标记为"推断时间戳"（不修改原始数据）

**验收**：能识别出至少5个可能过时的节点，老化评分逻辑可解释。

---

### T4 · 知识质量综合评分模型 ✅必须

**目标**：整合T1-T3，建立知识质量综合评分模型，输出知识质量报告。

**具体要求**：
1. 实现 `analyze_overall()` 方法：
   - 综合评分：一致性(30%) + 覆盖率(30%) + 老化(20%) + 知识深度(10%) + 知识广度(10%) = 0-100分
   - 知识深度：L2/L3节点占比（越高表示提炼越充分）
   - 知识广度：覆盖领域数（越高表示知识面越广）
   - 等级划分：优秀(≥85) / 良好(70-84) / 一般(50-69) / 较差(30-49) / 危险(<30)
2. 实现 `generate_report()` 方法：
   - 输出结构化报告（dict），含：综合评分、各维度评分、TOP问题列表、改进建议
   - 报告格式与SelfAwarenessEngine现有四维报告兼容（便于集成）
3. 实现 `compare_profiles()` 方法：
   - 对比两次知识质量分析结果，输出变化趋势（变好/变坏/停滞）
   - 与SelfAwarenessEngine的compare_profiles方法接口一致
4. 性能要求：全库知识分析<10秒（知识节点数预计<10000）

**验收**：能生成完整的知识质量报告（含综合评分+各维度评分+TOP问题+改进建议），报告可被SelfAwarenessEngine消费。

   - 五维健康度总览：代码静态/数据文件/运行时动态/代码结构/知识质量，各维度评分+综合评分
2. 修改 `tools/run_self_awareness_analysis.py`：
   - 新增 `--include-knowledge-quality` / `--no-include-knowledge-quality` 开关（默认开启）

**验收**：运行run_self_awareness_analysis.py能输出包含五维健康度的完整报告，关闭开关时与原行为完全一致。
