- 代码学习、冷存compaction、后台学习消化等重操作未纳入自适应

- `config.py`（新增配置项）

**具体修改点**：

#### 2.1 代码学习频率自适应

**当前行为**：每批次学习20个方法，批次间隔固定（LEARNING_INTERVAL_SECONDS=300）

**自适应方案**：
1. 每批次开始前查询当前系统负载（CPU使用率、队列深度）
2. 根据负载动态调整：
   - 低负载（CPU<40%且队列<2000）：正常频率，每批次20方法，间隔300秒
   - 中负载（CPU 40-70%或队列2000-5000）：降频，每批次10方法，间隔600秒
   - 高负载（CPU>70%或队列>5000）：暂停，间隔1200秒后重试
3. 学习进度不受影响，只是频率调整
4. 增加自适应日志：每次调整时记录负载和调整决策

#### 2.2 冷存compaction自适应暂停/恢复

**当前行为**：compaction按固定间隔运行，高负载时也不暂停

**自适应方案**：
1. compaction开始前查询当前系统负载
2. 高负载（CPU>70%或队列>5000）时暂停compaction，记录暂停原因
3. 每5分钟检查一次负载，负载恢复正常后自动恢复
4. 增加compaction优先级：知识节点数>阈值时即使中负载也执行（防止冷存积压）
5. 增加自适应日志：暂停/恢复时记录负载和决策

#### 2.3 后台学习消化频率自适应

**当前行为**：肺器官持续消化大模型回复，高负载时也不减速

**自适应方案**：
1. 每批次消化前查询当前系统负载
2. 根据负载动态调整消化批次大小：
   - 低负载：每批次消化10条
   - 中负载：每批次消化5条
   - 高负载：暂停消化
3. 增加消化队列深度监控，队列过长时优先消化
4. 增加自适应日志

#### 2.4 统一负载查询接口

**问题**：各模块各自查询负载，代码重复

**修复方案**：
1. 在runtime_metrics中新增`get_system_load()`方法，返回统一的负载信息：
   - cpu_percent：CPU使用率
   - queue_depth：队列深度
   - memory_percent：内存使用率
   - load_level：low/medium/high/critical
2. 各模块统一调用此接口，避免重复实现
3. 负载计算逻辑集中管理，便于后续优化
