**优先级**：P1（高）
**预估工时**：3小时
**验证方式**：pytest + 代码审查 + 模拟自主进化轮次

**问题描述**：
2026-09-15框架运行日志分析发现：
- PatchAutoApprover连续16轮修复率<10%，当前修复率0.0%
- 自主进化第1轮发现60个问题，0个修复成功

**根因定位（星轨已初步分析）**：
1. `nucleus/reasoning/SafeEvolutionExecutor.py` 第163行：
   ```python
   _project_root = os.path.dirname(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
   ```
   这是**局部变量**，但第595、597、1481行等多处引用的是 `self._project_root`（实例变量），该实例变量**从未被初始化**，导致AttributeError或None引用。

2. 白细胞虽检测到问题并生成补丁，但PatchAutoApprover修复率0%导致补丁无法自应用，形成"发现问题→无法修复→继续发现"的死循环。

**任务要求**：
1. **修复_project_root bug**：将第163行局部变量改为实例变量 `self._project_root = ...`，确保所有引用处正常工作
2. **全量排查SafeEvolutionExecutor中其他局部/实例变量混淆问题**：搜索所有 `self.` 引用，确认对应的实例变量都在`__init__`中初始化
3. **诊断PatchAutoApprover修复率0%的完整链路**：
   - 检查补丁生成→审批→应用的完整流程
   - 确认LLM修复路径是否因渠道超时（ark-seed系列问题）而失败
   - 检查本地修复规则库是否为空或覆盖不足
4. **修复后验证**：模拟一轮自主进化，确认至少能完成1个简单问题的自动修复
5. **添加自主进化健康度监控**：每轮输出发现数/修复数/修复率/失败原因分布，便于持续监控

**验收标准**：
- ✅ SafeEvolutionExecutor._project_root修复为实例变量，所有引用处无AttributeError
- ✅ 全量排查无其他局部/实例变量混淆问题

### T2 · P2-393延伸 ark-seed深度思考模型渠道优化：请求复杂度路由 + 动态max_tokens

**优先级**：P2（高）
**预估工时**：3小时
**验证方式**：pytest + 实际API调用测试 + 代码审查

**问题描述**：
2026-09-15框架运行日志+实际API测试发现：
- ark-seed-evolving复杂请求（1500字深度分析）90秒超时无法完成
- ark-seed-21-turbo 0%成功率，ark-seed-evolving 7.7%成功率（15分钟运行窗口）
- 简单请求（"你好"）ark-seed系列均能在8秒内成功
- ark-ds-v4-flash同样的复杂请求50.5秒完成（含2841 reasoning_tokens）

**根因**：ark-seed系列（Doubao-Seed-Evolving/2.1-turbo/2.1-pro）是**深度思考模型**，复杂请求会生成大量reasoning_tokens，推理时间极长（>90秒），不是超时时间设置问题，也不是endpoint_id问题。

**星轨已完成的紧急止血**：config.py中max_tokens_override 4096→1024，优先级降级，并发降低。需重启生效。

**任务要求**：
1. **调研火山方舟Doubao-Seed系列的思考控制参数**：
   - 查阅火山方舟API文档，确认是否支持`enable_thinking`/`thinking_type`/`reasoning_effort`等参数
   - 如果支持，测试关闭思考模式后的推理速度和输出质量
   - 如果不支持，记录为平台限制
2. **实现请求复杂度路由机制**：
   - 在PulseLung渠道选择逻辑中，根据请求输入长度和类型判断复杂度
   - 简单请求（输入<500字、非深度分析类）可优先使用ark-seed系列（推理快、质量高）
   - 复杂请求（输入>500字、或包含"分析/深度/详细"等关键词）强制路由到ark-ds-v4-flash或zhipu
   - 路由规则可配置（灰度开关）
3. **实现动态max_tokens机制**：
   - 根据请求复杂度动态调整max_tokens：简单请求512，中等请求1024，复杂请求2048
   - ark-seed系列上限不超过1024（避免推理时间过长）
   - ark-ds-v4-flash/zhipu可保持较高上限
4. **添加渠道推理速度画像**：记录每个渠道的平均响应时间（按请求复杂度分层），用于动态调度决策
5. **验证**：用简单/复杂两种请求分别测试ark-seed系列，确认优化后成功率显著提升

**验收标准**：
