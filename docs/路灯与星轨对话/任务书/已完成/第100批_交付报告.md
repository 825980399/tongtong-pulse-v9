## T-100c（P1）D017 日志轮转自感知

**根因**：`check_log_integrity` 把「当前 size < 上次 size」判为 `truncated`（外部截断）、把「inode 变化」判为 `replaced`（外部替换）。但框架自身轮转时有两种形态：copy-truncate 路径使 size 骤降（误判 `truncated`）、rename 路径新建文件使 inode 变化（误判 `replaced`）。二者都会触发「★检测到日志被外部截断」告警，**误判**框架内正常轮转为外部破坏。

**处置**（保留 `.1`/`.2` 编号备份，既有留存测试不破）：
- 新增轮转唯一标记 `.rollover_marker.json`（含唯一时间戳），`SafeRotatingFileHandler.doRollover` 在 rename 与 copy-truncate 两条成功路径均写入；
- `check_log_integrity`：当 `status ∈ {truncated, replaced}` 且标记时间戳在 `LOG_ROLLOVER_AWARE_WINDOW_SEC`（默认 120s）内 → 复判为 `rollover`，写 `rollover` 事件（`note` 区别于外部截断），并消费标记（避免长期掩盖真实截断）；
- 初始化日志：轮转自感知走 `INFO`（不再触发外部截断 `WARNING`）；
- 标记文件为 `.json`，不被 `cleanup_old_logs` 当作日志清理，亦加入 `LOG_RETENTION_PROTECT`。

**diff（关键）**：`nucleus/logger.py` +94 行（标记常量/读写函数/复判逻辑/doRollover 接线/初始化分支）；新增回归测试 `tests/test_t100c_log_rollover_awareness.py` 6 例。

**先红后绿**：未加复判逻辑时，测试 `test_integrity_reclassifies_truncated_to_rollover` / `test_integrity_replaced_reclassified_with_marker` 会断言 `rollover` 而实际得 `truncated`/`replaced`（red）；加逻辑后 **6 passed**。既有 `test_log_retention_m42.py` / `test_m74_bugfix_robustness.py` / `test_log_decay_robustness_m49.py` 62 例全绿（编号备份 `.1`/`.2` 行为未破坏）。
