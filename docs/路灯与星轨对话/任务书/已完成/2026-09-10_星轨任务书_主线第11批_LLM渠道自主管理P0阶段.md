REMOTE_API_CHANNELS = {

    "advanced_api_url": "https://api.deepseek.com/v1/chat/completions",
    "advanced_api_key": os.environ.get("DEEPSEEK_API_KEY", ""),
    
    # 主力渠道池（平常对话，按优先级轮询）
    "default_channels": [
        {
            "name": "deepseek",
            "model": "deepseek-flash",
            "api_url": "https://api.deepseek.com/v1/chat/completions",

        # 预留更多渠道位置（智谱、豆包等，后续P2阶段接入）

### T3：P2-59 LLM渠道自主管理P0阶段 - 肺部多渠道支持（核心，2-3小时）

**背景**：肺部（PulseLung）当前只支持一个远程API，需要扩展为多渠道选择和故障转移。

**任务内容**：
1. 在`organs/body/PulseLung.py`中新增方法：
   - `_select_default_channel()`：从渠道池中按优先级选择最佳渠道
   - `_rotate_channel(current_channel)`：当前渠道失败时轮询下一个
   - `_update_channel_health(channel_name, success, latency)`：更新渠道健康度
   - `_call_channel(channel, prompt, **kwargs)`：统一调用接口

2. 改造`_call_remote_api()`：
   - 高级任务（code/deep_think/complex_reasoning）→ 用advanced_model
   - 平常对话 → 从default_channels按优先级选择
   - 调用失败 → 轮询下一个渠道
   - 所有渠道失败 → 回退本地Ollama（已有逻辑）

3. 渠道健康度（内存缓存）：
   - 记录每个渠道的成功率、平均响应时间、连续失败次数
   - 连续失败3次 → 暂时熔断（5分钟后重试）
   - 每次调用后更新健康度

4. **下游调用方零改动**：仍然调用`lung.call_llm(prompt, task_type=...)`

**验收标准**：
- 肺部支持多渠道配置
- 渠道失败时自动轮询下一个
- 所有远程失败时回退本地Ollama
- 下游9个调用方无需修改
- 新增测试：`tests/test_llm_channels_m11.py`（≥5例）
