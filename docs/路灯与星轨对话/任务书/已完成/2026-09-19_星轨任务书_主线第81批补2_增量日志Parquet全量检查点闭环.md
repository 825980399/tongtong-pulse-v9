## 一、为什么有这个补正（星轨读码拦截，必须先读懂）

星轨在翻转第二个开关前通读增量日志全链路，确认：写入（`_m67_incremental_log_save`）、重放（`_m67_apply_incremental_log`）、删除集根因修正、删除比例熔断、行 checksum、乱序幂等（均为第81批 T3 成果）逻辑本身完整；加载侧 `load()` 也已在 Parquet/JSON 分支**汇合之后**统一执行增量重放（`PulseSnapshot.py:1573-1578`），对 Parquet 主存储生效。

**但发现"全量检查点 ↔ 增量日志"没有闭环，直接翻开会半生效（带病上线）：**

| 检查项（补正前基线行号，施工后以实际为准并重新贴出） | 实测结果 |
|---|---|
| `_full_save()` 定义 | `PulseSnapshot.py:639-729`，写 JSON 全量 + 状态更新 + Parquet 行数校验，**全程不调 `_m67_clear_incremental_log()`** |
| `_m67_clear_incremental_log()` 全项目调用点 | **仅 2 处**：`:969`（删除熔断降级全量后）、`:1027`（日志达 50000 行阈值全量合并后），均为异常/罕见路径 |
| 外层 `save()` 全量分支 | `:448-452` 调 `_full_save`；`:463-467` 仅 `if self._use_parquet and not _use_incremental: save_parquet()`，**全量成功后不清 jsonl** |
| 熔断路径 `:967-980` / 达阈值路径 `:1025-1031` | 直接 `_full_save()` 后就 `clear`，**没有调用 `save_parquet()`**（Parquet 只在外层 `save()` 全量分支写，这两条路径在 `_m67_incremental_log_save` 内部、return 后外层不再刷 Parquet） |
| `save_parquet()` 返回值 | `:2487-2495` 明确返回 bool（失败 False、无节点 True、node_pool 未注入 False），**可作为"Parquet 是否物化成功"的判据，当前无人据此决定是否清日志** |

**后果（翻开第二个开关后）：**

1. 常规全量保存（稳态每 `SNAPSHOT_FULL_SAVE_INTERVAL=3600` 秒一次，或退出 force_full）刷新了 JSON + Parquet，却**从不清空 `snapshot_incremental.jsonl`**。jsonl 会无限累积（正常运行几乎到不了 50000 行阈值），每次启动都重放全部历史——虽有幂等保结果正确，但启动越来越慢、文件越来越大，增量日志"轻量、只含最近增量"的设计目的落空。
2. 熔断/达阈值两条路径把 jsonl 清空了，却**没刷新 Parquet**。加载以 Parquet 为准时，这次全量合并的变更只进了 JSON、没进 Parquet，存在丢数据风险。
3. 正确语义应是：**jsonl 只保留"最近一次 Parquet 全量检查点之后"的增量；一次全量保存把增量物化进 Parquet 成功后，jsonl 才能清空；Parquet 物化失败则必须保留 jsonl，靠下次启动"旧 Parquet + jsonl 重放"兜底，零丢失。**

**现有测试为何没拦住：** `tests/test_incremental_log_delete_m81.py` 的 `_mk_snap` 用 `PulseSnapshot.__new__` 造**残缺实例**（无 `node_pool`、`save_parquet()` 因 node_pool=None 直接返回 False、未走真实 `save()` 编排、未开 Parquet 主存储），7 例全部直调内部单元方法。它们在"JSON 主存储、无 Parquet"假设下成立，**没有任何一例覆盖"Parquet 主存储 + jsonl 增量 + 全量检查点清空/不清空 + 新实例 load()"的真实闭环**。本补正必须补这样的端到端测试。

**第一步灰度当前固有的新鲜度窗口（星轨补正告知，非本批修复对象，但本批闭环后消除）：** 第一步 Parquet 主存储=True、增量日志=False 时，稳态 Parquet 每 3600s 才随全量刷新一次，间隔内增量只进 JSON（旧 `_incremental_save`，约 37s/轮），主存储加载不读 JSON。故**正常退出（force_full 会全量并刷 Parquet）安全；异常崩溃重启最多丢最近一个全量周期的增量（RPO≈1h）**。本补正 + 第二步开关翻转后，增量随时落 jsonl、重启 Parquet+jsonl 重放，该窗口消除。

### T1 · 抽出统一的"全量检查点"方法（根因主修复）
- 在 `PulseSnapshot` 中新增一个内部方法（建议名 `_m67_full_checkpoint(saved_nodes, current_checksum, start_time) -> bool`），统一表达"全量物化 + 检查点清空"语义，供外层全量分支、熔断路径、达阈值路径三处复用，消除逻辑分叉：
