## 二、任务清单

### T1 · P1 记忆验证首跑延迟语义修正（方案B：推迟语义）

**债务ID**：P1-第61批裁决项1

**问题描述**：
- 第61批T2按任务书实现了`initial_delay_hours`（5~30分钟），但路灯验收时发现语义方向错误
- 任务书判定记忆验证"立即首跑（0秒）"，但实测不成立：`_loop()`首句即`sleep(interval_hours)`，首次执行本就在6小时后
- 按任务书实现后，效果是把首跑**提前**到启动后5~30分钟，与"错峰避峰"原意相反

**星轨裁决**：采用**方案B——改为"推迟"语义**，首跑 = interval + 随机偏移（6h + 5~30min）。

**修改文件**：
- `nucleus/mnemosyne/PulseNodePool.py`（`start_memory_verification_loop`方法）

**具体修改点**：

当前代码（第1207行附近）：
```python
_sleep_s = _first_delay if _first_delay > 0 else _interval
```

改为（推迟语义）：
```python
# ★主线第62批 T1/P1：修正语义为"推迟"——首跑 = interval + 随机偏移
#   旧行为（第61批）：_first_delay > 0 → 首次只等_first_delay（提前）
#   新行为（本批）：_first_delay > 0 → 首次等 interval + _first_delay（推迟）
#   _first_delay = 0 → 首次等 interval（与改造前完全一致，零回归）
_sleep_s = _interval + _first_delay
```

**配置更新**：
- `config.py`中`TASK_OFFSET_CONFIG`的`memory_verify_initial_delay_min/max`保持不变（300~1800秒）
- 语义从"提前"变为"推迟"，需更新docstring说明

**灰度开关**：
- 沿用`ENABLE_RANDOM_INITIAL_DELAY`（第61批已有）
- 关闭时`_first_delay = 0`，行为与改造前完全一致（首次等完整interval）

**测试更新**：
- `tests/test_random_initial_delay_m61.py`中记忆验证相关测试需更新断言：
  - `test_05_memory_verify_delay_lower`：首跑sleep应为 interval + delay（而非 delay）
  - `test_05b_memory_verify_delay_upper`：同上
  - `test_06_memory_verify_zero_keeps_old_behavior`：保持不变（delay=0时首跑=interval）
  - `test_06b_memory_verify_subsequent_uses_interval`：保持不变（第二轮起=interval）

**验收标准**：
1. `initial_delay_hours > 0`时，首跑sleep = interval_hours*3600 + initial_delay_hours*3600
2. `initial_delay_hours = 0`时，首跑sleep = interval_hours*3600（零回归）
3. 第二轮起sleep = interval_hours*3600（不变）
4. 灰度开关关闭时行为与改造前完全一致
5. 对应测试全部通过

### T2 · P1 核心门禁修复（InfoField.py:1684静默异常）

**债务ID**：P1-核心门禁违规（test_robustness_m7）

**问题描述**：
- `nucleus/field/InfoField.py:1684`存在`except Exception: pass`，静默吞异常
- 违反核心7文件门禁（静默异常必须记录日志）
- 非第61批引入，推断由第57批L2队列配置逻辑引入
- 导致`test_robustness_m7.py`1个用例失败

**修改文件**：
- `nucleus/field/InfoField.py`（第1682-1685行）

**具体修改点**：

当前代码：
```python
try:
    _pool._max_workers = _cfg["workers"]
except Exception:
    pass
```

改为：
```python
try:
    _pool._max_workers = _cfg["workers"]
except Exception as _e:
    # ★主线第62批 T2/P1：核心门禁修复——静默异常改为日志记录
    _log = getattr(self, "_logger", None) or __import__("logging").getLogger(__name__)
    _log.warning("[InfoField] L2线程池max_workers设置失败: %s (workers=%s)", _e, _cfg.get("workers"))
```

**注意事项**：
1. 检查该文件是否已有module-level logger，如有则直接使用，无需动态导入
2. 日志级别用`warning`（非error，因为这是配置设置失败，不影响主流程）
3. 保留`return _cfg`在try-except之后（当前代码结构）

**验收标准**：
1. `test_robustness_m7.py`全部通过（11 passed）
2. ruff F=0，E402净变化+0
3. py_compile通过
4. 异常发生时有日志输出，不再静默吞掉
