- 只分析**明确的函数/方法调用**（`func()`、`obj.method()`、`module.func()`）

- 调用关系只记录**定义位置→调用位置**，不记录参数/返回值

### 2.3 红线

- ❌ 不得修改任何器官代码（纯只读分析）
- ❌ 不得执行任何被分析的代码
- ❌ 不得删除或重命名任何函数

## 三、6项任务明细

### T1：跨文件调用图构建器（核心）

**新建文件**：`nucleus/self_awareness/CallGraphAnalyzer.py`

**功能**：
1. 遍历项目根目录下所有`.py`文件（排除`tests/`、`tmp/`、`.bak_*`、`__pycache__`）
2. 使用`ast`模块解析每个文件，提取：
   - 函数/方法定义（`def`，含类方法）
   - 函数/方法调用（`Call`节点）
3. 构建调用关系图：
   - 节点：函数/方法（格式：`module_path:ClassName.method_name`或`module_path:function_name`）
   - 边：调用关系（调用者→被调用者）
4. 解析跨文件调用：
   - `import module` → `module.func()` 解析为跨文件调用
   - `from module import func` → `func()` 解析为跨文件调用
   - `import module as alias` → `alias.func()` 解析
   - 相对导入（`from .module import func`）解析
5. 输出调用图数据结构：
   ```python
   {
       "nodes": [{"id": "module:Class.method", "file": "path", "line": 123, "type": "method"}],
       "edges": [{"caller": "module:Class.method", "callee": "other_module:func", "count": 1}],
       "stats": {
           "total_files": 50,
           "total_functions": 1200,
           "total_calls": 8000,
           "cross_file_calls": 3000,
           "dynamic_calls_unresolved": 50,
       }
   }
   ```

**方法接口**：
- `CallGraphAnalyzer(project_root: str)` — 构造函数
- `analyze() -> dict` — 执行全量分析，返回调用图数据
- `get_isolated_functions() -> list[dict]` — 返回从未被调用的函数列表
- `get_hot_functions(top_n: int = 20) -> list[dict]` — 返回被调用次数最多的函数
- `get_cyclic_calls() -> list[list[str]]` — 返回循环调用链（DFS检测）
- `get_deepest_call_chain(max_depth: int = 20) -> list[str]` — 返回最深调用链
- `export_json(path: str) -> int` — 导出调用图为JSON

**异常处理**：
- 文件解析失败（SyntaxError）→ 记录WARNING，跳过该文件，继续分析
- 导入解析失败 → 标记为"未解析导入"，不影响其他分析
- 循环调用检测设置最大迭代次数（防止无限循环）

### T2：调用图健康度分析

**文件**：`nucleus/self_awareness/CallGraphAnalyzer.py`（新增方法）

**新增方法**：`analyze_health(call_graph: dict) -> dict`

**功能**：基于调用图数据，计算代码结构健康度指标：

1. **孤立函数分析**：
   - 数量、占比、Top20列表（含文件和行号）
   - 分类：公共API（可能被外部调用）vs 内部函数（真正孤立）
   - 阈值：孤立函数占比>10%标记为"偏高"

2. **热点函数分析**：
   - Top20被调用次数最多的函数
   - 识别"超级函数"（被调用>100次，可能是God Function）
   - 阈值：单个函数被调用>100次标记为"关注"

3. **循环调用检测**：
   - 所有循环调用链（长度≥2）
   - 分类：直接循环（A→B→A）vs 间接循环（A→B→C→A）
   - 阈值：存在循环调用标记为"需关注"

4. **调用深度分析**：
   - 最深调用链（含路径）
   - 平均调用深度
   - 阈值：最深调用链>15层标记为"过深"

5. **跨文件耦合分析**：
   - 跨文件调用占比
   - 模块间耦合度（每个模块被多少其他模块调用）
   - 识别"核心模块"（被大量调用）和"边缘模块"（很少被调用）

6. **健康度评分**：
   - 综合评分（0-100），基于上述5个维度
   - 等级：优秀(≥85)/良好(70-84)/一般(55-69)/需改善(<55)
   - 各维度得分和改进建议

**输出结构**：
```python
{
    "score": 78.5,
    "grade": "良好",
    "isolated": {"count": 45, "ratio": 0.038, "top20": [...]},
    "hot": {"top20": [...], "super_functions": [...]},
    "cyclic": {"count": 2, "chains": [...]},
    "depth": {"deepest": 12, "average": 3.5, "chain": [...]},
    "coupling": {"cross_file_ratio": 0.38, "core_modules": [...], "edge_modules": [...]},
    "recommendations": ["建议1", "建议2", ...],
}
```

## 五、风险与注意事项

1. **AST解析兼容性**：Python 3.12的AST可能有新节点类型，需确保解析器兼容
2. **动态调用无法静态分析**：`getattr()`、`eval()`、装饰器等动态调用无法静态解析，应明确标记为"未解析"，不要猜测
3. **性能优化**：全库2.5万行分析，需注意AST解析的性能。可使用多进程并行分析（但需控制内存）
4. **循环调用检测**：DFS检测循环调用需设置最大深度，防止栈溢出
5. **调用图数据量大**：全库调用图可能有数千节点和数万边，导出JSON时注意文件大小（可能>10MB）
6. **不修改器官代码**：本批是纯分析任务，不得修改任何器官代码
7. **anchor文档需先调研**：写文档前先grep现有anchor装饰器的实际用法，确保文档与代码一致
