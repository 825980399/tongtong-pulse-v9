## 一、为什么有这个补正（星轨终验实测，必须先读懂）

T2 的"回填 API + 单元测试"本身正确（`tests/test_m70_lazy_materialize_m81.py` 5 例全绿），**但 API 从未接进生产运行链路**。路灯交付报告第一节声称"`get()` 访问节点前接线 `if getattr(node,'_m70_blanked'): self._m70_materialize_lazy_node(node)`（置于 activate() 前）"，星轨通读代码核实**该行并不存在**——与报告第七节自述的"Edit 工具对 main.py/长文件插入式编辑假成功（报成功但未落地）"同源。

星轨 grep + 读码实测（行号为补正前基线，施工后以实际为准并在交付中重新贴出）：

| 检查项 | 实测结果 |
|---|---|
| `PulseNodePool._m70_materialize_lazy_node` 定义 | 在 `PulseNodePool.py:2575`，逻辑正确（_m70_keep 内存优先→`recall_cold_nodes_batch` 冷召回→fail-closed ERROR） |
| **该方法的生产调用方** | **0 处**（全仓只有定义和方法体内自引用；`get()` L648–707 内没有任何调用） |
| `PulseSnapshot.set_cold_recall_source` | 定义于 `PulseSnapshot.py:1649`；**生产 0 调用**（仅测试 `test_m70...m81.py:123` 调） |
| `PulseSnapshot.materialize_lazy_nodes` 公开入口 | 定义于 `:1724`；**生产 0 调用**（仅测试 :106/:160 调） |
| main.py 对 `materialize/set_cold_recall/recall_cold/hot_cold_load` | **0 匹配**，启动未注入召回源 |

**后果**：当前三开关 False，lazy 清空不执行，线上零影响（已验零回归）；但一旦灰度第三步打开 `SNAPSHOT_HOT_COLD_LOAD`，L2/L3 节点被清空正文后，`get()`/KAL/胃/对话拿到 blanked 节点**不会回填 → 返回空正文，重蹈 G0 分层塌缩覆辙**。故 T2 不予验收，灰度第三步在本补正闭环前禁止开启。

现有 5 例测试的盲区：它们都在测试里**手动** `set_cold_recall_source(...)` / 手动 `materialize_lazy_nodes()`，所以绿；没有任何一例走"真实装配 + 真实 `pool.get()` 访问 blanked 节点 → 自动回填"的链路。本补正必须用这样的集成测试证明接线真实落地（先红后绿）。

## 三、任务清单

### T1 · PulseNodePool 单点 serve 热路径接线（根因主修复）
- 在 `PulseNodePool.get()`（基线 L648）中，节点已确定（三池命中或冷召回）之后、`node.activate()`（基线 L682）之前，加入：节点若 `getattr(node,"_m70_blanked",False)` 为真，先回填正文再继续。
- **锁安全硬约束（不得踩坑）**：`get()` 整体在 `with self._lock:`（基线 L655）内，而 `_m70_materialize_lazy_node → recall_cold_nodes_batch` 含 parquet 读 IO（可能百毫秒~秒级）。**不得在持锁状态下做冷 IO**，否则会把全局锁拖成队头阻塞、重新拉高队列深度。要求采用下列之一并在报告说明选型理由：
  - (a) 锁内仅做"内存 `_m70_keep` 快速回填"（纯内存、无 IO，可在锁内）；若内存无 keep，记录待召回 id 并在**释放锁后**调用批量/单点冷召回，再二次加锁写回节点 value/linked_nodes；或
  - (b) 沿用现有冷召回在锁外准备、锁内提交的模式（参考 get() 基线 L675 `_recall_cold_node` 的既有处理位置，评估它是否已在锁内 IO——若是历史问题，仅在报告记录、本批不扩大改动，但新增 m70 路径不得新增锁内 IO）。
- 关开关时节点无 `_m70_blanked` 属性 → 该分支必须 no-op、零额外开销、零回归。

### T2 · snapshot 冷召回源自动绑定（根因解，避免再靠 main 记得注入）
- 在 `PulseSnapshot.set_node_pool()`（main.py 基线 :717 调用）内部，绑定 pool 成功后**自动**设置 `self._m70_cold_recall_fn = node_pool.recall_cold_nodes_batch`（用 getattr 判空、可被 `set_cold_recall_source` 显式覆盖）。
- 这样不依赖 main 显式调用即生效（消除"main 漏调→fn 永远 None"这一整类失效）；同时在 main.py 装配段（建议紧邻 :717 `set_node_pool` 之后）**显式再调一次** `self.snapshot.set_cold_recall_source(self.node_pool.recall_cold_nodes_batch)` 作为双保险，二者不冲突。

### T3 · 批量/正文消费热路径接线
- 复核 `get_all_including_evicted`（基线 L1216/1244/1256）对 blanked 节点是否已能取回正文（T4 已接 `recall_cold_nodes_batch`/`_recall_cold_node`）；若取回的是 blanked 节点，需在该批量出口统一回填一次（优先批量 `recall_cold_nodes_batch`，禁止逐节点 IO 形成 N+1）。
- 定位并接线三类"需要正文"的消费方，在取用候选节点正文前调用 `snapshot.materialize_lazy_nodes(ids)` 或 pool 批量回填：
  1. KAL 检索/知识召回；2. 胃（PulseStomach）消化读取；3. 对话上下文组装/内在世界取节点正文。
  - 只用到元数据（node_id/evol_level/keywords/向量）的路径**不要**回填，保留省内存收益。
  - 每处接线在报告中贴 文件:行号 + 调用行，并说明为何该处"需要正文"。
- 启动加载顺序：确认 lazy 加载（main.py 基线 :1851 `load_batch_lazy`）之后、首个对话/消化周期之前，召回源已绑定（T2 保证），必要时在启动序列加一行"先 compaction 后 lazy、召回源就绪"的断言或 DEBUG 日志。

### T4 · fail-closed 可观测
- 回填失败（无 `_m70_keep` 且冷存无副本）时必须 ERROR 可见（API 已具备），确认热路径接线后该 ERROR 能带上 node_id 与触发器官；不得 try/except: pass 吞掉。
- 回填成功后正确清 `_m70_blanked`、移出 `_m70_lazy_ids`、`_cold_evicted.discard(id)`（API 已具备，接线处不要重复破坏状态机）。

### T5 · 集成测试（证明接线真实落地，关键，先红后绿，禁 mock 召回）
新增 `tests/test_m70_production_wiring_m81b.py`，至少包含：
- **A. 自动绑定测试**：构造 snapshot + 真实 PulseNodePool（可接临时冷存目录），只调 `set_node_pool(pool)`，断言 `snapshot._m70_cold_recall_fn is pool.recall_cold_nodes_batch`（不手动 set_cold_recall_source）。
- **B. 真实 serve 回填测试（核心反"假成功"）**：向真实冷存写入一个 L2/L3 节点（用临时 parquet 冷存或救命备份副本复制到 tmp，**禁 mock** recall），构造其内存 blanked 占位（有 node_id、`_m70_blanked=True`、value 为空）放入 pool；**全程不手动调用任何 materialize**，直接 `pool.get(node_id)`；断言返回节点 `value`/`linked_nodes` 已等于冷存真值、`_m70_blanked` 已清。
  - 先红证明：在接线前的代码上该测试必须失败（get 返回空 value）；接线后转绿。在报告中贴"先红"输出。
- **C. 锁安全测试**：并发多线程对若干 blanked/正常节点混合 `get()`，断言不死锁、总耗时不随 blanked 节点数线性恶化到锁饥饿（给出可重复的计时断言阈值，例如 N 个 blanked 单点 get 的墙钟时间应与批量召回量级一致、且无串行 N 次全冷存扫描）。
- **D. 关开关零回归**：`SNAPSHOT_HOT_COLD_LOAD=False` 下普通节点 get() 行为与改动前逐字节一致（不触发任何回填分支、无新增 ERROR）。
- **E. 故障注入 fail-closed**：blanked 且冷存无副本、无 keep 时，get() 不返回脏空正文静默成功——至少要能观测到 ERROR（可用日志捕获断言），且节点不丢失、不崩溃。
- 数据只用项目外救命备份 `D:\<PROJECT_ROOT>-pulse-safeguard\20260918_golden_layered\` 的**副本**复制到 tmp，绝不在原备份与真实 data/ 上写。
