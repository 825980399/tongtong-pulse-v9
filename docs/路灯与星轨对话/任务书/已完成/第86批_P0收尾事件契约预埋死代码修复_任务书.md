## T-86b：事件契约设计预埋（T-c1(3)信号分层）

**现状**：第83批 T-c1(3) 标"设计待排"——`nucleus/events/` 下无 `SearchEvent` 类，终止信号和结果信号混用同一事件类型，导致大脑皮层把"终止后的空结果"误读为"我来兜底"。

**改法**：
1. **设计**：定义事件类型分层：
   - `SearchEvent.COMPLETED`（搜索完成，带结果）
   - `SearchEvent.FAILED`（搜索失败，带原因）
   - `SearchEvent.TERMINATED`（搜索被主动终止）
2. **接线**：
   - 控制器发射点：根据搜索结果类型发射对应事件
   - 大脑皮层订阅点：只响应 COMPLETED/FAILED，不响应 TERMINATED
3. **最小改动**：只改事件常量 + 发射点 + 订阅点，不重构整个搜索流程。

**先红后绿**：
- 新增测试：搜索被终止时，断言大脑皮层收到 TERMINATED 事件但不触发兜底；
- 改前：终止信号和结果信号混用（红）；改后：分层明确（绿）。

**先红后绿**：

## T-86e：verification_learning_hub DEBUG 刷屏（新增）

**现象**：运行日志中 `[verification_learning_hub] DEBUG: [验证决策校验] code_learner/exploration_audit 置信度=0.90 匹配度=0.70，规则判定=False，实际=True（不一致，供阈值调优` 连续16行刷屏（22:24:49）。

**根因**：验证学习枢纽的"验证决策校验"日志级别为 DEBUG，但批量审查时高频输出，且内容重复（同一 code_learner/exploration_audit 反复输出相同结论）。

**改法**：
1. 同一条规则（code_learner/exploration_audit）在短时间内反复输出"不一致"时，加节流（如1分钟内最多1条）；
2. 或把"不一致"明细降为更细的DEBUG级别，只保留汇总（如"累计N条不一致"）。

**先红后绿**：
- 改前：批量审查时连续16行相同DEBUG；
- 改后：同规则1分钟内最多1条DEBUG。
