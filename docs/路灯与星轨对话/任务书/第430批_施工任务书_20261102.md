## 刀1：补丁派单源加上pending（你拍板：开）

**修什么**：现在有10条`runtime_verified`补丁躺在pending里，其中3条低风险的应该被派出去，但派单模块只读history看不到它们——等于生成了也白生成。

**怎么改**：
- 找到`patch_execution_dispatch`取件的地方
- 改成同时读`pending_patches.json`和`patch_history.json`
- 取件条件不变：`status=runtime_verified 且 risk=低`
- 不要重复派同一条补丁——派过的打个标记

**验证**：
- 改完后，那3条低风险补丁真的被派出去了吗？
- 有没有重复派同一条？
- history里原来的取件逻辑有没有被破坏？

## 刀2：开补丁队列老化清理（你拍板：开）

**修什么**：11条僵尸补丁最老的已经躺了9天了，还一直触发"已有待审批"的LLM门禁。开老化的话，超过N天没人理的补丁自动清掉。

**怎么改**：
- `ENABLE_PENDING_QUEUE_AGING` 从 `False` 改成 `True`
- 老化阈值设多少？建议7天（超过7天还没被approve的，自动归档）
- 不要硬删——移到归档目录，留个记录

**验证**：
- 开了之后，真的有僵尸补丁被清理了吗？
- 清理的时候有没有打日志？清了哪几条？
- 新生成的补丁不会被误清吧？（7天阈值应该够了）

## 刀3：台账外1289处silent_exc缺level补齐

**修什么**：429批只补了台账内421处，台账外还有1289处/252个文件缺level参数。纯机械活。

**怎么改**：
- 全库扫一遍`silent_exc(`调用，找出没写`level=`的
- 批量补`level="debug"`（和默认行为一致，不改语义）
- 逐文件隔离：备份→改→py_compile→失败回滚
- 注意中文行的字节偏移坑（429批踩过）

**验证**：
- 补了多少处？252个文件都补完了吗？
- 全库现在还有缺level的吗？
- 行为有变化吗？（应该没有，因为默认就是debug）
