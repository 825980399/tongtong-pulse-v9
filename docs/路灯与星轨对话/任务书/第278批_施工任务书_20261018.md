## 二、刀1 · 刀2动机环trend_factor（你已拍板选A：更保守）

### 刀1.1 定位
- **问题**：动机环现在根本没有报告输入口——PulseMotivationCycle._update_motivations:343—390的全部输入只有两路：经验池正样本positive[:5]、负样本negative[:3]。
- **你的拍板**：选A——更保守——评分降⇒trend_factor<1（她觉得"我状态不好，少搞点"）

### 刀1.2 改动
1. **第三路乘性修正**（不加新权重键）：
   ```
   trend_factor ← 由1b的结构化日报（score变化、self_cognition消费率、lfi delta_vs_prev）映射到 [0.85, 1.15]
   intensity    = reward_intensity * (1 - resource_pressure*0.5) * trend_factor
   溯源          动机payload带 {trend_source_report_id, trend_score_delta, trend_as_of}
   ```

2. **为什么乘性而非加性**：
   - 现公式已用乘性衰减表达"资源压力"
   - 再加性项会破坏界（intensity可能>1）
   - 乘性有界是这条链的既有不变量

3. **三条硬约束**：
   - ①stale报告不参与——如果昨日跨夜日报过期了（>24h），trend_factor=1（不修正）
   - ②trend_factor一律夹紧[0.85,1.15]并在payload留原值——防止她突然变得太保守或太激进
   - ③符号方向：选A（更保守）——score降⇒trend_factor<1（"我状态不好，少搞点"）；score升⇒trend_factor>1（"我状态好，多搞点"）

### 刀1.3 验收
- 重启后动机环会有第三路输入——trend_factor
- 重启后trend_factor由1b的结构化日报映射到[0.85,1.15]
- 重启后stale报告不参与（trend_factor=1）
- 重启后符号方向：选A（更保守）——score降⇒trend_factor<1
