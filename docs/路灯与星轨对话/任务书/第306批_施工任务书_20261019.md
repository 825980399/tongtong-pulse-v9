## 二、刀1′ · 补反射边（P0 · 实装event/entry两类kind）

**问题**：305刀2分色落地名义达成、实质只有3条边，event/entry两类根本没有写入路径。edges[]确实含kind字段，但边kind分布={static: 7367, byname: 3}，event: 0, entry: 0。

**改动**：
- CallGraphAnalyzer.py：实装event/entry两类kind的赋值路径
- event边：事件注册表（subscribes/handlers）的字符串常量事件名
- entry边：注册入口（on_/handle_/do_/signal_等总线反射调用的处理器）
- _resolve_by_name的多义策略从"直接放弃"升级为作用域优先消歧（同类→同模块→同目录）

**验收**：
- event边从0起步
- entry边从0起步
- byname边从3条提升（可调用体的按名边，不是1878条提及数）

## 三、刀2′ · 三轨合一（P0 · problem_fixed回写台账）

**问题**：305刀5的problem_fixed由T4派生只落在评估器输出层，台账未回写——现在仓里有两个同名problem_fixed：评估器输出层84/84（True 68/False 16）与台账层84条（True 58/None 26）。对外数字将自相矛盾。

**改动**：
- patch_verification_split.py：problem_fixed改为由reprobe_verdict派生（true_pass→True/partial_fix→None或False加partial标/not_applicable+None→None且带no_probe原因码）
- 14条真不可判保留None并标no_probe/legacy_unverifiable出分母（不许折叠成False）
- avg_fix_rate/real_fix_rate改读同一派生源

**验收**：
- problem_fixed全仓只有一个源
- 同名字段两处的数必须相等（现为68对58，差10）
- avg_fix_rate/real_fix_rate从同一派生源算
