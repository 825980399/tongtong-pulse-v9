> 依据：烛微《455批前置风险深挖》868行 + 454交付核验 + 在线实测发现种子分数过低
> 性质：**P1第二批**——hypothesize影子模式（只生成不进答案）+ 种子分数修正
> 前置：454已交付并重启（pid=26328）

## 背景

454交付后在线实测发现：注入开关开了、origin=user_query也对，但种子候选全部被`low_score<0.65`过滤了——因为种子的`_match_score`基础分只有0.50，实际query匹配下来大概0.60-0.63，够不到0.65的准入线。

本批做两件事：
1. 修正种子分数问题（种子是人工精选，不该跟经验池一样按0.65卡）
2. 落地hypothesize LLM算子的**shadow模式**——只生成假设记trace，不进最终答案

---

## 刀1 · 种子证据跳过min_score过滤（修正454）

**白话**：种子是我们人工精选的50条高质量证据，不该跟经验池里那些自动生成的模板一样按0.65分数卡——分数太低全被挡在外面了。

| 项 | 内容 |
|---|---|
| 改动 | `PulseLung.py:2366-2379`：种子候选合并进`_block453`时，给每条打`seed_override=True`标记 |
| build_injection | `evidence_injection.py`：`min_score`过滤时，`seed_override=True`的候选跳过分数闸（仍走净化/去重/top_k） |
| 阈值 | 种子单独给个更低的下限0.55（防完全不相关的硬进），不直接0门槛 |
| 开关 | `M454_SEED_MIN_SCORE = 0.55`（config.py） |
| 验收 | 同入口candidate_stats：query模式下种子命中≥10条（之前只命中1-3条） |

## 刀2 · hypotheses独立模块（新建nucleus/reasoning/hypothesize.py）

**白话**：给"假设"单独开一条电话线——不复用原来那套45秒裸HTTP的分支生成，自己控制超时、自己控制输出格式。

| 项 | 内容 |
|---|---|
| 新建 | `nucleus/reasoning/hypothesize.py` |
| 函数 | `hypothesize(question, evidence, *, deadline, origin, max_hypotheses=2)` |
| 返回 | `{status: ok|insufficient_evidence|timeout|parse_error|skipped_no_budget, hypotheses: [...], elapsed_ms}` |
| 渠道 | 复用`_m31_branch_endpoint`的端点解析，但**不复用**`_model_cache` |
| 超时 | `timeout = min(8.0, deadline - now - 10.0)`；剩余<12s直接`skipped_no_budget` |
| 参数 | `max_tokens=320`、`temperature=0.4` |
| 验收 | 单测：无证据时不调用LLM；超时返回timeout；剩余不足时跳过 |

---

## 刀3 · hypotheses JSON输出契约+解析

**白话**：让模型按表格填，不按表格填就不收——它说的是假设还是事实，系统必须分得清。

| 项 | 内容 |
|---|---|
| Prompt | 要求严格JSON输出：`{"speculative": true, "hypotheses": [{"claim": "...", "assumptions": [...], "evidence_ids": ["E1"], "confidence": 0.0, "test": "..."}]}` |
| 解析 | 去掉```json围栏后json.loads；失败⇒`parse_error`，该步跳过，**绝不把原文塞答案** |
| 校验 | `speculative`必须为true；`evidence_ids`只能引用本次提供的；`confidence`夹到[0,1]；无证据⇒confidence封顶0.3 |
| 上限 | 最多2条，超过截断 |
| 验收 | 单测：正常JSON解析成功；乱码/截断JSON返回parse_error；无evidence_ids时confidence≤0.3 |

## 刀4 · 请求级LLM算子计数器 + 预算控制

**白话**：一个请求只发一张"假设券"，用完就没了——重试也不能再领。

| 项 | 内容 |
|---|---|
| ContextVar | 请求级`llm_ops: int`计数器（加到evidence_injection的请求状态里） |
| 硬限制 | `hypothesize`调用前`if llm_ops >= M455_MAX_LLM_OPS(=1): return skipped_budget` |
| 计数 | 调用开始时`llm_ops += 1`；重试复用同一计数不清零 |
| 总预算 | 从Cortex收到问题开始计时；hypothesize最多8s；最终回答预留10s |
| 开关 | `M455_MAX_LLM_OPS = 1`（config.py） |
| 验收 | 单测：两次hypothesize只执行一次；重试不重复计数；并发两请求各自独立 |

---

## 刀5 · hypotheses shadow接线（只生成不进答案）

**白话**：先让假设模型在旁边"模拟思考"，记下来但不放进回答——看它想得对不对。

| 项 | 内容 |
|---|---|
| 触发 | 问题含`假设/如果/假如/会不会/可能/推测/推演/会怎样`等关键词 |
| 位置 | `_multi_step_execute_v2`：如果计划里有op=hypothesize，调`hypothesize()` |
| Shadow模式 | 结果写进`step_results`（status/elapsed_ms/hypotheses摘要），**不拼进最终答案prompt** |
| 开关 | `ENABLE_M455_HYPOTHESIZE_SHADOW = True`（config.py默认True，只shadow）；`ENABLE_M455_HYPOTHESIZE = False`（进答案的开关默认关） |
| trace | `step_results`里加`op=hypothesize`、`hypothesis_count`、`avg_confidence` |
| 验收 | 跑一个"如果……会怎样"的问题，trace里能看到hypothesize执行记录，回答里不出现假设内容 |

---

## 刀6 · 计划生成加op=hypothesize触发条件

**白话**：新添了一台假设机器，生产计划里也得给它排个工位——只有用户真的在问"如果……会怎样"才排。

| 项 | 内容 |
|---|---|
| 改动 | `_generate_task_plan`：加op=hypothesize触发条件 |
| 触发 | 问题含`假设/如果/假如/会不会/可能/推测/推演/会怎样/什么情况下`；或前序compare/quantify返回insufficient且问题开放式 |
| 限制 | 最多1个hypothesize步骤；`depends_on`指向提供证据的前序步骤 |
| 不触发 | 事实型问题（是什么/多少/哪一年）不触发 |
| 验收 | 单测："如果……会怎样"类问题计划里有op=hypothesize；"是什么"类没有 |

## 风险提示

1. 本批是**纯shadow**——hypothesize只生成不进答案，对线上回答零影响
2. 种子跳过min_score过滤后可能进一些不太相关的，仍走净化/去重/top_k
3. hypotheses用的渠道端点和分支生成一样，但超时更短、输出格式更严
4. 开关默认：shadow开、进答案关——出问题随时关
