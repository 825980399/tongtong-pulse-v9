4. 过滤逻辑要有注释说明为什么

### 验收标准

- 老污染条目被标记/剔除，不再参与search()匹配

## 刀3（P0）观察位判据对齐：expired_pending自愈不算健康

### 背景
406刀4实测：观察位数量5条（WATCH_CAPACITY=5），但可派单永远0。原因：
- 自愈侧（self_heal_watch）的"健康"判据只看"在不在pending文件里"
- 派单侧（patch_execution_dispatch.py:3004）对expired_pending返`(False, "expired")`
- 5条观察位全指向expired_pending（3条）或已结案（2条）
- 结果：数量永远达标、可派单永远0，破零三道闸永远走不通

### 施工要求
1. 定位self_heal_watch的健康判据代码
2. 改判据：expired_pending不再算"健康观察位"，要自愈补满时跳过expired的，补真·eligible的
3. 如果当前没有eligible的补丁，观察位数量应该显示为0而不是5（如实反映）
4. 派单侧逻辑不动（它拒派expired是对的）
5. 加埋点：观察位补满时打日志说明补了哪几条、为什么跳过expired的

### 验收标准
- expired_pending不再被算进"健康观察位"
- 观察位数量如实反映可派单数
- 自愈补满时跳过expired的
- 跑单测：造3条expired+2条eligible，确认观察位只算2条
