## 施工项4：每日 Tokens 用量统计＋付费阈值告警

**目标**：每日能看到曈曈调用API的 Tokens 总量（分渠道/分模型/免费vs付费），据此判断免费额度是否够用、是否需要再添免费平台。

**实现**（`nucleus/llm/call_recorder.py`，`LLMCallRecorder.record()` 聚合点）：

- 新增每日汇总落盘 `data/llm_traces/daily_tokens.json`（**当日滚动**，日期切换自动重置）：
  ```json
  {
    "date": "2026-10-23",
    "calls": 123,
    "total_tokens": 123456,
    "by_channel": {"zhipu-47-flash": {"calls": 80, "tokens": 10000}, "deepseek": {"calls": 3, "tokens": 5000}, ...},
    "by_model": {"glm-4.7-flash": {...}, ...},
    "paid_tokens": 5000,
    "free_tokens": 118456,
    "alerted": false,
    "updated_at": "..."
  }
  ```
- **付费判定**：渠道名 ∈ 付费集（当前仅 `deepseek`；配置新增 `PAID_CHANNELS = {"deepseek"}` 单一来源，未来新增付费渠道改此处）
- **阈值告警**：`paid_tokens` ≥ `DAILY_PAID_TOKEN_ALERT`（默认 **1,000,000** tokens/日）→ 日志 `WARNING [每日Tokens] 付费tokens=N 超阈值(1000000)，建议评估免费渠道额度/新增免费平台`
- **查询入口**：新增 `get_daily_tokens()`（返回当日汇总 dict）；命令行验证 `python -c "from nucleus.llm.call_recorder import get_daily_tokens; import json; print(json.dumps(get_daily_tokens(), ensure_ascii=False))"`
- **测试**：模拟免费+付费混合 3 条 record → by_channel/by_model/paid/free 聚合正确；日期切换重置为 0；告警阈值触发/不触发两例

> 兼容：`record()` 每次写 jsonl 的既有逻辑不动（写文件时同步更新汇总，用同一把锁防并发写坏）。
