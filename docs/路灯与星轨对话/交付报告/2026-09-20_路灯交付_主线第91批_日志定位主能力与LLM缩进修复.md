## 1. 根因定位（T0 实测，全部可复现）

### 1.1 T-91a 根因：**两个命名源结构性错位**

日志 TAG 由 `nucleus/logger.py:104-128::PulseFormatter.format` 从 **logger 名**派生：

| logger 名 | 日志 TAG | 规则 |
|---|---|---|
| `pulse.organ.胸腺` | `胸腺` | 去 `pulse.organ.`，再去 `Pulse` 前缀 |
| `pulse.organ.PulseHeart` | `心脏` | 同上（但生产代码传的是 `organ_name="心脏"`，非 `PulseHeart`） |
| `pulse.framework` | `框架` | **硬编码特例** |
| `pulse.module.WriteGuard` | `WriteGuard` | 去 `pulse.module.` |
| `pulse.structured_parallel` | `pulse.structured_parallel` | 其余 → 原名 |

logger 名来自 `BasePulseOrgan.__init__` 的 `get_organ_logger(self.organ_name)`。
而旧索引 `_build_organ_name_index()` 读的是**统一头部中文短语**
（`PulseEyes —— 脉冲驱动眼睛（知识检索器官 · v9.5 …）`）。

⇒ **命名源错位**：头部短语 `脉冲驱动眼睛` ≠ logger 名 `眼睛`。结果 16 个真实标签恒不可定位。

16 个缺口标签（V3 关闭时**恰好**这 16 个不可定位，结构性、不随日志增长变化）：

- **模块名 / logger 名型（9）**：`self_inspector`、`verification_learning_hub`、`wecom_chat_bridge`、`SemanticKernelService`、`WriteGuard`、`pulse.structured_parallel`、`自主探查`、`时间中枢`、`pulse`

## 3. T-91b 交付内容：LLM 补丁「缩进契约」三层防护

### 3.1 根因（T0 实测）

日志症状：`补丁验证失败: 语法错误: unindent does not match any outer indentation level`。

**根因 1（报错机理）**：`PatchManager._check_llm_patch_completeness` 关2（L1270-1278）：
```python
_ast.parse("def _wrap():\n" + _tw.indent(_tw.dedent(_modified).strip(), "    "),
           filename="<llm-patch>")
```
复现样本 A `"    def foo(self):\n        x = 1\n      return x"` ⇒ **逐字命中**
`IndentationError: unindent does not match any outer indentation level (<llm-patch>, line 4)`。
**报错行号 = 内容行 + 1**。样本 B（tab/空格混用）⇒ `TabError`；样本 C（首行缩进偏少）**反而 PASS`。

**根因 2（prompt 缺契约）**：`_call_llm_with_followup._call` 的 system prompt（L845-852）
**完全未提缩进**（只有 ASCII / 标点 / 括号要求）；`_clean_llm_code`（L2554）
只有「全角标点归一化」一种修复能力，**完全不处理缩进**。

**根因 3（★静默症状，危害更大）**：`PatchManager._verify_in_copy` 用
`modified_full = full_content.replace(original, modified)`（L915）—— **原位整段替换**。
插入块的缩进由 modified **自身首行**决定；首行落在 col 0 而原文在 col 12 ⇒
**类体提前终止**（方法被改写成模块级函数）；而插入块**自身在 base 0 上仍自洽** ⇒
`ast.parse` / `py_compile` / `import` **全部放行**——「语法合法 ≠ 结构未退化」。

**量化（`logs/pulse.log`）**：`补丁完整性检查失败` 12 次 / `语法错误` 8 次 / `unindent` 8 次。

**权威依据**：`modified` 的基础缩进**必须与 `original` 一致**（原位替换语义）。

### 3.2 三层防护（开关 `ENABLE_M91_LLM_INDENT_REPAIR`，默认 True）

| 层 | 位置 | 内容 |
|---|---|---|
| ① **prompt 契约** | `SafeEvolutionExecutor.py` L875-881 | 追加：*「保持与输入代码**完全相同的缩进层级与缩进宽度**：每个缩进层级使用 4 个空格，禁止使用制表符；只返回修复后的完整方法（含 def 行及其原有缩进），不要提升或降低代码所在的层级。」*（受开关控制） |
| ② **`_clean_llm_code` 阶段3** | L2728+ | 仅当关2 同口径 `_m91_gate2_parse` 失败时，对原串与当前串各试 `_m91_repair_indentation`，**过关2 才采纳** |
| ③ **基础缩进对齐** | `_m91_align_base_indent` | 三处补丁构造点（蒸馏 / `_submit_llm_patch` / 多文件阶段B）在 `_clean_llm_code` **之后**追加：`base(modified) < base(original)` 时行级 pad 平移，平移后**复验关2**，不过则放弃 |

**新增 helper**：
- `_m91_gate2_parse(code) -> (ok, err, lineno)` / `_m91_gate2_check(code) -> (ok, err)`（关2 **同口径**）
- `_m91_base_indent(code)`（**首个可执行行**，**跳过空行与纯注释行**；空 → -1）
- `_m91_indent_levels(lines, unit=4)`
- `_m91_repair_indentation(code)`：**行定位法**（`SyntaxError.lineno` — 行号只修报错行）；候选集**只取既有缩进层级**（等距取更深）；TabError 兜底（行首 tab 按 4 列展开）；最多 8 轮；最终仍不过关2 则**原样返回**
- `_M91_INDENT_UNIT = 4` / `_M91_REPAIR_ROUNDS = 8`

### 3.3 ★本批自曝并修复的 P0 级接线缺陷（门禁1 抓出，非事后发现）

**症状**：门禁1 `ruff check --select F` 报 **F821 × 3** —— `Undefined name '_llm_clean'`
（`SafeEvolutionExecutor.py:1572 / 2862 / 4542`）。

**根因（我的补丁缺陷）**：三处调用点本应是**在 `_llm_clean = self._clean_llm_code(...)` 之后追加**对齐调用，
实际却把该行**整行替换**成了对齐调用。后果：

1. `_clean_llm_code` 全项目**零调用** ⇒ **阶段3（缩进修复）+ 全角归一化 + code fence 剥离整体失效**；
2. `_llm_clean` 在赋值前被引用 ⇒ 三处均 `UnboundLocalError`。

**为什么既有 31 个单测没抓住**：A~G 组全部**直接调用** helper，从不校验「helper 是否真的被生产链路调用」
⇒ 「31 passed 全绿」与「生产链路已断」并存 —— **典型假绿**。

**修复**（字节级脚本 + 两行锚点消除缩进歧义 + 读回核对）：

```
改前（错）:  _llm_clean, _ = self._m91_align_base_indent(...)
改后（对）:  _llm_clean = self._clean_llm_code(<X>)  # ★PHASE17-A2
             _llm_clean, _ = self._m91_align_base_indent(...)
```

读回核对：`_clean_llm_code` 定义 L2785、调用 L1571 / L2863 / L4543（**恰 3 处，与改前一致**）；
`_m91_align_base_indent` 调用 L1572 / L2864 / L4544（**紧跟生产者**）。

**新增 H 组「调用点接线门禁」**（`test_llm_indent_contract_m91.py`，+6 用例，纯 AST 静态判定）：

| 用例 | 断言 |
|---|---|
| H1 | `_clean_llm_code` 调用数 **≥3**（防「被误删调用」死代码）且定义数 == 1 |
| H2 | **每一处** `_m91_align_base_indent` 的**前一条语句**必须把 `_llm_clean` 从 `_clean_llm_code(...)` 生产出来 |
| H3 | 消费端第 2 位置实参必须是 `_llm_clean`（生产者-消费者同名） |
| H4 | 对齐结果必须被接住（`x, _ = ...`），不允许丢弃 |
| H5 | 先红 AST：改前 3 调用 / 0 对齐；改后 3 调用 / 3 对齐 ⇒ 证明**纯增量** |
| H6 | 运行时冒烟：两个 helper 真实可调，且 `_clean_llm_code` 输出能过关2 |
