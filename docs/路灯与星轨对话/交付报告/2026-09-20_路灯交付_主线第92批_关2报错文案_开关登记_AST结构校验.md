### 1.3 T-92c/T-92d 根因：第91d 事故机制（"语法合法 ≠ 结构未退化"）

`_verify_in_copy` 的替换是**原位整段替换**（`:915`）：

```python

```

`replace` **不改变缩进** ⇒ `modified_code` 的基础缩进若与 `original_code` 不一致，
替换后的整份源码**仍是合法 Python**，但**类体/函数体被提前终止**。

T0 用**真实事故原件**（`data/patches/patch_history.json` 中两条 `source=llm` 补丁）实测：

| 补丁 id | 文件 | `base(original)` | `base(modified)` | 类方法 | 模块级函数 | `ast.parse` | `compile` |

| `patch_llm_1789886168_789a` | `organs/brain/PulseInnerWorld.py` | **8** | **0** | 368 → **271**（**-26.4%**） | 4 → 5 | ✅ 通过 | ✅ 通过 |

事故形态（`patch_llm_1789886168_789a` 的 `modified_code` 开头，逐字）：

```python
import logging
import re

logger = logging.getLogger(__name__)


def _calc_math_question(question):

        ...
```

即：**col 0 的 `import` 让 `class PulseInnerWorld:` 提前终止** → 其后 97 个
`    def xxx(self):`（4 空格）成为模块级 `def _calc_math_question` **体内的嵌套函数**
（4 空格恰好是它的函数体缩进）⇒ 整份文件**仍然解析通过**，但类方法数掉了 97。
