## 2. T-90a 落地：从「补字段」转为「补校验」（关0）

### 2.1 根因定位：为什么必须**单列一关**

改前，`original_code` 为空时的实际链路：

1. **关1 通过** —— 判据是 `not _mod_norm or _mod_norm == _orig_norm`；`original` 为空、`modified` 非空 ⇒ **不拦**；
2. **关2 通过**（语法可解析）；
3. **关3 拦下，但报错文案是错的** —— `ratio(("", mod)) == 0.0 < 阈值` ⇒ 报「与原文相似度过低(0.00 < 0.3)」，
   **把「字段没传」伪装成「内容残缺」**；
4. **还有两条静默短路**（本批新发现）：
   - 关3 内层 `except Exception: pass`（相似度计算失败即不阻断）；
   - 关3b 的前置条件是 `_orig_norm` 非空且 `_m89_len_floor() > 0`；
   - ⇒ 三者叠加时，空 `original_code` 的补丁可**同时绕过关3 与关3b**。

⇒ **「字段缺失」这条判据必须结构性地独立成关**，且与任何灰度开关/阈值解耦。

### 3.1 bug#1 · message 时机错位 + 「试一次即永久封死」

**根因**：`LogAnalyzer._scan_log_file` 中，定位发生在 **message 赋值之前两行** ⇒
首次定位实际调用 `_locate_for_issue(organ, "")`，而 `guess_method_from_message("")` **恒返回空方法名**
⇒ 即便文件定位成功也拿不到行号，且置信度被 **-0.2** 惩罚；更糟的是
`_locate_attempted = True` 被**无条件**置位 ⇒ 该问题**整个生命周期内定位机会为 0**。

**改法**（`LogAnalyzer.py`，+86/-15 行）：
1. message **提前**到定位之前填充；
2. 由「试一次即封死」改为**有界重试**：`_LOCATE_MAX_ATTEMPTS = 2` +
   新字段 `_locate_attempts` / `_locate_tried_msg`；新增 `_m90_should_locate` /
   `_m90_mark_located` / `_m90_apply_location`（后者是**纯抽取**，写回语义与改前逐字一致）；
3. 判据：已定位→不试；message 空→不试（**等 message 到位再试**）；达上限→不试；
   message 未变→不试（避免纯重复开销）。

**先红后绿（真跑 `_scan_log_file`，spy 捕获入参）**：

```
[legacy] _locate_for_issue 被调 1 次: [('胃', '')]            ← 首调 msg 为空串（红）
[now]    _locate_for_issue 被调 1 次: [('胃', '2026-09-20 14:00:31 [胃] ERROR: JSON 解析失败...')]  ← 非空（绿）
```

### 3.2 bug#2 · 类名标签恒不命中（第87批建好的类索引没接上来）

**根因**：`self_inspector.locate_issue` 的 1c 段只用 `_build_organ_name_index()`（**243 个中文头部名**），
而真实日志标签**多为类名**（`InfoField` / `PulseSnapshot` / `PulseNodePool` / `SafeEvolutionExecutor` …）；
第87批已建好的**全项目类索引（1007 类）** 从未接进本函数 ⇒ 恒 MISS。

**改法**：1c 段改为四路优先级
**类索引(0.75) → 中文名精确(0.7) → 前缀(0.6) → 包含(0.6)**，并保留原置信度阶梯。

### 3.3 bug#3 · 中文标签匹配写的是**前缀**关系

**根因**：`_cn.startswith(tag) or tag.startswith(_cn)` 只认前缀，
而「`胃` vs `脉冲驱动胃`」「`肺` vs `脉冲驱动肺`」「`框架` vs `能力框架`」是**包含**关系 ⇒ 双向皆假。

**改法**：在 `_m90_v2` 开启时追加包含匹配 `(tag in _cn) or (_cn in tag)`。

**根因**：`_TRACEBACK_FILE_RE.search(_tb)` 取**首帧** = 最外层调用者。

## 7. 本批发现但需星轨知晓的事项（诚实清单）

### 7.1 两条既有测试的「源码文本模式断言」被本批打破（已按项目惯例改写）

**语义等价、不再依赖固定字符窗口**。属测试侧改写，**不动生产代码**。
