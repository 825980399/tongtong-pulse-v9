## 二、四处票面判断被修正（本批最该看的部分）

### 刀1：不是"按名字拼出来的"，是**配置项**

票面说"全库 grep 不到源码字面量——是按名字拼出来的调度 tick"。实测：

```python
# config.py:143-145（203批刀3 登记）
"runtime_metrics":   {"interval": 60,   "event_type": "runtime.metrics.collect"},
"metrics_collector": {"interval": 300,  "event_type": "metrics.collector.tick"},
"snapshot_rotate":   {"interval": 1800, "event_type": "snapshot.rotate.tick"},
```

三个名字是 **`TIMECORE_SCHEDULE_CONFIG` 的配置值**（不是 const 枚举，所以 grep 事件名
搜不到发布点），注释原文即「消费侧接线待观察窗」—— 事实是**从未接线**。
唯一出口是 `TimeCore._dispatch_managed_tasks()`：到期就发，**不看有没有人接**。

⇒ 票面要求"pub 点加闸门"，但**没有 pub 点可改**。闸门放调度器（三个名字的唯一共同出口），
判据用 InfoField 新公开口 `has_real_consumer()`（与 `dead_events_report()` **同一套**，
剔除 `["*"]` 万能条件，不写第二份）。

### 刀3：不是"去重 key 未生效"，是**根本没有去重**

`PulseLiver` 全文件 `grep dedup|sha256|hashlib` **命中 0**。当日 1,605 条吸收 / 680 个不同正文，
最高一条重复 **70 次**（`[代码关联·PulseInnerWorld] set_node_pool 调用了 _init_kno…`）。
本刀补 sha256 指纹 + 有界集合（4096，FIFO）。

★不用"前 N 字"：种子记忆前缀高度重复（`【种子记忆】[自我理解·X] …`），
按前缀去重会**误杀不同内容**——有专测钉住这一条。

### 刀5：票面的假设不成立

票面：「`_l2_classify_scene` 把所有请求都判成非 code 场景导致 L2 不启用」。
实测：378 刀5 已把准入闸改成"只拒 code"、`user_query` 全放；计数器本身也正常
（本刀用 code 场景实测 `hits>0`）。

真问题是**读数分不出两件事**：① 生产面没人调 `lookup`；② 调了但全 miss ——
两者都显示 `hits=0/misses=0`。本刀加 `idle_state` 四态
（`disabled` / `no_calls` / `calls_no_hit` / `ok`）。
**若重启后仍 `no_calls`，真因是"没人调"，该去查 L1 命中率与调用方，而不是继续改 L2 判据。**

### 刀6：没有重复

32 个托管任务 vs 20 处 `Timer(`。逐项核后：TimeCore 表项是**周期 tick**，
器官内 Timer 是**一次性相位**（心跳对齐 / 单次延迟 / 超时熔断，常带引用捕获）。
迁进 TimeCore 会把"一次性"变"周期性" ⇒ 行为变。故**不迁**，只做两件：
① 在 config 写清 32 项清单与结论；② 把"真重复"定义成可检的守卫——
**Timer 回调里不许出现已登记的 event_type**。

## 四、待裁决 / 遗留

1. **刀1 的闸门默认开**：三个 tick 停发后，若将来真接线了消费者，必须**记得关闸**
   （或让 `has_real_consumer()` 自动放行——本批就是这样设计的：一接线就自动恢复投递，
   不需要改开关）。**这点建议运维知悉**：闸门不是开关，是"按消费者存在与否自动判定"。
2. **刀5 的真因未查**：本刀只给了判别口径。要定论需一次 live 观测：
   `idle_state=no_calls` 还是 `calls_no_hit`。
3. **刀4 未验证真实停服**：只验了装置（Event 可打断、置位点在器官停完之后），
   真实停服时长要下次重启时量。
4. **刀6 的 20 处 Timer 未逐条列出**（只做了守卫）。若要逐条清单，建议单独开票
   （属于文档工作，不影响正确性）。
5. **肝吸收去重只挡"进肝"**：`digest.knowledge` 日志仍会打（DEBUG 级），
   若还要压日志量，需另开——那是日志面，不是去重面。
