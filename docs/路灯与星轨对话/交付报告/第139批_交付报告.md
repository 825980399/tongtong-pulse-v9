## 二、T-139a：退出确认 `input()` 无限阻塞修复

### 2.1 问题（任务书前提，已实测确认）

`main.py::_confirm_apply_pending_on_quit`（原 L3375-3407）在交互终端弹「是否应用并重启验证？(Y/n)」
时直接调用 `input()`。**若 `sys.stdin.isatty()` 判定为真但实际无输入**（伪 TTY / 管道 / 期望脚本驱动），
退出路径将永久阻塞 —— 框架既无法自愈也无法退出。属 P1 紧急。

### 2.2 修复内容

**新增模块级常量**（`main.py`，import 区末尾）：

```python
PULSE_QUIT_CONFIRM_ENV = "PULSE_QUIT_CONFIRM"
PULSE_QUIT_TIMEOUT_ENV = "PULSE_QUIT_TIMEOUT_SEC"
PULSE_QUIT_CONFIRM_DEFAULT_TIMEOUT = 30.0
```

**新增辅助函数** `_prompt_with_timeout(prompt, timeout) -> (answered, value)`：
- 用 **工作线程 + `threading.Event`** 包裹 `input()`；
- 工作线程设为 **daemon**（超时后残留线程不阻塞进程退出）；
- 返回二元组区分三种语义：
  - `(True, str)` — 用户在时限内提交输入；
  - `(False, "")` — **超时无输入**（调用方按默认 Y 继续）；
  - `(False, None)` — EOF / Ctrl+C / 异常（用户取消，视为拒绝）。

**改造** `_confirm_apply_pending_on_quit`：
1. **`PULSE_QUIT_CONFIRM=0`**（兼容 `false/no/off`）→ 非交互直接跳过确认，返回 True，**不调用 input**；
2. `PULSE_QUIT_TIMEOUT_SEC` 可覆盖超时秒数（非法值回落默认 30s）；
3. 超时 → 按**默认 Y** 继续（与任务书「30 秒无输入按默认值 Y 继续」一致）；
4. 用户取消（EOF/Ctrl+C）→ 返回 False（保留原语义，避免意外重启）。

> ⚠️ **首版设计缺陷与修正**：首版 helper 超时与取消均返回 `None`，导致超时被误判为「取消」→ 返回 False，
> 与任务书「超时按默认 Y 继续」相悖（测试 `test_confirm_timeout_defaults_yes` 首跑即捕获）。
> 改为**二元组返回**后语义清晰，测试转绿。

### 2.3 灰度与兼容性

- **默认行为完全不变**：`PULSE_QUIT_CONFIRM` 未设置时走原逻辑（isatty + input），仅叠加 30s 超时兜底；
- **存量测试 0 回归**：`tests/test_main_quit_patch_confirm_m59.py`（第59批 9 例）**全过**——
  其 mock `builtins.input` 立即返回，`_ev.wait(timeout)` 即时满足，行为与改动前一致。
- 关闭零副作用：`PULSE_QUIT_CONFIRM=0` 时不触碰 PatchManager、不弹提示。
