## 一、刀5 冷化容量闸门修复（P0）

### 1.1 ★347 前提订正（先证伪，再动手）

任务书沿用 347 的判断：`total_nodes_all=13708 > max_hot=10000` ⇒「本应持续驱逐却 0 驱逐」是缺陷。实测**不成立**：

| 口径 | 读数 | 来源 |
|---|---|---|
| 节点**全集**（D7 基数） | **13708** | `data/knowledge/pulse_knowledge_snapshot.json` 头 `total_nodes_all`（`l2_l3=13224 / l1_saved=484 / save_mode=full`，mtime 12:25:42，0.662GB） |
| 全部池实时 | total 13755 | `data/monitor/health_snapshot.json -> nodes` |
| **热池** | **9673** | 同上 |

`13708` 是**全部池**基数，不是热池。热池 9673 < max_hot=10000 ⇒ **本就不该触发驱逐**，0 驱逐是正确行为，不是缺陷。

### 1.2 真缺陷（结构缺失，不是"闸门失效"）

`_enforce_capacity()` 全仓唯一调用点是 `add()` 内（`PulseNodePool.py:491`）。而启动从快照恢复走的是 `load_batch()` / `load_batch_lazy()`，**这两条路径一个 `add()` 都不经过** ⇒ 批量装载路径上**根本没有闸门**，热池可越过 `_max_hot` 直到下一次 `add()` 才自愈。

修复：两处循环**外**各补一次 `self._enforce_capacity()`（放循环外只跑一次，避免每节点全扫热池）——`_m348_d5_load_batch_gate` / `_m348_d5_lazy_gate`。

### 1.3 自证（`tmp/p348_root/d5_coldgate.json`，6 例全过）

| 用例 | 输入 | 期望 | 实测 | 结论 |
|---|---|---|---|---|

| **B 负控** | 同上但 `_enforce_capacity` 打桩成 no-op | **hot=20** | 20/0 | ✅ **证明"夹紧"真是闸门干的** |
