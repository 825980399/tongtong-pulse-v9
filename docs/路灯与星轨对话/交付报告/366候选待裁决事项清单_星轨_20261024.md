### 甲1 · 内存自动 GC 真开启（P1 · 候选 T-内存自动GC开启-1 · 重启生效 · 不停机）

**白话背景**：曈曈长跑内存一路涨（362 实测 heap 3070→6066MB、RSS +2.93GB；363 长窗 RSS 3650→6058MB）。框架里本来留了「内存太高就自动回收一次」的闸门，但现在翻不开，等于刹车装在图纸上没接到踏板。历史 L237、L260 两轮都结过 GC 议题，当前仍是**半接线**状态。

**星轨现场复核证据（HEAD 实测，不是引用烛微结论）**：

- 开关定义：`config.py:5425 ENABLE_MEMORY_AUTO_GC = False`；阈值变量 `config.py:5427 MEMORY_AUTO_GC_RSS_MB = 8192.0`（8GB GC 线）；增长率阈值 `config.py:5426 MEMORY_GROWTH_ALARM_MB_PER_MIN = 10.0`。
- 闸门在：`nucleus/runtime_metrics.py:525` 读开关；`:547 if auto_gc and _enable_gc: gc.collect()`。
- **缺口一（调用面没接通）**：唯一现网调用点 `organs/core/PulseMetricsCollector.py:994` 调 `check_memory_alarm_detailed()` **没传 `auto_gc=True`**，形参默认 False。现在就算把 config 开关翻 True，`:547` 第一道 `auto_gc` 仍短路，`gc.collect()` 不会执行——**翻开关＝零行为**。
