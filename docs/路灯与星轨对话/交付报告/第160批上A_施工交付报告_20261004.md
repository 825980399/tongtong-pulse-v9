## 三、刀5（T-身份种子使命-1）— 含根因定位

### 5.1 根因（任务书要求 30 分钟定位）

`config.SEED_MEMORIES[3]`（使命种子）：

```python
{"value": "我的使命是站在世界最顶端，守护这个世界。…",
 "keywords": ["使命", "守护", "新人类", "进化"],
 "space_path": "/身份/使命/核心"}          # ← 关键
```

而 `_on_check_identity` 原逻辑只查：

```python
l3_nodes = self.node_pool.query(space_path_prefix="/身份/自我")
```

`PulseNodePool._get_path_prefix_ids`（L2151）按 `startswith` 过滤，
`/身份/使命/核心` 与 `/身份/自我` 在第 4 字符即分叉（**自我 ≠ 使命**），
因此 **使命种子节点从不进入候选集** → 校验恒判「未找到」→ 每次心跳恒报
`missing_seeds=['使命']`（运行日志 19:36 / 19:57 / 20:14 三次复发）。

> 注：其余 4 条种子（`/身份/家庭/小林`、`/身份/家庭/路灯` 等）在运行期可被
> `/身份/自我` 子树内的既有节点关键词覆盖到，故**只有「使命」暴露为 degraded**。

### 5.2 修复

- 查询范围放宽到**整棵 `/身份` 子树**（覆盖 `/身份/自我`、`/身份/家庭`、`/身份/使命`），
  由灰度开关 `IDENTITY_SEED_CHECK_PREFIX`（默认 `"/身份"`）控制；
  改为 `"/身份/自我"` 即退回旧严格域（应急回滚）。
- 关键字匹配追加 `node.value` 语义包含兜底（**keywords 命中 OR value 语义包含**）。
- `checked_prefix` 改为回填真实查询范围（诊断字段不再硬编码 `/身份/自我`）。

### 5.3 验收证据（离线）

新增 `tests/test_identity_seed_mission_m160.py`（6 用例全绿）：
