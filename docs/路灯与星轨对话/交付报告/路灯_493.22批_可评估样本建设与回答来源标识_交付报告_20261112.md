## 五刀落地

### 刀1 可评估样本建设（P0）
- `tools` 一次性生成器产出 **20 类问法 × 10 条 = 200 条**合成样本，覆盖烛微清单全 20 类（器官位置/别名/状态/队列/数量/模块关系/效果/位置/事件订阅/代码指称/断网本地/因果哲学/多轮紧邻/多轮隔轮/跨用户/过期记忆/低置信歧义/未知/模块名污染/反问长文本）。
- 每条字段：`query / category / expected_organ / expected_action / expect_answer_contains`，落 `data/monitor/eval_samples_49322.jsonl`（独立文件，不污染影子日志）。
- **50 条金标**（覆盖全部 20 类，每类 2~3 条）：用**确定性可复算判据**标注 `labeled_correct`——实跑 `self_query_fastpath_explain` 取实际答复，按期望串包含 / 应跳过降级 / 期望器官一致性判定，并写回 `actual_answer`。
- 误答率 = 1 − 金标正确率，实测 **27/50 正确、误答率 46.0%**（可复算，非主观编造）。

### 刀2 两套账恢复可对账（P0）——方案B
任务书推荐方案B「明确单向」；与 493.21 方案A 内核（**不做强制双向对齐、reconcile 只读**）兼容：
- `reconcile()` 保持纯只读（493.21 已改），本批未改其语义；CLI 仍只读报告。
- 数据层用**生产 API `hub.record()` 一次性生成 3 个真实 vl id**，写回 absorb_trace 的 `verification_learning_id`，并标 `link_policy="one_way"`；**vl 侧 `absorb_trace_id` 留 None、不强求回指、不做双向对账**。
- 文档明确：「两套账单向关联，不做双向对账」。
- 实测：跑 10 次 `record()` 后 absorb_trace 一字不变（单向引用不被冲掉）。

### 刀3 A/B 字段真值（P0）
`shadow_rules.record_shadow_compare` 新增可选 `answer_a / answer_b / winner`（默认 None，向后兼容），按 `(query, rule_id)` 去重写 3 条真实规则记录。

**诚实口径（子代理实证硬结论）**：`would_answer` 与 `explain["answer"]` **同源**，主笔开关 False 使实际回答走大模型且**未落进任何文件**，因此当前**没有真实双答案可比**：
- `answer_b` = 真实影子候选文本（本地 fastpath 候选；实测「晚上好」有值，「数字化生命」「科技新闻」本地未命中 → 如实 None）；
- `answer_a` = 主笔实际回答文本，取不到 → 如实 None（不编造）；
- `winner` = **恒 None**（任务书「没有真实对比不要写假 winner」）；
- 额外 `local_candidate_hit` 布尔字段给出**真实可判定的真值**（3 条都有），`ab_truth_note` 说明缺口与前置条件。
- 要产生真对比，需主笔 emit 链路按同一 cid/session 落盘实际回答文本（后续批次）。

### 刀4 回答来源标识（P1）
- 新增 `nucleus/self_index/answer_source.py`：`infer_answer_source(source, local_hit)` 按**真实 `source` 串**映射三态（`self_only` / `self_enhanced` / `llm_only`），判定不了返回 None（不猜）；`CONSOLE_PREFIX` 三态→前缀；`record_answer_source_event()` 落真实来源事件；`stats_by_day()` / `stats_by_session()` / `overall_stats()` 出占比。
- **影子 writer 层不编造三态**：子代理实证 writer 只有本地候选信号、没有主笔/LLM 信号 → `answer_source` 字段加入影子行但**默认 None**，只由主笔链路按真实来源传入。
- `chat_service.py` 控制台打印点按真实 `source` 加 `[曈曈自答]` / `[本地+大模型]` / `[大模型直答]` 前缀（无真实信号不加假前缀），并落来源事件。
- `health_ui.py` 加 `/answer_source/stats` 端点 + 监控总览**纯 CSS 饼图卡片**（自答/混合/大模型占比，按天/会话统计，无外部库）。
- 实测来源事件 4 条：占比 自答 25% / 混合 25% / 大模型 50%，按天 1 天、按会话 3 个。

### 刀5 内存止血观察（P1，只定位不修）
- 新增常驻 `tools/rss_hourly_probe_49322.py`：每小时采样 RSS（psutil / `/proc` 兜底）+ 附带 health 快照真实读数，`--report` 出趋势；**样本不足 24 条时明确打印"24 小时连续样本尚未累积，不出 24h 结论"**，不伪造。
- 独立定位报告：`docs/路灯与星轨对话/分析报告/路灯_493.22批_内存增长源定位报告_20261112.md`。
- 定位结论（按证据强度）：① 阶跃式组件加载为主因（`memory_alarm_trace` 331 行高频 "阶跃 +1GB（加载组件，非泄漏）"）；② `dict` 214 万 / 457.5MB 是最大对象类型（top_types 最新一份），大头在字符串/原生分配需 tracemalloc 细分；③ 影子/账本/记忆均 KB 级，**不是** GB 级增长源；④ 当下 `is_leak_signal=false`、稳态 13.3MB/min，属阶跃后平台期。
- 修复建议（放后续综合优化 P0 批次）：按标签定位 dict owner、阶跃削峰、常驻容器设上限、24h 采样接线。本批**未改任何内存相关生产逻辑**。
