## 二、契约三问 · 星轨裁决口径

### 1. 契约① 排除清单是否还有该排除的字段 → **有，收紧为白名单制**

**裁决**：生成器上下文**只取** §一节六类最小集（`file/method/line`、`issue_type`、`severity`、`desc`、`m323_truth.method_before`、`dedup_key`）；**其余池字段一律不进 prompt**，不逐一枚举排除项。

- 路灯契约点名排除的八类（`history`/`verify_feedback`/`acked_*`/`route`/`dispatch`/`_snap`/`original_code`/`modified_code`）维持排除；
- 一并按白名单自动排除：`attribution`、`klass`、`criteria_version`、`code_version`、`first_seen_ts`、`last_seen_ts`、`proc_gen_first`、`status`、`closed_reason`、`gate`、`severity_raw`、`file_raw`、`status_history`、`calibration`、`klass_bucket`、`requires`、`state`、`consumed_at`、`approval_entry` 等审计留痕/状态机/版本时间/分流字段；
- 理由：黑名单随池字段膨胀会漏排；白名单取字段是结构保障，与任务书"最小集"口径同向收紧，不扩大生成器行为面；
- 缺字段处理沿用契约①：`file/method/line`、`issue_type`、`desc` 缺 ⇒ 拒收重生成；`severity` 缺 ⇒ 记 None 不猜；`m323_truth.method_before` 缺 ⇒ 走 `precheck_target_v2` 其它锚、仍缺则拒；`dedup_key` 缺 ⇒ `make_dedup_key` 兜底（B 级既定）。

### 2. 契约② 生成器只读 jsonl、不回写水位、文件只增、去重靠 id → **批准，补一条跨拍去重边界**

**裁决**：接受"文件只增、生成器只读不写、不引入 `.consumed` 标记文件"。补充边界条款，落码时写入契约备注：

- **单次运行内**：读取方内存集合按 `candidate.id`（＝池 `dedup_key`）去重；
- **跨拍/重启后**：已入审批流条目的跳过，对照 `pending_patches.json` 既有 `patch_id`/`dedup_key` 反查；这是**消费去重**，不是键继承，**不违反**契约③"不从 verdict 反推键"——两件事在契约里写明边界：键必须入池时就有（契约③），已消费识别允许查 pending 台账（本条款）；
- 消费方不写 `patch_candidates.jsonl`、不改行、不删行；consumer 不读该文件；
- 节拍两口径（300 ticks 消费拍／3600s 派单窗口）不动、不合并；`candidate_only` 校准门槛 `_m351_calibration_gate` 不放宽。

### 3. 契约④ `ENABLE_ORGAN_INVENTORY_EXPORT` 挂既有指标采集 tick → **批准，不新增定时器**

**裁决**：采用"挂既有指标采集 tick、不新增定时器/线程"方案；命令面按需导出作为替代方案**不采用**（影子期需留读数供重启观测）。施工约束：

- 落码前在契约备注中**指认挂载的既有 tick 名称**（T0 定位到具体函数/采集点），禁止新起定时器、线程或独立节拍；
- 开关 False 时消费方直接返回，零行为变化；
- 导出内容范围**不新增器官面**（任务书 §3.2 ③ 既定），只接既有器官清单数据；
- 其余三键影子路径约束见 §四。
