## 4. 各任务交付

### T-107a（P0）D171 无人值守能力

**根因**：框架缺乏进程级资源观测能力——RSS 锯齿、句柄/线程无监控、无阈值告警；且生产代码存在 npz/npy 句柄泄漏（`np.load` 返回 NpzFile/NpyFile 持有文件句柄，不 `close` 则进程生命周期内持续占用，重载时累积）。

**改法（被动、节流、零副作用、不依赖 config 运行开关——守红线）**：
1. `organs/body/PulseLiver.py`：新增资源看门狗。
   - 模块常量阈值：`_RESOURCE_SAMPLE_INTERVAL_SEC=300`、`_RESOURCE_RSS_WARN_BYTES=6GB`、`_RESOURCE_RSS_GROWTH_BYTES=2GB`、`_RESOURCE_HANDLES_WARN=5000`、`_RESOURCE_OPEN_FILES_WARN=2000`。
   - 心跳驱动钩子：`_check_and_optimize` 入口调 `self._maybe_sample_resource()`（内部 5min 节流）。
   - `_sample_resource_usage()`：用 `psutil` 采样本进程 RSS / `num_handles()`（Windows）/ `open_files()`（*nix）/ `num_threads()`；维护滚动基线（约 8h 窗口）；超阈值打 WARNING；采样异常被 `try/except` 吞掉（DEBUG，绝不干预主流程）。
   - `_resource_stats()`：暴露最新快照，`get_stats()` 已挂 `"resource"` 键 → 5051 面板可直接读取。
2. `nucleus/semantic/VectorStore.py:284`：npz 句柄泄漏修复——`with np.load(...) as data:` + `.copy()`。
3. `nucleus/vector_store/faiss_store.py:364`：npy 句柄泄漏修复——`with np.load(...) as _arr:` + `.copy()`。

**验收（代码层）**：
- py_compile 通过、ruff F=0。
- 句柄泄漏修复机制已红→绿验证（见 §6）。
- RSS/句柄监控为被动采样，正常无告警、零副作用；阈值告警路径在资源越界时触发。

**验收（运行时，遗留）**：连续 8h RSS 增长 < 500MB、句柄数稳定——需框架重启后连续运行观测（本轮框架未运行，见 §8）。

### T-107b（P1）D172 死订阅清理

**根因**：订阅关系由“各器官 `get_resonance_conditions()` 返回的事件清单”×“全项目 `emit()` 发射事件”两处分散维护，缺乏统一审计，存在订阅了但无人发射的死订阅、发射了但无器官接收的孤儿脉冲。

**改法**：
- 新增 `tools/ci/audit_subscriptions.py`（AST 静态审计，零运行时副作用）：反射 `nucleus.const` 事件类 → 解析全项目 `emit()` 与 `get_resonance_conditions()` → 交叉比对输出**订阅健康报告**（死订阅 / 孤儿发射 / 零发射器官）。
- 运行结果（`tmp/subscription_audit.txt` / `.json`）：
  - 发射事件种类：**43**；订阅条目：**278**；零发射器官：**4**（`qica/endocrine/genetic/immune`）。
  - 死订阅初筛 **176**（占 63%）——**重要说明**：该数字被**动态发射**严重放大（大量 `emit(event_type=变量)` 无法被静态分析看见），属噪声高估，**不可直接据此批量删除**。

**关于“清理无用订阅 减少50%+”的安全决策**：
- 静态度量无法区分“真的死订阅”与“经变量动态发射的订阅”。若机械删除 176 条订阅（跨 80+ 器官文件），会破坏运行期共振、且框架本次未运行无法即时回放验证，**违反“不停框架 + 不破坏运行路径”红线**。
- 故本批交付**审计工具 + 健康报告**作为可复用资产，并明确：**批量清理须待框架重启、用运行期事件 Trace 确认后的“已验证死订阅清单”执行**（建议由星轨终验时按本报告给出的工具复核）。这是“安全优先”的纪律选择，非遗漏。
- 零发射器官 4 个已列出，其中 `immune/genetic/endocrine` 多为被动响应器官、订阅他人事件而自身不发射，属设计特征；`qica` 为调用入口，结论待终验确认保留/精简。
