### 刀4 dry-run 候选落盘修复（P1）
**差距根因（明确）**：`shadow_raw_candidates=35` 是 `metrics_dryrun()` 每次**现扫影子日志**得到的候选行数（含重复 query、含 veto 标记、与磁盘文件无关）；`file_rows=1` 是 `alias_candidates_dryrun.jsonl` 的真实落盘行数。两者差这么多的主因是**根本没触发落盘**：
- 自动落盘唯一入口 `_maybe_trigger_dryrun()` 需 `_DRYRUN_COUNTER >= 100`，但该计数器是**进程内模块变量、重启归零**，而影子日志长期仅 54 行 ⇒ `extract_and_append_dryrun()` 从未被自动调用；现存那 1 行来自测试/历史手工写入（confidence 0.95 与影子日志的 0.9 不同）。
- 次因：落盘按 `query|organ|label` 去重（`learned_alias.py:597/649`），35 条候选仅 `distinct_queries=3`（胃在哪 / 胃在身体的哪个位置 / 肺在哪）⇒ 即使全量回填，真实上限也只有 **3 行**，不可能 1→35。
- 排除：关系问法过滤（影子 query 无一命中）、veto（`veto_blocked=0`）、统计口径错、`append` 只写一次。

**修复**（不改 promote/线上回答）：`_maybe_trigger_dryrun()` 新增进程启动后**首次写影子补一次全量回填**（`_DRYRUN_BACKFILL_DONE` 幂等标志），复用原 `extract_and_append_dryrun()` 逻辑；100 条门槛保持不变。实测 `file_rows 1 → 3`（回填 2 行，正是 3 个 distinct_queries 减去已有的"胃在哪"），`online_answer_delta=0`、未写 overlay。`test_m49312_dryrun.py` 的 100 门槛测试同步隔离首次回填（保留原语义）+ fixture 复位新标志。
