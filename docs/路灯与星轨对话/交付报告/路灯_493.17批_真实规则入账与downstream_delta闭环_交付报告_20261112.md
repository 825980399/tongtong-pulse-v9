## 偏差与说明（诚实口径）

1. **真实规则来源**：任务书举例 `growth_distill / ab_test / runtime_patch`。子代理全仓核实：生产规则由 `verification_learning_hub.distill_rules` 在内存现场生成、不含 `rule_id`/`source`；`ab_test`/`runtime_patch` 在规则代码中根本不存在（仅 config 文档串/任务书提到）；`source=growth_distill` 是 QICA 写证据账时的硬编码兜底值；`lesson_strategies.json` 是「批次计数盘账」不是可回放规则库。按「不编造数据」原则，本批 3 条真实规则取自**真实运行数据** `data/semantic_lessons.json`（本地/LLM 意图不一致的真实学习记录，含真实 content + llm.paths），`rule_id` 用其真实 md5 可回溯；未伪造 A-B / runtime 补丁规则。
2. **刀3 闭环选的是 QICA `classify` 知识路径，不是"胃在哪"的 fastpath 回答**：核实「规则吸收 → '胃在哪' 回答变化」这条链**不存在**——别名表是 `exporters.ORGAN_ALIAS_TABLE` 硬编码静态表，`learned_alias_overlay` 开关关且文件不存在，`QICA.absorb_growth_rules` 不写别名表、fastpath 也不读 `_domain_knowledge`，主笔开关还关着。QICA 唯一真实消费点是 `_resolve_knowledge_paths` → `classify_internal/on_pulse` 的 `knowledge_paths`（`QICA.py:1504`）。故用这条**真实可观测**的路径变化做闭环（任务书刀3 验收允许「路径」），不假造回答变化。
3. **磁盘条数漂移**：`verification_learning.json` 被活体进程持续改写（115→46→14），本批以施工当下实测 14 条为准，全部回填；并靠 `_save()` 兜底 + 重启加载新代码自愈。任务书「46 条」是更早快照。
4. **测试污染治理**：`test_m49316 / test_m49314 / test_m360_legacy_misc` 的 absorb 用例原先直接写生产 `absorb_trace.jsonl`，会把测试种子混进真实规则账。本批统一改为 tmp 隔离（`_m49317_absorb_trace_path` 注入 / tempfile），回归不再污染生产数据。
