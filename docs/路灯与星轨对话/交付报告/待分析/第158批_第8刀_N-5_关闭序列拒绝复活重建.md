## 一、现象与根因

- **现象（N-5）**：框架停机时，`main.py` 以**并行 ThreadPoolExecutor（`_TPE`）**关闭各单例（`shutdown_reasoning_pool` 与 `shutdown_vector_store` 同批并发执行）。关闭窗口内，其它线程一次迟到的 `get_reasoning_pool()` / `VectorStore.get_instance()` 若撞在「全局实例已被复位」这一瞬间，就会**新建一个全新实例**——进程池会 spawn 出全新 worker 子进程、向量库会重建实例并可能重新加载索引，形成**停机复活竞态**（关了又活，子进程泄漏 / 退出挂起）。
- **根因**：两个单例的工厂函数此前**只有「实例是否已存在」这一个判据**，缺少「当前是否正处于关闭序列」这一状态。
  - `ReasoningWorkerPool.shutdown_reasoning_pool()` 会显式 `_reasoning_pool = None`（其 docstring 明确为「使重启时重建全新进程池」），关闭窗口内 `get_reasoning_pool()` 见到 None 即新建 → **spawn 新 worker**。
  - `VectorStore` 原本**无**任何 `_closed` 标记，`shutdown()` 仅做 flush，全局实例常驻；一旦引入「复位实例」语义即会复活。
- **目标（路灯触发指令第 8 刀）**：worker-pool / VectorStore 加「已关闭拒绝重建」闸门。

## 二、修复内容（对称双闸门）

### 1. `nucleus/reasoning/ReasoningWorkerPool.py`

- 新增模块级闸门 `_reasoning_pool_closing`。
- `shutdown_reasoning_pool()`：**先在锁内置位** → 再执行 `_inst.shutdown()`（在锁外，不阻塞持锁）→ 收尾在锁内复位全局 `_reasoning_pool = None` 并解除闸门。
- `get_reasoning_pool()`：双检锁内，若 `_reasoning_pool is None` 且闸门置位 → **拒绝新建，返回 None**；若已有实例（含关闭窗口内正在 shutdown 的那个）→ **照常返回该实例**，其自身 `_closed` 标记拒绝内部重建（`_rebuild_pool` / `_try_minimal_rebuild` / `_maybe_recover_from_degraded` 三处既有检查）。

### 2. `nucleus/semantic/VectorStore.py`

- 新增类级闸门 `_closing` + 实例级标记 `_closed`。
- `get_instance()`：无实例且闸门置位 → 拒绝新建（返回 None）；否则行为不变。
- `_ensure_loaded()`：遇 `self._closed` 直接返回 `self._loaded`，**不再触发懒加载重建**（这是 VectorStore 侧的「拒绝重建」落点）。
- `shutdown()`：`finally` 中置 `_closed = True`。
- `shutdown_vector_store()`：置位闸门 → flush → 解除闸门。

### 3. 重要设计取舍：避免「反向制造复活」

> 这是本刀最关键的一处判断，也是首版实现中被自查发现并修正的缺陷。

- 首版实现在 `shutdown_vector_store()` 的 `finally` 中加了 `VectorStore._instance = None`，**这是错的**：修复前本函数只做 flush、**保留全局实例**，shutdown 后 `get_instance()` 返回的仍是同一个已关闭实例（不会重建）。改为置 None 之后，shutdown 完成后的下一次 `get_instance()` 反而会**新建出一个全新实例**——与「拒绝复活重建」的目标**背道而驰**，等于亲手制造了一条新的复活路径。
- 因此 `shutdown_vector_store()` **不复位 `_instance`**，保持修复前语义，由实例内 `_closed` 标记承担「拒绝重建」职责。
- `ReasoningWorkerPool` 则**保留**原有的 `_reasoning_pool = None`——其 docstring 明确说明这是为「重启时重建全新进程池」服务，属既有**重启**语义（worker 进程非 daemon，重启必须换新），不做改动；闸门只把「新建」这一动作**收紧到关闭窗口之外**。

### 4. 返回值契约变更（已核查全部调用点）

关闭窗口内且实例已复位时，两个工厂函数可能返回 `None`。已逐一核查：
