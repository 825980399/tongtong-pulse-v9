## 一、现象（立票原疑）

- 日志特征：`库内=test/bge-small-zh`、`维度不符 库内=8`（生产应为 `BAAI/bge-small-zh-v1.5` / 512）。
- 连带现象：语义内核"降级关键词通道"10+6+3 次。
- 疑点：向量库元数据被测试模型（8 维）污染，导致语义内核降级。

## 二、核对过程与证据

### 1) 出厂黄金值（nucleus/semantic/VectorStore.py）
- `:52` `_GOLDEN_MODEL = "BAAI/bge-small-zh-v1.5"`、`:53` `_GOLDEN_DIM = 512`（与 config.py:770-771 `model_name/expected_dim` 一致）。
- `:84-85` 生产实例 `self._dim/self._model` 默认取自 config 黄金值。✅

### 2) 生产库防护链（已存在，未污染的前提）
- **启动自检** `self_check_at_startup()`（:219-247）：生产库 meta 的 model/dim ≠ 黄金 → 记 `★自检告警：疑似此前被测试污染` + 备份清空，从空库启动（语义内核不受影响）。仅生产路径执行（:226 `if not self._is_production_path(): return True`）。
- **加载拒绝** `_load()`（:260-285）：模型指纹不符 / 文本预处理不符 / 维度不符 → 一律 `拒绝加载旧向量` 并备份，绝不把污染数据载入生产语义空间。
- **落盘守护**（:445-452）：flush 时若 `model/dim` 与黄金不符，`f"dim={self._dim}) 与出厂黄金值不符，避免把 test/bge-small-zh / dim=8 写进 data/knowledge/vectors.npz`——**显式阻止测试元数据写入生产库**。
- **污染备份门控** `_maybe_backup_on_mismatch()`（:211）：`if not self._is_production_path(): return`——仅生产路径备份，测试实例保留原文件供断言。

### 3) "语义内核降级关键词通道"来源（`nucleus/semantic/`）
- 这是**设计内零风险降级**（`VectorEncoder.py:102` 注释「单例、懒加载、零风险降级」）：编码器/模型不可用时回落关键词通道，框架照常运行。
- 触发点：`VectorEncoder.py:223/264`、`SemanticKernelService.py:75/115/121`、`AsyncEncodeQueue.py:144/155/203/211`。
- 测试态（8 维测试模型、编码器未加载）必然触发降级；生产态（黄金模型就绪）走语义通道——与污染无关，是预期的测试侧现象。

## 三、结论

- **生产向量库已被多层防护**（黄金常量 + 启动自检 + 加载拒绝 + 落盘守护 + 污染备份门控），`test/bge-small-zh` / dim=8 **不可能**写入或载入生产 `data/knowledge/vectors.npz`。
- 日志中的 `库内=test/bge-small-zh / 维度不符 库内=8` 是**测试实例**元数据，被加载拒绝链（`拒绝加载`）正确拦截；"降级关键词通道"是测试态编码器缺位的设计内降级——二者皆属 X-3 施工噪声，**非生产缺陷**。
- 与第 2 刀 T-落盘路径泄漏-1 **同源**：均来自测试故障注入 / 测试模型 / 测试隔离目录，生产代码与配置无缺陷。
- **无需对 VectorStore / config / 语义内核做任何修正**（防护链已正确，多改反损测试断言与降级安全网）。
- 建议（交 X-3 / 落盘健康读数层）：将 `库内=test/bge-small-zh` / `维度不符 库内=8` / `降级关键词通道（测试编码器未加载）` 作为施工噪声特征剔除，不计入生产健康读数。
