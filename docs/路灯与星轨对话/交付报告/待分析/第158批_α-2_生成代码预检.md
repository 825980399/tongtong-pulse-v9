## 二、增强内容

### 面 A：沙箱语法预检闸门（SafeEvolutionExecutor.py）

- 新增模块级函数 `_sandbox_syntax_precheck(code) -> (通过, 错误文案)`，语义为「与主流程验证解耦的隔离语法判据」：
  - 纯 `ast.parse`，**不执行代码、不污染主进程状态**；
  - 判据复用 `_assess_patch_quality` 的「四次尝试」口径（完整 / 包装类 / 包装函数 / dedent），对**方法体片段（base>0）也能正确判定**；
  - 返回 `(通过, 错误文案)`，失败文案含 `msg (line N)` 便于定位。
- 在 `_generate_patch` 的「替换有效性校验（`modified_code == original_code` 去重）」之后、生成变更摘要之前插入闸门：
  ```python
  _syn_ok, _syn_err = _sandbox_syntax_precheck(modified_code)
  if not _syn_ok:
      _module_logger.warning(
          f"[沙箱语法预检] 拒绝语法错误补丁: {plan_type} {method_name}: {_syn_err}")
      return None
  ```
- 行为保证：语法错误补丁在质量评估与 LLM 重试前即被拦截；语法正确补丁零行为变化（仅新增一道前置判定）。

### 面 B：自生成代码失败率维度（FailureTracker.py）

- 新增常量 `_FAILURE_RATE_ALERT_THRESHOLD = 0.67`，与 `SafeEvolutionExecutor._dynamic_llm_min_trust` 的 `rule_bad` 判定（规则失败率 >= 67%）**口径一致**，避免双标准。
- `__init__` 增 `self._failure_rate_threshold`，承接该常量。
- `record_failure` 在既有「连续失败 >= 3 次升级」逻辑之外，**叠加**失败率告警（不替换）：
  - 条件：`failures >= 2` 且 失败率 `>= 0.67` → WARNING `[失败率告警] 自生成代码失败率 N%（f/t）达阈值 67%...`；
  - 计数器异常时 try/except 仅 `debug`，不影响主流程。
- 新增查询接口：
  - `get_failure_rate(signature)`：单签名失败率 = 失败 / (失败+成功)；
  - `get_global_failure_rate()`：全局 = 总失败 / 总尝试；
  - `get_stats()` 增 `"global_failure_rate"` 字段，供仪表盘/日志消费。
