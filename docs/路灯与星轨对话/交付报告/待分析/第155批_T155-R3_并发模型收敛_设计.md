### 2.3 关键事实

- `ParallelScheduler` 是**事实主导基准**（调用面最广，覆盖器官/推理/探查/外部执行/信息场）。
- `Hybrid` 提供 `Parallel` 缺失的**进程池（CPU 密集型真并行）**；`Structured` 提供 `Parallel` 缺失的**任务组扇出/依赖协调**，且内部复用 Hybrid 进程池。
- 二者**非死代码**：`self_inspector` 真实依赖 Structured 的 `SubTask` 扇出；`main.py` 启动/停机显式管理 Hybrid/Structured 的进程池与任务组生命周期。

## 3. 核心矛盾（为何不能简单"删掉 hybrid/structured"）

任务书字面意图是"parallel 唯一基准、hybrid/structured @deprecated"。但：

1. **能力缺口**：`ParallelScheduler` 仅线程池。若直接删 hybrid/structured，则 `self_inspector` 的多文件并行解析、main.py 启动时的进程池预初始化、以及任何 CPU 密集型真并行路径将**失去进程池后端**——回归到"假并行"（GIL 下 CPU 密集任务无法真并行）。
2. **生命周期耦合**：main.py 在 `:2777-2801` 显式 `shutdown(wait=True)` Hybrid/Structured 的进程池与任务组，避免进程泄漏/僵尸。删之须先接管这些资源的回收。

→ 因此"收敛"的正确含义是 **API 层收敛（统一门面）**，而非 **实现层删除**。

---

## 4. 设计决策（提案）

**D1 — 唯一基准 = `ParallelScheduler` 门面。** 所有**新增**并发代码一律走 `get_parallel_scheduler()`；禁止新代码直接 `import Hybrid/Structured`。

**D2 — `Hybrid` / `Structured` 标 `@deprecated`，但保留实现不做删除。**
- 在模块 docstring 顶部与 `get_hybrid_scheduler` / `get_structured_parallel_scheduler` 上加 `# @deprecated: P2-64 并发收敛，新代码请用 nucleus.parallel_scheduler.get_parallel_scheduler()` 注释，并在文档中登记淘汰窗口。
- 不立即删：避免一次性大规模回归；给 `self_inspector` 与 main.py 停机路径留迁移缓冲。

**D3 — 进程池/任务组能力下沉（后续阶段，待裁决）。** 二选一，本提案**不执行**：
- **D3-A（推荐，低风险）**：将 Hybrid 的 `ProcessPoolExecutor` 与 Structured 的 `SubTask` 扇出**作为可选后端接入 `ParallelScheduler`**（新增 `submit_cpu_bound` / `run_group` 方法，内部复用现有进程池逻辑），使 parallel 成为**真正**的完整门面；待 parallel 接管全部能力后，Hybrid/Structured 退化为空壳→再删。
- **D3-B（激进）**：保留 Hybrid/Structured 为进程池/任务组"专用提供方"，仅标记弃用、长期共存；新代码仍统一经 parallel 门面，但 parallel 对 CPU 密集任务内部委托给 Hybrid。

# Concurrency Contract · 并发模型合约（P2-64）

## 1. 唯一基准
-  sanctioned scheduler = `nucleus.parallel_scheduler.ParallelScheduler`（门面 `get_parallel_scheduler()`）。
- 所有新增并发需求：线程池任务 → `submit_parallel`；读并行度 → `get_parallelism()`；
  停机 → `shutdown_parallel_scheduler()`。

## 2. 弃用项（@deprecated，不删除）
- `nucleus.HybridParallelScheduler`（进程池/线程池自动选池）—— 仅遗留调用点使用。
- `nucleus.StructuredParallelScheduler`（任务组扇出/依赖协调）—— 仅 self_inspector 与 main 停机路径使用。
- 禁止新增 import；新增代码违反 → ruff 规则 / pre-commit 拦截（待加 `T155-R3-deprecated-import` 守卫）。

## 3. 语义约束
- parallel 默认线程池；CPU 密集型真并行须显式走进程池后端（D3-A 落地前，现存量 CPU 密集任务继续走 Hybrid，不得"为收敛而降级为线程"）。
- 硬熔断：parallel 线程 ≤64；hybrid 进程 2–16（保留，不得移除）。
- 停机顺序：先 Structured（任务组）→ 再 Hybrid（进程池）→ 最后 parallel（线程池），避免任务悬空。
