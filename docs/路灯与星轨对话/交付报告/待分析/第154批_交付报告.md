## 四、T154-10-b 详情（环境依赖预失败清理）

### 4.1 现象
全量 `pytest --collect-only` 报告 **3 个 collection ERROR**，导致整个收集被 `Interrupted: 3 errors` 中断（4454 测试无法运行）：
```
ModuleNotFoundError: No module named 'tmp.test_isolation'
ModuleNotFoundError: No module named 'tmp.test_isolation'
ModuleNotFoundError: No module named 'tmp.test_log_isolation'
```

### 4.2 根因（已核实）
- 缺失模块：`tmp/test_isolation.py`、`tmp/test_log_isolation.py`。
- `git log --all` 从未跟踪二者；`git check-ignore` 确认其被 `.gitignore` 忽略；`.bak_batch154/tmp/` 亦无副本 ⇒ **从未入库、工作树已丢失、无备份可恢复**。
- 波及面：`tests/test_test_dir_cleanup_m18.py`、`tests/test_self_awareness_m19.py`、`tests/test_log_stability_m22.py`（3 测试，模块级 import 致收集失败）+ `tests/conftest.py`（L89/95 函数级 import）+ `tools/verify_phase17_1_5.py`（L21 import）。
- 属 **M18/M19/M22 批次的 git-ignored 易失辅助模块**，非 154 批引入。

### 4.3 处置（能修则修）
对 3 个测试文件加 `pytest.skip(..., allow_module_level=True)` 守卫，将硬 `ImportError` 降级为**干净 skip**：
- 模块恢复后守卫自动失效、测试自动回归；
- 改动仅 3 文件、纯守卫、可逆、零逻辑改动；
- `conftest.py` 与 `tools/verify_phase17_1_5.py` 的函数级 import 不在 pytest 收集路径上触发（仅当对应 fixture/工具被调用时），未做侵入式修改（属其他批次文件，超出本批范围）。

### 4.4 验证
- `pytest --collect-only`：**4454 tests collected，0 error**（原 3 error）。
- 3 文件单独运行：**3 skipped**（clean，非 error）。
- `ruff check --select F` 三文件：**All checks passed!**

### 4.5 不能修的部分（列清单+原因）
- **无法重建两辅助模块**：`tmp/test_isolation.py`/`tmp/test_log_isolation.py` 源码从未入库且无备份；且 `test_test_dir_cleanup_m18.py` 直接**读取其源码并断言特定子串**（`_VS.VectorStore._instance = None`、`_TMP = ISO_DIR` 等），凭空重建无法可靠满足，重建即引入猜测性逻辑。
