## 五、刀4：`dedup_key_v2` 三态 + 一条铁律

v2 与 v1 的**唯一**差别是 method 来源：v1 取 `patch["method"]` 字段（历史里可能是推断名），
v2 取 `_m323_ast_def_name(modified_code)` 解析的**真实 def 名**。公式完全不变
（复用 `patch_generator.make_dedup_key`）。

```
same     真实名 == method 字段 ⇒ v2 与 v1 同值（仍写，便于下游统一取 v2）
differs  两者不同 ⇒ 写 v2 并打 INFO 留痕（这正是 v2 要暴露的）
skipped  解析不出 def 名 ⇒ **不写 v2**
```

**铁律：`skipped` 时绝不许写占位 v2** —— 假键会让去重按错的组归并，比没键更糟（有专测）。

**双写不迁移**的理由：存量 `method` 是否真实无法自动判定，就地改写会让 v1 与池侧
`dedup_key` 对不上、两侧对账断掉 ⇒ 迁移并入下一个停机窗。
