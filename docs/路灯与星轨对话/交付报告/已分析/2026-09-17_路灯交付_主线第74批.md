## 二、各任务交付明细

### T1 双腿模块 dict.append bug 修复（P0）

**根因（铁律T0 实测定位）**：
真实文件为 `organs/motor/PulseLegs.py` 的 `_write_learn_log`（约 L1359-1372），非任务书暗示的 `nucleus/legs`。
- 原代码 `safe_read_json(log_path, default={})`：`safe_read_json` 仅当内容**解析失败**才返回 default；当 `legs_learn_log.json` 内容为合法 JSON `dict` 时，返回该 dict。
- 随后 `log_data.append(entry)` 抛 `AttributeError: 'dict' object has no attribute 'append'`。
- 该异常被外层 `try/except` **静默吞掉**，仅打印 `[双腿] 数据处理异常已忽略`，导致双腿学习日志长期丢失（170.3 运行日志显示出现 7 次以上）。

**修复方案**：
```python
log_data = []
if os.path.exists(log_path):
    try:
        # ★主线第74批 T1：默认 [] 而非 {}——内容 dict 时 safe_read_json 返回 dict，
        #   .append 抛 AttributeError 被静默吞，导致双腿学习日志丢失
        log_data = safe_read_json(log_path, default=[])
    except (ValueError, OSError) as e:
        self._log(LogLevel.INFO, f"[WARNING] PulseLegs 双腿学习日志读取失败: {type(e).__name__}: {e}")
        log_data = []
    # ★主线第74批 T1：防御性类型守卫——非 list 时记 WARNING 而非抛异常
    if not isinstance(log_data, list):
        if isinstance(log_data, dict):
            self._log(LogLevel.DEBUG, f"[第74批T1] 双腿学习日志为dict格式，已转为list保留: {log_path}")
            log_data = list(log_data.values())
        else:
            self._log(LogLevel.WARNING, f"[第74批T1] 双腿学习日志格式异常(非list/dict)，重置为空: {type(log_data).__name__}")
            log_data = []
log_data.append(entry)
```
- 同时移除硬编码行号 `PulseLegs.py:1157`（铁律禁止硬编码行号）。

**影响**：正常 list 日志路径零变化；异常格式仅记 WARNING 不崩，历史 dict 格式日志保值转为 list。

### T4 Windows 文件占用降级（P1）

**现状（铁律T0 实测，前批已部分实现）**：
- `nucleus/logger.py` `SafeRotatingFileHandler.doRollover`：第49/59批已有 rename 重试 + 复制截断兜底。
- `nucleus/mnemosyne/PulseNodePool.py` `compact_cold_storage`：第63批已有 Windows 文件锁重试（10次/2s）+ 强制删除兜底 + 30分钟冷却。
- 缺口：重试为**固定间隔**，被占用时日志仍刷 `WinError 32`，重试风暴无退避。

**修复**：固定间隔 → **指数退避**（保留重试次数/强制删除兜底/冷却）：
- 日志轮转：`min(_wait * (2 ** _attempt), 2.0)` 秒（0.2/0.4/0.8… 上限 2s）。
- 冷存 compaction 删除：`min(_retry_int * (2 ** (_attempt-1)), 16.0)` 秒。
- 冷存 compaction 重命名：`min(1.0 * (2 ** (_attempt-1)), 8.0)` 秒。

**影响**：正常轮转/compaction 路径零变化；被占用时降低重试频率、减少日志噪声，不崩溃。
