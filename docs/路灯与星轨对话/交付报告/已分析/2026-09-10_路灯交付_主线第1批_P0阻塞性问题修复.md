## 三、各任务修改内容摘要

### 3.1 任务1：P0-7 自主进化修复率 0%（✅ 完成）

**根因（已确认）**：`LogAnalyzer._scan_log_file` 的 ERROR/CRITICAL 分支调用
```python
_issue = self._get_or_create(issues, _key, "", 0, "", _level)   # file/line/method 全空
```
而 Traceback 分支有精确定位。普通 ERROR 行占绝大多数 → SafeEvolutionExecutor 拿不到代码位置 → 无法生成补丁 → 修复率 ~0%。

**修复**：

1. `self_inspector` 新增 3 个方法：
   - `_build_organ_name_index()` —— 扫描文件头部 `ClassName —— 中文器官名`，
     构建「中文器官名 → 文件路径」索引（**220 条**）。
     ★零硬编码，直接复用头部完善四批次的成果，新增器官自动纳入。
   - `guess_method_from_message(organ, msg)` —— 5 种模式提取方法名
     （Traceback 风格 / `in xxx` / `方法 xxx` / `def xxx` / `xxx()`）
   - `locate_issue(organ, msg, file_hint)` —— 三路定位（消息内路径 > file_hint > 器官名），
     返回 `{file, method, line, confidence}`

2. `LogAnalyzer` 惰性接入（仅在需要补全时创建 SelfInspector，不拖慢常规扫描），
   对无位置问题反推位置；置信度 <0.5 标记 `needs_human_confirm`，不进自动修复队列。

3. issue 结构新增 `locate_confidence` / `needs_human_confirm` / `_locate_attempted`。

**实测**（10 条典型 ERROR）：
```
补全率: 9/10 = 90.0%
  内在世界 → organs/brain/PulseInnerWorld.py (conf=0.60)
  大脑皮层 → organs/brain/PulseCortex.py     (conf=0.60)
  潜意识   → organs/brain/PulseSubconscious.py (conf=0.60)
  嘴巴     → organs/motor/PulseMouth.py      (conf=0.60)
  完全不存在的器官 → - (conf=0.00)   ← 唯一定位失败，正确拒绝而非伪造
```
带方法名的用例能精确到行：`_knowledge_retrieve` → **第 7154 行**，置信 0.75。

**踩坑**：`parse_methods` 会跳过 `_` 开头的私有方法，导致"方法存在却被判不存在"而误降置信度。
已改用 **ast 全量查找兜底**（不动 `parse_methods` 本身，避免影响其他调用方）。

### 3.3 任务3：P2-31 InfoField L3 背压（✅ 完成）

**根因（已确认）**：`_resize_layer_pools_by_level()` 在负载升级时压缩 L3 worker：
```
critical → L3 = 0   （完全停止消费）
heavy    → L3 = 1
moderate → L3 = 1
```
而 L3（后台自主层）生产者不停 → 消费停滞 → 队列恒满 100 → 拒绝累积 600+。

**修复**（B 为主、C 为辅 + 监控）：

1. **B 消费提速**：moderate 级别 L3 worker **1 → 2**。
   （critical 保持 0 属有意保护，未改动）

2. **C 降级放行**：超限后不再一律拒绝——
   高优先级脉冲（priority 数值越小越优先，默认 ≤3）仍放行并计数，
   仅低优先级被丢弃。避免关键自主脉冲长期饥饿。

3. **监控**：
   - 队列深度达上限 **80%** 即输出 WARNING（提前预警，不必等满）
   - 新增 `_layer_overflow_allowed` 计数，日志含器官名与优先级
