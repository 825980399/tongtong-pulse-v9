## 二、T1 RequestDeduplicator 实施（P2-161）✅

**交付物**：`nucleus/field/RequestDeduplicator.py`（324 行）+ `tests/test_request_dedup_m26.py`（**18 例**，全过）

| 方法 | 说明 |
|---|---|
| `__init__(timeout=30, max_wait=10, reuse_ttl=5.0)` | 超时/等待上限/复用窗口 |
| `try_claim(request_id)` | 返回 `claimed` / `waiting` / `duplicate` |
| `complete(request_id, result)` | 完成并缓存结果，唤醒等待者 |
| `get_result(request_id)` | 取已完成结果 |
| `cancel(request_id)` | 放弃在途请求，让等待者立即接管 |
| `stats()` / `get_state()` / `reset()` / `shutdown()` | 诊断与生命周期 |

**线程安全**：单把 `RLock` + `Condition`；**持锁期间绝不执行业务**（等待走 `cv.wait()` 释放锁）→ 无死锁；
等待者不新建线程；结果写入先于 `notify_all()`。

**★实施中发现并修正的关键问题（设计文档未覆盖）**：
第25批的止血方案（3 秒时间窗「命中即 `return duplicate_skipped`」）位于 `_on_select_model` **更靠前**的位置，
会抢在去重器之前拦截 —— 若不处理，**去重器开启后也形同虚设**，D1/D2 缺陷依旧。
修正：**去重器开启时跳过止血**（`_stopgap_active = self._request_dedup() is None`），
去重器关闭（默认）时止血行为**完全不变**。

**接入点**：`PulseLung._on_select_model`，**仅对话路径**（`is_dialogue and not is_background`），
后台学习/自主交互不参与。认领→（真实调用）→`complete`；远程失败 →`cancel`（让等待者立即接管，不白等 30s）。

**灰度**：`ENABLE_REQUEST_DEDUP` **默认 False**（环境变量 `PULSE_REQUEST_DEDUP=1` 可开启）。
★验收标准要求「连续观察 1-2 批后再默认开启」→ 本批保持默认关闭。
