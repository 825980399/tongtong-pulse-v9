★**任务书偏差之二**：任务书称「SafeEvolutionExecutor已有丰富数据（**21 项指标**）」——
实测 `get_stats()` **只返回 1 项**（`{"total_patches_generated": len(self._patch_log)}`），
且 `_patch_log` 是**内存态、上限 20 条**。**真实数据源**为 `_patch_manager.load_json(history_file)`

**评分**（任务书 §T2.3，权重可配置 `EVOLUTION_HEALTH_WEIGHTS`）：
成功率 ×0.4 + (100−回滚率) ×0.3 + 稳定性 ×0.3（稳定性 = 100 − min(100, 崩溃率×10)）。
**issues**：成功率 <80% → high；回滚率 >20% → high；子进程崩溃 → medium/low；无记录 → info + `status="unavailable"`。

无记录 → status=unavailable  score=None  issues=[no_record/info]

**注意**：`status="unavailable"` + `score=None` → 自动**不参与** T1 综合评分（`_score_of` 返回 None）。

## 六、待裁决事项（3 项）

### ① `.log` 扩展名白名单会排除**真问题**（建议优先裁决）

任务书 §T5.2 要求默认排除 `.log`。实测：`logs/pulse_crash.log`（**6.49 MB**，
`no_consumer_with_producer` 成员 —— 源码有产出方、无消费方）被 `.log` 白名单排除
→ 有效无消费由 **4 → 3**。

**风险**：该文件的"写了没人读"是真问题（崩溃日志累积 6.5MB 无人读取）。
**选项**：
- (a) 维持现状（任务书字面）：`.log` 全排除，真问题不可见；
- (b) 从默认白名单**移除 `.log`**：有效无消费回到 4 条，但 `logs/` 下 383 个日志文件重新计入 no_consumer（噪声回升）；
- (c) **推荐**：保留 `.log` 排除，但把 `logs/` 加入 `PRODUCTION_CONSUMPTION_EXCLUDE_DIRS`
  之外的**例外机制**（或对 `no_consumer_with_producer` 的条目豁免扩展名白名单）——
  即「扩展名白名单**不作用于源码产出方命中的路径**」。

### ② 「信噪比 > 50%」的口径

本批输出**双口径**（报告与 `summary` 均含）：
- `signal_ratio`（真问题占比）= 3 / (3 + 135) = **2.2%**
- `noise_filtered_ratio`（噪声过滤率）= 1840 / (1840 + 135) = **93.9%**

若按后者，任务书目标达成；若按前者，则不达标 —— 因为**源码通道只解析出 17 个数据路径**
（第36批口径），剩余 135 条全是 `data/**` 下的运行产物（`data/context/*.json`、
`data/knowledge/*.parquet`、`data/evolution/*.json` 等），它们"磁盘存在但源码未引用"是**常态**。
**请裁决**：是否需要进一步把 `data/context`、`data/knowledge`、`data/evolution`（除 test_runs）
等运行态目录纳入默认白名单（预计可将未排除数压到 < 30）。

### ③ T3 私有识别的边界

本批采用 **exact**（仅 `_load`/`_save` 精确形式）。若星轨希望覆盖 `_save_user_rules`
这类**带后缀**的私有族，需接受 `_fetch_url_text` / `_read_method_body` 等误报
（实测候选 19 → 39+）。**当前保守策略已交付**，如需放宽请指示。
