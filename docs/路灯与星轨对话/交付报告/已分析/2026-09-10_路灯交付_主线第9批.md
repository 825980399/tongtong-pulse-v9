## 三、T1 · P2-76 PatchManager Popen 参数错误

**根因**：`nucleus/security/sandbox_limits.py` 的 `execute_code_in_subprocess` 中 `subprocess.Popen(...)` 误传了 `timeout=` 关键字参数。Popen 不支持该参数，导致 `Popen.__init__() got an unexpected keyword argument` 进而补丁 import 检查失败。

**修复**：
- 删除 Popen 调用上的 `timeout=EXTERNAL_CALL_TIMEOUTS["subprocess_medium"]`（超时已由后续的 `communicate(timeout=timeout_seconds)` 兜底，语义不变）。
- 同步删除因此变为未使用的 `from config import EXTERNAL_CALL_TIMEOUTS` 导入，避免 F401。
- Popen 的 `text=True` / `encoding="utf-8"` / `errors="replace"` 保留（3.12 合法）。

**验证**：`tests/test_sandbox_popen_m9.py`（2 例）——真实起子进程执行普通代码（不再报 unexpected keyword argument），并验证移除 Popen timeout 形参后超时仍由 `communicate` 兜底（`limit_hit == "wall_clock"`）。均通过。

## 四、T2 · P2-72 宽泛 except Exception 治理

**策略（零行为改变风险）**：
1. **JSON 单一读取 try 块**（`try: x = json.load(...)` / `safe_read_json(...)` 单行）：`except Exception` 收窄为 `except (ValueError, OSError)`。
   - 说明：`json.JSONDecodeError` 是 `ValueError` 子类，故 `(ValueError, OSError)` 等价覆盖 JSON 解析与 IO 错误，且**无需模块导入 `json`**，零运行时风险。
2. **兜底无日志的 `except Exception`**：保留兜底，仅在 handler 首部插入一行 `print(f"[WARNING] {basename}:{行号}: {type(e).__name__}: {e}")` 实现"记录详细日志"，不改变控制流，禁止裸 `except: pass`。

**健壮性保障**：
- **块级高风险判定**：仅当 `try` 块源码范围真正出现高风险令牌（`json.load`/`safe_read_json`/`safe_http_json`/`LLM_CALL_CONFIG`/`api_rate_limited`/`requests.get/post`/`VectorStore`/`apply_patch`/`safe_write_json`）才视为高风险路径，避免把同文件无关 try/except 一并改写（初版文件级判定会导致 217 处改动，过度）。
- **防 F841**：若 handler 已有日志则不引入未使用变量（`except (ValueError, OSError):` 不带 `as e`）。
- **跳过单行 handler**（body 与 `except` 同行），避免插入错位破坏源码。
- **幂等**：已收窄/已日志的站点跳过，重复运行安全。

**落地规模**：**15 处 JSON 收窄 + 58 处兜底补日志 = 73 个动作站点，覆盖 40 个文件**，远超"≥50 处"要求。全库 306 个 `.py` 经 `ast.parse` 全部通过。

**验证**：`tests/test_except_refine_m9.py`（5 例）——覆盖 JSON 收窄并补日志、兜底补日志、幂等重跑、已有日志不重复、单行 handler 跳过。均通过。

## 六、T4 · P2-48 知识快照流式读取 + LRU 缓存

**新建** `nucleus/mnemosyne/lazy_snapshot.py`（与 `PulseSnapshot` 完全解耦）：
- **流式读取**：用 `mmap` + 括号配对扫描器逐节点提取字节切片，**不一次性 `json.load` 318MB**；`node_id → 字节偏移` 索引单次扫描建立（内存恒定），`get_node` 按需 seek 单节点反序列化。
- **LRU 缓存**：默认 `max_cache=1000` 节点（`OrderedDict` 实现），命中直接返回，未命中按需解析并逐出最久未用。
- **鲁棒性**：扫描器对字符串转义、嵌套花括号、Unicode 内容鲁棒；无第三方依赖（标准库）。
- **接口**：`LazySnapshotView`（`.get_node` / `.iter_nodes` / `.metadata` / `.node_ids` / `.to_list` / `stream_nodes()` 生成器）。

**接入** `PulseSnapshot.load(full_load: bool = True)`：
- `full_load=True`（**默认**）：走原全量加载逻辑，**逐字节未改动**，行为零变化（向后兼容铁律）。
- `full_load=False`：返回 `LazySnapshotView`；惰性失败自动回退全量加载（捕获异常后落回原有逻辑）。

**验证**：`tests/test_lazy_snapshot_m9.py`（7 例）——流式提取全部节点（含特殊字符/Unicode 鲁棒性）、LRU 淘汰、元数据提取、惰性 vs 全量等价、iter_nodes 完整性、`full_load=True` 回归、生成器。均通过。
