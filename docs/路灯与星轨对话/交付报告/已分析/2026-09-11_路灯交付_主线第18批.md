### T2 ProductionConsumptionMatcher（646 行）

按任务书实现产出/消费识别（open / json / numpy / pandas / shutil / 方法名启发式）、
文件级映射、路径归一化、动态路径标记、四分类、按大小排序的报告与持久化。

**三处必要的实现增强**（均为让静态分析真正可用，已加注释与测试）：

1. **`os.path.join` 字面量片段拼接**：真实项目路径几乎都是 `os.path.join(ROOT, "data", "x.json")`，
   提取字面量片段拼成部分路径（含变量根时标 `static=False`）。
2. **★局部变量路径追踪**（关键）：实测项目中 `open()` 首参 **98% 是变量**（Name 134 次 / Constant 仅 1 次），
   不做追踪几乎识别不到数据文件。新增 `visit_Assign` 记录 `p = os.path.join(...)` → `open(p)` 解析
   （函数级作用域，不做跨函数传播）。
   → **数据文件识别数 1 → 16**。
3. **只认带数据扩展名的路径**：曾把 `os.path.join("data", name)` 的 `data` **目录片段**误当数据文件（误报），已收紧。

## 五、遇到的问题（均已成为护栏）

1. **★`shutil.rmtree(ignore_errors=True)` 在 Windows 上会静默失败** → 后用 `os.path.exists` 二次验证 + 强删 +
   报告，才暴露出"删除成功但随后被 atexit 重建"的真相。
2. **★atexit 绑定实例方法**（`atexit.register(self.shutdown)`）不受单例置空影响 —— 三层根因的第 3 层。
3. **★包 `__init__.py` 导出的类名与子模块同名**：`import a.b.ProductionConsumptionMatcher as x`
   会拿到**类**而非模块（`from a.b.ProductionConsumptionMatcher import fn` 正常）。
   生产代码（main.py）用后者，安全；测试改用 `importlib.import_module`。
   **建议后续避免此命名模式**。
4. **★沙箱重复执行命令**（第15批已记录）：本批多次出现补丁脚本"第二次 assert 失败但第一次已成功"，
   故所有补丁脚本改为**幂等**（先判标记再改）—— 本批 5 个脚本因此免于返工。
5. **EOL 写坏**：某次写回时未先归一化 `\r\n`，产生 `\r\r\n`（Python 可解析但行尾符不规范），已修复。
6. **verify 间歇性退出码异常**：本环境曾出现 1 次 `exit=1` 且无结果输出（T1–T11 全 PASS、无 Traceback，
   疑与沙箱/框架并发有关）；重跑即 `exit=0 / 43 PASS`。已在报告中留痕，建议正式环境复核。
