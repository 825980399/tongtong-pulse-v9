## 任务1：P1-42 L3 背压高负载下复发

### 根因分析
L3 worker 数仅由 `_resize_layer_pools_by_level` 按**机器负载等级**（cpu/mem）变化（moderate=2），与**队列深度完全脱节**。当某器官突发脉冲（如 12:12 人格内核/控制器/大脑皮层连续入队），深度 3 分钟内 80%→90%→100%，而 worker 仍固定于 2，**消费速率跟不上生产速率** → 拒绝分发 + 高优先级强制放行。即：扩容逻辑看的是"机器忙不忙"，不是"队列满不满"。

### 修复方案（方案B 动态扩缩容，带护栏）
- 新增开关 `config.l3_dynamic_scaling_enabled = True`（默认开，关闭即退回原负载等级逻辑，零行为变化）。
- 周期 tick 末尾调用 `_auto_scale_l3_by_depth()`：按队列深度决策——
  - 深度 ≥ 0.95 → +2 worker；≥ 0.80 → +1 worker；≤ 0.50 且 > base → −1 worker
  - **冷却 15s**（避免抖动）、**上限 5 worker**、**下限 2（base）**，防止资源失控。
- 关键：扩容看"队列深度"而非"机器负载"，与突发生产直接挂钩。

### 可观测性（满足"队列深度时序可查询"）
- 每完成一次 L3 分发 `_record_l3_completion()` 记 60s 滑窗消费速率。
- `_l3_producer_counts` 累计生产者计数，可导出 **生产者 TOP5 器官**。
- `get_l3_telemetry()` 端点返回：深度时序 / 生产者 TOP5 / 消费速率(脉冲/秒) / 拒绝计数。

### PHASE18 预埋
- `_record_phase18_l3()` → `record_l3_backpressure(depth, limit, workers, producer_top5, consumer_rate_per_sec)`，受 `ENABLE_PHASE18_SIGNALS` 控制。

### 验收对照

| 不拒绝分发（除非 100% 超 30s） | 扩容降低深度 → 拒绝减少（逻辑已覆盖）；**运行时确认** |

## 任务2：P0-7 自主进化闭环持续受阻

### 根因分析
11 个待审批补丁全部卡在 `need_human`，表面是"门槛太高"，实则**字段错位**：自动生成的补丁用 `runtime_verified: true` / `status: "runtime_verified"` 标记验证，而旧 `_verified()` 只认 `verified` 字段（恒 False）→ 全部判"未验证" → 无法 auto_approve → 积压 11 个、连续 26 轮修复率 <10%。

### 修复方案
- `_verified()` **桥接**修复（受 `PATCH_AUTO_APPROVE_ACCEPT_RUNTIME_VERIFIED = True` 控制，默认开）：`verified` 字段 **或** `runtime_verified in _VERIFIED_TRUTHY` **或** `status == "runtime_verified"` 即视为已验证。修复后 11 个信任分=30/conf=high/risk=低/runtime_verified 的补丁将正常走 auto_approve。
- 新增 `prune_pending(dry_run=False)`（受 `PATCH_AUTO_APPROVE_PRUNE_PENDING = True` 控制）：归档 obsolete / stale（超 `PATCH_AUTO_APPROVE_STALE_DAYS`）/ 已应用补丁到 `pending_patches_resolved.json`，直接把积压压到 <5。
- 新增 `get_pending_stats()`：按 `by_decision` / `by_risk` / `by_trust` 分布输出——即任务书要求的"明确的日志和统计"。

### PHASE18 预埋
- `scan_pending` 末尾 `record_evolution(**fields)` → `record_evolution`，受 `ENABLE_PHASE18_SIGNALS` 控制。

### 验收对照
| 任务书验收 | 落地情况 |

| 修复率 >30% | 根因消除后自动放行（逻辑单测覆盖 `_verified` 桥接）；**运行时数值需星轨框架侧确认** |
| 待审批 <5 | `prune_pending` 清理 stale/obsolete（逻辑单测覆盖）；**运行时确认** |
