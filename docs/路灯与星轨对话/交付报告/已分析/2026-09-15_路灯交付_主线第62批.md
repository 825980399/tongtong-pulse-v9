## 七、本批踩到的工程陷阱（重要，已写入债务清单）

**沙箱 safe-delete 按 turn 累积阈值（50 次）会被批量文件移动吃满。**

- 现象：同回合 `shutil.move` 移动 74 个 tmp 文件后，pytest 分片出现大量
  `SystemExit: 1` 假失败（累积 count 一度达 **534**），涉及与本批**完全无关**的测试
  （test_event_bus_m14 / test_lazy_snapshot_m9 / test_call_graph_m21 /
  test_json_key_m26 / test_semantic_cache_m41 等）。
- 更隐蔽形态：`tmp/test_isolation.py` **导入期** `_purge_stale_iso_dirs()` →
  `shutil.rmtree` 被拦截 → pytest **INTERNALERROR（exit=3）**，表现为「整片 no tests ran」，
  本批 S11/S18/S20/S21 均为此形态，**极易误判为代码问题**。
- 判别特征：失败栈落在 `sitecustomize.py` 的 `_safe_remove` / `_try_trash` /
  `_safe_shutil_rmtree`。
- 处置：大批量文件操作**单独回合**执行；分片回归改为**每次 1~2 片**小批量调用；
  污染后在新回合重跑即恢复（本批重跑 7 片全部 passed）。
