## 二、T1（P0-263）进化验证真实基线 —— ★根因确证

### 2.1 根因链（用真实数据校准）

任务书问"是验证没跑？跑了没写？还是写了被覆盖？" —— **实测答案是第四种：判据本身恒假**。

```
SafeEvolutionExecutor._count_errors_for_location(file, method, since)
    ↓ 判据：is_error_level_line(line) and (file_basename in line) and (method in line)
    ↓ 而框架日志格式为 `[模块名] 级别: 消息`（如 `[渠道] test-ch 调用失败: TimeoutError: ...`）
    ↓ **从不输出方法名** → `method in line` 结构性恒 false
    ↓ 结果：56 个已应用补丁位置在全量日志中合计命中 **0** 条
```

**判据对比实测**（56 个补丁位置在全量 `pulse.log` 中的错误计数合计）：

| 判据 | 命中数 |
|------|--------|
| **现行**（文件名 + 方法名） | **0** |
| 放宽 1（仅文件名） | **8** |
| 放宽 2（文件名 + 行号） | 8 |

### 2.2 修复内容（带灰度开关）

| # | 修复 | 说明 |
|---|------|------|
| 1 | **判据分档** | 新增 `EVOLUTION_BASELINE_MATCH_MODE`：`file_method`（旧，兼容）/ **`file`（新默认）** / `file_or_method` |
| 2 | **窗口语义** | 基线从 `since=0`（全量历史）改为「**修复前 N 天**」窗口（`EVOLUTION_BASELINE_WINDOW_DAYS=7`）→ 与"修复后"可比 |
| 3 | **新增 `post_apply_errors`** | 任务书要求，此前**完全缺失**；`verify_fix_from_logs` 所有返回路径均已带上 |

|------|------|

**★未达标的根因（数据约束，非代码缺陷）**：
* `logs/pulse.log` 实测时间范围 **2026-09-13 11:30 ~ 13:18（仅约 2 小时）**、总 8091 行、**错误行仅 9 条**；

## 四、T3（P0-250）语义缓存器 v0 —— ★内在模型 L1 第一个落地

**新增** `nucleus/llm/semantic_cache.py`（449 行）

| 交付项 | 实现 |
|--------|------|
| 相似度 | 复用 `nucleus.semantic.VectorEncoder`（bge-small-zh-v1.5，512 维，**懒加载**，后台线程编码） |
| 缓存结构 | `{hash, prompt, response, ts, hit_count, vec}` → JSONL 追加写 |
| 持久化 | `data/cache/semantic_cache.jsonl` |
| 容量 / TTL | `SEMANTIC_CACHE_CAPACITY=10000`（LRU 淘汰）/ `SEMANTIC_CACHE_TTL_DAYS=7` |
| ★L1 红线 | `lookup()` 只返回**命中统计**（相似度/命中次数），**绝不返回缓存内容** → 调用方无从替换回复 |
| ★零阻塞 | `observe_async()` 投递到后台队列（daemon 线程处理）→ 主推理流程不受影响 |
| 灰度 | `ENABLE_SEMANTIC_CACHE_OBSERVE`（默认 True）；关闭 → 不启线程/不落盘/零 IO |
| 埋点 | `PulseLung._call_via_channels` 成功点旁路观测 |

### 4.1 ★★阈值真实校准（任务书给 0.92，实测偏保守）

| A | B | cosine |
|---|---|--------|
| 今天天气怎么样 | 今天天气怎么样 | **1.0000** |
| 今天天气怎么样 | 今天的天气如何 | 0.9205 |
| Python怎么读文件 | Python 读取文件的写法 | 0.8716 |
| 你是谁 | 你叫什么名字 | 0.7220 |
| 如何提高系统性能 | 怎样让系统跑得更快 | 0.6746 |
| 曈曈是什么 | 帮我写一个排序算法 | 0.3291 |
| 今天天气怎么样 | 推荐一部电影 | 0.2975 |
| 如何提高系统性能 | 今天午饭吃什么 | 0.2083 |

**同类最小 0.7220 / 异类最大 0.6746** → 任务书的 0.92 **只命中"几乎逐字相同"**，
大量同义改写（0.67~0.92）会漏判；而任务书的另一条验收"不同问题相似度<0.5"**在真实数据上不成立**
（有 2 例跨主题 >0.5）。两条验收标准**互相冲突**（bge-small-zh 对本项目语料的区分度本身偏弱）。

**本批处置**：**保持 0.92**（保守，误报极低）；**实测数据已写入装配注释**；
建议若要在 L2 启用返回，阈值应下调到 **0.78~0.85** 区间（待更多真实数据标定）。

### 4.2 ★端到端实测（真模型）

| 观测顺序 | 问题 | entries | hits | misses |
|---|---|---|---|---|
| 1 | 今天天气怎么样 | 1 | 0 | 0 |
| 2 | 今天的天气如何（同义） | 2 | **1** | 0 |
| 3 | 推荐一部科幻电影 | 3 | 1 | **1**（与天气类无关 ✓） |
| 4 | 请推荐一部科幻电影（同义） | 4 | **2** | 1 |

**命中率 66.7%（2/4）**；512 维向量正确落盘。

### 4.3 ★修复的真实缺陷：缓存永不积累

首版实现中 `_handle()` 在 `lookup()` 返回 `None`（空缓存/编码器未就绪）时**直接 return**
→ 首次观测写不进去 → **缓存永远为空**（实测 entries 恒 0）。
已改为"无论比对结果如何都写入本次调用"。
