### T1 LLM 调用留存字段补全（P1-285 / P1-286）

**★T0 核实（改变了实现重点）**：

| 核实项 | 任务书前提 | 实测 | 结论 |
|---|---|---|---|
| `prompt_version` 字段是否存在 | 「在 `record()` 中**增加**该字段」 | **字段早已存在**（第40批） | 真实缺口是**默认值 + 调用点从不传参** |
| `error` 字段是否存在 | 「当 `success=False` 时记录 error」 | **字段早已存在** | 同上 |
| 缺口规模 | `prompt_version` 100% 缺失；failed error 全空（111） | **246/246 缺失；111/111 全空** ✅ 准确 | — |
| 「进化循环调用点」 | 需补版本号 | ★**进化循环根本没有埋点** | **需新建埋点** |

**★本批最高价值修复**：实测 `data/llm_traces` 的 `origin` 分布只有 `user_query`(155) / `system_internal`(102)，
**`evolution_task` 恒为 0** —— 而按依赖度统计**进化循环占 LLM 调用的 98.8%**。
根因：`LLMEvolutionEngine` / `SelfReflectionEngine` / `SafeEvolutionExecutor` 三个引擎**各自直连 HTTP**，
从未接入留存管道 → **内在模型最关键的数据源完全空白**。本批以**装饰器**（一行/引擎）补齐。

**交付**：

* `record_evolution_call()` + `trace_evolution_call()` 装饰器（`prompt_pos` 参数适配不同引擎签名）。
* PulseLung 4 个调用点版本号：`lung.entry.v1` / `lung.remediation.retry.v1` / `lung.semantic.v1` / `lung.chat.v1`。

### T2 语义缓存升 L2 设计（P0-250 / P2-288）

**★核心产出是「用真实数据否掉了 0.92」**（`tools/calibrate_semantic_threshold.py`，真实 bge-small-zh-v1.5）：

| 类别 | 相似度区间 |
|---|---|
| 同义改写对（10 组，应命中） | **0.8602 ~ 0.9673** |
| 不同话题对（10 组，不应命中） | **0.1048 ~ 0.3883** |

⇒ **可分离带 (0.3883, 0.8602)**，两族**完全不重叠**。

| 阈值 | precision | recall | F1 |
|---|---|---|---|
| **0.85** | 1.0000 | **1.0000** | **1.0000** ← 推荐 |
| 0.90 | 1.0000 | 0.7000 | 0.8235 |
| **0.92（当前）** | 1.0000 | **0.6000** | 0.7500 ← **漏检 40%** |
| 0.95 | 1.0000 | 0.1000 | 0.1818 |

**真实语料（66 条去重 prompt）**：最近邻相似度 min **0.7193** / 中位 0.9649 / max 0.9917；
命中率 `0.60~0.70→100%`｜`0.72~0.92→98.48%`｜`0.96→69.7%`。

> **★结论：0.92 的保守方向反了** —— 它对"异类上界 0.3883"留了 0.53 冗余，却**已经高于同类下界 0.8602 之上**，直接漏检。
> **推荐 0.85**（安全带 [0.75, 0.86]，硬下限 0.70）。**本批仅出证据，未改配置**（`SEMANTIC_CACHE_THRESHOLD` 仍为 0.92）。

设计文档含：架构升级路径（A→**B-shadow**→C）、四道安全闸门、TTL/LRU/容量、灰度 5%→100%、三层回滚、六项监控、7 条风险与缓解。**未改任何运行逻辑。**

## 九、★本批踩坑与教训（已入 skill §39）

1. **★★契约变更会打断"精确签名假件"**：给 `_call_remote_api` 加 `prompt_version` 形参 →
   `test_request_dedup_m26.py` 的 `def _remote(prompt, model, enable_thinking=False)` 立即 TypeError。
   **修法**：该方法**保持签名不变**，版本号经**一次性实例属性**转交（转交后清零防串味）。
   → 教训：**给"被测试广泛打桩的方法"加形参前，先 grep `_method =` / `def _fake`**。
2. **★★框架正在运行这一事实，改变了两个任务的执行方式**：`logs/pulse.log` 与 `data/llm_traces/*.jsonl`

   不可"删除重建"。→ 教训：**开工先确认框架是否在跑**（读 `pulse.log` 尾部，而非只查 `.py` mtime）。
3. **★T0 核实再次改变实现重点**：任务书说"增加字段"，实测**字段早已存在**，真缺口在调用点。
   若照字面做，会得到"改了默认值但数据仍 100% 缺失"的假交付。
4. **★`ruff --select F` 抓到自己的 `NameError`**：`tools/calibrate_semantic_threshold.py` 的
   `main()` 里 `_p` 赋值却引用 `p` —— 若只靠"跑一次看看"，会在**报错路径之外**漏掉。
   本次靠 `--select F` + 实际运行双重暴露。
5. **★跨文件聚合口径要"拍平"**：回填工具 `apply_file()` 原返回 `{"plan": {...}}` 嵌套结构，
   而 `run()` 按顶层 `x["total"]` 聚合 → `KeyError`，被自己的门控测试当场抓住。
