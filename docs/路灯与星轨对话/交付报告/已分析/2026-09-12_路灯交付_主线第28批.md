## 三、逐任务交付

### T1 大模型输出长度优化（P2-171）— ✅

**根因（实测到行）**

```
PulseLung._build_chat_prompt(:2043) 结尾：
    f"\n请用完整有内容的回复（建议3-6句话，50字以上，避免一句话敷衍）:"
                                    ↑ 硬编码，任何问题（含要求写长文的）都被压到 ~100 字
渠道路径 system prompt（:732）虽含"避免过于简短敷衍"，但**无量化要求**
适配器 max_tokens 默认 512（对 300+ 中文字仍有余量）→ 次要因素
真实样本：中位 87 字 / 均值 102 字 / 最大 256 字（25 条）
```

**修复（三处，全部带灰度）**

1. `config.py` +17 行：`ENABLE_OUTPUT_LENGTH_OPTIMIZATION`（默认 True）、
   `LLM_TARGET_OUTPUT_LENGTH=300`、`LLM_SHORT_REPLY_LENGTH=50`、
   `LLM_LONG_QUESTION_MIN_CHARS=30`、`LLM_MAX_TOKENS_OVERRIDE=1024`、`LLM_LONG_REPLY_KEYWORDS`（16 个）；
2. `PulseLung.py` +87/−2：
   - 新增 `_m28_needs_long_reply`（**问题长度 ≥ 阈值 或 命中长文意图关键词**）、
     `_m28_chat_length_hint`（对话路径分级文案）、
     `_m28_system_length_suffix`（渠道路径 system 后缀）、
     `_m28_max_tokens_nonchannel`（非渠道 max_tokens，**下限 512 保护**）；
   - 替换硬编码长度指令；渠道路径 system 追加同源长度指令；
   - 渠道路径 `build_request` 显式传 `max_tokens`（**渠道 policy 的 4096 override 优先，不被覆盖**）；
3. 分级效果：长问题 → 「不少于300字，可分段或分点展开…」；短问题（"你好"）→ 「50字左右即可，**不必刻意展开**」（**不影响短问题快速回复**）。

**验证**：`tests/test_output_length_m28.py` **28 例全过**；`tmp/check_m28_t1.py` 34/34。
★**零回归**：开关关闭时三处分别回到「原文案 / 空后缀 / 512」，已由 6 例断言固化。

**端到端（★待办）**：运行实例为 08:30 启动（早于本次改动）→ 需再重启一次。
验证脚本：`tmp/check_m28_t1_runtime.py`（对比优化前后输出长度）。
