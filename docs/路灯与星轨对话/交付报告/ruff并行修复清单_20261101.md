### 4.3 附带修掉：R1 打红的 2 条「钉措辞」断言

跑回归时发现 `tests/test_m372_b456_cold_chain.py` 的 `test_01` / `test_03` 是 **R1 打红的**
（不是既有红）：它们写死

```python
assert "full_load=False if _m372_lazy_on else True" in _main
```

而 R1 把 `main.py` 那行做了 SIM211 等价化简（`False if x else True` ⇒ `not x`，
**穷举 9 个取值验过运行时等价**）⇒ 字面量一变，两条用例就红了。

**这是「等价」的边界**：等价改写对**运行时**成立，对**源码文本断言**不成立。
改法是把断言从「钉措辞」换成「钉语义」——加一个 `_full_load_arg()` 解析
`self.snapshot.load(full_load=<expr>)` 的实参，只要求它由 `_m372_lazy_on` 派生、
且不重新读一次配置：

| | 绿/红 | 说明 |
|---|---|---|
| 修前 | 1 / 3 | `test_01`、`test_03` 被 R1 打红；`test_04` 是既有红（它钉历史 commit `5dff8abe`，`PulseSnapshot.py` 之后确实改过） |
| 修后 | **3 / 1** | 只剩 `test_04` 那条既有红 |

★写这段时踩了一次自己的坑：第一版正则用裸 `full_load=([^)\n]+)`，取到的是**注释里**
那个 `full_load=False`（`main.py:2234` 的 `# 以 load(full_load=False) 直接驱动验证`），
得到一个永远失败的判据。收紧成 `self\.snapshot\.load\(\s*full_load=` 才对。
