## 三、刀1 · 覆盖率口径诊断（只读 · 实测结论）

- 图：`data/call_graph/graph_20261019_181955.json` → `nodes=6779` / `edges=7666`
- stats：`total_functions=6779`、`total_calls=63566`、`unresolved_calls=27278`（42.9%）、`external_calls=27009`（42.5%）、`dynamic_calls_unresolved=27295`、`parse_errors=0`
- 节点三类计数：仓内定义节点 `A=6779`；外部/未定义目标 `B=0`（边只含已解析仓内 callee，外部/未解析根本不进 edges）；未解析引用 `C=0`
- 两种分母覆盖率：
  - 分母=distinct callee 目标(3910)：仓内命中/3910 = **100%**（所有 callee 均解析到仓内）
  - 分母=仓内定义节点(6779)：仓内命中/3910 = **57.68%**
- 结论：**57.7% = 3910/6779 = 「仓内被调用函数占比」**，其分母【已排除】外部/未定义目标（它们根本不进 edges，也不在 6779 节点集内）。因此任务书猜想「外部/未定义被算进分母压低 57.7%」【不成立】——57.7% 是真实的「函数被调用足迹」指标，不是口径失真。
- 真正影响 dead_code 解禁的是【按调用点】的解析完整度：`unresolved 42.9% + external 42.5%`（外部属合理、应排除）→ 仓内可解析调用的解析率 = `9279 / (63566 - 27009) ≈ 25.4%`，远低于 70%。
- 解禁条件裁定建议（供星轨/小林裁）：① 当前 70% 阈值若指「调用解析完整度」，实测约 25.4%，【未达】；② 57.7% 这个数【不能】作为解禁依据（它是足迹口径，与解析质量无关）。建议将解禁条件重写为「仓内可解析调用解析率 ≥ X%（明确排除 external）」，且当前实测未达。如实降级申报。
