## 一、T-112a：D186 写锁优化 + 假死探测器可观测化（P0）

**根因**：全局唯一写锁 `_WRITE_LOCK` 竞争严重（92.9% dump 线程 parked 在写锁上）；假死探测器 `print` 不进 logging，事后无法自证。

**改动（4 处）：**

1. **D186-A 按路径分锁**（`nucleus/data/DataAccessLayer.py`）
   - 新增 `_PATH_LOCKS = {}`（normcase(abspath) → Lock）+ LRU 上限 1024；
   - 新增 `_get_path_lock(path)`（normcase + LRU 收敛，超上限丢最旧引用）；
   - `safe_write_json` / `safe_write_text` 由全局 `_WRITE_LOCK` 改为 `_get_path_lock(path)`，备份 I/O 移出锁外。
2. **D186-D 退避重试**：新增 `_replace_with_retry(tmp, target, max_retries=3)`，缓解 Windows 读者持句柄导致的 `WinError 32/5`。
3. **E 假死探测器可观测化**（`main.py` `_liveness_watchdog`）
   - `print(_msg)` → `logging.warning(_msg)`（进日志文件）；
   - 触发前写带时间戳 `WATCHDOG_DUMP stall=… handled=…` 行；
   - `pulse_crash.log` 超 20MB 自动轮转（faulthandler 常驻句柄重新 enable）；
   - `silent_exc(...)` → `logging.warning(...)`（静默异常升级 WARNING）；
   - 顺带修正崩溃日志路径为绝对路径（原先相对 cwd，容器/服务场景下可能落错目录）。
4. **配套修复**：
   - `organs/core/PulseMetricsCollector.py:205-209` 直写 `json.dump` → 改走 `safe_write_json`（硬化写通道）；
   - `nucleus/mnemosyne/ReasoningExperience.py` `_save` 加 `threading.RLock()` 防并发/递归保存互相覆盖，并改走 `safe_write_json`。

**验收**：
- ✅ 并发压力测试通过（`tests/test_write_lock_contention_m112.py`：8 文件 × 4 线程全返回 True，无丢失/损坏；退避重试模拟 `errno=32` 通过；唯一 tmp 写后无残留）；
- ✅ `parked` 比例从全局互斥降为按路径隔离（`test_path_lock_isolation`：同路径同锁、异路径异锁）；
- ✅ 假死触发可进日志（`grep "假死探测器"` 有命中，且落 `pulse_crash.log`）；
- ⚠️ `WinError 32 消失` 与 `parked 比例降到 0` 需在**真实启动 + 高并发 dump** 下观察（本批为停框架离线交付，运行时压测留待终验/重启后观测）。

## 三、T-112c：L0 看门狗 boot 超时修复（P1）

**根因**：boot 重任务（服务检查 + 硬件检测）在 L0 worker 串行执行，总预算 ~12s > L0 看门狗 8s 超时；顺带 `Popen(timeout=)` bug（Popen 不接受 timeout 形参）。

**改动（`organs/core/PulseSystemManager.py` + `nucleus/field/InfoField.py` + `config.py`）：**

1. **boot 重任务异步化**：拆出 `_run_boot_checks()` 后台守护线程承载「服务检查 + 硬件检测」；`_on_system_boot` 仅同步执行轻量步骤（建目录 + `_schedule_health_check`），立即返回 `{"boot":"started","services":"pending","hardware":"pending"}`，不阻塞 L0 worker。结果存实例属性（功能不丢）。
2. **Popen(timeout=) 真 bug 修复**（`_on_start_service`）：
   ```python
   _proc = subprocess.Popen(service["start_cmd"], stdout=DEVNULL, stderr=DEVNULL,
                             creationflags=CREATE_NO_WINDOW if win32 else 0)
   try:
       _proc.wait(timeout=EXTERNAL_CALL_TIMEOUTS.get("subprocess_medium", 30))
   except subprocess.TimeoutExpired:
       self._log(WARNING, f"启动 {service['name']} 超时（wait），进程仍在后台运行")
   ```
   → Ollama 等托管服务自动启动将真正生效（原 `Popen(..., timeout=)` 抛 `TypeError` 致启动失败）。
3. **L0 超时接 config**（`InfoField.py:386`）：`self._l0_timeout = float(PULSE_LAYER.get("l0_processor_timeout", 8.0))`；`config.py` `PULSE_LAYER` 仅新增键 `"l0_processor_timeout": 8.0`（不动运行开关）。看门狗真死锁检测循环（`_now - _ts > self._l0_timeout`）保留。

**验收**：
- ✅ 冷启动 boot 窗口不再被重任务阻塞（异步化）；
- ✅ Popen bug 修复（不再 TypeError）；
- ✅ 超时阈值可经 config 动态调整（`PULSE_LAYER.get('l0_processor_timeout')=8.0` 冒烟通过）；
