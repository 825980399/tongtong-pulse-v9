## 2. T-96a（P0）：进化通道接入渠道池

### 2.1 根因定位

`SafeEvolutionExecutor._call_llm_for_repair` 的 HTTP 出口直读 `config.REMOTE_API_CONFIG`
（`https://api.deepseek.com/v1/chat/completions`，**官方收费**），与对话链路的健康之外：

- ❌ 不走 `config.get_active_channels()` ⇒ 智谱/火山的免费与赠送额度**完全没用上**；
- ❌ 不接 `ChannelHealthTracker` ⇒ 渠道熔断失效、进化链 86% 失败率下仍无退避地持续重试（烛微 N3）；
- ❌ payload 里的 `model` 恒为全局默认 ⇒ 即便将来换了 URL，请求的仍是旧模型。

### 2.2 改法（三层回落 + 灰度）

在 `SafeEvolutionExecutor` 新增 4 个能力点（**全部新增，不改既有调用**）：

| 方法 | 作用 |
|---|---|
| `_m96_channel_pool_on()` | 灰度开关 getter（读 `config.ENABLE_EVOLUTION_USE_CHANNEL_POOL`，默认 **False**） |
| `_m96_set_lung(lung)` | **注入钩子**：允许 main 传入运行中的 PulseLung 实例 ⇒ 与对话链路**共享同一个** ChannelHealthTracker 账本 |
| `_m96_select_channel()` | 按优先级选可用渠道，判据与生产同源：① `get_active_channels()` ② `ChannelQuotaMonitor.apply_to_channels()` ③ `ChannelHealthTracker.is_available()` |
| `_m96_record_channel_result()` | 把进化链调用结果回写健康度（`.record(name, success, latency)`，**同账本**） |

**三层回落**（任一层失败都回到既有行为）：

1. 开关关闭 ⇒ 直连 `REMOTE_API_CONFIG`（**当前默认，零行为变化**）；
2. 开关开但 `get_active_channels()` 为空/异常 ⇒ 回落 `REMOTE_API_CONFIG`；
3. 渠道字段不全（`api_url` / `model` 缺一）⇒ 跳过该渠道继续找下一个；全池不可用 ⇒ 回落。

**model 透传**：`_call_llm_with_followup(..., model="")`，payload 改 `"model": (model or <全局默认>)`。

```
CODEBUDDY_TOOL_CALL_ID                  = ...    ← ★按「工具调用」分桶累计
```

shim 把 `os.remove` / `shutil.rmtree` 重定向到回收站，并且**同一 tool-call 内累计删除满 50
次后直接 `raise SystemExit(1)`**（`sitecustomize.py:826`）。由于 state dir 是共享的，
**累计量会跨 pytest 子进程累加**。

V1 在**同一个 Bash 工具调用**里连跑 30 个 pytest 子进程 ⇒ 共享同一个 bucket ⇒
前几片的删除量烧穿 50 ⇒ 后面 19 片**成片假失败**。

**对照实验**（`tmp/m96_why.py`，同时排除 `PYTHONPATH` 因素）：

|---|---|---|
