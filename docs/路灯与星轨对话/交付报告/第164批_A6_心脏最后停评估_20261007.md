# 第164批 刀A6（P3）·「心脏最后停」退出顺序评估结论

> 来源：烛微 162 批活体观测 LIVE-2（心脏停搏早于批量汇总，"心脏最后停"实测未达成 `PulseHeart.py:222`）。
> 验收口径：退出顺序评估结论成文；如需修改给出落点与影响面。

## 一、结论

**当前「心脏最后停」未达成（与 LIVE-2 观测一致），根因已定位，属时序矛盾而非缺失实现。**
修复落地成本低（仅 `PulseHeart` 一处或 `main.py` 一处），建议停窗 + 单元门控后实施；不影响运行期心跳。

## 二、根因（逐行实测）

`main.py::stop()` 的优雅退出流程存在两处对「心脏」的矛盾处理：

1. **早期全局 STOP 广播（line 2583-2592）**
   ```python
   # ★P1-5修复：先给所有器官发STOP脉冲，再依次停止
   stop_pulse = self.pulse_core.emit(
       source_organ="main", event_type=SystemEvent.STOP, priority=10, layer=PulseLayer.L0_LIFELINE)
   self.info_field.publish(stop_pulse)   # ← 广播给【所有】订阅器官，含心脏
   ```
   心脏订阅 `SystemEvent.STOP`，其 `on_pulse` → `_on_system_stop`（`PulseHeart.py:219`）在此处即被触发，
   立刻执行 `self._log("INFO", f"心脏停搏，总计 {self._beat_count} 次心跳")`（**PulseHeart.py:222**）。

2. **心脏实际拆除在最后（line 2599 / 2604-2605 / 2650-2652）**
   ```python
   # ★终止优化：器官停止并行化（心脏最后停）
   for organ_name, organ in list(self.organs.items()):
       if organ_name == "心脏":
           continue   # 心脏最后停  ← 并行拆除显式跳过心脏
       ...
   # 最后停止心脏
   if hasattr(self, 'heart') and self.heart and self.heart.is_running:
       self.heart.stop()   # ← 真正调用在收尾
   ```
   `PulseHeart.stop()`（`PulseHeart.py:852`）先 `_cancel_timer()`、`_booted=False`，再 `super().stop()`。

**矛盾点**：第 1 步把「心脏停搏」日志打在了关机流程**最开头**（早于其它器官拆除与运行统计），
而代码注释与并行循环都声明「心脏最后停」。于是关机日志里 `心脏停搏` 远早于批量汇总/其它器官退出，
造成运维误判——这正是 LIVE-2 记录的「心脏停搏早于批量汇总」。

## 三、影响面

- **仅影响关机期日志时序与可观测性**，不影响运行期心跳节律、不影响数据持久化（上下文快照在 STOP 广播前已保存，line 2567-2581）。
- 不改变「心脏物理上最后被拆除」的事实（line 2651 确为最后调用），只是「停搏」语义日志提前了。
- 对依赖 `HeartEvent.ALIVE(status=已停搏)` 信号的下游（若有）时序略有前移，但仍在关机窗口内，无功能危害。

## 四、修复建议（落点）

### 方案 A（推荐，仅改 `PulseHeart`，零 main.py 风险）
在 `_on_system_stop` 中区分「早期广播」与「最终拆除」：早期 `SystemEvent.STOP`（此时 `self._booted` 仍为真）只取消定时器、**不记停搏**；真正停搏日志改由 `PulseHeart.stop()` 在 `_booted=False` 之后输出，并用 `_stop_logged` 防重。

- 落点 1：`PulseHeart.py:219-230`（`_on_system_stop`）—— `if self._booted: return {timer_cancelled}`（早期广播早退，不记停搏）。
- 落点 2：`PulseHeart.py:852-856`（`stop`）—— `_booted=False` 后调用统一的 `_log_stop()`（记「心脏停搏」+ 发 `HeartEvent.ALIVE 已停搏`），`_log_stop` 内 `if self._stop_logged: return` 防重。
- 健壮性：无论基类 `Organ.stop()` 是否再发 STOP 脉冲，停搏日志都只出现**一次**且位于最终拆除。

### 方案 B（改 `main.py`）
初始 STOP 广播排除心脏（与 line 2604 并行跳过心脏保持一致），使「心脏停搏」仅由 line 2651 的 `heart.stop()` 触发。改动点集中但触及关机编排主流程，需更谨慎的回归。

## 五、验证方式

- **单元级（可在不停框架/停窗下执行）**：实例化 `PulseHeart`，模拟两次 STOP 投递——
  ① `booted=True`（早期广播）→ 断言 `_on_system_stop` 返回且不记「停搏」；
  ② 调 `stop()`（booted=False）→ 断言恰好记一次「心脏停搏」且 `HeartEvent.ALIVE(status=已停搏)` 发出一次。
- **集成级（停窗真实关机）**：观察 `logs/pulse.log`，确认「心脏停搏」位于收尾、晚于其它器官拆除与运行统计。

- 实施后需单元门控 + 停窗真实关机验证（当前曈曈已停止，满足停窗纪律）。
