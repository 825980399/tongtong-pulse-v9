### 5.3 ★本批吃到的三个新坑（已记入长期记忆）

1. **注释吞代码**：给单行 dict 追加行内 `#` 注释且不换行，会把同一行后面的
   `"status": "verified"` 吞进注释 → 补丁实际没有 status → 被别的通道抢先批准。
   症状极隐蔽（测试只报"状态不对"，不报语法错）。**规则：往单行结构里插注释，必须插成独立行。**
2. **`bash -c` 双引号里的反引号会被 shell 当命令替换**：刀12 D 面第一次写入，
   `` `_all_ok = ...` `` 被执行成命令（`_all_ok: command not found`），正文里静默丢了引用。
   **规则：带反引号/`$`/反斜杠的文本一律写脚本文件再跑**（与既有铁律同源，这次又犯一次）。
3. **同文件两刀要拆成两笔提交**：刀1/刀2 都改 `PatchManager.py`。做法是
   `存全量 → git checkout 还原 → 只跑刀1 补丁脚本 → 提交 → 拷回全量 → 提交刀2`，
   比 `git add -p` 可复现、可审计。
