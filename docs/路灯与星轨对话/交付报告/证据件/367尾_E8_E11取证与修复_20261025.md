## ★E8 施工中撞出的新 bug：修复链会**静默篡改语义**

### 现象

```
输入  {"关键步骤": ["a" "b"]}          ← 数组里两个字符串缺逗号
改前  method="repair"  →  {'关键步骤': ['a" "b']}   ← 两个元素合并成一个！
```

### 根因

`_escape_inner_quotes` 的判定：
```python
nxt = 跳过空白后的下一个字符
if nxt in (",", "}", "]", ":", ""):  # 字符串结束
else:                                 # 内部引号 → 转义
```
`"a" "b"` 里 `a` 后面的 `"`，向后看是 `"`（另一个字符串的开始）⇒ 不在结束集 ⇒
被判「内部引号」⇒ 转义 ⇒ 整段变成**一个**字符串 `a" "b`。

这直接推翻 `PulseStomach:788` 原注释「修复器内部保证…**不会引入语义错误结果**」。

### 为什么比解析失败更糟

失败会 fallback 或被丢弃；**篡改会静默污染知识库** ——
LLM 输出的「关键步骤」从 2 条变 1 条，没有任何人会发现。

### 修法：宁可不修，不可篡改

内部引号**后面紧跟另一个引号**时不转义（保持字符串结束语义）⇒ 该候选解析失败。

实测**零能力损失**：

| 输入 | 改前 | 改后 |
|---|---|---|
| `["a" "b"]` | repair → **篡改** | `none`（诚实失败） |
| `"he said "hi" ok"` | repair | repair ✓ 仍能修 |
| ```` ```json ```` fence | extract | extract ✓ |
| 尾随逗号 / 缺冒号 | repair | repair ✓ |

既有 4 个测试文件 25 例全绿（无回归）。

## E11 `T-学习目标漂移-1`

### 票面

「『代码』两次强制切换（连续 3 次评估不佳）复核学习判据；与 E4 占位符族先对照是否同源」。

### 与 E4 是否同源：**不同源**

- E4 = **产出侧**（LLM 输出里占位符没替换，格式/模板问题）；
- E11 = **评估侧**（学习目标词表与知识路径词表对不上，判据问题）。
二者不共用代码路径，无共同上游。**无需并批**。

### 根因：两套词表**无交集**（铁证）

| 侧 | 产出方 | 词表 |
|---|---|---|
| 能力画像 | `SelfAwarenessEngine:778` | `code_health` → **「代码」** |
| 知识路径 | `PulseInnerWorld._get_path_label_for_plan` | `"/技术" → "技术架构与编程"` 等 7 条 |

评估判据 `if label and target_area in label` ⇒ 即 **`"代码" in label`**。

实测各领域名的命中数：

```
「代码」                        ⇒ 0 条      ← 就是它在漂移
「技术」「编程」                  ⇒ 1 条（/技术）
「反思」「身份」「知识」「社会」「本能」 ⇒ 各 1 条
```

⇒ 「代码」目标的 `nodes_after` **恒为 0** ⇒ `nodes_growth ≤ 0` ⇒
必判「效果不佳」⇒ 3 次后强切 ⇒ 切走又切回。

日志实证（两个进程代次各来一遍）：
```

```
（`#4` 与 `#1` 是计数器随进程换代重置 —— 这本身也是"切走又回来"的旁证。）

### 顺带发现同段另两处 bug

**B. 无样本被当 0% 成功率**
`area_traces` 为空时 `success_rate = 0.0`，与「样本全是低分」同形 ⇒
「这个窗口没跑过含该领域的推理」被当成「学得差」而累加失败。
（这与 353 批 `hit_rate=None` 是同一条口径：无样本 ≠ 零。）

**C. 单字匹配**
`for word in label: if word in question` —— 遍历的是**字符串的每个字**，
「技术架构与编程」里只要问题含「与」就命中该领域，失败领域统计被严重放大。

### 三处修复

| # | 改动 | 要点 |
|---|---|---|
| A | 新增 `_GOAL_AREA_PATH_PREFIXES` + `goal_area_path_prefixes()` | 映射不到返回空元组 ⇒ **退回**原判据，绝不因查表失败就判失败 |
| B | `_has_sample` 区分无样本 | 无样本 ⇒ 不计失败、不清零、不切换，只留痕 |
| C | 整体匹配替代单字匹配 | `if label and label in question` |

### 验收（10 例，含两个守门员）

- 别名映射 6 例：`代码→/技术`／其余领域名／未知名返回空／含关系最长键优先／
  ★**对称性**（知识路径标签表每条路径都必须有别名能命中）／
  ★**反向**（别名值必须是真实存在的知识路径）；
- 判据修复 4 例：`nodes_after` 确实走别名分支／无样本挡板存在且写明不计失败／
  单字遍历已消除（**AST 判，不用文本包含**）／有样本仍照常算成功率。

两个「★」是**防再分叉**的守门员：原 bug 的故障是**延时显形**
（3 个评估周期、约 1 小时才切一次），没有这两条测试只能等日志漂移才发现。
