## 三、处置口径与可复用做法（★沉淀件）

### 3.1 三类处置方式（按族选用，不一把梭）

| 方式 | 适用族 | 做法 |
|---|---|---|
| **A. 级别降级** | F1／F8／F9 | 控制流每拍必然输出、且存活证据另有所托（beat_count / health_snapshot）⇒ INFO 降 DEBUG |
| **B. 状态变化才打** | F2／F3／F4／F5／F6／F7 | 读数/状态不变则不打，一变立刻恢复；被抑制次数记入 `suppressed()`，可在聚合行尾带出 ⇒ **降噪不等于消失** |
| **C. 聚合为一行** | F2 | 同族逐条刷屏合并为整次操作一行汇总（含次数/命中/跳过/逐项明细），异常仍单列 |

### 3.2 新建可复用判据件：`nucleus/log_state.py`

- `changed(tag, state) -> bool`：内容节流（state 与上次同 tag 相同则返回 False）
- `sig(obj)`：把 dict/list/set 归一成可比较的稳定结构（键序无关，支持嵌套）
- `suppressed(tag) -> int`：自上次放行以来被抑制的次数
- `reset(tag=None)` / `snapshot()`：测试与观测用

**与既有 `nucleus/_warn_throttle.py` 的分工（★165 一开关一语义，不合并）**：

| 件 | 节流维度 | 用途 |
|---|---|---|
| `_warn_throttle.should_warn(key, interval)` | **时间窗** | 持续失败态的 WARNING 刷屏限流（放行与内容无关） |
| `log_state.changed(tag, state)` | **内容** | 读数/状态刷新类日志（放行只看内容有没有变） |

### 3.3 同族内已有先例时沿用就地判据（★214 重锚最小改动）

F6-a（Liver:1072）**没有**引入 `log_state`，而是沿用紧邻 1078／1206 两处**同族已有**的 `getattr(self, '_last_xxx', -1)` 就地判据写法。理由：同一函数内三处并列，混入两种写法会破坏可读性且增加后续维护分歧面。
