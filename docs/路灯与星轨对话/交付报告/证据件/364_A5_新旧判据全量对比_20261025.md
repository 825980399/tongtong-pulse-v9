## 二、方法与口径

| 项 | 说明 |
|---|---|
| 旧判据 | `tools/ci/ci_common.py::extract_handlers`（权威，直接调用），identity 四元组 `(path, qualname, nth, sha16)` |
| 新判据 | `extract_handlers_v2`（本工具内），identity 六元组 `(path, qualname, nth, tname, kind, sha16)`，任务书称「五元组」（tname+kind 合一档） |
| 形态 kind | `pass` / `ret` / `assign`（旧判据既有）＋ `cont` / `break`（★A5 新增） |
| 跨判据可比键 | `(path, qualname, nth, sha16)` —— 与 tname/kind 无关，用于判定「同一个 handler 的两副面孔」 |
| added | 新判据命中、旧判据未命中（新拦截面） |
| removed | 旧判据命中、新判据未命中（应为 0，非 0 即新判据实现偏差） |
| nth 口径 | 与旧判据一致：只统计「无上报（无 Raise / 无 LOG_FUNCS 调用）」的 handler，否则 diff 全是噪声（已由单测守住） |
| 生产面 | `config.py` / `main.py` / `organs/**` / `nucleus/**`，排除 `tests/ tmp/ data/ .bak*`（沿用坑 219 口径） |
| 全仓面 | `git ls-files *.py`（与 cw2 门禁 rot 检查同一文件集） |
| tier A/B/C | **启发式建议档，非裁决**：A＝qualname 命中闭环轮转/写盘/账本关键词；B＝可选依赖类捕获或配置读取兜底；C＝其余 |

## 四、人工复核（抽样 9 条，★含启发式误判订正）

| # | 位置 | 代码事实 | 启发式档 | 人工复核档 | 说明 |

| 5 | `PulseSnapshot.py:216 cleanup_temp_snapshot_residue` | 单个临时文件删除失败 `continue`（注释：不影响其它） | A | **C** | 清理路径，可豁免但应留痕 |
| 6 | `daily_reader.py:450 _read_last_queue_stats` | 候选报告读失败跳下一候选 | A | **C** | 3 个候选内跳过 |

| 8 | `AsyncEncodeQueue.py:188/190 _worker` | `except queue.Empty: continue` ×2 | C | **控制流** | 同上 |
| 9 | `semantic_cache.py:418/454` | `except queue.Empty: continue` ×2 | C | **控制流** | 同上 |

**复核结论**：
1. tier 自动归类**不可靠** —— 6 条 A 档里 5 条实为 C（误判源：按 qualname 关键词命中，无法区分「写账本」与「读账本时跳坏行」）。三档归类**不能自动化**，必须人工逐条带元数据（理由/责任人/批次）。
2. 真正值得判 A 的目前实测只有 **`call_recorder.py:681`** 1 条（轮转清理失败静默跳过）。
3. `queue.Empty: continue` 5 条应单列「控制流型」，不计入静默定义。
