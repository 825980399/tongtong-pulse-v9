## 三、★② 是文档滞后，但底下藏着一个**只在 FAIL 路径才暴露的解包错误**

改前 `_fmt_identity` 按四元组解包，而 371A5 起 `ci_common.handler_identity` 返回**五元组**：

```python
return (fp["path"], fp["qualname"], fp["tname"], fp.get("kind", "pass"), fp["sha16"])
```

`_fmt_identity` 只在这三处被调用：`:280`（豁免外新增明细）、`:293`（rot 明细）、`:301`（未跟踪明细）
—— **全都是门禁失败时才会走的打印路径**。⇒ 平时跑不到；一旦真失败，**报告器自己先 ValueError**，
把"带明细的 FAIL"变成 traceback。这不是"注释过时"，是报告器的真实缺陷。

修法：按元数分支（5 → 主路径；4 → 历史格式；其他 → `repr`）。**判据逻辑一行未动。**

实测三种输入：

```
五元组 -> a.py::f[try/pass]deadbeefdeadbeef
四元组 -> a.py::f[#1]deadbeefdeadbeef
异常形态 -> ('x',)
```
