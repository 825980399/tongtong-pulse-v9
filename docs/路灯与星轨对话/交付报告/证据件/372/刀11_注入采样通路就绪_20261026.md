## 二、交付物（新增 `tools/ci/memprobe_372_inject.py`，零生产 import）

| 项 | 内容 |
|---|---|
| 复用关系 | `_sample_inproc_base()` **直接 import** 371 刀1 `probe_memory_attribution_371.sample_inproc`；不可用时退化本件实现并在 `err.base_import` 标注（**不静默降级**，`base_source` 字段留痕） |
| 五维分器 | ①GC 分代 ②线程 ③容器 ④类型 Top ⑤器官（近似） |
| no-gc 对照 | `sample_inproc_v2(no_gc=True)` **跳过 `gc.collect()`** —— 理由：预收 gc 会临时改变堆形状，长窗每次都收等于"用采样动作污染读数"（铁律188 自噬同型）。归因必须 gc/no-gc 差分，才能回答"这些对象是活着的还是等着被收的" |
| 异常口径 | **一律结构化落 `err`，不上抛**（长窗采样中途崩掉会毁掉整段数据，比缺一维更糟）；每个维度各自 try，一维失败不影响其他维 |
| 注入片段 | `--emit-inject-snippet --duration-s 1800 --interval-s 5` ⇒ 打印可粘贴代码（默认 30min／5s 一拍 = **360 对** gc/no-gc 样本） |

### 2.1 分器维度表（与候选五类的对应关系）

| 维度 | 取数 | 对应候选（N1 取证件 §四） |

| `gc_generations` | `gc.get_count()` + `gc.get_stats()` × 3 代 | image_mb（不可释放镜像）／patch_ast_cache |

```
mode=self_v2  base_source=probe_memory_attribution_371  err=None  elapsed=13.7ms
维度 = [gc_generations, threads, containers, type_top, organs]
gc 分代(counts/s分代collections) = 0:362/16  1:1/1  2:0/1
线程 n=1(daemon 0)  前缀Top=[('MainThread',1)]
容器 objects_total=9936  top=(tuple 1029, dict 979, list 258)
器官(近似) top=[]        ← 探针进程内本来就没有器官实例，符合预期
```

单拍 **13.7ms**（含一次 `gc.collect()`）⇒ 5s 一拍对活体开销可忽略；这也是为什么
长窗用 5s 而不是 1s（1s 会把 gc 压力叠上去，反过来污染读数）。

## 四、长窗采样方案（重启窗执行，本批不做）

| 项 | 口径 |
|---|---|
| 时长 | **≥30min**（≥360 对样本），覆盖至少一次平台期 |
| 采样 | gc / no-gc **成对**采（同循环内相邻两次，间隔 <1ms，保证同"时刻"） |
| 归因顺序（单变量） | ①先量 `threads`（191 线程是否稳定增）→ ②`containers`（哪类容器在涨）→ ③`gc_generations`（是否 gen2 uncollectable 增）→ ④`organs`（哪个器官实例数涨）→ ⑤`type_top` 定位到具体类 |
| 提级阈值（立即报小林） | `ok` 转 False／任一器官实例数归零（器官停摆）／单拍耗时 >2s（探针本身变负担）／进程 RSS 触顶崩溃 |
| 判定 | 「活着的」= no-gc 读数与 gc 读数**同趋势**；「等着被收的」= gc 读数显著低于 no-gc ⇒ 前者才需要修 |
