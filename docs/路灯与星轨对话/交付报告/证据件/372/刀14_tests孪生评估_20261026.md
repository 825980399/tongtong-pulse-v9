## 一、被删的到底是什么（`d63d1d69^:base/BasePulseOrgan.py`，759 行版，块自 656 行起）

`__main__` 自测块里有两段**并发**验证（其余是 `_emit` layer、`_send` 透传等单线程演示）：

```python
# 4. 并发安全验证：10 线程同时调用正常脉冲
for i in range(10):
    t = threading.Thread(target=concurrent_call, args=(test_organ, "test.normal"))
```

## 二、为什么判"有价值"（三条，逐条实测）

### 2.1 被测方法是**热路径**，且文档明写"并发安全版"

`base/BasePulseOrgan.py:502` `_handle_pulse_safe` docstring 原文：

> 安全的脉冲处理入口（**v9.5 并发安全版**）。
> 支持多线程并发调用：
>   - 熔断状态检查与错误计数使用锁保护
>   - 业务逻辑 on_pulse 在锁外执行，不阻塞其他线程并发处理不同脉冲

⇒ 这是**每个器官每次收脉冲**都走的唯一入口。它自己声明的并发契约，比任何演示都值得有测试锚。

### 2.2 测试面**零覆盖**（不是"已有覆盖所以不必补"）

| 检索 | 结果 |
|---|---|
| `grep -rn "_handle_pulse_safe" tests/*.py` | **0 命中** |
| 熔断三态（`OrganStatus.FUSED` / 半开 `RECOVERING`）在 tests 中 | 无针对性用例（`fused` 的命中全是 `refused` 之类的**子串误配**） |

⇒ 354 批删掉那段之后，**这条并发契约在产品里没有任何测试守着**（`_fuse_lock` 被改成无锁、
`_error_count` 改成非原子自增之类的回归，整仓跑绿也发现不了）。

### 2.3 熔断/半开是**状态机**，最容易被"顺手优化"改坏

`_handle_pulse_safe` 里有：锁内判 `FUSED` → 冷却到期转 `RECOVERING`（半开）→ 计数达
`_fuse_threshold` 再 `FUSED`。这类"三段时序 + 并发"逻辑，人工 review 很难看出问题，
而原演示块**恰好就验了这两条**。

## 三、为什么不建议原样"搬回 `__main__`"，而要搬到 tests

- `__main__` 块在**生产文件里**：不会被 CI 跑、不会被任何采集覆盖，等于"写了但没人执行"；
- 且它是"高危 59"之一（刀13 面）：起 15 个线程 + 依赖 print，属该清理的形态；
- 搬到 `tests/` 后：进 CI、可被 `-k` 单跑、可断言 `OrganStatus` 枚举（而非字符串 `"fused"`）。
