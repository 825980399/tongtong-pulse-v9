> ★与票面「抽样 8 条 7 条 def 仍在」的口径分歧（请核验轮裁决）：

## 二、驳回二：`T-NUL实证-1`

### 星轨的判词

> 工具虽在仓里，但**根本没挂进 pre-commit**；340 报告只写「疑与」根目录 NUL 有关，
> 没做移走后复扫 Ruff panic 是否消失的因果坐实。路灯证据件写「已被 pre-commit 调用」
> 是误述。

### 驳回成立 —— 我的原句就是错的

实测 `.git/hooks/pre-commit` 挂的门禁清单：

```
cw2 静默except  /  5 静态门（弃用import·事件字符串·断链·silent_exc arity·legacy装配）
collect 红基线  /  S4 冷索引  /  cw3-B ctx 陈旧读  /  cw3-A 语义守恒
check_pending_register  /  check_register_columns
```

**没有 `check_nul_files_gate`**。

我错在把工具自己 docstring 里的「用法：`python tools/ci/check_nul_files_gate.py`（pre-commit 调用）」
**当成了事实**。那是声明，不是现场。

### 因果坐实（2×2 对照，`ruff check .`，stdout/stderr 分开捕获）

| 条件 | rc | stdout 行数 | Panic | package root 告警 |
|---|---|---|---|---|
| 有 NUL / 热 cache | 1 | 42191 | 无 | 无 |
| 有 NUL / 冷 cache | 1 | 42191 | 无 | 无 |
| 无 NUL / 冷 cache | 1 | 42191 | 无 | 无 |
| 无 NUL / 热 cache | 1 | 42191 | 无 | 无 |

**四组输出逐字相同** ⇒ 在当前环境，NUL 对 ruff 全库扫描**零影响**。

旁证三条：

- **ruff 版本同一版本**：`dev-requirements.txt:13 ruff==0.16.5`（138 批 T-138b 硬钉），
  本机 `ruff 0.16.5` ⇒ 不是版本漂移造成的差异；
- `ruff check NUL` 单点扫描 ⇒ `E902 函数不正确 (os error 1)`——**报成 lint error，不 panic**；
- `.ruff_cache/` 内 **grep 不到 NUL**（无历史 root 残留）。

### 诚实结论：**因果不可判定，不是「已坐实」**

340 记的 panic 在本环境**复现不出来**。因此「移走 NUL ⇒ panic 消失」这条因果
**无法坐实**——不是「坐实了」也不是「证伪了」，是**前提不在场，实验无基线**。

说「已证实因果」就是编证据。340 原文本身写的就是「**疑**与…有关」。

**能做的最强表述**：在当前 ruff 0.16.5 + 当前 cache 状态下，NUL 存在与否对全库扫描
无可观测差异；340 那次 panic 的触发条件必须另有因子（cache 历史状态最可能），
而那个状态已经不存在，无法回溯验证。

### 那为什么仍然接钩（理由改判）

**不是**为了修 panic，是为了防**保留名文件被 git 跟踪**：
一旦 `git add NUL` 提交进库，checkout 与 CI 在 Windows 上会崩，
且 `.gitattributes` 补救不了（保留名在 NTFS 层面无效）。

门禁语义正好匹配：`git ls-files` 只扫**已跟踪** ⇒ 已跟踪的保留名 FAIL，
未跟踪/被忽略的仅 stderr 警告不阻断。当前实测 rc=0 PASS。

落点：改 `tools/ci/hooks/pre-commit`（**入库的模板**，不是 `.git/hooks/` 本体——
后者不入库，改了别人 clone 不生效），安装器 `tools/ci/install_precommit_hook.py` 负责同步。
插入点：5 静态门之后、S4 之前，独立小段。提交 `1071e384`（`[ci-gate-change]` 单独笔）。
