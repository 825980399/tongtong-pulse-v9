## 一、为什么「单点实测」会得出假干净

`unresolved_samples.dump_samples()` 每次落盘后都调 `_roll()` 滚动清理，而 `_roll()`：

```python
for _old in _fs[:-_KEEP]:      # _KEEP = 7
    os.remove(...)
```

目录里只有 1-2 份样本时，`_fs[:-7]` 是**空切片** ⇒ 一个都不删。
单点跑一次看到「没删任何文件」，很容易写成「写面已干净」——
但这不是写面消失，是**触发条件没满足**。同一个函数、同一个写面，
只要份数越过 7，它就开始删。

⇒ 复测必须**成对**：条件未满足 ⇒ 不写；条件解除 ⇒ 必写。只验一侧＝又一次假干净。

## 四、零污染证据

复测全程只写显式注入的沙箱目录（`tmp_root`/`project_root`/`PULSE_ISOLATION_ROOT`）。
可反查的硬证据：预置文件名 `unresolved_samples_20200101_0000*` 极独特，不会与活体产物撞名——

* 生产 `data/call_graph/` 下：该模式文件 **0 个**

这条比「文件数不变」更稳：活体每 61 分钟会自己写一份图快照，文件数本来就会变。

## 五、复测件怎么用

```
python tools/ci/replay_conditional_writes.py --plan     # 只看矩阵（含条件与注入口）
python tools/ci/replay_conditional_writes.py --replay   # 实跑成对复测（沙箱）
```

`--replay` 退出码：三项复测全通过才 0。以后写面改动后复跑一次，
就能确认「写面还在、且隔离得住」，而不是又一次单点「没删＝干净」。
