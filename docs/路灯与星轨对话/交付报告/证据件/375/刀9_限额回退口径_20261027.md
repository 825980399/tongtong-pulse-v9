## 一、票面 vs 实测：两半不对称

票面：「44 撤销/作废后当日入池限额是否回退需钉死」。

实测发现「撤销」和「作废」是**两种完全不同的机制**，此前只有一半被堵：

| 路径 | 机制 | 是否回退额度 | 依据 |
|---|---|---|---|
| 撤销 `已撤销` / `target_drifted_closed` | 只改 `status`，条目仍在池里 | **不回退** | 354刀5 生效 |
| 撤销 `wont_fix` / `cancelled` / `revoked` | 同时命中 348 的**豁免**集合，先 `continue` | **回退** | 348刀2 生效，354 分支走不到 |
| **作废**（284刀5 结构缺陷） | `continue` 出队：**不写 status、不进 history、条目消失** | **回退** | 无任何口径覆盖 |
| `applied` 出队 | 进 history | 不回退 | 280刀4（正常出池） |

两处实锤：

1. **作废是「删条目」不是「改状态」**。`PatchManager._m280_converge_pending` 里
   `if _mismatch or _no_def: ... _voided += 1; continue` —— 条目既不 append 也不写
   `status`，只往 `converge_voided.jsonl` 台账留一行。而 `_m333_intake_rate` 只读
   `pending_patches.json` + `patch_history.json` 两轨 ⇒ 作废条目的入池记录**两轨都没有**
   ⇒ 当日入池数 −1 ⇒ 「每天 ≤1 条」可被「生成 → 作废 → 再生成」无限绕开。
2. **撤销的两条集合打架**。`_O3_QUOTA_EXEMPT_STATUSES`（348刀2，豁免⇒不占额度）
   与 `_O3_REVOKED_STATUSES`（354刀5，撤销⇒不回退）交集是
   `{wont_fix, cancelled, revoked}`；主流程**先判豁免再判撤销**
   ⇒ 这 3 个值被豁免 `continue` 掉，`revoked_no_rollback` 对它们**恒 0**
   （写了但读不到），而且额度**实际是回退的**，与 354 的注释相反。

## 三、本刀改了什么（两处生产，零判定变更）

### ① `self_inspector._m333_intake_rate` 增**第三轨**

```python
_voided_p = os.path.join(_root, _m375_cvrel.replace("/", os.sep))   # 与上两轨同一个 _root
```

★ 基准必须与上两轨**同一个** `_root`：`converge_voided_ledger_path()` 钉的是
「本模块上溯三层」的项目根、**不看 `project_root` 参数** —— 照它读，
`project_root=临时目录` 的隔离调用仍会读到**生产台账**（铁律158 路径注入）。
只借它的相对路径常量 `CONVERGE_VOIDED_LEDGER_REL`，不抄字面量。

三条去重（防虚增 —— 虚增会让限额变严、把正常入池卡死）：

| 规则 | 理由 |
|---|---|
| 只认台账**自带 O3 标记**的条目 | 存量 170 条无标记一律不计（宁可漏报） |
| 同 `patch_id` 多条台账只算 1 条 | append-only 会多次留行，同一条补丁只入池过一次 |
| `patch_id` 仍在两轨里则不双计 | 上面已计过 |

落窗用 `generated_at`（入池时间），取不到回落 `ts`（作废时间）——
用入池时间才与上两轨同口径（隔日作废不会把昨天的账记到今天）。

新增返回键：`voided_no_rollback` / `voided_candidates` / `voided_dup_skipped` /
`voided_ledger`（`ok` / `absent` / `bad_lines` / `unreadable`）。
两轨都读不到时这四个键填 **None**（不可算，不填 0）。

### ② `PatchManager._m280_converge_pending` 台账补字段

```python
issue_type=str(_it.get("issue_type") or ""),
o3_dead_code=bool(_it.get("o3_dead_code") is True),
generated_at=_it.get("generated_at") or 0,
```

没有这三个字段，第三轨就只能「全计」（虚增）或「全不计」（漏报）——两种都是错。

### ③ 撤销口径**分档**（只改观测，不改准入）

撤销计数**前移到豁免之前**，并拆成三条自洽读数：

```
revoked_total        = 撤销状态总条数（真实计数，不受豁免影响）
revoked_but_exempt   = 其中被 348 豁免掉 ⇒ 当日额度**实际回退**
revoked_no_rollback  = total − but_exempt（撤销且仍计入额度）
```

日志两行（可 grep）：`[354限额] 撤销不回退 n=…` 与
`[375限额] 撤销分档 总=… 真正不回退=… 撤销但被348豁免(额度已回退)=…`、
`[375限额] 作废不回退 补算=…`。

## 四、24 例判据（`tests/test_m375_c9_intake_rollback.py`）

| 组 | 断言 |
|---|---|
| 撤销（5 值参数化） | 回退与否**只由两集合交集决定**：交集内 ⇒ `count=0` 且 `revoked_but_exempt=1`；交集外 ⇒ `count=1` 且 `revoked_no_rollback=1`。**不锁「哪种行为对」** —— 裁决改了集合，本件自动跟随，不会变成历史快照 |
| 撤销分档自洽 | `total == no_rollback + but_exempt`；`restore` 与 `revoked` 不合流 |
| 作废（缺口本体） | 池里已没有该条目、台账有 ⇒ `count=1`（额度不退）；`voided_ledger="ok"` |
| 去重三则 | 同 id 在池⇒不双计；同 id 多条台账⇒只算 1；both 时 `voided_dup_skipped` 有数 |
| 不虚增 | 存量无 O3 标记 ⇒ `voided_candidates=0`，且 `voided_ledger="ok"`（证明是「不计」不是「没读到」） |
| 落窗 | 窗外 3 天 ⇒ `voided_candidates=1` 但 `voided_no_rollback=0` |
| 三态 | 台账缺失 ⇒ `absent` 且 `source_ok` 仍 True（缺台账不是"数据源不可读"）；坏行 ⇒ `bad_lines` 且好行照计 |
| 限额两侧 | 作废补算越过限额 ⇒ `rate_ok=False`；正好 = 限额 ⇒ `rate_ok=True`（语义是 `<=`） |
| 基准一致性 | tmp 台账有 1 条带标记作废、**生产台账真实存在但无标记** ⇒ 必须读到 tmp 的（否则 isolation 破口） |
| 防抄第二份 | 源码里不许出现台账文件名字面量 |
| 台账字段 | AST 断言 `note_converge_voided(...)` 带 `o3_dead_code=` 与 `generated_at=` |
| 常量同源 | `CONVERGE_VOIDED_LEDGER_REL` 与 `converge_voided_ledger_path()` 同源（防漂移） |

### ★ 反向验证脚本自己也被反向验证了一次

v1 的六项**全部**报「没有 RED」，看着像「判据一条都抓不住」，实际是**采集层失灵**：

- v1 用 `pytest -q` 解析 stdout 里的 `FAILED ` 行与 `N passed` 汇总行。但 pytest 收尾
  清理 `tmp_path` 会触发 safe-delete 钩子往 stdout 打 JSON
  （`[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {...}`），把汇总行冲掉
  ⇒ 基线被判成「非全绿」、注入被判成「没抓住」。
- v2 加 `-rf` 与 rc 断言后 V6 正常，但 V1–V5 仍受同一噪声影响。
- v3 改用 `--junitxml` 按 testcase 的 `failure`/`error` 子节点取失败集，
  并把 `rc∈{2,3,4,5}`（中断/内部错/无测试）视为「没跑起来、不算证据」，才拿到真读数。

**教训：报「判据没抓住」之前，先证明「测试真的跑过了」。** 采集层写错时，
「全绿」和「全红」看起来一模一样。

## 六、裁决项（本刀不改判定，交星烛/小林）
