## 三、本刀改了什么（`call_recorder.py` 三处）

### ① 补错误面计数（`_m352b_accumulate`）

```python
_cell["failed"]     = ... + (0 if _ok else 1)          # 只给 by_channel
_cell["rate_limit"] = ... + (1 if _is_429 else 0)      # 只给 by_channel
```

`by_model` **不加** —— 限流/失败是渠道属性，混进模型桶会让两处口径打架。
429 判定走显式标记表 `_RATE_LIMIT_MARKERS`（`429` / `too many requests` /
`rate limit` / `throttl` / `限流` / `请求过于频繁`），不是「在理由串里随手找关键字」。
500 / timeout **不算**限流（限流是容量信号、失败是质量信号，两种病）。

### ② 渠道族聚合（`CHANNEL_FAMILIES` + `_m375_family_calls`）

```python
CHANNEL_FAMILIES = {
    "zhipu": ("zhipu", "zhipu-47-flash"),
    "siliconflow": ("siliconflow-qwen2-7b",),
    "modelscope": ("modelscope",),
}
```

族表是**显式全集**（渠道名来自 config targets，可枚举）。族外**同前缀**渠道仍计入
但单列到 `unknown` —— 「族表过期」必须可见，否则新渠道上线后占比会突然"变小"、
结论悄悄变 defer，而没人知道该更新族表。

### ③ 判据补全 + 三态

```python
_z_health = 1.0 - _z_failed / _z_calls        # 无样本 ⇒ None
_cond2 = (_z_health is not None and _z_health < 0.6) or _z_429 >= 2
_v1 = "undecidable" if (_tot_all <= 0 or _z_calls <= 0) else \
      ("join" if (_both_over and _cond2) else "defer")
```

千帆一侧分**三态**（不能一刀切成「有数据/没数据」）：

| 状态 | 条件 | 结论 |
|---|---|---|
| `no_calls` | 两个渠道两日一次都没出现 | `defer` —— 零调用 ⇒ 限流必然 0，这是**事实** |
| `ok` | 出现过且都有 `rate_limit` 键 | `join` if ≥2 else `defer` |
| `stale_schema` | 出现过但缺 `rate_limit` 键（旧格式） | `undecidable` —— 分不清「真 0」与「没采」 |

合成一个 `unavailable` 会让**从没配 key** 的渠道永远不可判（key 白设）。

返回体新增 `error_surface`：`zhipu_calls / zhipu_failed / zhipu_rate_limit /
zhipu_health / zhipu_members / zhipu_unknown_members / qianfan_*` —— 只有结论没有分母，
复核的人没法判「是没触发还是没算」。

## 六、改了一条 354 的既有断言（说明理由）

`test_354_d4_pool_expansion_join_when_criteria_met` 原来用
「占比 80%/85%、零失败、零限流」的 rows 断言 `join`。那等于「只要用得多就换渠道」，
把「依赖」和「依赖且不好用」混为一谈 —— **它是把判据被削一半这件事固化成了规格**。
本刀把它改成「占比高 **且** 不健康」的 rows，并新增 `test_07` 反向钉住
「占比高但健康 ⇒ 不换」。断言强度是**升**的（原来只判一个条件，现在两个都判）。
