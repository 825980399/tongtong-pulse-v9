## 二、修了什么：看门狗自己的盲区（`5f0897a4`）

`m365_beat_watchdog` 唯一的旁路条件：

```python
if self._heartbeat_in_progress:
    # 正在跑的那一拍自己会续链；看门狗不插队（否则双定时器）
    return {"action": "skip_in_progress"}
```

**这个假设在"那一拍卡死"时不成立**——而卡死正是断链的唯一成因。
看门狗与心跳就此同归于尽：一个等不到续链，一个等不到信号。

改法：给重入守卫加**时长**判据。

| 守卫已持有 | 判定 | 动作 |
|---|---|---|
| ≤ 1×interval | 正常快拍 | 静默跳过（不刷屏） |
| (1×, 3×] | 慢了但可能还在跑 | **跳过 + 60s 节流 WARNING** |
| > 3×interval | **判定卡死** | 强制复位守卫 + 续链 + ERROR 留痕（计数） |

三个取舍：
1. **3× 的由来**：与看门狗既有 `gap > 2×interval` 告警线错开一档，正常慢拍（<2×）绝不动；
2. **不删 `in_progress` 判断**：删了会双定时器并发跑心跳，`_beat_count` 竞态
   —— 不能为修一个 bug 造另一个；
3. **必须补"跳过可见性"**：跳过分支过去**完全静默**，外部只能看到"心跳不动了"，
   看不到"看门狗在跑但一直跳过"。这是 17 小时无人察觉的直接原因之一。

13 例验收（卡死强复位／正常慢拍不插队／2.9× 不误杀／3.1× 强杀／无时刻保守跳过／
计数／进入写时刻／finally 清零／只续链一次／慢持有告警／快拍安静／60s 节流）。
