# 377 刀4 · tracemalloc 常驻 ＋ heap_attribution unavailable 口径（P2）— 施工证据

> 批次：377 ｜ 票：T-377-内存观测-1 ｜ 日期：2026-10-28
> 性质：**观测面**（任务书 §五 边界：不改内存回收策略）

## 一、两处病根（376 刀5 A/B 的结论，本批动手修）

| # | 病根 | 代码位置（改前） | 后果 |
|---|---|---|---|
| 一 | `start(1) → take_snapshot() → finally: stop()` **全在同一次调用内** | `_m339_memory_probe` 采样段 | 快照 `since_start` 只覆盖探针自己那几毫秒 ⇒ **17/17 份产物 `tracemalloc_rows` 全 0 行** |
| 二 | `top20 = (_gc_types or _tm_rows)`；`heap_attribution(_tm_rows or _gc_types)` | `_payload` 组装段 | gc 的**条数**行顶掉 tracemalloc 的**尺寸**行 ⇒ 拿计数当字节算占比，`total_size_kb` 恒 `0.0`、`pct` 恒 `None`，下游再把 None 当 0 读 |

两病根叠加的效果：产物里「**没采到**」与「**真是 0**」长得一模一样（铁律276）。

## 二、改动

### 2.1 新增模块级助手（`PulseMetricsCollector.py` 类定义之前）

- `_m377_tm_ensure()` —— 按 `M339_TRACEMALLOC_MODE` 三态（`resident`/`window`/`off`）
  确保 tracemalloc 状态；`resident` 下 `start(1)` 且**不 stop**；未知取值按 `resident`
  处理并留痕（观测面不因拼错而静默退化成空采）。
- `_m377_tm_delta(snap, base_path, top_n)` —— 当前快照 vs `_tm_baseline.snap` 做
  `compare_to` 差分成**增量行**（`size_diff > 0`，按字节降序）；四态
  `ok / no_growth / no_baseline / baseline_unreadable`，**不用空列表冒充无增量**；
  每次调用都把当前快照写成新基线供下一拍比较。
- `__init__` 里 `self._m377_tm_state = _m377_tm_ensure()` —— **进程早期**就起常驻，
  失败不影响器官装配。

### 2.2 探针主体（`_m339_memory_probe`）

- 产物目录与 344补 3 域过滤**前移**到采样之前（差分基线要落在同一个可能是改道后的目录）；
  改道逻辑本身零改动。
- 采样段：`_started` 才 `start`；`basis` 二选一如实写 `since_start` / `cumulative`；
  **只有本拍临时开启且仍是 window 模式才 stop**（resident 绝不停，停了下一拍又空采）。
- 新增 `tracemalloc_rows_state`（`ok/empty/off/unavailable`）、
  `tracemalloc_delta_rows`、`tracemalloc_delta_state`、`tracemalloc_mode`。
- `top20` 改 `_tm_rows or _gc_types`（尺寸优先），并新增 **`top20_source`**
  = `tracemalloc`/`gc_types`/`none` —— 这一栏是字节还是条数，产物自己说清楚。
- `heap_attribution` 只吃 `_tm_rows`（不再喂 gc 计数行）。

### 2.3 `_m349_heap_attribution` 契约变更（**不再吐 0.0**）

```python
无带尺寸行（空 / 全计数行 / 全 0）
  ⇒ {"state": "unavailable", "reason": "no_rows" | "zero_size_rows",
     "buckets": {}, "total_size_kb": None, "rows_with_size": 0, ...}
有尺寸行
  ⇒ {"state": "ok", "buckets": {...size_kb/count/pct...}, "total_size_kb": <真值>, ...}
```

契约安全性核实：`heap_attribution` / `total_size_kb` 在生产代码与测试里
**均无消费方**（全库 grep 只命中定义处与 `PulseInnerWorld.py` 里同名但无关的局部变量），
产物是只写证据件 ⇒ 改契约不影响任何判据。

### 2.4 `config.py`

```diff
-M339_TRACEMALLOC_MODE = "window"           # "window"=仅钩子内开启后关（零常驻开销），"resident"=常驻
+M339_TRACEMALLOC_MODE = "resident"         # "resident"=常驻(默认) / "window"=钩子内开关 / "off"=关闭
```

## 三、读数（实跑一次探针，产物落 `tmp/`，不碰生产 `data/`）

```

第 1 拍  ran=True mode=tracemalloc elapsed=0.008s
```

**因果验证**：增量第一行 `+12812.7KB @ b377_d4_probe.py:41` 正是脚本里

⇒ 差分确实把「这段时间涨在哪一行」指出来了，不是又一个空壳读数。

### 首跑踩到并修掉的一个真 bug

第一版把「基线落盘」放在产物写盘之前，而 `os.makedirs(_dir)` 在**产物写盘段**里
⇒ 基线 `snap.dump()` 撞 `FileNotFoundError`，被 `silent_exc` 静默吞掉，
**连续两拍都是 `no_baseline`**。已在 `_m377_tm_delta` 落盘前自己建目录并留注释。
（这条本身就是「静默吞异常让故障与正常同形」的又一例，故写进证据。）

## 五、生效条件与残留

- **重启生效**（`PulseMetricsCollector` 在活体进程内）；
- 代价：`start(1)` 只记 1 层帧，是 tracemalloc 的最小开销档；活体常驻后
  **内存占用会略微上升**（每笔分配记 1 帧元数据）—— 这与刀2 把 G4 线提到 7000
  的方向一致，但仍需在下一份产物里对比 `heap_mb` 前后，**本刀不预称「无影响」**；
- 下一份产物（05:00 或 13:00 槽位）才看得出真实收益；`_tm_baseline.snap` 会与
  产物同目录（`data/reports/memory/`），首次落盘后第二拍才有 `delta_state=ok`；
- 残留：`buckets` 里 `ast/pulsenode/image` 在纯 Python 探针下多为 0（只归到 other），
  因为 tracemalloc 只看得到 Python 层分配 —— 属已知能力边界，不是本刀引入的。
