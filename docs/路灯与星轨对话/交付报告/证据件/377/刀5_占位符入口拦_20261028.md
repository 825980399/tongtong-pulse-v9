## 二、改动 1：素材**入口**拦（`_fuse_group`）

改前位置与判据都不对：

```python
# 改前：过滤发生在「取样循环」里，且只认一个内联字面量
for _n in quality_nodes[:10]:
    if _skip_ph and _ph_literal in _val:      # ← 只覆盖 "[器官别名]" 一类
        continue
```

三个后果：① 漏 `关联知识：。` / `[归纳升华]` / `[数据流·` 三类；
② 占位符节点**已计入** `len(quality_nodes)` ⇒ 阈值放行、关键词抽取、
「由 N 条认知融合而成」三处全被虚高；③ 素材集没变干净，产出守卫还要再兜一次。

改后（`_fuse_group` 内、**阈值判定之前**）：

```python
quality_nodes = [n for n in quality_nodes if not self._is_path_noise(...)]
_ph_dropped, quality_nodes = self._m377_drop_placeholder_nodes(prefix, quality_nodes)
if _ph_dropped and not quality_nodes:
    self._log(LogLevel.WARNING, f"融合跳过(素材全为占位符): 剔除{_ph_dropped}条，路径={prefix}")
    return False
```

配套：新增 `_m377_is_placeholder()`（判据**唯一定义**在 `PlaceholderSanitizer`，
本文件不再写第二份字面量；取不到判据时退化为单字面量并**只告警一次**，
不静默缩小判据面）；产出守卫（原 `_ph_literal in concept`）同步换判据。

## 三、改动 2/3：熔断已存在，只补「指纹看不见素材变化」这个缺口

现成机制（364 刀A4，未改）：`m364_fuse_backoff_plan(fail_count, fp, prev_fp, base)`
四档 —— `first` / `fingerprint_changed`(计数重置) / `data_unchanged_capped`(封顶 6h) /
`exponential`。

**缺口**：指纹原为 `(len(nodes), quality_count)`，`nodes` 是**分流前**的全集。
刀5-① 剔除的是 `_fuse_group` 内部的 `quality_nodes`，`nodes` 不变 ⇒
**素材实际变干净了，指纹却一字不动** ⇒ 364A4 判「指纹未变」继续封顶 6h，
本刀的效果在新代码上线后**永远看不见**。

补齐：新增 `_m377_fuse_fingerprint(nodes)` = `(非占位符节点数, 其中 trust≥40 数)`，
`_fuse_l2_to_l3` 改用它。行为：拦截一生效指纹必变 ⇒ 允许重试**一次**；
重试仍失败（指纹已稳定）⇒ 照旧封顶，不会无限重试。
日志用的 `_quality_count` 保持**全节点**口径不变（不同事实不同措辞，铁律166）。

> ★这一条是「熔断只补缺口」的实质内容，不是把已有功能重写一遍。
