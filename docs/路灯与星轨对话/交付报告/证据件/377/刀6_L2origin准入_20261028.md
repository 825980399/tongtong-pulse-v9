## 一、T0 勘误（三条，全部来自实测，不是读代码猜的）

### 勘误1：`system_internal` 不是「边角流量」，改前它是**主流**

任务书原文把它写成「自动学习映射」，读起来像少数路径。实测 `PulseLung._m40_resolve_origin`
（`organs/body/PulseLung.py:1935`）：

```python
if origin:                      # 显式 origin 优先
    return str(origin)
return ORIGIN_ALIASES.get(str(caller or ""), ORIGIN_SYSTEM_INTERNAL)
#                                               ^^^^^^^^^^^^^^^^^^^^ 缺省兜底
```

`ORIGIN_ALIASES`（`nucleus/llm/call_recorder.py:69`）只有 4 条：

| caller | 解析出 origin | 改前 L2 准入 |
|---|---|---|
| `user_dialog` | `user_query` | 放行 |
| `background_learning` | `system_internal` | **拒** |
| `evolution` | `evolution_task` | 拒 |
| `digestion` | `digestion` | 拒 |
| 任何未登记的 caller | `system_internal`（兜底） | **拒** |

**读数的意义**：改前凡是「后台学习 + 所有未登记的调用方」,在 L2 缓存白名单处被一刀切拒掉。
而这条拒绝**不进 `_stat`**（旧代码是裸 `return False`）⇒ `hits`/`misses` 恒 0，
与「压根没有请求」同形。这与 283/284 批「`lookup_l2` 生产调用面 = 0」的旧结论叠在一起，
形成了「L2 一直空转」的错觉 —— 实际是**被自己的准入闸挡在门外**。

> 本刀**不**声称「L2 命中率会立刻上升」。改后只保证「知识问答类不再被准入闸挡」，
> 命中率要看后续 live 读数（判据见第六节）。

### 勘误2：「只限知识问答类」**不能**实现成「只放 chat」

第一版按字面写成 `_M377_ORIGIN_SCENE_GATE = {"system_internal": ("chat",)}`，
单测当场全红。原因在判据轴上（`_l2_classify_scene`，`semantic_cache.py:584`）：

```python
_reason_markers = ("为什么", "如何", "分析", "因为", "所以", "逻辑", "推导",
                   "原因", "解释", "原理", "比较", "区别", "vs", "?",
                   "？", "怎么", "怎样", "论证", "结论")
if _code >= 2:   return "code"
if _reason >= 1: return "reasoning"     # ← 任一 reason 标记就进 reasoning
return "chat"                            # ← chat = 零 reason 标记
```

**知识问答本身就是提问**。任何一句真正的知识问答都会带「为什么/怎么/？/解释/原理」之一
⇒ 判 `reasoning`；要落 `chat` 必须**一个都不带**，那就只剩「陈述句」一种形态。
「只放 chat」= 把真·知识问答全拒 —— 与本刀目的正好相反。

**处置**：闸改为 `("chat", "reasoning")`，即**只拒 code**。理由：
在这条轴上真正会造成「缓存旧答案污染演化」的只有 `code` 形态（演化在改码），
`chat` 与 `reasoning` 都是自然语言问答，语义缓存本来就是要服务它们。

> 这条已写进代码注释与用例注释（`test_m377_d6_allowed_origins_contract`），防止后人"按字面修回去"。

### 勘误3：裸用 `_l2_classify_scene` 会放过**单标记**的栈回溯（探针发现的真缺口）

生产口径探针 `tmp/b377_d6_probe.py` 第一次跑，4 个形态里有 1 个不合预期：

```
"代码型/带栈": prompt = "Traceback (most recent call last):\n  File 'x.py', line 3\nValueError"
  as_system_internal: admitted=true  why=allowed_knowledge_qa      ← 不该放行
```

根因还是上面那张表的 `_code >= 2`：这段只命中 **1** 个标记（`Traceback`），
`ValueError` 不含 `Error:`（无冒号）⇒ `_code = 1` ⇒ 不判 code；又无 reason 标记 ⇒ 判 `chat` ⇒ 放行。

**这是本刀真正的漏洞**：一段纯机器报错进了语义缓存，下次同样的报错会拿到旧答案 ——
正是任务书括号里那句「避免缓存旧答案污染演化」要防的事。

**处置**：加一层**机器产物硬签名**（叠加，不是替换）：

```python
_M377_HARD_CODE_SIGNATURES = ("traceback (most recent call last)", "```")

def _m377_scene_for_gate(prompt: str) -> str:
    _p = (prompt or "").lower()
    for _sig in _M377_HARD_CODE_SIGNATURES:
        if _sig in _p:
            return "code"
    return _l2_classify_scene(prompt)        # ← 其余原样回落，一行不改
```

硬签名**只收两条**，判据是「人不会在自然语言提问里逐字写出来」：

- `traceback (most recent call last)` —— 栈回溯头，只出现在机器输出里；
- ```` ``` ```` —— 代码围栏，只出现在代码块里。

**刻意不收** `def ` / `import ` / `return ` 这类单词。反例就在测试里：

```
_PROG_QA = "Python 里 import 和 from 的区别是什么？"
  _l2_classify_scene → reasoning（只有 1 个 code 标记）  ⇒ 闸放行 ✓
```

若把 `import ` 收进硬签名，这句**真·编程知识问答**会被拒 —— 那是把勘误2 的跟头再摔一遍。
单词类仍只走原有的「≥2 个标记」计数。

**口径守恒**：`_l2_classify_scene()` 本身**一行没改** —— 188刀1 建它时写明「仅用于遥测计数，
不参与任何缓存命中/拒绝判定」，本刀只是**在旁边**加了一个准入专用口径，
遥测里的场景分桶（命中率/污染率按场景）逐字不变。

## 八、待裁决 / 遗留（交给星轨）

1. **灰度开关是隐式键**：`ENABLE_L2_ADMIT_SYSTEM_INTERNAL` 走 `getattr(config, ..., True)`，
   **没有**写进 `config.py` —— 因为 §〇 只声明了「含 1 件改 config（刀2 G4 线）」，
   本刀再落一个键会让声明面失准。要长期灰度请在 378 批正式落键并写注释。
   临时关闭方法：在 `config.py` 加一行 `ENABLE_L2_ADMIT_SYSTEM_INTERNAL = False` 即逐字回到旧政策。

2. **`_l2_classify_scene` 的 code 判据（≥2 标记）天生不适合当闸**。本刀用硬签名补了两条最要命的
   （栈回溯头 / 代码围栏），但**不是穷举**。仍可能漏的形态：
   - 只有一处 `SELECT * FROM` 的 SQL 片段（1 标记）；
   - 只有一处 `print(` 的片段（1 标记）；
   - 只有一处 `Error:` 的单行报错（1 标记）。
   这些都判 `chat` ⇒ 会放行。**建议 378 批**：把「code 判据」从"数标记个数"改成"按签名分级"
   （强签名 1 个即算 / 弱签名 ≥2），并在 `_l2_classify_scene` 之外单独维护该分级表，
   避免继续动那个"仅用于遥测"的既有函数。

3. **命中率是否真的上升，本刀不做结论**。live 判据（下一拍起看）：
   - `[semantic_cache_l2] 准入闸 admission` 这行**首次出现**，且 `admitted.allowed_knowledge_qa > 0`；
   - `admission.rejected.scene_code_not_knowledge_qa` 有值 ⇒ 说明 code 闸在生产里确实拦到了东西
     （若长期 0，则本刀的场景闸在生产上是空转，只有白名单那半边起作用 —— 那也要如实记）；
   - `stats()["hit_rate"]` 若从恒 0 变为非 0，才算「L2 空转」被解开。

4. **`_m40_resolve_origin` 的兜底是 `system_internal`**：任何未登记的新 caller 都会被打上
   `system_internal`（不是"未知"，而是"系统内部"）。这在归因上是**猜**，不是事实。
   本刀不碰它（改 origin 归因会波及 recorder 全链），但记一笔：将来新增 caller 时须显式登记
   `ORIGIN_ALIASES`，否则它的流量会被 L2 当成后台学习处理。
