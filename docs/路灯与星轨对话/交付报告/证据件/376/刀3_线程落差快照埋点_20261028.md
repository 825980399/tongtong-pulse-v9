## 一、票面要什么，实际能给什么

票面：跨夜 131 个连续采样点只报「落差 94-97、滞留快照 0 条」，**没说那几十条线程是谁起的**；
要求在 watchdog 处补 OS 线程名快照，dump `threading.enumerate()` 的 name/ident，找出没被 Python 登记的那批。

**一处必须先说清的能力边界**：CPython **不提供**原生线程的名字。
`threading.enumerate()` 只能看到「注册过」的线程，`_DummyThread` 连名字都只有占位。
所以本件**不编造名字**，给的是三样能验证的东西：

| 给什么 | 用什么答 | 性质 |
|---|---|---|
| ① Python 侧全量清单 | `python_side_threads()`（`:283`）：name/ident/daemon/dummy | 事实，可直接读 |
| ② 没被登记那批的**确切 tid** | `native_only_threads()`（`:325`）：OS tid 集合 − Python ident 集合，附 CPU 时间 | 事实 |
| ③ 新增那批出现在**哪一拍** | `build_gap_snapshot(...)["new_tids"]`（`:342`）：与上一拍 tid 差分 | 相对量，可与同时段动作对照 |

**拿不到 ≠ 0**：`_os_tids(proc)` 取不到时返回 `None`（`:309`），`native_only` 落
`state="unavailable"` / `count=None`，不是 `count=0`（铁律276）。

## 二、域自检：`ident` 与 OS tid 到底同不同源（本机实测）

怕的是「两边根本不是同一套编号」——那样 `native_only` 的数就是垃圾。
本机（Windows，Python 3.12.6）在本进程起 3 条子线程，子线程存活期间取两侧集合：

```
py_idents=[27564, 28960, 29260, 29292]
os_tids  =[26288, 27564, 28232, 28960, 29260, 29292, 29508]
子线程 ident 全在 OS tid 集合内 = True
差集 os - py = [26288, 28232, 29508]（条数 3）
差集 py - os = []（条数 0）
活体 PID=8188 OS线程=192
```

两条结论：

1. **同源**（`py - os` 为空，子线程 ident 全在 OS tid 里）⇒ `native_only` 可以当绝对数读。
2. **`native_only` 的基线本来就不为 0**：一个只有 4 条 Python 线程的裸进程已经有 **3** 条
   native-only（BLAS/运行时的原生线程）。这就是 `GAP_IDENT_DOMAIN_SLACK = 5`（`:276`）的取值依据——
   允许少量原生运行时线程存在，不把它误判成「域错位」。

活体框架进程 OS 线程 192，与 374刀9 报的落差 94-97 相互印证（192 − 95 ≈ 97 条 Python 活跃），
说明这两个读数出自同一事实、不是各算各的。

## 三、抓多少：限流三触发（131 拍不会刷屏）

`should_snapshot()`（`:371`）：

| 触发 | 条件 | 理由 |
|---|---|---|
| `first_warn` | 首次判定 warn | 第一现场最值钱 |
| `jump_+N` | 落差比上次快照再涨 **≥ 5** | 抓「新增那一拍」，正好对上 `new_tids` |
| `periodic_N` | 持续告警期间每 **12** 拍 | 5min × 12 = 1h 一次，看趋势 |

其余一律返回 `(False, "")` ⇒ `maybe_gap_snapshot` 返回 **`None`**（不是空 dict，不冒充「抓了但没内容」）。
131 个连续采样点按此最多抓 1 + 少数几次，不会把日志和内存刷爆。快照滚动有界 `MAX_GAP_SNAPSHOTS = 8`（`:270`）。
