### 刀6附 · 对账门禁两处机制缺陷（`[ci-gate-change]` `fd841d57`）

刀6 做完后门禁**仍然报**同一条违规。查下去不是刀6 没做到，而是门禁自身豁免分支走不到：

1. **缺陷1 · 豁免走不到**（铁律159）：`main()` 先 parse 一次收集 `protected`（AST 节点 id 集合），
   再调 `scan_file()`，而它内部**又 parse 一次**用第二棵树的节点去比对 ⇒ id 永不命中。
   实测同一份源码：`scan_tree(同树)` → 0 违规；`scan_file(二次解析)` → 2 违规。
   改法：`scan_file` 一律用自己那棵树重算 `protected`。
2. **缺陷2 · 入口文件从未被扫**：`PROD_FILES` 循环写的是 `fp = os.path.join(REPO_ROOT, fp)`
   ——自引用，`fp` 实际是上面 `os.walk` 泄漏的变量 ⇒ **config.py / main.py 从来没被扫过**，
   且在「没走到 walk」的场景直接 `UnboundLocalError`。
3. **缺陷3 · 修好缺陷2 后立刻暴露的误判**：`main.py::from somatics.sensor import Sensor`
   被判「未声明第三方」——`somatics/` 是仓库内代码目录，只是缺 `__init__.py`（命名空间包）。
   改法：根目录下有 `.py` 且不属 data/logs/tmp/docs 等非代码目录的，一律算项目内顶层。

验证：门禁 `exit 0`（PASS）＋ `--selftest` 通过；单测 8 → **12 passed**（新增 3 条各钉一处缺陷）；

### 刀7 · `_handle_pulse_safe` 并发契约孪生（`T-372-b14测试孪生-1`，P3）

`tests/test_m372_b14_organ_concurrency_twin.py`（3 例，产品代码零 diff）：

① 10 线程 `Barrier` 同起跑 ⇒ 零逃逸异常、10 个结果全非 None、状态 RUNNING、计数 0；
② 3 error + 2 normal（分两波，各波内 Barrier 同起跑）⇒ 熔断、错误计数**精确等于 3**（无漏记）、

口径：一律 `OrganStatus` 枚举比较，**不用字符串 `"fused"`**（372刀14 证据件 §四点名的坑）。

**前提勘误（372刀14 测试同步）**：该件 test_02 原断言「不许偷建孪生」、test_01 原断言
「tests 面零覆盖」，均为**当时**前提、已被本刀取代 ⇒ test_01 改为「排除本文件+孪生后不得有
第三处覆盖」，test_02 保留产品面零 diff 断言、把「不许建」改为「孪生在位」。强度不降。
**反向验证**：rev1（计数改成每次重置为 1）⇒ test_02 红；rev2（去掉熔断期拒收）⇒ test_02 红。
