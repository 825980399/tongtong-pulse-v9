## 六、能力边界（先写边界，再写结论 —— 铁律196）

1. **预检只查 `def` 存在性**：查不出「方法还在但内容已被改」（签名漂移 / 语义漂移）。这类漂移会照常进入生成，产物仍可能被 `check_method_contract` 拒 —— 但那是**事后**拒，不省算力。
2. **模板档覆盖极窄**：仅 `silent_exception`，且要求「已 import `silent_exc` + 单 `case pass`」。真实池 400 条里 **0 条**符合 ⇒ 目前是**闲置产能**。
3. **免费渠道会 429/500**：实测 `zhipu-47-flash` 连续 3 次调用前两次 `429`、一次 `500`（免费档 `max_concurrent=1`）。当前策略是**换渠道**，没有指数退避；若三条可用渠道同时挂，会落收费 `deepseek`（任务书允许的"收费兜底"）。
4. **两个新免费渠道当前不可用**：`DASHSCOPE_API_KEY` / `SILICONFLOW_API_KEY` **未配**环境变量（`config` 启动即告警"该渠道将被自动跳过"）。所以转移链实测只有 `[zhipu-47-flash, zhipu, deepseek]` 三条 —— 涉及百炼/硅基的路由**未实测**，只能静态核对。
5. **`glm-4.7-flash` 是推理模型**：实测 `max_tokens=8` 时 `completion_tokens` 全落在 `reasoning_tokens` 上，`content` 为空、`finish_reason=length`。生成器若给小 `max_tokens`，产物会是空串且**不报错**。调用侧须给足预算（生产用 2048，可用）。
6. **刀1 的 40 条里 o3 那条不经生成器**：`o3_dead_code=True` 走 `verify_ast_delete`（静态三问），所以"12 在位"里不含它。
