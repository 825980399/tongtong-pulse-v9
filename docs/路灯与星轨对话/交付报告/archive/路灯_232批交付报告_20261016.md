## 二、刀1 · 关键偏差（T0 核实，未执行字面指令）

### 2.1 任务书前提与现码不符（已 git blame 钉死）
任务书 刀1.1 称 `:1505-1506` "直接 `record_remediation_attempt/success` 进 metric、**完全旁路 indexer**"。

但实测 `organs/brain/PulseCortex.py` 当前代码（git blame `ae810f10`，**170批 C2 已加**）：
```python
# 170批 C2 刀1（RC-1）：转肺补救成功回执（原链路只加分母、无分子）
_rec_succ(1)                                   # ← 直接 metric 计数（保留）
_idx.record_remediation_success(                # ← 170批起已调用 indexer
    question=ctx.get("content", ""),
    correct_answer="",                           # ← 空答案
    rule_candidate="lung_remediation:delegated")
```
**结论：当前 :1505 已调用 `_idx.record_remediation_success`，"完全旁路 indexer" 不成立。**

### 2.2 distilled=0 真因＝索引器空答案早返回（非缺 _idx 调用）
索引器 `nucleus/reasoning/ReasoningExperienceIndexer.py:300-303`：
```python
_q = str(question or "").strip()
_a = str(correct_answer or "").strip()
if not _q or not _a:
    return                                       # ← 空答案早返回：remediation_count 不增、distilled 不埋点
```
而 Cortex 肺委派路径 `correct_answer=""` → 触发早返回 → **distilled 死火**；但 `_rec_succ(1)`（LLMDependencyMetrics 度量）仍直调计数。所以"distilled=0"观察为真，机制是"调了 indexer 却因空答案早返回"，与任务书所述机制不同。

### 2.3 字面指令（"移除直调度量、改为经 `_idx`"）会破坏补救率度量
- 索引器 `record_remediation_success` **不 bump** `record_remediation_attempt`／`record_remediation_success`（度量），仅埋 `record_remediation_distilled`（见 :318-320）。
- 若按字面移除 `:1505` 的 `_rec_att(1)`／`_rec_succ(1)`，肺委派路径的成功将**不再进入补救率度量** → `remediation_distill_rate` 分母（success）断流 → 补救率指标失真（回归）。
- 且即便移除，空答案早返回依旧 → distilled 仍 0，**仍修不了 distilled**。

**故刀1 字面改法在当前代码下既破坏度量、又不达目标，本批未执行。**

### 2.4 哨兵（刀2）已反证并定位该旁路
刀2 哨兵实测（§三）证明：连续两窗空答案早返回 → distilled 滞后 success → 告警触发。即**该旁路真实存在且已被检测**，与烛微231"distilled=0 在肺委派路径"观察一致，但根因表述（"缺 _idx 调用"）需更正为"空答案早返回"。

### 2.5 刀1 待裁决（见§七）
"delegated 补救是否应产 distilled" 属设计口径：若应产，需改索引器早返回语义或 :1510 传真实答案（非字面移除度量）；若 delegated 本就不蒸馏，则 distilled=0 属预期、哨兵为预期告警。需星轨/用户定夺，本批不单方改动。
