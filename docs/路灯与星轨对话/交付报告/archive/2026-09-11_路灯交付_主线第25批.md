## 二、T2 doubao 渠道 400 错误修复（P2-162）【P1】✅ 完全闭环（含真实请求实证）

### 2.1 根因（已用真实请求对照实验证实）

**`nucleus/llm/openai_compatible_adapter.py:38-42`**：

```python
if "enable_thinking" in kwargs:          # ★只要键存在就无条件写入两个字段
    req["thinking"] = {"type": "enabled" if _think else "disabled"}
    req["reasoning_effort"] = "high" if _think else "low"
```

而 `PulseLung._call_channel(:721)` **无条件**把 `enable_thinking=<bool>` 透传给适配器 → **每个渠道的请求体都带 `thinking` + `reasoning_effort`**。

火山方舟 Ark v3 对这两个字段做**组合校验**，`disabled + low` 是**非法组合**：

```
[A-带thinking] HTTP 400 {"error":{"code":"InvalidParameter",
    "message":"Invalid combination of reasoning_effort and thinking type: low + disabled"}}
[B-裁剪后]     HTTP 200 {"choices":[...{"content":"收到"...}]}
```

→ zhipu / deepseek 不校验该组合（故此前只报 doubao 400），**完全解释了「仅 doubao 连续 400」的现象**。

### 2.2 修复

1. **渠道字段白名单**（`config.CHANNEL_REQUEST_FIELD_POLICY` + `ENABLE_CHANNEL_FIELD_POLICY`）：
   `PulseLung._apply_channel_field_policy()` 按渠道裁剪 `thinking`/`reasoning_effort`；doubao 另设 `max_tokens` 上限 4096；
2. **400 原因可见化**：`_call_channel` 新增 `except urllib.error.HTTPError`，把上游返回的 `code + message` 以 **WARNING** 打出（此前被整段吞掉，运维只能看到「HTTP Error 400: Bad Request」）；
3. **脱敏 HTTP dump**（`DEBUG_CHANNEL_HTTP_DUMP`，默认关，环境变量 `PULSE_HTTP_DUMP=1`）：打印完整请求/响应；`Authorization` 只留前缀（`Bearer ark-1****`）。

### 2.3 验证（**走生产代码路径的真实请求**）

| 条件 | 结果 |
|---|---|
| 开关开（默认，修复生效） | `PulseLung._call_channel(doubao, …)` → **返回「收到」（HTTP 200）** |
| 开关关（复现原缺陷） | 同一调用 → **返回 None（HTTP 400 被拒）** |

→ 既证明**修复有效**，也证明**关闭时行为与改造前一致（零回归）**。
