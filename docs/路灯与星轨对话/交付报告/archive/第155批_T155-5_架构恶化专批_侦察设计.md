## 三、P2-64 · 并发模型混合（先出设计再动码）

**实测（ledger D043）**：`threading.Lock` 命中 207 处 / 128 文件；`Thread` 70/42；`Queue` 16/10；`asyncio.Lock=0`；**三套 scheduler（parallel / hybrid / structured）并存**。债务："按器官收敛为单一调度原语，淘汰 asyncio 混用"。

**设计**：
1. 选定**唯一调度原语**（推荐 `parallel` scheduler 为基准，因其覆盖最广），将 `hybrid`/`structured` 标记为 `@deprecated`，经 N 批逐步迁移调用方。
2. 逐器官收敛：每个器官内部统一用一种 Lock/Executor，消除 threading+asyncio 混用（当前 asyncio.Lock=0 说明 asyncio 尚未实际混用，风险低于预期，但仍需统一原语以防未来踩坑）。
3. 引入 `concurrency_contract.md` 约束文档 + `ruff`/AST 门禁（禁止新模块引入第二套 scheduler）。
4. **执行前置**：先产出调度原语选型裁决（星轨拍板 parallel/hybrid/structured 之一）→ 再动码。

**本批状态**：仅设计 + 选型待裁决，**未动码**。
