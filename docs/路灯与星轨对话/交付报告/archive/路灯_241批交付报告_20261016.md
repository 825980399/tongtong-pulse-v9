## 一、任务定位

241批＝**C案一刀三得**（`record_remediation_returned` 专用方法），收口 237批遗留的 B3 双记问题：

- **双记根因（237批观测备注已点明，241 收口）**：170批分发侧 `_receipt_ledger_record` 后调 `record_remediation_success(question, "", "lung_remediation:delegated")`（空答案→delegated 分支，不 +1 `_remediation_count`，但 `_rec_succ(1)` 记一次 success 分母）；237批回执钩 `_maybe_append_self_state` 命中账本再调 `record_remediation_success(question, answer, "lung_remediation:returned")`（**非空答案→另 +1 `_remediation_count` 并产蒸馏**）。同一条肺补救的 `record_remediation_success` 被调两次，其中回执钩的非空调用把 `_remediation_count` 重复 +1，即"双记"。
- **C案解法**：回执钩改调**专用方法** `record_remediation_returned`，不再 +1 `_remediation_count`，但仍产蒸馏，并新增 `remediation.returned` 兑现率直算键；另在 sweep TTL 过期处新增 `remediation.missed` 失约率直算键——一刀三得（灭双记 / 兑现率 / 失约率）。

## 二、四刀落地明细

### 刀1 · 专用方法 `record_remediation_returned`（ReasoningExperienceIndexer.py）
- 新增 `record_remediation_returned(question, answer, rule_candidate=None, confidence=0.8)`，紧邻 `record_remediation_success` 之后（:375）。
- 与 `record_remediation_success` 的差异（均按任务书"不再+1 _remediation_count，但产蒸馏"）：
  - **不 bump `_remediation_count`**（灭双记核心）；
  - **不 bump `remediation.success`**（避免单轮补救记两次）；
  - **额外 bump `remediation.returned`**（兑现率 = returned / attempt 直算）；
  - **仍产蒸馏**：`record_remediation_distilled(1)` + `store_l2` + L2 节点写入（与主成功路径沉淀一致）；
  - **不触碰旁路哨兵**（哨兵只统计分发侧 成功→蒸馏 关系，避免缺口被 returned 的蒸馏扰乱）。

- `record_remediation_distilled(1)` 落点：把"肺补救真实答案的蒸馏计数"从原回执钩的 success 路径**平移**到 returned 路径——净计数仍为每轮 1 次，未改变全局 `distilled` 口径。
