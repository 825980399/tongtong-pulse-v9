### 根因（三处叠加，全部实测确认）

| # | 缺陷 | 证据 |
|---|---|---|
| 1 | **时序倒置**：`connect()` 依赖 `ENABLE_INFLUXDB_TIMESERIES=True`，而脚本在 `_build_real_writer()` **之后**才打开开关 | 源码 L113-115 vs L128 |
| 2 | **单例只构造不连接**：`get_influxdb_store()` 仅 `InfluxDBStore()`，`_available` 恒 False → `is_available()` 必为 False | `influxdb_store.py:343-348` |
| 3 | **真实 store 无 `counts` 属性**：脚本按 `mock.counts[...]` 断言 → 即便连接成功也会 `AttributeError` | 真实 store 仅提供 `get_stats()` |

## 三、已实施的修复

1. **`_build_real_writer()`**（`tools/verify_write_only_e2e.py`）
   - 先打开 `ENABLE_INFLUXDB_TIMESERIES` / `ENABLE_INFLUXDB_WRITE_ONLY` → 再取单例 → **显式 `connect()`** → 再判可用性。
   - 新增 `RealStoreAdapter`：转发**全部写入到真实 store**（真实落库），同时累计 `counts` 供断言使用。
2. **`InfluxDBStore.connect()` 凭证校验**（`nucleus/timeseries_store/influxdb_store.py`）
   - `InfluxDBClient` 的构造**不验证 token** → 凭证失效时 `connect()` 仍返回 `True`，
     随后 `write()` 静默失败（返回 True 而库里查不到数据），**全程无任何报错**。
   - 修复：`connect()` 成功后执行一次轻量凭证校验（`buckets()` 查询），失败则
     `_available=False`、记 WARNING 并返回 `False`。
   - 灰度开关 `INFLUXDB_VERIFY_CREDENTIAL_ON_CONNECT`（默认 True，置 False 即回退旧行为）。

## 四、真实验证结果（修复后）

```
[influxdb_store] [WARNING] [T2] InfluxDB 凭证校验失败（token 无效/权限不足）:
  ApiException: (401) Unauthorized  —— unauthorized access
```

| 验证项 | 结果 |
|---|---|
| `connect()` 建立连接 | ❌ 被凭证校验拦下（此前是**假 True**） |
| 数据写入 InfluxDB | ❌ 不可达（凭证无效） |
| **用查询验证数据落库** | ❌ 原生 Flux 直查同样 401 |
| 写入失败时框架不崩溃 | ✅ `node_activated/node_modified/...` 在不写态返回 `False`，**不抛异常** |
| 开关关闭零副作用 | ✅ 8 项 PASS（mock 路径） |

**关键取证**：修复前曾观测到 `connect()=True`、4 个写入方法返回 `True`、`flush()=True` 且缓冲区清空，
但 `query_count=0` / `query_latest=[]`；改用原生 `InfluxDBClient` 直查才暴露真因 —— **401 Unauthorized**。
即：**凭证失效时，整套写入链路「看起来完全正常」，实则一条数据都没写入**。
