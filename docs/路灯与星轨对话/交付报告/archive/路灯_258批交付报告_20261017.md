## 二、各刀落点明细

### 刀1 · 孤儿心跳线（P0）
- 新增模块常量 `_ORPHAN_HEARTBEAT_EVERY_SEC = 3600`、`_LAST_ORPHAN_HEARTBEAT_TS = 0.0`（沿用 `_PAIR_FLUSH_EVERY_SEC` 先例）。
- 在 `flush_to_file` 的**孤儿写盘之后**（`safe_write_json(orphan_path, ...)` 之后）插入心跳块：此时 `new_orphans` 已算、`events_snapshot` 在手，五个数全齐。
- 节流：`_now_hb - _LAST_ORPHAN_HEARTBEAT_TS >= 3600` 才打一行 → 2s 闸下一夜≤24 行，不造噪音海。
- 五行内容：`[孤儿判定] 基数=N 未回填=M 平反=X 通配=W 孤儿=K`
  - N = 环内 emit 条数（`events_snapshot` 中 `type=="emit"`）
  - M = `matched_organs` 为空的 emit 数（判定前原始嫌疑面）
  - X = 被订阅表平反的条数（逐 emit 调 `_subscription_provider` 判 `is True`，提供器内部已防御，直接调）
  - W = `bus.subscription_count("**")`（**必须带**：没有 W 心跳线自身也无法区分「健康」与「失明」——正是257断盲的根）
  - K = `len(new_orphans)`
- 首选增强：当 `K == 0 且 W > 0` 改打 WARN「判定面可能被万能监听器短路」——把257的「失明」结论变成可自证的一行哨。

### 刀2 · SOP v1.2五条（P1）
- **刀2.1/2.5 硬闸 max_apply=1**：新增常量 `_HARD_CAP = 1`；`auto_apply_pending` 入口 `if max_apply > _HARD_CAP: print("[WARNING] ... 批量指令被SOP硬闸截断，本轮仅应用1条") ; max_apply = min(max_apply, _HARD_CAP)`。把「纸面纪律」升为代码不变量（252事故执行面即 `max_apply` 被放大）。
- **刀2.2 到期真验证**：`apply_patch` 应用后记 `patch["effect_verify_due_at"] = time.time() + _DEFAULT_OBSERVE_WINDOW_S(=60)`；`verify_applied_patches_effect`（EvolutionLoop 心跳调用方）的筛选条件新增 `effect_verify_due_at` 到期触发，并在每补丁验证后写回 `patch["recommended"]`（补足原 `effect_verify_scheduled` 标志「扳机接钩未响」的第五形态）。
- **刀2.3 一补丁一记录七字段**：沿用既有 `_applied_patches` 滚动面补键，新增 `observe_window_s` / `verify` / `symptom` 三键（不新建第二账本）。`ts/patch_id/applied` 已由 `created_at`/`id`/`status+applied` 承载；**`risk` 维度在 ParamPatchManager 无对应概念**（风险等级属补丁书队列，非本管理器），列为待星轨裁定项。
- **刀2.4 回滚原子性三破口**：
  ① `rollback_patch` 全体持 `self._lock`（消除与并发 apply 的竞态）；
  ② 同参数补丁互斥——应用后将同 `param` 的旧生效补丁置 `status="superseded"`（防非栈式回滚写中间态）；
  ③ 缺键降级申报——若补丁缺 `old_override_value` 键（来自 `_load_history` 复原），回滚退化为弹回默认并打 WARN。

### 刀3 · 望远镜第〇检查（P1）
- **② 键名对齐**：`compute_lfi` 的 activity 取值先查 `_name`(organ_name) 再查 `_cls`(class_name)；`fetch_runtime_activity` 新增 `class_name/organ_name → organ_name` 映射，逐键对齐 `organ_activity`（其多以 `source_organ`/`class_name` 为键，而 LFI 节点以 `organ_name` 为键）——使运行态活跃度能正确流入，`approx` 字段具备翻「运行态(pulse计数)」的条件。
- **① 根因**：离线取证时 `fetch_runtime_activity` 返回 `{}` 的根因＝**无活体 BloodVessel 实例（框架未运行）**；键名对齐解决的是「有数据但键不匹配」那一因。重启后任取数即可定论。
- **③ delta 作废**：`_evaluate_checks` 新增 `delta_void = not approx_running` 与 `delta_void_reason`；当 `approx` 未翻运行态时，所有 delta 读数按作废处理（不再被误读为「望远镜」）。

### 刀4 · int(v)截断潜伏刀＋span文案（P2）
- `payload_raw = compute_lfi(runtime_activity={k: float(v) ...})`（原 `int(v)` 会把非峰值器官 activity 压成 0 的潜伏刀，当前被 `activity_override` 掩盖）；两套统一 float。
- 在 `actual_overall = _overall_score(payload_raw, activity_override=raw, ...)` 处加注释「activity_override 是唯一的真值通道，勿删」。
- span「不含本轮」文案：`_evaluate_checks` 返回新增 `span_excludes_current_round: True` 与 `span_note: "跨度不含本轮（_evaluate_checks 在 _append_curve 之前调用，仅统计历史样本间隔）"`，消除「0.9998天 vs 2.0天」的反复误读。
