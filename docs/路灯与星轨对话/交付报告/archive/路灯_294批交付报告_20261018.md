## 三、四刀改动明细

### 刀1 · 装掌握率分母（2 文件）
- **`nucleus/self_awareness/daily_reader.py`**：新增 `append_mastery_section(report_path, logger)`。
  - 分母 `total` = `get_self_inspector().get_organ_code_structure()` 各器官 `method_count` 求和（稳定静态口径，任务书「现成件」明确指向）。
  - 分子 `understood` = 信息场 `get_info_field().get_current("code_learner.stats")` 尽力取，取不到记 0 并标注 `source=unavailable`。
  - 日报追加【掌握率】节 + INFO 日志。
- **`nucleus/self_awareness/DailyScheduler.py`**：`run_once` 日报落盘后挂 `append_mastery_section`（复用电既有 `not self._is_test_env() and _rp` 守卫，失败只 warning）。

### 刀2 · 同类快照版本收敛（1 文件）
- **`organs/brain/PulseCodeLearner.py::_build_data_flow_graph`**：写入新数据流节点前，`node_pool.query(space_path_prefix=f"/自我理解/代码/{organ}")` 捞出旧节点，仅命中 `value` 含「数据流」的节点标记 `state="dormant"`（superseded），不误伤同路径「[自我理解·」方法理解节点。

### 刀3 · 空报告不再计产出 + EventTap 查明（1 文件改动 + 查明结论）
- **`nucleus/reporting/publishers.py`**：新增 `_count_usable_dims(summary)`，`publish_self_cognition` 在「可用评分维度 <2」时不发布（返回 None + INFO 日志），使空报告不再计入产出、消费方不再读到空报告。
- **EventTap 接线查明（根因，未改代码）**：`main.py:1103-1140` 生产装配注册了 production_consumption / fake_loops / log_analyzer / code_review / call_graph / knowledge_quality / evolution_health 七个分析器，**唯独缺 `event_tap → runtime_events` 维度的注册**。`integrate_event_tap` 只在 `tools/run_self_awareness_analysis.py:109`（手动脚本）注册。⇒ 生产框架 `runtime_events` 维度恒空，报告必然显示「EventTap未启用或统计为空」。**EventTap 本身已正确启动（`get_event_tap` 订阅 `"**"`，两开关 ENABLE_EVENT_BUS_TAP/ENABLE_EVENT_TAP_INTEGRATION 均 True），根因是引擎侧分析器接线缺失**，非「统计对象/时序」问题。

### 刀4 · 统一验证真值源（1 文件）
- **`nucleus/self_awareness/quality_score_v2.py::_patch_true_fix_rate`**：由「只读主动复现口径（patch_active_reprobe.true_fix_rate）」改为「N-9 口径（maturity_ledger.patch_rates，与 patch_quality_evaluator 同源）＋ 主动复现口径并存取低值」。N-9 口径即 fixed/judgeable（unverifiable 不计分子也不计分母），消除「83.34 vs 22.6%」的两口径错位，自评保守。
