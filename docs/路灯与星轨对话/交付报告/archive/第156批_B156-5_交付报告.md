## 二、任务书偏差清单（须上报星轨）

双轨核验（D1 裁定）后对任务书的如实校正：

1. **★生产者"接"非"改名"**：任务书称 `assess_load_level` "缺失"、并给"改名定频去抖"选项。实测该函数**存在且逻辑完整**，断链根因是 **`set_level` 生产零调用点** → 等级恒 `LOW` → 永不降频。裁定为**接生产者**（`_sync_adaptive_level` 下发），"改名定频去抖"选项经双轨核验为误判，**改由 157 批仅验收**（本批不动函数名，规避大面改名风险）。
2. **★阈值锚定 L3 物理上限**：原阈值 `500/1500/3000` 远超 L3 软上限 `100` / 硬上限 `300`，队列真实量级 `max 72` 永不触发。重标为 `100（MEDIUM）/ 200（HIGH）/ 300（CRITICAL）`，CRITICAL 锚硬上限 300（实测 300 即判 CRITICAL，>300 仍 CRITICAL）。
3. **★跳过可观测**：原 `should_execute` 两跳过分支（CRITICAL 暂停 / MEDIUM·HIGH 节流）**无任何日志**，既刷屏又不可观测。加 `_log_skip`：等级变化记 INFO、暂停记 WARNING、节流记 DEBUG（每操作 300s 节流）、LOW 等级早返回不记录。
4. **★告警值过期标记（X-3 根治）**：X-3 历史问题 `_last_queue_depth` 陈旧锁存 `14890` 逐字相同反复告警 8 次。票④加 `expires_at`（TTL 600s）+ 同值重复抑制（间隔 <600s 抑制）+ 陈旧判定（>120s 视为陈旧）；票④补进一步将陈旧判定改为**哨兵 fail-open**（详见 §三.4）。

## 三、四票接线点声明（精确落点）

全部改动位于 `nucleus/runtime_metrics.py`（票② 阈值常量另落 `config.py`）：

### 票① 生产者接线（断链根因修复）
- 新增 `_sync_adaptive_level(self)`：读 `get_system_load()` + `assess_load_level(queue_depth=self.get_queue_depth(), cpu_percent=..., memory_percent=..., snapshot_saving=False)` → `get_adaptive_controller().set_level(_lv)`；异常走 `silent_exc`。
- 在 `_maybe_sample_history` 末尾（`self._history.append` 后、`_check_alerts` 前）调用 `self._sync_adaptive_level()`，使每次采样真正驱动等级变化。

### 票② 阈值按 L3 物理上限重标
- `assess_load_level` 内 `_adaptive_threshold("QUEUE_DEPTH_THRESHOLD_MEDIUM", 500/1500/3000)` 改默认回退值为 `100/200/300`。
- `config.py`（行 4767–4770）：`QUEUE_DEPTH_THRESHOLD_MEDIUM/HIGH/CRITICAL` 由 `500/1500/3000` 改为 `100/200/300`（带 B156-5 票② 注释）。
- CPU 维度阈值（`50/70/85`）**不在本批重标范围**，保持语义（测试 `test_cpu_dimension_unchanged` 守护）。

### 票③ should_execute 跳过可观测
- `AdaptiveFrequencyController.__init__` 加 `self._level_since = 0.0`、`self._skip_log_at = {}`。
- `set_level` 等级变化时记 INFO（logging 异常走 `silent_exc`）。
- `should_execute` 两跳过分支接入 `_log_skip(name, paused)`：CRITICAL→WARNING、MEDIUM/HIGH→DEBUG（每操作 300s 节流），LOW 等级早返回不记录。
- 新增 `_log_skip(self, name, paused)`（logging 异常走 `silent_exc`）。

### 票④ 告警值带过期标记
- `__init__` 加 `self._last_queue_depth_at = 0.0`、`self._queue_alert_last_depth = None`、`self._queue_alert_last_at = 0.0`；采样时 `_last_queue_depth_at = time.time()`。
- 模块级常量：`_QUEUE_DEPTH_STALE_TTL=120.0`、`_QUEUE_DEPTH_STALE_TOL=0`、`_QUEUE_DEPTH_ALERT_REPEAT_TTL=600.0`、`_QUEUE_DEPTH_ALERT_TTL=600.0`。
- `_check_alerts` 队列深度告警分支重构：`_age = _now - self._last_queue_depth_at`；`_stale = self._last_queue_depth_at > 0.0 and _age > _QUEUE_DEPTH_STALE_TTL`（哨兵 fail-open，见补）；`_repeat` 同值且间隔 <600s 抑制；写入 `expires_at: _now + _QUEUE_DEPTH_ALERT_TTL`。

### 票④补 哨兵 fail-open 修正（根治 test_m78 回归）
- 初版 `_stale = _age > _QUEUE_DEPTH_STALE_TTL`：当 `_last_queue_depth_at` 为哨兵 `0.0` 时 `_age = now - 0 = 巨大`，**误判陈旧**吞掉真实越阈告警（`test_m78_queue_depth_trend` 回归 FAILED）。
- 修正为 `_stale = self._last_queue_depth_at > 0.0 and _age > _QUEUE_DEPTH_STALE_TTL`：哨兵 `0.0`（无有效采样时刻）不按陈旧抑制，**fail-open** 避免误吞真实告警。异常路径仍走 `silent_exc`，cw2 门禁不受影响。
