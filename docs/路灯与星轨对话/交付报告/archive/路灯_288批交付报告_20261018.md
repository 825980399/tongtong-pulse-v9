### 刀4 · 行动面有数（补 motor.execute）❌（根因已查明）

`PulseInnerWorld` 的"自主"路径是 `_trigger_autonomous_derivation`（因果/归纳/类比推导，
`:11349`），**不执行任何代码**——grep `motor.execute/MotorEvent` 在 PulseInnerWorld 零命中。
`motor.execute` 的既有发布端（PulseCortex/PulseEars/chat_service/PulseHands）**全部在用户
主动发代码块/文件时触发**，运行期用户未发代码故 0 触发（286批刀7结论）。因此"内在世界
自主执行路径补 motor.execute"**无落点**：内在世界没有自主写代码的路径，强行补 = 造死代码。
**判定：设计待排**（若要让"行动面有数"，须先有内在世界自主生成可执行代码的能力，属新能力
而非补点）。

### 刀5 · growth.need_detected 真发一次 ❌（根因已查明）

发射点已就位且**有 no-op 接收方**（第200批 `nucleus/events/orphan_receivers.py` 已登记），
0 命中根因是**发射条件过窄、运行期永不满足**：

- `PulseLiver:3362/3387/3414`：仅当某本能 `len(related_l3) <= 1` 且存在子概念时发射；
- `PulseInterestModel:618`：仅当存在 `stale_dims`（某兴趣维度 `last_boost` 超期/为空）时发射。

运行期各本能 L3 支撑均 >1、兴趣维度均近期已 boost → 两条路都不触发。
**修法**（诚实、不补 no-op）：在每日低频钩子（DailyScheduler）加一条"当日零 growth.need_detected
则发射一次"的兜底（有接收方则真送达，无接收方如实进孤儿清单）。此项与刀3同属运行期核心
链路改造，**降级到下批**，根因与修法点已写明。

### 刀7 · semantic_cache.jsonl 行数骤减成因查明 ✅

成因 = **`flush()` 全量重写 + hash 去重 + TTL 7天清理**（非 bug，非 rotate 外部操作）：

- `semantic_cache.py:269 flush()` 按 `_entries`（dict，天然按 hash 去重）**全量重写** jsonl；

- 守护线程在 `_handle` 后 / `close()` 时触发 flush → 491 行（含重复追加与过期行）重写为
  277 行（去重后 + 剔过期）。

**结论**：L1 缓存**非全史**（append 又经去重重写 + TTL 清理），行数下降是正常维护行为，
`容量上限 10000` 与 `TTL 7天` 均未触发（277 < 10000 且样本为新近）。按任务书要求在文档中
声明"L1缓存非全史"（见下）。
