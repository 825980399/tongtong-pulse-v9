## 一、现象与根因

- **现象（N-9 假通过=2）**：`data/patches/patch_history.json` 中两条 `organs/body/PulseLiver.py` 补丁被 `patch_quality_evaluator` 判为 `fake_pass`，但二者**补丁均已逐字落地**（第42批 T4 已由 `tests/test_liver_silent_fix_m42.py` 用源码切片逐字比对固化，源码回退即失败）。
- **根因：判据粒度错配**。`evaluate_patch` 只认 `baseline_errors` / `post_apply_errors`，这是**文件级**错误计数——同一文件里其它方法的错误也会计入，与目标方法无关。于是：

| 补丁 id | 方法 | 文件级计数 | `real_effectiveness` | 原标签 |
|---|---|---|---|---|
| `patch_1788590332_d156` | `_build_knowledge_association_graph` | baseline=4 / post=4 | **0.0** | `fake_pass` |
| `patch_1788765051_7ff3` | `_save_fuse_cooldown` | baseline=0 / post=4 | **-1.0** | `fake_pass` |

- **事实订正**：此前记录中 `_save_fuse_cooldown` 一度被记为 `unverifiable`。实测复核其 `real_effectiveness(0, 4)` 按模块既有规则「baseline==0 且 post>0 → -1.0」得 **-1.0**，故原标签实际为 `fake_pass`（其补丁侧自记的 claimed effectiveness 为 0.5）。**两条原标签都是 `fake_pass`——这正是「假通过=2」的所指**。
- **真凭实据**：两条记录的**方法级复现探针**均为 `reprobe_verdict = "true_pass"`，`reprobe_baseline_hits=1 → reprobe_after_hits=0`（修复前 1 处裸 pass 无留痕 → 修复后 0 处），粒度与补丁目标（单个方法）一致，与第42批 T4 逐字比对结论吻合。

## 二、修复内容

### 1. 补补丁历史清单（`patch_quality_evaluator.py:30` 口径）

模块 docstring 新增「★N-9「假通过=2」复核结论」表，逐条列明：补丁 id / 方法、文件级计数、原标签、方法级复现探针证据、复核结论（真通过·摘除），并注明由 `tests/test_liver_silent_fix_m42.py` 固化。

> 附：M3 口径交叉核对（`tmp/audit_evidence_157/master.json` 的 `M3_entry_funcs_zero` 21 条 / `M3_entry_methods_zero` 40 条）**均不含**这两个方法——即二者有真实调用点（`PulseLiver.py:2158`、`:2708`），**假通过成因不是"未被调用"**，而是文件级计数口径，与零引用清单无关。

### 2. 摘除 / 重验

- 新增 `reprobe_effectiveness(p)`：用方法级复现探针重算效果（`reprobe_verdict == "true_pass"` 且基线命中 > 0 且修复后归零），证据不足返回 `None`。
- 新增 `N9_REPROBE_EXEMPT` 显式复核清单（2 条 `(file, method)`）+ `_n9_exempt()` 判定。
- `evaluate_patch`：清单内条目在复现证据成立时以复现探针作为效果判据，并**跳过 `fake_pass` / `unverifiable` 判定**，落入正常分数分级；返回字典增列 `reprobe_effectiveness` / `reprobe_used`。
- `__all__` 导出 `REPROBE_TRUE_PASS`、`N9_REPROBE_EXEMPT`、`reprobe_effectiveness`。

### 3. ★关键设计决策：显式清单，而非通用启用

> 这是本刀最值得留痕的一次自查纠偏。

首版实现为「所有记录通用启用复现判据」。实测发现：`patch_history` 共 **70** 条记录带 `reprobe_verdict=true_pass`，通用启用会连带把其中 **68 条 `unverifiable` 一并改写为 `good`**——这已**超出本批授权**（路灯口径为「假通过=**2**」），且这些 `unverifiable` 是「文件级 baseline=0 无参照物」这一**已知判据缺陷**的下游后果（模块 docstring 明载本批 62/67 条属此类），其定性应由专门批次统一处理，不应在本刀擅自扩大。

因此收窄为**显式清单**，只收 N-9 指定的 2 条，保证改动面精确可审计、非目标记录零变化。该决策与其理由已写入代码注释与模块 docstring。
