# 157 批 P2-4｜差集日志误报解释模板（C-7(b) 装配差集）

> 来源：烛微审计整改 P2-4（20261002 星轨代小林传达）。
> 用途：活体窗内 C-7(b) 装配差集日志出现时，附此模板解释"多 ="误报，避免误判为缺陷。

## 一、背景

C-7(b) 装配回路通电后，装配自检（`organ_assembler.validate` / `assemble`）会输出
**"声明-实例差集"**日志：对照 `ORGAN_META`（56 器官声明）与 `_create_organ` 实际实例化结果，
列出"声明方有、实例方缺失"或反之的条目。

## 二、误报窗口（预期内，非缺陷）

任务书 **Q158-3** 已裁：`main.py` 中 **39 处 `_create_organ` 硬编码调用保留**，
**不转入声明式装配**，退役排 **158+**。因此差集日志对这 39 处会呈现：

- 形式一：`声明侧有条目 / 实例侧仍有另一条目` → 看似"多 ="（重复/多出）；
- 形式二：`声明侧标注弃用 / 实例侧仍在直接创建` → 看似"声明-实例不一致"。

这两种形态**均为 Q158-3 刻意保留的预期行为**，不是断链、不是装配缺陷。

## 三、活体验收附言模板（直接复制）

```
差集日志中标注 [保留-158+] 的条目 = 39 处 _create_organ 硬编码调用，
按 Q158-3 裁决延至 158+ 退役，当前差集属预期（非缺陷、非断链）。
验收口径：仅"非 [保留-158+] 的未知差集"才计为异常。
```

## 四、处置结论

- P2-4 整改方式：**附误报解释模板**（本件），不改动 39 处 `_create_organ`（Q158-3 冻结）。
- 若后续 158+ 退役这 39 处，差集日志将自然收敛，本模板同步作废。
