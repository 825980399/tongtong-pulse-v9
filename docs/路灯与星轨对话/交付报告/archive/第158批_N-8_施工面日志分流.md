# 第158批 · N-8 施工面日志分流（P1）· 交付报告

> 触发：路灯_触发指令_E1修复与3新票核验与活体余票_20261002.md（星轨 2026-10-02 晚）
> 性质：P1 施工面日志分流（一次性领取第 4 刀）

## 一、现象与根因

- **现象**：pytest 运行与 `verify_phase17_1_5.py` 验证过程产生的测试专用日志（VectorStore 模拟磁盘写满 / 进程池「模拟重建失败」ERROR / CallGraphAnalyzer 语法错误跳过 等 50+ 条），经框架 root FileHandler 写进生产 `logs/pulse.log`，淹没真实运行事件。原 conftest 用丢弃过滤器静音，虽保 `pulse.log` 干净但一并**丢失**测试日志，无法事后追溯。
- **根因**：pytest / verify 运行期未将框架日志定向到独立文件；conftest 的 `_isolate_project_log_files` 会话夹具对所有 `logs/` 下 FileHandler 一律「丢弃」，无归集点。
- **目标（路灯触发指令第 4 刀）**：`pytest`/`verify_phase17_1_5.py` 写 `logs/pytest.log`（拟建件）；`pulse.log` 只收运行事件。

## 二、修复内容

1. **`nucleus/logger.py`**：新增 `get_pytest_logger(name="pytest")` —— 隔离 logger（挂载 `pulse.pytest.{name}`，`propagate=False`），独立文件 `logs/pytest.log`，每条前缀 `[PYTEST]`，含 `SanitizingFilter`。三保险（独立文件 / `[PYTEST]` 标签 / 不冒泡）与 `get_smoke_logger` 同构。
2. **`tests/conftest.py`**：
   - 在框架 import 之前 `os.environ.setdefault("PULSE_LOG_FILE", logs/pytest.log)` —— 复用 `logger.py` 既有 `PULSE_LOG_FILE` 隔离机制（子进程通过环境变量指定独立日志文件），使 pytest 运行期框架根日志器（VectorStore / 进程池等）直接落 `logs/pytest.log`；`setdefault` 不覆盖调度器可能注入的隔离路径。
   - `_mute_project_logs_handlers` 的 `_is_logs_handler` 改为「放行 `logs/pytest.log`」（仅对指向生产 `pulse.log` 的 handler 挂丢弃过滤器），避免测试面日志被丢。
   - 会话夹具文档更新说明 N-8 改向意图。
3. **`tools/verify_phase17_1_5.py`**：
   - 框架 import 前 `setdefault` `PULSE_LOG_FILE=logs/pytest.log`（尊重调度器隔离）。
   - 导入 `get_pytest_logger("verify_phase17_1_5")`，`check()` 诊断行**双写**到 `logs/pytest.log`（与 stdout 实时输出并存），`main()` 启动标识写入 `pytest.log`。
