## 2. T-117a：tracer flush 头判尾更（本批主体）

### 2.1 根因（T0 实测确认，与烛微 §4.1 完全一致）

`utils/pulse_tracer.py`：
- `:103` 判「距上次 ≥ `_FLUSH_INTERVAL`(2s)？」
- `:151` **完成两轮 `safe_write_json` 之后**才更新 `_last_flush_time = now`

闸非原子 ⇒ 突发窗内 k 个并发者全判「该我刷」，k 份近乎同内容的重复写排同一把 per-path 锁。
`DEBUG_PULSE_TRACE=True`（config.py:3376）→ 生产全程生效；调用点只有
`BasePulseOrgan.py:313 / :479` 两处，且都在**器官主循环的业务逻辑之前**。

### 2.2 改动

**方案A（占闸）**：
```python
def _claim_flush_gate() -> bool:
    global _last_flush_time
    with _gate_lock:
        _now = time.time()
        if _now - _last_flush_time < _FLUSH_INTERVAL:
            return False
        _last_flush_time = _now   # 判完立刻占闸
        return True
```
并把 `:151` 的尾更删除；`flush_to_file(force=False)` 新增 `force` 形参供 atexit 终刷绕过闸。
`_gate_lock` 刻意与 `_events` 的 `_lock` 分开，避免「取快照」与「抢闸」互相排队（原 convoy 正是锁串联）。

**方案B（后台刷）**：
- `BasePulseOrgan.py:313/:479` 两处同步 `flush_to_file()` 移除（import 同步收敛为仅 `log_emit` / `log_receive`）
- tracer 内 `_ensure_flusher()` 由 `log_emit` / `log_receive` **运行期懒启动** daemon 线程
  `PulseTracerFlusher`（0.5s tick，真闸仍是 2s）
- `atexit.register(_flush_at_exit)` 终刷；无事件时不做无谓 IO
- ★红线守住：**import 期零线程、零 IO**（门禁实测 import 后线程表只有 MainThread）

### 2.3 验收（hammer 副本桩）

| 场景 | 判据 | 结果 |
|---|---|---|
| 50 线程同时 flush（改后） | `safe_write_json` 调用 **≤2/窗** | ✅ ≤2 |
| ★正控：同样并发跑**旧**头判尾更逻辑 | 必然 **>10** | ✅ >10（证明判据有区分力，不是恒真） |
| 闸可恢复性 | 同一窗口二次刷被拦；窗口过后再刷放行 | ✅ 不是死锁 |
| force 绕过闸 | atexit 终刷能写 | ✅ |
| import 期红线 | 无 `PulseTracerFlusher` 线程 | ✅ |
| 懒启动 | 首次 `log_emit` 后恰 1 个 daemon 线程 | ✅ |
| 静态契约 | BasePulseOrgan AST 无 `flush_to_file()` 调用 | ✅ |
