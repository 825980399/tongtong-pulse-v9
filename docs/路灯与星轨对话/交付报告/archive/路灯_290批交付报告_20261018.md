## 二、逐刀详情

### 刀1 · 想象加冕 ✅（3 文件 +13/−0 语义）

**前提偏差（重要）**：任务书点名 `PulseKnowledgeRetriever.py:150` 与 `pulse_inner_world_knowledge.py:1088`
两处正则「直接剥掉标签 ⇒ 抹掉来源」。实测这两处是 `clean_node_value` / `_clean_node_value`——
**纯显示清洗路径**，函数只返回清洗后的字符串、**没有任何节点对象可写元数据**。
真正的「丢来源」根因是：想象节点的 source 身份**从未作为节点字段持久化**
（`PulseNode` 只有 `source_organ`/`trigger_reason`，无 `source`/`verification_status`）。

**正解（按意图实现，非按字面位置）**：

1. `nucleus/mnemosyne/PulseNode.py`：新增两字段 `source`（默认 `""`）、`verification_status`（默认 `"verified"`），
   `__init__`/`to_dict`/`from_dict` 三处同步，**向后兼容**（旧快照缺失 → 默认值）。
2. `organs/brain/PulseSubconscious.py`：两处想象 emit 打标——
   `creative.counterfactual`（反事实想象）与 `dream.fiction`（虚构梦境），
   payload 加 `"source": "imagination"`、`"verification_status": "hypothesis"`。
3. `organs/body/PulseStomach.py`：`_on_digest_knowledge` 读 payload → `_do_digest` 加 `source`/`verification_status`
   形参透传 → 节点创建处写回（仅当参数非空才写，默认不写，零回归）。

**验收口径**：重启后带 `verification_status=hypothesis` 的节点 0→>0；检索可按该字段分档（字段已进 `to_dict`，可查询）。

### 刀2 · 洞察/想象评分器＋Top-N落盘 ✅

`nucleus/InsightBoard.py`：
- 新增 `_m290_score_entry(entry)`：`score = confidence × relevance × novelty`（纯函数、无副作用）。
  - confidence：`entry["confidence"]`（post 时已有）
  - relevance：启发式——有 keywords +0.2、有 related_dimension +0.2（基准 0.6，钳 0~1）
  - novelty：内容长度极简代理（钳 0.5~1.0）
- 新增 `_m290_top_n()`：默认 5，可从 `config.INSIGHT_TOP_N_DUMP` 覆盖。
- `dump_to_disk`：每条带 `score` 且按分降序、仅保留 Top-N（payload 增 `top_n` 字段），返回落盘条目数。

**降级申报（novelty）**：任务书要求 novelty 用现成 `VectorEncoder`/`ExperienceRetriever` 算。
集成需编码全量知识语料、且要跑在日拍低频路径，本批（运行期热改）用内容长度代理替代，
真实新颖度由后续批接 VectorEncoder 覆盖。已在代码注释明示。
