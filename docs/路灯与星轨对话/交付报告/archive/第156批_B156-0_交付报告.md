## 三、关键偏差与踩坑（须上报星轨）

1. **★阻断级：登记册 CSV 结构损坏**——星轨 `b732bc2` 入账的 11 张活体窗票只有 8 列（表头 9 列），缺「裁决批次」。会让 `check_pending_register.py` **阻断本批一切提交**。已按正常行 83 字段映射修复（csv 模块按行解析、只重写损坏行，LF/BOM 与裁决内容逐字无损）。**系上游数据问题，非本批引入。**
2. **★门禁票号撞型（潜伏误报）**：`check_pending_register.py` 的票号正则 `D\d{2,4}`（债票 D008）与 **ruff pydocstyle 规则码 `D###`** 同形——任何含 D### 的文件入库会被判「新票未入册」。已加窄豁免（仅基线件目录，对文档/代码的拦截不变）。
3. **★hook 环境错配（门禁失效隐患）**：`pre-commit` 原 `PY=python` 在 Git Bash 解析到**托管 Python 3.13.12，根本没装 pytest** → collect 段跑 pytest 失败、节点数解析为 `None`、门禁形同虚设。已强制 hook `PY=D:/Program Files/Python312/python.exe`（3.12.6，装了 pytest）。**此问题在 156 批前已存在，建议星轨在 CI 环境也统一 Python 解释器。**
4. **collect 正则兼容**：pytest 实测输出为 `4456 tests collected`（非 `collected 4456 items`），已修正正则兼容两种格式。
5. **cw2 静默 except 回潮**：`check_red_baseline_gate.py::_run_once` 的 `except subprocess.TimeoutExpired` 块原只 `return`，被 cw2 判定为「新增静默 handler」。已加 `silent_exc(...)` 调用（CI 门禁认可通道），cw2 `[1]` 复 PASS。
6. **工作树脏文件骤降**：开工时 216 项外部格式化脏文件，本会话期间星轨侧已提交消化，仅余 3 项（全为他会话遗留：1 个 modified `tests/test_lazy_snapshot_m9.py` + 3 个 untracked docs），按 §三.4 **不碰不提交**。
7. **RUF100 口径**：任务书称 666，实测 632（随启用规则集变化）；已固定单规则口径 + 版本硬钉消除漂移。
