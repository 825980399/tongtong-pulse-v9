## 1. T-106a（P1）沉默告警刷屏治理

### 1.1 根因

   `"企业微信", "framework_self_modify_gate", "Web对话", "FunctionLoader"`（存量死键/带后缀条目保留不动）。
2. **`organs/body/PulseBloodVessel.py:92,219-224`** — 新增节流状态 `self._last_patrol_silent_set`；
   DEBUG 巡检行改为「仅当本轮沉默器官集合与上一轮不同才打印」，消除同一批器官每 40 秒重复刷屏。

## 2. T-106b（P2）只写不读增量门禁

### 2.1 根因（来自 wo4 债务审计）
仓库存在「只写不读」类缺陷：D1 死配置键（顶层 `UPPER` 键零读取方）、D2 只写不读属性/字段（写入后无读取点）。
本批目标：**收编 wo4 原型为正式 CI 工具，并建设「增量」门禁**——仅拦截本次 diff 新增的写点，不清理、不误判存量债务。

### 2.2 改法
1. **新建 `tools/ci/check_write_only_gates.py`（668 行）** — 收编 wo4 的 D1(`d1_dead_config`)/D2(`d2_writeonly`) 分析内核，复用第104批 CI 四道关口同构模式：
   - `changed_files(base)`（`git diff --name-only`）+ `git_show`/`git_read_worktree` 取基线/工作树文本；
   - `added_lines(old,new)`（`difflib.SequenceMatcher` 算新增行号集合）；
   - 仅当缺陷「写点」落在本次 diff **新增行**才计为门禁失败（`confidence=="已实锤"` → CI 红；`疑似/需人工` 仅 WARN 不阻塞）。
   - 含 `--selftest` 正控 7 项（fixtureA 写点报红 / fixtureB 有读不报 / live 属性永不报 / 增量 NEW_DEAD_KEY 报红 / 存量 EXISTING_KEY 不误报 等）。
   - D1 判据：`config.py` 顶层 `UPPER` 键 → 全仓读取方计数（AST + token + 字符串三通道 + `config.get_xxx()` 间接读取 + 别名常量传播），零读取方才判 dead。
2. **`.gitee/workflows/ci.yml` 第 5 道关口** — 在「静默 except 门禁」后、「关键测试运行」前新增：
   ```yaml
   - name: 只写不读增量门禁 (第106批 T-106b 防回潮)
     run: |
       if [ "${{ github.event_name }}" = "pull_request" ]; then
         BASE=$(git merge-base origin/master HEAD)
       else
         BASE="HEAD~1"
       fi
       python tools/ci/check_write_only_gates.py --base "$BASE" --target worktree --verbose
   ```

### 2.3 验收与证据（先红后绿）
- **selftest 7/7 ALL PASS**（两次独立运行：`tmp/ci_gate_selftest.log`、`tmp/ci_gate_selftest_final.log`）。
- **真实集成红测**（`tmp/t106b_red_correct.log`）：向根 `config.py` 注入 `SYNTHETIC_DEAD_KEY_106` →
  `d1.status=['dead'] 写点在新增行=True -> 门禁判定=FAIL(捕获=True)`；注入后已**逐字节还原**（残留校验 `SYNTHETIC_DEAD_KEY_106=False`）。
- **存量不误判**：`存量死键被误判为新增=False`（扫描 D1=564 键、D2 attrs=72 等，仅增量新增写点触发）。
- 全量扫描结论（防回潮基准）：D1 564 键中 dead=16 / string-only=54 / test-only=34 等均为**存量**，本门禁不清理、只防新增。
