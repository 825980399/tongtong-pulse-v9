## 二、双轨发射路径失真根因（三层解剖）

### L1 打点层（主因，97.5% emit 未命中）
- **轨 A**：器官经 `BasePulseOrgan._send(:317)` → `pulse_core.emit` + 原 `_send` 内 `:334` 处 `log_emit`（受 `DEBUG_PULSE_TRACE` 门控）。
- **轨 B**：器官直连 `self.info_field.publish(self.pulse_core.emit(...))`（PulseEyes:367/451、PulseVisualCortex 多处、chat_service 等），**绕过 `_send` 打点**。
- 结果：直连轨 B 的 emit 全部漏记 → 洞鉴实测 **97.5% emit 未命中**，join 健康度仅 **14.2%**。

### L2 文件层（次要）
- `pulse_tracer` 只落「被打点到的 emit」，轨 B 事件永不进 `data/monitor` 的 emit 行。

### L3 判定层（加剧）
- 接收侧 `log_receive` 挂在 `_handle_pulse_safe:526`（全接收覆盖）→ receive 全、emit 缺 → **join 断裂**（接收有、发射无）。

### 修复思路
把 `log_emit` 从「`_send` 单点」下沉到「`PulseCore.emit` 单点」。由于**所有 emit 最终都经 `PulseCore.emit`**（轨 A 经 `_send`、轨 B 直连），下沉后两轨合一、单点全覆盖；原 `_send` 打点移除以防重复。

### 5.1 BOM 坑（原方向遗留，本方向已规避）

### 5.2 m117 全量跑 2 failing（如实披露，非回归）
- **现象**：在全量 pytest 联跑中，`test_m117_tracer_flush.py` 的 `test_05`/`test_06` 报「恰有 1 个 flusher」断言失败（实际 2 个）。
- **根因**：新方向使 `PulseCore.emit` 调 `log_emit` → 启动**全局 `PulseTracerFlusher` daemon 线程**；当 `test_spike_wiring_m203` 等先 import 真实 `nucleus.pulse.PulseCore` 触发该 daemon 后，m117 用 `importlib` 加载**独立副本**再起一个同名线程 → `threading.enumerate()` 数到 2。
- **性质**：这是**测试隔离弱点**（进程级 daemon 线程跨模块泄漏），**非生产回归**；且 CI 门禁是 collect 模式、**不执行测试函数**，故不影响门禁结果。
- **铁律151 印证**：逐文件隔离单跑 m117 = 9/9 PASS（见 §四）。
- **建议（留待他批/星轨裁决）**：m117 的 `setUp/tearDown` 可加固为「停掉所有进程级 `PulseTracerFlusher` 线程」，或 tracer 给 flusher 线程按模块实例命名空间——属测试隔离加固，不纳入 226 范围（避免碰他批契约测试）。
