## §一 T0 核实 · 根因钉死

全仓枚举 `target_organ=` 引用 + 精读 `base/BasePulseOrgan.py` 的 `_emit`（:266）与 `_send`（:291）签名，确认四向串味根因：

- `_emit` 形参序：`(event_type, payload, target_organ, priority, ttl_ns, layer)`
- `_send` 形参序：**完全相同** `(event_type, payload, target_organ, priority, ttl_ns, layer)`
- 但 :289 旧调用却按 `(event_type, payload, priority, ttl_ns, layer, target_organ)` 传——**第3~6位整组错位**：
  - 第3位 `_send.target_organ` 收到 `_emit.priority`（整型）→ **int 幽灵源**（224 批追源结论的底层真因）
  - 第4位 `_send.priority` 收到 `_emit.ttl_ns`
  - 第5位 `_send.ttl_ns` 收到 `_emit.layer`
  - 第6位 `_send.layer` 收到 `_emit.target_organ`
- 影响面：所有走 `_emit` 辅助方法的器官脉冲 `priority/ttl_ns/layer` 语义全部传错槽——比幽灵突触更严重（224 报告已判"必须先修再排电窗"）。

全仓 `_send(` 调用点核查：仅 `base/BasePulseOrgan.py:294` 一处生产调用（已修）；另有 `:751` 测试调用用关键字 `layer="L3"`（正确，无错位）；其余匹配为 `functions/web_chat.py` 的 `_handle_send` 与无关测试，不涉脉冲发送。

## §二 刀1 改动落点（base/BasePulseOrgan.py）

`:289` 位置参数调用改为**关键字传参**（最稳，彻底消解位置耦合）：

```python
# 原（位置参数错位）：
return self._send(event_type, payload, priority, ttl_ns, layer, target_organ)

# 改（关键字传参）：
return self._send(
    event_type=event_type,
    payload=payload,
    target_organ=target_organ,
    priority=priority,
    ttl_ns=ttl_ns,
    layer=layer,
)
```

旁附根因注释（`★第225批 刀1`）。`_send` 下游（:321-323 与 :351-357）本身即以关键字/字典正确转发 `priority/layer/target_organ` 至 `pulse_core.emit` 与兜底构造，修复 `_emit→_send` 边界后整链归位。
