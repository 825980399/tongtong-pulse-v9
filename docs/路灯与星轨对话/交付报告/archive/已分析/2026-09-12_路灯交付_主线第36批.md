## 四、★核心发现

### 4.1 引擎"集成但未调度"（P1）

```
main.py:879  →  _init_self_awareness()  →  register_analyzer × 4（本批补到 6）
                                             │
                                             └─ ✗ 全库无 run_all_analyses( 生产调用点
                                                 → 分析永不在框架内自动执行
                                                 → 只靠人工/脚本触发
```
`_init_self_awareness` 的 docstring 明写"**不自动触发分析**（启动期不宜阻塞）"——这是**有意的低风险设计**，但**没有任何后续调度补齐**，导致设计 §5.6 的"每日报告"与阶段一目标「每日自动生成自我认知报告」**未落地**。

### 4.2 配对器覆盖率 0.73%（P1）

| 指标 | 值 |
|---|---|
| 扫描源码文件 | 255（`scanned_files`） |
| 调用点 | 47694 |
| 识别到的**数据路径** | **17** |
| 磁盘实际数据文件 | **2321**（其中 `data/` 1559 / `docs/` 266 / `nucleus/` 77 …） |
| **覆盖率** | **0.73%**（17 / 2321） |
| 设计目标 | 「发现**所有**有产出无消费的数据文件」（设计 §六「834 个数据文件」） |

原因：`_iter_scan_files` 只收集 `.py`；数据文件来自**源码里的路径字面量**，因此：
- 运行时动态拼接的路径（如 `f"fake_loops_{ts}.json"`）只留下**模板**；
- 磁盘上存在但代码里无字面量的文件（`data/knowledge/*`、多数 `data/stream/*`）**全部漏报**。

### 4.3 误报率 64%（超过任务书 20% 阈值，**请裁决**）

11 条「疑似无消费」逐条复核：

| 类别 | 数量 | 明细 |
|---|---|---|
| **文件在项目根不存在**（`size=null`，动态命名模板 / 相对路径解析偏差）→ **不可操作误报** | **7** | `change_log.md`、`data/proprioception_report.json`、`fake_loops.json`、`fake_loops_report.txt`、`pending_patches_resolved.json`、`production_consumption.json`、`production_consumption_report.txt` |
| **真实存在且确无消费** → 有效命中 | **4** | `data/config_override.json`(366B)、`data/stream/hormone_emotion_log.json`(5.8KB)、`data/stream/legs_learn_log.json`(15.9KB)、`logs/pulse_crash.log`(6.5MB) |

⇒ **可操作准确率 4/11 ≈ 36%，误报率 64%**；另发现 **1 处疑似漏判**：`data/config_override.json` 在代码中被 **7 个文件**引用（含 `config.py`），但配对器记为「消费次数 0」——需人工确认其读取方式是否为动态路径。

### 4.4 自我观察噪声

4 条「疑似无消费」是**引擎自己的产物**（`fake_loops.json` / `fake_loops_report.txt` / `production_consumption.json` / `production_consumption_report.txt`）—— 引擎把自己的输出判为"没人用"。语义上成立，但**自我指涉**，会持续污染指标（建议排除自身产物目录）。

### 4.5 虚假闭环检测器漏判私有命名方法（P2）

`EvidenceCalibrator`（`nucleus/reasoning/SelfCalibrator.py:198`）的加载方法是**私有** `_load`（:383），而检测器只认 `load` / `load_xxx` 前缀：
```python
def _is_load_name(name): return any(_n == p or _n.startswith(p + "_") for p in _LOAD_PREFIXES)
# _LOAD_PREFIXES = ('load','read','fetch','retrieve')  →  "_load" 不匹配
```
⇒ 任务书要求核实「EvidenceCalibrator 之前的路径错误问题是否被正确识别」——**答案：否**（该模块**永不进入候选**，因为加载方法命名带下划线）。这是**判定规则缺口**，不是历史问题已修复。
