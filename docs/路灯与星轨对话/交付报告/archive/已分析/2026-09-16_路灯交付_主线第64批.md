## 三、各任务实施

### T1（P0）器官扫描 TTL 缓存机制
- `_scan_all_organs` 外包缓存检查（TTL + 文件 mtime 双维度失效）、统计、手动失效、浅拷贝返回；原实现搬入 `_do_scan_all_organs`。
- 辅助：`_check_files_changed` / `_update_file_mtimes` / `invalidate_scan_cache` / `get_scan_cache_stats`。
- 配置：`ENABLE_ORGAN_SCAN_CACHE`（默认 True，关闭零回归）、`ORGAN_SCAN_CACHE_TTL=300`。

### T2（P0）高频方法二级缓存
- `resolve_organ_file` / `get_organ_code_structure` / `get_method_detail` 加 `(result, self._scan_cache_time)` 版本戳缓存；扫描缓存刷新→版本戳变→二级缓存自然失效（零侵入 T1）。
- `get_method_body` 因含文件读取+AST 分析副作用，**不加**缓存（对应任务书虚构 `get_method_info` 偏差）。

### T3（P1）自适应缓存 TTL
- `_get_adaptive_cache_ttl()`：灰度 `ENABLE_ORGAN_SCAN_ADAPTIVE_TTL`（默认 False）。CPU >80→600s / >60→450s / 正常→300s。psutil 缺失时优雅降级为 `_cpu=0.0 → 基础 TTL`。

### T4（P1）队列深度纳入自适应
- `RuntimeMetrics.get_queue_depth()` 返回瞬时 `_last_queue_depth`（复用 B3 告警口径）。
- 配置：`QUEUE_DEPTH_HIGH_THRESHOLD=5000` / `QUEUE_DEPTH_CRITICAL_THRESHOLD=10000` / `QUEUE_DEPTH_LOW_THRESHOLD=2000`。
- 深度 >CRIT→延长 900s；>HIGH→600s；<LOW→恢复 300s。

### T5（P2）缓存统计与可观测性
- L2 命中/未命中计数；`get_scan_cache_stats` 增加 `l2_hits`/`l2_misses`/`l2_hit_rate`。
- 每 300s 节流打印缓存统计日志。
- `status` 命令显示扫描缓存统计（命中率/命中/未命中/失效/L2）。

### T6（P2）测试 + 隔离修复 + 债务清单
- 新增 `test_organ_scan_cache_m64.py`(10) / `test_organ_scan_adaptive_ttl_m64.py`(4) / `test_queue_depth_adaptive_m64.py`(4) 共 **18 例**（≥任务书 16 例），全过。

## 五、待星轨裁决

1. **队列深度 < LOW 阈值强制恢复基础 TTL，即便 CPU 高**：本批实现为「队列维度 max 延长 / min 恢复基础」，故 CPU 高(600)+队列低(0)→`min(600,300)=300`。任务书 T3 与 T4 在此冲突，本批按 T4 字面实现。若希望 CPU 高不被队列低覆盖，需改为仅对「延长」分支生效。
2. **`get_method_body` 是否加文件级缓存**：本批保守不加（文件读取+AST 副作用）；若需覆盖该高频路径，建议绑文件 mtime 的细粒度缓存（独立专项）。
3. **端到端性能验证**：需运行期观察（CPU 30-40%、命中率 >95%）。灰度默认开、零回归；运行时指标待框架实跑采集。
4. **psutil 依赖**：CPU 自适应维度依赖 psutil；生产 Python 3.12 已装，managed 3.13.12 缺失时降级为固定 TTL（不崩溃）。测试统一用 `D:/Program Files/Python312/python.exe`。
