## 七之二、★T1 自检发现的缺陷（本批自行发现并修复）

### 缺陷

`SelfAwarenessEngine.generate_report` 中新增的 `_m50_report_summary` 用：

```python
_d = json.loads(json.dumps(profile, default=str))     # ← 反模式
```

而 `profile` 是 **dataclass**（`SelfAwarenessProfile`）**不可直接 JSON 序列化** →
`default=str` 会把**整个对象**转成 repr 字符串 →
`json.loads` 得到 **str** → `.get()` 抛 `AttributeError`。

**后果**：`自认知报告发布恒失败`，且被 `except` 吞成 DEBUG 日志：

```
[M50-T1] 自认知报告发布失败（已忽略）: AttributeError        ← 只记类型，无从定位
```

### ★为什么第一轮测试没抓住

首轮 T1 测试只做了**源码接线断言**（`assertIn("publish_self_cognition", seg)`），
**未真正调用集成路径**（`generate_report()` → 发布）→ **bug 被测试全绿掩盖**。

### 修复

1. 改用画像自带 `to_dict()`（其次 `dataclasses.asdict`），并对非 dict 降级为空 dict；
2. **发布失败日志补异常消息**（`%s: %s` 带 `_m50_e`）—— 不再只记类型；
3. **新增功能级集成测试** `tests/test_self_awareness_publish_m50.py`（6 例）：
   - 真调用 `generate_report()` 并断言 `self_cognition` 信封进入总线（★核心）
   - 断言 `_m50_report_summary` 返回**真 dict**（非字符串）
   - 容忍 dataclass / dict / None / str / int / list 六种输入
   - **AST 级防回归**：函数体内不得再用 `json.dumps/loads`
   - 断言失败日志带异常消息
   - 断言报告确实落盘到总线目录

### ★教训（已入 skill §45.1/§45.8）

- **「接线断言」≠「功能验证」**：集成路径必须**真跑一次**；
- **日志只记 `type(e).__name__` 等于静默**：必须带 `e` 本身；
- **源码文本扫描必须用 AST**：本批两次因「docstring 里写了反模式文字」被正则误判
  （`explicit_base_dir=True` / `default=str`）。

### 附带修复

`tmp_nucleus_dead_code.py`（**非本批产出**，18:14 由审计侧生成于仓库根）存在
`F541 f-string without placeholders` → 破坏全库 `F=0`，已修正为普通字符串（1 行）。
