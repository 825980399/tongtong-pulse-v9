## 2. 任务2（P1-24）QICA 相关度计算语义鸿沟优化

### 2.1 根因（语义鸿沟在哪）
`nucleus/qica/IntentChannels.py` 的 `ch_semantic` 通道对 24 意图余弦相似度做 **min-max 归一化**：使「本查询相对最像的意图」恒 = 1.0，**无论其绝对余弦多低**。

这与 `VectorEncoder.apply_score_gate` 注释（2026-09-07 实测）完全同源：
> bge-small-zh 余弦被严重压缩——同类均值 0.46、异类均值 0.42，两分布几乎重叠，任何绝对阈值都切不开。

后果：语义宽泛的「**知识查询**」原型（"什么是X"类）成为**黑洞**，在融合路径（78.5% 样本走融合）把 规则查阅/技术推理/概念解释/记忆回想/学习成长/元认知报告 等一律吸走。基线回归中 21 个错分有 ~15 个错归知识查询。

### 2.2 修复（置信度感知）
`ch_semantic` 在 min-max 相对排序之外，乘上**绝对置信度**：
```
raw_conf = clamp((cos - FLOOR)/(CEIL - FLOOR), 0, 1)   # FLOOR=0.42(异类基线), CEIL=0.58(同类基线)
score = minmax_norm × raw_conf
```
- 绝对余弦高（真正匹配）→ raw_conf≈1.0，满权保留；
- 仅「相对最像、绝对余弦低」→ 被显著压低，让真正匹配的意图浮出。
- 关闭 `ENABLE_QICA_SEMANTIC_CONF_AWARE` 完全退回旧 min-max（向后兼容）。

### 2.3 配套权重/阈值微调
- 句式通道疑问句提升名单补 `规则查阅`（此前仅 6 个意图，规则查阅 是疑问句却无句式信号，完全依赖语义通道 → 0.50 准确率）。平铺 +0.5 对所有疑问句生效，不破坏同类疑问句的相对排序。

### 2.4 回归结果（158 条 / 24 意图）

| 版本 | 意图级 | 路径级 | 说明 |
|---|---|---|---|
| 基线（旧 min-max） | 137/158 = **0.867** | 143/158 = 0.905 | — |
| + 置信度感知 | 141/158 = 0.892 | 146/158 = 0.924 | 关系查询0.80→0.90，技术推理0.57→0.71 |
| + 规则查阅句式提升 | 143/158 = **0.905** | 148/158 = **0.937** | 规则查阅 0.50→0.83 |

**残差 15 错分仍以知识查询黑洞为主（~9 个）**，但已非原型失配：
- 原型库诊断：最近原型意图与金标一致率 **154/158 = 0.975** → 原型库与金标语料**对齐良好，无需重建**。
- 残差源于多通道融合的细粒度交互，进一步调优存在对 158 条过拟合风险；核心语义鸿沟（min-max 摧毁绝对置信）已修复。

### 2.5 新增配置项（config.py）
```

QICA_SEMANTIC_CONF_FLOOR = 0.42          # 异类余弦基线

```

## 3. 任务3（P1-23）知识节点 quality_flag 消费（假闭环第5例）

### 3.1 根因
`ExperiencePollutionGuard` / `cleanup_alias_placeholder_nodes.py` 会**写** `quality_flag`（polluted / suspect / placeholder_alias），但检索侧 `VectorStore.search_by_vector` **从不读**，形成假闭环。

### 3.2 修复（可插拔消费）
`VectorStore` 注入 `quality_flag_provider`（可插拔）+ 权重表 + top_k 放宽：
```python
QUALITY_FLAG_WEIGHTS = {"polluted":0.0, "suspect":0.5,
                        "placeholder_alias":0.3, "clean":1.0, "ok":1.0,
                        "none":1.0, "":1.0}
```
- `search_by_vector` 取 `top_k*3` 候选 → 按权重缩放相似度 → `polluted`(权重0) 直接剔除 → 排序裁 `[:top_k]`；
- top_k 不足时自动放宽候选池；
- `provider=None` 时行为**完全不变**（保护 43/43 回归）；
- 默认挂经验库 provider（惰性读 `reasoning_experience.json`/`experience_pool.json`），**不安全**常驻；
- 知识快照 provider（`build_snapshot_quality_flag_provider`）以 helper 形式提供，**不自动挂载**（避免 318MB 常驻）。

### 3.3 单测
`tmp/test_mainline3_quality.py`（桩化 `cosine_matrix`/`topk`）：polluted 过滤、suspect/placeholder 降权、top_k 放宽、正常不受影响、provider=None 等价、权重表——6 例全过。

## 4. 任务4（P1-18）StreamMiner 消费链路打通

### 4.1 根因
A-16 在 `InfoField` 已实现 `consume()` 调用并发射 `pattern_prewarm` 脉冲（action=preload_knowledge），但**全库无任何消费方**真正执行预加载（见 2026-09-08 第七批交付报告遗留项）。脉冲发出即止，链路断裂。

### 4.2 修复
新建 `nucleus/genesis/PatternPrewarmConsumer.py`：
- 维护 `knowledge_preload_cache: dict[event_type, 线索]`，将「即将发生的周期事件」在到达前预热知识线索；
- 默认 `EVENT_KNOWLEDGE_HINTS` 静态映射（高频事件优先：heart.beat/system.boot/ears.heard/…），**零外部依赖即可工作**；
- `set_vector_resolver()` 可插拔接入真实知识库检索（候选节点 id）；
- `serve_on_arrival()` 事件真实到达时返回预热线索并记命中——**可测的"实际效果"证据**；
- 单例 `get_pattern_prewarm_consumer()` 供 InfoField 与测试共享。

`InfoField.py`（受 `ENABLE_STREAMMINER_CONSUMPTION` 灰度控制）在发射脉冲的同时，把 `_prewarm` 交给 `get_pattern_prewarm_consumer().on_prewarm(_prewarm)`，预加载真正落地。
