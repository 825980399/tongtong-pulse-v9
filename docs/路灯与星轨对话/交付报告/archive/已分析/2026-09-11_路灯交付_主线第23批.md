## 二、6 项任务完成情况

### T1 · 知识一致性分析 ✅
`analyze_consistency()` 实现 4 类检测（纯规则/关键词/统计，**不依赖大模型**）：

| 类型 | 检测方式 |
|---|---|
| 直接矛盾 | 同主体「X 是 Y」vs「X 不是 Y」（正/负模式配对 + Jaccard 相似度 ≥0.34） |
| 数值冲突 | 同指标不同数值（连接词必需 + 相对差 >5%） |
| 因果矛盾 | 同「因」推出互斥「果」（一正一反 + 相似度 ≥0.2） |
| 定义不一致 | 同概念「X 是指…」多定义且相似度 <0.55 → **标记 `needs_review`**（复杂语义交人工确认） |

评分：`100 − 涉及矛盾节点数/总节点数 × 100 × 2`。输出含类型/严重度（按涉及节点最高层级 L3>L2>L1）/置信度/节点ID。

### T2 · 知识覆盖率分析 ✅
`analyze_coverage()` 四维：**领域覆盖**（`space_path` 首段分域，低密度→盲区并列建议）、
**深度覆盖**（L1/L2/L3 比例 + 识别「只有 L1 无提炼」的浅层领域）、
**关联覆盖**（无任何关联=孤岛）、**时间覆盖**（近 90 天注入量）。
评分 = 领域 35% + 关联 30% + 深度 20% + 时间 15%。

### T3 · 知识老化分析 ✅
`analyze_aging()` 四类：**时效性**（>180 天）、**版本关联**（引用低于当前版本，当前取 `config.KNOWLEDGE_CURRENT_VERSION` 默认 9.5）、
**访问频率**（`activation_count=0` 且 >90 天无激活=休眠）、**矛盾驱动**（与 T1 冲突相关的节点）。
输出含年龄/空闲天数/类型/建议操作（update/archive_or_delete/review），无时间戳时标记 `timestamp_inferred`（**不修改原始数据**）。

### T4 · 知识质量综合评分模型 ✅
`analyze_overall()`：一致性 30% + 覆盖率 30% + 老化 20% + 知识深度 10% + 知识广度 10%，等级五档（优秀≥85/良好70-84/一般50-69/较差30-49/危险<30）。
`generate_report()` 输出 `{score, level, dimensions, weights, summary, top_issues, suggestions, stats}` —— 与引擎现有四维 dict 契约兼容。
`compare_profiles()` 接口与 `SelfAwarenessEngine.compare_profiles` 一致（improved/degraded/unchanged/delta）。

## 六、遇到的问题与处置

1. **★首版数值冲突误报率极高（895 处）**：原正则把连接词写成**可选**，等于「任意文本+数字」都命中 ——
   实测把「（由30条相关知识归纳）」解析成指标「条相关知识归纳由」、把年份 `2026` 当数值。
   **处置**：连接词改**必需** + 年份区间过滤（无单位时）+ 指标名虚词黑名单（的/了/由/在/和/与/或…）
   → 误报 895 → **6 处**，综合评分 63.38（一般）→ **94.11**。
2. **同概念重复占位**：定义不一致按节点对生成 `N*(N-1)/2` 条，同一概念重复占满 TOP 列表
   → **处置**：同概念只保留最严重一条 → 冲突 103 → **9 处**。
3. **盲区阈值过严**：初版取全库 1%（10496×1%=105）→ 连 93 节点的正常领域也判盲区
   → **处置**：调为 0.2% → 盲区 7 → **3 个**（仍满足任务书「≥3 个」）。
4. **m19 单次运行必触发限流**（见 §四说明）→ 按类分次取证。
