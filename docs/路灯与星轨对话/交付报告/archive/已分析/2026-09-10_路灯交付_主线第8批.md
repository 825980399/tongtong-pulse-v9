## 二、各任务交付明细

### 任务1 · P2-62 统一数据访问层（核心，✅ 完成）

**新建模块**：`nucleus/data/DataAccessLayer.py`
- `safe_read_json(path, default=None)`：异常处理 + 编码容错（utf-8 → gbk → latin-1 回退）+ 文件锁
- `safe_write_json(path, data, backup=True)`：原子写（`tmp` + `os.replace()`）+ 自动建目录 + 备份（最多 3 版本）
- `safe_read_text` / `safe_write_text`：文本读写对称接口
- 写入失败返回 `False` 不抛异常（与 `VectorStore.flush` 一致），数据安全优先

**收口情况**：**15 个生产文件（17 处调用点）** 接入 `safe_write_json`，均为高频写入核心路径（经验池、快照、QICA、备份管理、各器官状态持久化等），满足并超过「≥10 处」要求（含 DAL 模块本体共 16 文件）。

**偏差核实**：任务书称「97 文件直接用 `open()` 读写 JSON、84 个 `json.dump()`」。实测全库散落远大于此，按「渐进式改造、优先高频核心路径」原则只收口最危险的高频写入，未一次性全改（符合任务书第五章第 5 条）。

**测试**：`tests/test_data_access_layer.py` 新增 **10 例**（原子写 tmp+replace、gbk 回退、损坏归档、真实收口回归等）。

### 任务4 · P2-37 孤儿 Event 常量第二批审阅（✅ 完成）

**四步法**：① 全局搜索常量名 → ② 确认零命中（排除注释/字符串/测试）→ ③ 确认非传感器词汇表 / 外部协议常量 → ④ 确认删除不影响其他模块。只摘除「确证死重复」常量，宁多保留不误删。

**扫描修正**：既有第3批扫描脚本 `tmp/scan_orphans_m3.py` 的 `EXCLUDE_DIRS` 未含 `.bak*`，导致本期新建的 `.bak_mainline8` 被扫入、误报「0 孤儿」。重写 `tmp/scan_orphans_m8.py`（排除 `basename.startswith(".bak")`），得真实结果：`const.py` 171 成员、**26 个零命中候选**。

**处理结论**：
- **24 个保留**：经判定为传感器 / 执行器 / 视觉 / 控制词汇表（外部协议 / 订阅者契约风险），摘除会破坏订阅契约 → 按「宁多保留」原则全部保留。
- **2 个确证摘除**：`StreamMinerEvent.PATTERN_DISCOVERED`、`DecisionEvent.RESULT`（四步验证全库零引用、非词汇表/外部协议），原位留摘除说明注释（仿主线第3批 `MODEL_SELECTED` 风格），空类 `StreamMinerEvent` / `DecisionEvent` 保留。

**偏差核实**：任务书称「剩余 106 候选、第二批 20 个高置信度候选」。实测真实候选数与分布与任务书描述不符（旧扫描脚本误报 + 词汇表占多数），按四步法实际只摘除 2 个确证死常量，符合「只摘确证死重复」原则。

**质量门禁**：`nucleus/const.py` `ast.parse` 通过；全库 ruff F = 0；框架回归 43/43。
