### T3 P2-59 肺部多渠道支持

**改动**（`organs/body/PulseLung.py`，1343 → 1649 行）：

新增 11 个方法：
| 方法 | 职责 |
|---|---|
| `_channels_config()` | 取多渠道配置；不可用返回 None（灰度判据） |
| `_get_channel_health()` | 惰性构造健康度跟踪器（参数取自配置） |
| `_select_default_channel()` | 按优先级选最佳可用渠道（跳过熔断中） |
| `_rotate_channel(current)` | 当前渠道失败时取下一未熔断渠道 |
| `_update_channel_health(name, success, latency)` | 更新健康度并判定熔断 |
| `_build_channel_messages(prompt)` | 统一构造 messages（复用既有人格提示词） |
| `_call_channel(channel, prompt, **kw)` | 统一渠道调用（经适配器构造请求 → POST → 解析） |
| `_gateway_channel()` | 开关打开且网关可用时返回网关渠道 |
| `_is_advanced_task(model)` | 判定高级任务（advanced_model 或 advanced_tasks 命中） |
| `_build_advanced_channel()` | 构造高级任务渠道 |
| `_call_via_channels(prompt, model, ...)` | **路由主逻辑**：网关优先 → 高级渠道 → 渠道池轮询 |

**路由规则（`_call_via_channels`）**：
1. 开关打开且网关可用 → 优先网关渠道
2. 高级任务（code/deep_think/complex_reasoning）→ `advanced` 渠道（收费 API，deepseek-flash）
3. 平常对话 → `default_channels` 按 priority 升序，逐个尝试（跳过熔断中）
4. 全部失败 → 返回 None，由上层既有逻辑回退本地 Ollama

**`_call_remote_api` 接入方式**（最小侵入）：
在方法开头插入灰度分支——`_channels_config()` 非 None 时改走 `_call_via_channels`，否则**完全保持原有单端点逻辑**（后方代码一行未动）。

**渠道健康度**：新增 `nucleus/llm/channel_health.py`（`ChannelHealthTracker`）
- 记录成功率 / 平均延迟 / 连续失败次数
- 连续失败 ≥3 → 熔断 300 秒（到期自动半开）
- 内存态、线程安全（锁保护）、不持久化（符合 P0 约定）

**下游零改动验证**：`call_llm(prompt, task_type=...)` 签名与返回结构未变；`_call_remote_api` 返回值仍为 `str | None`。

### T4 P2-59 OpenAI 兼容适配器

**新增目录 `nucleus/llm/`（4 个模块）**：

| 文件 | 职责 |
|---|---|
| `base_adapter.py` | `BaseLLMAdapter` 抽象基类：`build_request` / `build_headers` / `parse_response` / `check_availability` / `supports` |
| `openai_compatible_adapter.py` | `OpenAICompatibleAdapter`：OpenAI `/v1/chat/completions` 格式（覆盖 DeepSeek/智谱/豆包/百炼/vLLM/Ollama） |
| `adapter_registry.py` | `AdapterRegistry` + `get_adapter_registry()` 单例；含**预留的 `ExternalGatewayAdapter`**（待接入，空实现） |
| `channel_health.py` | `ChannelHealthTracker`（T3 共用） |

**裁决选3 落点**：`ExternalGatewayAdapter`（`adapter_type="external_gateway"`）已注册，`check_availability` 在未配令牌时返回 False → 默认（网关关闭）时零副作用；待 P1 阶段配置网关令牌后可直接启用，无需改肺部代码。

**设计特点**：
- 适配器**无状态、不依赖网络库**，只做 dict↔dict 结构转换，HTTP 由肺部执行（最小依赖）
- `parse_response` **逐层结构防御**，任何异常结构返回 None 不抛
- 未知 adapter 类型**回落 OpenAI 兼容**（最通用格式），保证新渠道配置错也不炸链路
