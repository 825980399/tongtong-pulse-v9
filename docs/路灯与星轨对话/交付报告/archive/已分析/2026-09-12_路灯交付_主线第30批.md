## 二、★★ 本批最重要的两个纠偏（都推翻了任务书的判断）

### 2.1 "multi_step_execute 输出只有 12 字"——**是观测假象，不是 bug**

任务书 §v2 把它列为 **P1**，并要求"修复输出聚合逻辑"。**实测：不存在该 bug。**

**证据链**：`functions/chat/chat_service.py:215` 打印的日志是
`控制台输出: {content[:300]}…`，而 `content` **含换行** —— 多行内容写进日志文件就是**多行**。
用 `grep`/`head` 只命中首行，于是看起来"只有 12 字"。

按**行区间**读取原始日志（1126–1140）：

```
[1126] 控制台输出: 这个问题我分了4步来想：
[1127] （空行）
[1128] ⚠️ 先「了解A」这一步没走通：
[1129]  请你以 数字生命的自 我认知与成长 … 暂无足够信息
[1131] ⚠️ 接着「了解B」这一步没走通：
[1132] … 暂无足够信息
[1134] ✅ 接着「对比分析」：
[1135]  我的"自我"不是某个单一器官产生的，而是53个
[1137] ⚠️ 最后「结论建议」这一步没走通：
[1138] … 暂无足够信息
[1140] 4步里成了1步，没走通的那部分还需要再确认 (来源=inner_world, 长度=277)
```

**完整输出 277 字**，且日志末尾的 `长度=277` 是权威长度。
另用实验单独验证 `_synthesize_step_results`：**186 → 185 字（无害）**。

⇒ 故**未修改** `_synthesize_step_results`（避免无谓改动引入回归）。

### 2.2 ★第29批 T1（深度思考入口路由）**实质无效**——根因是「复杂度标度不匹配」

**这是本批最有价值的发现。**

项目里存在**两套互不兼容的复杂度算法**：

| 算法 | 使用方 | 同一问题取值 |
|---|---|---|
| `nucleus/reasoning/StrategySelector.py:225` `estimate_complexity` | **cortex 侧** | **0.7** |
| `organs/brain/PulseInnerWorld.py:20516` `_assess_question_complexity` | **检测器实际使用** | **0.15** |

第29批按**前者**标度把阈值设为 `0.6` → 95 号 `_detect_force_deep_think` **几乎永不触发**。
运行时实证（改动前，12:59:50）：

```
[2363] 思考纪律·深度通道: '请分析当前系统的架构设计与优化方向，对比多种方案的优劣…'
[2394] （经过深入思考后补充）{'status':'degraded','reason':'子进程无知识上下文…'} (长度=312)
```

即：**检测器链全未命中**，问题落到检测器链**之后**的「思考纪律·深度通道」。

**本批修复**：阈值 **0.6 → 0.3**（对齐 InnerWorld 标度），并把两套标度的差异写入 `config.py` 注释。
实测同一问题在 InnerWorld 标度下为 **0.65 ≥ 0.3** ✓（导入冒烟已验证）。

## 六、任务书未提及但实测发现的问题

1. **多步检索成功率低**：一次真实请求 **4 步中 3 步失败**（`⚠️ 这一步没走通` + `暂无足够信息`），
   且步骤检索词退化（把整段问题碎片拼进检索词：`输入="请你以 数字生命的自 我认知与成长 请你以…"`）。
   → 记 **P2-184**。
2. **`_deep_think` 子进程恒降级**：返回
   `{'status':'degraded','reason':'子进程无知识上下文，请改用主进程同步执行深度思考'}`。
   本批只做了「**不把该内部 dict 拼进用户可见答案**」，**降级根因未修** → 记 **P2-185**。
3. **`"为什么/如何/怎么"` 被误列为"简单询问词"** → 因果类长问题被永久排除出深度思考。**本批已修正**。
4. **分支生成只检查旧配置**：`_generate_branch_with_model` 读 `REMOTE_API_CONFIG`（兼容层），
   在渠道体系下可能恒返回 `None`（解释了日志中的 `输出="None"`）→ 并入 P2-184。
