## T4 第69批遗留延续（优先）✅

### 4.1 PulseSnapshot 冷热加载
**文件**: `nucleus/mnemosyne/PulseSnapshot.py`

新增 `_m70_apply_hot_cold_load()` / `_m70_hot_cold_enabled()`，并在 `load()` 中接线：
- **L1 热节点**：保留完整 `value`，常驻内存
- **L2/L3**：清掉大字段（`value` / `linked_nodes`），只留元数据
- 登记 `self._m70_lazy_ids`，供后续按需补全
- 输出 INFO 统计：`共N 热(L1)=X 懒加载(L2/L3)=Y`

**安全边界（重要）**：只清**可重建**的大字段；`node_id` / `evol_level` / `space_path` /
`keywords` 一律保留，否则下游按路径/层级检索会失效。
任何异常都被 `load()` 捕获并**退回全量加载** —— 零数据丢失优先于省内存。

### 4.2 fast_ops FAISS 对接
**文件**: `nucleus/fast_ops.py`

在 **GPU 之后、Cython top-k 之前**插入 FAISS 路径（临时 FlatL2 索引）。

**关键决策 —— 阈值保护**：
```
仅当候选数 >= FAISS_FAST_OPS_MIN_CANDIDATES（默认 5000）才走 FAISS
```
理由：FAISS 需先建索引 O(N·D)，**小候选集建索引的开销大于暴力余弦本身，会变慢**。
设阈值是零回归的关键 —— 不能为了"用了 FAISS"而全量切换。
失败/未安装 → 静默回退原 CPU 路径。

## T3 分布式架构设计 ✅

**新增**: `nucleus/distributed/sharding.py` + `routing.py` + `__init__.py`
**文档**: `docs/分布式架构设计文档_20260917.md`

### 分片（推荐混合：evol_level + md5 哈希）
```
L1 → shard 0-1 (2片)   L2 → shard 2-7 (6片)   L3 → shard 8-15 (8片)
```
- 纯哈希缺陷：热节点被打散，无法针对性优化
- 纯层级缺陷：层内倾斜无解
- 混合：保留层级局部性 + 摊平层内热点（测试验证 L1/L3 分片集合无交集）

### 一致性
- `eventual`（默认，性能优先）/ `strong`（L1 热节点等关键数据）
- 冲突解决：LWW 默认；向量时钟第71批+评估

### 路由与负载均衡
- 4 种策略：`round_robin` / `least_conn`(默认) / `consistent_hash` / `dynamic`
- 健康分 0.0~1.0，低于 0.5 不参与路由
- **推荐混合路由**：客户端缓存直连 + 代理兜底

★**只做设计与接口定义，未实施**（第71批+按文档第六节路线逐步引入）。
