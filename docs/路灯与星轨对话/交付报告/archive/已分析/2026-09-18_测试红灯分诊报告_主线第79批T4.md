## 4. 关于 T4「目标 <10」的说明（偏差如实记录）

任务书 T4 目标为「失败数 37 → <10」。实测权威失败 **125 唯一**，且分布为：
- **≈100 例为环境级（D）**：根因是 workbuddy 沙箱的 safe-delete 批量删除守卫 + Playwright 未装，**与代码质量无关**，在本项目自有 CI 中会通过；
- **25 例为真实既有缺陷（A 4 / B 16 / C 4）**，横跨 m13/m47→级联/m52/m56/m64/m65/m66/m67/m71/m72/m35 等**多个其他批次子系统**，**无一属于本批（79）**。

因此「降至 <10」**无法在本批（79）scope 内达成**，强行达成只能靠二选一——(a) 关闭环境安全守卫（越权、环境层而非代码层）；或 (b) 修复 16+ 个 B 类真实缺陷（各属其所属批次，跨 10+ 子系统，单点修复风险高、易引入回归）。依项目铁律「不强行凑数」「偏差如实记录」，本批**只产出分诊与归属**，不越权改写其他批次子系统。

**推荐收口路径（移交后续批次 / 测试 CI 配置）**：
1. **D 类（≈100）**：在测试 CI 放宽 safe-delete 守卫（或把所有测试临时目录统一经 `tmp/test_isolation.py` 隔离夹具、控制单 turn 删除 <50）；为 browser 测试装 Playwright。仅此一项即可消除约 100 失败。
2. **A 类（4）**：由第80/81批生成或重定位第71批设计文档到 `docs/`，或测试改用非日期戳取数。
3. **C 类（4）**：编译 `FrequencyCodec` Cython 扩展（或放宽 import-count 断言为降级感知）。
4. **B 类（16）**：逐一批次立案——经验子系统（m56/m65/m66）数据契约对齐、InfoField `_task_count_lock`（m13）、SelfInspector `_method_body_hits`（m64）、PulseStomach 降级返回 dict（m52）、snapshot_kal 异步跳过日志（m67）、distributed `ADD_UNDERFLOW`（m72/m73）、KAL 死 noqa（m35）。
