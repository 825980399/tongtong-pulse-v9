## 疑问1：PulseController / PulseLegs 的 E402（结构性）—— 是否授权移动函数？

**描述**
两个文件剩余 15 条 E402，根因不是 import 位置写错，而是 **`budget_guard` 装饰器工厂函数定义在模块
import 之前**（PulseController.py 第 ~60-101 行，PulseLegs.py 同构）。Python 必须先定义装饰器才能
在类体内使用，所以这是**有意的结构**，不是笔误。

**相关代码位置**
- `organs/motor/PulseController.py`：第 60-101 行 `def budget_guard(...)`，随后第 25-52 行的 import 被判 E402
- `organs/motor/PulseLegs.py`：第 ~20 行 `def budget_guard(...)`，第 30-42 行 import 被判 E402

**可选方案**
- **方案A（不动）**：承认 E402 15 条为设计内项，写入 ruff.toml 的 per-file-ignores
  ```toml
  "organs/motor/PulseController.py" = ["E402"]
  "organs/motor/PulseLegs.py" = ["E402"]
  ```
  零代码风险，但掩盖了「函数定义在 import 前」这一事实。
- **方案B（重构）**：把 `budget_guard` 抽到独立模块（如 `nucleus/ResourceBudget.py` 内或新建
  `utils/budget_guard.py`），两处改为 import 引入。改动面小（2 个文件的装饰器定义 + 1 处 import），
  但 PulseController 是 160KB 核心文件，动 import 顺序有加载时序风险。
- **方案C**：把 `budget_guard` 函数移到文件末尾、import 全部前置 —— **不可行**，装饰器需在类定义前可用。

**需要星轨确认**：
1. 选方案A还是方案B？
2. 若选 B，是否授权对 PulseController.py 做 import 区调整（该文件属「大文件」约束范围）？
