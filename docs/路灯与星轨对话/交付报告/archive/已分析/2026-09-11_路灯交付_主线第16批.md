## 二、T2 P2-94 FrequencyCodec Cython 模块重复加载

**文件**：`nucleus/pulse/FrequencyCodec.py`

### 根因（复核确认并细化）
日志「只记一次」的守卫用的是**实例属性** `self._cython_loaded`，而 `FrequencyCodec()`
在子进程（`ReasoningWorkerPool._execute_reasoning_task` 的 `encode_batch`）与多处调用点
**被反复新建** → 每个新实例都再打一次 INFO（任务书报 70+ 次；本批重启后的新日志 7 分钟内已见 5 行）。
且 `from ..._frequency_codec_cy import encode_cy` 写在**函数体内**，每次调用都走一遍 import 语句。

### 修复（灰度 `ENABLE_FREQUENCY_CODEC_CACHE`，默认 True）
1. 解析结果上移到**模块级进程级缓存**（`_CY_LOAD_STATE`），每进程只真正解析一次；
2. 主进程首次加载 → **INFO**；子进程（`multiprocessing.current_process().name != "MainProcess"`）→ **DEBUG**（不刷屏）；
3. 同进程 import 次数计数，**超过 3 次打 WARNING**（回归哨兵，防再次退回实例级加载）；
4. **`encode_batch` 的 `encode_batch_cy` 同样纳入缓存**（任务书只提到 `encode_cy`，实测它也是热路径内 import）；
5. 提供 `_reset_cy_load_state()` 供测试隔离；Cython 不可用仍正确回退 Python 原生实现。

### 验收（实测）
`_get_encode_cy()` 连续调用 3 次 → `import_count == 1`、返回同一函数对象；
10 个实例连续编码 → 仍 `import_count == 1`；Cython 总开关关闭 → 返回 None 且 `encode()` 回退正常。

测试 `tests/test_frequency_codec_cache_m16.py` **10 例**。

`_verify_integrity` 在 `actual_count == 0` 时**无条件**打
`ERROR: 恢复的节点数为0，快照可能为空` 并返回 False ——
**既不区分「快照本身为空（首次启动，正常）」与「快照有 N>0 个节点却恢复出 0（真失败）」，也没有任何诊断信息。**
（注：当前新日志中该 ERROR 出现 **0 次**——第13批 P2-88/P2-86 修复后已大幅收敛。）

### 修复（灰度 `ENABLE_SNAPSHOT_DIAGNOSTIC`，默认 True）

   声明 N>0 却恢复 0 → `ERROR …判定为**加载失败**。诊断: …`；
2. **`_snapshot_diagnostic(data)`**：文件大小 / 版本 / `node_count_at_save` /
   `nodes` 的类型与长度 / `data=None` / 顶层类型异常；
3. **保存前校验**：`save()` 中若有效节点为 0 → WARNING（不阻断保存）；
4. 开关关闭 → 退回原「无条件 ERROR」（零回归）。

### 修复（灰度 `ENABLE_L3_BACKPRESSURE_OPTIMIZE`，默认 True）

   并附带「已过滤低价值/重复」条数；放行时复位连续计数；
3. **统计**：`get_l3_backpressure_stats()`（过滤原因分布、背压次数、连续峰值、L3 拒绝数）。

**作用域保证**：过滤与告警**只作用于 L3**（`layer_tag == _PULSE_LAYER_L3`），L0/L1/L2 判定完全不变。
