## 四、★★ P0-2 结论重大修正（本批最高价值发现）

| 口径 | `problem_fixed` | 可判定率 |
|---|---|---|
| 第47批（**日志基线**） | 0 true / 1 false / **59 none** | **1.67%** |
| 第51批（**代码复现**） | **58 true** / 2 none | **96.7%** |

### 结论修正

> **「无法用日志验证」≠「没有被修复」。**

第47批的 0% 是**日志口径不可判定**（`pulse.log` 轮转截断 → 基线恒 0），
**不是"补丁无效"**。代码级复现证明：

* 60 条补丁全部有 `original_code` + `modified_code`，且**两两不同**（不存在空补丁）；
* **51 条真通过 + 7 条部分修复**（问题减少但未清零）、
* **假通过 0 条 / 修复无效 0 条**。

**「空转」的真正根因**不是"补丁是空的"，而是**验证方式依赖了会被轮转截断的日志**。

### 新机制（不依赖日志）

```
① 按 issue_type 选检测器（AST 静态分析，不执行被检代码）
② original_code  → 期望检出 ≥1 处（复现成功）
③ modified_code  → 期望问题减少/消失（修复有效）
```

结论分类：`true_pass` / `partial_fix`（★新增细分）/ `false_pass` / `ineffective`
/ `verification_failed` / `not_applicable`。

**回填**：60 条已写入（备份 + **sha256 逐字节校验**），不删除任何既有字段。
**接入**：`patch_verification_split` 新增**最高优先级**分支，无该字段时**完全回退**旧逻辑（零回归）。
