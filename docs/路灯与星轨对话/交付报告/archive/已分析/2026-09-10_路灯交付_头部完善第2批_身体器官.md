## 五、P1-29 内在世界 AttributeError 修复情况

**症状**：`AttributeError: 'float' object has no attribute 'append'`（2026-09-10 01:56:24，学习目标锁定「推导」后）

**根因**：`self._last_reflection_insights` 在 `__init__` 里被**误初始化为 `0.0`**（float），
而写入处的守卫写的是 `if not hasattr(self, '_last_reflection_insights'):` ——
属性存在（只是值类型错），**hasattr 恒为真，守卫完全失效**，每轮反思都撞 float.append()。

**修复（3 处，`organs/brain/PulseInnerWorld.py`）**

| 位置 | 修复前 | 修复后 |
|---|---|---|
| 约 273 行 `__init__` | `self._last_reflection_insights = 0.0` | `= []`（并附 ★P1-29 注释） |
| 约 4729 行 写入侧 | `if not hasattr(...):` | `if not isinstance(getattr(self,'_last_reflection_insights',None), list):` |
| 约 20706 行 读取侧 | `if hasattr(...) and self._last_reflection_insights:` | 取出局部变量后 `isinstance(_refl_insights, list) and _refl_insights:` |

**为什么用 isinstance 而不是 hasattr**：`isinstance` 同时覆盖三种脏值来源——
① 初始化笔误；② 从持久化快照恢复出的旧脏值；③ 运行时被别的模块改写。
单测 `test_05/06/07` 分别验证了这三种场景都能正确恢复为 list 并完成 append。

## 六、本轮过程中的一次误伤与回滚（必须记录）

**事故**：我第一次跑空白清理时用了
`ruff check --select W291,W293,W292,RUF100 --fix`。

**问题**：`--select` 会**只启用这 4 条规则**，于是 RUF100（unused-noqa）把
**所有其它规则的 `# noqa` 全部判定为「未使用」并删掉**——包括真正在用的：

```
- "correlation_id": payload.get(...),  # noqa: F601   →  noqa 被删
- content = payload.get(...)           # noqa: F841   →  noqa 被删
- emotion = self._get_current_emotion() # noqa: F841  →  noqa 被删
- ... 共 18 处，涉及 F841/F601/B010/I001/PLC0206/DTZ006/SIM103/SIM114
```

结果 `PulseInnerWorld.py` 的 **F 类错误从 0 涨到 7**。

**处置**：立即用 `.bak_b19ws` 全量回滚 7 个文件 → 确认 F 回到 0 →
**只带 `W291,W293,W292`（去掉 RUF100）重跑** → F 仍为 0，
并用 `diff -w -B` 逐文件确认「相对清理前**只有空白差异**」，7/7 通过。

**教训（已写入项目记忆）**：
> ruff `--fix` 带 `RUF100` 时，**绝不能配 `--select` 缩小规则集**。
> RUF100 只在「被启用规则」范围内判定 noqa 是否有用，配合 `--select` 会大规模误删。

2. **换行符被整文件转换 CRLF → LF**
   - 6 个 body 文件的行尾全部由 CRLF 变为 LF（写回时未保留原行尾）。
   - Python 运行无影响；但与第1批 brain 文件表现一致（brain 15 个也已是 LF），
     而 `organs/` 下仍有 53 个文件是 CRLF —— **项目本身是混用的**。
   - 风险：git 会把这些文件显示成「整文件变更」，代码评审困难。
   - 建议：由星轨统一裁决项目行尾规范（全 LF / 全 CRLF / 加 `.gitattributes`），一次性处理。

3. **剩余 27 条 W293** 为 unsafe fix，主动保留（见 3.1）。

4. **`# -*- coding: utf-8 -*-` 与 UP009 冲突**
   - 项目头部规范要求 coding 声明，但 ruff UP009 认为 Python3 下多余。
   - 建议后续把 `UP009` 加进 `ruff.toml` 的 ignore，否则会长期挂 7 条。

5. **`ruff.toml` 的 `line-length` 落在顶层而非 `[lint]` 下**
   - 任务书原文写「在 `[lint]` 下添加」，但 ruff 的 `line-length` 是**顶层配置项**，
     放进 `[lint]` 不生效。已按 ruff 规范放顶层，实测生效（E501 19668→1745）。
