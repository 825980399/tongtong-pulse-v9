## 二、刀1（P0）：修我自己上一批造成的静默失明

**起因**：384 刀2 依规清零 `pending_patches.json`，把**唯一**观察位
`o3_b31b31fee790d6e9` 一并删掉。此后 `watch_candidate` 对每个位都返 `not_in_pool`，
而那是**正常返回值**（不报警）⇒ 破零彻底静默失明。

### T0 三个前提都要修正

| 票面假设 | 实测 |
|---|---|
| 从 pending 里挑 1 个 O3 候选即可 | **pending 8 条里 O3 = 0**（全是 `runtime_verified` 的 patch_llm_*）⇒ 自愈必然走到"无候选"分支 |
| history 可作观察位来源 | history 仅 2 条 O3，都是 `wont_fix`/`approved` —— **已结案，永不再被派单** |
| （可选）从问题池挑 | 池里有 590 条 O3，但 `o3_<id>` 算法是 `sha1(file::method::issue_type::marker)`，与池 `dedup_key`（`sha1(file\|method\|issue_type)`）**不是同一个** ⇒ 不能拿 dedup_key 直接拼 |

### 两条设计取舍（都有反向守卫）

**① healthy 只看 pending，不看 history。**
破零观察的是「这个补丁会不会被**选中进沙箱**」，只有 pending 里的才会被派单。
history 里的已结案条目永远 `selected=0`，把它当"活着"会让自愈**永不触发**。
★我第一版正是这么写错的（返回 `healthy`），被 `test_..._history_only_is_not_healthy` 抓住。

**② 告警按 `changed` 去重。**
`_m351_watch_zero_break` **每拍派单都调**，无条件打 WARNING 会在一次停机里刷出成百上千条。

### 当前真实状态（如实）

```
self_heal_watch(真实 pending, 真实 history) → state=no_candidate
why=pending_has_no_o3_candidate  active=[2 个静态位]  pending=8
```

首次派单会打：

```
[385刀1] 破零观察位在 pending 里全失效且**无法自愈**: state=no_candidate
why=pending_has_no_o3_candidate active=[...] pending=8
⇒ 破零判据已失明，需人工补位（只告警一次，状态变化才再报）
```

**这是如实**：观察位确实没了。本刀保证「不再静默」，不是「凭空造一个观察位」。
恢复读数需要**人工补一个 O3 补丁进 pending**。

## 三、刀2（P1）：DL3 影子账本 Step 1

### 契约严格抄文档

字段来源 `docs/洞鉴与星轨对话/分析报告/洞鉴_385前置_内在模型方向审查_20261028.md`：
§6.2 输入 11 字段 / §6.3 输出 12 字段 / §6.4 账本四条纪律。
`signals` **保持嵌套**（原文写 `signals.l2`，压平会让"哪些是信号"看不出来）。

命名用 `DL3` / `dec_` 前缀 —— InfoField 已有 **L3 脉冲层**，撞名会让检索持续互误。

### 三条红线逐条有守卫

1. **不改执行行为**：`shadow=True` 恒真；`shadow_result` 的 `action` **默认 DEFER**
   （影子期出现 `EXECUTE` 会让账本像"在下指令"）。真记录执行时须显式传 `EXECUTE` + `rollback`（校验强制）。
2. **不新写判据**：只抄既有链路事实（洞鉴 §6.6）。
3. **开关默认关**：关时三个 `observe_*` 第一行就返回，不构造对象、不写盘。

### 性能：P99 从 43.65ms 压到 <5ms（票面单测③）

| 根因 | 改法 |
|---|---|
| 每次 `append` 全文件扫幂等（O(n²)） | 进程内 `_SEEN_IDS` 集合（有界 5000 FIFO） |
| 每次 `os.fsync`（10-30ms） | 去掉，只 `flush`（观测数据丢最后一行可重放；fsync 会把"每拍 1 条观测"变成"每拍一次磁盘同步"） |
| 每次 `import proc_gen` | 模块级 `_PG_CACHE` |

### 三个调用点

| 域 | 挂点 | 节流 |
|---|---|---|
| patch | `_m351_watch_zero_break` 观察循环（派单出口） | 无 |
| resource | `_collect_memory_pressure` 拍链尾（不新增调度点） | 每 30 拍 |
| chat | `PulseLung._m40_trace_call`（383刀2 影子之后，同一 LLM 收口） | 每 100 次 |

★resource/chat **只在有结果时才写 `_out`**，保证开关关时输出结构与改前逐字相同。
