## 二、刀0 · P-15 派单语义归因（L 圈判读地基）

### 2.1 钉死 `dispatched` 语义

`dispatched = len(_results)`，而 `_results` 只在 `dispatch_and_verify(_sandbox, _p)` 之后 append。
⇒ **`dispatched=1` 的含义是「已在沙箱执行并回写 1 条」**，既不是"仅选中"，也不是"应用到源码"
（sandbox 的 `motor.execute` 只验证、不落源码）。

### 2.2 因果链：为什么 4 圈 dispatched=1 但账本零变化

日志实测（`logs/pulse.log`，12:38—17:38 共 6 圈，逐圈同形）：

```
12:38:33 [分诊节拍] 触发自动分诊 dispatched=1 ... 
12:38:33 [行动面通电] 回扫=13 可疑=0 派单=1 结果=[('patch_1788891582_6ecc', False)]
13:38:34 [行动面通电] 回扫=13 可疑=0 派单=1 结果=[('patch_1788891582_6ecc', False)]
... 六个小时，**同一个 patch_id，结果全部 False**
```

三重原因，缺一不可：

1. **执行全失败**：`runtime_verify_result.detail` 实测为
   `[执行验证] motor.execute 失败: 代码包含危险关键字: getattr(, setattr(` —— 被沙箱 DANGEROUS_KEYWORDS 拦下。
2. **失败不回写状态**：`_write_back` 失败时只写 `runtime_verify_failure_reason`，**不动 `status`**
   ⇒ 候选池（`status in {runtime_verified, approved}`）每圈仍选中同一条 ⇒ **重复失败循环**。
3. **账本不是同一本**：派单写 `data/patches/patch_history.json`，**从不写** `expectation_ledger.jsonl`。
   烛微观测的"台账 84 条 / applied 76 未变"属实，但那本账**本来就不接收派单副作用**。

> 结论：`dispatched=1` 既不能证明自转，**也不足以证明有副作用**——它只证明"又试了一次"。

### 2.3 落地改动（`nucleus/evolution/patch_execution_dispatch.py`）

- 三拆计数：`dispatched_selected` / `dispatched`（保留旧口径＝已执行）/ `dispatched_applied` /
  `dispatched_verify_failed` / `blocked_reason` / `selected_source`
- 失败退出：`runtime_verify_fail_count`（成功清零），达 `_DISPATCH_FAIL_CAP=2` ⇒ 转人工，
  `blocked_reason=verify_fail_cap(N>=2)`，**不再进沙箱**
- 拦截环节指认：`select_for_auto_triage` 的拒收分布（status/risk/morph/trust/lifecycle/blast）
  经 `_LAST_TRIAGE_REJ` 暴露，压成 `blocked_reason=triage:blast=11,...`
- 留痕：`data/reports/patch_dispatch_trace.jsonl` 每圈一行（selected/applied/blocked/patch_ids）
- 节拍日志改三拆：`selected=%s executed=%s applied=%s blocked=%s`

### 2.4 实测（`tmp/p324_root/data/patches/` 隔离副本，真实历史 + 真实失败形态）

| 圈 | selected | executed | applied | blocked_reason | 该 patch fail_count |

⇒ 验收线达成：`blocked_reason` 非空时能指认拦截环节；**没有用 `dispatched=1` 冒充副作用**。

## 三、刀1 · 活体新图节拍排查（★重点）

### 3.1 结论：不是"节拍失效"，是**没有这个节拍**

生产唯一图落盘路径（全仓仅此一条）：

```

        ↓ 由 run_all_analyses 驱动

```

⇒ 11:37 重启后，下一次图落盘是**次日 03:00**。"12:37 后无新图"**是设计如此**。

三个被误读的事实，本批订正：

| 现象 | 真相 |
|---|---|
| `interval=3600` 生效却无新图 | 该 interval 属 **patch_execution_dispatch 派单钩子**，与图重建无关（323 刀6 混为一谈） |

| `ENABLE_STRUCTURE_RESCAN` 已登记 | 该键为 `False`，`_on_structure_changed` 首行即 `{"status":"disabled"}` ⇒ 事件驱动重扫也是关的 |

### 3.2 落地改动

- `SelfAwarenessEngine.py` 新增 `rebuild_graph_snapshot(now=None, force=False)`：
  走**同一把尺子**（`integrate_call_graph`），按 `CALL_GRAPH_REBUILD_INTERVAL_SEC`（默认 3600s，

- `config.py`：登记 `CALL_GRAPH_REBUILD_INTERVAL_SEC=3600.0`（单次全量 AST 实测 16.47s ⇒ 占空比 ≈0.46%）
