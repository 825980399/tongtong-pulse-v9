## 5. 环境坑（本会话真实踩过，每条都付过代价）

| # | 坑 | 正解 |
|---|---|---|
| 1 | `Edit` 工具改含 `{}` 的代码会**静默 no-op** | 用 python `content.replace` + `count==1` 断言 + 写盘 + 读回校验 |
| 2 | CRLF 行尾易被破坏 | 新/改文件须 `cr == lf` 且无 `\r\r\n`；改后与 `.bak_batchN/` 对拍；`docs/*.md` 惯例 LF（单独提交） |
| 3 | 补丁锚点行尾不匹配 | **锚点必须取自文件真实行尾**（本会话 `m314_patch1` 用 `\n` 拼 CRLF 文件，`index()` 直接失败） |
| 4 | cw2 静默 except 门禁 | 新 `except` 必须留痕：`silent_exc(where=…)` 或 `logger.debug`；能用 `isinstance` 就别用 try |
| 5 | `git commit` 不带 `-- <paths>` 会吞暂存区他方文件 | 必须显式带路径；未跟踪件先 `git add` |
| 6 | `tools/ci/` 不得与业务同批暂存 | CI 改动须标 `[ci-gate-change]` |
| 7 | 提交竞态 | `GATE_PARALLEL=1` 并发会被杀 → 前台 + `GATE_PARALLEL=0` |
| 8 | `index.lock` 残留 | 先 `tasklist` 查 git 进程，**连续两次为 0** 才可删 |
| 9 | 中文 / 含空格 pathspec | 路径整体加双引号；中文路径实测可正常提交 |
| 10 | 趋势门禁被污染 | **必须独占跑**：并发扫描会抬高 medium 计数（实测 44→49/52） |
| 11 | `safe-delete` 硬保护 | `rm` / `Remove-Item` 都被重定向到回收站，失败即拒兜底；大批 `.bak_*` **不要试图删**，交星轨处理 |
| 12 | bash 内嵌多行 `python -c` 会被破坏 | 补丁写成 `.py` 文件再执行 |
