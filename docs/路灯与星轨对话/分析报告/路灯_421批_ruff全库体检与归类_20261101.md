## 1. 先说口径（这三件事不看清，后面全部会误判）

### 1.1 这 5416 条不是"新增的债"，是**换了把尺子**

`ruff.toml` 里**没有 `select`**，只写了 `line-length = 120`、`ignore`（8 条）和两条
`per-file-ignores`（`PulseController` / `PulseLegs` 的 E402）。也就是说规则集取的是
**ruff 自己的默认集合**。而 ruff 0.16.5 的默认集合已经不是老版本那套 `E4/E7/E9/F`：

| 口径 | 启用规则数 |
|---|---|
| 本项目 `ruff.toml` 生效 | **406 条** |
| `--isolated`（完全忽略配置） | 413 条 |

⇒ 现在跑出来的是 UP/SIM/RUF/DTZ/PLW/FURB… 一整片"宽尺子"结果。它记录的是
**"如果按现代 Python 规范体检，这仓库长什么样"**，不是"最近谁写坏了"。

### 1.2 项目真正的门禁口径是 `--select F,E9`，而且只跑**改动件**

```
改动件口径  ruff --select F,E9 <本批改动文件>   → 绿（420 批 14 道门禁 rc=0）
全库口径    ruff --select F,E9 .                → ★ 2 条 F401（本次实测）
```

那 2 条在：

```
tests/test_m406_k4_patch_risk_gate.py:21   `time` imported but unused
tests/test_m407_k1_prompt_guard.py:21      `json` imported but unused
```

**这不是新债，是口径差**——`铁律速查.md` 的 293 条早就写过：「改动件的 lint 口径 ≠
全库门禁口径……收尾必跑一次 `ruff --select F .`」。这次是那个坑的实证：418/420 收尾的 14 项门禁
全是 rc=0，可全库 F 一直挂着这 2 条没人看见。10 秒可清，建议下次收尾顺手做掉。

### 1.3 仓库里那份"非 F 全量基线"已经过期 20 天，不能再当判据

`tools/ci/baselines/ruff_nonf_baseline.json` 生成于 **187 批（`b51260e`，2026-10-11 20:18）**：

| 项 | 基线（187 批） | 现在（421 批） | 变化 |
|---|---:|---:|---|
| non-F 总量 | 3522 | **5414** | +1892 |
| `UP031` printf 风格 | 552 | **2710** | **+2158** |
| `UP032` 可转 f-string | 801 | **89** | **−712** |
| `RUF100` 多余 noqa | 558 | 431 | −127 |

`UP031`↑`2158` 与 `UP032`↓`712` 的反向漂移有个很朴素的解释：**中间有人跑过 `ruff --fix`**
（`UP032` 是 safe fix，被批量改掉了），而 **`UP031` 只支持 unsafe fix**，所以一处没动、
反倒被 233 批新代码（尤其 `tests/`）持续推高。

⇒ 结论：**这份基线描述的已经不是当前仓库**。要么重锚，要么 retire。在重锚之前，
请任何人不要拿它当"应该只有 3522 条"的判据（那是拿旧地图找新路）。
