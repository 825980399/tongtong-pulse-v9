## §2 刀1：三个检测器

### 2.1 做了什么

三条规则**不是新发明**，逐条对齐 `nucleus/self_inspector.py` 的同名诊断器，常量同名同值：

| issue_type | 判据（AST） | 与诊断侧的关系 |
|---|---|---|
| `periodic_task_no_reentry` | 方法体出现周期信号（调用名以 `_schedule_` 开头 / `Timer(...)`），且**任何标识符**都不含 `_in_progress`/`_is_running`/`_busy`；`__init__` 等构造器不判 | 同源 `_check_periodic_task_no_reentry` + `_M356_NO_REENTRY_SKIP` |
| `non_atomic_write` | 存在 `open(...)` 且模式串含 `w`；整块未出现 `.tmp`/`tempfile`/`os.replace`/`os.rename` | 同源 `_check_non_atomic_write` |
| `cross_module_singleton_call` | `get_xxx().method(...)`（接收者是 `get_xxx()` 的返回值）；`self.get_x().y()` 天然不命中；契约三件套豁免；片段内能解析出 `get_xxx` 来自非 `organs.*` 时豁免 | 同源 `_check_cross_module_singleton_call` + `_M356_CONTRACT_SINGLETONS` + 374刀5 来源分档 |

**有意保留的三处差异**（方向都是"复现侧更准"，已量化在 2.3）：

1. 诊断侧用正则扫**原始文本**，不认注释/文档串 ⇒ 注释里写一句 `open(x,'w')` 或 `_schedule_next_beat()` 就被判缺陷。复现侧走 AST，注释天然不参与。
2. 诊断侧的 `open\(([^)]*['\"])w['\"]` 里 `[^)]*` 遇嵌套括号就断 ⇒ 真正的 `open(os.path.join(a,b), 'w')` 反而**漏报**。
3. `cross_module_singleton_call` 的诊断侧要读目标文件做来源分档；复现侧是纯函数、只吃代码片段 ⇒ 片段外的 import 解析不出时**仍计入**（与诊断侧"来源解析不出仍报"同向），偏差方向是"多算"。
