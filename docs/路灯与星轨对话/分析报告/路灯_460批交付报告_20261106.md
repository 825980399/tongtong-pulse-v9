## §1 裁决变更：从「有人拦」到「可挽救」

星轨的裁决把安全模型换了一套，这是本批最重要的变化，单列说明：

**旧模型（我上一轮建议）**：自动出候选补丁 → 人工裁决 → 应用。
**新模型（本批）**：证据准入 → 曈曈自裁决 → 自动应用 → 应用后验证 → 失败真回退 → 结构化经验回灌 → 同类冷却。

「不担心改错」不是取消边界，而是把边界从**人**移到**机制**。本批实际生效的六层：

1. 八闸原边界一字未动：`blast<=1`、`single_file`、`not_core`、`risk=low`、`trust`、`confidence=high`；
2. 447 边界一字未动：每日最多自动批准 1 条；
3. 自裁决额外边界：影响面 ≤1 文件、**证据不全不放行**、**快照失败不放行**；
4. 改前按字节快照（含行尾与 sha256）＋改后 `ast.parse`（可注入真单测）；
5. 失败真回退：`restore_snapshot()` 写回并双端校验，再以 `PatchManager.rollback_patch()` 作二级兜底；
6. 同类错误软硬双保证：结构化 `error_type` 进 452 提醒段（软）＋ 连续同类 2 次进 24h 冷却、冷却期内不再派单（硬）。

> 关键取舍：**不可判定 ⇒ 不放行**。`false_pass`（改前复现不出）既不算通过也不算失败，
> 而是 `inconclusive` 留在队列补证重判，配 `M460_MAX_REPRO_RETRY=3` 上限（铁律55）。
> 这保证「敢于向前迈进」不会退化成「闭着眼放行」。

## §2 四刀落地

### 刀1 · 证据准入门（P0）

新增旁路模块 `nucleus/evolution/self_verdict.py`（两段式，不新增第二个写口）：

- `collect_evidence(patch)` 一次调齐三个既有探针，把 `reprobe_verdict` / `problem_gone` /
  `baseline_errors` 回填到**副本**，专治八闸这两条恒拿不到值：
  `baseline_positive` 要 `>0`、`problem_gone_true` 只认显式 `True`。
- `approval_bridge.maybe_approve_scoped()` 在八闸前接 `prepare()`、应用后接 `finalize()`；
  `note_approval_trace()` 仍收原 patch，`decision()` 一个字没改。
- 三道降级：总闸关 / 准入未过 / 依赖异常 ⇒ 用**原 patch**，逐字节回到 460 前行为
  （`ENABLE_M460_SELF_VERDICT=False` 可 A/B 复现旧现场）。

### 刀2 · 三态自裁决（P0）

`verdict()` 返回 `apply / reject / inconclusive`，判据全可留痕：`true_pass` + `problem_gone is True`
+ `baseline_errors > 0` + 影响面合规 + 八闸全过 ⇒ `apply`；`partial_fix` ⇒ `reject`；
`false_pass` / 不可判定 ⇒ `inconclusive`（不丢弃，重试上限 3）。

### 刀3 · 改前留痕与真回退（P0）

`snapshot_before()` 逐文件按**字节**存 `NNN.bin` + `meta.json`（`sha256` / `eol` / `crlf` / `bare_lf`）；
`restore_snapshot()` 真写回并对快照与落盘各校验一次 sha256。
`finalize()` 在应用成功后跑 `verify_after_apply()`，失败即触发回退——**这是 447 注释答应过但从未执行的一步**。

### 刀4 · 问题单准入 + 失败经验回灌（P1）

`make_ticket()` 复用 `audit_problem_pool.make_dedup_key`（sha1、弃行号、路径归一），
15 分钟聚合窗口内同键合并计数不重复派单（457 教训：Playwright `page_load` 超时整天在报，
逐条 ERROR 派单会刷爆队列）。
`record_lesson()` 把失败写成**机器可分类**的 `self_verdict:<code>`（不是自由文本——
459 批 229 条作废记录只有 1 种 reason 模板、171 条 `issue_type=None`，分派器拿不到输入，同型教训）；
连续同类 2 次 ⇒ 写 `cooldown` 留痕，`make_ticket()` 在冷却期内直接拒单。

> 收紧条件：八闸正常拒绝**不写经验库**（那不是「改错了」，写进去会灌满 452 提醒段、
> 稀释软保证）。只有「改后验证失败」和「反复补证耗尽」两条才记经验。

## §4 六个坑（给下一个人）

1. **★★探针回填绝不能覆盖调用方已有的更强证据。** 首轮接线把 447 三套顶红：
   探针「如实」返回 0，把构造好的 `baseline_errors=2` 冲掉了。契约必须是
   **只补缺失**，且 `verdict()` 要看「合成后」证据而不是探针原始值。
2. **★★注释不等于实现。** 447 写着「失败自动回滚」，函数里一次 rollback 都没有；
   读闭环先看有没有**执行**，别只看注释和留痕。
3. **★「缺少机制」和「机制没接线」是两回事。** 本批三个探针 + 映射表 + 回退接口 +
   经验库提醒段全都在位，真实缺口只有「审批前没人统一调」。取证要先 grep 完成日志与调用点。
4. **★记忆会过期。** 开工时 HEAD 已被星轨并发推进 3 笔、开关从 False 变 True、
   348 条删除已被归档提交清掉。任何「当前状态」都必须现场验，不能照抄上一份报告。
5. **★新增 `_out` 字段要查全等断言。** 接线前先 grep 既有测试有没有 `assertEqual(整个 dict)`；
   本批 447 全是逐字段断言，才敢加 `self_verdict` 键。
6. **★结构化 `error_type` 是「吸取经验」的前提。** 自由文本会让 `build_reminder` 的
   按类型计数退化成「229 条同一句话」，提醒段等于没写。
