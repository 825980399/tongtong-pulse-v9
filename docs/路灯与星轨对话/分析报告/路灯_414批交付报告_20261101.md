### 6.3 ★首拍挖出一个真 bug：权重被乘了两次

`top_hits` 把 `_s * _w` 存进 `_scored` 元组，输出时又算 `score_weighted = _s * _w`：

```
原始分 7.0，TEMPLATE_WEIGHT = 0.3
  score          = 7.0 × 0.3 = 2.1      ← 这里已经乘过一次
  score_weighted = 2.1 × 0.3 = 0.63     ← 又乘一次
实际生效权重 = 0.3² = 0.09，不是设计值 0.30
```

**为什么 412/413 都没发现**：那时生产池 `is_template` 一条都没有，`_w` 恒为 1.0，平方了还是 1.0。
而 412 单测 `test_33` 的断言 `score_weighted == score * TEMPLATE_WEIGHT` 恰好**兼容**这个错误实现
（因为 `score` 本身就是加权分）—— 典型的「断言钉了错误实现，能同时通过对的和错的」。

**修法**：`_scored` 只存**原始分**，排序时现算加权分，输出 `score`=原始分 / `score_weighted`=原始分×权重。

**修后实测**：

| 条目 | 修前 score | 修前 weighted | 修后 score | 修后 weighted | 设计值 |
|---|---:|---:|---:|---:|---:|
| 模板（原始 8.0） | 2.4 | 0.72 | **8.0** | **2.4** | 8.0×0.3=2.4 ✓ |
| 模板（原始 7.0） | 2.1 | 0.63 | **7.0** | **2.1** | 7.0×0.3=2.1 ✓ |
| 非模板（原始 7.0） | 7.0 | 7.0 | 7.0 | 7.0 | 不变 ✓ |

排位变化：标记前模板占据前 5，标记后全部掉到非模板之后 ✓（降权真的影响排序，不是只加字段做样子）

补判据 `tests/test_m414_k4_weight_once.py`（4 条），用 **`score_one()` 的原始分**当基准
绕开 412 test_33 的循环论证 —— 那条断言对 0.3 和 0.09 都能通过，分辨不出来。
