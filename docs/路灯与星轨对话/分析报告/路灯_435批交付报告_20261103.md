## 4. 刀1：写放大倍数降了吗？

**改动**：`_keep_backup` 按文件大小分级——
- `size <= 1 MiB`（配置/台账类关键小文件）→ 只保留 **1 代** `.bak`，清掉更早的 `.bak.1/.bak.2`；
- `size > 1 MiB`（快照/日志类大文件）→ **不备份**（0 代）；
- `ENABLE_M435_BACKUP_TIER=False` → 逐字回到原 3 代滚动（零行为变化）；阈值可 `M435_BACKUP_SMALL_MAX_BYTES` 覆写。

**活体数据**（隔离目录 + 真实 `safe_write_json`）：

```
[刀1] 小文件(100KB) 写 5 次 → 备份文件: ['small.json.bak']   ← 1 代
[刀1] 大文件(2MB)  写 3 次 → 备份文件: []                    ← 0 代
```

**写放大**：
- 小文件：4×（写 1 + copy2 3）→ **2×**（写 1 + copy2 1）；
- 大文件：4×（写 1 + copy2 3）→ **1×**（不备份）。

**★如实说明**：盘上 `_keep_backup` 产生的备份**都是小文件**（最大 131KB，34 个文件共 1.3MB —— 另两个 805MB/485MB 的 `.bak` 是快照轮转，不走 `_keep_backup`）。所以本刀的真实收益是「小文件 4×→2×」，未达到任务书「≤1.2×」的字面值；若要对小文件也做到 1×，需把 `M435_BACKUP_SMALL_MAX_BYTES` 调到 0（放弃所有备份）——**不建议**，那是拿可回溯性换指标。

## 5. 刀2：trim 还全量读吗？

**改动**：
1. `_trim_pair_file` **不再 `readlines()`**：新增 `_m435_tail_scan` 反向 block 读（1 MiB/块，`bytes.count`/`bytes.split` 全走 C 实现），一次拿到「总行数 + 保留起点」，再从起点**分块复制**（4 MiB/块）到 tmp；
2. `_backup_pair_file` 改 **`os.link` 硬链接**（零拷贝）；硬链接不可用时回退 copy2（行为与改前一致）。

**活体数据**（60 万行 / 15.3MB 真实文件，隔离目录）：

```
[刀2] trim 耗时 0.033s → 剩余 450000 行（cap=50万,low=45万）；备份 15.3MB；copy2=0 次 link=1 次
```

**A/B 对比**（同文件同口径，旧实现从 `.bak_batch435` 加载）：

```
旧(readlines+copy2): 15.3MB → trim 0.201s，剩余 450000 行，copy2=1 次
新(尾部读+硬链接): 15.3MB → trim 0.030s，剩余 450000 行，copy2=0 次   ← 快 6.7×
```

**★施工中发现并修正的性能陷阱**：首版 `_m435_tail_scan` 用 Python 逐字节循环数换行符，A/B 实测 **0.899s vs 旧 0.215s（慢 4 倍）**——省了内存却拿 CPU 换了。改用 `bytes.count` + `bytes.split`（C 实现）后降到 0.030s。

**IO 模型**：改前 ≈ 读 15 + copy2(读 15 + 写 15) + 写 tmp 14 = **59MB**；改后 ≈ 读 15（仅计数）+ link 0 + 读尾部 14 + 写尾部 14 = **43MB**（降 28%）。

**残留 `.trim.bak` 清理**：现场残留 `data/monitor/pulse_pairs_20261102.jsonl.trim.bak` = **148.2MB**（11-02 的旧文件，属历史遗留）。**未自动删除**——按「先扫描 → 出清单 → 隔离/备份 → 可回退」纪律，清单在此，建议移入 `data/_archive/` 或直接删除（由你裁决）。
