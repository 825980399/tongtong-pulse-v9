## 一、为什么不删（先说结论）

任务书允许两条路：「完全没用的 → 删」「有设计意图但没接上的 → 加 TODO 说明为什么留着」。
本批全部走**第二条**，依据是**已有裁决在先**：

> 第 157 批 `C-3` / `C-4` / `C-6` / `C-9` 四张票，经 `Q157-2`、`Q157-3` 裁决，
> 对这些模块的执行结果是 **③"明确弃用标注 + 登记拟接线批次"**，而不是 ②"删除"。
> 原文（`docs/分析报告/archive/烛微_第157批前置分析_20260930.md:118`）：
> 「`SelfModel` = **③明确弃用标注** … `Interoception` = **③** … `OrganCoordinator` = **②删除或③**（取决于 Q157-3）」
> 实际落地选了 ③。**398 批没有授权推翻 157 批的裁决**，因此不删。

另有一条独立理由：这些模块平均 300 行、类结构完整（不是空壳代码碎片）。删除是不可逆的设计丢失，
而"删除能省下的收益"（少量磁盘与阅读干扰）远小于"重建要重做一遍调研"的成本。

## 三、核实方法（可复现）

```python
# ① 生产面/测试面双扫，收集所有 import 的任意路径段
for node in ast.walk(tree):
    if isinstance(node, ast.Import):       imported |= {段 for 每个 name.split('.')}
    elif isinstance(node, ast.ImportFrom): imported |= {段 for module.split('.')} | {每个 asname}

# ② 模块基名不在 imported 里 ⇒ 疑似孤儿
# ③ 三重交叉排除误判：
#    - 字符串字面量命中（importlib / __import__ / 停机注册表 / 子进程命令行）
#    - 顶层符号（class/def/赋值名）被别处按 Name/Attribute 载入
#    - config.py / main.py / 5960 个 yaml·json·toml 里的模块名或类名
```

**三重交叉的实际命中全部是审计产物**（`data/cc_baseline.json`、`god_file_baseline.json`、
`data/reports/audit/audit_*.json`、`data/reports/code_review/*.json`、
`tools/ci/baselines/silent_except_baseline.json`）—— 这些是**扫描器写出来的报告**，
不是"谁在用这个模块"的证据，不能据此判活。

唯一真实命中是 `search_scheduler` 在 `main.py` / `config.py`（见 C 类 #17）。
