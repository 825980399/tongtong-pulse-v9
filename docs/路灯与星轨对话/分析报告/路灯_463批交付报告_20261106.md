## §2 三刀落地

### 刀1（P0）冷却判据分级 · `cooldown_policy.py`

纯函数 `classify(issue, local_fixable_types, high_risk_types)`：

| 判定 | 动作 |
|---|---|
| 高危安全拦截 | `cool`（保持长冷却，防线不动） |
| 本地规则白名单内 | `skip_cool` |
| **有 file+method 且 type 在 446 检测器覆盖表内** | **`skip_cool`** |
| 无代码定位的日志类 | `cool`（正常冷却） |
| 其他代码类 | `cool_short`（300s，约一轮循环） |

接线到登记循环，并加 `ENABLE_M463_NO_REFRESH_COOLDOWN=True`：**已有未过期冷却不再刷新 deadline**，这是「到期解冻恒为 0」的直接修复。总闸 `ENABLE_M463_COOLDOWN_POLICY=False` ⇒ 逐字节回到旧 `_cooldown_classify()`，可 A/B 复现。

### 刀2（P0）强制复检解冻

同一指纹累计被冷却跳过达 `M463_FORCED_RECHECK_HITS=3` 次 ⇒ 强制放行一次复检并清零计数。判据提成纯函数 `should_force_recheck(hits, need)`，冷却扫描与单测共用同一口径；内存级计数，重启即一次天然复检。日志追加 `／463强制复检N个`。

### 刀3（P1）候选池优先级 + 修复漏斗留痕

- `priority()` 排序：本地规则可修(0) → 检测器可复现代码类(1) → 其他代码类(2) → 日志类(9)，确保有限名额给能出补丁的问题。
- `repair_funnel.py`：每轮把 `candidate / filtered / cooldown_skipped / forced_recheck / admitted / planned / processed / submitted / cool_skipped_by_policy / cooldown_registered` 十个读数 append-only 落盘，下一轮不必再从滚动日志里拼（344 批作废台账的同型教训）。
- 四处接线都在 `SafeEvolutionExecutor.repair_with_distillation()` 内：`try/except + silent_exc` 包住，**失败绝不影响修复主流程**。

## §5 三个坑

1. **★★「不可修复」不能等价于「不在本地规则白名单」。** 446 检测器能复现的代码类问题全部被这个等价关系误伤；判据必须问「有没有可复现的修复路径」。
2. **★★每轮重登记 = 永不过期。** 实盘「到期解冻 0 个」不是 TTL 太长，是 deadline 每轮被推到 `now+TTL`。禁止刷新比调小 TTL 更根本。
3. **★内联判据要提成纯函数。** 强制复检若内联在扫描里，单测只能复制一份口径，日久必然漂移；`should_force_recheck()` 单一口径可测。

另：本批首轮单测有一条写成 `assert X is True or X is False` 的恒真断言，按「判据要有判别力」已改为精确断言。
