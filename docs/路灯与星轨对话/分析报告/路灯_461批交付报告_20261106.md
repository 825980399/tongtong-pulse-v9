## §5 五个坑

1. **★★「软提醒」不等于「不再犯」。** 459 的提醒段、445 的 `require_full_def` 都写了，但同一错误仍作废 59 次：前者 LLM 可不读，后者只接一条生成路径。硬保证必须是**在写入口把条目剔掉**。
2. **★★「只补缺失」契约会挡住真实修复。** 460 为防「0 覆盖 2」定了严格契约，结果生成侧显式写的 `None` 键让探针补不进去。461 改成「只升级不降级」，两边都保住。
3. **★改 CRLF 文件用 Python 脚本的隐式字符串拼接会写坏一行代码**（本批首轮 `evidence` 两行被拼成一行 ⇒ `SyntaxError`）。处置：从备份恢复 + 只重跑那一处；列表元素之间必须显式逗号，多行 f-string 每行都要闭合引号。
4. **★判「闭环有没有跑通」要看**「有没有产出快照/回退」**，不是看代码在不在。** 460 全部机制在位，实盘仍是 0 次。
5. **★`data/reports/` 是活体持续写入的**，判污染要按「与本批相关的文件」计数，不能拿全仓文件数当证据。
