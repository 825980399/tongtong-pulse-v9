## 4. 刀1：L1 池还有 >1s 长任务吗？

**改动**：`_review_own_code_issues` 的「全库扫描 + 补丁生成」整段下沉到**专用低优先级后台线程**（`_code_review_worker`，`threading.Thread(daemon=True)` + `_m416_set_thread_lowest` 降优先级 + 单飞）。

**★关键纠偏（任务书未明示的连带风险）**：任务书要求「打开 force=True」。但核实发现 `submit_deferred_scan` 的线程体 `_m416_scan_body` **只扫描留痕、不回传 issues、不生成补丁**，若直接 force=True，周期审视的「发现→日志归因→参数审计→工具检查→运行时审查→补丁生成」整条闭环会**永久停摆**（`started=True` 时 `_review_own_code_issues` 直接 return）。故未采用裸 force=True，改为「整段审视下沉」，既消阻塞又不丢闭环。

**验证**：隔离环境 `_review_own_code_issues` 提交耗时 **0.0000s**（不再同步跑 10.6s 扫描），后台线程启动。重启后应观察：adaptive/前台池无 >1s 长任务；`_m416_scan_body` 仍保留 416 刀启动窗口内的留痕扫描语义（窗口外走低优先级线程同步扫描+补丁生成）。

## 5. 刀2：日志还阻塞业务线程吗？

**改动**：`_init_root_logger` 里 SafeRotatingFileHandler 不再直挂 root，改为 `QueueHandler(queue)` 入队 + `QueueListener` 单线程落盘。三个连带点已处理：
1. **树外 logger 桥**（356 刀 NUL 空洞事故点）：原按 `isinstance(_h, SafeRotatingFileHandler)` 遍历 root.handlers 复用主 handler，root 换 QueueHandler 后该查找会落空、自建直写 handler 复现 NUL 空洞 ⇒ 改为复用模块级 `_FILE_HANDLER`，且树外 logger 也挂 `_QUEUE_HANDLER`（入队）。
2. **`os._exit` 跳过 atexit**：main.py 退出路径显式 `flush_queue_logs()`。
3. **filter/formatter**：PulseFormatter/SanitizingFilter/LogAggregationFilter 仍挂 file_handler（QueueListener 唯一持有者），格式化语义不变。

**验证**：root 挂 QueueHandler=True、不再直挂 SafeRotatingFileHandler；200 条日志入队 **0.003s**（入队非抢锁落盘）；flush=True 日志落盘。重启后应观察：L0 看门狗 logging_io 卡点消失、业务线程不再被日志写盘阻塞。
