# 475 批 · 角色翻转第一期：曈曈主笔草稿的影子旁路

日期：2026-11-07　｜　提交：本笔代码提交　｜　分支 master，未 push

## 一、这一刀要解决什么

用户定义的长期目标：**把「外包 LLM 生成 `modified_code`」变成「曈曈自己处理、LLM 辅助」**。
474 批交付的是地基（能力内核 + 3 个自有算子 + 结构化台账 + 观测节拍），
但**补丁生成主链路仍由 LLM 主笔**，曈曈只做生成后的缩进补偿。

本刀是**角色翻转的第一步**：建立「曈曈自己出草稿」的通道，以及
「曈曈草稿 / LLM 产物」的 A/B 对照度量。**不替换任何东西。**

## 二、实现（4 个文件）

| 文件 | 改动 |

| `nucleus/reasoning/PatchManager.py` | `save_pending_patch()` 保存前挂一行旁路调用（8 个调用点的唯一入口） |

### 两个必须分清的维度

- **`self_draft`（主笔）**：从 `original_code` 出发跑自有算子，**不看 LLM 产物**。
  命中并真的改了代码 ⇒ `covered=True`，这一题曈曈能自己写。
- **`self_revision`（修订）**：以 LLM 的 `modified_code` 为输入跑算子 ⇒
  量「LLM 产物里有多少需要曈曈把关」，即「LLM 辅助、曈曈处理」的实证。

### 诚实边界（不假装会写）

第一批 3 个算子只会修**结构性缺陷**（缩进层级、docstring/类型注解、裸静默 except），
不会实现业务逻辑。所以覆盖不了就明确登记 `external_needed=True`，
绝不编造一份「假草稿」。这正是按 `error_type` 分桶收敛的度量基础。

### 安全契约

- **只读 patch**（内部深拷贝），绝不改任何字段/状态/判据；
- 产出只写 `data/autonomy/patch_draft_shadow.jsonl`（`/data/` 已 ignore）；
- 不碰八闸、审批、apply、自重启、日限额、冷却；
- 任何异常 `silent_exc` 吞掉，绝不阻断入池；
- 基准独立：`_code_metrics()` 直接用 `ast.parse` + 文本对两边用同一把尺，
  **不拿算子的 `verify()` 当基准**（铁律 30）；
- 内核不外联任何 LLM/HTTP（铁律 304，AST 门禁守着）。

## 三、第一张 A/B 对照表（基于 4 条真实补丁，只读离线计算，不写生产台账）

| 补丁 | issue_type | 主笔覆盖 | 修订覆盖 | 检出的 LLM 缺陷 | body 缩进 LLM→修订 | 裸 except LLM→修订 | 修订语法 |
|---|---|---|---|---|---|---|---|
| `patch_llm_1794030546_c3e2` | non_atomic_write | — 需外部 | ✅ | indent_level_align | 12 → 8 | 0 → 0 | OK |
| `patch_llm_1794030764_3274` | periodic_task_no_ree | — 需外部 | ✅ | indent_level_align | 12 → 8 | 0 → 0 | OK |
| `patch_llm_1793968480_715f` | non_atomic_write | — 需外部 | ✅ | silent_exc_backfill | 8 → 8 | 1 → 0 | OK |
| `patch_llm_1794027875_aed5` | periodic_task_no_ree | — 需外部 | ✅ | indent_level_align | 12 → 8 | 0 → 0 | OK |

**结论：主笔 0/4（业务逻辑修复，诚实登记需外部），修订 4/4。**

四条 LLM 产物全部带结构性缺陷：3 条方法体多缩 4 格（12→8），
1 条引入裸 `except: pass`（1→0）。这**正是 473 批刀22b / 刀22c 我两次手工收口的问题**
——现在这套动作已被编译成算子，能自动检出并修订，且修订后全部 `ast.parse` OK。

也就是说：**「曈曈主笔」还不会，但「LLM 出草稿、曈曈把关修订」已经具备可执行能力**。
这是角色翻转最现实的第一段路，也验证了「把经验编译成算子」这条路线是对的。
