## §2 刀1：trust 从 30 到 ≥60

### 2.1 加分模型（任务书原文逐条落地）

| 规则 | 分值 | 判据 |
|---|---|---|
| `risk_low` | +20 | `risk_level ∈ {低, low}` |
| `single_file` | +10 | 目标文件数 == 1 |
| `blast_le_1` | +10 | blast（同文件数）≤ 1 |
| `baseline_positive` | +10 | `baseline_errors` 是数字且 > 0 |
| `problem_gone_true` | +20 | `problem_gone is True` |
| **合计** | **70** | 够 60 那道门 |

★三个口径选择，都写在代码注释里：
1. **不设基础分** —— 任务书说"加起来应该能到 ≥60"，那就是 70，不是 40+70=110。
2. **只升不降** `max(旧值, 新值)` —— 信任分是多面共用字段；证据不全就把 40 压到 20，会顺手关掉本来能过的自动应用线。
3. **证据不全 ≠ 更低分** —— 五项全不成立时新分为 0，`max` 保住旧值，不把"没证据"变成"更可疑"。

## §3 刀2：problem_gone 从 None 到 True

### 3.1 它到底怎么流转的（任务书的疑问，逐层回答）

```
生成侧:  patch 字典里没有 problem_gone 字段（全仓 87 条 history 里 0 条有这个键）
应用时:  EvolutionEffectVerifier.verify() 把判定写进
         data/evolution/effect_verify.json → verdicts[id].dims.problem_gone
         —— **只写台账，不写补丁顶层**
审批时:  approval_bridge.decision() 读的是 patch["problem_gone"]（顶层）
时序:    verify() 在 apply_all_pending 里（**应用之后**）；审批在 save_pending_patch 之后、
         apply 之前 ⇒ 对新件，台账里**没有**它的记录（与 pending 交集 = ∅）
```

所以"补丁顶层没有这个字段"不是漏同步，是**从来没人写**，且任务书指的那个源在时序上取不到。

### 3.2 本批的取数顺序（三级，先强后弱，每级都记来源）

| 优先级 | 源 | 说明 |
|---|---|---|
| ① | 顶层已有显式布尔 | 人/上游判过就不覆盖（`source=existing`） |
| ② | `effect_verify` 台账 `dims.problem_gone` | 只对**重新入队/已应用过**的件有效 |
| ③ | **静态复现** `active_reprobe(original, modified)` → `_M375_PROBLEM_GONE_MAP` | `true_pass ⇒ True`、`partial_fix/ineffective ⇒ False`、`false_pass/无法解析 ⇒ None` |

★**语义要说清**（也写进了 config 注释）：③ 给的 `True` 是「**修复后的代码里静态检测不到该缺陷**」，
不是「运行时问题消失了」。这正是八闸⑤要的"显式为真的证据"；而且这是 375刀4 已经采信的**同一条映射**，
本批没有新造口径，差别只在"应用前先算一次"。

### 3.3 活体：`approval_bridge` 现在能读到 True 了吗？——能

```
刀2: problem_gone=True  source=reprobe  verdict=true_pass
      reason=复现实测：修复前复现、修复后完全消失
八闸⑤ problem_gone_true: PASS  problem_gone=True（只认显式 True）
```

单测 `test_decision_reads_top_level_true` 直接钉住"同步前 False → 同步后 True"。
