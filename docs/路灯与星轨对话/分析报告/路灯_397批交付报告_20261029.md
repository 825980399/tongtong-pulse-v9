## 二、T0 核实：票面与实测的三处差异

### ① 刀1：「`_frequency_codec_cy` 已实测缺 `_md5_int`」在本环境无法复现

重编**之前**实测：

```
>>> from nucleus.pulse import _frequency_codec_cy as m
>>> m._md5_int(b'hello world') == int(hashlib.md5(b'hello world').hexdigest(), 16)
True        # 空串 / 'a' / 'hello world' / 中文 / 1000 字节，5 组全一致
```

所以"MD5 C 化收益当前为 0"这半句**不成立**。pyd 早于 pyx 却是真的（6 个全部，5 个同秒 09-05 00:53，pyx 是 09-06 15:10 / 09-20 21:36）⇒ 重编仍有价值，但判据不能只盯一个符号。本批把判据升级为**符号级全量比对**（`.pyx` 里每个 `def`/`cpdef` vs 实际导出）。

### ② 刀2：「367 → 409」的 367 对不上，且只改排除集到不了 409

本机改**之前**实测覆盖 **394**，不是 367。409 − 394 = 15：

| 缺口 | 数量 | 成因 |
|---|---|---|
| `nucleus/data/` 6 个 | 6 | **排除集**：裸名 `"data"` 连带剪掉深层同名目录 |
| `hardware/` 7 个 | 7 | **扫描范围**：`_DEFAULT_SCAN_DIRS` / `config.CALL_GRAPH_SCAN_DIRS` 没列 |
| `config.py` | 1 | 同上 |
| `pulse_doctor.py` | 1 | 同上 |

也就是说只改"排除匹配方式"只能 394 → 400。本刀**两处一起改**才到 409。

### ③ 刀5：「资源/风险两域」—— 契约里没有 "risk" 域

`contracts.SCOPES` 闭集是 `("chat", "patch", "resource", "schedule")`，**没有 risk**。风险体现为 **patch 域候选的 `risk` 等级**。本批**不开新域**（改闭集会连带影响 `validate()` 与其它域），"资源 + 风险"落到实现上 = `resource` + `patch`。

### ④ 刀4 的数字恰好对上（顺带解释了 13 是怎么来的）

按 AST 扫生产面 `getattr(<cfgvar>, "NAME", default)` 得到 **15 个**无赋值键：
11 个 `ENABLE_*` + `PENDING_GRADED_PILOT_ONLY` + `ENABLE_COLD_STORAGE` = **13 个开关**（正好票面），
另 4 个是**阈值/路径参数**（同病，一并补齐并单列）。

| 闸 | 读什么 | ⇒ would_be | reason_code |
|---|---|---|---|
| 用户覆盖 | `constraints.user_override` | APPROVE（覆盖一切，不算否决） | USER_OVERRIDE |
| 禁改文件 | `forbidden_files` 命中 `evidence_ref` | REJECT | POLICY_BLOCK |
| 风险等级 | 候选 `risk` ≥ high | REJECT | POLICY_BLOCK |
| 资源临界 | `rss_mb` ≥ 9000 | REJECT | RESOURCE_PRESSURE |
| 资源偏高 | `rss_mb` ≥ 6000 | DEFER（`DEFER_ONE_TICK`） | RESOURCE_PRESSURE |
| 预算耗尽 | `llm_budget` ≤ 0 且候选成本 > 0 | DEFER | BUDGET_EXHAUSTED |
| 无候选 | — | DEFER | EVIDENCE_MISSING |

排序：否决沉底，其余 (风险升序, 成本升序, 优先级降序)。
两条防御：未知风险按 0 处理（**不是**最危险，否则一次字段写法变更会把整个域 REJECT 掉）；`rss_mb` 取不到返 `None` 不是 0。

★**过渡期红线：`action` 仍是 DEFER**，真裁决只在 `arbitration.would_be`。理由：一旦 action 出现 APPROVE/REJECT，账本看起来像"L3 已经在下指令"，而执行器此刻**必须忽略它**——这种错位比"没有裁决"更危险（396 刚修过同型：读数看起来在自愈，实际在掐链）。

实测账本里同时出现 `APPROVE`（resource 正常）与 `REJECT`（patch 高风险），`action` 一列全 DEFER；chat 域 `arbitration` 为空字典（只写不判）；开关关时仍零写入。

## 五、踩到的坑（本批新增，值得记）

1. **MSVC 目录存在 ≠ 编译器可用**：`Microsoft Visual Studio\18\` 是空壳，只有 `BuildTools\VC\` 骨架，没有 `cl.exe`/`vcvarsall.bat`。判断工具链要 `which cl` + `find vcvarsall.bat`，**不能只看目录在不在**。
2. **MinGW 通道可用但要实测**：distutils 的 `--compiler=mingw32` 能编出 Python 3.12 可 import 的 .pyd，但这是 ABI 问题，不能靠"应该可以"，必须编→import→调用三步都过。
3. **"改默认槽位没改生效值"第 5 次**：`_DEFAULT_SCAN_DIRS` 改了没用，`config.CALL_GRAPH_SCAN_DIRS` 才是运行期值。
4. **排除集里的"冗余项"会在范围扩大后变成杀手**：`hardware` 在排除集里躺了很久无害，一把 hardware 纳入扫描范围就整段剪掉 6 个文件。
5. **cw2 连 `except ...: continue` 和"只做赋值"都算静默** —— 测试文件与 `tools/` 下脚本同样受管。
6. **正则扫源码会把 docstring 里的示例当真代码**：`patch_execution_dispatch.py` 注释里有 `getattr(cfg,'X',default)`，据此报出一个不存在的"幽灵开关 X"。改用 **AST** 只看真实 `ast.Call` 节点（铁律 227 同型）。
7. **`from nucleus.self_awareness import CallGraphAnalyzer` 拿到的是类不是模块**（包 `__init__` 重导出），要模块里的私有函数必须走 `sys.modules[...]`。
