## 三、为什么「不该有→撤订阅」是 0 条

撤订阅是**破坏性**动作：删掉订阅条件等于把一个器官的外部触发 API 拆了。
本批 10 条里**没有一条**能证明"这个事件形态是错的" —— 它们要么是能力走旁路（#11 #13 #16 #17）、
要么是缺一个外部世界（#8 #14）、要么是缺上游事实源（#12）。
**"暂时没人发" ≠ "不该有这个事件"**，故一律不撤，按"观察 + 归属下一批"处理。

## 四、已修 3 条的实现要点（给核验用）

### #9 / #10 `PulseProprioception._m406_report_hw_transitions(dc)`

- 签名取自 **`dc`（设备管理器枚举表）**，**不是** `self._hardware_capabilities`。
  原因：`_on_device_attached` 会直接改 `_hardware_capabilities[...]["available"]`，
  拿它当基准会形成「事件回灌 → 下一轮重建改回去 → 再上报」的 **flapping 自环**。
  `dc` 是外部真值，事件处理路径不碰它。
- 首帧对**已可用**设备补一条 `ATTACHED`（`initial=True`）＝「启动枚举补首帧」，
  否则开机就在位的摄像头永远不会被上报。
- 任何异常只记 WARNING，不影响能力矩阵（能力矩阵是本体感知的核心产出）。
- 调用点在 `_evaluate_hardware_capabilities()` 末尾，**紧随** `self._hardware_capabilities = caps`。

### #15 `main._crash_hook` → `SystemEvent.ERROR_REPORT`

- 位置：`sys.excepthook = _crash_hook` 之前、堆栈打印之后。
- payload：`{error_type, error_message(≤500), source_organ="框架", origin="uncaught_exception"}`。
- `source_organ="框架"` 刻意不用"白细胞"：用器官名会让 `PulseWhiteCell` 收到"自己发的"脉冲。
- 节流：同指纹（`类型:消息前80字`）60s 内只发一次；单进程全程上限 50 次。
  理由：线程反复抛同一个错时，每次都让免疫系统跑一遍 `_attempt_repair`，代价远高于写日志。
- 失败一律 `silent_exc`：**崩溃钩子本身不得因上报失败而丢取证**。

## 五、交给下一批的 7 条（附裁决点）

1. **#16 / #17 是否"旁路改主路"** —— 现为直调；改走事件需要接受 L0 异步投递带来的时序变化。
   建议：先只做**只读观测**（在定时器里额外发一条 `HEALTH_CHECK` 但 handler 加"本轮已跑"幂等），验证一轮再切换。
2. **#13 事件与直调并存** —— `PulseSemanticComprehension` 直调 `classify_internal` 且自发结果，
   `QICAEvent.CLASSIFY` 通道无人用。要么统一到事件，要么撤订阅，不宜长期两套。

5. **#14 视觉帧** —— 需要先统一 `somatics/sensor.py` 与视觉皮层两条采集旁路。
