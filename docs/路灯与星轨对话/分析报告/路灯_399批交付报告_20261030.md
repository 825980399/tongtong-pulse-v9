## 二、T0 核实：刀1 照做会造出更糟的台账

### 坑一（致命）：差集两侧用了**不同的键函数**

```python
# tools/ci/m365_silent_ledger.py::build_ledger（399 之前）
_old_cmp = set(_m.handler_identity(x) for x in _old)          # 5 元组
_added   = [x for x in _new if _m._cmp_key(x) not in _old_cmp]  # 4 元组 ← 永远不在集合里
```

* `ci_common.handler_identity` = `(path, qualname, tname, kind, sha16)` —— **5 元组，含 tname/kind**，
  371A5 把 `nth` 从身份里去掉了；
* 扫描器 `_cmp_key` = `(path, qualname, nth, sha16)` —— **4 元组，含 nth、不含 tname/kind**。

两个元组长度都不同，**永远不可能相等** ⇒ 差集恒等于全集。399 实测：

```
旧判据抓到 _old = 542
新判据抓到 _new = 552
_added          = 552   ← 100% 命中，一条都没被"旧判据也抓到了"排掉
```

`_cmp_key` 自己的注释写明它就是"跨判据可比键（同一 handler 的两副面孔）"。
两侧统一用它之后，真差集 = **10**。

### 坑二：真跑一遍会抹掉人工结论

`preserve` 按 **6 元组** `identity_of` 搬运元数据。差集涨到 552 后，
台账 68 行身份 **0/68 对得上** ⇒ `manual_review`（6 条 A 档人工结论）与 `exemption`（5 条）
**全部丢失**，`test_m366::test_01` 当场红。

### 坑三：`--emit` 会顺手丢掉两个顶层计数

`manual_review_n` / `control_flow_exempt_n` **从来不是 `build_ledger` 产出的**，
是手工写进 json 的。emit 一次双变 `None` ⇒ `test_01`/`test_02` 红，
而人看到的只是"台账没零漂移"，根本想不到是计数丢了。

### 坑四：`schema` 会被打回 v1

366 N3（`da1f0ad1`）把台账升成 v2，但**只在 json 里手改了 `schema` 字段**，
工具常量 `SCHEMA` 一直是 `v1` ⇒ `--emit` 一跑就退版，`test_m365_b3::test_01` 红。

> 坑三、坑四是同一类：**基线 json 里有一部分内容不是工具产出的**。
> 这类"手写进基线"的字段，任何一次重算都会静默丢掉，而且丢掉时测试的报错信息
> 指向的是别的地方（"你改了判据"而不是"你丢了计数"）。

### 3.2 返工：退役设计从「另一个数组」改回「原地字段」

第一版我把 58 条离开差集的行搬进一个**独立的 `retired` 数组**，`rows` 只留 10 条在册。

1. **项目早就有约定**：371A5 起台账用 `retired_by` 字段做退役标记，首行那条
   `main.py::_probe_loop` = `"371A5第1笔（break→continue＋WARNING，已非静默 handler）"`；
   `test_m369_blade4` / `blade6` 一直按这个字段过滤。**再开一套名单必然分叉。**
2. **更直接的问题**：那条 A 档人工结论（`call_recorder::_rotate`）被搬出 `rows` 后，
   就脱离了 `test_m366::test_01` 能看见的范围。**判据没红，是因为我顺手改了判据** ——
   这正是"用改判据掩盖结构变化"。发现后 `test_m366` **整体回退**，只保留一处必要修正
   （`test_03` 的 `same` 从"全集条数"改成"在册条数"，因为 `diff_ledger` 已跳过退役行）。

最终形态：

| 字段 | 含义 | 现值 |
|---|---|---|

### 3.3 58 条退役行的归因（"漂移都是预期内的"要有证据）

逐条 AST 核过，全部落进四类，**没有一条是"莫名消失"**：

| `retired_reason` | 条数 | 含义 | 核实方法 |
|---|---:|---|---|
| `fixed` | **55** | 函数还在，函数体内已有 `silent_exc(...)` | `ast.walk(fn)` 找 `Call(func=Name/Attribute 'silent_exc')` |
| `func_gone` | **1** | qualname 在现仓找不到 | `ParamABTestEngine::_analyze_log_segment` |

**结论：68 条待办已修完 58 条** —— 这是 365→398 三十多个批次持续收口的结果，
