## 三、470 两刀

### 刀1 对齐判据收紧（两层）

**我 469 批错在哪**：`_m469_align_method_patch` 只校验「整段方法在文件里唯一」，
然后把 `original_code` **无条件**换成整方法，从不核对 original 到底是不是这个方法的方法体。

用 22 条真实历史补丁实测，**旧判据放行 14 条，逐条核对后 14 条全是错的**：

| 类型 | 条数 | 语义后果 |
|---|---|---|
| `orig_OVERLAP`（跨出方法边界） | 1 | 方法之后的语句被卷进替换 |
| `orig_IN_body`（只是方法内一段，如只有 `try:` 块） | 2 | 整个方法被降级成那一段的内容 |
| `orig_mismatch`（与当前方法体不等） | 6 | 按整方法替换等于乱改 |
| `modified_other_method`（**改名成别的函数**） | 5 | 目标方法在替换后**消失** |

最后一条最严重，也是当初最难看见的。旧判据用「strip 后以 def 开头」判断是不是整方法，
这两种都骗过去了：

```python
def _get_node_count(self):              # 名字被改
        def get_node_count(self):       # 8 空格缩进嵌套 + 改名
```

而且它同时骗过了我 469 报的全部四项判据：替换后 `ast.parse` 通过、方法总数 78→78 不变、
基础缩进相等、整段唯一。**只有把「目标方法是否还在」拿来比**，才看得见 `before True / after False`。

**新判据（两层）**：
1. 用与 `self_inspector._read_method_body` **同一规则**（跳过 docstring）计算方法体，
   只有 `original == 方法体` 才允许把 original 扩成整方法。
   这一条是关键——旧口径拿「def 之后全部行」当基准，而 original 来自 `get_method_body`（跳过 docstring），
   两边差一个 docstring，于是该拒的放行、该放的漏判。换成同规则后，`c862` 与 `b782` 曾严格相等 566 字。
2. `modified` 的 def 行方法名必须与补丁 `method` 一致，否则拒绝并留痕。

**效果**（22 条真实补丁，证据件 `m470_knife_changes.json`）：

| `how` | 条数 | 含义 |
|---|---|---|
| `as_is` | 6 | 本来就不需要对齐 |
| `orig_mismatch` | 9 | 拒绝 |
| `modified_other_method` | 5 | 拒绝（改名） |
| `span_not_found` | 2 | 拒绝（方法不存在） |
| **`whole_method_aligned`** | **0** | **零错误放行** |

不是把功能关掉：`orig == body` 且名字对得上的补丁仍会正常对齐（单测 B1/B7 验的是
「替换后 target 和 other 两个方法都还在、新方法体非空」）。
