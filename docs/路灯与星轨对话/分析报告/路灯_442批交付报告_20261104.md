## §1 刀1：O3 消费者为什么没在跑

### 根因（不是"调度没挂"，是**节拍饿死**）

调用链本身是完整的：

```
main.py:1290  _295_reg_dispatch()            → DailyScheduler.add_tick_hook(60s 轮询)
   └─ dispatch_on_tick()                     ← 每 60s 被调
        ├─ 首次：_last_dispatch_ts = now → return {"status":"armed"}   ← **到此为止**
        └─ 之后：elapsed < PATCH_DISPATCH_INTERVAL_SEC(3600) ⇒ skipped_not_due
              └─ 只有 elapsed ≥ 3600 才走到 _m335_o3_consume() → o3_open_gate_report()
```

`_m335_o3_consume()` 在 `dispatch_on_tick` 里的位置是**派单间隔判断之后**（335 批原文
「同节拍先消费开闸结论」，但那一节拍指的是**已到期的那一拍**）。
而 `_last_dispatch_ts` 是**进程内变量**，框架今天重启了多次 ⇒

> **没有一个进程活过 1 小时** ⇒ 永远停在 `armed` ⇒ O3 判定一次没跑
> ⇒ `[340判死]` 0 条（441 实测 5.6 万行日志）⇒ streak 永远推不动。

### 修法

新增**独立节拍** `PATCH_O3_GATE_INTERVAL_SEC = 300`（下限 60s 由代码兜底），
把 O3 判定从"派单到期那一拍"解耦出来，写在 **armed 早退之前**：

```python
_now = time.time()
_iv  = _dispatch_interval_sec()
# ★442刀1：先按独立节拍评估 O3 开闸结论（与"要不要派单"无关）
if _last_o3_gate_ts is None or (_now - _last_o3_gate_ts) >= _o3_gate_interval_sec():
    _last_o3_gate_ts = _now
    _m335_o3_consume(now=_now)
if _last_dispatch_ts is None:      # ← 派单仍保持原节拍与 armed 语义
    ...
```

- 只做**只读判定 + 入池**，不派单、不花钱（与 335 刀6 的熔断边界一致）；
- 派单节拍、`HARD_CAP=1`、`max_blast_radius=1` **一个数没动**。

### 活体验证（本批能给的证据边界）

- 源码位置判据已钉死：单测 `test_o3_gate_runs_before_armed_early_return` 断言
  `_m335_o3_consume` 出现在 `if _last_dispatch_ts is None:` **之前**；
- 间隔取值三条：默认 300 / 读 config / 下限 60，单测全绿；
- **`[340判死]` 日志要等重启后才会有** —— 当前 pid 跑的是旧代码。重启后
  5 分钟内应出现第一条，届时看 `连续=%d/%d` 的实际读数（本批**未能**给出该读数，
  如实记，留 443 首项复核）。

## §2 刀2：degraded 接进告警出口

### 改动（`organs/core/PulseMetricsCollector.py` +14）

在**读数点**（`_m421_patch_chain_read` 判定 `degraded` 之后）直接打 WARNING，
10 分钟节流（模块级 `_M442_DEGRADED_WARN_AT`）：

```
[442刀2][补丁链降级] patch_chain.state=degraded：apply=0 但 pending=1
（gen=… queue=1 apply=0 ledger=…）｜处置：查审批是否卡住/派单是否选中/基线闸门是否拦截
```

**为什么放读数点而不是看板**：441 的结论是「降级了没有任何**程序**据此动作」，
接在 health_ui 只是给人看；接在读数点，机器（日志/巡检/告警采集）都能看见，
且不新增调度面。

### 活体验证

