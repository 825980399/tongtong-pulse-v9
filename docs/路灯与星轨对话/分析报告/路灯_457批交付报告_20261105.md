## §4 给 458 的坑（本批实测新增）

1. **「日志里有 Timeout 8000ms exceeded」≠「假设超时」**：那是 Playwright 的
   `page_load` 超时（`TIMEOUT_CONFIG["page_load"]=8000`），来自 `PulseController`。
   排查 LLM 超时请看 `[肺] [渠道]` 与 `[457刀2]`，别看控制器那行。
2. **判断某功能"有没有跑过"，先 grep 它的完成日志**：`[455刀5]`/`[456刀1]` 计数为 0
   是本次推翻"根因"的关键证据 —— 比读代码猜快得多。
3. **`_ir_run_detectors` 是最大的早退面**：19 个检测器优先级排队，
   `_detect_experience_route`(65) 一命中就 `_fallback_to_lung_model` 返回。
   任何"挂在 dispatch 里的影子/埋点"都要先假设它**不会被执行**。
   这也是 t146 四条存量红（`no_match` → `experience_failed_to_lung`）的同源形状，
   建议 458 一并裁决。
4. **`_sanitize` 显式白名单**：本批没有新增 trace 字段（刀4 复用 456 已登记的四个键），
   所以没有再踩；下次加字段仍然要登记。
5. **pytest 写生产留痕**：刀5 落盘口已加 `"pytest" in sys.modules` + 默认路径护栏，
   并有单测 `test_sample_never_writes_production_path_under_pytest` 钉住。
6. **`ContextVar` 型链预算要有"未登记＝不启用"的退路**：否则 455 的 29 条既有单测
   会因为"上一个用例留下的链起点"集体变红（本批用 `begin_chain()` 显式登记避开）。
