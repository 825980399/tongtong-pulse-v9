### 三个必须写下来的结论

**① 不能凭 `args` 拼 def 行。** `args` 丢了 `self` 与 `-> bool`，拼出来的文本在源文件里定位不到，而应用侧是 `full_content.replace(original_code, modified_code)` —— 定位不到就**静默不替换**。只能回源文件取原文。

**② 445 的开关罩错了路径。** `require_full_def` 只接在 `_call_llm_for_repair`（单文件），而 63/63 的 `no_def` 全来自 `patch_multi_*`。等于装了锁，但门在另一边。

**③ 实盘证据（本批最强的一条）。** 活体 14:55:26 打出：

```
跨文件补丁验证失败: patch_multi_1793948125_2623
  → ['语法错误(IndentationError): unexpected indent (<llm-patch>, line 1624)']
```

`line 1624` 落在 `_compress_group` 方法体内部（def 行是 1610）。3000 字符的硬边界正好把方法从中间切断 —— 这不是推测，是 467 病灶的现场。

### T0 期间额外撞到的一个坑（已写进代码注释与回归测试）

`struct_defects` 第一版用 `textwrap.dedent` 判语法，结果**含 def 的完整方法被判 `unexpected indent@1`**。

根因：`dedent` 用 `^[ \t]+$` 认「纯空白行」，而 **CRLF 文件的空行是 `\r`** —— 匹配不上 ⇒ 公共前缀算成 0 ⇒ 一字不剥。`PulseLiver.py` 正好是 4079 CRLF / 0 裸 LF。

修法：先归一化行尾，再按 `dedent → 原样 → class 包裹` 三种形态依次试。已固化为 `test_05_crlf_blank_lines_do_not_break_syntax_check`。

### 刀3 为什么「不合格就不回队列」

`PatchManager._m280_converge_pending` 对 `no_def` 是**无条件作废**。把注定被作废的补丁塞回队列，会白占一次入池名额（375 刀9 的当日限额），还会把 `no_def` 计数再推高一次 —— 既浪费又把指标搞脏。

### 刀5 为什么必须单开一个台账

`criteria_window` 的 `no_def` 台账里已经有 `_compress_group` 的 **51+ 次历史**。若直接复用它判「连续 5 次即不可修」，467 一上线第一天就会把该目标永久关掉 —— 而 467 恰恰是想先把它修好。

所以新台账 `data/evolution/struct_defect_ledger.jsonl` **只记 467 结构门之后的失败**，起点干净；并且结构门每次成功都写一条 `ok` 作为**恢复点**，连续计数从这里断开 —— 没有恢复点，只要历史攒够 N 次，即使后来修好了也永远停在那里。

## 三、验效（都是真实标本，不是构造样例）

### 3.1 同一段代码的两种喂法

| | 长度 | 结构判定 |
|---|---|---|
| 旧喂料（`body`） | 12514 | `['no_def']` |
| 新喂料（`method_block`） | 12903 | `[]` |

新喂料首行 = `    def _compress_group(self, prefix: str, nodes: list[PulseNode]) -> bool:`，**与源文件逐字一致**（`blk in raw_text` 为 True），且 12903 ≤ 16000，能整段进 prompt。

### 3.2 def 名抽取：与入队侧对拍

以 `PatchManager._m280_extract_def_name`（入队侧**真函数**）为基准，10 个样本（含 `async def` / 带缩进 / 带围栏 / 无 def / 截断括号）全部一致。

两处若漂移，就会出现「生成侧自检说合格、入队侧判 no_def」的再次分叉 —— 所以这条对拍是**必要**的门。

### 3.3 结构判定的判别力

| 输入 | 判定 |
|---|---|
| 原样 | `[]` |
| 改 def 名 | `def_name_mismatch:_compress_groupx` |
| 去掉 `if` 的冒号 | `syntax_error` |
| 空串 | `empty` |

### 3.4 结构门端到端

场景：首发坏补丁 → 回灌第 1 次仍坏 → 回灌第 2 次修好。

```
LLM 调用 2 次，返回 1 条，含 def，缺陷标记已清除
```

**「第 2 次才修好」这件事本身说明上限 2 是必要的** —— 若设 1 次，这条就废了。

一直修不好时：LLM 调用 = 2（等于上限，不无限重试），返回 0 条，台账落一条 `struct_defect`。

### 3.5 跨文件迁移补丁不被误杀

调用方补丁的 def 名当然不等于目标方法名。判据：模型若明确标了别的方法名，只查语法、不查名字 ⇒ 本用例 `good=1, bad=0`。

### 3.6 不可修退出

| 场景 | 结果 |
|---|---|
| 连写 5 条缺陷 | `stop=True, streak=5, limit=5` |
| 写一条 `ok` | `stop=False, streak=0` |
| A 目标 5 次缺陷 / B 目标干净 | A=True, B=False（互不干扰） |
| 一边绝对路径、一边相对路径 | 按 basename 归一到同一键 |
