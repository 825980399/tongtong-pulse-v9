## §1 刀1：真问题 → 真补丁 → 真 apply

### 1.1 真问题是从哪找出来的（可复现的方法）

不是拍脑袋挑的，用**仓里已有的检测器**扫出来的：

```python
# 对 organs/ 下每个 .py 跑 detect_silent_exception（patch_active_reprobe 的检测器）

organs/body/PulseLung.py              9 处
organs/senses/PulseVisualCortex.py    7 处
...（共 19 个文件）
```

逐条看下来，多数是误报（`except Exception as e: self._log(...)` 已留痕）。
**真问题**在 `organs/motor/PulseController.py::_semantic_extract_keywords`：

```python
        except Exception:
            return []
```

关键词提取一旦抛异常，**静默返回空列表**：调用方看到的是「没提取到关键词」，
而不是「提取器坏了」——两者在下游行为上完全不同（前者降级使用原文，后者应告警）。
它同时命中两条铁律精神：静默 except（铁律 4）+ 故障不可见（438/439 一直在治的病）。

### 1.2 真补丁

```diff
-        except Exception:
+        except Exception as e:
+            self._log(LogLevel.DEBUG, f'关键词提取失败（已留痕）: {e}')
             return []
```

零语义变更（返回值仍是 `[]`），只把「静默」变成「可观测」。

### 2.2 `auto:bridge` 能不能过治理层

**根因找到了**：`approve_patch()` 里 `_approve_via(_patch, "human", signer, ...)` 把
**source 写死成 `human`**，而 `_boundary_check` 规定
「human 口 signer 必须以 `human:` 开头、非 human 口不得冒充人工」
⇒ `auto:bridge` 走 human 口**必被拒**。

改法（只加不改，铁律 54）：
- `approve_patch(..., source: str = "human")` 新增可选参数，默认值与旧行为逐字一致；
- `approve_patch_by_id()` 按签名前缀路由：`human:*` → human 口；其余 → **auto 口**。

实测：

```
signer=auto:bridge   source=auto   → 路由正确（不再被 human 口的前缀规则拒）
signer=human:ludeng  source=human  → 路由正确
```

**但** `_approve_via` 是三道关（`_govern_fields_ok` → `_boundary_check` → `_truth_ok`），
我用的合成样本缺 `evidence` / `m323_truth` 等字段，仍返回 False。
**结论：签名前缀这一关已通；字段契约那两关没验到**（真实补丁没走
`approve_patch_by_id`，因为 apply 是脚本直写的，没进 pending 队列）。如实留账。

**没有**。派单链要先有 `approved` 件才会选中；本批没有产生 approved（见 §1.4-①）。
