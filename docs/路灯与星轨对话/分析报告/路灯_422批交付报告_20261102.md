### 偏差 4（刀4）—— 不是"错过 04:00 窗口"，是两套日戳口径

任务书假设"04:00 那次没跑"。实测**跑了**：

```
data/reports/night_digest_state.json:
  last_run_ymd = 20261102    last_added = 114
  last_run_ts  = 1793562733  ⇒ 墙钟 2026-11-02 03:52:13
data/narrative/:
  narrative_20261101.jsonl   16165 B   mtime 11-02 03:51
  date=20261101  generated_at=1793562680  events=0  headline=当日无叙事事件
```

真因是**两套日戳各自都对、合起来才出这个现象**：

| 用途 | 表达式 | 11-02 04:00 的值 |
|---|---|---|
| 夜间编排的"今日幂等" | `now.strftime("%Y%m%d")`（**日历日**） | `20261102` |
| 叙事落盘日 | `digest_anchor(now)`（**摘要日**） | `20261101` |

`narrative_digest.DIGEST_SETTLE_HOUR = 6`，04:00 跑时 `tm_hour=4 < 6` ⇒ 锚点回退一天
⇒ 落**前一天**的文件。后果：`narrative_YYYYMMDD.jsonl` 要等**次日凌晨**才出现，
白天查"今天有没有叙事"永远是空的。

### 偏差 5（刀4 验证项）—— "目录下一天多个时间点的 flush 记录"无法用摘要文件行数体现

`narrative_store.persist_daily()` 的语义是**替换当天那一行**：

```python
_kept = [r for r in _old if str(r.get("date")) != _day]   # ← 去掉当天旧行
_rows = _kept + [_row]                                     # ← 只保留一行
```

一天跑 4 拍，文件里**永远只有 1 行**（`replaced=1`）。
要让"多时间点"可见，只有两条路：

- **(A)** 把 `persist_daily` 改成追加多行 —— 会同时推翻 `prev_row` / `summary` /
  `list_days` / `continuous_days` 的全部假设，回归面极大；
- **(B)** 另建 append-only 审计账 —— 本批选这条：`data/narrative/flush_history.jsonl`。

**摘要文件契约一字未动**，活体段6 已证：账 4 条、摘要文件仍 1 行。

### ⑧ 刀3 防循环闸是否有效？会不会无限重启？

**有效，且是四层叠加**：

| 层 | 机制 | 实测 |
|---|---|---|
| 1 | `_self_modify_forbidden_until`（框架自禁写期） | `remain=500s` 正确拦截 |
| 2 | 重启桶 `counter/max=3, cooldown_h=6.0` | `locked=False` 时放行，锁定时报 `restart_locked` |
| 3 | **最短运行窗 600s**（本进程至少跑满 10 分钟才允许 apply） | `age=301<600` 正确拦截 |
| 4 | 同件重试上限 3 次 ⇒ 标 `dead`，全 dead ⇒ `retry_exhausted` | 第 3 次 `dead=True`；随后 `stop=0/fired=0` |

**为什么不会无限重启**：

- 每次重启前必过第 3 层 ⇒ 两轮 apply 之间**至少隔 10 分钟**，单日理论上限 ~144 轮；
- 但第 2 层把重启次数硬卡在 **3 次/6h 窗口**，超了直接锁死；
- 第 4 层保证"同一个坏补丁"最多烧 3 次就进 `dead`，不会每拍重来；
- 失败尝试还写 `apply_retry_422.json`，`give_up` 后**当槽不再调 runner**（活体段⑤已证 `stop=0`）。

⇒ 最坏情况是"3 次重启 + 若干次 5 分钟空转判定"，**不是无限循环**。
