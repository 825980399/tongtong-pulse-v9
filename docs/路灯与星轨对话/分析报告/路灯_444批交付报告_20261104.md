## §刀5 补丁派单闸诊断：为什么 pending=2 都过不了

**两条 pending 的真身**

| id | 文件::方法 | 关键字段 | 真相 |
|---|---|---|---|
| `patch_llm_…_f3d7` | `organs/brain/PulseSubconscious.py`::`update` | risk=低 trust=75 baseline=**0** | **目标方法不存在**（`grep "def update"` 0 命中）；`original_code` 是方法体片段、`modified_code` 是完整 `def` ⇒ fragment 形态 |
| `o3_…e2ffba8d1623` | `nucleus/audit_problem_pool.py`::`export_hub_routes` | risk=高 trust=**0** | `original_code` / `modified_code` **都是 0 字** —— O3 只写了"这条疑似死代码"，没有给任何代码 |

**卡在哪几道闸（逐条实测）**

1. `is_fragment_to_full` → #1 命中（原码是方法体片段、新码含 `def`）；
2. `baseline_positive` → #1 命中（`baseline_errors=0`，且 `patch_active_reprobe` 对
   `periodic_task_no_reentry` **无检测器** ⇒ `verdict=not_applicable / hits=-1`）；
3. `pilot_only` 白名单 → 两条都不在 `PILOT_FIRST_BATCH`（只有 3 条 tuple）；
4. 空码 → #2 无论怎么调都应用不了。

**结论：这两条都不该放行。** 「调一下让 1 条过闸」= 把一条**目标方法不存在**的补丁或
一条**空代码**补丁塞进生产源码，正是 438/439/443 反复在治的"假修"。所以本批**不放宽任何闸**，
改为修两个**生成侧/判废侧**的真缺陷：

**改动（`PatchAutoApprover.py` +30 / `config.py` +6）**

1. **`is_obsolete` 增「方法存在性」判据**：原判据只看 `original_code` 是否仍是文件子串 ——
   而方法体片段可能存在于**别的方法**里（本例正是如此），于是这条补丁永远留在 pending。
   现要求 `method` 必须在文件里能找到 `def method(`（支持类方法与模块级函数）；
   `original_code` 为空（新增方法）时不判。
2. **O3 空码候选有界生命周期**：`source ∈ {o3_open_gate, o3}` 且 `modified_code` 为空 ⇒
   超过 `M444_O3_EMPTY_CODE_MAX_DAYS=3` 天未人工确认即 obsolete。给它一个终点，不再永久占位。

**活体**

```

       id=…1623 obsolete=False（age=0.2d，3 天后自动归档）

```

**单测 4 条**：`tests/test_m444_k45_guards.py`（方法不存在⇒obsolete / 方法存在⇒不判 /
