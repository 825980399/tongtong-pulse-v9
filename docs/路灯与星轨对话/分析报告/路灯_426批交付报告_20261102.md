## 四、刀3：经验池上限 + 近似去重（P1-05）

### 4.1 上限定多少、删谁

- **总量上限 `max_total_experiences = 800`**（原来 500 是「压缩闸」：把老条目压成摘要，总量仍能涨到 1500）。
- 淘汰**分级**，不是无脑删老：
  - **绝对保护三类**：最新 10% 时间线、`decay_rate == 0`（永不衰减的锚点）、`pinned`
  - **相对两档**：低 activation 先走；同档内**最旧的先走**
- ★踩过的坑：第一版用 `activation_count >= 3` 当保护线，实测真实池 activation 中位数 **200+**，人人满足 ⇒ 淘汰闸永不生效。换成上面的「相对中位数两档」才真的有判别力。

### 4.2 去重：精确 + 近似

- **精确去重**：原本就有。
- **近似去重**（本批新增）：`difflib.SequenceMatcher` 阈值 **0.98**。
  - ★判定必须用**原文**算比例 —— 第一版拿归一化文本算，把「学习到 1 条 / 0 条」这种**语义相反**的抹成 1.0 合并了（430 → 137 条，明显过头）。
  - 归一化只做**分桶粗筛**（数字 → `#`，前 8 字为桶键），桶内**排序后只与最近两个代表比** ⇒ O(n) 而非 O(n²)。
  - ★不这么做的代价：桶内两两比，200+ 条同族文本退化成 2 万次 difflib，**首次加载卡 16 秒**（对话会顶住）。
- **合并是幂等的**：合并会改写基条 summary ⇒ 后续条目才够阈值，所以要**多轮跑到稳定**（实测第 1 轮 94 条、第 2 轮 0 条）。

### 4.3 实测（`tmp/m426_d3_verify.py`，生产数据**副本**）

```
源（生产池）        431 条（已摘要 406），activation 总和 28799
加载后              337 条（合掉 94，带 merged_count 标记 63 条），activation 总和 28893  ← 只增不减
写入侧              长文改 1 个字符 ⇒ 并入已有条目、不新增；全新内容 ⇒ 照常写入
上限淘汰            cap=10 时 337 → 41（删 296），最新/锚点/pinned 全保留
幂等                第二次 compact_similar merged=0
开关关闭            ENABLE_M426_EXPERIENCE_COMPACT=False ⇒ 431 条原样，一条不动
耗时                load+compact 405ms（开关关 6ms）；单次写入稳态 23~24ms（开关关 27.5ms）
```

> ★「合掉 94」与日志里 `431 → 337` 对得上；同一算法在 430 条输入上跑出 `430 → 301`（合 129）。
> 差异来自「只与最近两个代表比」的近似窗口：输入多一条会改变代表与链式合并结果。
> 这是 **O(n) 换彻底性**的自觉取舍，不是 bug；如果星轨要求「并得更干净」，把窗口从 2 放到 3~4 即可（代价是线性变慢）。
