## 一、结论速览

任务书给的判断是「阈值是 0.5 不是 0.75，纯知识查询拦截挡掉绝大多数正常提问」。
**前半句对，后半句只对了一半** —— 拦截确实挡掉了绝大多数提问，但**放开它，经验路由仍然是 0 产出**。

真因按贡献度排序：

| 序 | 事实 | 量化 |
|---|---|---|
| 1 | 经验库 89.1% 是**代码学习 prompt 污染** | 114 / 128 条 `example_question` 形如「请分析以下Python方法，并返回一个JSON格式的结果…」 |
| 2 | 这 114 条类型是 `remote_api_confirmed`，被 `_SKIP_TYPES` 整类跳过 | 跳过 114 条 = 库容的 89.1% |
| 3 | 但它们在 `search()` 里**打分最高**（remote 加权 ×1.5），把本地经验全挤掉 | 10 条典型纯知识提问 best_score 恒为 **0.8874**，全部来自污染条目 |
| 4 | ⇒ 唯一结局是「命中 → 类型闸跳过 → 0 产出」 | 100% |
| 5 | 剩下的本地经验里，12 条是**兜底话术**（`local_fallback`），只有 1 条有效 | 12 条示例：「我需要更多的一手资料和实践来建立扎实的认知」 |
| 6 | 阈值 0.5 **不是**瓶颈 | 排掉远程条目后 12/12 提问 best_score 仍在 0.60~0.70 |

一句话：**不是阈值太严，是候选池被污染后又被类型闸整类砍掉，而真正的本地经验只剩 1 条。**

## 五、污染源定位

```python
# organs/body/PulseLung.py:2837-2849
# 3. 推理经验库更新——高质量回复标记为擅长领域
try:
    if quality.get("passed") and quality.get("level") == "high":
        ...
        _exp.record(
            prompt,                                              # ← 整条 prompt 当 example_question
            "remote_api_confirmed" if model_source == "remote" else "local_model_confirmed",
            source="quality_feedback",
            confidence=quality.get("score", 0) / 4.0
        )
```

肺的体检反馈把**通过质量门的每一个 prompt** 都记进推理经验库。代码学习器也走肺的大模型，
于是「请分析以下Python方法…」这批模板化 prompt 批量入库（114 条），并且：

- `remote_api_confirmed` 在 `search()` 里享受 **×1.5 加权**；
- `length` 等结构特征又让它们与任意提问都算得上"相似"；
- ⇒ 它们**恒定占据 best_match**，把真正的本地经验挤到看不见。

这是"污染 → 加权放大 → 抢占 → 被类型闸砍掉 → 0 产出"的完整闭环。

## 六、本刀改了什么 / 没改什么

**改了**

1. **埋点**（`_detect_experience_route`，`search()` 之后、类型闸之前）
   ```
   [406刀3] experience_route score=0.89 hit=1 thr=0.50 n=128 \
            type=remote_api_confirmed src=quality_feedback query="…" top_hit="…"
   ```
   带 `hit/thr/n/type/src` 五个字段，就是为了让 3 天数据能直接回答
   "是没命中，还是命中了被闸砍" —— 只打 `score` 的话这两个问题分不开。
2. **`ReasoningExperience.last_search_diagnostics`**：`search()` 在 `score < 0.5` 时返回 `None`，
   会把**低分段真实分数一起丢掉**，而那正是"阈值该不该调"的唯一证据 ⇒ 加一个只读诊断快照。
3. **纯知识拦截放开**：从"见到就跳"改为"本地命中 ≥ `EXPERIENCE_KNOWLEDGE_GUARD_MIN_HITS`（默认 3）才跳"。
   命中计数用「核心词 × 有界采样节点」探针（与 `_m35_entry_probe` 同口径），
   **不用 `_knowledge_retrieve`** —— 它内部 `top_k=3`，"≥3 条"几乎恒不成立，
   且中途会触发 `feedback_llm_fallback` 副作用。

**没改**

- 阈值 `_min_confidence` 仍 **0.5**（任务书明确要求先看数据）
- `_SKIP_TYPES` 原样保留（远程经验仍不在本地执行）
- `_KNOWN_DERIVATION_TYPES` 白名单原样保留
- 不接倒排 + 向量

**已知的"改了但当前无效"**：因为命中的全部是 `remote_api_confirmed`，放开拦截后
仍会在类型闸被砍 —— 即本刀**不改变线上产出**（只是多一次毫秒级 search）。
这正是安全的：埋点先跑 3 天，数据说话再动闸。

## 七、交给下一批的裁决点

| # | 级别 | 裁决点 | 理由 / 证据 |
|---|---|---|---|
| 1 | **P0** | `search()` 应在**打分阶段**就排除 `_SKIP_TYPES`，而不是"选完最高分再在调用方跳过" | 否则远程条目恒定抢占 best_match（实测 10/10 恒 0.8874），本地经验永远拿不到机会 |
| 2 | **P0** | `PulseLung` 质量反馈记经验时应过滤**代码学习类 prompt**，或按 `source` 分流到独立库 | 114/128 条是「请分析以下Python方法…」模板污染（`PulseLung.py:2844`） |
| 3 | **P1** | `source="local_fallback"` 的 12 条兜底话术不该作为可复用经验 | 排远程后它们以 0.68 成为最高分，回答会输出「我需要更多的一手资料…」 |
| 4 | **P1** | `failure_mode` 不在 `_KNOWN_DERIVATION_TYPES` 里，被静默丢弃 | 1/128；要么补白名单，要么显式弃用 |
| 5 | **不要动** | 阈值 0.5 | 排掉污染后 12/12 都能过 0.5；调阈值治不了病 |

**顺序建议**：先做 #2（停污染）→ #1（改打分口径）→ #3 → 再看 3 天埋点数据决定阈值。
反过来先调阈值，只会让兜底话术更早被当成"经验"复用。
