### 刀1 `nucleus/observability/experience_hits.py` +136 −40（265 → 361 行，LF）

**改什么**：候选窗口从「最近 200 条」放开为**分层全量召回**。


`top_hits_ex()` 新增（返回命中 + 每层读数），`top_hits()` 变为薄包装：

```python
def top_hits(question, top_k=2, pool=None, limit=None):
    return top_hits_ex(question, top_k=top_k, pool=pool, limit=limit)["hits"]
```

**为什么是分层而不是简单放大常量**（实测支撑）：

| 池条数 | limit=200 | limit=20000 |
|---:|---:|---:|
| 418 | 2.66 ms | 4.45 ms |
| 2 000 | 4.81 ms | 23.10 ms |
| 5 000 | 10.64 ms | 56.22 ms |
| 20 000 | 49.41 ms | **259.95 ms** |

`query_experiences(limit=N)` 的成本主要来自**遍历全池 + 排序**（limit 200 与全量实测
0.49 ms vs 0.52 ms，几乎相同），真正随候选数增长的是**打分**（每条一次正则）。
⇒ 直接把常量放大到全量，池长大后单次就是 260 ms；分层可以「现在 4.9 ms、将来也不退化，
最坏仍能扫到全池」。

**三个必须守住的设计点**（都是踩过才写进去的）：

1. **`top_hits()` 的签名与返回形态一字未改** —— 仍返回 `list`、不命中返回 `[]`。
   既有调用方（`PulseLung` / `observe`）与既有单测都按 `len(hits)==0` 判"这次没命中"。
2. **`limit` 显式传值时严格单窗口** —— 保持 423 之前的语义，不偷偷扩窗。
3. **`observe()` 必须继续调 `top_hits()`**（不是 `top_hits_ex`）——
   `test_m411_k4::test_51` 用 `monkeypatch.setattr(eh, "top_hits", …)` 注入假池，
   首版直调 `top_hits_ex` 绕过了这个桩，该用例当场去查生产池、从「命中 1 条」变「0 条」而红。
   已改回，并在代码里写明理由。

### 刀3 `nucleus/evolution/archive_recovery.py`（新 442 行，LF）+ `main.py` +18 + `config.py`（含在刀2 的 +40 里）

**改什么**：启动时扫一遍 archive，把「运行时验过、但从没被应用」的件重新入池。

判据（六道，每道都单独计数）：

| # | 条件 | 理由 |
|---|---|---|
| ① | `status == "runtime_verified"` **或** `runtime_verified is True` | 两种口径都认（§一.3） |
| ② | `applied` 非真 | 应用过的不要 |
| ③ | 年龄 ≤ 30 天 | 太老的不回收；时间取不到也不回收（不猜） |
| ④ | `o3_dead_code` 非真 | O3 判死的不要捞回来 |
| ⑤ | id 不在当前 pending | 避免重复入池 |
| ⑥ | id 不在周期 apply 的 dead 账 | 被判死的不要捞回来空转 |

**为什么单独成模块**：`PatchManager.save_pending_patch` 有六道闸（域守卫 / def 名对齐 /
片段→完整 / 危险预检 / 风险定级 / 滞留清理），任何一道都可能把历史件挡掉，**而且不返回值**
（成功失败分不清）。回收是"批量重放历史件"，需要的是**可计数的逐条判据**。

**为什么回收后不会立刻被 apply**：`status` 恢复成归档前状态
（`status_before_archive`，缺失时退化为 `runtime_verified`），而周期 apply 只统计
`status == "approved"` ⇒ 回收件最多"重新排队等审批"。

**形状兼容**：`flatten_archive()` 认三种历史形状（扁平 list / 批次 list / dict-with-items），
且支持**同层混合**（生产当前就是混合的）。

**审计**：每轮落 `data/patches/archive_recovery_log.jsonl`（append-only，含逐条排除计数）。
