## 四、本刀新增：`nucleus/evolution/patch_risk_gate.py`

### 4.1 分级规则（对齐任务书 ②）

| 等级 | 判据 | 能否免签自动应用 |
|---|---|---|
| **high** | 碰审批池/状态机（`APPROVAL_POOL_FILES`）**或** 跨器官（新增行 import 了别的 `organs.<x>`） | 否（转人工） |
| **low** | diff 窄（`comment_only` / `doc_only` / `test_only`）**且** 三条件全绿 | **是** |
| **medium** | 其余（逻辑改动 / diff 无法判定） | 否（转人工，本刀不动） |

`diff_kind` 判定顺序（先便宜后贵，先结构后解析）：
`tests/` → `test_only`；`.md` 或 `docs/` → `doc_only`；前后 AST 骨架（去 docstring）相同 → `comment_only`；
其余 → `logic`；缺字段/解析失败 → `unknown`。**前后完全一致按 `logic` 处理**（那是"没改"，不是"只改注释"）。

### 4.2 三条件（对齐任务书 ③）

| 条件 | 实现 | 为何这么判 |
|---|---|---|
| ① 单测全绿 | `verification.passed is True` ∧ `no_regression is True` ∧ `post_apply_errors ∈ {0, None}` ∧ (`verified is True` 或 `status ∈ VERIFIED_STATUSES`) | 以**验证产物**为证，不看自我声明。四个字段在真实 pending 记录里**全部存在**（已逐条核对 8 条 `patch_llm_*`），不是凭空加的门槛 |
| ② 不跨器官 | 目标在 `organs/<name>/` 时，新增行不得 import 其他器官包；非 `organs/` 下视为满足 | 非器官文件"跨器官"无从谈起；它是不是审批池由条件③管 |
| ③ 不碰审批池 | `file ∈ APPROVAL_POOL_FILES`（13 项，含本模块自己，防自改） | 单个真源清单，不散落在多处 |

### 4.3 挂接点（只收窄、不放宽）

- **风险标签**挂在 `pending_write.write_pending()`（**唯一写口**），不挂 11 个写点：
  写点必漏，写口"只要进 pending 就一定有标签"。落盘的那份 JSON 里**已经带** `m406_risk`。
- **闸**加在 `PatchManager._m85_local_low_risk_auto_apply`（A 通道）与
  `_m101_low_risk_release_path`（B 通道）的 `return True` **之前**。
  原本 `return False` 的路径一字未动 ⇒ 语义上只可能"少放行"，不可能"多放行"。
- `PATCH_M406_NARROW_GATE=False` ⇒ `gate_allows()` 恒 `(True, "gate_off")` ⇒ **完全回退 406 前**（零回归，开关两态各跑一遍已证）。
- 闸自己坏了（判据抛异常）⇒ `(False, "judge_failed")`，**保守拒绝**；读不到 config 开关 ⇒ 按默认启用继续判，
  **不因一次 import 抖动静默关闸**。
