## 二、T0 前提核实：8 处任务书偏差

> 依 `pulse-batch-delivery` §1：任务书描述经常有偏差，先核实再施工。本批 8 处，**其中 3 处会直接把刀做错**。

| 口径 | 条数 |
|---|---|
| `derivation_type == "remote_api_confirmed"` | 114 |

不是 `derivation_type`（后者与"真·远程经验"同值，分不开）。

### 偏差 2（刀1）「源头 `PulseLung.py:2844`」—— 是块内行号，不是函数入口

### 偏差 3（刀1）「标记为 `deprecated`」—— 项目既有口径不是这个词

项目已有完整清洗口径（`nucleus/data/experience_cleanup.py:142 is_retrievable`）：

```
polluted=True / is_cleaned=False / pollution_risk / cleanup_reason / cleanup_batch / cleanup_at
```

且 `config.EXPERIENCE_RETRIEVER_FILTER_POLLUTED` 已存在。新造 `deprecated` 字段会与

### 偏差 4（刀2）「污染条享 ×1.5 加权」—— **不成立**

`search()` 的加权读的是 `exp["source"]`：

```python
if source == "remote_api":            score *= 1.2
elif source == "remote_api_confirmed": score *= 1.5
```

而污染条的 `source` 实际是 **`quality_feedback`** ⇒ 两个分支都不命中 ⇒ **×1.5 从未发生**。
污染条抢 top1 靠的是特征相似度本身（0.8830），不是加权。
⇒ 这条偏差的重要性在于：**修加权没用**，必须改候选集或改特征。本批走候选集。

### 偏差 5（刀2·会做错）「`_SKIP_TYPES` 在 `ReasoningExperience.search()` 里」—— 不在

`nucleus/mnemosyne/ReasoningExperience.py` 里 `_SKIP_TYPES` 出现 **0 次**。
它在 `organs/brain/PulseInnerWorld.py:4364`（**路由侧**，命中之后才判）。
`search()` 本身**没有任何类型过滤** —— 这正是"先让错的赢、再宣布比赛作废"的机制根源。

⇒ 因此 `search()` 新增 `exclude_types` 参数，清单由**调用方注入**，
检索层不复制一份（两份清单各改一半 = 谁都不知道真实边界）。
单测 `test_52` 钉住清单**一字未改**（仍是 `("remote_api_confirmed", "remote_api")`）。

### 偏差 6（刀3）「5 条观察位全指向 expired（3）或已结案（2）」—— 形态不是这样

实测 `active_watch_ids()` = **2 条静态种子**，这 2 条**压根不在 pending 里**
（`verdict=not_in_pool`），不是"已结案"。自愈从 pending 补进来的是 **3 条 expired**。
真实 pending 11 行 = 8 条 `runtime_verified` + 3 条 `expired_pending`。

⇒ 真实形态是「**2 条缺失 + 3 条已死**」，两种事实不能混说。所以刀3 把它们分成
两个字段报：`dead_active`（已死）与 `not_in_pool`（缺失，由既有
`watch_batch` 的 `verdict` 报）。

### 偏差 7（刀3）「观察位数量应显示 0 而不是 5」—— `active` 从来不是 5

`WATCH_CAPACITY = 5` 是**上限**不是目标值。因为补进来的全是 expired 且旧判据认为健康，
所以只补到 3 就停了 —— 2+3 = 5 **恰好撞上限**，看着像"补满 5 条"。
406 报告里的"5 条观察位"是 2+3 的合计。

⇒ 刀3 新增 `n_active`（要观察几位 = 2）与 `n_eligible`（还有几位能派单 = 0）
两个口径同时给，避免继续被读成"5 条可用"。

### 偏差 8（刀2）验收判据「造一条污染 + 一条真经验，确认真经验被选中」在 407 前也能过

407 前的代码里，污染条拿下 top1 之后会被下面 `_SKIP_TYPES` 整类砍掉 `return None`，
于是"真经验被选中"这个现象在旧代码上**也观测得到**（只是排在后面重算时）。
⇒ 这条判据区分不了前后。真正能区分的是「**打分阶段**候选集大小」与
「`best_score` 是否被污染条抬高」，所以判据落在 `n_excluded_type` / `n_excluded_polluted`
与 C 组的**独立计数**上，不落在"谁被选中"。

### 3.2 判据设计的关键取舍

**强指纹**：`请分析以下Python方法` / `返回一个JSON格式的结果`。
没有用笼统的"请分析以下"—— 那会命中真实用户提问（`请分析以下两种架构的差异` 实测判 `False`）。

**弱指纹**：`方法名:` + `代码:` + `返回格式` 三件套**同时**出现。
单看 `方法名:` 会误伤"用户真的在描述表结构"（`test_05` 钉住这条）。

**为什么判据看文本而不是 `source`/`derivation_type`**：污染条的
`source=quality_feedback`（与正常条同值）、`derivation_type=remote_api_confirmed`
（与"真·远程经验"同值）—— **只有文本形态能把两者分开**。

## 五、刀3（P0）观察位判据对齐

### 5.1 根因（两个模块对同一状态理解不一致）

| 模块 | 判据 | 对 expired 的结论 |
|---|---|---|
| 派单侧 `_m339_o3_dispatch_ready()` | `status == "expired_pending"` | `(False, "expired")` |
| 自愈侧 `self_heal_watch()` | 只看「**在 pending 文件里找得到**」 | **健康** |

expired 行留着不删 ⇒ 旧判据恒判健康 ⇒ 从不补位 ⇒ 数量恒虚高而可派单数为 0。

### 5.2 五处改动

| # | 内容 |
|---|---|
| 1 | `WATCH_DEAD_STATUSES = ("expired_pending",)` —— 只列这一项（把派单侧**已经在用**的那条搬来当健康判据，不新增判据） |
| 2 | `_m407_watch_alive(row)`：**只判 `status`**，不判 `o3_auto_dispatch_ready` / `requires_confirmation` —— 那两项在这 3 条上都是"可以派"的值，靠它们判会全票通过 |
| 3 | 健康判据 = 「在 pending 里找得到 **且** 状态未死」；死掉的位收进 `dead_active` |
| 4 | 补位循环跳过死状态候选，逐条记进 `skipped`；`_picks` 空而 `skipped` 非空 ⇒ 新状态 `only_expired` |
| 5 | 数量两口径：`n_active`（观察范围）/ `n_eligible`（可派单）；补位后**重算** eligible |

**`only_expired` 为什么不与 `no_candidate` 合并**：前者该去**重新排发**，
后者该去**造补丁**。合成一句告警会把人引到错方向（铁律166：不同事实不同措辞）。

**为什么不改 `active_watch_ids()`**：它回答"要观察哪几位"（范围），
`alive_watch_ids()` 回答"这几位还有几个活的"（能力）。把前者改成后者，
expired 位就不再被观察 ⇒ 破零读数直接消失 —— **为修一个假健康指标挖掉一个真观测点**。
⇒ 两个口径并存，报告/告警读后者。

## 八、待裁决项（3 条）

### 待裁 1（P0）★建议立刻裁决：`_derive_experience_default` 该不该彻底删掉

本批已用开关 `EXPERIENCE_REUSE_EXAMPLE_AS_ANSWER=False` 把它关掉，但**代码还在**。
- 现状：默认关闭 ⇒ 每次 `unknown` 命中都会走 `_fallback_to_lung_model()`，
  经验路由在 `unknown` 类型上**只贡献"命中"不贡献"答案"**
- 建议：**彻底删掉这条路**（连同开关）。理由：经验池没有答案字段，
  这个能力在任何数据形态下都不成立；留着一个"打开就出错"的开关是负债不是资产
- 需要星轨确认：是否有任何调用方依赖 `status="experience_default"` 这个返回值

### 待裁 2（P1）经验池里那 30 条"干净但质量差"的记录怎么办

刀1 清理后剩 30 条参与打分，其中高分区全是 `unknown` / `local_fallback`，

它们现在不会造成错答案（刀2 配套已关），但会**占用 top1 把分数抬到 0.68**，
让"经验路由命中率"这个指标继续虚高。

建议：另开一批，用 `experience_cleanup.classify()` 重新分类这 30 条，
把"陈述句型 example_question"标记为 `low_quality`（新风险档），
或在 `record()` 加一道"入参像不像问题"的软校验（**不建议**，判据太玄）。

### 待裁 3（P2）七层自检 L4 停机判据不对齐（406 遗留）

见 §七 判据④下方。停机时 L5/L6 判 SKIP、L4 判 FAIL —— 同一种事实两种结论。
建议 L4 也按 `framework_down` 判 SKIP。
