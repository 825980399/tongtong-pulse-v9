## 二、刀1 · 自动入队池打开（P0）

**病灶复述（308 的账）**：308 把 535 条待复核清单从 `issues` 降级成纯统计 ⇒ 进化发现池里**一条 review 条目都没有**，`data/patches/pending_patches.json` 长期 0 行 ⇒ 闭环自动端断料。

### 2.1 `nucleus/self_inspector.py` — 恢复入料口（不是放行）

- 中间档重新 `append` 到 `issues`，但字段被钉死：`type='dead_code'`、`severity='info'`、**`review_only=True`**、`review_reason='graph_coverage_mid_band'`；
- **判死阈值一条未改**（仍是 `_COVERAGE_JUDGE=0.70`），覆盖率 57.58% ⇒ 依旧「不判死」；
- 统计口径**并存**：`_DEAD_CODE_REVIEW_STATS` 新增 `items`（≤20 条明细），供入料侧取用 —— 否则每次入料都要重跑一次全库扫描；
- 新增 **`build_review_intake(limit=1, items=None)`**：单批**硬上限 1 条**（`limit=5` 也只出 1 条、`limit=0` 即关闭），并硬拒两类：
  - **生命周期名**（`__init__/__del__/start/stop/close/run/on_pulse…`）⇒ 转人工（删了必炸，且图上牵连半径结构性失明）；
  - **核心文件**（`main.py/config.py/const.py/PulseCore.py/InfoField.py/PatchManager.py/SafeEvolutionExecutor.py`）⇒ 转人工；
  - 产出条目带 `intake='review_intake'`、`requires_confirmation=True`、`intake_reason`。

### 2.2 `nucleus/evolution/EvolutionLoop.py` — 入队口（任务书未列的**必要**第 5 个文件）

`discover_all_issues()` 末尾接 `_m311_collect_review_intake()`：

- **放在 `unique[:max_issues]` 截断之后**并入 —— 放前面会在池子填满时被切掉，「0→有料」就是假的；
- 数量走配置 `REVIEW_INTAKE_MAX_PER_BATCH`（`getattr` 读取，缺省 1，0 即关）；
- `summary` 新增 `review_intake`，入料多少在日志里直接可见；
- **不在此处现跑 dead_code 检测器**（历史实测分钟级），只读统计明细，无明细如实返回 0。

### 2.3 `nucleus/evolution/patch_execution_dispatch.py` — 自动分诊（池子不再长期停在 2 条）

新增 `select_for_auto_triage(history, limit=1)`，把 306 的「2 条白名单」升级成**可解释规则**：

| 闸 | 规则 |
|---|---|
| 状态/风险 | `runtime_verified` + `risk_level ∈ {低,low}` |
| 形态 | `is_fragment_to_full` 为真 ⇒ 排除（片段→完整=嵌套 def 风险） |
| 置信 | `trust_score >= AUTO_TRIAGE_MIN_TRUST(40.0)`（历史实测取值 30/40/45/50/80） |
| 生命周期 | 命中 `_LIFECYCLE_NAMES` ⇒ 转人工 |
| 牵连 | `blast_radius_of` 返回 `None`（不可判定）或 `>1` ⇒ 转人工 |
| 批量 | `limit` **硬上限 1**（`limit=5` 也只派 1 条） |

派单主流程：白名单池为空时回落分诊（**顺序不反** —— 确定性优先于统计置信）。

## 三、刀2 · 二级实体化 MVP（`code.structure.changed` → 图重扫，P1）

### 3.1 `nucleus/const.py`
`Event.CODE_STRUCTURE_CHANGED = "code.structure.changed"`（自动进 `_EVENT_CONSTANTS`，`is_registered_event` 实测 True）。

### 3.2 `nucleus/self_inspector.py` — 传感端 `detect_structure_changes()`

- 扫描域 = `config.CALL_GRAPH_SCAN_DIRS`，指纹 = `(mtime, size, 方法数)`；**只有 (mtime,size) 变了才解析 AST 数方法数**；
- 差集 `changed/added/removed` → **一条**聚合脉冲（`layer='L3'`, `priority=2`, `target_organ='自我认知'`），payload 带 `prev_graph_file/prev_graph_mtime/criteria_version`；
- 首跑只建**基线不发事件**（否则每次重启都发「全库都变了」的假脉冲）；进程内 60s 合并窗口；基线不落盘（本批写入面不含 `data/`）；
- 发射路径复用既有单例：`InfoField → PulseCore.emit → InfoField.publish`，任一步缺失只留痕返回 False。

**成本实测（351 文件）**：首拍 **4138.9ms**（一次性 AST 全量）、稳态 **48.3ms**、未改动时 0 事件。
⇒ 挂在**既有自认知节拍**（新增分析器 `structure_change`），**不新增定时器、不给 122s 加拍**；首拍增量 4.1s 落在「≤5s」预算内（接近上限，见 D3）。

### 3.3 `nucleus/self_awareness/SelfAwarenessEngine.py` — 消费端

- `__init__` 幂等订阅 `code.structure.changed`（订阅本身零开销，开关在 handler 首行判 ⇒ **翻开关无需重启装配**）；
- `_on_structure_changed()`：开关 `ENABLE_STRUCTURE_RESCAN`（`getattr` 读，**默认 False 影子关**）+ `RESCAN_MIN_INTERVAL_SEC`（缺省 300s）双重节流 → `integrate_call_graph()` 重扫 → `update_review_graph_identity()` 回写 `graph_file/graph_mtime/graph_source/graph_as_of`。

**E2E 实测**（真实 InfoField+PulseCore，重扫部分打桩避免写 `data/`）：`emit=True` → 订阅命中 → `rescan_count=1` → 统计 `graph_file` 变为新图 → 事件落 `InfoField.get_history(event_type=...)` 且 `layer='L3'`；间隔内第二次调用 `status=throttled`。
