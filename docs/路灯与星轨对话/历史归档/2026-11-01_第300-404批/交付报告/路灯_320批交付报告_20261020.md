## 四、刀0 · 04:00 `_ledger_sweep` 0产出归因（P0 · 真异常）

### 归因结论（带代码锚点）

**不是**版本行为、**不是**未注册、**不是**调度没跑。真因是 **幂等键缺"来源"维度**：

```python
# 修复前（nucleus/world_model/expectation_ledger.py::sweep）
_existing.add((str(_r.get("assertion_id")), _day))      # ← 键 = (断言id, 当天)
...
_key = (str(_r.get("assertion_id")), _today)
if _key in _existing:
    continue                                            # ← 逐条 skip，added 恒 0
```

**链路**：`night_orchestration.py:329-330` 的 `_ledger_sweep(project_root)` 确实注册在 04:00 digest 内（已核对）；但 00:0x 有**验证运行**先写了当日 114 条，把「当日幂等位」占满 ⇒ 04:00 活体 sweep 的 120 条断言**逐条命中 `(id, today)`** ⇒ 全部 skip ⇒ `added=0`，且**日志只打一条 `[318刀5][ledger] 新增 0 条`，看不出 skipped**，所以悬了一夜。

### 修复

1. **幂等键加来源**：`(assertion_id, day, source_process)` ⇒ 验证运行只占 `verification` 位，活体 `live` 位仍空
2. **四段留痕**：`[320刀0][ledger_sweep] triggered=True generated=? skipped=? reason=? source=? total=?`
   - `reason ∈ {ok, all_idempotent_skipped, no_assertions, write_error}` —— 使「钩子未到」/「到了但被幂等挡住」/「真写了」三者**在日志里可区分**
3. **04:00 挂点显式传 `source="live"`**（`night_orchestration.py`），digest 第五节同步输出 triggered/skipped/reason/来源
4. 写盘异常也留痕（`reason=write_error:<ExcType>`），不再静默

### 验收

## 八、刀4 · SC-2 第二挂点核实（P1 · 319遗留）

### 结论：**语义不等价**，第二挂点不挂 hub（带证据）

`verification_learning_hub` 真实的规则应用入口是 **`apply_rules(organ, rules)`**（`apply_rules_to_organ` 全库确实不存在，319 结论正确）。

**证据（静态取证）**：`apply_rules` 函数体 30 行 / 1139 字符，**不含** `open(` / `write` / `_save(` / `guard_write` —— 它只做 `self._organ_appliers[organ]` 回调派发 ＋ 别名路由。语义是"把**学习规则**派给吸收方"，**不改任何源码 AST**。

**而 SC-2 判据是 A1/A4 代码图指标**（failed 只许减不许增）。规则应用前后图完全不变 ⇒ 在此挂 SC-2 **恒等通过、零信息**。因此：

- **SC-2 覆盖范围明确为「补丁应用侧」**（`patch_execution_dispatch._sc2_probe`，dispatch 后 600s 节流探针），不覆盖规则应用侧
- 该结论带代码锚点＋函数体取证，非"挂不上就算了"

> 若星轨仍要求规则侧留痕，建议另立"规则生效后 re-analyze 对比"专项（会引入一次全库建图 ≈16s，有成本，需裁定）。
