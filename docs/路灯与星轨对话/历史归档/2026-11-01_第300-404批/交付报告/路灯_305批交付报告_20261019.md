## 二、刀1 · dead_code 判据对齐图 id（P0 · 止住 541 回归）

### 2-1 304 的根因（已复现）

304 按**裸 method name** 比对（`{node["name"] | id ∈ callee}`），而图节点 ID 是 `module:Class.method` ⇒ 同一个 name（如 `__init__`）背后是跨数百个文件的几十个不同函数，**同名合并**导致误判。

### 2-2 本批改动

新增 `_m305_load_graph_index()`（取代 304 的两个方法），返回 **id 级**索引：

- `in_edge_ids`：有入边的节点 id（权威「活着」集合）；
- `id_by_fileline`：**一级定位** `(文件, def 行号)`；
- `ids_by_filename`：**二级兜底** `(文件, 方法名)`；
- `covered_files` / `node_count` / `ok`。

判据循环改为：先 `(file, line)` 命中 id，失败再 `(file, name)`，都落空 ⇒ `no_node`（不判）；命中后按 **id 是否在 `in_edge_ids`** 判定。

### 2-3 ★关键发现：判据对齐后仍是 541，真因是**图本身太稀疏**

诊断实测：

| 指标 | 数值 |
|---|---|
| 图 nodes | 6738 |
| 有入边节点 | **3818（入边覆盖率 56.7%）** |
| 图域内方法总数 | 3045 |
| 一级 (file,line) 命中 | 594（19.5% —— 行号漂移较多） |
| 二级 (file,name) 命中 | 2449 |
| 有入边（活） | 970 |
| 无入边（判死候选） | **2073** |

⇒ 43% 的图节点没有入边：跨模块 resolve 率偏低 ⇒ **「无入边」里大量是「没解析出来」，而不是「真没人调用」**。这等价于「没测」，按判据纪律**不许据此判死**。

### 2-4 因此加「图质量守卫」（本批第二处关键判断）

入边覆盖率低于阈值（`_MIN_COVERAGE = 0.70`）⇒ 本判据**整体让位**（只记 INFO 日志，不产出问题）：

```
[305刀1] 图入边覆盖率 56.7%（有入边 3818 / 节点 6738）低于可信阈值 70%
         ⇒ 「无入边」不足以证明死代码，本轮不判死（待图解析率提升后自动生效）
```

**实测：dead_code = 0**（止住 541 回归）。

## 三、刀2 · edge_types 从「三个计数」升级为真实节点对边（P0）

### 3-1 304 的根因

`_pass2_resolve` 对动态调用**一律 `continue` 丢弃** ⇒ 按名边根本不在图里；`edges[]` 无 `kind` 字段（实测 `kinds={'NA': 7358}`），分色只在落盘时用正则数了三个整数。

### 3-2 本批改动

1. `_Collector.visit_Call`：识别 `getattr(x, "y")` 字面名 ⇒ `kind="byname"`（并记录 `attr_name`）；其余动态调用 `kind="dynamic"`；静态调用 `kind="static"`。
2. 新增 `_resolve_by_name()`：按字面名解析（**优先同模块、全库唯一命中**；多义或找不到 ⇒ 空串，不猜测）。
3. `_pass2_resolve`：按名调用**不再丢弃**，能解析到方法就建 `kind="byname"` 的边。
4. `analyze`：每条边带 `kind` 字段（默认 `static`）。
5. `dump_graph_snapshot`：`edge_types` 由 `edges[].kind` **聚合**（不再全库重扫正则）。

### 3-3 实测

`edges kind 分布 = {static: 7367, byname: 3}`；落盘 `edge_types = {static: 7367, byname: 3, event: 0, entry: 0}`。

**byname 只有 3 条的根因（如实）**：`getattr` 绝大多数用于**取属性/判空**而非**调用**，不产生调用边；加上 `_resolve_by_name` 要求唯一命中（多义即弃），故真实可解析的按名调用边本就稀少。

## 四、刀3 · 牵连闸改入边方向＋None 语义＋起点消歧（P0）

| 304 缺陷 | 本批修正 |
|---|---|
| 沿 `caller→callee` **出边** BFS ⇒ 量的是「我依赖谁」 | 默认 **`direction="in"`（入边 = 谁依赖我）** |
| 缺名返回 **0** ⇒ 调用方放行（把「查不到」当「牵连小」＝**假通过**） | 缺名/图缺/起点未定位 ⇒ **返回 None**，调用方 `is None` 必须**转人工** |
| 裸 name 起 BFS ⇒ 同名合并 | **起点消歧**：优先 `(file, name)` 精确定位（补丁的 file/method 字段），其次要求 `Class.method` / `module.Class.method` 限定名；仅裸 name 且无 file ⇒ **None（转人工）** |

### 实测（13 条 runtime_verified 低风险真实补丁）

- **定位命中 12 / 13（92%）⇒ 不饿死**；未命中 1 条（`PulseInnerWorld._build_how_am_i_response`）⇒ 转人工，**不假通过**。
- blast 取值有区分度：0 / 2 / 3 / 5 / 6 / 8 ⇒ `max_blast_radius=1` 下放行 3 条、转人工 9 条。
