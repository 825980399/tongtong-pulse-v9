## 二、刀1 · M92 总闸（P0）

**实测**：`config.py:5574 ENABLE_M92_PATCH_BASE_INDENT_GUARD = True`、`config.py:5586 ENABLE_M92_PATCH_AST_STRUCT_GUARD = True`。

读取链路确认（`PatchManager._m92_base_indent_guard_on/:237`、`_m92_ast_struct_guard_on/:265`）：

```python
return bool(getattr(config, "ENABLE_M92_...", _M92_..._DEFAULT))
```

⇒ **config 优先**，两关在 295 批翻 True 后**运行时早已生效**；`_M92_*_DEFAULT`（231-232）只是「config 未定义/读取异常」时的兜底，此前仍为 False。

**本批动作**：按任务书把两个 **DEFAULT 由 False 翻 True**（双保险），使「未定义 config 键」时同样是开闸态。
**关闸路径保持不变**：把 config.py 对应键显式置 False 即可（`getattr` 优先于默认值）。

实测：`base关=True ast关=True DEFAULT兜底=True True`。

## 三、刀2 · dead_code 判据接反射可见性（P1 · 给反射可见性）

**根因**：`_detect_dead_code` 只看 `name(` 形式的**静态调用计数**，看不到按名派发与注册表 ⇒ 302 批 638 条里 617 条（96.7%）是反射可达/公共 API/预埋，全为误报。

**补齐三条可见性判据**（`nucleus/self_inspector.py::_detect_dead_code`）：

1. **字符串常量可见性**：方法名出现在全库任一**字符串常量**中 ⇒ 视为可达（覆盖事件注册表 `subscribes`/`handlers` 与回调名单以字符串写下的名字）；
2. **`getattr` 按名派发可见性**：`getattr(self, "xxx")` 形式的字面名（全库数百处）⇒ 视为可达；
3. **公共能力面可见性**：公共 API 前缀（`get_/set_/is_/has_/create_/...`）或位于 `config.py`／`nucleus/`／`base/`／`tools/` 的方法 ⇒ 属对外契约，不判死代码。

方向是**宁可少报，也不把在跑的能力判成死代码**。

**实测效果**：

| 指标 | 302 批 | 本批（三条判据全开） |
|---|---|---|
| dead_code | 638 | **27**（−611，−95.5%） |
| 问题总数 | 712 | **97** |
| D 类真死代码候选 | 21 | **21**（判据稳定，未被误豁免） |
