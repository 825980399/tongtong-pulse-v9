## 一、刀1 · 修 `rescan_high_risk_levels` 调用签名（P0）

### 真实病灶不在调用点，而在被调用方的装饰器
任务书指向 `DailyScheduler.py` 的调用签名，实测**调用写法本身是对的**：
`_300_pm(self._project_root).rescan_high_risk_levels()` 是标准实例调用。病灶在
`nucleus/reasoning/PatchManager.py:1039`：

```python
@staticmethod
def rescan_high_risk_levels(self) -> dict:      # ← 带 self，却绑成 staticmethod
```

`@staticmethod` 把方法绑成普通函数后，`实例.rescan_high_risk_levels()` **一个实参都不传**
⇒ `TypeError: missing 1 required positional argument: 'self'`。自 300 批落地起，
**存量高危回扫从未成功执行过一次**；306/308 两次升 `CRITERIA_VERSION` 后的「按新判据重算」
全部死在这一行，仅由 `silent_exc` 可见化留痕（烛微 15:16:29 抓到的正是它）。

**修法**：删掉那行 `@staticmethod`（改回普通实例方法），保留 `self` 的全部语义。
调用点**一行未改**，只补一条成功留痕日志（见下）。

### 附带：调用点补「非异常日志」（验收项要求）
`rescan_high_risk_levels` 内部只在 `changed>0` 时打 WARNING，0 变更时完全静默——
这正是这个 bug 能藏 9 个批次的观察盲区。故在 `DailyScheduler` 调用处补：

```
[309刀1] 存量高危回扫完成: changed=%s total=%s
```

### 实测（隔离根 `tmp/p309_root/`，**不动生产台账**）
```
rescan OK: {'changed': 1, 'total': 84}
idempotent 2nd: {'changed': 0, 'total': 84}
```
- 修复前：必然 TypeError，`changed` 永远拿不到；
- 修复后：首次真的重定级 **1 条**（高危族 `sql_injection/lock_with_emit/non_atomic_write`
  里 `risk_level != 高` 的那条），二次调用 `changed=0` 证明**幂等**成立。
- 隔离证据：生产 `data/patches/patch_history.json` 仍 84 行 / 高危 0 条 / mtime `15:16:19`
  **未被本批触碰**；变更只发生在 `tmp/p309_root/` 副本（84 行 / 高危 1 条 / 15:34:26）。

## 二、刀2 · 修 `nucleus.PulseBloodVessel` 模块路径（P0）

### 这条其实是**两个 bug 叠在一起**（「同因不同果」的因果链到此闭合）
```python
from nucleus.PulseBloodVessel import PulseBloodVessel   # ① 路径错（真身在 organs/body/）
inst = PulseBloodVessel.get_instance()                  # ② 该类没有 get_instance()
...
_remapped[str(_nk)] = float(_v)                         # ③ 值是 dict，float() 必抛
```

1. **路径错**：血管真实位置 `organs/body/PulseBloodVessel.py`；
2. **访问器错**：`PulseBloodVessel` **没有** `get_instance()`。仓内既有范式是模块级
   `get_blood_vessel()`（`main.py:1548` 用 `set_blood_vessel_instance` 注册活体实例；
   `SelfAwarenessEngine:457` 同用法）——只改 import 仍会 `AttributeError`；
3. **取值口径错**（最隐蔽，也是「掌握率 source=unavailable」的真正近因）：
   `get_stats()["organ_activity"]` 的值是 `{"sent": n, "received": m}` 的 **dict**
   （`PulseBloodVessel:155` 初始化），`float(_v)` 必抛 `TypeError`
   → 被 `silent_exc` 吞成 `{}` → 上游判「未进入运行态口径」→ `source=unavailable`。

**修法**：改 `from organs.body.PulseBloodVessel import get_blood_vessel` + `inst = get_blood_vessel()`
（`None` 直接返回 `{}`）；值归并为标量 `sent+received`，与 `SelfAwarenessEngine:463—470`
既有口径**一字不差**，不新造第二套读数。

### 实测
```
activity type: dict  n= 2
sample: {'控制器': 12.0, '嘴巴': 3.0}      # (7+5) / (2+1)，class_name 已按 organ_name 对齐
values all float: True
```
修复前同一输入返回 `{}`（`silent_exc` 吞掉 TypeError），修复后非空且全为 float。
