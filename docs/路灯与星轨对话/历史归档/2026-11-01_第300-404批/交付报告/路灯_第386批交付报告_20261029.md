## 四、刀3（P1）内存观测先活下来

### 死结

live 00:30~00:55，每 5 分钟一次：

```
[339内存观测] 单次快照 18.38s / 9.60s / 7.49s / 6.66s / 6.73s / 9.70s > 3.00s ⇒ 不写盘
```

**全部不写盘 ⇒ 产物目录一个文件都没有。** 真因是判定写成了
「**整份扫完**再判超时」，而 `gc.get_objects()` 全扫描在活体堆下必然 6~18s ⇒
这个分支**永远**走到"不写盘"。降采样解决不了（耗时在遍历本身），
异步写盘也解决不了（写盘不是瓶颈）。

### 落法

1. `_M339_GC_SCAN_BUDGET_SEC = 2.0`（**必须 < 3.0**，有守卫用例）
   —— 遍历每 65536 个对象检查一次耗时，超预算即停
2. 产物新增 `gc_scanned` / `gc_truncated` / `gc_scan_budget_sec`
3. **截断也写盘**（`M339_WRITE_ON_TRUNCATED` 默认 True）：截断说明耗时已受控，
   此时"不写盘"只会让产物继续缺席。关掉 ⇒ 逐字回旧判定
4. ★不篡改 `elapsed_sec`：第一版我用 `_elapsed = 0.0` 绕过超时判定，
   那会让产物写"耗时 0 秒" ⇒ 又一个假读数。已改成独立标志放行，真实耗时照落盘

**能力边界**：截断后 `top20` 只是**已扫描部分**的分布，不是全堆分布，
所以三个扫描口径字段必须一起落盘。

★票面写 `data/metrics/memory_*`，实际产物目录是 `data/reports/memory/top_types_*.json`。
