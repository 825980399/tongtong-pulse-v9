## 二、逐刀要点

### 刀1 · 心跳停跳根因（P1）

**定性靠证据不靠推断**：2026-10-26 17:24:34→17:28:03 约 209s 里，`health_snapshot.json`
的 mtime/beat_count 与 `logs/pulse.log` **同时冻结**（不是"心跳单独死"），恢复瞬间
RSS 4.52GB→2.46GB、打开文件 17→0，并有一批补跑日志涌出 ⇒ 是**进程级停放**；
恢复后所有周期件自愈，唯独两条**自续链**（心跳 `pulse_core.emit`、TimeCore `_broadcast`）
永久死亡 ⇒ 根因是**续链只写在 finally**：那一拍卡在 `field.publish` 没返回，finally 永不执行。

**改法四层**（全硬编码常量）：① 进入即**先排下一拍**再干本体；② 重入守卫由布尔升为
**带租约的锁**（超租约判上一拍卡死、本拍接管续跳，连击 >3 次只保链不自伤）；
③ 接管时 faulthandler 抓**全线程栈**落 `logs/heartbeat_stall/`（**不用 Timer**）；
④ 看门狗兼作**进程级停放探针**（应睡 5s 却过 ≥35s ⇒ 判挂起并抓栈）。

**自核查修掉三处自伤**：TimeCore 不 cancel 旧 Timer 会每拍翻倍；守卫释放改**认令牌**
（否则旧拍替接管拍开门，造出原本不存在的并发）；锁用**模块级常量**（本仓大量单测用
`__new__` 造实例，实例锁会集体 AttributeError）。

### 刀6 · D2 嵌套函数重复计数（P2）

`^\s*(?:async\s+)?def` 把嵌套函数也收成"方法"，外层 body 本已包含它 ⇒ 同一物理行报两条。
两层修：① **根因**——`_m374_nested_func_lines()` 用 AST 求嵌套定义行并跳过（外层已覆盖），
**类方法不算嵌套**；② **兜底键**——出口按 `(file, 行号, 类型, 签名)` 去重，签名**不含
method**（外层名与嵌套名正是重复计数唯一的区别）。
前提写明：`_parse_methods` 行号**系统性偏 1~2**（`\s` 含 `\n` 吞空行 + 切片基准偏一），
故单靠行号键去不掉内外层重复，必须靠嵌套判定。嵌套在方法条目里占 26/1409 ≈ 1.8%。

### 刀9 · 线程引导滞留观测（P2）

`Thread.start()` 在**新线程引导完成前不返回**，引导期一卡调用方就停在 start() 里。
两个坑不踩：**不用 Timer**（Timer 自己也要 start()）、**不用 `is_alive()`**
（start() 返回前恒 False）。判据只认 **`thread.ident is None`**，由启动期预建的常驻看门狗
（`ensure_watchdog()`，`main.py` 启动段）轮询判定；`safe_start()` **先登记再 start**，
start 返回后按 ident 判是否真引导成功——**ident 仍为空则不撤登记**（"start 返回 ≠ 引导完成"）。
配套：PulseLiver 的 T-107a 采样增「OS 线程数 − Python 活跃线程数」落差，突增 ≥1 且**连续
2 个采样点**才告警（单点抖动不算），拿不到 OS 数记 None **不填 0**。
