## 二、逐刀要点

### 刀1 · N1 内存爬坡归属只读取证

**★最重要的口径分离**（写进证据件首段，防误读）：
- `--pid` **进程外读数** = 曈曈真实值；`--self` **进程内分器** = **只反映探针自己**（跨进程拿不到 `gc.get_objects()`）。
- 探针**零生产 import**（刻意用标准库 `logging` 而非 `nucleus._silent_except`）、不新起定时器、不进心跳链。

**活体实测**：RSS **7275.2MB**（阈值 6144，超）／VMS 9615.1MB／句柄 **2439**（阈值 5000，未超）／线程 **191**；
打开文件 psutil 在 Windows 无 `num_fds` ⇒ 如实 `None`，用肝 T-107a 日志侧补齐 = **17**（阈值 2000）。

**★曲线形状判定（本刀最有价值的结论）**：RSS **不是线性爬坡，是锯齿+平台**——
17:04 7.20GB → 17:09 **6.93GB（−0.27GB）**，基线增长 3.03→2.77GB 同步回落，peak 7575.0MB。
⇒ 该查「**为什么平台这么高**」，不是「谁在漏」。
同时如实标注：5 分钟窗不足以定趋势，只下「非单调线性」一条，**不下「已收敛」**。

**排除项**：文件句柄泄漏（打开文件 17，离阈值两个数量级）；心跳积压（timeout 0 / pending 0）。

**归属候选 5 条**（`image_mb` 610.7MB 不可释放镜像居首）＋后续修复票方向：**先只做「注入采样」不做修复**。

## 四、流程优化（任务书 §七第 11 条 · 小林专项条款）

按「问题定位 → 最小改动 → 定向单测 → 证据留痕 → 回读复核 → 提交分笔」六步自评，
**沉淀 4 条可复用做法、补强 3 个薄弱点**。

### 4.1 沉淀的可复用步骤

| # | 步骤 | 本批出处 |
|---|---|---|
| 1 | **两档口径强制分离**（能测的 / 不能测的分开写，不许混述） | 刀1 探针把「进程外真实读数」与「进程内只反映自己」写进 evidence 首段 + `note` 字段 + `boundary` 列表，三处同步 |
| 2 | **取不到填 `None` 不填 `0`** | 刀1 打开文件在 Windows 无 `num_fds` ⇒ 如实 `None`，改用日志侧补齐并注明退化口径；单测 `test_04` 把「必须 None」钉死 |
| 3 | **断点结论必须落到「写侧 or 读侧」二选一** | 刀3 不停留在「回载=None」，而是查磁盘证实 `reload_stats.json` 从未生成 ⇒ 断在写侧，避免后续按「读侧路径不一致」做错方向 |
| 4 | **零漂移也是结论** | 刀4 不把「111 块没变」当成「没做事」，而是明确写成「360 至今无新增/无收口/口径未变 ⇒ 基线仍稳定可用」 |

### 4.2 补强的薄弱点

1. **取证探针的分器粒度**：刀1 把「器官/线程/缓存池/GC」四面显式列进工具接口，
   即使本批只跑通进程外一档，接口已按四面留好（后续注入即可复用，不二次开发）。
2. **三闸对照表的锚点可复现性**：刀3 单测 `test_01` 直接断言四个函数的**签名与常量值**仍在
   （`_O3_MISJUDGE_LINE=0.10`、`_M340_JUDGE_ACTION_MIN_TICKS=3`），锚点漂移立刻报错。
3. **注释断言的幂等覆盖面**：刀2 把「注释唯一性」从口头纪律变成**可执行断言**，
   并加**反向判别**（把注释再贴一遍 ⇒ 计数器必须报 2），证明断言不是恒真。

### 4.3 后续批次如何沿用

- 任何「只读取证」类刀，工具接口一律按「可测 / 不可测」两档设计，**不可测项在输出里显式标注 `note`**。
- 任何「断点定位」类结论，必须给出**反方向也排除**的一句（本例：「不是读侧路径不一致」），否则后续会做错方向。
- 任何「基线没变」的复核，都要把「没变」写成结论并给归因，而不是当成无事发生。
