## 四、刀1 · R1 self/obj 属性调用接消歧（P0 主线）

**改动**（`nucleus/self_awareness/CallGraphAnalyzer.py`）

- **R1**：`_resolve()` 的 `self.X()` 分支原来只查"同模块 qualname 表"，跨模块继承/mixin 即落空 ⇒ 改为落空时转 `_resolve_by_name`（作用域优先：同类 → **同文件** → 同模块 → 同目录 → 全库唯一），带 `caller_class` / `caller_file`，命中即标 `kind="self_attr"`
- **R2**：`obj.X()` 多义**仍不猜**，但全库同名唯一时建边（标 `kind="unique_name"`）；**硬护栏**：`_is_external` 判为外部的一律不享受此兜底（防把 os/json 算成"已解析"）
- 新增 `_m318_name_index()`（名称 → 节点 id 索引，懒惰构建）——避免每条未解析调用全表扫 `_defs`（27k × 6.8k 次不可承受）
- `_resolve_by_name` 改走该索引（语义不变）

**验收（隔离 + 全库实测）**

- K1-1 `self.X()` 跨模块命中并标 `self_attr` ｜ K1-2 `obj.X()` 唯一建边标 `unique_name`
- K1-3 多义仍不猜 ｜ K1-4 `os.path.join` 不进 R2 兜底（external 护栏）
- 全库：解析率 25.4% → **32.39%**、覆盖率 57.7% → **65.05%**
- **未达 35%/70% 验收线**——见 §十一 如实降级①

> **同文件档增强零收益（如实）**：在 `_resolve_by_name` 多义路径新增"同文件"档后，全库边数**未变**（9560），说明同文件多类同名的形态在本库极少；保留该档（无害、更严谨），但不宣称收益。

## 五、刀2 · dead_code 解禁条件换尺子（P1）

**改动**（`nucleus/self_inspector.py`）

- 新增 `SelfInspector._m318_resolve_rate(stats)`：**仓内可解析调用解析率**，分母显式排除 external
  `internal = total − unresolved − external`；`rate = internal / (internal + unresolved)`
- 档位常量：`_RESOLVE_GATE_JUDGE = 0.50`（X=50% 中间档→判死档新门槛）· `_RESOLVE_GATE_HIGH = 0.70`（高置信）· `_RESOLVE_GATE_REVIEW = 0.35`（待复核）· `_A1_FAILED_MAX = 0.50`
- `_detect_dead_code` 改为**新尺子优先**：`<35% silent`；`35~50% review`；`≥50% judge`；`≥70% high_confidence`
- **A1 护栏**：新增可选入参 `_a1_failed_rate`，超过 `Y=50%` 则降一档；**不可得（None）时不阻断**——"没测 ≠ 有病"，也不许据此放行
- `criteria_version = "2026-10-19.318.resolve50"`；旧覆盖率**保留为参考读数**（仍输出、可审计），不再当闸门
- **per-item 按 `criteria_version` 留样**：新增模块级 `_DEAD_CODE_PER_ITEM_BY_VERSION` / `_m318_record_per_item()` / `get_dead_code_per_item_by_version()`（每版本上限 500 条）——判死档打开后一次涌进数百条也不会被滚动 7 份冲掉

**验收**：K2-1 基线 stats 反算解析率 = **25.38%**（与烛微 25.4% 一致，口径自洽）｜K2-2/2-3 档位与版本常量｜K2-4 per-item 按版本留样（12 条可存可读）

**当前结论**：解析率 32.39% ⇒ **silent 档**（不判死、不出清单）。R1 还需再涨约 2.6pp 才进 review 档、约 17.6pp 才进判死档。
