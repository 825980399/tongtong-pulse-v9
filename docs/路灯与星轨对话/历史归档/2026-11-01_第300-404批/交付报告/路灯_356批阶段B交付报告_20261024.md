## 二 刀12 日志轮转截断修复（P1 · 星轨 v1.2 实拍）

### 三处根因（全部代码确认并修复）

| # | 根因 | 修法 | 实测 |
|---|---|---|---|
| ① | `_copy_truncate_rollover` 里 `if self.stream is not None:` —— 停机/close 后 **stream=None 整段跳过截断**，只复制不截断 | stream 不可用 ⇒ 退回独立句柄 `open(base,'r+b')` seek/truncate/fsync | **stream=None：5002 → 0 字节**（修复前保持 5002） |

| ③ | 树外 bridge 用**普通 FileHandler** 直写同一 pulse.log，与 SafeRotating 各持偏移 ⇒ 截断后对方在旧偏移写出空洞、把文件重新撑大 | bridge **优先复用主 SafeRotatingFileHandler 实例**（同一实例 = 同一偏移） | 源码守卫 |
| ④ | 轮转风暴（17 秒 20+ 条）无任何限额 | `_m356_rollover_budget_ok()`：60s 滑窗上限 3 次，超限冷却降级 + 单行告警 | 第 4/5 次返回 False |

### ★现场证据链（比"同内容副本"更强）

```
.5 ⊂ .1  = True      # .5 是 .1 的严格前缀
.1 ⊂ 主文件 = True   # .1 是主文件的严格前缀
```
三份日志构成**前缀链**——每次轮转只是把"越来越长的主文件"又拷贝了一份却从未截断。这是①的**指纹证据**，也说明 `.5` 内容 100% 被 `.1` 包含（可安全删除），而"同内容"这个说法**只在前 4KB 成立**。
