## 二、A 组 · 停机恢复线（刀1 P0 首刀 → 刀2）

### 刀1 · ChatService 剥离主装配路径（P0 · 342 刀5 回归修复）

- **问题（四方互证坐实）**：342 刀5 `32e24c1b` 去掉旧版 daemon 线程包装后，`function_loader.py:115` 同步调 `ChatService.start()`，其内部 `_chat_loop()` 在 `:337 input()` 阻塞 **6h23m**；主线程永久未进主循环（4366-4368 循环外首拍 `[351节拍]` 本代次 0 命中），shutdown 通道/补丁闸门/消费口/退出流程全部不工作。
- **改法（小林已拍板方向）**：
  1. `_chat_loop()` 起独立 daemon 线程，或改非阻塞 select 轮询 stdin；
  2. `start()` 仅注册监听器＋打横幅＋起循环线程后**立即返回**；
  3. `FUNCTION_META` thread_mode 据实更正（现 blocking 与 328 行「完全非阻塞」注释名实不符）；
  4. 342 前置查证补记「ChatService 例外：start() 内部同步驻留阻塞循环」；
  5. 补单测：装配完成后主线程不被 `input()` 阻塞（主线程跑过装配点即返回）。
- **边界**：不碰状态机/审批池/审计池数据；不动 `_chat_loop()` 内业务消息处理逻辑，只改线程模型；stdin 在无控制台场景（pythonw/服务化）下 EOF 行为要留痕不炸。

### 刀2 · watcher 前移＋启动失败留痕（P1）

- **问题**：卡点二现场——EOF 后主线程推进到 `main.py:4225` `config.start_config_watcher()` → `config.py:4185 Thread.start()` → `threading.py:999 self._started.wait()` 死等（两轮堆栈快照帧一致）；同进程另有 7 个后台线程同类卡死。
- **改法**：
  1. T0 先复核 watcher **无器官实例依赖**（load_all 之前可用）；
  2. 前移 `start_config_watcher()` 调用点到 load_all 之前；
  3. watcher 线程启动失败/超时观测留痕（不静默吞）；
  4. 是否更深修（CPython 机制面）待烛微丁票 `T-372-前置-CPython线程启动死等定性-1` 定性后再议，本刀只做前移＋留痕。
- **边界**：watcher 行为不变，只改调用时机与留痕；不新建定时器进心跳链（丙票 `T-372-线程句柄埋点告警-1` P2 到期 375 另排）。
