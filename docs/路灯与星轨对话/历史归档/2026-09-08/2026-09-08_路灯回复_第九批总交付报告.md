原输出：`我了解到，我按照4个步骤进行了处理：。✅ 步骤1…`（机器腔 + 悬空句号 + 无过渡）

### 4.2 大脑皮层输出锁超时（多步推理被 90s 一刀切）

## 三、任务3 身份认知 ✅（自测 18 项 + 端到端 13 项）

### 3.1 新建 `nucleus/mnemosyne/IdentityKnowledgeManager.py`（约 700 行）
数据结构：`人物名 → {aliases, relations[{target, relation, confidence, source, raw, first_seen, last_confirmed, hits}], pending[]}`

- **抽取**：别名链（`就是/也就是/即/亦即/aka`）+ 正向关系（`A是B的Z`）+ 反向关系（`B的Z是A`）；`_clean_target()` 是关键修复——先按别名连接词取最后一段，再删关系词，再归一自称，**避免把"[属主真名]也就是你"整体当成人名**
- **关系推理**：`RELATION_INVERSE`（反向表）+ `RELATION_COMPOSE`（组合表）。`A是B的父亲 + B是C的父亲 → A是C的祖父`，推理置信度 ×0.9 且标 `inferred`/`via`，**与直接陈述区分开**
- **冲突绝不覆盖**：同 target 不同关系 → 进 `pending` 队列 + WARNING，等人工裁决（`resolve_pending(index, accept_new)`）。这是刻意设计——宁可挂着不知道，也不能把错的固化成长期记忆
- **路径/沉淀**：`person_path → /人物/{人名}`；`export_nodes()` 只导出置信 ≥0.75（`confirmed_threshold` 可配）的已确认关系，`suggested_level="L3"`

### 3.2 对话记忆消费更新身份
`PulseInnerWorld._ingest_identity_claims(question, user_name)` —— **放在 `_record_conversation` 所有门槛之前**。这一点很关键：用户说「小林就是[属主真名]也就是你的父亲」时回答往往很短，若放在长度/置信度门槛之后，这类短对话会被整个跳过，身份永远学不到。高置信再经 `_persist_identity_nodes` 幂等沉淀为 L3 节点（已存在同名节点跳过）。

### 3.3 回答拼凑修复（节点标签过滤）
新增 `_NODE_LABEL_FIELDS`（功能/依赖/参数/风险/关键步骤/调用关系/方法列表/入口方法/叶子方法/返回值）+ `_strip_node_labels()`，在 `_clean_inference_output` 第 3.5 步调用。处理：删「标签: 内容」整体 → 删孤立标签串（`依赖、功能:`）→ 清理残留空句与悬空顿号句号。
实测：`这个模块的情况是 功能: 负责推理调度 依赖: engine、memory 参数: topk=5 返回值: 结论文本。整体运行稳定。` → `这个模块的情况是。整体运行稳定。`（正文保留，标签全清）

### 3.4 QICA 人物路径接通
知识检索处改为 `_identity_hit = self._identity_lookup(question)` **优先命中**——不再依赖 QICA 是否恰好给出 `/人物/` 路径（此前知识树里根本没这些节点，检索必然落空）。
