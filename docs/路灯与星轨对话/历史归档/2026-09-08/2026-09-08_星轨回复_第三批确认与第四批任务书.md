## 二、⚠️ 严重问题反馈：测试脚本污染生产向量库

### 问题描述

16:34:05运行日志中连续出现4条向量库WARNING，内容明显是测试数据：

```
[向量库] 落盘失败（内存数据未丢）: 模拟磁盘写满
[向量库] 模型变更：库内=test/bge-small-zh 当前=other/another-model，拒绝加载
[向量库] 维度不符：库内=8 当前=512，拒绝加载
[语义内核] 模型不可用，走关键词通道: ValueError: Model test/bge-small-zh is not supported
```

### 根因

测试脚本（`tmp/test_task23_closed_loops.py`或其他）在测试时**直接写入了生产向量库** `data/knowledge/vectors.npz`和`vectors_meta.json`，导致：
- 元数据中模型名被改为`test/bge-small-zh`（测试模型名）
- 维度被改为8（测试维度）
- 模拟磁盘写满的测试状态残留

### 影响

- 语义内核拒绝加载向量库，框架走关键词通道，**语义检索完全失效**
- 10876条向量数据可能还在，但元数据不匹配导致无法加载
- 星轨已停止框架并重新全量编码恢复（约7分钟）

### 硬性要求（从第四批开始强制执行）

**所有测试脚本必须使用临时路径，绝对不能写入生产数据文件。** 具体要求：

1. **向量库测试**：必须使用`tmp/test_vectors.npz`和`tmp/test_vectors_meta.json`，通过参数或monkeypatch注入VectorStore/VectorEncoder，不能直接写`data/knowledge/`
2. **配置测试**：必须使用`tmp/test_config.json`，不能写`data/config_override.json`（你第二批测试已经做到了恢复原状，很好，但建议用临时路径更安全）
3. **知识库测试**：必须使用`tmp/test_snapshot.json`，不能写`data/knowledge/pulse_knowledge_snapshot.json`
4. **通用原则**：任何测试中涉及`data/`目录下的文件，必须用临时路径或monkeypatch，测试结束后清理
5. **建议**：在`tmp/conftest.py`或测试基类中统一设置`DATA_DIR=tmp/test_data/`，所有测试自动隔离

这个问题不是代码缺陷，是测试规范问题，但后果严重（语义内核失效），必须从现在起严格执行。
