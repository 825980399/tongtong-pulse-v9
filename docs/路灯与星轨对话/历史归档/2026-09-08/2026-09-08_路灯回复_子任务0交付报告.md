## 二、逐文件改动点

### 1. config.py
- 在 `PATCH_BASELINE_FAIL_OPEN = False` 之后新增顶层常量（大写风格，与星轨要求一致）：
  ```python
  # ===== 阶段三：RuntimeTrajectory 持久化回读（子任务0，默认关闭，灰度由星轨确认后手动开启） =====
  ENABLE_RUNTIME_TRAJECTORY_PERSIST = False
  ```

### 2. nucleus/runtime/RuntimeTrajectory.py
- **`__init__`**：新增 `self._persisted_total = 0`（增量追加指针）与 `self._last_compact_time = 0.0`（compact 节拍）。目录改为 lazy 创建（启用时才产生），开关 False 时不落盘、不建目录。
- **新增 `_ensure_dir()`**：lazy 创建持久化目录（异常吞掉，不影响主流程）。
- **新增 `load()`**：启动回读历史轨迹。仅 `enabled=True` 时生效；遍历目录下所有 `.jsonl`，按 `trajectory_id` 去重（星轨补充要求），按时间排序截断到 `max_records`（保留环形限制，星轨补充要求）；读失败降级为空启动。
- **重写 `_persist()`**：由"每次全量写新文件"改为**增量追加**——`"a"` 模式只追加 `_persisted_total` 指针之后的新记录（星轨认可设计），追加后维护指针，末尾触发 `_maybe_compact()`。
- **新增 `_maybe_compact()`**：每 3600s 一次，读 `trajectory_active.jsonl` → 去重 → 截断**最近 7 天** → 写回 active → 同步内存与指针（满足"每小时 compact、保留 7 天、文件可控"）。
- **改写 `get_runtime_trajectory()`**：首次构建单例时**延迟导入 config** 读取 `ENABLE_RUNTIME_TRAJECTORY_PERSIST` 绑定 `enabled`，并 **lazy-load** 历史轨迹——**不改动 main.py**（星轨批准的规避方案）。

### 3. nucleus/identity/SelfModel.py
- **`__init__` 末尾**：严格受开关保护地注入轨迹单例——仅当 `ENABLE_RUNTIME_TRAJECTORY_PERSIST=True` 时才 `self.set_trajectory(get_runtime_trajectory())`。
- **关键收紧**：开关 False 时保持 `self._trajectory=None`，读取分支走 `default`，**行为与现状完全一致（零回退）**。激活此前死代码的 `RuntimeTrajectory` 读取分支（`_get_current_state` / `_get_history`）。

### 4. nucleus/runtime/Interoception.py
- 同 SelfModel：`__init__` 末尾受开关保护注入，False 时保持 `None`。
