## 执行摘要（10 行内说清结论）

1. **时间基础设施已存在但三源分裂、基本闲置**：`nucleus/chronos/GlobalClock`（纳秒基准/uptime）与 `EventStream`（事件流）全项目零引用；`utils/time_utils.get_current_datetime()` 仅 3/62 器官共 6 处调用；另 50/62 器官裸 `time.time()` 各算各的。
2. **TimeCore 不该再造时钟，应做「统一广播层」**：组合复用 `GlobalClock`（生命时间）+ `time_utils`（语义时段/天气），向所有器官广播统一时间基线。
3. **时间意识六层次全部可落地，无结构性阻塞**；最大前置依赖是 `RuntimeTrajectory` 的持久化回读（切片02）——它是第二/五/六层的共同地基。
4. **TimeCore 定位**：放 `nucleus/chronos/TimeCore.py` 作**内核单例** `get_time_core()`（与 `get_runtime_trajectory()` 同范式），而非 `organs/body/` 器官——因其驱动所有器官 cron、自身不是订阅者。
5. **广播机制**：复用现有 `InfoField` 共振订阅（无原生 `PulseBus`），62 订阅异步分发可承受；配 `BasePulseOrgan.on_time_tick()` 空钩子统一收口（方案d）。
6. **第四层是核心**：PulseHeart 当前用本地 `interval/last_run` 被动触发规则；改为 TimeCore `trigger_due_rules()` 主动调度，灰度互斥 + 双写过渡规避漏跑/重复跑。
7. **第三层知识时效**：time 维（权重0.10）现基于 `last_activated` 新鲜度，非"来源时效"；改写 `_calc_time_dim` 支持 `source_time` 衰减，**不触五维宪法权重、不影响 peak 门**。
8. **第五/六层（预测/反思）** 排在阶段四：预测用"到达间隔中位数+配置回退"；反思复用现有 `PulseReflection`（前额叶）分析底座，TimeCore 定时发 `time.review.trigger` 做周期聚合——但均被切片02 数据缺口阻塞。
9. **6 类耦合点**（生命周期/调度互斥/时基分裂/总线分发/RT依赖/进化冲突）全部可解，无不可解冲突。
10. **所有新功能灰度开关默认 False**，遵守项目红线；实施顺序强制 02（先）→ 05 → 06/07。

## 三、TimeCore 设计方案

### 3.1 定位与时基分工
- **位置**：`nucleus/chronos/TimeCore.py`，内核单例 `get_time_core()`（对齐 `get_runtime_trajectory()` 范式）
- **时基分工（强制约定）**：
  - 调度/节流 → 墙钟 `time.time()`（不受 `GlobalClock.pause/scale` 影响）
  - 生命时间/可观测 → `GlobalClock.get_uptime_seconds()` / `now_ns()`

### 3.2 类结构草案
```python

    _instance = None
    def __init__(self, info_field, pulse_core, config):
        self._ic = info_field; self._pc = pulse_core; self._cfg = config
        self._interval = config.PULSE.get("timecore_broadcast_interval", 60.0)
        self._timer = None; self._lock = threading.Lock()
        self._last_tick: dict = {}

    def _build_time_info(self) -> dict:
        # 复用 GlobalClock.get_uptime_seconds() + time_utils.get_current_datetime()/get_weather()
        # 补 season/is_weekend/is_holiday/uptime_hours（先修 time_utils 负面缓存 P5）

    def _schedule_next(self):
        with self._lock:
            self._timer = threading.Timer(self._interval, self._tick)
            self._timer.daemon = True; self._timer.start()

    def _tick(self):
        try:
            info = self._build_time_info(); self._last_tick = info
            p = self._pc.emit(source_organ="时间中枢", event_type="time.tick",
                              payload=info, priority=2, layer="L3")   # L3 异步，避开 L0 背压
            self._ic.publish(p)
        finally:
            self._schedule_next()                      # 复用 PulseHeart 自触发链

    def predict_next_run(self, rule_id): ...          # 第五层（阶段四）
def get_time_core(): ...                              # 懒加载单例
```

### 3.3 广播机制（方案 d）
- TimeCore 经 `InfoField.publish` 发 `time.tick`（L3 层）；62 器官各自在 `get_resonance_conditions` 加 `time.tick` 订阅
- `BasePulseOrgan` 加空 `on_time_tick(time_info)` 钩子统一收口；handler 走 InfoField 安全包装（`handle_pulse_safe`，`:440-536`），某器官异常不拖垮分发
- 发布方线程内 O(62) if 匹配 + 62 异步线程池任务，`publish` 立即返回不阻塞（`:559-700`）

### 3.4 与 PulseHeart 的关系
- **基础心跳保留**：`threading.Timer` 链、BEAT/ALIVE、`_calculate_heart_rate`、`survival_orchestrator`（红线1：不改现有心跳）
- **调度渐进接管**：灰度 `enable_timecore_active_schedule` 默认 False；开启后 Heart 旁路 `_check_scheduled_tasks`（`:400`），TimeCore 接管；迁移期双写去重
