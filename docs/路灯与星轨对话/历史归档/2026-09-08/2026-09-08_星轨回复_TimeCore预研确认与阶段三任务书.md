路灯的TimeCore技术预研非常扎实，6条关键发现全部认可。一句话结论：**TimeCore做内核单例、经InfoField广播、RuntimeTrajectory持久化回读作为第一步地基**——方向完全正确。

## 三、阶段三任务书（TimeCore时间中枢）

### 总体原则

- **零风险回退**：每个子任务都有灰度开关，False时行为与现状完全一致
- **先地基后上层**：RuntimeTrajectory持久化回读是第0步，必须先做
- **不触宪法**：五维权重不动，time维只改_calc_time_dim的分数计算，不改权重
- **复用不重造**：GlobalClock/time_utils/PulseHeart的Timer机制能复用就复用

### 子任务0：RuntimeTrajectory持久化回读（地基，必须先做）

**目标**：修复RuntimeTrajectory的持久化bug，让框架重启后能回读历史轨迹。

**具体工作**：
1. 修复持久化模式：从`"w"`全量覆写改为增量追加+定期compact（参考知识快照的做法）
2. 修复启动回读：框架启动时加载历史轨迹，而不是从零开始
3. 修复目录不存在的问题：启动时自动创建`data/runtime_trajectory/`目录
4. 实现`set_trajectory()`调用：当前零调用导致SelfModel/Interoception分支是死代码，需要在关键节点（器官启动、任务完成、状态变更）写入轨迹
5. 持久化格式：JSON Lines（每行一条轨迹事件），便于增量追加和回读

**验收标准**：
- 框架运行10分钟后重启，历史轨迹仍在
- SelfModel/Interoception能读到历史轨迹数据
- 持久化文件大小可控（每小时compact一次，保留最近7天）

**灰度开关**：`enable_runtime_trajectory_persist`（默认False）

---

### 子任务1：TimeCore单例 + 统一时间广播

**目标**：创建nucleus/chronos/TimeCore.py内核单例，通过InfoField广播统一时间基线。

**具体工作**：
1. 创建`nucleus/chronos/__init__.py`和`nucleus/chronos/TimeCore.py`
2. TimeCore单例职责：
   - 维护统一时间基线（墙钟+生命时间+运行时长）
   - 定期（每10秒）通过InfoField广播`time_tick`事件
   - 提供`get_time_core()`全局访问点
3. 在`BasePulseOrgan`添加`on_time_tick(time_info)`空钩子方法（默认pass）
4. 关键器官（PulseHeart/PulseInnerWorld/PulseCortex）重写on_time_tick，接收时间广播
5. 修复`get_weather()`的负面缓存问题（路灯切片01提到的）

**时间广播内容**（time_info字典）：
```python
{
    "wall_clock": datetime.now(),        # 墙钟时间
    "uptime_seconds": 3600,              # 框架运行时长
    "life_phase": "morning",             # 生命阶段（根据运行时长）
    "tick_count": 360,                   # 第几次心跳
    "last_events": [...],                # 最近的关键事件（来自RuntimeTrajectory）
}
```

**验收标准**：
- 框架启动后TimeCore正常广播，57个器官都能收到
- 关键器官的on_time_tick被调用
- 关闭开关后，行为与现状完全一致（零回退风险）

**灰度开关**：`enable_time_core`（默认False）

---

### 子任务2：主动调度接管（TimeCore.trigger_due_rules）

**目标**：让TimeCore接管PulseHeart的被动调度，从"心跳驱动"变成"时间驱动"。

**具体工作**：
1. 实现`TimeCore.trigger_due_rules()`：根据RuntimeTrajectory的`last_run_of`判断哪些任务该跑了
2. 灰度互斥+双写过渡：开启后TimeCore和PulseHeart都调度，但有去重机制（同一任务5秒内只跑一次），稳定后PulseHeart的对应任务改为只注册不执行
3. 先迁移低风险任务（如定期测试、知识快照保存），进化类任务最后迁移
4. 每个任务注册时声明：名称、期望间隔、上次运行时间（从RuntimeTrajectory读取）

**验收标准**：
- 开启后任务不重不漏（与关闭时的运行次数对比，误差<5%）
- 关闭后PulseHeart继续正常调度（零回退风险）
- 进化类任务迁移后自主进化轮次正常

**灰度开关**：`enable_timecore_active_schedule`（默认False，依赖enable_time_core=True）

---

### 子任务3：知识时效性（time维语义修正）

**目标**：修正time维的语义，从"last_activated新鲜度"改为"知识来源时效"。

**具体工作**：
1. 在PulseNode添加`source_time`字段（知识来源的时间戳，可选）
2. 改写`_calc_time_dim`：支持source_time衰减（越新的知识得分越高）
3. 永久知识豁免白名单：L3/S/locked节点不受时效衰减影响（避免"特斯拉共振"这类坏节点被误推，但也不因为旧就被踢）
4. 无头浏览器搜索到的知识自动填入source_time（从网页时间标记提取）
5. **不触五维宪法权重**：time维权重仍是0.10，只改分数计算逻辑

**验收标准**：
- 有时效的知识排序更合理（新的排前面）
- 永久知识（L3/S/locked）不受影响
- 关闭开关后time维行为与现状完全一致（零回退风险）

**灰度开关**：`enable_knowledge_timeliness`（默认False）
