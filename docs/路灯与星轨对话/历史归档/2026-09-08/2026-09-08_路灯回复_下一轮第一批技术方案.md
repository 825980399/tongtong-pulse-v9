## 一、调研结论（与任务书的 3 处偏差，重要）

### 偏差1（任务1）：全局学习器空转的真因不是"配置关闭"，而是 `_lessons_provider` 从未注入

任务书推测"是抽样逻辑有bug？触发条件？配置关闭？"

**真实根因**（已逐行核实）：
- `PulseGlobalLearner._collect_and_sample()`（`organs/core/PulseGlobalLearner.py:240-269`）的样本**唯一来源**是：
  ```python
  lessons = self._call_provider(self._lessons_provider, limit=10, default=[])
  ```
- `_lessons_provider` 由 `set_lessons_provider()`（同文件 111 行）注入。
- 但 **main.py 从未调用它**——`main.py:1460-1477` 注入了 experience_pool / semantic_comprehension / self_inspector / code_learner / lung 共 5 个依赖，**唯独没有 `set_lessons_provider`**。
- → `_lessons_provider=None` → `_call_provider` 返回 `default=[]` → `samples=[]` → 抽样=0 → `_execute_comparisons` 直接 `return 0` → 学习=0。**与星轨观察到的"4次审计全0"完全吻合。**

**更深层问题**：`_execute_comparisons`（271-304）代码注释自承——
> "调用大模型进行比对（简化：这里仅记录，具体比对逻辑由各模块完成）"
即该方法**实际从未真正调用大模型比对**，只往 experience_pool 写了一条"通过比对学习了新案例"的体验记录。所以即使补足样本，"学习"也只是记账，不产生可落地的优化结论。任务书要求"学习内容包括运行参数优化、搜索策略调整、消化质量改进"，这是**新增能力**，不是简单填补 None。

### 偏差2（任务4）：TimeCore 白名单机制**已存在**，方案A 是"加一项"而非"新建机制"

任务书建议"加入白名单"是对的，但现状比预期更省事：

### 偏差3（任务8）：不是"注入逻辑bug"，而是 `PulseNodePool` 的**内容级去重**把新节点合并了

任务书推测"只在节点不存在时创建 / 注入逻辑有路径处理bug"。

**真实根因**（已读 `nucleus/mnemosyne/PulseNodePool.py:270-335`）：
- `add()` 有两道去重：
  1. **幂等检查**（294-306）：按 node_id 去重
  2. **内容级去重**（311-316）：`_try_merge_duplicate(node)`，**L3 阈值 80% 相似度、检查最近 30 个节点**，命中则"合并到已有节点，不重复添加"
- `main.py:2624-2640` `_inject_seed_memories()` **没有去重逻辑**，每次都新建 PulseNode 并 add
- → 快照恢复后旧路径 `/自我/架构/共振引擎` 节点已存在且 **value 完全相同** → 新节点被内容去重合并 → **新路径 `/自我/架构/推理引擎/共振引擎` 下无任何节点**
- **这完美解释了星轨观察到的"五维共振注入成功、共振引擎注入失败"**：
  - 五维共振：我在 D-1 微调了 value（"五维共振指…加权打分机制…"）→ 与旧节点内容差异超阈值 → 未去重 → ✅ 注入成功
  - 共振引擎：我只改了 space_path、**value 一字未动** → 与旧节点 100% 相同 → 触发去重 → ❌ 被合并
