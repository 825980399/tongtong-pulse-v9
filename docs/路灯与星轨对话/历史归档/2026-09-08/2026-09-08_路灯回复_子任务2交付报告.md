## 二、修改点说明

### 1. TimeCore 托管调度（核心）
- `_init_managed_tasks()`：从 `config.TIMECORE_SCHEDULE_CONFIG` 读配置，每任务 `last_run = now - (interval - random.uniform(0.5, interval))`，**与 PulseHeart `_jitter` 完全一致**的错峰公式，消除启动尖峰。
- `_dispatch_managed_tasks()`：遍历 `_managed_tasks`，到期（`now - last_run >= interval`）则经 `get_info_field().publish(...)` 发射 pulse，锁内更新 `last_run`、锁外 publish（对齐 Heart 防死锁）。
- 发射的 pulse **逐字段对齐 Heart._emit**（验收标准4）：
  ```python
  {
      "event_type": info["event_type"],      # 与 Heart 发出的完全一致
      "source_organ": "TimeCore",            # 可追溯，不影响按 event_type 路由
      "payload": {"task_id": tid, "last_run": ..., "scheduled_at": now},
      "priority": 3,                         # 对齐 Heart._emit priority=3
      "layer": "L3",                         # 对齐 Heart._emit layer="L3"
  }
  ```
- `_tick()` 顺序（星轨确认）：`self._broadcast()` → `if _active_schedule_enabled: self._dispatch_managed_tasks()`。

### 2. PulseHeart 跳过被接管任务（最小侵入）
- 仅在 `start()` 的 `with _scheduled_tasks_lock:` 块末尾追加 7 行：开关开启时从 `_scheduled_tasks` pop 被接管 task_id，**22 个注册语句零改动**，核心器官核心逻辑未触碰。
- 用 `import config as _tcfg` **局部导入**（实测 PulseHeart 模块级无 `import config`，避免改模块头引入循环依赖风险）。
- 天然无双重执行：Heart pop 后 `_check_scheduled_tasks` 不再遍历这些 key，TimeCore 成为唯一触发方。

### 3. watchdog（可选增强，已做轻量版）
- 每次 `_tick` 记录 `_last_tick_time`，若距上次跳变 `> 2 * interval` 打 ERROR 告警（提示关闭开关回退 Heart）。
- **未做自动回退 Heart**：回退需 Heart 重新注册任务，风险较高；星轨明确"可选、不强制"。告警即足够触发人工/后续干预。
