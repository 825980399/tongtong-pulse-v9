## 五、Cython 状态（★ 12:39 星轨纠正：Cython 实际已启用，必须改 .pyx）

### 纠正前（错误假设）
- 初版报告基于"星轨 12:35 旧版回复里 Cython 默认 False"的判断，认为 Python 兜底层改动即生效、**无需改 .pyx**。

### 纠正后（实测真值）
- `config.FEATURE["use_cython_extensions"] = True` → `_resonance_cy_available=True` → `_calc_time_dim` 实际走 **Cython 版 `calc_time_dim_cy`**，Python 兜底层**不会生效**。
- 因此**必须同步改 Cython 源码并重编译**，否则时效性融合在 Cython 启用时完全不工作。
- 运行日志佐证：`Cython加速模块已加载 (_resonance_cy)`、`Cython扩展自检: 6/6 全部加载`。

### 补充：Cython 同步修改（本次新增）
1. **`_resonance_cy.pyx`** — `calc_time_dim_cy` 签名由 `calc_time_dim_cy(double elapsed_seconds)` 改为：
   ```python
   def calc_time_dim_cy(double elapsed_seconds, double source_age_seconds=0.0, bint enable_timeliness=False) -> float:
   ```
   - `enable_timeliness=False`：仅激活新鲜度，与现状逐字节一致，**零回退**。
   - `enable_timeliness=True`：`score = 0.5 * activation + 0.5 * source`（source 分段阈值 <7天=1.0/<30=0.85/<90=0.65/<365=0.40/>=365=0.20）。
   - 纯数值、nogil 块内完成，不涉及 Python 对象。
2. **重新编译** — `cd nucleus/pulse && python setup_cython.py build_ext --inplace --compiler=mingw32`
   （本机无 MSVC 14.0，改用 MinGW gcc `/d/mingw64/bin/gcc` 编译；4 个扩展全部 gcc 链接成功）。
3. **ResonanceEngine.py 调用处** — `_calc_time_dim_base` 在开启路径向 Cython 传 `(elapsed, source_age, enable_timeliness)`；
   **融合只在 Cython 内做一次**，Python 层不再二次融合（杜绝双重加权），Python 兜底层镜像同逻辑。
4. **节点字段修正** — 星轨示例写 `node.source_time`（对象式），但 `node` 实际是 **dict**，已改为 `node.get("source_time")`，与既有 `_calc_time_dim_base`/`_source_timeliness` 风格一致。
