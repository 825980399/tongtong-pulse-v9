- 经验结构：{问题特征 token / 修复策略 / 领域 / 命中次数 / 成功率 / 权重 / 来源}
- **沉淀**：补丁**验证通过后**调用 `_record_repair_experience()`（=一次成功修复），同源同策略自动合并强化而非膨胀

- **跨领域**：同领域 ×1.15 加成，异领域**不惩罚**（这是"举一反三"的核心）
- **衰减**：未命中经验按天降权（0.02/天），低于阈值淘汰；复用失败反馈降权，连续失败3次淘汰
- **日志**：经验命中/沉淀/反馈均打 INFO（经验ID/匹配度/领域/策略摘要）

### 关键技术决策：匹配算法用**重叠系数**而非 Jaccard
初始用加权 Jaccard，实测"请求超时导致抓取失败"（双腿）与"网页请求超时抓取失败"（控制器）相似度仅 0.583，**跨领域匹配不到**。根因：Jaccard 被经验里的长尾特征稀释，短问题几乎永远匹配不上。
改用 `交集 / min(查询集, 经验集)`（重叠系数，交集<2 视为偶然撞词）→ 匹配度 0.607，跨领域命中；同时不相关问题（"关键词提取纯度偏低"）命中数 = 0，无误召回。

### 挂点

## 四、任务 A-16：StreamMiner 消费链路补全 ✅

### ① hebbian_weight 回写 —— **实证结论：未完全断裂，但有真实缺陷**
按星轨要求"先确认再动手"，核查结果：
- **未断裂**：v23.0 已在 `PulseNodePool.get()` 内联实现"激活 → 取平均连接权重 → 写回节点"
- **真实缺陷 1（只增不减）**：用 `max(旧值, 新值)`，赫布衰减后节点权重永远降不下来，陈旧共现关系被永久固化
- **真实缺陷 2（覆盖窄）**：只有 `get()` 一条路径回写

**修复**：新增 `PulseNodePool.sync_hebbian_weight()`，改为 **EMA 平滑（α=0.3）可升可降**；`get()` 改用新方法。实测：共现后 0.1592，连接衰减后 → 0.1274（旧实现会停在 0.1592）。

### ②③④⑤ 其余四个断裂点
| 断裂点 | 实现 | 验证 |
|---|---|---|
| ② 周期模式无消费方 | `get_upcoming_events(horizon)` + `register_periodic_predictions()` → InfoField 发射 `pattern_prewarm` 脉冲（预加载知识/预留资源） | 预调度产出 1条（heart.beat / 10秒后） |
| ③ 重复模式无消费方 | `get_load_forecast()` → 负载预测（高频事件 high 级，供调度优先级优化） | 产出 knowledge.written/heart.beat 均为 high |
| ④ 模式未持久化 | `save_patterns()`/`load_patterns()` → `data/stream_miner/patterns.json`（原子写），含模式+周期缓存+质量统计 | 落盘→重载 1个模式，周期缓存恢复 |
| ⑤ 质量无评估 | `evaluate_pattern_quality()`：统计预测命中率，样本≥5 且命中率<0.3 → 自动淘汰 | 低质模式（1/10）被淘汰 |

**综合入口** `consume()`：一次调用完成预调度+负载预测+质量评估+定期落盘。
**命中校验**：`feed_event` 内校验周期预测（容差60秒）→ hit/miss 统计。

### ⚠️ 修复了一个真实死锁（自查发现）
`feed_event` 已在 `with self._lock` 内，再调 `_check_prediction_hits()`（内部同样加锁）→ **普通 Lock 自死锁**，开关一开框架直接卡死（自测首次运行即卡死在 feed_event，60秒无响应）。
修复：`self._lock` 改为 `threading.RLock()`（Lock 超集，对既有调用点完全兼容）。
