## 二、任务C：置信度Guard增强 + 路径桥接收紧

### C-1：收紧 _verify_knowledge_relevance 路径桥接漏洞

**当前问题**：
`PulseInnerWorld.py` 的 `_verify_knowledge_relevance`（约17956行）存在路径桥接漏洞——只要space_path名含问题任一2字主题词就返回0.45保底相关。例如"身份自我"含"自我"→桥接命中→不降级，导致错误节点被当作相关结果。

**修复要求**：
1. 路径桥接不能只看路径名包含主题词，必须同时满足：
   - 路径名包含问题的**核心关键词**（≥3字，或问题中权重最高的词），而非任意2字主题词
   - 节点内容本身与问题有至少1个关键词重叠
2. 如果只有路径名匹配但节点内容无关键词重叠，相关度上限降为0.20（而非0.45）
3. 增加白名单：`/自我/架构/` 下的路径可以保留0.45桥接（架构知识路径名本身就有意义）
4. 其他路径（特别是`/身份/`、`/自我状态/`、`/综合/`）必须走严格匹配

**验收标准**：
- 问"共振引擎"时，`/身份/自我` 路径不再被桥接为0.45
- 问"你是谁"时，`/身份/自我` 路径仍能正常匹配（不影响正常查询）
- 单元测试覆盖：路径名匹配但内容不匹配 → 相关度≤0.20

### C-2：置信度Guard增加检索相关性检查

**当前问题**：
5.3的confidence guard只检查三通道一致性（confidence≥0.6），不检查检索结果相关性。当三通道一致指向错误节点时，confidence也会高，guard拦不住。

**修复要求**：
1. 在 `PulseInnerWorld.py` 本地推理返回前，增加检索相关性二次检查：
   - 如果检索结果的最高相关度 < 0.30，即使confidence≥0.6，也return None走兜底
   - 阈值复用现有的相关度计算结果，不另造阈值
2. 增加日志：当因检索相关度低而走兜底时，打印 `[置信度Guard] 检索相关度不足(0.XX<0.30)，走兜底`
3. 不改变现有confidence guard的逻辑（<0.6仍return None），只是增加一道检查

**验收标准**：
- 检索相关度0.00 + confidence 0.75 → 走兜底（之前会硬编错误答案）
- 检索相关度0.50 + confidence 0.75 → 正常返回
- 检索相关度0.50 + confidence 0.40 → 走兜底（confidence不足）
- 单元测试覆盖3种场景
