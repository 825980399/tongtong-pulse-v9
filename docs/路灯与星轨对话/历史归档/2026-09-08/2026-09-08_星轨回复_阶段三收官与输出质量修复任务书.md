## 二、新发现的P0问题：本地推理输出质量差

### 问题现象

用户输入：`曈曈，什么是共振引擎？`

框架输出：
```
我了解到，[曈曈] 【种子记忆】[自我状态] 系统当前处于light负载状态，
信息场有53个活跃条件，四层线程池（L0, L1, L2, L3）正常运行。
【关联发现】以下知识与种子记忆存在关键词关联：
关联1(共同关键词: 自我状态): [自我状态] 当前知...（由10条认知融合而成）。此刻的我——
```

**问题**：输出完全没有回答"什么是共振引擎"，而是在描述自我状态，内容拼凑、不完整、不相关。

### 根因分析

#### 根因1（P0）：QICA路径检索与查询不相关

```
QICA领域知识库命中: 概念匹配→['/身份/自我', '/自我/架构/检索优化']
QICA路径检索: 路径=/身份/自我, 命中节点
```

用户问"共振引擎"，但QICA命中的是`/身份/自我`路径。检索到的节点都是关于自我状态的，导致后续推理基于错误的知识。

**可能原因**：
- QICA的概念匹配逻辑过于宽泛，"引擎"被匹配到了"自我状态"相关节点
- 缺少查询关键词与路径的相关性校验
- 共振引擎相关的知识节点可能路径不对或缺失

#### 根因2（P0）：本地推理输出拼凑逻辑有问题

内在世界（inner_world）的`qica_knowledge`方法生成的输出是：
- 【种子记忆】+ 自我状态描述
- 【关联发现】+ 关键词关联
- （由N条认知融合而成）
- "此刻的我——"

这种模板化输出没有直接回答用户问题，而是在展示内部状态。

**需要检查**：`PulseInnerWorld.py`中`qica_knowledge`或相关方法的输出生成逻辑。

#### 根因3（P1）：置信度guard只检查语义理解，不检查检索相关性

```
语义理解: intent=一般对话, confidence=0.75
```

置信度guard（子任务5.3）检查的是共振引擎返回的confidence，但这个confidence是"三通道一致性"，不是"检索结果与查询的相关性"。当三通道一致指向错误节点时，confidence也会高，guard拦不住。

**需要增强**：增加检索结果相关性校验，如果top-k结果与查询关键词重叠度低，应该转大模型或诚实兜底。

#### 根因4（P1）：策略选择与实际执行不一致

```
大脑皮层: 策略选择: 规则推理 (复杂度=0.5, 置信度=0.955)
[B2策略接线] 建议=规则推理 实际=qica_knowledge（仅记录，不改变行为）
```

大脑皮层建议用"规则推理"，但实际执行的是"qica_knowledge"。B2策略接线只是记录，没有改变行为。

**需要确认**：这是设计如此还是bug？如果是设计如此，是否需要调整策略优先级？

## 三、修复任务书（建议优先级）

### 任务A（P0）：修复QICA路径检索相关性

**目标**：用户问"共振引擎"时，QICA应该命中共振引擎相关路径，而不是`/身份/自我`。

**排查要点**：
1. 检查QICA的概念匹配逻辑，为什么"共振引擎"会匹配到`/身份/自我`
2. 检查共振引擎相关知识节点的路径和关键词
3. 增加查询关键词与路径的相关性校验
4. 如果检索结果相关性低，应该回退到语义检索（向量通道）或转大模型

**验收标准**：
- 输入"什么是共振引擎"，QICA命中的路径应包含"共振"或"引擎"相关关键词
- 检索到的top-3节点应与共振引擎相关
- 如果没有相关节点，应诚实告知"我对这个概念了解不多"，而不是拼凑不相关内容

### 任务B（P0）：修复本地推理输出质量

**目标**：本地推理的输出应该直接回答用户问题，而不是展示内部状态。

**排查要点**：
1. 检查`PulseInnerWorld.py`中`qica_knowledge`方法的输出生成逻辑
2. 当前输出模板（【种子记忆】+【关联发现】+认知融合）是否适合直接回答用户问题
3. 是否需要增加"基于检索结果生成直接回答"的逻辑
4. 输出截断问题（"当前知..."）的原因

**验收标准**：
- 输入"什么是共振引擎"，输出应包含共振引擎的定义/作用
- 输出不应包含【种子记忆】【关联发现】等内部状态标记
- 输出完整，不截断

### 任务C（P1）：增强置信度guard - 增加检索相关性校验

**目标**：当检索结果与查询不相关时，即使三通道一致性高，也应该转大模型或诚实兜底。

**实现思路**：
1. 在置信度guard中增加检索结果相关性检查
2. 计算查询关键词与top-k检索结果的重叠度
3. 如果重叠度低于阈值（如<20%），标记为"检索不相关"，转大模型
4. 阈值可配置，灰度开关保护

### 任务D（P1）：清理"特斯拉共振"错误节点

**背景**：之前发现知识库`/自我/状态/知识/频率共振`下有一个错误节点把"共振引擎"定义成特斯拉物理共振。

**任务**：
1. 定位该错误节点
2. 评估删除/修改/标记过时的风险
3. 执行清理（建议先标记过时，观察稳定后再删除）

### 任务E（P2）：子任务3.1 - 网页时间提取

**背景**：阶段三子任务3.1留待后续，现在可以开始。

**目标**：无头浏览器搜索时，解析网页的时间标记，给新知识节点标注source_time。

**实现思路**：
1. 在搜索器官（双腿/控制器）的解析链路中增加时间提取
2. 支持常见时间格式（发布时间、更新时间、相对时间）
3. 提取的时间写入新知识节点的source_time字段
4. 与子任务3.0的知识时效性联动
