## 三、任务2：DataQualityGuard 统一脏数据入口

**我选了方案B（facade 编排），并说明偏离星轨"推荐方案A"的理由**：

| | 方案A 扩展 ExperiencePollutionGuard | 方案B 新建 facade（我选） |
|---|---|---|
| 改动面 | 动已交付、已接线、已测试的模块 | 零改动现有模块 |
| 数据形态 | 三类检测器字段/词表完全不同，硬塞成一个类 → 上帝对象 | 每个检测器保持独立可测 |
| 目标达成 | 一个入口 | **同样一个入口 + 一份统一统计** ✅ |

三个检测器数据形态确实不兼容（经验条目字段是 summary/confidence、权重 polluted=0.1；知识节点字段是 value/space_path、权重 polluted=0.3；重复检测是两两 Jaccard），合进一个类只会互相打架。方案B 同样满足"一个入口、一份统计"，且零回归风险。

**DataQualityGuard 能力**：
- `scan_experience_entries()` 经验库污染（纯内存，可测）
- `scan_experience_files()` 真实经验库文件（默认只读）
- `scan_nodes()` 节点污染 + **统一写 quality_flag 到 dict 节点**（关键：PollutionTagger 本身对 dict 节点不写回，这里补上——这是"统一写 quality_flag"的核心）
- `find_duplicates()` / `mark_duplicates()` 复用第一批 Jaccard+倒排索引
- `scan_all()` 三路统一扫描 + 汇总统计
- `clear_flag()` 撤销标记（标记可逆）
- 模块级单例 `get_data_quality_guard()` / `reset_data_quality_guard()`

**未接线**（灰度默认关闭）：本批只交付"入口"本身，**没有**把它挂进框架启动/检索链路，也没有动 `config.py`。要上线需新增一个灰度开关 + 一处调用点——请星轨确认后再做（见文末疑问）。
