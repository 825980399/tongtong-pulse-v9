## 任务1：B-7 LLM依赖度量埋点（P1，工作量适中）

### 目标
量化框架对大模型的依赖程度，为后续"减少外物依赖、增强自持能力"提供数据基础。

### 具体要求
1. 在`nucleus/`下新建`LLMDependencyMetrics.py`（或扩展现有监控模块），实现4个核心计数器：
   - `llm_call_count`：大模型调用次数（按器官/场景分类：肺回答/代码学习/自主进化/其他）
   - `local_inference_count`：本地推理次数（规则通道/简单问题本地回答/置信度守卫）
   - `search_count`：外部搜索次数（无头浏览器/RSS/百科）
   - `digestion_count`：知识消化次数
2. 每次大模型调用/本地推理/搜索/消化时自动计数，持久化到`data/metrics/llm_dependency.json`
3. 每小时计算并日志输出依赖度指标：
   - `llm_dependency_ratio = llm_call_count / (llm_call_count + local_inference_count)`
   - `self_sufficiency_score = local_inference_count / total_requests`
4. 在人体UI（health_ui）中增加"LLM依赖度"面板展示（如果health_ui支持扩展）
5. 提供`reset_metrics()`方法，支持按天/按周重置

### 验收标准
- 计数器准确，不重复计数
- 持久化文件格式清晰，可人工读取
- 日志每小时输出一次依赖度指标
- 全项目语法0错误，回归46/46

### 改动范围

## 任务2：EvidenceCalibrator回报源接线（P1，第九批遗留）

### 目标
第九批新建的EvidenceCalibrator（置信度证据化）当前`record()`方法无生产调用方，历史成功率恒为冷启动0.7，是假闭环。需要接入真实回报源，让置信度校准真正基于历史数据。

### 具体要求
1. **回报源1：推理经验库confidence**
   - 每次本地推理完成后，将实际置信度与结果正确性反馈给EvidenceCalibrator
   - 正确性判定：推理结果被后续对话采纳/用户未纠错=正确；用户纠错/转大模型=错误
2. **回报源2：用户显式纠错语句检测**
   - 在对话记录中检测用户纠错语句（"不对""错了""不是这样"等）
   - 检测到纠错时，将上一轮推理标记为错误，反馈给EvidenceCalibrator
3. **回报源3：大模型二次调用兜底**
   - 本地推理置信度不足转大模型时，标记本地推理为"未通过"，反馈给EvidenceCalibrator
4. 三路加权汇总：推理经验库(0.5) + 用户纠错(0.3) + 大模型兜底(0.2)
5. 每次反馈后更新`data/reasoning/self_calibration_evidence.json`，日志输出更新后的历史成功率

### 验收标准
- EvidenceCalibrator.record()有至少2个生产调用方
- 历史成功率不再恒为0.7，随运行动态变化
- 日志可观察到置信度证据更新
- 全项目语法0错误，回归46/46

### 改动范围
- 修改`nucleus/reasoning/EvidenceCalibrator.py`（扩展record方法）
- 修改本地推理入口（加反馈调用）
- 修改对话记录处理（加纠错检测）
- 修改肺的大模型兜底逻辑（加反馈调用）

### 具体要求
1. **分析当前待审批补丁**：
   - 读取`data/patches/pending_patches.json`，统计积压数量和等待时间
   - 分类：可自动放行（低风险/已验证）/需人工审批（中风险）/应拒绝（高风险/重复）

2. **补丁自动裁决机制**：

   - 对重复补丁（同一文件同一位置的多次尝试），自动合并或拒绝
   - 自动放行的补丁需记录到`data/patches/auto_approved.json`，可审计
3. **本地修复规则扩展**：
   - 检查`repair_rules.json`，统计当前规则覆盖的问题类型
   - 补充常见问题类型的本地修复规则（如：未使用变量/导入缺失/简单拼写错误/日志格式统一）

4. **高危拦截优化**：
   - 分析被高危安全拦截的补丁，区分"真高危"和"误判"
   - 对误判的拦截类型（如修改测试文件/修改文档），降低拦截等级
5. **修复率监控**：
   - 每轮自主进化后日志输出：发现X个/修复Y个/通过率Z%
   - 连续3轮修复率<10%时告警

## 任务4：B-12 经验库污染处理（P1，推理质量）

### 目标
推理经验库有44条污染数据，影响推理质量和置信度校准。需要清理污染数据并建立持续检测机制。

### 具体要求
1. **污染数据扫描**：
   - 读取`data/reasoning/`下的经验库文件
   - 检测污染类型：①自相矛盾的经验 ②与身份认知冲突的经验 ③低质量/无意义经验 ④重复经验
   - 输出污染分析报告，列出每条污染数据的位置、类型、原因
2. **污染数据清理**：
   - 对明确污染的数据（自相矛盾/重复/无意义），标记`quality_flag=polluted`并降权（不删除，可追溯）
   - 对可疑数据，标记`quality_flag=suspect`，等待人工确认
   - 清理后经验库有效数据不少于原数据的80%
3. **持续检测机制**：
   - 每次新经验写入时，自动检测是否与现有经验矛盾
   - 发现矛盾时，不直接拒绝，而是标记并通知自我认知器官
   - 每周自动运行一次全库污染扫描
4. **污染数据消费**：
   - 被标记为polluted的经验，推理时权重降为0.1
   - 被标记为suspect的经验，推理时权重降为0.5
   - 日志输出污染数据对推理结果的影响统计

### 验收标准
- 44条已知污染数据全部被标记（polluted或suspect）
- 新增经验写入时有自动矛盾检测
- 推理时污染经验权重正确降低
- 全项目语法0错误，回归46/46

### 改动范围
- 修改推理经验库读写逻辑（加quality_flag）
- 新建污染检测工具函数
- 修改推理时的经验权重计算
