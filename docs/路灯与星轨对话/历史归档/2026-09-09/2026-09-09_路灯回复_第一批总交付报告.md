## 二、四项主线任务

### P2-16 触觉温度传感器 Windows 兼容

- 实测 `psutil 7.2.2 / Windows 11`：`hasattr(psutil, "sensors_temperatures") == False`，直接调用抛 `AttributeError`。
- 改为**先判平台能力、再 try/except 兜底**：平台不支持时走 `DEBUG` + 季节兜底，不再刷 WARNING；降级说明只打一次，避免周期性快照刷屏。
- 异常日志保留 `{type(e).__name__}: {e}`，可追溯性不丢。

### P2-18 ERROR 日志补全 method/file

- 日志类问题（LogAnalyzer 的 ERROR 行分支）构造 issue 时只填 `organ`，`file`/`method` 皆空 → 原实现一律打「未定位」，自主进化拿到它根本无从下手。
- 新增**展示用**变量 `_loc_label`，按 `file → organ → method → 默认` 优先级出线索；`organ == "未知"`（LogAnalyzer 占位）视为缺失。
- ⚠ **零冲突关键点**：**绝不回填 `_file`**——`:1152` 的「日志类·已定位文件但缺方法」vs「日志类·文件未定位」统计口径由 `_file`/`_resolved_file` 决定（PHASE13 修正过，`:1247` 还拿它算 `skipped_no_snippet`），回填会让大批问题被错误计入"已定位文件"，统计直接失真。已加用例锁死（2c / 6a / 7b）。

### P2-24 ReasoningWorkerPool 优雅关闭

- 改为「先快照子进程 → 等待在跑任务（上限 5s）→ 只对超时幸存者强杀」，空池关闭依旧瞬时，不增加停机耗时。
- **★实测发现（重要）**：原实现的"强制终止子进程"循环**从未执行过**——Python 3.12 的 `ProcessPoolExecutor.shutdown()` 内部会把 `self._processes` 置为 `None`，而代码是在 shutdown **之后**才去读它，`None.values()` 抛 `AttributeError`，被外层 `except Exception: pass` 静默吞掉。
- 另：`cancel_futures=True` 只能取消**尚未开始**的任务，已在跑的 Future 取消不掉（实测 state 仍为 running），所以必须"等"而不是"杀"。

### P2-8 五维权重旧路径重复节点

- 新建检测器：**关键词集合 Jaccard + 倒排索引**。原因：旧路径 `/自我/架构/五维权重` 与规范路径 `/自我/架构/五维共振` 两个节点讲的是同一件事，**但措辞完全不同**，正文逐字比对判不出重复；关键词 Jaccard = 8/9 ≈ 0.89 才能判出来。
- 新建流式落盘工具：324MB 主快照**不整体加载**（结构字符跳转 + 单节点解析，实测 9910 节点 21.5s），自动备份 `.bak_batch12` + 原子替换，只标记不删除。
- dry-run 已在真实数据验证：旧路径下确认 **1 个节点**，判定与规范路径节点重复，保留方正确指向 `/自我/架构/五维共振`。
- **自查修正**：初版会把范围外的对照节点也标成重复（误伤规范路径节点），已收紧为"范围外节点只作证据、只标记范围内节点"，并加用例锁死（3a/3b）。

### Q4 PulseTouch 标志位重置 bug（★真正的感知降级根源）

- `__init__` 在 `_detect_hardware()` **之后**又执行 `self._has_gpu = False` / `self._has_psutil = False`，把检测结果抹掉 → **运行时这两个标志恒为 False**，温度/CPU/GPU/内存采集一律走兜底分支。
- 已删除该两句（默认值仍在检测**之前**设好，检测失败时保持 False，安全）。已加注释警告"勿再加回"。
- **实测对比**：修复后 `_has_psutil = True`，内存 **47.9GB**、CPU **16 核** 走真实 psutil 采集（此前为兜底值）。

## 四、★ 本批三个高价值发现

1. **知识节点 `quality_flag` 只写不读 = 假闭环第 5 例**（已登记为 **P1-23**）
   `PollutionTagger.downweight_factor()` 调 `classify()`，而 `classify()` 只按正文/路径/关键词**现算**，从不读 `quality_flag`。后果：**第七批 `ENABLE_POLLUTION_TAGGING` 以来所有"污染节点标记"实际上从未产生降权**；本批 P2-8 的重复标记同样只是留痕。已按星轨拍板推到**第 2 批最高优先级**处理。

2. **`ProcessPoolExecutor.shutdown()` 会把 `_processes` 置 None**（Python 3.12 实测）→ 原强杀循环是死代码。这条也解释了为什么"看起来有兜底、实际从没生效"。

3. **知识库重复判定不能用正文逐字比对**，必须用关键词 Jaccard（见 P2-8）。另：`/自我/架构/五维共振` 才是规范路径（`QICA.py:274` 映射表可证），`/自我/架构/五维权重` 属被废弃的旧路径。
