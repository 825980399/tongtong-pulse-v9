## 3.3 第一批任务详细说明（4 项，已精确定位）

### 任务1：P2-16 触觉温度传感器 Windows 兼容（小）

- **文件**：`organs/senses/PulseTouch.py`
- **位置**：第 **401** 行 `def _detect_temperature(self) -> float:`，第 **410** 行 `temps = psutil.sensors_temperatures()`
- **现状**：Windows 下 `psutil` **没有** `sensors_temperatures` 属性（或有但为空），每次启动产生 WARNING 噪音
- **修改方式**：
  1. `hasattr(psutil, "sensors_temperatures")` 平台判断，Windows 直接返回默认值（如 `0.0` 或 `None`）并 `DEBUG` 级说明；
  2. 即便存在也需 `try/except` 兜底（某些 Linux 容器返回空）；
  3. **异常日志必须含 `{type(e).__name__}: {e}`**，且用 `except Exception as e:`（不许裸 except）
- **测试要求**（≥2）：
  - 无 `sensors_temperatures` 属性时返回默认值且不抛异常、不产生 WARNING
  - 正常返回温度时解析正确（可用 mock 注入假 psutil）
- **验收**：启动日志不再出现该 WARNING

### 任务2：P2-18 ERROR 日志补全 method/file（小）

- **文件**：`nucleus/reasoning/SafeEvolutionExecutor.py`
- **位置**：
  - 第 **941** 行：`f"file={_file or '未定位'}"`
  - 第 **1013** 行：`f"[LLM门禁] 跳过 {_file or '未定位'}.{_method} ({_type})："`
- **现状**：问题记录时 `file`/`method` 拿不到就打"未定位"，导致自主进化**无法自动修复**（定位不到文件）
- **修改方式**：
  1. 回溯该作用域内 `_file`/`_method` 的来源（问题字典通常有 `file`/`method`/`organ` 等键，或可从 `issue` 字典取）；
  2. 补全取值优先级：`issue.file → issue.organ → issue.method → 已知默认`；
  3. **注意第 1144/1155/1247 行**已有"日志类·文件未定位"的统计口径（PHASE13 修正过），**不要破坏该统计**（零冲突原则）
- **测试要求**（≥2）：
  - 问题字典含 file/method 时日志输出真实值（不再"未定位"）
  - 确实缺失时仍走"未定位"分支且不崩溃
- **⚠️ 坑**：本文件 3000+ 行、改动频繁，**改前务必 `.bak`**；且注意别与 1161 处裸 except 混改

### 任务3：P2-24 ReasoningWorkerPool 进程池优雅关闭（小）

- **文件**：`nucleus/reasoning/ReasoningWorkerPool.py`
- **位置**：第 **269** 行 `def shutdown(self):`；第 **277-283** 行直接 `_p.terminate()`；第 **306** 行 `def shutdown_reasoning_pool()`
- **现状**：关闭时**直接 terminate 子进程**，导致子进程异常终止、产生 ERROR 噪音
- **修改方式**：
  1. 先尝试优雅关闭：对 `ProcessPoolExecutor` 调 `shutdown(wait=True, timeout=N)`（或先 `cancel_futures`）并 `join` 等待；
  2. **超时后**再降级 `terminate()`（保留兜底，避免挂死）；
  3. 关闭前把待处理 Future 取消/等待，避免"任务被中断"报错
- **测试要求**（≥2）：
  - 正常关闭：子进程优雅退出，无 ERROR 噪音
  - 有运行中任务时：等待/超时逻辑生效，最终仍能关闭（不挂死）
- **验收**：框架停止时不再出现子进程异常终止的 ERROR

### 任务4：P2-8 五维权重旧路径重复节点清理（小，需查询知识库）

- **目标**：清理知识库中路径前缀 `/自我/架构/五维权重` 下的**重复节点**（据清单为 1 个）
- **现状**：该路径属"旧路径"，其下有重复节点；节点数据在知识库（主快照 `data/knowledge/pulse_knowledge_snapshot.json`，**318MB，勿整体 json.load**，会吃满内存）

  - 或写脚本**流式/分块**扫描快照，或先用 `tools/` 下已有工具导出该路径节点；
  - 相关代码里"五维权重"字样出现在：`config.py`、`nucleus/qica/QICA.py`、`nucleus/synapsys/ResonanceEngine.py`、`organs/body/PulseLung.py`、`organs/brain/PulseKnowledgeRetriever.py`（可交叉确认路径规范）

  - 能正确识别同路径下的重复节点（构造两条同内容节点验证识别）

## 3.4 代码规范与约束（★硬性）

1. **零冲突原则**：改动前对照原有逻辑，禁止引入逻辑冲突；改后必须验证原功能不受影响
2. **测试优先**：每个修改 **≥2 个测试用例**；测试脚本一律放 `tmp/`，命名 `tmp/test_batch12_<任务>.py`
3. **测试隔离（血泪教训）**：
   - 测试**必须**走 `tmp/test_isolation.py`；**任何新增落盘路径都要同步加进 `redirect_all()`**（含 `_ISO_BASE_DIR` patch + 单例 reset，缺 reset 会写生产目录）

4. **备份**：改动前 `.bak` 备份（本批建议后缀 `.bak_batch12`）
5. **灰度**：新能力默认 `False`，验证稳定后再开
6. **P2-14 代码头部职责说明**：**本批不做**（等小林晚上通知）
7. **ruff**：错误级（F 类）**必须 = 0**：`ruff check --select F`；交付前跑一次
8. **异常日志规范**：`except Exception as e:` + 日志含 `{type(e).__name__}: {e}`；资源清理/数据处理/外部依赖→`DEBUG`，核心流程→`WARNING`
9. **文件头部模板**（新建文件时）：首行 `{模块名} —— {职责}` + `版本: v10 PulseNet` + `设计: 路灯、小林、星轨` + `日期`
