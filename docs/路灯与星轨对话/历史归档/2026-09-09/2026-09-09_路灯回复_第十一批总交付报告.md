## 三、★ 顺带发现并修复的 4 个真 bug（本批额外价值）

这 4 处不在任务书清单内，是接线与验证过程中实测暴露的**系统性缺陷**，均已在本次修复（全部 `.bak_batch11` 备份）：

### bug 1-3：`_ISO_BASE_DIR` 测试隔离**从未生效**（3 个模块同款）
```python
# 原写法（三模块一致）
if base_dir is None:
    base_dir = <生产 data 目录>      # ← 已赋值
self._base_dir = base_dir
if base_dir is None and _ISO_BASE_DIR:   # ← 恒为 False！
    base_dir = _ISO_BASE_DIR
```
- 影响模块：`SelfCalibrator`、`IdentityKnowledgeManager`、`EvolutionEffectVerifier`
- 后果：`tmp/test_isolation` 设的隔离目录**从未生效**，测试进程会把数据写进生产 `data/`（与第十批 23:50 向量库污染同类风险）。
- 修复：`_ISO_BASE_DIR` 判断**提前**到默认目录赋值之前。

### bug 4：证据文件**从未真正落盘**（「假闭环」的物理根因）
- 配置 `CONFIDENCE_EVIDENCE_CONFIG.storage_path = "data/reasoning/self_calibration_evidence.json"` **已含文件名**；
- 原代码 `os.path.join(base_dir, storage_path)` 后又拼一次文件名 → 得到 `.../self_calibration_evidence.json/self_calibration_evidence.json`（把 `.json` 当目录）→ `save()` 时 `open()` 必抛 `NotADirectoryError` 并被 `try/except` 吞掉。
- 后果：历史成功率**从未持久化**，每次重启都回到冷启动 0.7 —— 这正是星轨所指「置信度证据化假闭环」的根因，比"缺调用方"更底层。
- 修复：按「是否已含 `.json` 文件名」分支处理，并 `makedirs` 兜底；落盘路径与星轨预期一致（`data/reasoning/self_calibration_evidence.json`）。
