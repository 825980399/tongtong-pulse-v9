### 任务1：485处"异常已忽略"日志修复（P0）

**问题现状**:
- 全项目485处"异常已忽略"日志
- 其中484处没有捕获异常变量（`except Exception:` 而非 `except Exception as e:`）
- 日志内容只有"异常已忽略"四个字，无异常类型、无异常消息、无上下文
- 15处仍然是 `pass`（完全无日志）

**修复规范**:

```python
# 修复前（无用日志）
except Exception:
    self._log(LogLevel.DEBUG, "异常已忽略")

# 修复后（有信息量）
except Exception as e:
    self._log(LogLevel.DEBUG, f"异常已忽略: {type(e).__name__}: {e}")
```

**分级处理原则**:
- **资源清理类**（文件关闭、连接断开、锁释放）→ DEBUG，格式：`f"清理异常已忽略: {type(e).__name__}: {e}"`
- **数据处理类**（JSON解析、类型转换、编码解码）→ DEBUG，格式：`f"数据处理异常已忽略: {type(e).__name__}: {e}"`
- **核心流程类**（推理、进化、通信、器官初始化）→ WARNING，格式：`f"异常已忽略（需关注）: {type(e).__name__}: {e}"`
- **外部依赖类**（API调用、网络请求、浏览器操作）→ DEBUG，格式：`f"外部依赖异常已忽略: {type(e).__name__}: {e}"`

**特殊处理**:
- 15处 `pass` 全部改为有日志的形式
- 83处用字符串 `"DEBUG"` 而非 `LogLevel.DEBUG` 的，统一改为枚举
- 36处用 `_logger.debug` 的，保持不变但补充异常信息

**验收标准**:
- 全项目搜索"异常已忽略"，每一处都必须包含 `{type(e).__name__}` 或等价的异常类型信息
- 全项目搜索 `except Exception:`（不带as e），数量应为0
- 全项目搜索 `except Exception: pass`，数量应为0
