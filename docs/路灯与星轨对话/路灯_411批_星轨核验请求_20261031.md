## 三、请裁决的 8 处

### 3.1 ★★刀1「采各器官 RSS」不存在 —— 我换成了对象图浅尺寸，请裁口径

任务书要"用 `psutil.Process().memory_info()` 或 `tracemalloc` 采**各器官** RSS"。

三件事都做不到：

1. **各器官 RSS 不存在**：所有器官在同一个 Python 进程里，内核按页/映射记账，
   不按 Python 类拆分。`psutil` 只能给整进程读数（实测 11290 MB，与你们的 11.1GB 吻合）。
2. `tracemalloc` 单次 837s（任务书自己标注了"已知死路"）。
3. `gc.get_objects()` 按 `type(o).__module__` 归因几乎无效：**20,547 个对象里只有 9 个**
   能归到器官（99.96% 是内置 dict/list/str，见 371 批探针）⇒ 归因等于没做。

**我的做法**：从**器官实例**出发、深度≤2、`visited` 去重，累加 `sys.getsizeof()`
得到"对象图浅尺寸"，产物里写死三条口径：

```json
{"rss_separable": false,
 "basis": "organ_object_graph(depth<=2, shallow_getsizeof)（**不是 RSS**）",
 "note": "单进程内 RSS 无法按器官拆分；objs/est_mb 是对象图浅尺寸（同一对象只算一次）"}
```

**请裁**：接受这个口径吗？若你要的是"能定位到谁在涨"，它能回答（排名稳定、口径一致）；
若你要的是"精确到 MB 的归属"，**那在单进程 Python 里做不到**，
只能靠"重启前后差分"或"关掉某器官做 A/B"。
