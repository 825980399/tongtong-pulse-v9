> 状态：落地规范（声明，非实现）｜ 来源：177批《O-A3 SKILL规范与资源清单设计稿》+ 180批刀1

---

## 一、目标

建立目录级 `<能力目录>/SKILL.md` 规范与资源清单声明机制。**声明而非实现**：资源清单与
`tools/export_public.py` 白名单同面，保证「声明即进包面」，避免 PII/内部资源漏进公开包。

---

## 二、SKILL.md 字段集

每个能力目录顶层放一个 `SKILL.md`，必须含以下字段：

| 字段 | 必填 | 含义 | 示例 |
|---|---|---|---|
| `name` | 是 | 能力名（唯一，与目录名一致） | `request_dedup` |
| `scope` | 是 | 适用目录 / 边界（防止跨边界误授权） | `nucleus/field/` |
| `entry` | 否 | 入口（声明，不强制实现） | `observe_request` |
| `resources` | 是 | 资源清单（文件 / 工具 / 依赖） | 见第三节 |
| `risk` | 是 | 风险等级（P0–P3） | `P2` |

---

## 三、资源清单与导出白名单同面

- `resources` 直接映射 `tools/export_public.py` 白名单条目；**声明即进包面**。
- 资源清单变更须同步白名单，避免「声明了却没进包」或「进了包却没声明」的遗忘漂移。
- PII 一致性：任何落入 `resources` 的文件若含 PII，必须同时在 `export_public.py` 白名单
  走 PII 闭环（属主 `.owner_pii.json` + 独立复扫 `independent_rescan_148.py`）。

### 3.1 resources 条目形态

```yaml
resources:
  - path: nucleus/field/request_dedup_observe.py   # 文件
    kind: code
  - tool: get_influxdb_store                          # 工具/接口
    kind: api
  - dep: bge-small-zh-v1.5                            # 依赖（语义模型）
    kind: model
```

## 四、目录级规范

- 每个能力目录顶层放 `SKILL.md`，框架按目录扫描加载（声明式，不改执行）。
- **缺 `SKILL.md` 的能力目录降级为「未声明」**，不参与自动授权。
- 本批仅落规范与声明；自动加载执行逻辑、扫描器写作均不实装（设计稿 §七）。
