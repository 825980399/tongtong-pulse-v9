# 星轨工作流程规范（强制执行，每批必做）

> 创建：2026-09-27
> 版本：v1.1（2026-09-28 根据烛微「星轨工作流程专项审计」全量修订）
> 目的：避免漏项、错项，所有检查可机检、可留痕、可追溯，全部打勾才能生成任务书/交付验收

---

## 一、每批生成任务书前必做五步（全部打勾才能生成）

- [ ] 1. 读完路灯上一批完整交付报告，所有待星轨裁决的问题全部拍板，写进本批任务书；先清理积压未读报告，不允许跨批沉底
- [ ] 2. 读完烛微前置分析报告，把可施工的问题转成任务，附最新校准行号
- [ ] 3. 运行日志告警脚本，把上一批次以来的ERROR/WARNING逐项处置，顺手加进本批任务，无告警需附脚本输出
- [ ] 4. 核对待裁决登记册、待办总览区，所有到期项、之前分析未修的问题全量过一遍，确定排期/挂起理由
- [ ] 5. **来源完备性自检**：本批任务书每条任务行必须带 `← 来源: <D票号 / 总账P级票 / 日志告警条目 / 业主指令>`；跑来源追溯脚本，输出「未被任何任务覆盖的上批D票清单」，非空必须逐条写明处置，禁止以「读一遍看看漏没漏」作为检查手段
- [ ] 6. **前提标注自检**：任务书所有行号引用、「已完成/已存在/已修」状态断言，必须紧跟 `[实测@HH:MM]`；转述未验一律标 `[转述-未验]`，跑观测标记脚本，无标记行号引用为0才允许出件
- [ ] 7. **删除/移出类条目逐条列拍板**：任务书内所有「直删/物理删除/移出项目根」条目（无论文件大小）必须在任务书开头「已拍板」段**逐条列出**并附授权来源（小林拍板/Q票裁决），禁止只写任务行不写拍板行；D-A4 事件教训：1.32MB 直删因未单独报备产生授权缺口（2026-09-29 已追认）

---

## 二、每批交付验收必做六步（全部打勾才能算验收通过）

- [ ] 1. 读完路灯完整交付报告，必须包含《T0偏差》《门禁结果》章节（章节内嵌或独立文件均可），待授权项无遗漏
- [ ] 2. **待授权项专项检查**：专门梳理「待星轨授权/铁律113/push挂起」，全部拍板并写进登记册/下一批任务
- [ ] 3. **关键功能独立验证**：不盲信路灯门禁结果，星轨自己跑一遍核心校验，产出`第N批_星轨独立复算.md`，四要素缺一不算验收：①完整命令 ②完整stdout/stderr原文 ③执行时刻 ④当时HEAD与工作树sha
- [ ] 4. 在本批次记录里，完成的待办项全部改为`[x]`并标注完成
- [ ] 5. 在文件最底部的待办总览区，完成项及时标记、移出活跃区
- [ ] 6. **脚本两边核对**：跑总账一致性脚本，输出「总览区有/批次无」「批次已完成/总览未标记」两张差集表，原文贴进独立复算件，差集非空本批不得收口

---

## 三、路灯五道门禁验收标准（必须全绿才算通过）

1. ruff F 全库 = 0（未使用导入/未定义变量）
2. 改动文件 import 冒烟全通过（py_compile仅辅助，不作正式门禁）
3. pytest 相关测试 0 failed
4. CI 静默except gate PASS（静默except只降不升、无解析错误、无CRCRLF）
5. 行尾零翻转（CRLF/LF不混，和基线一致）

---

## 四、总账更新铁律

1. 待办总览区**永远在文件最底部**，所有新批次记录都加在总览区上方
2. **每批增量核对 + 每10批全量核对**：每批用一致性脚本核对当批条目；每10批全量复核，把核对时刻、核对人、发现条数写进总览区一行，无该行视为未核对
3. 流程纪律永远在文件前部，不被挤到中间
4. 绝对禁止出现：批次说没做、总览说做完了的矛盾情况
5. 所有结论单点写入：同一结论只在总览区/登记册写一次，其他章节用「见ID」引用，禁止双写，避免更新不同步成矛盾账

## 五、模型选择提醒规则

1. 日常小修小补：默认使用Hy3（白天免费时段）
2. Hy3额度用完：提醒切换DeepSeek-V4-Flash（既定兜底）；**Space Bunny（OpenRouter `stealth/space-bunny-alpha`）临时替补纳入（2026-10-02 小林拍板·暂定观察期：额度仅提示至 10-07 且预计涨价，编码质量未验证，仅作临时替补不写死为正式兜底；额度/价格变化或质量不达标时立即复核撤出）**
3. 夜间23:00-次日8:00：使用Hy4 preview（免费时段）
4. 跨模块重构、复杂bug根因、高风险操作：任务书开头醒目标注⚠️，提醒手动切DeepSeek-V4-Pro
5. 星轨/路灯均无权限自行切换模型，仅做提醒

## 六、微光（外援）调用规则

因额度成本约束，微光不承担固定巡检、每批常规工作，不加入固定流水线：
1. 定位为**按需深度梳理外援**：仅在全框架文档重梳理、data深度盘点这类偶尔大活时按需调用
2. 日常批次核对、总账更新、data常规巡检由星轨按流程完成，不增加微光环节
3. 入职引导文件存档，后续额度充足或确有必要时再启用固定分工

---

## 七、优先级铁律

1. 主线永远是：技术债务清偿 → 设计文件落地 → 框架稳定性优化
2. 比赛/推广仅顺手参与，不专门占批次，截止前提交邮件即可
3. 比赛相关任务全部降到P3，不打乱正常推进节奏
4. 运行日志里的任何警告都不放弃，全部登记，每批顺手处置，不攒成大问题

## 九、待裁决登记册（单一事实源）

1. 所有「待星轨裁决/待小林拍板/待授权」事项，**只在`docs/台账/待裁决登记册.csv`落一次**，固定列：
   `ID,提出方,提出批次,摘要,P级,状态,到期批次,裁决批次,裁决内容`
2. 总账各批次章节不再新开「待裁决」小节，仅写「见登记册ID」
3. 每批任务书开头必须列「本批到期未裁项」，非空先裁后派；超5批未裁自动标「已提请小林」
4. 登记册校验脚本检查：ID唯一、状态合法、到期批次非空、到期项已列

## 附则：星轨九条自我约束规则（v1.1，小林批准）

1. **验收必须有真实副作用**：脚本真跑、远程真推、报告有明确消费方，无副作用仅可记⏳，禁止标✅；0命中结论必须带正控
2. **任务书前提带观测标记**：严格区分`[实测@时间]`与`[转述-未验]`，未验项≥3条任务书开头标⚠️
3. **总账定期瘦身**：每10批顺手归档已完成内容，不专门占批次，规模数字按统一脚本刷新
4. **积压票自动升级**：挂起超3批下一批开头列阻塞，超5批必须提请小林裁决，不得无限顺延
5. **统一度量衡**：所有规模数字以`tools/measure_baseline.py`输出为准，排除缓存/备份/临时目录，附脚本版本+日期
6. **验收者被验收**：烛微每批抽查3条上一批新标✅的强结论（含1条发布类、1条闭环类、1条随机），不成立即登记入历史漏项表
7. **结论单点引用**：同一结论仅在登记册/总览区写一次，其他位置用ID引用，禁止双写造成矛盾
8. **复发即登记**：交付报告必须含「复发历史事故」小节，复发即同批更新历史漏项表，不允许复盘不落规则
9. **验收器独立性**：CI脚本/豁免名单/阈值变更必须单独成提交，禁止与被验收业务代码同提交，变更需在独立复算件逐条签核
