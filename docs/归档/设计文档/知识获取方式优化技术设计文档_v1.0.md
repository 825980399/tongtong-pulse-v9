## 一、现状分析

### 1.1 当前知识获取方式

| 方式 | 器官 | 效率 | 质量 | 资源消耗 | 适用场景 |
|------|------|------|------|---------|---------|
| 爬虫抓取 | 双腿（PulseLegs） | 低（需解析HTML） | 中 | 中 | 通用网页 |
| 无头浏览器 | 控制器（Playwright） | 极低（6-9秒/次） | 高（可执行JS） | 极高（Node.js+Chromium） | 复杂动态页面 |
| 大模型API | 肺（PulseLung） | 中（2-5秒/次） | 高（已结构化） | 中（API成本） | 深度问答 |

### 1.2 核心问题

1. **效率低**：无头浏览器每次搜索需6-9秒，且消耗大量内存（Node.js+Chromium多进程）
2. **资源浪费**：简单的实体查询（如"什么是人工智能"）也用浏览器爬取，杀鸡用牛刀
3. **无增量机制**：每次都是全量爬取，没有订阅式的增量获取
4. **无策略路由**：所有外部知识获取都走同一条路径，不会根据知识类型选择最优方式
5. **重复抓取**：同一主题可能被反复抓取，没有缓存和去重

### 1.3 预研结论（2026-09-08实测）

| 渠道 | 可用性 | 效率 | 内容质量 | 备注 |
|------|--------|------|---------|------|
| RSS-Solidot奇客 | ✅ 可用 | 0.5秒/20篇 | 高（科技新闻） | 推荐 |
| RSS-InfoQ中文 | ✅ 可用 | 0.4秒/20篇 | 高（技术深度） | 推荐 |
| RSS-博客园精华 | ✅ 可用 | 0.4秒/20篇 | 中高（技术博客） | 推荐 |
| RSS-阮一峰周刊 | ✅ 可用 | 2.2秒/3篇 | 高（科技周刊） | 推荐 |
| RSS-少数派 | ✅ 可用 | 0.5秒/10篇 | 中（效率工具） | 可选 |
| RSS-知乎日报 | ❌ 被反爬 | - | - | 不可用 |
| RSS-掘金 | ❌ 超时 | - | - | 不可用 |
| RSS-V2EX | ❌ 超时 | - | - | 不可用 |
| 中文维基API | ❌ 超时 | - | - | 网络限制 |
| 英文维基API | ❌ 超时 | - | - | 网络限制 |
| 百度百科HTTP | ⚠️ 需修复编码 | - | - | URL编码问题 |

**关键发现**：RSS订阅源效率比无头浏览器高**10-20倍**（0.4秒 vs 6-9秒），且返回结构化内容，无需HTML解析。

## 二、架构设计

### 2.1 设计目标

1. **效率提升**：简单知识获取从6-9秒降到1-2秒
2. **资源节约**：减少无头浏览器使用频率，降低内存占用
3. **增量获取**：通过RSS订阅实现知识的持续增量更新
4. **策略路由**：根据知识类型自动选择最优获取方式
5. **保持自持**：所有外部获取都是"拐杖"，框架自己的消化整合能力才是核心

### 2.2 整体架构

```
                    ┌─────────────────────────┐
                    │   知识获取策略路由器      │
                    │ KnowledgeAcquisitionRouter│
                    └────────────┬────────────┘
                                 │
           ┌─────────────────────┼─────────────────────┐
           │                     │                     │
    ┌──────▼──────┐      ┌──────▼──────┐      ┌──────▼──────┐
    │  RSS采集器   │      │  百科查询器  │      │  浏览器搜索  │
    │ RssCollector │      │ WikiQuerier  │      │ BrowserSearch│
    └──────┬──────┘      └──────┬──────┘      └──────┬──────┘
           │                     │                     │
           └─────────────────────┼─────────────────────┘
                                 │
                    ┌────────────▼────────────┐
                    │   知识消化整合层（现有）   │
                    │  胃(PulseStomach) + 肝   │
                    └─────────────────────────┘
```

### 2.3 策略路由规则

| 知识类型 | 首选方式 | 备选方式 | 判定条件 |
|----------|---------|---------|---------|
| 科技新闻/行业动态 | RSS采集器 | 浏览器搜索 | 查询词含"最新""新闻""动态"等 |
| 技术概念/定义 | 百科查询器 | 浏览器搜索 | 查询词是名词性短语（如"什么是XX"） |
| 技术教程/深度文章 | RSS采集器 | 浏览器搜索 | 查询词含"教程""怎么""如何"等 |
| 实时信息/社交内容 | 浏览器搜索 | - | 需要JS渲染或登录的网站 |
| 框架主动学习 | RSS采集器（定时拉取） | - | 双腿的主动学习任务 |

## 三、详细模块设计

### 3.1 RSS采集器（RssCollector）

**文件位置**：`nucleus/knowledge/RssCollector.py`（新增）

**核心功能**：
1. 订阅多个RSS源，定时拉取增量更新
2. 解析RSS/Atom格式，提取标题、摘要、链接、发布时间
3. 去重（基于链接和标题哈希）
4. 过滤（基于关键词黑名单和质量评分）
5. 将高质量内容推送给胃进行消化

**配置设计**（config.py新增）：
```python
RSS_COLLECTOR_CONFIG = {
    "enabled": False,  # 灰度开关，默认关闭
    "feeds": [
        {"name": "Solidot奇客", "url": "https://www.solidot.org/index.rss", "category": "科技新闻", "weight": 0.8},
        {"name": "InfoQ中文", "url": "https://www.infoq.cn/feed", "category": "技术深度", "weight": 0.9},
        {"name": "博客园精华", "url": "https://feed.cnblogs.com/blog/sitehome/rss", "category": "技术博客", "weight": 0.7},
        {"name": "阮一峰周刊", "url": "https://www.ruanyifeng.com/blog/atom.xml", "category": "科技周刊", "weight": 0.85},
        {"name": "少数派", "url": "https://sspai.com/feed", "category": "效率工具", "weight": 0.6},
    ],
    "pull_interval": 1800,  # 拉取间隔（秒），默认30分钟
    "max_articles_per_pull": 10,  # 每次拉取最多处理的文章数
    "min_quality_score": 0.5,  # 最低质量评分阈值
    "keyword_blacklist": ["广告", "推广", "招聘"],  # 关键词黑名单
    "dedup_ttl": 86400 * 7,  # 去重记录保留时间（7天）
}
```

**核心方法**：
```python
class RssCollector:
    def __init__(self, config): ...
    def pull_all(self) -> List[RssArticle]: ...  # 拉取所有源
    def pull_feed(self, feed_config) -> List[RssArticle]: ...  # 拉取单个源
    def parse_feed(self, content) -> List[RssArticle]: ...  # 解析RSS/Atom
    def deduplicate(self, articles) -> List[RssArticle]: ...  # 去重
    def filter_quality(self, articles) -> List[RssArticle]: ...  # 质量过滤
    def should_collect(self, query: str) -> bool: ...  # 判断是否适合用RSS获取
```

**数据结构**：
```python
@dataclass
class RssArticle:
    title: str
    summary: str
    url: str
    published_at: datetime
    source: str  # 来源名称
    category: str  # 分类
    quality_score: float  # 质量评分
```

**与双腿的集成**：
- 双腿（PulseLegs）的主动学习任务优先调用RssCollector
- 如果RssCollector返回空或质量低，回退到现有爬虫/浏览器方式

### 3.2 百科查询器（WikiQuerier）

**文件位置**：`nucleus/knowledge/WikiQuerier.py`（新增）

**核心功能**：
1. 针对实体/概念查询，优先使用结构化API
2. 多源 fallback：英文维基API → 百度百科HTTP → 浏览器搜索
3. 提取摘要、关键信息、相关链接
4. 缓存查询结果（避免重复查询）

**配置设计**：
```python
WIKI_QUERIER_CONFIG = {
    "enabled": False,  # 灰度开关
    "sources": [
        {"name": "百度百科", "type": "http_scrape", "url_template": "https://baike.baidu.com/item/{keyword}", "weight": 0.8},
        # 维基百科API因网络问题暂不可用，保留配置待网络环境改善
        # {"name": "英文维基", "type": "api", "url": "https://en.wikipedia.org/w/api.php", "weight": 0.9},
    ],
    "cache_ttl": 86400 * 30,  # 缓存30天
    "timeout": 10,  # 查询超时
    "max_summary_length": 500,  # 摘要最大长度
}
```

**核心方法**：
```python
class WikiQuerier:
    def query(self, keyword: str) -> Optional[WikiResult]: ...  # 查询实体
    def query_baidu(self, keyword: str) -> Optional[WikiResult]: ...  # 百度百科
    def parse_baidu_html(self, html: str) -> Optional[WikiResult]: ...  # 解析百度百科HTML
    def get_cache(self, keyword: str) -> Optional[WikiResult]: ...  # 读缓存
    def set_cache(self, keyword: str, result: WikiResult): ...  # 写缓存
    def should_query(self, query: str) -> bool: ...  # 判断是否适合百科查询
```

**百度百科URL编码修复**：
```python
# 中文关键词需要quote编码
from urllib.parse import quote
url = f"https://baike.baidu.com/item/{quote(keyword)}"
```

### 3.3 知识获取策略路由器（KnowledgeAcquisitionRouter）

**文件位置**：`nucleus/knowledge/KnowledgeAcquisitionRouter.py`（新增）

**核心功能**：
1. 根据查询类型自动选择最优获取方式
2. 实现 fallback 链（首选失败自动尝试备选）
3. 统计各渠道成功率和效率，动态调整权重
4. 统一接口，对上层屏蔽具体获取方式

**核心方法**：
```python
class KnowledgeAcquisitionRouter:
    def __init__(self, rss_collector, wiki_querier, browser_search): ...
    def acquire(self, query: str, context: dict = None) -> AcquisitionResult: ...
    def classify_query(self, query: str) -> QueryType: ...  # 查询分类
    def select_channel(self, query_type: QueryType) -> str: ...  # 选择渠道
    def fallback_chain(self, query: str, channels: List[str]) -> AcquisitionResult: ...
    def record_stats(self, channel: str, success: bool, elapsed: float): ...  # 记录统计
```

**查询分类规则**：
```python
class QueryType(Enum):
    NEWS = "news"  # 新闻/动态
    ENTITY = "entity"  # 实体/概念定义
    TUTORIAL = "tutorial"  # 教程/方法
    REAL_TIME = "real_time"  # 实时信息
    UNKNOWN = "unknown"  # 未知类型
```

### 3.4 与现有器官的集成

#### 双腿（PulseLegs）改造
- 主动学习任务优先调用`KnowledgeAcquisitionRouter.acquire()`
- 如果Router返回结果，直接推送给胃消化
- 如果Router失败，回退到现有爬虫方式
- 新增配置项控制是否启用Router

#### 控制器（PulseController）改造
- 深度搜索时，先尝试Router的百科查询
- 只有Router失败或需要JS渲染时，才启动Playwright
- 减少浏览器启动频率

#### 配置热加载
- 所有新增配置支持`config_override.json`热加载
- 灰度开关可动态开启/关闭，无需重启

## 六、与"自持智能"哲学的关系

### 6.1 这些优化是"拐杖"不是"腿"

RSS采集器、百科查询器、策略路由器都是**提高知识获取效率的工具**，相当于更好的"眼睛和耳朵"。但真正的"腿"是框架自己的：
- 知识缺口识别能力（知道自己缺什么）
- 知识消化整合能力（把外部知识变成自己的）
- 知识应用创新能力（用学到的知识解决新问题）

### 6.2 远期方向：框架自己学会"怎么学"

当前阶段：人工配置RSS源、人工定义路由规则
远期目标：
- 框架根据自己的知识缺口，自动发现和订阅新的知识源
- 框架根据获取效果，自动调整路由策略和源权重
- 框架总结"什么知识用什么方式获取最高效"，形成自己的学习方法论

这才是真正的"自持智能"——不是依赖固定的获取方式，而是自己学会如何学习。

## 八、风险与注意事项

1. **RSS源稳定性**：部分源可能失效或被反爬，需要容错处理（超时跳过、失败计数、自动降级）
2. **内容质量**：RSS内容质量参差不齐，需要质量评分和过滤机制
3. **版权问题**：只提取摘要和链接，不存储全文，尊重版权
4. **网络环境**：维基百科API不可用，百度百科可能有反爬，需要多源fallback
5. **缓存一致性**：百科缓存30天，对于快速变化的内容可能过时，需要设置合理的TTL
6. **与现有逻辑的冲突**：新增代码必须通过if开关保护，不影响现有逻辑
7. **内存占用**：RSS文章缓存需要控制大小，避免内存泄漏
