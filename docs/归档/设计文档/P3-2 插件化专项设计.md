目标：把「58 处硬编码装配」迁移为「声明式装配 + 依赖拓扑排序」，落实宪法规则8（插件化开闭性）。

二、设计目标
新增器官不改核心代码：只需「放入目录 + 声明 ORGAN_META」，装配器自动发现并装配。
消除前向引用二次注入：依赖声明用符号名，装配器按拓扑序解析。
环依赖显式化：双向互注用「晚绑定回填」声明，不靠隐式顺序。
FEATURE 开关声明化：开关进 ORGAN_META，关闭时下游容忍 None。
双路径收敛：每个器官只有唯一装配来源。
三、ORGAN_META 扩展 Schema（阶段2 核心）
当前 ORGAN_META 只有 name/class_name/system/always_online。扩展为：

python
ORGAN_META = {
    "name": "大脑皮层",
    "class_name": "PulseCortex",
    "system": "brain",
    "always_online": True,

    # ★阶段2新增1：FEATURE 开关名（config.FEATURE 的键，缺省=始终创建）
    "feature_flag": None,

    # ★阶段2新增2：创建期必需依赖（符号名 → 组件/器官名）
    # 这些依赖必须在创建时就注入（拓扑序保证其先被创建）
    "extra_deps": {
        "node_pool": "node_pool",
    },

    # ★阶段2新增3：组装期后置注入（前向引用/环依赖的晚绑定）
    # target 是符号名，setter 是目标器官的 set_xxx 方法
    "post_wiring": [
        {"target": "qica", "setter": "set_qica"},
        {"target": "inner_world", "setter": "set_inner_world"},
        {"target": "self_awareness", "setter": "set_self_awareness"},
    ],
}
字段语义：

extra_deps = 硬依赖（创建期必须存在）→ 参与拓扑排序，缺依赖则装配报错。
post_wiring = 软依赖（可后置回填）→ 不参与拓扑排序，所有器官创建完后再统一回填；用于前向引用和环依赖。
四、装配器设计（OrganAssembler）
4.1 装配流程（四阶段）
Phase 0  基础组件装配（非器官：node_pool/info_field/pulse_core/resonance_engine/
         frequency_codec/snapshot/knowledge_tree/experience_pool 等）

Phase 1  拓扑排序 + 创建无环依赖的器官
         —— 按 extra_deps 建 DAG，Kahn 算法分层创建，缺依赖即报错

Phase 2  处理前向引用/环依赖
         —— post_wiring 晚绑定：所有器官创建完后，按声明回填 set_xxx

Phase 3  FEATURE 降级传播
         —— 开关关闭的器官置 None，下游依赖用 getattr 容忍 None

4.3 环依赖处理（晚绑定）
thymus↔white_cell、self_awareness↔hormones 这类互注：

声明为双向 post_wiring（A 注 B，B 注 A）。
装配器先创建双方（不注入彼此），再统一回填。
若某个器官的 on_pulse 在回填前就被触发，setter 需容忍「依赖尚为 None」（现有代码已用 if self.xxx: 防御）。
4.4 FEATURE 声明与降级
feature_flag 关闭 → 器官不创建，self.organs[name] = None。
下游 post_wiring 回填时若 target 为 None → 跳过（setter 前加 if target:）。
依赖为 None 的器官自身逻辑已用 if self.xxx: 防御（现状即如此）。
4.5 双路径收敛
motivation_cycle / global_learner：去掉「动态加载 + 硬编码 fallback」双路径，统一为「ORGAN_META 声明 + 装配器创建」单一来源。
日志名重置（reset_logger("动机循环")）作为 post_wiring 的一项声明，而非散落代码。

验收暴露并修复的既有 bug（与声明式装配无关，legacy 同样触发）：PulseSystemManager._check_and_repair_services 对「服务命令不存在」（如沙箱无 ollama）无 try/except，导致 system.boot 处理抛 FileNotFoundError。已修复：subprocess.Popen 包 try/except，FileNotFoundError 及通用异常降级为 stopped，不中断启动。

重要结论（修正此前判断）：「沙箱缺企业微信/大模型 API/硬件无法端到端启动」这一判断过于保守。实测证明这些外部依赖仅影响运行期对话/推理/硬件感知，不影响装配、启动、心跳、快照——装配依赖（node_pool/info_field/pulse_core 等核心组件）均为本地可建。故端到端验收可在沙箱完成。

默认路径建议（✅ 已决策，2026年8月31日）：默认仍保持 use_declarative_assembly=False（legacy）。决策依据：① 切换默认的增量收益仅为「开发期新增器官零改 main.py」，非运行期性能/稳定性提升；② 等价性证据虽强（56 器官/恢复 6936 节点/心跳/优雅关闭全通过），但缺长稳、并发、异常注入等长周期回归；③ 回退成本已为零（开关已存在）。触发切换的前置条件：声明式通过 3 轮以上长稳+快照往返+并发心跳+异常注入回归；出现「频繁增删器官」真实场景；全量 diff 一致性测试覆盖。详见总表 1.13 节。

七、验收标准
阶段2 验收：OrganAssembler.validate() 无「未声明依赖」，且报告覆盖全部 75 处手动注入；现有硬编码装配启动后行为不变。

八、一句话总结
插件化的本质不是「删掉 58 行」，而是把散落在 main.py 的 75 处手动注入，收敛为 ORGAN_META 里的显式依赖声明——extra_deps（硬依赖，拓扑排序）＋ post_wiring（软依赖，晚绑定回填）＋ feature_flag（开关降级）。阶段2 先让声明与校验成立，阶段3 才切换装配引擎。
