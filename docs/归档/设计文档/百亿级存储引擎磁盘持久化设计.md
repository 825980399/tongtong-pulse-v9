〇、版本修订说明
v1.0 将问题定义为「内存放不下 → 塞进磁盘」，主线是「磁盘持久化 + 检索可扩展」。经评审指出一个方向性短板：
上千亿条知识在 float32 下原始体积约 4000 PB，物理上不可行——体积问题不只是「内存 vs 磁盘」的位置问题，更是「向量本身太大」的量化问题。
v2.0 据此重构为分层混合存储架构：按访问热度分层，不同层级用不同量化精度、存储介质、索引结构。核心原则：不可能也不需要把上千亿条知识全部用高精度向量存在内存里。
同时，v2.0 增加一个诚实边界：PulseNet 当前检索基于标量 frequency_signature（非 1024 维向量），向量量化章节是「未来向量化演进」的前瞻设计，而非当前瓶颈的立即解药。

1.2 核心矛盾（分两个量级看）
量级一：元数据规模（当前真实瓶颈）
PulseNode.to_dict() 有 26 个字段（node_id/value/keywords/五维坐标/关联关系/验证历史等），单节点序列化约 500B2KB。百亿节点 ≈ 50GB200GB，千亿节点 ≈ 500GB~2TB。这是元数据体积问题，可通过列式压缩 + 分片 + 冷热分层解决。
量级二：向量规模（未来演进瓶颈）
若未来为每个节点引入 1024 维 float32 embedding 做语义检索：
• 单条向量 1024×4 = 4KB
• 千亿条 ≈ 4000 PB，物理上不可能
这是向量量化问题，必须靠三级量化分层解决。 这是本文 v2.0 的核心增量。
1.3 设计目标
1. 可扩展：支撑百亿~千亿级知识节点的持久化、索引与检索。
2. 低侵入：不改器官层对 PulseNodePool 的调用契约，存储引擎作为可插拔后端。
3. 可追溯：知识不因进程退出丢失，冷数据可随时召回。
4. 渐进演进：分阶段落地，每阶段独立可用、可回退。

3.2 关键设计要点
1. 热层（百亿以内）：保留最高精度，负责最终精排和高频命中，是真正对外输出的知识主体。
2. 温层（千亿以内主体）：海量知识的主力存储，PQ/INT4 在压缩和精度间取最优平衡，是工业界大规模向量库标准配置。
3. 冷层（千亿级长尾）：只做第一轮粗召回，把候选集捞出来再到上层精排；精度损失被多层检索抵消，换来体积数量级下降，是支撑千亿规模的核心手段。
4. 必须做校准：直接硬量化精度掉得快，推荐 TurboQuant 类偏移校准法——首次建索引时做一次分布校准，后续增量写入复用参数，把量化召回损失控制在 1%~2% 以内。
3.3 多层检索流程
查询 → 冷层 1bit 粗召回（捞候选池）
     → 温层 PQ 中筛（缩候选集）
     → 热层 FP16/INT8 精排（最终输出）

对应 PulseNet 现状：PulseNode 的 keywords/space_path/importance/abstraction 等是「属性元数据」；linked_nodes/semantic_relations/phase_locked_to 是「图谱关系」；QICA 的 INTENT_RULES 与领域知识库是「规则类知识」。三者本就该分治，当前混在一个 JSON 里是待改进点。

七、数据流设计
7.1 写入路径
器官 add_node(node)
  → 按 evol_level 路由到对应层
  → L4：内存常驻 + 明文规则
  → L3：FP16/INT8 量化 → 热层索引（HNSW）+ Parquet 元数据 + SSD 热备
  → L2：INT4/PQ 量化 → 温层索引（IVF）+ Parquet + WAL
  → L1：1bit/2bit 量化 → 冷层索引 + ORC 归档 + WAL 段追加
7.2 读取路径（多层检索）
查询 → 冷层粗召回（1bit 倒排，百毫秒）
     → 温层中筛（PQ，十毫秒）
     → 热层精排（FP16，毫秒）
     → 返回；命中节点写回热池（LRU 预热）
7.3 冷数据召回
按路径/频率/关系检索 → 外置索引 → node_id 集合（跨分片）
  → 批量从冷层 ORC 召回 → 反量化（按需）→ 写回温/热层
￼
八、分阶段演进路线（从 v9.5 出发）
每阶段独立可用、可回退，不破坏器官层调用契约。
阶段 A：核心层规范化（近期，可先做）
• L3/L2 引入 INT8 量化 + Parquet 元数据快照，替换纯 JSON 快照。
• 体积先压下来，加载速度提上去，千亿级从核心层规范化开始。
• 收益：快照体积下降、批量分析变快，为后续量化/分片打地基。
• 📄 施工图已出：docs/阶段A施工图-Parquet列式元数据快照.md（含 Parquet schema、接口、迁移工具、回退开关、验收清单，可直接照着写代码）。
阶段 B：冷存储 + 二值量化（中期）
• L1 层单独走冷存储 + 二值量化，感知节点/原始碎片等海量低价值数据与 L2/L3 分治。
• 做粗召回候选池。
• 收益：L1 长尾数据不再挤占 L2/L3 的高精度资源。
阶段 C：LSM + 分片 + 外置索引（长期千亿级）
• 引入 LSM 引擎（RocksDB）+ node_id 一致性哈希分片。
• 路径/频率/关系三类外置索引磁盘化 + 异步构建。
• 收益：跨入「亿级→千亿级」可扩展区间。
阶段 D：按需加载 + 缓存换入换出（长期千亿级必改）
• 不能再启动全量加载所有知识，必须：热层常驻、温层按需加载、冷层归档召回。
• 否则哪怕压缩再高，千亿级也不可能全部塞进内存。
• 分布式（分片跨机）+ 向量检索引擎（Milvus/FAISS）接入。

十一、结论
上千亿级知识存储没有单一格式，是分层混合存储架构。核心原则：按访问热度分层，不同层级用不同量化精度、存储介质、索引结构。
对 PulseNet 的落地顺序：先核心层规范化（INT8 + Parquet）→ 再冷层二值量化 → 再 LSM + 分片 → 最后按需加载。每步都保持器官层调用契约不变，可回退、可验收。
最重要的一条认知：千亿级的终极手段不是「更高的压缩比」，而是**「按需加载 + 缓存换入换出」**——热层常驻、温层按需、冷层归档召回，让系统永远只把「当前需要的知识」放在内存里。
