一、背景与目标
背景
P3-L1 是「自主深度探查」三层递进中的第一层。当前探查代理（P0~P2）是无记忆的静态扫描器：每一轮三通道并行审查，目标集（扫哪些器官/文件/规则）编译期写死，与上一轮发现了什么完全无关。这导致两个问题：

重复劳动：长期干净的区域每轮都全量重扫，浪费算力。
反馈缺失：历史高频出问题的文件/类型，没有得到「额外关注」，探查命中率低。
目标
让探查器有记忆：把上一轮探查结果沉淀为「历史问题分布」，下一轮探查时对「历史高频问题区域」加权深扫、对「长期干净区域」降频浅扫，同时保留全量兜底避免遗漏新问题。

非目标（明确排除）
不做「自主假设生成」（那是 L2）。
不做「完全自主规划」（那是 L3）。
不改 run_parallel_audit 的对外契约（保持向后兼容）。
二、关键设计决策（代码级事实驱动）
在写方案前，我先核对了三处代码事实，它们直接决定了实现方式：

决策1：历史问题分布不能存学习枢纽的 _entries
事实：verification_learning_hub.py 的 check_and_get_distillable（第 208~223 行）在达到蒸馏阈值时会把条目从主列表清空；get_stats（第 395 行）只返回计数，不含 file/type 聚合。

结论：L1 需要独立的「探查策略记忆」存储（新建轻量模块），不能复用会被蒸馏清空的 _entries。这是最小侵入 + 数据不被破坏的唯一选择。

决策2：加权深扫需要新入口，不能复用 detect_code_issues
事实：self_inspector.detect_code_issues（第 1116 行）内部调用 _scan_all_organs()（无参数过滤），是全量扫描，没有「定向扫描某文件/器官」的入口。

结论：L1 的「加权深扫」通过探查策略层实现——策略层算出「本轮重点关注的文件/类型集合」，在聚合后对命中这些区域的 issue 加权标记（而非改变扫描逻辑本身）。这样零侵入 self_inspector，只叠加一层策略。

决策3：注入点在 PulseCortex._run_parallel_audit_async，不在 run_parallel_audit 内部
事实：PulseCortex._run_parallel_audit_async（第 1316~1349 行）在 _do_audit 里调用 run_parallel_audit(_inspector)，之后 record_audit_findings_to_hub(_report) 回流。

结论：L1 的「读上轮结果 → 算本轮策略」放在 _do_audit 里、run_parallel_audit 之前，把策略作为可选参数传入。run_parallel_audit 签名保持向后兼容（新增参数带默认值 None）。

三、设计思路
3.1 新增模块：nucleus/probe_strategy.py（探查策略记忆）
独立、零侵入、线程安全，职责单一——只负责「记历史 + 算策略」：

class ProbeStrategyMemory:
    def record_round(self, report: dict) -> None:
        """把一轮探查结果沉淀为「文件/类型 → 历史频次」增量统计。"""
    def compute_strategy(self) -> dict:
        """基于历史频次，算出本轮「重点文件集合 + 重点类型集合 + 加权系数」。"""
    def reset(self) -> None:
        """器官零状态复位。"""
数据持久化：复用现有 data/ 目录约定，落一个轻量 JSON（如 data/probe_strategy.json），与学习枢纽的 verification_learning.json 并列，互不干扰。

统计口径：

按 file 聚合：某文件历史累计 issue 数（按 severity 加权：high=3 / medium=2 / low=1）。
按 type 聚合：某问题类型历史累计出现次数。
时间衰减：只统计最近 N 轮（默认 5 轮），避免远古问题永远霸占权重。
3.2 策略语义（「加权」而非「排他」）
这是 L1 的核心原则，防止「过度拟合历史」：

区域	本轮处理	实现
历史高频文件	加权深扫（issue 标记 strategy_weight 提升）	聚合后对命中重点文件的 issue 追加 strategy_focus=True
历史高频类型	加权深扫（同类型 issue 排序靠前）	聚合后按「类型是否重点」重排序
长期干净区域	降频浅扫	保留在结果中，但不再单独关注
全量兜底	不丢任何 issue	run_parallel_audit 仍全量扫描，策略层只做「排序 + 标记」，不裁剪
关键：L1 不裁剪扫描范围，只做「标记 + 排序 + 回流」，因此零风险破坏「补闭环」原则——不会因为策略而漏掉新问题。

3.3 接入链路（最小侵入）
PulseCortex._run_parallel_audit_async._do_audit
  │
  ├─ 1. _memory = get_probe_strategy_memory()
  ├─ 2. _strategy = _memory.compute_strategy()          # 读上轮历史 → 算本轮重点
  ├─ 3. _report = run_parallel_audit(_inspector, strategy=_strategy)  # 可选参数
  ├─ 4. record_audit_findings_to_hub(_report)            # 原回流不变
  └─ 5. _memory.record_round(_report)                    # 沉淀本轮 → 供下一轮
run_parallel_audit(self_inspector=None, strategy=None) 的 strategy 参数：

None → 行为与改造前完全一致（向后兼容，零回归）。
传入 dict → 在聚合层对 issue 做「重点标记 + 排序」，不改变扫描。
