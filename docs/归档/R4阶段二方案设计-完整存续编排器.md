## 〇、一句话定位

把五层次从「各自独立读存续指数、无反馈闭环」升级为「统一感知 → 分层行动 → 结果反馈 → 再感知」的**全局稳态控制系统**，核心支点是**存续状态快照（SurvivalSnapshot）**，一切动作都围绕「存续意志」这一框架第一公理展开。

## 〇·一、三大核心决策点（最终定稿，无需再议）

### 决策1：反馈回写边界（最终定稿）

**只回写 3 类 100% 确定性、可量化、可复现的动作结果，其余全部禁止回写。**

| 允许回写场景 | 加分 | 确定性依据 |
|------------|:---:|-----------|
| 生命层：R2 自我保存全套动作执行成功（自检/回收/备份无异常） | +5 | 可复现、可量化 |
| 协调层：全局并发降载、任务节流执行生效 | +3 | 可复现、可量化 |
| 创造层：高危迭代锁成功冻结所有自主修改行为 | +2 | 可复现、可量化 |

**禁止回写场景**（全部模糊、主观、无量化）：
- 智慧层搜索开闭、知识修复（进度不可量化）
- 精神层自我关怀叙事、情绪稳定（纯主观状态）
- 所有高位恢复类动作（避免正向震荡）

**核心原则**：只做「纠错加分」，不做「常态加分」，从根源杜绝指数震荡漂移。

### 决策2：编排器驱动方式（最终定稿）

**绑定心跳脉冲驱动（BEAT），拒绝独立定时器。**

理由（架构级硬约束）：
- 存续指数本身由心跳节拍生成，同源驱动、时序绝对对齐，无错位
- 独立定时器会出现「指数已更新、编排未响应」或「编排轮询过快」的时序 BUG
- 跟随心跳天然支持暂停/休眠/降频，适配生命层节奏

**附加约束**：编排器不每拍都执行，**心跳每 5 拍执行一次状态检测**，轻量化、防冗余、降负载。

### 决策3：创造层稳定性锁解锁条件（最终定稿）

**连续 2 次心跳高位稳态判定（指数≥80）才自动解锁。**

拒绝：单次高位立即解锁（极易抖动回弹）。

逻辑：
- 单次高位：可能是瞬时修复的短暂峰值，系统未彻底稳定
- 连续两次稳态：证明系统已脱离危机、进入可持续健康状态

**安全兜底**：解锁后若再次跌落 low，立即瞬时重新上锁，无延迟、无窗口期风险。

### 决策4：实施分批策略（最终定稿）

**分两批次落地，最大程度降低风险。**

| 批次 | 内容 | 风险 |
|:---:|------|:---:|
| 第一批 | 步骤1+2：完整编排器内核（快照/双阻尼/降级/心跳驱动）+ 五层次钩子填充 | 低（可独立测试，无反馈回写、无强锁） |
| 第二批 | 步骤3+4：确定性反馈回写闭环 + 创造层高危稳定性强制锁 | 中高（稳后再上） |

**优势**：先跑通「感知-行动」主回路，观察 48 小时无震荡，再开启「反馈调控」，完全符合渐进式工程原则。

## 一、阶段二要解决的三件事（承接阶段一定稿）

阶段一已把「接口」锁死（`SurvivalSnapshot` dataclass + `on_survival_low/high` 空钩子 + 全局开关）。阶段二要做的是把**逻辑**填进去，补上定稿里明确缺失的三条回路：

| 缺失回路 | 现状问题 | 阶段二补法 |
|---------|---------|-----------|
| **感知回路** | 五器官各自独立读 `get_existential_state()`，口径可能不一致、时序错位 | 编排器统一读取 → 产出唯一标准快照 → 分发给五层次 |
| **行动回路** | 各器官各自降载，无「谁先降、降多少」的优先级协调 | 编排器按「生存 > 认知 > 调度 > 进化 > 人格」优先级顺序触发钩子 |
| **反馈回路** | 器官动作结果不回写，存续指数回升没有显式闭环 | 编排器收集五层次动作结果 → 回写存续指数 → 触发再感知 |

## 二、架构设计（最小侵入，复用现有基础设施）

### 2.1 组件关系图

```
                 ┌─────────────────────────────────────┐
                 │   SurvivalOrchestrator（新增协调层）  │
                 │   · 单一事实源：读 get_existential_state │
                 │   · 双阻尼过滤：阈值±8分 + 20分钟冷却    │
                 │   · 三条回路编排                        │
                 └──────────────┬──────────────────────┘
                                │ 分发 SurvivalSnapshot
        ┌───────────┬───────────┼───────────┬───────────┐
        ▼           ▼           ▼           ▼           ▼
     生命层       智慧层       协调层       创造层       精神层
   PulseHeart  双腿/内在/潜意识  控制器/调度  SelfInspector  精神宪法
        │           │           │           │           │
        └───────────┴─────┬─────┴───────────┴───────────┘
                          ▼ 动作结果回写
                 ┌──────────────────────┐
                 │  反馈回路（有阻尼）    │
                 │  回写存续指数/洞察板   │
                 └──────────────────────┘
```

### 2.2 核心原则（复用阶段一承诺）

1. **编排器只做「读 + 分发 + 收集反馈」**，不替代各器官原有逻辑。
2. **编排器异常自动降级**：任何异常 → 各器官回退到「各自读」现状，保证不新增单点故障。
3. **不改变脉冲通信**：编排器作为「补充协调层」，通过钩子直接调用，而非新增脉冲事件类型。
4. **双阻尼防震荡**：阈值抖动过滤（±8 分）+ 时间冷却（20 分钟），二者缺一不可。

## 三、核心设计：三条回路的完整实现

### 3.1 感知回路（统一快照）

**职责**：把 `get_existential_state()` 的原始输出标准化为唯一 `SurvivalSnapshot`，消除五器官各自读时的口径/时序差异。

```python
class SurvivalOrchestrator:
    def _sense(self) -> SurvivalSnapshot:
        """感知：读取存续状态，产出标准快照（含双阻尼过滤）。"""
        raw = get_existential_state()          # 复用现有接口
        snap = SurvivalSnapshot.from_existential_state(raw)
        # 双阻尼①：阈值抖动过滤（±8分内的波动视为噪音，不触发模式切换）
        if abs(snap.index - self._last_index) < 8 and not snap.mode_switched:
            snap.mode_switched = False
        # 双阻尼②：时间冷却（20分钟内不重复触发同一动作）
        if time.time() - self._last_action_time < self.COOLDOWN_SECONDS:
            return snap  # 冷却期内不触发新动作
        return snap
```

**关键决策**：`stable_duration`（稳态持续时长）作为第二重保险——只有状态稳定持续一定时长后，才判定为「真正的 low/high」，避免瞬时抖动误触发。

### 3.2 行动回路（分层钩子 + 优先级顺序）

**职责**：按「生存 → 调度 → 认知 → 进化 → 人格」的优先级顺序，依次调用五层次代表器官的 `on_survival_low/high` 钩子。

**优先级设计逻辑**：生存层动作最优先（存续是第一公理），协调层次之（资源降载先于认知收缩），认知层再次，进化层最后（存续低位时它必须最先让位）。这是小林评审定稿的「生命→协调→智慧→创造→精神」顺序。

**互斥串行约束**：前一层动作未执行完成/未返回，绝不执行下一层，杜绝多层同时降载导致的资源过度收缩、系统僵死。

```python
    # 分发顺序（定稿的优先级链：生命→协调→智慧→创造→精神）
    _LAYER_ORDER = [
        "life",          # 生命层：PulseHeart + R2自我保存（最优先）
        "coordination",  # 协调层：控制器/调度/节流（资源降载先于认知收缩）
        "wisdom",        # 智慧层：双腿/内在世界/潜意识
        "creation",      # 创造层：SelfInspector/代码学习/知识重构
        "spirit",        # 精神层：精神宪法/自我叙事（最后）
    ]

    def _act(self, snap: SurvivalSnapshot):
        """行动：按优先级链严格串行分发快照，触发对应钩子。"""
        for layer in self._LAYER_ORDER:
            organ = self._layer_organs.get(layer)
            if organ is None:
                continue
            try:
                if snap.is_low:
                    organ.on_survival_low(snap)
                elif snap.is_high:
                    organ.on_survival_high(snap)
            except Exception as e:
                # 单层失败不影响其他层（隔离故障）
                self._log_warning(f"层次[{layer}]动作异常: {e}")
```

### 3.3 反馈回路（动作结果回写 + 阻尼）

**职责**：收集五层次动作结果，回写存续指数，形成闭环。这是阶段一定稿里明确缺失的「反馈回路」。

```python
    def _feedback(self, action_results: dict):
        """反馈：收集动作结果，回写存续指数（有阻尼）。"""
        # 只回写「确定性结果」（如 R2 自我保存成功 → 生命层指标 +N）
        # 不回写「模糊结果」（如情绪波动），避免指数被动作结果来回拉扯
        for layer, result in action_results.items():
            if result.get("deterministic"):
                self._apply_feedback(layer, result)
        # 反馈写入 InsightBoard（复用现有基础设施），供后续闭环间共享
        get_insight_board().add_insight(...)
```

**反馈阻尼**：回写值做「±8 分阈值」过滤，只有实质改善才回写；且回写后立即进入 20 分钟冷却，避免「动作 → 指数回升 → 撤销动作 → 指数回落」的震荡。

## 五、双阻尼机制（防震荡核心）

这是阶段一定稿里最关键的稳定性设计，阶段二必须严格实现。

### 5.1 阈值抖动过滤（±8 分）

存续指数在 ±8 分内的波动视为「噪音」，不触发模式切换。只有当：
- `|当前指数 - 上次触发指数| >= 8`，或
- `mode_switched == True`（明确的模式切换标志）

才认为状态发生「实质变化」，才允许触发动作。

### 5.2 时间冷却（20 分钟）

同一动作（low/high）触发后，20 分钟内不重复触发。这是防「动作 → 指数变化 → 撤销动作 → 指数再变」震荡的第二道保险。

### 5.3 双阻尼的协同

```
原始指数变化 → [阈值过滤] → 是否实质变化？ → [时间冷却] → 是否可触发？ → 触发动作
                否：忽略                    否：等待冷却
```

两层过滤叠加，确保只在「真实且稳定」的状态变化时才动作，从根上杜绝震荡。

## 六、编排器异常自动降级（fallback）

阶段一定稿要求「编排器异常时各器官回退到各自读」。阶段二实现：

```python
    def tick(self):
        """编排器主循环（由心跳或定时器驱动）。"""
        if not SURVIVAL_ORCHESTRATOR_ENABLED:
            return  # 总开关关闭，五层次回退到各自读
        try:
            snap = self._sense()
            if snap.mode_switched or self._should_act(snap):
                self._act(snap)
                results = self._collect_results()
                self._feedback(results)
        except Exception as e:
            # ★自动降级：编排器任何异常 → 关闭总开关，回退到各自读现状
            self._log_error(f"编排器异常，自动降级: {e}")
            SURVIVAL_ORCHESTRATOR_ENABLED = False
```

**降级语义**：编排器异常不抛出、不阻塞主流程，静默关闭自身，五层次自动回退到「各自读」的现状。这样编排器永远不会成为单点故障。

## 八、架构级隐性约束（评审补充，强制落地）

### 约束1：状态锁死机制（防高频抖动终极保险）

在双阻尼之上，新增**状态锁定标记**：

一旦触发 low/high 正式动作，立即锁定当前状态，在 20 分钟冷却周期内：
- 无论指数如何小幅波动，不二次切换状态、不重复触发动作
- 只更新快照数据，不执行业务逻辑

**解决**：双阻尼仍无法规避的「临界值反复横跳」问题。

### 约束2：动作执行优先级强序、互斥约束

**Low 状态触发顺序（严格串行、不可并发）**：

```
生命层 → 协调层 → 智慧层 → 创造层 → 精神层
```

核心规则：
- 前一层动作未执行完成/未返回，绝不执行下一层
- 生存优先、调度次之、进化最后，完全贴合生命系统逻辑
- 杜绝多层同时降载导致的资源过度收缩、系统僵死

> 注意：此顺序与本文「行动回路」一节的生命→智慧→协调→创造→精神的顺序有差异。**以本约束的「生命→协调→智慧→创造→精神」为最终定稿**（协调层提前，确保资源降载先于认知收缩）。

### 约束3：InsightBoard 可观测埋点（强制落地）

所有编排器核心动作，必须落地洞察黑板记录：

| 埋点类型 | 内容 |
|---------|------|
| 状态切换洞察 | 记录「稳态变更、触发原因、分值变化、冷却时长」 |
| 分层动作洞察 | 记录每层钩子执行结果 |
| 反馈回写洞察 | 记录加分来源、加分数值、剩余冷却时间 |
| 降级触发洞察 | 编排器异常降级回退原生模式告警 |

**价值**：全程可追溯、可复盘、可调试，彻底解决隐性状态 BUG。

### 约束4：高位状态「保护性限流」

原方案只重视低位防护，忽略高位风险：

指数长期高位会导致：无节制搜索、无限制迭代、过度学习、资源暴涨。

新增高位约束：
- 高位**不禁止**动作，但**限制动作频率与并发上限**
- 防止健康状态下过度消耗资源、过度迭代引发不稳定

## 九、降级机制补强（彻底杜绝单点故障）

细粒度降级策略：

| 场景 | 降级行为 |
|------|---------|
