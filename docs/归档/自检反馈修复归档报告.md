## 二、逐项修复详情

### 修复 1（P2）：定期测试编码误报

**根因确认**：`PeriodicTestScheduler._run_scripts` 的 `subprocess.run` 虽有 `encoding="utf-8"`，但这**只影响父进程解码子进程输出，不影响子进程自身的 stdout 编码**。Windows 上子进程默认 stdout 为 GBK(cp936)，测试脚本 `print("✅")` 时在子进程内部写 stdout 就触发 `UnicodeEncodeError` → returncode=1 → 误判失败。

**修复**：`subprocess.run` 增加 `env={**os.environ, "PYTHONIOENCODING": "utf-8"}`，让子进程内部也用 UTF-8 输出。

**文件**：`nucleus/evolution/PeriodicTestScheduler.py`

### 修复 2（P2）：R3 分类器 LLM 兜底 + 自进化链路断层

**根因确认**：`SearchIntentClassifier.set_llm_callback()` 定义后全项目零调用（grep 证实），导致低置信度搜索不走 LLM 兜底、`evolution_samples` 永不积累、规则自进化链路（PatchManager 审批链）永不触发。R3 的「自进化」能力实际未激活。

**修复**（两处）：
1. `organs/motor/PulseLegs.py`：新增 `set_llm_callback()` 方法，把外部 LLM 调用封装注入分类器单例。
2. `main.py`：在双腿创建后，用 `lambda` 适配 `self.lung._call_remote_api` 签名（`_call_remote_api(prompt, model, enable_thinking)` → `(prompt) -> str|None`），注入分类器。

**文件**：`organs/motor/PulseLegs.py`、`main.py`

### 修复 3（P1）：快照保存并发写竞态（上次遗留）

**根因确认**：`PulseSnapshot` 定义了 `self._lock = RLock()`（第 74 行），但 `save()`/`_incremental_save()`/`save_l1()`/`save_parquet()` 四条写路径均未加锁。上次日志的「L1快照保存失败: WinError 2」即此竞态触发。

**修复**：用「入口加锁 + 扁平化」策略（避免重入死锁）：
- `save()` 加 `with self._lock`，实际逻辑抽到 `_save_locked()`。
- `save_l1()` 加锁，逻辑抽到 `_save_l1_locked()`。
- `save_parquet()` 加锁，逻辑抽到 `_save_parquet_locked()`。
- RLock 可重入，`save()` 内部调用 `save_l1()`/`save_parquet()` 不会死锁（已验证）。

**文件**：`nucleus/mnemosyne/PulseSnapshot.py`

### 修复 4：控制器学习失败补救 vs 对话补救脉冲彻底区分

**根因确认**：`is_dialogue` / `is_background_learning` 两标记散落各处，部分路径依赖「默认 False」的隐式行为，语义不统一。具体发现：
- `PulseInnerWorld` 后台学习补救调用（1247 行）只靠「不携带 correlation_id」隐式区分，未显式标记。
- `PulseLung` 消费端 `is_dialogue` 默认 False，任何忘记显式标记的对话补救都会被误当后台学习。

**修复**（两处）：
1. `organs/brain/PulseInnerWorld.py`：后台学习调用显式补 `is_dialogue=False + is_background_learning=True`，语义自明。
2. `organs/body/PulseLung.py`：`_on_select_model` 开头加统一「对话 vs 后台」判定助手，含两条自愈规则：
   - 规则1：后台标记为真 → 强制对话=False（后台优先，杜绝后台内容误输出）。
   - 规则2：两者都缺失 → 有 correlation_id 视为对话，否则保守视为后台（宁可静默消化，不让后台内容误输出/语音播报）。

**文件**：`organs/brain/PulseInnerWorld.py`、`organs/body/PulseLung.py`

### 修复 5（P2）：代码学习跳过「扫描异常」误判

**根因确认（已复跑证实）**：`PulseCodeLearner._learn_own_code_structure` 第 310 行用 `"error" in str(code_summary)` 做**字符串子串匹配**判断「是否扫描异常」。当正常扫描结果里，任何器官的公开方法名含 "error" 子串（如 `handle_error`、`report_error`、`error_handler`）时，整段 str 被误判为「扫描异常」，导致代码学习被错误跳过。

**修复**：改为结构化判断——`get_organ_code_structure` 异常时返回的是单键 `{"error": "..."}` 字典，正常时是 `{器官名: {...}}` 字典。新增 `_is_error_structure()` / `_is_valid_structure()` 两个静态方法做结构化判断，替代子串匹配。

**同类问题一并排查修复**（共 5 处）：
- `PulseCodeLearner.py` 第 303/310/410/1391 行（4 处）
- `self_inspector.py` 第 1923/1940 行（2 处）
- `PulseInnerWorld.py` 第 6222/6251 行（2 处）

**文件**：`organs/brain/PulseCodeLearner.py`、`nucleus/self_inspector.py`、`organs/brain/PulseInnerWorld.py`

**附带确认**：`get_organ_code_structure` 带 `organ_name` 参数时返回原始结构（含 file_path/classes/methods），不带参数时返回 summary（method_count/public_methods/directory），这是设计上的「两种返回形态」，代码自洽，非缺陷。
