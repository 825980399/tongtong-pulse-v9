## 二、关键实现细节

### 新增方法（PulseSelfAwareness）

| 方法 | 职责 |
|------|------|
| `_maybe_trigger_self_preservation(state)` | 触发判断：双重防抖 + 总开关 + 防重入，异步提交 |
| `_run_self_preservation(_index)` | 自我保存动作序列（后台线程执行） |
| `_on_preservation_done(operation)` | 完成回调 |
| `_on_preservation_failed(operation)` | 失败回调（降级告警） |

### 自我保存动作序列（4 步，任一失败不阻断）

① 健康自检（`KnowledgeTree.run_topology_health_check`）→ ② 资源回收（`InsightBoard.cleanup`）→ ③ 轻量索引快照（`PulseNodePool.save_index_snapshot`）→ ④ 结果记录到 InsightBoard

### 双重防抖设计

1. **状态跳变主触发**：`level=="low"` 且 `mode_switched==True`，或极度低位 `index<30`；
2. **冷却窗口节流**：距上次执行 `< cooldown_seconds(3600s)` 则跳过。

### 复用已有基础设施（不造轮子）

- `ExternalExecutor.submit`：异步执行（`priority=HIGH`、`max_timeout=30s`、`dedup_key` 防重）
- `PulseNodePool.save_index_snapshot`：轻量索引快照（**不调** `snapshot.save()` 全量，符合「低位只存元数据」的评审要求）
- `KnowledgeTree.run_topology_health_check`：健康自检
- `InsightBoard.cleanup`：资源回收

## 四、自查修正记录

1. **`priority` 参数**：初稿用字符串 `"high"`，核对 `ExternalExecutor` 真实接口后改为 `OperationPriority.HIGH` 枚举。
2. **回调签名**：`on_completed`/`on_failed` 实际是 `func(operation)`（单参数），错误信息从 `operation.error` 取，已修正 `_on_preservation_failed` 的取参方式。
3. **触发条件细化**：初稿「low 即触发」会在每 100 心跳重复触发（low 状态可能持续多拍），已细化为「mode_switched 或 index<30 才触发」，配合冷却窗口形成双重防抖。

---

## 五、回退预案

- **总开关**：`config.SELF_PRESERVATION_CONFIG["enabled"] = False` 一键禁用整套动作。
- **零侵入回退**：新增逻辑全部在「存续状态计算」之后的追加调用，删除 `_maybe_trigger_self_preservation` 调用即可完全回退，不影响原有存续感知逻辑。
