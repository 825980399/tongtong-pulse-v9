# 搜索意图体系统一归档报告（治本）

日期：2026-09-01
主题：统一两套搜索意图体系，消除技术债
涉及：`config.py`、`organs/motor/PulseController.py`、`nucleus/SearchIntentClassifier.py`

---

## 一、背景与问题

项目存在**两套并存但未打通的搜索意图体系**：

| 维度 | 旧体系 | 新体系（R3） |
|------|--------|-------------|
| 位置 | `config.py:search_intent_keywords` | `nucleus/SearchIntentClassifier.py` |
| 分类 | 4 类：learning/curiosity/creative/growth | 5 类：fact_query/concept_learning/error_diagnosis/trend_watching/deep_research |
| 判定 | `reason` 字符串子串匹配（脆弱） | 关键词打分 + LLM 兜底 + 规则自进化 |
| 使用方 | `PulseController._refine_search_url` | `PulseLegs` |

旧体系的 `search_intent_keywords` 存在四个问题：
1. 意图维度（心理动机）过时，缺失 error_diagnosis/trend_watching 等高频任务型意图
2. 子串匹配脆弱（`"学习" in reason` 误判英文/同义词）
3. 关键词质量偏低（泛化词，不如分类器的精准定位词）
4. 与 R3 分类器割裂，同一意图两路径结果不一致

## 二、治本方案

**核心思路**：让 `PulseController._refine_search_url` 复用 `SearchIntentClassifier` 判定意图（5 类），`search_intent_keywords` 降级为「意图 → 搜索限定词」的下游策略映射。

### 改动 1：config.py 扩展 search_intent_keywords 为 5 类

键名严格对齐分类器的 5 类意图：

```python
"search_intent_keywords": {
    "fact_query": "定义 含义 是什么",
    "concept_learning": "原理 机制 教程 入门 详解",
    "error_diagnosis": "报错 失败 异常 解决 排查",
    "trend_watching": "最新 热点 趋势 动态 2026",
    "deep_research": "综述 对比 分析 体系 架构",
}
```

### 改动 2：PulseController 改造 _refine_search_url

- 新增 `_classify_search_intent(text)`：调用 `SearchIntentClassifier.classify()` 判定 5 类意图，失败返回 None
- 新增 `_fallback_intent_terms(reason, keywords)`（静态方法）：保留旧 reason 子串匹配作为兜底，映射到新 5 类键
- 主流程：优先用分类器（准确、可进化），失败回退 reason 匹配（零回归）

## 三、验证结果

- ✅ 语法检查：`config.py`、`PulseController.py` 通过
- ✅ 分类器 5 类意图分类：fact_query/concept_learning/error_diagnosis/trend_watching/deep_research 全部正确
- ✅ 兜底逻辑零回归：旧 reason 子串匹配映射到新 5 类键，行为保留
- ✅ 端到端验证：
  - 「Python装饰器是什么」→ fact_query → 追加「定义 含义」
  - 「ImportError报错」→ error_diagnosis → 追加「失败 异常 解决」
  - 「分布式架构对比综述」→ deep_research → 追加「综述 对比 分析」

## 四、收益

1. **意图分类统一**：两条搜索路径（PulseController/PulseLegs）共用同一套分类器
2. **覆盖更全**：补上 error_diagnosis（错误排查）、trend_watching（趋势关注）等高频场景
3. **可进化**：分类结果随 SearchIntentClassifier 的规则自进化持续改善
4. **零回归**：分类器不可用时回退旧逻辑，不影响现有搜索功能
