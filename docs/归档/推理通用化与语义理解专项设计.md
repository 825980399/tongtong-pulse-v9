# 推理通用化与语义理解专项设计

> 生成时间：2026年8月30日（本窗口）
> 目标：把内部符号推理从「固定题型驱动」演进为「统一形式化 + 通用推理 + 语义理解辅助」，对标全球顶级 AI 的逻辑推理模式。

---

## 一、现状与问题（诚实诊断）

当前 `SymbolicReasoner` 是**题型驱动**的：`_try_compare`（传递闭包）、`_try_arithmetic`（变量代入）、`_try_csp`（回溯+约束传播）三个独立处理器。

**根本局限**：
1. **题型隔离**：跨题型混合题解不了（"A比B高 且 A住红房"这类混合无从下手）。
2. **纯正则解析**：无语义理解，无法识别量词/条件/否定形容词。
3. **无自我验证**：解出后不验证是否满足全部约束。
4. **能力边界不透明**：不知道「哪些逻辑类型框架能解、哪些不能」。

---

## 二、顶级 AI 的推理模式（借鉴对象）

o1/o3、AlphaGeometry、Anthropic 的共性：

```
自然语言 → 形式化（关系/约束/谓词）→ 搜索求解（约束传播/回溯/定理证明）
→ 自我验证（解是否满足所有约束）→ 思维链（中间步骤）→ 学习（从错误归纳策略）
```

核心是**「形式化 + 通用搜索 + 自我验证」**，而非「题型 + 专项规则」。

---

## 三、统一形式化模型（目标架构）

把一切逻辑题统一成**「关系 + 约束 + 目标」**：

```python
@dataclass
class Relation:
    kind: str       # greater / less / lives_in / has / assign ...
    subject: str    # A / 甲
    object: str     # B / 红 / 猫 / 5
    negated: bool   # 否定（甲不住红房）

@dataclass
class RelationSemantics:
    """关系语义（决定推理算子）"""
    transitive: bool   # 是否传递（greater 是，lives_in 否）
    functional: bool   # 是否函数（lives_in 是：每人住一房）

@dataclass
class SymbolicProblem:
    relations: list[Relation]
    entities: set[str]
    domains: dict[str, set[str]]
    goal: Goal | None
```

**关键洞察**：比较（`greater(A,B)`）和排除（`lives_in(甲,红)`）**不再是两个题型，而是同一套关系约束求解**。推理引擎根据 `RelationSemantics` 自动选择算子：
- `transitive` 关系 → 传递闭包
- `functional` 关系 → 唯一性约束
- 否定关系 → 排除约束

---

## 四、语义理解层（辅助解析）

不再纯正则，接入语义理解：
- **否定检测**：不住/不高于/不比...高 → negated 或 ≤ 关系
- **量词识别**：至少/恰好/所有/只有 → 计数约束（CSP 扩展）
- **实体识别**：甲乙丙 / A、B、C
- **句式检测**：疑问（谁/哪个）vs 陈述 vs 排序/比较请求
- **条件词**：如果...则 → 命题逻辑（下一阶段）

---

## 五、自我验证（顶级 AI 模式）

解出后，把答案代回所有约束，验证是否满足：
- 比较：无 `A>B 且 B>A` 矛盾
- CSP：解满足全部正/负约束
- 算术：代入求值可复现

验证失败 → 不返回答案，诚实降级。

## 七、已落地（阶段4 + 阶段5 + 阶段6）

### 阶段4（语义理解辅助 + 自我验证）

1. **自我验证·矛盾检测**：传递闭包后检测 `A>B 且 B>A` 矛盾，矛盾则 `solved=False`。
2. **语义理解辅助·复杂语义诚实降级**：识别量词/条件/否定形容词/概率/时序五类语义，`task_type` 标记为 `unsupported_xxx`，诚实降级交给大模型，绝不硬编。
3. **能力边界可观测**：`task_type` 标记（compare/arithmetic/csp/unsupported_*），通过验证学习枢纽可统计「框架能解哪些、不能解哪些」。

### 阶段5（统一形式化重构）

1. **统一关系模型落地**：新增 `Relation` / `RelationSemantics` / `Goal` / `SymbolicProblem`，比较、赋值、条件排除三类题统一为「关系 + 约束 + 目标」。
2. **语义注册表驱动**：`RELATION_SEMANTICS`（transitive/functional/negatable）自动选择算子，不再按题型硬编码。
3. **三段式流水线**：`_formalize`（解析）→ `_solve`（求解）→ `_verify`（自我验证），验证失败诚实降级。
4. **否定比较语义落地**：「不高于/不低于/不大于/不小于/不比X高/不比X矮」转为非严格不等式（≤/≥）参与传递闭包，支持严格/非严格混合推导（如 `甲≥乙>丙 → 甲>丙`）；并列（ties）导致多解时诚实降级。
5. **消除误判**：裸「两人/三人」（实体描述）不再误标为量词；CSP 多解/信息不足返回 `task_type="csp"` 而非误标 `unsupported_*`。
6. **QICA 语义接入点**：`reason(question, semantic_hints=...)` 支持外部已识别实体并入形式化。

### 阶段6（命题逻辑 + 量词约束）

1. **命题逻辑落地**：新增 `_solve_propositional` 算子，支持「如果…那么/则、只要…就、除非…否则」条件推理，推理规则覆盖肯定前件（modus ponens）、否定后件（modus tollens）、传递链（不动点传播）、矛盾检测。
2. **量词约束落地**：新增 `_solve_quantifier` 算子，支持「至少N / 恰好N / 所有 / 只有」计数约束，通过枚举 + 唯一性验证求解「谁满足谓词」。
3. **诚实降级保持**：命题逻辑中「肯定后件」（`A→B, B成立 ⇒ A?`）等无效推理无法确定时返回 `solved=False`；量词多解时同样诚实降级。
4. **能力边界重构**：`conditional` / `quantifier` 从「unsupported_* 诚实降级」升级为「propositional / quantifier 主动求解」，仅 `probability` / `temporal` 仍诚实降级。
5. **压力→策略闭环**（配套）：应激轴暴露 `get_stress_level()`，内在世界据压力调节认知负荷与工具选择（高压降并行、跳过深度搜索、优先内在分步求解）。

**核心原则**：**解不出就诚实降级，绝不硬编答案**——这是「准确性」的底线，也是「通用化」的推进方式：先诚实识别能力边界，再逐步扩大边界。

---

## 八、一句话总结

通用化的本质是**从「题型 + 专项规则」走向「关系 + 约束 + 目标」的统一形式化**：解析层加语义理解，推理层加通用搜索，结果层加自我验证，能力层加诚实降级。已依次落地「自我验证 + 语义理解诚实降级」（阶段4）、「统一形式化重构」（阶段5）、「命题逻辑 + 量词约束」（阶段6），并打通「压力→策略调节闭环」。

### A.1 核心数据结构（第一版，已演进为 Relation 模型）

```python
# nucleus/reasoning/SymbolicReasoner.py

@dataclass
class SymbolicStep:
    """一步推理（轨迹单元）"""
    step_id: int
    premise: list[str]      # 前提：["A>B", "B>C"]
    conclusion: str         # 结论："A>C"
    rule: str               # 推理规则："传递闭包" / "变量代入" / "排除法"
    confidence: float       # 置信度

@dataclass
class SymbolicResult:
    """推理结果"""
    answer: str | None          # 最终答案文本
    steps: list[SymbolicStep]   # 完整推理轨迹（可回溯/复盘）
    solved: bool                # 是否真正解出
    confidence: float

class SymbolicState:
    """工作记忆（分步推理的中间状态）"""
    facts: list[tuple[str, str, str]]   # (关系, 主体, 客体)，如 ("gt","A","B")
    variables: dict[str, float]         # 变量值：{"A": 5, "B": 3}
    domains: dict[str, set]             # 排除法候选域：{"甲": {"红","蓝","绿"}, ...}
    steps: list[SymbolicStep]           # 轨迹
```

### A.2 三类算子（第一版，已并入统一关系约束求解）

| 题型 | 算法 |
|---|---|
| 比较/排序 | Floyd-Warshall 传递闭包，得到全序/偏序 |
| 变量算术 | 变量代入表达式 → 复用 `_safe_eval_arithmetic` 的 AST 白名单沙箱 |
| 条件排除 | 回溯搜索 + 约束传播（候选域逐步缩小） |

### A.4 安全（不变）

- **不 eval 任意代码**：算术只做「变量字典代入 + AST 白名单」。
- **关系/约束运算只做集合与图运算**：不执行任何用户字符串。
- 输入统一 `re` 提取 + 白名单校验，拒绝含函数名/字母的表达式。

### A.5 独立单测示例

`SymbolicReasoner` 是纯函数式模块，不依赖器官/脉冲/框架，可独立单测：

```python
r = SymbolicReasoner().reason("A比B高，B比C高，谁最高？")
assert r.answer == "A"
assert len(r.steps) == 2  # 两条传递推导

r2 = SymbolicReasoner().reason("A=5, B=3, A+B=?")
assert r2.answer == "8"

r3 = SymbolicReasoner().reason("甲乙丙，甲住红房，乙养猫，丙不住绿房，谁养鱼？")
assert r3.solved and r3.answer is not None
```

### A.6 验收标准（第一版三阶段）

1. **阶段1**：比较/变量算术三类题内部解出，`llm_used=False`，轨迹有分步步骤。
2. **阶段2**：简单 CSP（3 实体）内部解出，实体规模有上限（如 ≤6）防组合爆炸。
3. **阶段3**：解不出的题返回 None 走大模型兜底，不破坏降级链；`_trace_inference` 轨迹含 `reasoning_steps`。
