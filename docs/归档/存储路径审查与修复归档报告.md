## 三、发现的问题与修复

### P1（关键）：相对路径依赖「启动目录」（cwd）

**问题本质**：框架路径分两类——
- 基于项目根目录（`os.path.dirname(os.path.abspath(__file__))` 或 `project_root` 拼接）：进化、自省、代码备份等模块，**任何目录启动都正确**。
- 相对路径（`"data/knowledge/..."`、`"logs"`）：知识快照、Parquet、日志、本能快照，**实际落点取决于启动时 cwd**。

而 `main.py` 没有 `os.chdir()` 归一化 cwd。若从其他目录启动（如 `cd /home && python /path/to/main.py`），相对路径会被解析到错误位置，导致数据「写错位置、知识看似消失」。

**修复**：`main.py` 启动时强制 `os.chdir` 到项目根目录（一行核心逻辑），使所有相对路径稳定落在项目内。

```python
# ★P1修复: 启动时把当前工作目录归一化到项目根目录
_PROJECT_ROOT = os.path.dirname(os.path.abspath(__file__))
os.chdir(_PROJECT_ROOT)
sys.path.insert(0, _PROJECT_ROOT)
```

### P2（一般）：测试文件硬编码绝对路径

**问题本质**：`data/evolution/tests/` 下 3 个测试文件硬编码 `_PROJECT_ROOT = '/workspace/tongtong-pulse-v9'`，项目迁移（如用户下载到 Windows）后失效。

**根源**：`nucleus/evolution/TestGenerator.py` 生成测试时用 `{self._project_root!r}` 把绝对路径写死进测试文件。

**修复**：
1. 修正 `TestGenerator.py` 的生成模板，改为基于 `__file__` 相对推导（向上四级），生成的测试文件可随项目迁移。
2. 修正已有 2 个测试文件（`loop_verify_test.py`、`test_smoke_health2_test.py`）的硬编码路径，改为相对推导。

```python
# 项目根目录 = 本文件向上四级（data/evolution/tests -> 项目根）
_PROJECT_ROOT = os.path.dirname(os.path.dirname(os.path.dirname(os.path.dirname(os.path.abspath(__file__)))))
```

### P3（优化）：临时文件落系统临时目录（仅说明，无需修复）

所有 `tempfile.mkstemp` / `TemporaryDirectory` 会落到系统 `/tmp`，但这些是**原子写入的中间文件 + 沙箱临时目录，用完即删**，不属于持久化知识存储。唯一例外是 `PulseCodeSandbox` 的代码执行沙箱（`tongtong_sandbox_` 前缀），同样用完自动清理。**不影响数据归档，无需处理。**
