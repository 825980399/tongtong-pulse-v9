# 曈曈 PulseNet 自我迭代进化闭环「完美级全自主」改造报告

> 版本：v26.0 进化闭环升级
> 目标：实现「完全自主优化、自主修改代码、自主重启验证应用」
> 状态：已完成核心改造，待本地运行验证

---

## 一、改造目标与背景

原框架已具备自我进化闭环的骨架（`PulseCodeLearner` → `SelfInspector` → `EvolutionSandbox` → `SafeEvolutionExecutor` → `PatchManager` → 重启 → `SelfVerifier`），但存在 **4 个关键断点**，导致无法达到「完美级全自主」：

| # | 断点 | 后果 |
|---|------|------|
| 1 | 核心文件强制人工审批 | `main.py`/`config.py`/`nucleus/*` 的补丁永远卡在 `verified`，不自动应用 |
| 2 | 应用时机是「框架退出时」 | 补丁要等框架退出才落地，无法「验证通过即应用」 |
| 3 | 触发被动 | 仅周期自审（500 次心跳一次），无「健康度下降」主动触发 |
| 4 | 无目标函数闭环 | 应用后未用健康度评估「进化是否有效」，无法判断保留还是回退 |

---

## 二、改造方案总览

采用「**全放开 + 强验证兜底 + 多目标健康度目标函数**」策略，打通四个断点：

```
健康度评估 ──下降/危险──→ 主动触发进化审查
                              │
                              ▼
                     SelfInspector 检测问题
                              │
                              ▼
                    EvolutionSandbox 静态推演
                              │
                              ▼
                 SafeEvolutionExecutor 生成补丁
                              │
                              ▼
                PatchManager 副本验证(语法+import+回归测试)
                              │
                              ▼
                    [approved] 自动批准(含核心文件)
                              │
                              ▼
                request_apply_now 写入立即应用标记
                              │
                              ▼
             主循环检测标记 → 应用补丁 → 重启
                              │
                              ▼
              SelfVerifier 三关验证(器官/知识/推理)
                              │
                      ┌───────┴───────┐
                      │               │
                  通过            失败
                      │               │
             健康度对比          rollback_last
                      │               │
             回升→保留      重启恢复
             下降→回退
```

## 三、具体改动清单

### 1. `config.py` — 进化配置升级

**改动**：`auto_apply_enabled` 由 `False` 改为 `True`，并新增健康度驱动配置。

```python
EVOLUTION_CONFIG = {
    "auto_apply_enabled": True,          # ★默认开启全自主进化
    "auto_apply_min_trust": 60,
    "auto_apply_max_risk": 2,
    "auto_apply_cooldown": 86400,
    "auto_apply_backup_required": True,
    "auto_apply_restart_check": True,
    # ★新增：健康度驱动的主动进化触发
    "health_driven_evolution_enabled": True,
    "health_drop_trigger_threshold": 8.0,   # 下降 8 分触发
    "health_danger_threshold": 55.0,        # 低于 55 分触发
    "health_evaluate_interval": 1800,       # 30 分钟评估一次
    "health_recover_confirm_threshold": 3.0,  # 回升 3 分确认有效
}
```

### 2. `nucleus/reasoning/SafeEvolutionExecutor.py` — 放开核心文件限制 + 修复判定 bug

**改动 A**：核心文件不再强制人工审批，改为「强验证兜底」自动批准。

```python
# 原逻辑：核心文件强制 verified（不自动应用）
if _auto_apply and not self._is_core_file(...):
    patch["status"] = "approved"
else:
    patch["status"] = "verified"

# 新逻辑：核心文件也自动批准，但标注 is_core_file 供后续链路区分
if _auto_apply:
    if _is_core:
        patch["is_core_file"] = True
    patch["status"] = "approved"
```

**改动 B（重要修复）**：`_is_core_file` 原有 bug——marker 用 `/nucleus/pulse/` 依赖路径带前导斜杠，而实际补丁多为相对路径（`nucleus/pulse/...`），导致 `nucleus/*` 核心目录**从未被正确识别为核心文件**（核心文件审批防线形同虚设）。现已修复为同时匹配「路径前缀」与「含前导斜杠」两种形式。

### 3. `nucleus/evolution/HealthScore.py` — 多目标健康度评分器（任务 #11）

5 维度加权合成 0-100 分：

| 维度 | 权重 | 指标 |
|------|------|------|
| 稳定性 | 40% | ERROR/CRITICAL/Traceback 密度 |
| 噪音 | 20% | WARNING 刷屏 + 重复日志 |
| 性能 | 20% | CPU/内存/脉冲耗时 |
| 活性 | 15% | 器官在线率 + 心跳 + 脉冲吞吐 |
| 知识演化 | 5% | L2/L3 节点沉淀 + 融合/压缩 |

### 4. `nucleus/evolution/EvolutionDriver.py` — 进化驱动器（任务 #14，新建）

提供两个核心能力：

- **主动触发评估** `evaluate()`：健康度下降超阈值或跌破危险线时，返回 `should_evolve=True` 及薄弱维度清单（供定向排查）。
- **进化有效性判定** `judge_evolution()`：补丁应用重启后，对比应用前后健康度，判断保留/回退。
- **立即应用标记** `request_apply_now()` / `has_apply_request()` / `consume_apply_request()`：打通「验证通过即应用」断点。

### 5. `organs/brain/PulseCodeLearner.py` — 接入健康度驱动

**改动 A**：`__init__` 注入 `EvolutionDriver` 单例。

**改动 B**：`_on_heartbeat` 新增 `_maybe_trigger_health_driven_evolution()`，健康度下降时主动触发进化审查（`priority=high`），不再被动等 500 次心跳。

**改动 C**：`_review_own_code_issues` 生成 approved 补丁后，调用 `request_apply_now()` 写入「立即应用」请求。

### 6. `main.py` — 打通「验证通过即应用」

**改动 A**：抽取 `_apply_pending_patches_and_restart(framework)` 复用函数。

**改动 B**：主循环每 10 秒检测「立即应用」请求，检测到后走「停止框架 → 应用补丁 → 重启」流程，不再被动等框架退出。

**改动 C**：finally 退出块改为调用抽取后的函数（保留原退出时应用入口）。

## 四、安全防线（四重兜底）

全自主进化的安全性由四重防线保障：

| 防线 | 机制 | 说明 |
|------|------|------|
| 1. 强验证 | 副本验证(语法+import) + 真实回归测试(2 个脚本) | 补丁落地前必须通过 |
| 2. 健康度对比 | 应用前后健康度对比，下降即回退 | 目标函数闭环 |
| 3. 自动回退 | `rollback_last` + `mark_rolled_back`（单轮仅回退一次） | 验证失败自动回滚 |
| 4. 防循环重启 | 重启计数器上限 3 次 + 冷却 24h + 信任/风险双门槛 | 防止无限重启震荡 |
