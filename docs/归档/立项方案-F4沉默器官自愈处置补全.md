三、三权分立架构（核心设计原则）
血管（检测）──ORGAN_ESCALATION──▶ 系统管理器（调度）──restart/degrade──▶ 目标器官（执行）
   │                                    │
   └── 只感知、只告警、只发射            └── 只读访问 organs 容器、只调用生命周期方法
• 血管：只负责检测沉默、分级、发射脉冲，不直接操作任何器官。
• 系统管理器：只负责接收处置脉冲、查容器、调度生命周期方法，不修改容器、不调用业务方法。
• 目标器官：只被动接受 restart/degrade，不知道谁在调度它。
￼
四、采纳的 5 项补充建议（本次实施新增）
4.1 处置防抖
• 同一器官 5 分钟内最多执行 1 次同级别处置。
• 处置后进入观察期（5 分钟），观察期内不重复处置。
4.2 降级自动恢复
• 降级（SUSPENDED）后，系统管理器持续观察。
• 连续 3 次巡检正常 → 自动清除 SUSPENDED，回到 RUNNING。
4.3 审计日志
• 每次处置输出结构化日志，统一 [自愈审计] 前缀。
• 字段：器官名 / 动作 / 级别 / 原因 / 结果 / 耗时。
4.4 豁免列表统一
• 血管和系统管理器共用同一常量定义，避免两边不一致。
• 将豁免列表收敛到 nucleus/const.py 的 SILENCE_EXEMPT_ORGANS。
4.5 权限边界书面化
• 系统管理器的 framework 引用只读：仅访问 organs 容器、仅调用生命周期方法（restart/degrade），严禁修改容器、严禁调用业务方法。
• 作为代码评审卡点。

def restart(self) -> bool
:
    """软重启：stop 后立即 start。子类可覆盖以清理内部状态。"""
    self
.stop()
    self
.start()
    return self
.is_running

def degrade(self, reason: str = "") -> None
:
    """降级：记录状态 + 告警，不真正销毁器官（保留可恢复性）。"""
    self
.status = OrganStatus.SUSPENDED
    self._log(LogLevel.WARNING, f"器官降级: {reason or '沉默自愈'}"
)

def recover(self) -> None
:
    """★4.2 降级自动恢复：从 SUSPENDED 恢复到 RUNNING。"""
    if self
.status == OrganStatus.SUSPENDED:
        self
.status = OrganStatus.RUNNING
        self._log(LogLevel.INFO, "器官已从降级状态自动恢复"
)
关键设计约束：
• restart 最小实现（stop→start），不强清内部状态。
• degrade 只标记状态 + 告警，不销毁数据，保证可回滚。
• recover 是 degrade 的逆操作，保证「降级 → 恢复」闭环。

十、结论
F4 处置闭环已评审通过。方案坚守「血管检测 → 系统管理器调度 → 器官执行」三权分立，采纳 5 项补充建议（防抖/自动恢复/审计/豁免统一/权限边界），新增独立开关 ORGAN_ESCALATION_ACTION_ENABLED（默认 False）实现灰度控制。
按分步顺序实施：先 Step 1（基类方法，零风险）→ Step 2（注入引用）→ Step 3（订阅+开关关）→ Step 4（开关开，先 restart）→ Step 5（边界验证）→ Step 6（文档同步）。
