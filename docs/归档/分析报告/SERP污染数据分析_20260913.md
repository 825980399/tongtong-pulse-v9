## 一、结论先行

### ★★ 最重要发现：污染的真正成因不是"写入时灌水"，而是「衰减摘要的模板化压缩」

```
污染 1179 条
  ├─ A类 980 条（83.1%）—— 衰减摘要机制 `_summarize_experience()` 的产物
  │      原文已被【覆盖销毁】，模板句 = 摘要输出，一一对应
  └─ B类 199 条（16.9%）—— 原始写入时即为模板化短句
         （"动机循环内部评估" 独占 157 条）
```

**决定性证据**（三项独立指标 100% 重合）：

| 指标 | 污染集合 | 干净集合 |
|---|---|---|
| 记录数 | 1179 | 322 |
| **模板句匹配** | **980（83.1%）** | 21（6.5%） |
| **`is_summarized=true`** | **980（83.1%）** | 21（6.5%） |
| **模板句 ∩ 已摘要** | **980（100% 重合）** | 21（100% 重合） |
| `motivation ≤ 30 字` | **1173（99.5%）** | 267（82.9%） |

> 模板句匹配数 **精确等于** 已摘要数（980 = 980，交集亦为 980）——
> 这排除了"巧合"，说明**每一条被摘要的记录，摘要结果都落进了同一个模板**。

### 因果链（代码级）

`nucleus/mnemosyne/experience_pool.py:241-267`：

```python
def _summarize_experience(self, experience: dict):
    if experience.get("is_summarized", False):
        return
    _motivation = experience.get("motivation", "")
    _reward_type = experience.get("result_reward", {}).get("type", "")
    _emotions = "、".join(experience.get("emotion_tags", [])[:3])
    _summary = f"我曾因{_motivation[:30] or '某种动机'}而行动，获得了{_reward_type}奖赏"
    if _emotions:
        _summary += f"，感受到{_emotions}"

    experience["is_summarized"] = True
    experience["summary"] = _summary[:150]          # ★覆盖原文
    experience["motivation"] = _motivation[:50]     # ★截断
    experience["field_frequency_snapshot"] = {}     # ★清空
```

**三重信息损失**：
1. `summary` 被**模板句覆盖** → 原文不可恢复
2. `motivation` 截断到 30 字（摘要用）/ 50 字（字段用）
3. `field_frequency_snapshot` 清空

→ 813 条原本**不同**的经验，因 `motivation[:30]` + `reward type` + `emotion_tags[:3]` 三者组合相同，
被压成**同一句**"我曾因维持系统平衡而行动，获得了cognitive奖赏，感受到平静"。

### ★ 对修复方向的颠覆

| | 任务书/历史定性 | **实测真相** |
|---|---|---|
| 成因 | 写入侧"历史灌水" | **83.1% 是衰减摘要的产物（读取/维护侧）** |
| 主战场 | 写入拦截（防污染） | **改 `_summarize_experience` 的模板化压缩** |
| 只做写入侧防污染的效果 | — | **最多解决 16.9%（199 条）** |

> ⚠️ **若不改摘要机制，即使删光现有 980 条，下一轮 `check_decay()` 触发时污染会原样再生。**

| 日期 | 总记录 | 污染 | 干净 | 污染率 |

★ **污染 100% 集中在 09-09 单日；此后连续 4 天（248 条）零新增污染。**

**解释**：
- 09-09 触发了一次大规模 `check_decay()` → 批量衰减 → 批量摘要 → 批量模板化
- 此后 4 天写入 248 条**全部干净** → 说明**写入侧当前并未在灌水**
- 佐证：`nucleus/evolution/ExperiencePollutionGuard.py` 创建于 **2026-09-11**（晚于污染日）

> ⚠️ 但这**不代表安全**：只要 `_summarize_experience` 未改，
> 下一次大规模 `check_decay()` 触发时，这 248 条干净记录**会变成新的 1179+ 条污染**。
> **这是一颗定时炸弹，不是已解决的问题。**

## 五、不可逆性分析

### 5.1 依赖标记分布

| 标记 | 含义 | 命中数（污染内） |
|---|---|---|
| `is_summarized=true` | 已被摘要压缩 | **980** |
| `activation_count > 0` | 被检索激活过 | **0** |
| `quality_weight > 0` | 已进入质量体系 | **0** |
| `field_frequency_snapshot` 非空 | 已参与场频统计 | **0** |

组合分布**只有两种**：`S---`（980）与 `----`（199）。

### 5.2 真正的不可逆 = 980 条（A类）

| 类别 | 数量 | 可否恢复原文 | 处置 |
|---|---|---|---|
| **A类**（已摘要） | **980** | ❌ **`summary` 已被覆盖，原文不存在** | **真·不可逆** |
| **B类**（未摘要） | **199** | ✅ 原文即如此（本就是模板短句，无信息量） | **可安全删除** |

> **与任务书"226 条不可逆"的差异说明**：
> 任务书的 226 在当前数据与 `pollution_report.json` 中**均无法复现**（该快照未记录此数）。
> 实测不可逆为 **980 条**（判据：`is_summarized=true` 且 `summary` 已被模板覆盖）。
> 数量级差异来自判据不同——本报告按"原文是否已销毁"判定，更为保守。

### 5.3 污染记录的"零消费"现象

污染 1179 条中 `activation_count > 0` 为 **0**，`quality_weight > 0` 为 **0**
→ **污染记录从未被检索消费，也从未进入质量体系**。

这说明当前**降权/过滤在事实上是生效的**（污染没污染到检索结果），
P0-3 的真正危害在于：**它们占据 78.5% 的存储与扫描成本，并在"取前 N 条"时稀释有效经验的命中密度**，
而非"把噪声学进模型"（至少目前尚未发生）。
