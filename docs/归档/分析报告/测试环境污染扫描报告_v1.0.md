## 三、统一守卫：`nucleus/data/write_guard.py`（本批新增）

**判据（与第43批 `call_recorder` 内联守卫**同源**，抽成共享模块）**：

```
拒写 ⟺ ENABLE_TEST_ENV_WRITE_GUARD
        ∧ 处于 pytest 环境（PYTEST_CURRENT_TEST 或 pytest ∈ sys.modules）
        ∧ 目标路径落在本项目 data/ 内
        ∧ 调用方未显式注入目录
```

**★为什么只判 `data/` 前缀**（这条设计决定了"零回归"）：

| 写法 | 是否被拦 | 说明 |
|---|---|---|
| 写 `data/...`（生产数据） | **拦** | 目标 |
| 写源码文件（补丁应用 `patch["file"]`） | 不拦 | 不是 `data/`，且是正当功能 |
| 写 `mkstemp` 临时文件 | 不拦 | 在系统 temp 下 |
| 测试传 `project_root=tmp` / `base_dir=tmp` | 不拦 | 路径天然落在真实 root 之外 |
| 显式 `explicit=True` | 不拦 | 调用方自担隔离责任 |

**★永不抛出**：守卫自身故障 → 放行（绝不阻断正常功能）。

|---|---|---|---|

**桩判据（结构性，非关键词）**：渠道名 `^[a-zA-Z]\d{1,2}$`（`c1`/`c2`）｜模型名同形（`m1`/`m2`）｜应答命中桩值｜★**高频短桩**（同一 prompt ≥10 次且 ≤6 字符 —— 本次命中 `"hi"` × **146**）。

> ★**146 与第43批 T0 的数字精确吻合** —— 说明第43批的守卫已生效（**未新增**桩），
> 这 146 条是守卫上线**之前**的历史存量。

### 4.3 ★为什么对在写文件"只提取不重写"

扫描时发现 **`logs/pulse.log` 与 `data/llm_traces/*.jsonl` 的 mtime 在持续前进**（20:38→20:47 期间仍在增长），
读日志尾部确认**曈曈框架正在实时运行**（内在世界/潜意识/双腿/胃/肺 全在活动）。

⇒ 此时重写 `calls_20260913.jsonl` 会**与在写进程竞争 → 数据丢失**。
故对在写文件一律**只提取污染记录 + 写 MANIFEST**，物理移出推迟到**停机窗口**。

**★裁决 #5 一致性**：第43批裁决第 5 项同意「146 条历史测试桩保留作回归样本」——
本批正是把它**归档保留**（可随时用作污染识别的回归语料），**未删除**。
