## 三、★根因：报告为什么没人读

### 3.1 机制层面：生成即丢弃

```python
# nucleus/self_awareness/SelfAwarenessEngine.py:615
def generate_report(self, output_path: str | None = None) -> str:
    """生成可读文本报告；给了 output_path 则同时落盘。"""
```

**默认 `output_path=None` → 不落盘，只返回字符串。**

生产调用点仅 3 处：

| 调用点 | 是否传 `output_path` | 结果 |
|---|---|---|
| `nucleus/self_awareness/DailyScheduler.py:296` | ✅ 传 `_rp` | **落盘** + `_res["report_path"]=_rp` |
| `functions/chat/chat_service.py:464` | ⚠️ 待核 | 仅 `print` 提示 |
| `nucleus/evolution/ParamPatchManager.py:945` | ⚠️ 待核 | 仅 `print` 提示 |

→ **是否落盘完全依赖调用方自觉**，无框架级保障。

### 3.2 架构层面：无统一分发层

```
生成器 A ──┐
生成器 B ──┼──> （各自落盘 / 各自丢弃）──> 无注册、无索引、无分发
生成器 C ──┘                                  │
                                              ▼
                                    消费者需【自行知道路径+格式】
```

**三缺**：
1. **缺注册表** —— 没有地方记录"系统里有哪些报告"
2. **缺统一格式** —— 有 JSON / 纯文本 / HTML / 仅日志 四种形态
3. **缺分发机制** —— 没有"报告生成 → 通知订阅者"的通道

→ 结果：只有**恰好知道路径**的叙事自我吃到了报告，其余全部沉底。

### 3.3 数据层面：报告本身不可消费

| 问题 | 例 |
|---|---|
| **快照不刷新** | `pollution_report.json` 停留在 **17:50**，此后数据已变化（1179 vs 1193）→ 消费了也是**过期信息** |
| **无时间戳契约** | 部分报告无 `generated_at` 字段，消费者无法判断新鲜度 |
| **无严重度字段** | 报告里有数据，但**没有"这条有多严重"的机器可读字段** → 无法分级触发 |
| **格式异构** | 文本报告需正则解析才能机器消费 |
