## 二、★ 重大发现：经验池被重复灌水，1501 条只剩 36 种内容

对 `experience_pool.json` 的 1501 条 `summary` 做指纹统计：

| 指标 | 数值 |
|---|---|
| 条目总数 | 1501 |
| **不同的内容种类** | **仅 36 种** |
| 最高频内容出现次数 | **846 次**（"我曾因维持系统平衡而行动，获得了cognitive奖赏，感受到平静"） |
| 次高频 | 421 次（"动机循环内部评估"） |
| 第三高频 | 102 次（"我曾因自我审计而行动…"） |

**结论**：这不是"少量污染"，而是**经验写入链路缺少去重**——同一条经验被反复写入上百次，经验池实质被灌水，直接稀释推理时的经验权重（同一句话权重被放大 846 倍），这比零散污染对推理质量的伤害更大。

**建议（需星轨定夺，本批未做）**：在经验写入处增加去重（同 `summary` 已存在则累加 `activation_count` 而非新增条目），这属于**写入链路改造**，超出"只标记不删除"的本批范围，故仅标记降权、未改写入逻辑。

## 三、处理方式（已执行）

1. **只标记不删除**：污染条目标 `polluted: true` + `quality_flag` + `pollution_reason` + `quality_weight`，条目本身全部保留。
2. **降权消费**：`polluted` → 权重 **0.1**；`suspect` → 权重 **0.5**；正常 → 1.0。由 `ExperiencePollutionGuard.weight_of(entry)` 提供，推理检索时按此降权。
3. **备份**：两个库均已备份为 `.bak_batch11cd`，可回滚。
4. **检测规则**（`nucleus/evolution/ExperiencePollutionGuard.py`）：
   - 空内容 / 过短（<2 字符）
   - 测试残留关键词（test / tmp / mock / 模拟 / 测试 / 占位 / xxxx 等）
   - 置信度 < 0.3
   - 内容完全重复
   - 同问题不同结论 → 标记 `suspect`（可疑，非直接污染）
   - 缺少时间戳与 id 元信息 → `suspect`

## 四、持续检测机制（任务4.2）

- 新建 **`nucleus/evolution/ExperiencePollutionGuard.py`**，提供：
  - `detect(entry)`：单条检测，供**新经验写入前**调用（零依赖、纯函数、可单测）；
  - `scan_library()` / `scan_all()`：全库扫描与标记，可挂到每周定时任务；
  - **污染率 > 5% 自动 WARNING**（本次 `experience_pool.json` 97.6% 已触发告警日志）。
- **为什么独立成模块**：星轨建议挂在 `SelfCalibrator` 或 `ExperienceTransfer` 中，但后者体量大、改高风险；独立模块职责单一、可单测、零侵入，后续挂接只需在写入处 import 调用即可。
