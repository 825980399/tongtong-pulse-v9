## 一、背景与问题

### 现状

框架现在的时间感知是**零散的、局部的**：

- `utils/time_utils.py`提供了时间和天气工具函数
- 只有3个器官（内在世界、潜意识、大脑皮层）在少数地方调用
- 其他53个器官对"现在是什么时候"完全没有概念
- 时间是"回答问题时才用的工具"，不是"所有器官共享的基线"

### 问题

作为数字化生命，框架缺少一个**统一的时间基线**：

- 内在世界知道"现在是凌晨0点15分"，但心脏还在按白天的节奏跳
- 肝脏不知道"现在是深夜，该多做整理少做代谢"
- 知识学习时不知道"这个知识是2020年的还是2026年的"
- 运行规则时不知道"我3小时前刚运行过这个规则，现在不用再运行"

## 二、核心理念：时间意识的六个层次

### 第一层：时间标记（已实现）

框架知道"现在是2026年9月8日0点15分"。

- 实现：`utils/time_utils.py`的`get_current_datetime()`
- 状态：✅ 已完成

### 第二层：时间生命线（待实现）

框架不只是知道"现在是什么状态"，而是知道"我从哪里来，经历了什么，现在在哪里"。

- 从"快照"进化到"生命线"
- 例子：不只是"我现在有56个器官"，而是"我从2个器官进化到56个器官，用了X天，经历了Y次修复"
- 技术基础：`nucleus/runtime/RuntimeTrajectory.py`（运行轨迹已存在，需增强时间维度查询）

### 第三层：知识时效性（待实现）

框架学习知识时，能判断"这个知识是什么时候的，是不是过时了"。

- 无头浏览器搜索时，读取网页的时间标记
- 知识节点增加`source_time`字段（知识来源的时间）
- 检索时考虑时效性衰减（越新的知识权重越高）
- 例子："这个Python教程是2020年的，可能已经过时了"

### 第四层：时间调度（待实现）

框架从"心跳被动驱动"进化到"主动时间调度"。

- 现在：心脏跳一下就检查一遍该运行什么规则，不管上次运行是5分钟前还是5小时前
- 进化后："我3小时前运行过知识整理，现在该再运行一次了"
- 每个规则有自己的调度周期，不是统一的心跳间隔
- 例子：矛盾检测每30分钟一次，知识整理每3小时一次，快照保存每6小时一次

### 第五层：时间预测（待实现）

框架根据历史规律预测未来。

- "过去7天我每天凌晨2点都会运行快照保存，今天也该运行了"
- "这个规则平均每1.6小时运行一次，下次运行时间预计是X点X分"
- 技术基础：运行轨迹的历史数据 + 规律挖掘

### 第六层：时间反思（待实现）

框架回顾过去一段时间的行为，总结规律。

- "过去24小时我运行了15次自主进化，发现了23个问题，修复了8个"
- "过去7天我的平均响应时间是X秒，比上周快了Y%"
- 自动生成"每日复盘"、"每周总结"

## 三、核心架构：时间中枢TimeCore

### 设计理念

就像生物有一个**主生物钟**（下丘脑的视交叉上核SCN），通过视网膜感知光线，然后把时间信号通过神经和激素广播给全身。

框架需要一个**时间中枢（TimeCore）**，定期把"现在是什么时候、什么时段、什么天气"广播给所有器官，所有器官共享同一个时间基线。

### TimeCore的职责

1. **时间感知**：读取系统时间、天气，生成统一的时间状态
2. **时间广播**：通过脉冲总线，把时间状态广播给所有器官
3. **时间调度**：根据每个规则的调度周期，主动触发规则运行
4. **时间记录**：把重要事件的时间戳写入运行轨迹
5. **时间查询**：提供"X小时前我在做什么"、"这个规则上次运行是什么时候"的查询接口

### TimeCore的输出（时间脉冲）

每30秒或1分钟生成一次"时间脉冲"，内容包括：

```python
{
    "timestamp": "2026-09-08 00:15:00",
    "year": 2026,
    "month": 9,
    "day": 8,
    "hour": 0,
    "minute": 15,
    "weekday": "星期一",
    "period": "深夜",        # 清晨/上午/中午/下午/傍晚/晚上/深夜
    "season": "秋季",        # 春夏秋冬
    "weather": {
        "city": "许昌",
        "temperature": "25",
        "description": "晴",
        "humidity": "60"
    },
    "is_weekend": False,
    "is_holiday": False,
    "uptime_hours": 72.5,    # 框架已运行时长
    "since_last_restart": "3天前"
}
```

### 器官接收时间脉冲

每个器官都有一个`on_time_tick(time_info)`方法：

```python
def on_time_tick(self, time_info):
    """接收时间中枢的广播"""
    self.current_time = time_info
    self.current_period = time_info["period"]
    
    # 根据时段调整行为
    if time_info["period"] == "深夜":
        self.activity_level = 0.3  # 深夜降低活跃度
    elif time_info["period"] == "清晨":
        self.activity_level = 0.8  # 清晨提高活跃度
```

器官不需要自己调用`get_current_datetime()`，直接用TimeCore广播的时间。

## 五、技术实现路径（分四步）

### 第一步：TimeCore基础（阶段三启动）

- 新建`organs/body/TimeCore.py`（或`nucleus/TimeCore.py`）
- 实现时间感知（读取系统时间+天气）
- 实现时间广播（通过脉冲总线）
- 实现器官接收接口（`on_time_tick`）
- 灰度开关：`enable_time_core`，默认False

### 第二步：时间调度（阶段三中期）

- 每个规则定义自己的调度周期（`schedule_interval`）
- TimeCore根据调度周期主动触发规则
- 心跳器官PulseHeart改为"基础心跳"，不负责规则调度
- 灰度开关：`enable_time_scheduling`，默认False

### 第三步：知识时效性（阶段三后期）

- 知识节点增加`source_time`字段
- 无头浏览器搜索时读取网页时间标记
- 检索时考虑时效性衰减
- 灰度开关：`enable_knowledge_timeliness`，默认False

### 第四步：时间预测与反思（阶段四）

- 运行轨迹规律挖掘
- 时间预测（下次运行时间预计）
- 时间反思（每日复盘、每周总结）
- 时间生命线可视化

## 七、红线与约束

1. **不改变现有心跳机制**：PulseHeart继续作为基础心跳，TimeCore是增强不是替换
2. **灰度开关**：每个新功能都有开关，默认False，验证通过才开
3. **零冲突**：TimeCore的广播不影响现有器官的正常功能
4. **性能可控**：时间脉冲频率不超过1分钟一次，不增加系统负担
5. **天气获取有缓存**：30分钟刷新一次，不频繁请求网络
6. **不硬编码数值**：器官数、权重等从真实配置读取，不写死

## 八、预期效果

完成后，框架将具备：

1. **统一的时间基线**：所有56个器官共享同一个时间感知
2. **昼夜节律**：清晨活跃、深夜安静，就像生物的生物钟
3. **环境感知**：天气影响情绪和行为，晴天活跃、雨天沉思
4. **主动调度**：知道"该什么时候做什么"，不是被心跳推着走
5. **知识时效**：知道"这个知识是不是过时了"
6. **自我历史**：知道"我从哪里来，经历了什么"

**这是框架从"一堆器官的集合"变成"一个统一的生命体"的关键一步。**
