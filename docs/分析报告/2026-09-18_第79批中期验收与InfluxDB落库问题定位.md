## 三、T3 InfluxDB 真实写入 —— ⚠️ 连接打通，但暴露 flush 丢数据 bug（P1，新发现）

### 3.1 token 环境变量问题（已厘清）
- 用户已于 09-18 上午完成 InfluxDB 初始化并 `setx` 写入**用户级永久环境变量**（注册表实测正确，token 前缀 `0LW_vnKV`，长度88；URL/ORG/BUCKET 均正确）。
- 路灯 workbuddy 执行会话与星轨工具会话的**父进程均在 setx 之前启动**，子进程继承的是父进程缓存的旧环境块（旧 token 前缀 `BOLejK-F`），故路灯侧读到空/旧 token → 401。
- **结论：永久变量本身正确；重启 Doubao / 重新登录后所有新进程即生效。** 这不是代码缺陷。

### 3.2 星轨用正确 token 实跑真实后端（关键结果）
- Buckets 接口：**200 OK**，真实连接成功（`available: True`，使用真实 InfluxDB 后端）。
- 但 `tools/verify_write_only_e2e.py --backend real` 结果：
  - 4 项写入计数 **FAIL（全=0）**：node_modified / node_activated / node_accessed / query_executed 均未落库；
  - 快照显示 `buffered: 23, batch_size: 5000`——23 条数据卡在客户端缓冲区；
  - 进程退出时报：`The batch item wasn't processed successfully because: cannot schedule new futures after interpreter shutdown`。
- Flux 查询 `pulse_metrics` 桶近24小时：**空结果，零数据**。

### 3.3 根因（真实 bug，mock 环境永远发现不了）
1. **批量阈值过大**：`batch_size=5000`，日常指标量（单次验证仅23条）永远攒不满一个批次，不触发主动 flush；
2. **缺少 shutdown flush**：没有注册 `atexit` / 解释器退出前的强制 flush + close，进程结束时缓冲区数据被丢弃；
3. **线程池生命周期错误**：解释器 shutdown 后仍有任务向已关闭的 ThreadPoolExecutor 提交 future，报错且丢数据。
- **后果**：在当前数据量下，InfluxDB 双写"看起来健康（8/8 PASS，因为那是 mock 降级 + 链路检查），但真实数据一条都落不了库"——又一起"代码现实领先运行现实"。

### 3.4 修复建议（纳入第80批"外部存储收口"）
- 写入客户端增加：定时 flush（如每 5-10 秒）+ 缓冲区阈值 flush（阈值调到与实际流量匹配，如 100-500）+ `atexit` 强制 flush/close；
- 解释器退出信号（SIGTERM/KeyboardInterrupt/atexit）统一走优雅关闭，先 flush 再 shutdown 线程池，杜绝 shutdown 后提交 future；
- verify 脚本结束前显式 `close()`，并在真实后端断言"查询得到刚写入的点"，把"落库可查询"作为硬门禁（当前只验链路不验落库，是漏网原因）；
- 修复后用本文件同款 Flux 查询复核数据真实落桶。
