## ② LLM 补丁代码 SyntaxWarning（`<unknown>:行号`）

**现象**：控制台三条 `SyntaxWarning: invalid escape sequence '\.' '\(' '\s'`，文件名显示 `<unknown>`。

**根因**：`ast.parse(source)` 不传 filename 时默认 `<unknown>`。框架对 LLM 生成补丁做语法验证的多处未传 filename：
- `PatchManager.py:763/1031/1089/1133/1884`
- `self_inspector.py:696/702/1103`
- `SafeEvolutionExecutor.py:3437` 附近
- 行号10/14/56 是 LLM 代码内部行号——正则忘加 `r` 前缀。

**影响**：功能上 `'\.'` 与 `r'\.'` 等价，正则引擎认得，没坏；但刷控制台，是 LLM 补丁代码不规范旁证。

**方案**：
1. `ast.parse` 调用处补 `filename='<llm-patch>'`（或 `<orig>`/`<mod>` 类似命名）便于定位；
2. 或在 LLM 补丁验证侧把 SyntaxWarning 降级为 DEBUG 不刷控制台。

**验证**：改完跑一次 LLM 补丁 review/repair，控制台不再出现 `<unknown>:行号` 的 SyntaxWarning。

## ④ 真对话验收发现（2026-09-19 20:00 重启后小林实测）

### 4.1 "在吗"本地推理失败兜底（问候路由不完整）

**现象**：用户输入"在吗"，QICA 识别"情感问候"（分数差值仅0.001，触发探索），但最终输出：
> "这个问题我还需要再想想，暂时给不出确定的答案 (来源=inner_world)"

**根因**：问候类短问题走了本地推理路径，但本地推理没有"在吗"的直接回复模板，失败后兜底成"暂时给不出确定答案"。对比"你好"走了 deepseek LLM 生成正常问候，"在吗"却没走 LLM。

**方案**：问候类短问题（你好/在吗/嗨/早上好等）在 QICA 意图路由后，增加"直接本地回复模板"分支，不进入本地推理，直接回复"在的呢，有什么我可以帮你的吗？"之类。

### 4.2 D168 净化白名单漏了 [器官] 等标记词

**现象**：用户输入长文后，L39295 最终输出泄露内部标记词：
> "深层原理：[器官] [器..."

**根因**：D168 净化规则覆盖了"关联知识/[核心智慧]/代码片段:"，但**没覆盖 [器官]、[大脑]、[肺] 等器官名方括号标记**。含这些标记的内容被直接输出给用户。

**方案**：D168 净化白名单补全所有器官名标记（[器官]、[大脑]、[肺]、[胃]、[心] 等），含任一标记一律不清放（与"关联知识"同规则）。

### 4.3 搜索被中断：关键词提取错误 → 审查误判 → 信号冲突

**现象**：用户输入"搜索一下今天的科技新闻"，完整链路：
1. L39587 内在世界触发深度搜索（异步线程池）
2. L39603 控制器阶段1: site:baike.baidu.com 今天的科技新闻
3. **L39606 语义增强提取: ['探索', '适合', '生活']** ← 提取错误
4. L39608 内在世界审查: 关键词与主题无关 → 通知终止
5. L39612 大脑皮层兜底: correlation_id= 为空
6. L39618 搜索被终止，跳过阶段2

**三个问题**：
1. **关键词提取质量差**：控制器阶段1语义增强提取（LLM）把"今天的科技新闻"提取成"探索、适合、生活"——完全不相关。
2. **审查误判**：内在世界审查逻辑"关键词与主题无关就终止"，但根因是**提取错误**不是**主题错误**。审查机制把"提取错误"误判为"主题无关"，直接终止了搜索。
3. **信号冲突**（用户指出）：终止后大脑皮层同时收到空结果开始兜底验证，两个逻辑对同一搜索的状态判断不一致——**终止信号和结果兜底信号没有区分**。

**用户设计建议（架构级）**：不同逻辑应该采用不同的脉冲信号，尽量避免因信号相同造成冲突。例如：
- 终止搜索脉冲 vs 搜索结果脉冲 vs 兜底验证脉冲，应该用不同事件类型，不应让大脑皮层把"终止后的空结果"误读为"我来兜底"。

**方案**：
1. 关键词提取：对"新闻/科技/今天"等明确主题词，不应过度语义增强，保留原词；
2. 审查逻辑：区分"提取错误"和"主题无关"——如果关键词与原始搜索词重叠度低，应先重试提取，而不是直接终止；
3. 信号分层（架构级）：搜索终止信号用独立事件类型，不与搜索结果/兜底验证混用。
