### ⚠ 发现一：任务书 echo/sum 的键名与 worker 契约不符（非链路故障）

`nucleus/reasoning/subagent_worker.py` 实际读取的键名与任务书给出的**不一致**：

| op | 任务书给的键 | worker 实际读的 | 按任务书跑的结果 |
|---|---|---|---|
| echo | `message` | **`payload`**（:80） | `echo=null` |
| sum | `numbers` | **`nums`**（:82） | `sum=0` |
| hash | `data` | `data`（:89） | ✅ 一致 |

为区分"链路不通"与"键名写错"，加跑 worker 真实契约对照：

- `{"op":"sum","nums":[1,2,3]}` → **`sum=6`** ✅
- `{"op":"echo","payload":"hello"}` → **`echo="hello"`** ✅

**结论：真起链路完全打通，偏差仅在键名。** 两处均未擅自修改（改 worker 属扩面、改任务书非我职权），
**交星轨裁决**：是让 worker 兼容 `message/numbers`，还是修订丁步任务规格用 `payload/nums`。

### ⚠ 发现二：`pid` 恒为 None（既有缺陷，影响"起"的判据）

任务书验收"起"要求看 `SubagentRunResult.pid`，实测 8 次调用 **pid 全为 None**。
根因：`run_subagent` 用 `subprocess.run()`，其返回 `CompletedProcess` **没有 `pid` 属性**，
代码 `pid=getattr(proc, "pid", None)` 恒取到 None（仅 `Popen` 才有 pid）。
若要真 pid 需改用 `Popen` + `communicate(timeout=)`，属 runner 结构性改动，**待裁**。

## 二、刀2 · 心跳线两行修正（P2）— 已落地

改动位置 `utils/pulse_tracer.py`（孤儿心跳线，:620-659）：

1. **`_hb_M` 加 min_age 过龄过滤 ＋ 新增 `_hb_Y` 未到龄数**
   - 原 `_hb_M` 不查龄期，而 `_detect_orphans` 先按 1.5s 跳过未到龄者
     ⇒ 启动风暴期整环 emit 全"未到判定龄"却被记成"未回填=满额"（**稳定虚报**）。
   - 现 `_hb_M` 只统计**已过龄且未回填**；新增 `_hb_Y` 记录**未到龄**条数。

2. **WARN 带全量读数 ＋ 触发条件改为 `K==0 且过龄未回填>0`**
   - 原条件「`_hb_K==0 且 _hb_W>0`」前提已过期（260甲案删通配短路、262 过滤 observer），
     且原 WARN **不带任何计数**——恰在最可疑时刻全省读数。
   - 现 WARN 与 INFO 同带全量读数：**基数/未回填/平反/通配/孤儿/主路自证/派发丢包/未到龄**。

INFO/WARN 两行现均含"未到龄=%d"，启动窗可直接读到"未到龄"而非"未回填=满额"。
**零语义变更**：仅观测口径，不改判定逻辑。
