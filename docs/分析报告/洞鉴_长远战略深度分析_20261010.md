## §1 暂缓设计文档整合评估

### 1.1 SCNet 超算镜像重跑（T-超算镜像重跑-1，P2）

**现状取证**：
- Notebook 路线已验证全链路打通（`星轨_SCNet超算部署_环境整理与验证记录_20261009.md`）：57/57 器官在线、无密钥/无 GPU/无 Cython 降级容错全过、人体 UI 公网访问正常。
- 一键脚本 `tools/scnet/` 已入库（setup/verify/README）。
- 遗留：`setup_cython.py` 主仓不存在（0/6 编译，性能降 3 倍）、Ollama `Popen(timeout=)` 兼容性 bug、0.0.0.0 绑定安全提示、OpenCV/pyaudio 缺系统库。

**洞鉴评估**：

| 评估项 | 结论 |
|---|---|
| 对长稳窗验证的价值 | **高，但非紧迫**——超算验证的是"极端降级环境容错"，本地长稳窗已覆盖常规稳态；超算的独有价值是 DCU/无密钥/无 Cython 三降级叠加态，这是本地无法复现的 |
| CPU 共享队列 vs 授权 DCU 组 | 决策依据 = **验证目标**：若目标是"降级容错链路验证"，CPU 共享队列已足够（Notebook 已证）；若目标是"性能上限曲线/Cython 真实性能"，则需 DCU 组——但当前 Cython 编译链断，DCU 也无性能收益，**CPU 队列性价比更高** |
| 插入主线时机 | **建议 184 批后并行插入，不阻塞主线**——理由：①核心债 180-182 正在清，超算重跑不依赖也不阻塞；②镜像路线需小林装 Docker+领普惠包（200 卡时），属外部依赖驱动，不可控；③CPU 共享队列可先用一键脚本快速跑一次降级容错复测，成本低 |

**优先级建议**：**P2，184 批后并行**（不占主线批刀位，由小林窗口驱动）。前置条件：①Cython Linux 编译分支小票先落（T-Cython Linux编译分支-1，在册）；②Ollama Popen timeout 小 bug 修。镜像 v2 重跑可拆为"环境复测（CPU 队列，1 次窗口）→ 镜像固化（DCU 组，待预算）"两段。

**优先级**：**中（建设期第二梯队）**——理由：底层实装度不错，但需先做"消费点审计"再决定深化方向，避免建在无消费的地基上（这正是路线图反复警告的"装饰性指标"陷阱）。

**建设路径**：

2. **185+**：品格代码化均衡化——对实现度低的品格要素（如坚韧）补充工程落点；引入"人格漂移检测"（人格一致性 < 阈值时告警）。

### 2.4 自我修改代码权限

**现状取证**：
- 当前已有"自主进化"能力（SafeEvolutionExecutor 子进程 mode=review/repair），但代码补丁需人工审批（PatchManager 免签闸门，洞鉴 173 报告证"待审积压 1→25 零应用"）。
- 路线图不可逆清单明确：❌ 自动修改人格内核、❌ 自动修改核心配置、❌ 自动应用未经验证的补丁、❌ 自动执行系统命令。

**可行性**：**低（当前阶段不可行）**——安全边界不具备：①补丁验证空转刚修复（P0-2），修复率仍低；②自我修改代码权限的本质是"让框架自主改自己的代码"，在评估闭环未闭环、人格稳定性未达标前，风险极高；③不可逆清单已把"自动应用未经验证的补丁"列为红线。

**建设路径**（远期）：
1. **前置条件**（必须全部满足）：①评估闭环闭环（认知反思驱动决策）；②补丁验证有效率 >80%；③人格一致性 >90%；④有完整的回滚机制（已部分具备，KEEP=2 kill-9 已验证）。
2. **185+ 可做的安全步**：扩大"自动应用"范围仅限**非核心文件**（如配置参数、知识节点），核心代码仍需人工审批；引入"修改影响半径"分析（改这个文件会影响哪些器官）。
3. **远期（PHASE19+）**：在 LFI≥80、修复率>80% 的前提下，逐步开放核心代码的自主修改，但保留人工一票否决。

**优先级**：**最低（远期，不进 182-185 排期）**——理由：安全边界不具备，且路线图不可逆清单已明确划定红线；当前阶段应强化"补丁验证+人工审批"而非放权。建议作为长期方向保留，不立近期票。

**可行性**：**中**，但需先明确"跨窗口"的定义。

3. **若为跨设备/用户**：远期，涉及隐私合规，需先有社会层（用户画像/信任）基础。

**优先级**：**待定（依赖裁定）**——先提请小林明确定义，再决定优先级。当前不建议盲目立票。
