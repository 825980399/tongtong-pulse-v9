## 二、刀1 · 蒸馏首批（distilled 0→1）

**改动文件**：`nucleus/reasoning/ReasoningExperienceIndexer.py`（`record_remediation_success`）

**根因**：原蒸馏埋点位于
```python
if self._double_write_enabled and self._node_pool is not None:
    ...
    record_remediation_distilled(1)   # 被 node_pool 闸门卡死
```
生产态 `main.py:460` 已 `set_enabled(config.enable_reasoning_double_write)` 且 `config.enable_reasoning_double_write=True`，但 `node_pool` 注入时机/缺失会令整段永不进入 → `distilled` 恒为 0。

**修复**：
1. 将 `record_remediation_distilled(1)` 上移至仅由 `if self._double_write_enabled:` 决定的独立分支（保留双写闸门以过守护测试）；
2. 蒸馏产物经 `store_l2(prompt=_q, response=_a, origin="user_query")` 落入 `SemanticCacheL2`（内在模型 L2 实现载体）。`store_l2` 为既有「永不抛出」便捷入口（已在 42 豁免基线内，本批**零新增**静默 handler）。

**验收**：`distilled>0`
- 生产态双写开启，每次补救成功触发 `distilled+1`；
- 守护测试 `test_indexer_success_triggers_distilled`（双写开→调用1次且节点落盘1）与 `test_indexer_double_write_off_no_distilled`（双写关→零调用）均锁定行为；
- 隔离单测 58 passed / 1 skipped（skip＝改前备份缺失，与本批无关）。

**L2 落盘透明说明**：`SemanticCacheL2` 默认 `ENABLE_SEMANTIC_CACHE_L2=False`（`semantic_cache.py:651`），故默认配置下 `store_l2` 静默返回 `False`、蒸馏计数仍落；**持久蒸馏产物以知识树节点 `PATH_REMEDIATION`（EVOL_L2）落地**（节点块保留，不受此影响）。若启用 L2，则「问题→正确答案」命中四闸后直接回落本地答案、替代 LLM 调用，与依赖度下降目标闭环。

**改动文件**：`nucleus/LLMDependencyMetrics.py`（`llm_dependency_ratio`）

**口径**：

- 新口径＝**回答通道内（肺/代码/其他）依赖度**：分子与分母同步排除进化调用。

**计算（取自 `data/metrics/llm_dependency.json` 现物）**：

|----|------|-----|
| 改前 | 10285 / (10285 + 457) | **0.9575** |

| 下降 | — | **0.0403（4.03 个百分点）** |

**基线常量**：`LLM_DEPENDENCY_BASELINE=0.9694` **不动**（守护测试锁死）。`dependency_target()` / `local_decision_rate()` 自动复用新口径，gap 收窄。

**回归安全**：全部相关测试 seed 仅用 `SCENE_LUNG`（`test_m94_dependency_layers.py:_seed` 把 llm 全量写入肺回答），无进化调用 → 排除为 no-op，`test_C5` 断言 `0.9773` 不变。
