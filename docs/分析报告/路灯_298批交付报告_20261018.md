## 三、三刀改动明细

### 刀1 · 入队口形态校验（`nucleus/reasoning/PatchManager.py::save_pending_patch`）
- 在 280刀1 def 对齐断言后，新增形态判据：`original_code` 无 def 且 `modified_code` 有 def（=「片段→完整」，复用 `_m280_extract_def_name` 同源）→ 拒绝入队（`return`），`_shape_rejected_count += 1`。
- 源头拦比派单侧过滤更彻底：坏补丁根本不入 pending 队列。

### 刀2 · 入队被拦计数哨兵（PatchManager + daily_reader + DailyScheduler）
- **三个类属性计数器**（`class PatchManager` 下，内存态跨实例共享）：
  - `_shape_rejected_count`（入队形态拒绝数）
  - `_enqueue_count`（入队数，`save_pending_patch` 成功 append 处 +1）
  - `_m92_rejected_count`（M92 守卫拒绝数，`_verify_in_copy` 两处 stage=base_indent_guard_failed / ast_structure_guard_failed +1）
- **日报四数**：`daily_reader.append_queue_stats_section` 输出「新补丁=NN｜入队被拦=MM｜M92拒绝=KK｜pending=PP」，挂 `DailyScheduler.run_once`。
- 读法（任务书）：MM/KK>0 且 PP=0 ⇒ 治好了；NN=0 ⇒ 停一停；NN>0 且 MM=0 且 PP>0 ⇒ 校验没在工作。

### 刀3 · is_fragment_to_full 设为 select 永久排除（`nucleus/evolution/patch_execution_dispatch.py`）
- `select_patch_for_execution` 的 `is_fragment_to_full` 过滤**本为永久排除**（295批已实现），本批补注释强调「非首批边界、即使放宽到 approved 也绝不派单」，防「放宽到 approved」时真执行 2 条 problem_fixed=True 的结构损坏补丁。
