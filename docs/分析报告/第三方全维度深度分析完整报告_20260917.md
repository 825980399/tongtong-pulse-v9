## 四、核心子系统深度分析

### 4.1 InfoField 事件总线（nucleus/field，2664 行）——全项目最硬核的部分

`publish`→TTL 校验→业务指纹幂等→风暴检测→负载自适应→持锁写历史→条件匹配→四层线程池分发，每步有锁等待埋点。**亮点确属业界级**：L0 看门狗在重建池前用 `sys._current_frames()` dump 卡死线程栈、看门狗自身被 try 包住防止「最后防线先死」；`_resize_layer_pool` 用 cancel_futures 精确递减替代 clear() 暴力归零；背压 docstring 明确解释为何不用阻塞式有界队列（会堵死 L0 生命线）。注释里保存了完整事故链，可审计性是一流水平。

**实测硬缺陷（今日逐行复验）**：

1. 提交侧 `_inflight_dispatch_count +=1` 有锁（:712），完成侧 `-=1` **无锁**（:898）——读-改-写三步竞态，而该值是唯一队列深度指标来源，**队列指标本身可能长期漂移**。
2. 私有 API 依赖：`pool._work_queue.qsize()`（:1648）直取 CPython 内部队列；`reload_l2_config` 改 `_pool._max_workers`（:1712）在池已启动后是空操作——**L2 并发热重载实际无效**。
3. **「五维共振」名不副实**（今日复验）：`_match_condition` 仅判 min_priority + event_types；`space_paths`/`intent_labels` 全库零消费，标准注册路径根本不传这两个参数——宣称五维，实现 1.5 维。
4. `OscillonField.py:471` 路线图宣称「InfoField（继承 OscillonField）✅已实现」，实际 InfoField 继承 SilentLogMixin（:122），`propagate_oscillon` 直接 `return {}`——**代码里的自我文档失实**。
5. publish 历史环形缓冲逐条保留完整 payload 拷贝（maxlen=1000），LLM 级载荷下是隐性内存驻留；去重指纹异常时静默退回唯一 pulse_id（永不命中），无「指纹失效」告警。

### 4.2 mnemosyne 记忆子系统（13 文件 / 11574 行）——方向对、执行欠账多

- **「增量保存」名不副实**（今日亲验 :545-631）：整读 479MB JSON→内存合并→整体重写，省的是序列化不省 IO；真增量 jsonl 方案已写但**未生效**（`snapshot_incremental.jsonl` 实测不存在）。
- **Parquet 主存储真实落地**（今日亲验日志）：23:32 完成冷存 compaction，158MB→1 个文件；压缩比 28:1 有实测证据。但 `SNAPSHOT_SAVE_JSON_BACKUP=True` 使 479MB JSON 双写仍在，00:45–00:50 一轮保存 4 次 ×~2 分钟 IO 风暴。
- **快照膨胀主因**（子代理流式实测，主线程认可口径）：`semantic_relations` 占 **428MB/89.6%**，平均 184 条关系/节点、最大 1921 条、864 节点≥1000 条；`linked_nodes` 与关系 target 集合 Jaccard 0.932——同一邻接关系存两遍；`add_semantic_relation` 无度数上限、去重线性扫描。
- **冷热分离实测为功能空转**（本报告的独立结论，修正文档口径）：加载时全部 12295 节点按热层处理，日志「热层 12295/惰性 0」；`_m70_lazy_ids` 全库只写不读、补全回路不存在；幸好分级判定有缺陷（`_determine_pool` 按 dict 的 evol_level 键恒默认 L1），L2/L3 内容才未被真正清空——**磁盘快照 12295 节点 value 全部完好**（主线程流式验证）。结论：**数据无损，但该特性 0% 生效且日志口径失真**。
- `conflict_count` 不进 to_dict/from_dict（今日复验，代码注释自认「集成待肝脏」）→ `should_downgrade_l3` 需 conflict_count≥3 永不满足，**宪法「L3 冲突降级」通道形同虚设**；`upgrade_to_L2` 用字符串 `min()` 提升重要度，**S 级走此路径会被静默降为 A**（PulseNode.py:194）。
- **锁粒度全项目最粗**：PulseNodePool 一把非重入锁 31 处持有，范围覆盖 pyarrow 读写盘、Neo4j/Influx 网络调用、O(N²) 容量淘汰——与 InfoField 主链路共争同一池。

## 十一、版本控制与可回滚性：本报告的 P0 级发现

今日实测 `git status` 报 `fatal: not a git repository`——`.git` 目录缺 `refs/` 与 `packed-refs`（HEAD/logs 仍在）。项目自述 v1.0→v9.5 的全部 git 历史**事实上不可寻址**，「回滚能力」名存实亡；现存证据链里已有 `.git.recovery.bak`，说明损坏此前已发生并被搁置。当前的实际回滚手段是 12 个 .bak_batch* 目录 + .release-tmp + backups/ 共 ~400MB 手抄本——无提交语义、无差异可查、无原子性。**一个把「可回滚」写进宪法的项目，自己的主干仓库是坏的。** 此项应为全项目第一优先修复（方案见十二章）。

## 十四、结论
