## 二、为什么 tracemalloc 归因还拿不到（本刀最大阻塞）

票面要求「用 tracemalloc 跑 24h，抓 top20 长命对象」。实测**做不到**，三层原因：

### 1. 槽位限制：tracemalloc 只在 05 / 13 点采

```python
_M339_PROBE_HOURS = (5, 13)
if _in_slot and _last != _slot:
    _mode = "tracemalloc+gc_objects" if _heap_hi else "tracemalloc"
elif _heap_hi and _last_gc != _slot:
    _mode = "gc_objects"          # ← 现在 08 点走的就是这条
```

109 份产物的 mode 分布：**gc_objects 92 / tracemalloc+gc_objects 17**。
现在 08:48，下一次 tracemalloc 采样要等 **13:00**。

### 2. 绝大多数产物来自子进程，而子进程 `tracemalloc_is_tracing=False`

今日 10 份产物的 proc_gen 与 tracing：

| proc_gen | heap_mb | tm_tracing | 身份 |
|---|---|---|---|
| pid22392 | 6837.3 / 7573.8 | **True** | 主进程 |
| pid7360 | 19917.2 / 9917.1 | False | 自主迭代子进程 |
| pid16272 | 9917.2 ×2 | False | 自主迭代子进程 |
| pid11484 | 9917.2 ×2 / 19905.6 / 9905.5 | False | 自主迭代子进程 |

主进程 tracing=True，但它不在槽位 ⇒ 不产 tracemalloc 行；
子进程在槽位时 tracing=False ⇒ 也产不出。**两条路都堵着。**

### 3. 历史 17 份 tracemalloc 产物同样全空

`top_types_20261023/26/28` 的 tracemalloc 模式产物：
`tracemalloc_rows_state=None`、`is_tracing=False`、`rows=0`、`top20_source=None`
⇒ 与记忆里「window 模式 start→snap→stop 同调用内 ⇒ 恒空采」是同一个坑。

## 三、四大嫌疑对账（票面点名的四个）

| 嫌疑 | 实测 | 判定 |
|---|---|---|
| **知识库快照** | `pulse_knowledge_snapshot.json` **722.5MB** ＋ `.20261029_075312.bak` **723.5MB** = 1446.0MB | ★**头号嫌疑**：见下 |
| 脉冲对 pulse_pairs | 16 个文件共 **1164.6MB**（今日 45.3MB、昨日 183.2MB） | 主要是磁盘；内存里是否驻留待查 |
| EventBus 队列 | L3 硬上限 **300 条**（条目数，不是字节） | 有界，不是无界泄漏源 |
| 器官缓存 | 待查（本轮未取到进程内口径） | — |

### 知识库快照为什么是头号嫌疑

**每个自主迭代子进程一启动 heap 就 ≈ 9917MB（9.9GB）**，而它的
`image_mb` 只有 **82.8MB**（模块镜像很小）⇒ 那 9.9GB 几乎全是**数据**，
不是代码。而子进程生命周期只有约 5 秒（07:20:12 启动 → 07:20:17 完成），
**它没时间累积任何东西** —— 这 9.9GB 是**启动即加载**的，唯一的大件就是
722MB 的知识库快照（JSON → Python 对象展开约 14 倍）。

推论：**任何需要加载知识库的进程，固定成本 ≈ 10GB**。
主进程 7GB 里的大部分也是它。

### 一个附带异常（待查）

子进程 heap 出现**瞬时翻倍**：pid7360 19917.2 → 9917.1；pid11484 9917.2 → 19905.6 → 9905.5。
翻倍值恰为稳定值的 2 倍，疑为 `_m169_memory_pressure` 在进程启动瞬间
把 mmap 映射页重复计入 RSS（快照是 mmap 加载的）。**属读数问题还是真实峰值，本刀未定论。**

## 四、主进程增长的性质（能说的与不能说的）

**能说**：
- 94.2 MB/分钟的净增长是**实测**（两点取样，7.82 分钟）
- 增长发生在**主进程**，与子进程无关（子进程 5 秒就退出，今日 17 次均如此）

**不能说**（边界，避免误导）：
- 两个采样点只能给**平均速率**，看不出是线性还是阶跃
- **没有** tracemalloc 尺寸行 ⇒ **无法指认**是哪类对象在涨
- 因此本刀**不给出**"泄漏在 X 结构"的结论 —— 那需要 13:00 的 tracemalloc 数据
