## 三、裁定理由（为何选 ③/② 的 294,479，而非脚本直读的 296,830）

1. **对外可复现性优先**：README 的读者是 clone 者。`.aionclaw-tmp` 未被 git 跟踪（仅 `.git/info/exclude:9` 屏蔽），clone 出去**根本不存在该目录** ⇒ 外部人跑 `measure_baseline.py` 得到的必然是 294,479 级，若 README 写 296,830，**外部一跑就对不上**，等于自己制造第二个口径。
2. **不推翻前人定义，只统一时点**：总览 §〇 的"生产口径"本来就是"扣 `.aionclaw-tmp`"，与本裁定同定义；差异纯属时点。故本次裁定实质是把总览 §〇 的数**刷新到 `0306626`**，而非另立口径。
3. **这是 A2 票的第二个危害面**：`.aionclaw-tmp` 泄漏在 161 报告里按 PII 出口（B-2）立项，本条补充——**它同时污染规模口径**（把运行时残留算进工程规模）。修 A2（`export_public.py:62` + `measure_baseline.py:35` + **`nucleus/const.py:19` 点号缺陷**，见 161 复核 §2.2）后，脚本直读值将与 tracked-only 自动一致，届时无需再做"扣减"话术。
4. **口径唯一性纪律**：脚本 docstring `:8` 自述「后续所有报告的规模数字必须引用本脚本输出」。本裁定**不违反**它——仍引脚本，只是附"排除未跟踪运行时目录"的必要条件，并把它写成可执行判据（§五-A5 副产物）。
