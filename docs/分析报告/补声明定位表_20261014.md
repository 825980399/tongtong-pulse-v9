# 补声明定位表（219批·刀2）· 广播度三档制（甲档/乙档/丙档）

> 本表为 218/219 批「补声明落地」的统一定位清单，与 `docs/分析报告/图谱边集预名单_20261014.md`（217批刀1·E_proj 92边对 / 104条去通配边 / 42个(emitter,event)组）配套。
> 落地补声明（emit 调用点加 `target_organ=` kwarg）属自愿声明制下的语义决策，按任务书纪律「只降不升、不硬猜」。

## 头注

- **参数指纹**：数据源＝217 批 `图谱边集预名单_20261014.md`（导出 `tools/export_event_graph.py` v0.5，导出窗 2026-10-14 20:59:29）；本批筛选脚本 `tmp/m219_analyze.py` / `tmp/m219_tiers.py` 复用同次原始导出 `tmp/_m217_export_raw.json`（145 全量边 / wildcard=`PulseBloodVessel`）。
- **导出窗**：2026-10-14 20:59:29（继承 217 批刀1 同一份静态派生，无重导出）。
- **算法（广播度三档制）**：
  1. 从原始 145 边按 `(emitter, event_type)` 聚合订阅者集合（剔除 wildcard `PulseBloodVessel`）→ **42 组**。
  2. **甲档＝订阅者集合恰好 1 个** → **25 组**（1→1 天然边，可安全声明）。
  3. **乙档＝订阅者 2~3 个** → **9 组**（待电后按 matched 高频者定"主响应"再补，220批）。
  4. **丙档＝订阅者 ≥4 个** → **8 组**（高扇出广播，永不补）。
- **⚠ 218 分析脚本缺陷更正（重要）**：218 批 `tmp/m218_true_1to1.py` 误将"剔除 wildcard"实现为按 `emitter==PulseBloodVessel` 过滤（而非 `subscriber==PulseBloodVessel`），导致甲档仅算出 2 条而严重少计；本表按正确口径重算为 **甲档 25 条**。218 实际落地 2 条（恰好落在真甲档子集内，无错补），但"甲档仅2"的结论系误判。219 在重算基础上续补。
- **关键安全约束**：`PulseCore.emit` 的 `target_organ` 是**每条脉冲携带的语义标注（非路由键）**（`nucleus/pulse/PulseCore.py:194` 注释明示）；tracer 按脉冲记录（`utils/pulse_tracer.py:170/:261`）。甲档为 1→1 天然边，单 target 声明**不污染** R_runtime；丙档若强行声明单 target 会把高扇出脉冲全打同一目标，等于"替广播编一个只有他听见了"的假拓扑（211 红线"单 str 禁数组"），故永不补。
- **多调用点边处理**：同一 `(emitter, event)` 若从多处 emit（如 `Liver/growth.need_detected` 有3个调用点），必须**全调用点统一声明**才算完整；219 为守住"≤10点"且不产生部分声明，优先落单调用点甲档边，多调用点甲档边整体递延至后续批次一次性补全。
