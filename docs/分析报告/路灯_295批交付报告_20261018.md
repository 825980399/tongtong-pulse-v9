## 三、五刀改动明细

### 刀1 · M92 两道关翻闸（config.py）

### 刀2 · 派单路径 + 刀3 · 执行结果回写（新建 `nucleus/evolution/patch_execution_dispatch.py` + main.py 挂载）
- **新建派单模块**：
  - `select_patch_for_execution(patch_history, limit=1)`：取 status=runtime_verified 且 risk=低 的补丁（13 条先例），低风险优先、同风险 trust_score 降序，单批上限 1。
  - `dispatch_and_verify(sandbox, patch)`：把 modified_code 经 `sandbox.on_pulse(MotorEvent.EXECUTE)` 路由执行（命中黑名单 + 子进程隔离沙箱，绝不 apply 源码）。
  - `_write_back(patch, verdict)`：回写 runtime_verified（成功 True / 失败 False）+ runtime_verify_result + 失败原因。
  - `dispatch_runtime_verified_patches(limit=1)`：主入口，每日派单 ≤1 条。
  - `register_with_daily_schedule()`：挂 DailyScheduler 每日钩子。
- **main.py 挂载**：装配后 `set_dispatch_framework(self)` 注入 framework + `register_with_daily_schedule()` 注册每日钩子（复用 210 批 lfi 注册模式，不新增静默 handler）。

### 刀4 · 补注册 event_tap → runtime_events（main.py）
- 生产装配处补注册 `event_tap → runtime_events` 分析器（与 36/38 批补注册 call_graph/evolution_health 同款一行装配）。`runtime_events` 已确认在 `_PROFILE_DICT_FIELDS`（SelfAwarenessEngine.py:53）。

### 刀5 · 派单前形态回扫（派单模块内）
- 新增 `_extract_def_name(code)`（与 `PatchManager._m280_extract_def_name` 同源正则）+ `is_fragment_to_full(patch)`（original 无 def 且 modified 有 def → 「片段→完整」→ 可疑）。
- `select_patch_for_execution` 先跑形态判据，过滤「片段→完整」可疑补丁。
- `dispatch_runtime_verified_patches` 派单前对全部 runtime_verified 低风险补丁回扫，标记 `_295_suspect_morphology=True`，可疑不派单。
