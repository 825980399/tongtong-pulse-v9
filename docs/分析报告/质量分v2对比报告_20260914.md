## 二、v2 体系设计

### 2.1 五维度（★全部来自可量化运行数据）

| 维度 | 权重 | 公式 | 数据源 |
|---|---|---|---|
| `module_effectiveness` | **0.30** | `50×报告消费率 + 50×补丁真实修复率` | ReportBus 统计 / `patch_history` 主动复现 |
| `issue_severity` | **0.25** | `max(0, 100 − (P0×10 + P1×4 + P2×1))` | 债务清单中含 🔴 的表格行 |
| `test_coverage` | **0.20** | `器官测试覆盖率 × 100` | `organs/**.py` vs `tests/**.py` |
| `static_health` | **0.15** | `max(0, 100 − ruffF×5)` | `ruff --select F` |
| `data_integrity` | **0.10** | `100 × (1 − 0.5×污染率) × 标记完整度` | `data/experience/experience_pool.json` |

### 2.2 四条设计原则

1. **只认有效性** —— 不再有「有模块就给分」，无有效性数据的模块**不得计分**；
2. **可证伪** —— 每维度输出 `score` + `formula` + `data_source` + `raw`（原始值）；
3. **不惩罚「不知道」** —— 数据不可用 → `score=None`，**不参与**加权（不当作 0）；
4. **权重按重要性** —— 不再是等权（有效性 0.30 / 严重度 0.25 / 覆盖率 0.20）.

## 四、★新发现（本批顺带定位的真实缺陷）

### ReportBus 落盘报告**丢失消费状态**

**证据**：磁盘 137 份报告，`consumed_by` **全部为空**（消费率 0.0000）。

**根因**（`report_bus.py::publish`）：

```python
_persisted = self._write(envelope)      # ← 落盘时 consumed_by 还是空的
self._trim()
self._prune_disk()
if dispatch:
    ... 消费者返回真值 → envelope.consumed_by.append(...)   # ← 消费标记在落盘之后
```

⇒ **落盘的报告永远不含消费标记** → 重启后 `load_from_disk()` 恢复的报告
全部显示"未消费" → **消费率统计失真**。

**影响**：v2 的 `module_effectiveness` 中消费率子项恒为 0（本批实测值）。
**处置**：**不在本批修改**（涉及 publish 时序语义变更，风险中）→ 登记为 **P2-366**。
