## 二、根因分类

### 类型 A：测试期望漂移（config 被前置批有意翻 True，测试未同步）—— 例 1/2/3（m71×3）

- `config.py:5218` `ENABLE_INFLUXDB_TIMESERIES = True`（注释：★第173批刀0 窗前定值：开启，长稳窗采集 process_rss_mb 时序）
- `config.py:5249` `ENABLE_INFLUXDB_WRITE_ONLY = True`（注释：★第173批刀0 窗前定值：开启）
- `config.py:5250` `ENABLE_INFLUXDB_AUTO_CONNECT = False`（★第174批刀1 接线灰度，默认关）
- 三个 m71 断言写于 173 批之前，要求这些键为 False；173 批刀0 按长稳窗取证需要**有意**将其翻 True（属设计决策，非脏状态、非回归）。
- `pool._m71_influx_enabled()`（例 3）内部即读 `ENABLE_INFLUXDB_WRITE_ONLY`/`TIMESERIES`，因此随 config 翻 True 一并变 True，根因同源。
- **判定**：测试断言已与现行配置契约不符，属**测试期望漂移**，不是代码 bug。

### 类型 B：代码/契约自相矛盾（实现返回值与自身文档/测试不一致）—— 例 4（m85×1）

- 落点：`nucleus/evolution/patch_verification_split.py:293` `real_fix_rate(patches)`
- 关键行：`:320` `return round(_ok / _known, 4) if _known else None`
- 自身契约：`:318-319` 注释明确「**无可判定样本时返回 0.0**（不返回 0/0 的 NaN，也不虚报满分）」
- 测试 `test_32_all_none_is_zero_not_crash`（:348）正是按该契约断言返回 `0.0`。
- 实际：输入 5 条全 `problem_fixed=None` 的补丁 → 循环内 `_known` 始终为 0 → 落到 `if _known else None` 返回 **None**，与自身注释及测试期望矛盾。
- **判定**：**代码漂移 / 契约自相矛盾**——实现返回值偏离其声明契约（应返回 0.0 却返回 None）。这是真实缺陷，但属「测试已先行固化契约、实现未达标」，本刀不修，报星轨裁决：要么把 `:320` 改为 `... else 0.0`（贴合契约与测试），要么若 None 是有意 sentinel 则同步改注释+测试。
