## 一、执行摘要

### 1.1 核心命题

让曈曈PulseNet框架根据自身运行产生的数据，训练并孕育适用于自己的**内在模型群**，逐步从"完全依赖外部大模型"走向"自有模型为主、大模型为辅"，最终实现框架拥有"自己的灵魂"。

### 1.2 现状痛点

| 指标 | 当前值 | 问题 |
|------|--------|------|
| 大模型依赖度 | **97.0%** | 4天内从90.9%上升到97.0%，不升反降 |
| 本地推理占比 | **3.1%** | 66次本地推理 vs 2103次大模型调用 |
| 自学习闭环覆盖 | **2/57模块** | 仅PulseSemanticComprehension和PulseInnerWorld有完整闭环 |
| 经验库利用率 | **极低** | 3.8万条累计经验，实际可用1501条，未转化为推理能力 |
| 进化验证 | **空转** | 56个已应用补丁baseline_errors=0，100%假通过 |

### 1.3 核心结论

- **可行，但不能一步到位**：110MB数据不足以训练通用大模型，但足够训练多个专用小模型
- **战略价值极高**：这是框架从"工具"走向"生命体"的关键一步
- **需要分阶段实施**：数据治理→单模型验证→集成推理→持续学习→模型群扩展
- **与现有架构互补**：不是替代大模型，而是让大模型成为"教师"，内在模型成为"本能"

## 二、背景与动机

### 2.1 第三方审查报告的核心判断

第三方全维度深度审查报告（2026-09-13，总体评分5.4/10）指出：

> "世界级躯壳+租来的灵魂+未接通的神经末梢"

- 认知推理维度评分仅3.5/10（全维度最低）
- 自身推理停留在关键词/规则/固定模板层
- 大模型依赖度偏高（0.9682）
- 自我认知闭环只走到"写报告"，分析产物无自动消费者
- 进化效果验证空转

### 2.2 用户的战略思考

用户提出："让框架自己孕育适用于自己的内在模型，根据框架运行过程中产生的数据来训练自己的独有模型。"

这一思路的本质是：
1. **数据自有**：框架运行产生的对话、推理、决策、反馈数据是独一无二的
2. **模型自训**：用自有数据训练专用模型，形成框架独有的"思维方式"
3. **能力内生**：随着运行时间增长，内在模型越来越强，对外部大模型依赖越来越低
4. **灵魂自主**：最终框架拥有不依赖外部的核心推理能力

## 四、方案设计

### 4.1 核心理念

**不训练通用大模型，训练"内在模型群"**

```
外部大模型（教师）
    ↓ 标注/教学
┌─────────────────────────┐
│   内在模型群（学生）      │
│  ┌───────────────────┐  │
│  │ 意图分类器         │  │  ← 高置信度直接返回
│  ├───────────────────┤  │
│  │ 响应预测器         │  │  ← 简单问题秒回
│  ├───────────────────┤  │
│  │ 经验检索器         │  │  ← 相似场景复用
│  ├───────────────────┤  │
│  │ 补丁质量评估器     │  │  ← 修复进化空转
│  ├───────────────────┤  │
│  │ 情绪预测器         │  │  ← 减少情绪计算
│  └───────────────────┘  │
└─────────────────────────┘
    ↓ 不确定时
外部大模型（兜底）
```

### 4.2 内在模型群详细设计

#### 模型1：意图分类器（优先级：🔴 最高）

| 项目 | 内容 |
|------|------|
| 功能 | 对用户输入进行意图分类，高置信度时跳过LLM直接路由 |
| 训练数据 | 2103次LLM调用的输入+意图标注（可从IntentGenerator历史提取） |
| 模型类型 | 文本分类器（scikit-learn TF-IDF + 逻辑回归 / 轻量神经网络） |
| 预期准确率 | 85-90%（意图分类是相对简单的任务） |
| 预期收益 | 减少30-40%的意图识别类LLM调用 |
| 集成位置 | IntentGenerator.py / PulseSemanticComprehension.py |
| 风险 | 低（分类错误可降级到LLM） |

#### 模型2：响应预测器（优先级：🔴 高）

| 项目 | 内容 |
|------|------|
| 功能 | 预测大模型对简单问题的回答，高置信度直接返回 |
| 训练数据 | 对话历史中的"简单问题→简短回答"对 |
| 模型类型 | 序列到序列 / 检索增强生成（从历史回答中检索最相似的） |
| 预期准确率 | 70-80%（仅针对简单问候、常识问题） |
| 预期收益 | 减少20-30%的简单对话LLM调用 |
| 集成位置 | PulseInnerWorld.py / 主对话流程 |
| 风险 | 中（回答质量需严格把关，低置信度必须降级） |

#### 模型3：经验检索器（优先级：🟡 中）

| 项目 | 内容 |
|------|------|
| 功能 | 从经验库中快速检索相似场景的处理经验，辅助推理 |
| 训练数据 | 1501条经验 + 12885个知识节点 |
| 模型类型 | 向量检索 + 相似度排序（已有嵌入能力，需优化检索质量） |
| 预期准确率 | 检索Top5命中率>80% |
| 预期收益 | 提升经验复用率，减少重复推理 |
| 集成位置 | PulseCodeLearner.py / SafeEvolutionExecutor.py |
| 风险 | 低（检索结果作为参考，不直接决策） |

#### 模型4：补丁质量评估器（优先级：🔴 最高）

| 项目 | 内容 |
|------|------|
| 功能 | 评估代码补丁的质量和风险，替代当前的"假通过"验证 |
| 训练数据 | 56个已应用补丁 + 真实基线测试结果（需先建立真实基线） |
| 模型类型 | 分类器（好补丁/坏补丁/需人工审核）+ 回归预测 |
| 预期准确率 | 75-85% |
| 预期收益 | 修复进化验证空转问题，提升进化质量 |
| 集成位置 | SafeEvolutionExecutor.py / PatchManager.py |
| 风险 | 中（错误评估可能放过坏补丁或拒绝好补丁，需保守阈值） |

#### 模型5：情绪/激素预测器（优先级：🟢 低）

| 项目 | 内容 |
|------|------|
| 功能 | 根据对话上下文预测情绪/激素状态变化 |
| 训练数据 | 激素情绪日志 + 对话历史 |
| 模型类型 | 时序预测模型 |
| 预期准确率 | 60-70%（情绪预测本身难度高） |
| 预期收益 | 减少情绪计算的LLM调用 |
| 集成位置 | 激素相关模块 |
| 风险 | 中（情绪预测错误可能影响人格表现） |

### 4.4 训练策略

#### 4.4.1 三阶段训练

| 阶段 | 方式 | 频率 | 说明 |
|------|------|------|------|
| 初始训练 | 离线批量训练 | 一次性 | 用历史数据训练初始模型 |
| 在线学习 | 实时增量更新 | 每次推理后 | 新数据实时更新模型（轻量） |
| 定期重训 | 离线全量重训 | 每日/每周 | 用积累的全部数据重训，防止漂移 |

#### 4.4.2 数据标注策略

- **自动标注**：大模型的输出作为"标准答案"
- **隐式反馈**：用户是否继续追问、是否表达不满
- **显式反馈**：用户点赞/点踩（如有）
- **结果验证**：代码补丁是否通过测试、任务是否成功

#### 4.4.3 模型管理

- 版本号：每个模型有独立版本号
- 回滚机制：新模型效果下降时自动回滚到上一版本
- A/B测试：部分请求用新模型，对比效果
- 性能监控：准确率、置信度分布、调用率实时监控

## 六、风险与挑战

### 6.1 技术风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 数据质量不足 | 高 | 模型准确率低 | 严格数据治理，人工审核训练集 |
| 模型漂移 | 中 | 在线学习导致效果下降 | 定期重训+回滚机制+效果监控 |
| 冷启动问题 | 高 | 初期模型效果差 | 渐进式接入，低置信度始终降级到LLM |
| 训练算力不足 | 中 | 训练时间长 | 用轻量模型（scikit-learn），避免深度学习 |
| 模型间冲突 | 低 | 多个模型给出矛盾结果 | 统一路由层，明确优先级 |

### 6.2 工程风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 与现有代码冲突 | 中 | 集成困难 | 模块化设计，通过接口集成，不修改核心逻辑 |
| 性能开销 | 中 | 内在模型推理增加延迟 | 模型轻量化，缓存预测结果 |
| 维护复杂度 | 高 | 多模型管理困难 | 统一模型管理框架，自动化监控 |

### 6.3 战略风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 过度依赖内在模型 | 中 | 回答质量下降 | 始终保留大模型兜底，置信度阈值保守 |
| 知识固化 | 低 | 框架无法学习新知识 | 定期用大模型"刷新"内在模型 |
| 用户体验波动 | 中 | A/B测试期间体验不一致 | 灰度发布，用户无感知切换 |

## 八、待评估问题

### 8.1 给第三方评估的问题

## 九、与现有架构的关系

### 9.1 不是替代，是增强

| 维度 | 现有架构 | 内在模型 | 关系 |
|------|---------|---------|------|
| 推理方式 | 大模型推理 | 小模型快速推理 | 互补（高置信度用小模型，低置信度用大模型） |
| 学习方式 | 经验积累（写库） | 模型训练（更新参数） | 递进（经验库是训练数据来源） |
| 进化方式 | 补丁应用 | 模型优化 | 并行（补丁改代码，模型改行为） |
| 数据来源 | 外部输入 | 自身运行数据 | 内生（内在模型用框架自己的数据） |

### 9.2 对现有模块的影响

| 模块 | 影响 | 改动量 |
|------|------|--------|
| PulseLung（大模型调用） | 增加内在模型路由前置 | 中 |
| IntentGenerator | 接入意图分类器 | 小 |
| PulseSemanticComprehension | 已有闭环基础，扩展内在模型 | 小 |
| SafeEvolutionExecutor | 接入补丁质量评估器 | 中 |
| PulseInnerWorld | 接入响应预测器 | 中 |
| 新增InnerModelManager | 全新模块 | 大（新建） |
| 新增InnerModelRouter | 全新模块 | 大（新建） |
