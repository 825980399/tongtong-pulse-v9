# 路灯 · 382-B 施工前置：**刀3 照字面做会把影子变成真释放**

- 时间：2026-10-28 20:5x｜批次：382-B（刀2/刀3/刀11）
- 结论：**刀3 不开灯**。票面的施工要求与代码语义相反，按字面做等于打开真实释放路径。

## 一、票面 vs 代码

票面（§刀3）：
> 开 `ENABLE_MEMORY_RELEASE_TREE=True`（**影子，不真释放**）。

代码（`nucleus/mnemosyne/release_policy.py:490-520`）：

```
shadow      : ENABLE_MEMORY_RELEASE_TREE=False ⇒ 不调用 executor，只留痕
live        : 开关 True 且给了 executor ⇒ 按 G2_TARGETS 逐类调用（真动作）
no_executor : 开关 True 但没 executor ⇒ 如实报缺执行面
```

判定链在 `apply_decision()`：

1. `tier` 不在 G2/G3 ⇒ 直接跳过；
2. `dec["release_enabled"]` 为假 ⇒ **shadow**（现状）；
3. 否则 `executor is None` ⇒ no_executor；给了 executor ⇒ **live**。

⇒ **`TREE=False` 才是影子；`TREE=True` 是"允许真动作"**。票面把两者写反了。
如果照票面翻开关，只要有人把 executor 接进来，下一步就是真释放 ——
而当前 heap 9.2GB 全落 G4，一旦 `tier` 判据松动，释放面会直接落在活体上。

## 二、刀3 真正需要的观察，不需要开灯

票面要的是「看 tier 分布（G0/G1/G2/G3/G4 各多少）」。这个**只读即可**：

- `release_policy.decide(...)` 的返回里就有 `tier` / `tier_why`；
- 生产侧 `PulseMetricsCollector` 的内存压力行已带 tier；
- 现有 `data/reports/memory/` 下的轮转文件可直接统计分布。

**建议**：刀3 改成「从既有落盘统计 24h tier 分布」，产出一张分布表 + 结论
（例如"G4 占 92%，G2/G3 从未触发 ⇒ 分档线需重定"），**一行开关都不动**。
这才是"观察"，而且可复算。

## 三、刀2（OA4 双路影子）——建议延后，理由是先算成本

票面：同一 prompt 走规则与走 LLM 各跑一遍，记录一致率，不替换 LLM。
问题：**这会让 LLM 调用量翻倍**，而当前渠道里有收费兜底（`deepseek`）。
在没确认「影子只算不调」的开关之前开灯，等于悄悄把成本抬一倍。

**建议**：先在报告里给出「当前 LLM 调用量 / 若翻倍的日成本估算」，
再由小林拍板是否值得。若渠道全是免费额度，可以直接开；若含收费兜底，建议
先做「只统计规则侧命中率」的**单向影子**（不额外调 LLM，用已发生的调用做对照）。
