## 一、审查对象与方法

**协作体系的实测构成**（不是设计图，是跑出来的样子）：

```
小林 ── 唯一拍板人 / 框架资源所有者（启停由人手工执行）
  ├─ 星轨  派任务书 · 做裁决 · 记总账（prose 账本）· 写登记册 CSV（机读账本）
  ├─ 路灯  唯一施工者（写码 + commit，11 笔未 push 等批末统一推）· 维护 tools/ci/*
  ├─ 烛微  只读前置分析 · 码级结构审计（AST 链）· 门禁工具化建议
  └─ 微光  只读活体窗观测 · 行为面裁决 · 快扫交叉验证
工件流：任务书 → 分析报告 → 任务书/总账引用 → 施工 commit → 交付报告 → 验收 → 登记册结案
```

**取数手段**（每条结论都能复算，脚本 `tmp/collab_evidence_158/collab_facts.py`，结果 `collab_facts.json`）：
1. `git log --diff-filter=A` 统计**首次入库**——剔除批量补录造成的 mtime/挪动假象；
2. `git log -S<票号>` 定位票号进入某账本的**确切提交**——用于两套账滞后测量；
3. 登记册 CSV 结构化解析（9 列 × 94 行，含 `提出方` 署名列）；
4. 总账全文计数（角色提及、按文件名引用、整段抄录段落行号）；
5. 门禁实跑 + `Win32_Process` 命令行 + `logs/pulse.log` 时间戳/字节增双证。
