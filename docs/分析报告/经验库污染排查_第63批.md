## 二、止血措施有效性验证（代码层面）

第47批"止血"由两类逻辑构成：

1. **写入时标记**（`nucleus/mnemosyne/experience_pool.py:423-433`）：
   ```python
   if experience.get("polluted") is True:
       experience["polluted"] = True
       experience["cleanup_reason"] = _cls   # 来自 experience_cleanup 分类
   ```
   该分支在经验写入路径上，**存在且在运行**（1026 条标记即为证）。

2. **分类判据**（`nucleus/data/experience_cleanup.py:86`）：
   ```python
   CLASS_WRITE_SIDE = "write_side_boilerplate"  # 写入侧样板短句（元数据式）
   ```
   凡是被判定为"写入侧样板短句"（如压缩摘要"我曾因X而行动，获得了Y奖赏，感受到Z"）
   的经验，统一归入此类并标记 polluted。

3. **批量扫描工具**（`ExperiencePollutionGuard.py` / `DataQualityGuard.py` / `PollutionTagger.py`）：
   负责离线扫描存量库并标记，本次 1026 条即来自此类扫描（batch=56）。

**结论**：止血措施的"标记"环节在运行；但"清理"环节（`is_cleaned=True` 或真正淘汰）
**从未执行**——标记后无任何降污动作，污染率被锁定在高位。

## 三、污染源定位

主要污染源 = **`write_side_boilerplate` 分类覆盖面过宽** + **清理流程缺失**：

- `write_side_boilerplate` 把经验的**压缩摘要/元数据式短句**整体判为"样板污染"。
  这些短句多为经验总结的自然产物（非 SERP 灌水、非占位残留），属**误判**。
- 第56批扫描将该类一次性标记 1026 条（占全库 82.6%），且 `quality_weight` 被置 0.1，
  但 `is_cleaned` 不跟进 → 只降权、不清除。
- 经验读取侧（`experience_retriever.py:186`）默认排除 `polluted=True`，
  意味着 82.6% 的经验**实际不可被检索**——止血"标记"已实质削弱经验库可用性，
  而"清理"缺位使该状态固化。

---

## 四、修复建议（建议开专项批次，不在第63批改动）

1. **收窄 `write_side_boilerplate` 判据**（优先级高）：
   当前把正常压缩摘要误判。应区分"无信息量的真样板"（如固定模板串）与
   "有意义的压缩总结"（含具体动机/奖赏/情绪）。后者不应判污染。
2. **真正实现清理闭环**：
   标记后应有周期性 `is_cleaned=True` 或对确属无价值的样板做淘汰，
   而非只降权不清除（当前 `is_cleaned` 恒 False 是污染率不降的根因）。
3. **重校准污染率告警阈值**：
   若 82.6% 经验因"写入侧样板"被标记，说明判据本身已失真，
   告警阈值（POLLUTION_RATE_WARN）需基于**收窄后**的口径重新设定。
4. **缺口补标**：
   216 条未标记记录（含 207 条已 summarised）应纳入统一标记路径，消除覆盖不全。

**明确 bug 判定**：本批次未修改生产经验库数据（遵守任务书"只读取分析"约束）。
上述"清理缺失 + 分类过宽"属**设计/校准缺陷**，建议专项批次处理，不在第63批顺手改。

---

## 五、小结

- 污染率高位（82.6%）的根因 = 第56批一次性宽口径标记（write_side_boilerplate）+ 清理闭环缺失。
- 止血措施"标记"在运行，"清理"未运行 → 污染只增不减。
- 建议专项批次：收窄分类判据 + 实现清理闭环 + 重校准告警阈值。
