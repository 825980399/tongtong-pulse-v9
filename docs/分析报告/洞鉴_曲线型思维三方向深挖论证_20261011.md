- **"高频访问重置并提升"**：已半存在——[PulseNode.activate()](file:///d:/xinrenlei/tongtong-pulse-v9/nucleus/mnemosyne/PulseNode.py#L217-L222) 每次检索命中重置 `last_activated`、`activation_count+1`，时间维得分随之回到 1.0；且 `dormant→active` 自动复活。

### 1.2 接入点（按改动面从小到大三档）

1. **派生档（不写字段）**：仿时间维现状，检索时从 `last_activated/activation_count` 现算 strength。零快照成本，但每次打分重复计算。
2. **字段档**：PulseNode 增 `memory_strength`，在 [activate()](file:///d:/xinrenlei/tongtong-pulse-v9/nucleus/mnemosyne/PulseNode.py#L217-L222) 内做强化（访问重置+提升）。现成范式是 [sync_hebbian_weight](file:///d:/xinrenlei/tongtong-pulse-v9/nucleus/mnemosyne/PulseNodePool.py#L191-L232) 的 EMA 回写法（可升可降、带开关）；持久化照抄 181 刀4 `episode` 字段范式（`getattr` 向前兼容 + to_dict/from_dict 成对，PulseNode.py:154/376/461）。
3. **联动档**：把 strength 作为 dormant 标记 / 肾遗忘 / 冷存驱逐的**输入信号之一**（现输入是年龄+激活次数+importance），不新增生命周期机制。L3 locked 与 L4 本能节点豁免衰减。

与 compaction 的关系：compaction 是冷存合并（存储动作），strength 是排序/淘汰信号；strength 只影响"谁沉、谁留、谁排前"，不改变 compaction 流程本身。

### 1.3 回归面（有硬约束，不能直接改检索权重）

- **宪法红线**：五维总权重 0.40/0.30/0.15/0.10/0.05 是规则1.3（[config.py:679-685](file:///d:/xinrenlei/tongtong-pulse-v9/config.py#L679-L685)、ResonanceEngine:839 注释明示"修改属修宪"）。强度通道只能走**记忆维内部分配**（α'/β'/γ' 先例，ResonanceEngine:792-849）或关键词通道内部再分配，不动总权重。
- **双实现一致性**：关键词/时间通道均有 Python + Cython（`calc_memory_dim_cy`/`calc_time_dim_cy`）两套实现，注释要求"逐字节一致"（:763、:1133），改公式必须双改且过 parity 测试。
- **下游面**：resonate_topk 被知识检索器 / InnerWorld / QICA 消费，召回序变化直接影响 RAG 回答；污染降权乘数链（suspect×0.7/polluted×0.3，:527-530）须保持。
- **冷存 schema**：字段落盘需同步 Parquet schema（[PulseNodePool.py:2668](file:///d:/xinrenlei/tongtong-pulse-v9/nucleus/mnemosyne/PulseNodePool.py#L2668) 附近 pa field 声明），有新增列成本。

### 1.4 最小可落地步（183-184，全部观测级）

1. 纯函数 `memory_strength(last_activated, count, τ)` 落 nucleus 工具模块，τ 走 config；在共振检索日志中输出**影子排序对比**（现排序 vs 加入 strength 的排序，top10 重合率），不改变返回结果。

### 2.3 风险面（作用域污染是最大风险，有据可查）

`_call_remote_api` 是多路共用通道：对话、双腿 3 路并发搜索（main:1358 注入）、语义理解器、**SafeEvolutionExecutor 补丁生成**（共享渠道选择 machinery，SafeEvolutionExecutor:1149-1208）。若温度按全局时间漂移，补丁生成/意图分类/搜索查询在夜间也会变"发散"。因此：

1. **必须带 scope**：夜间高温只允许 `scope=chat`；补丁生成、SearchIntentClassifier 分类、搜索 query 构造永久豁免（裁定项3）。
2. **渠道兼容**：Ark v3 曾因不支持字段组合直接 400（PulseLung:1087-1093 注释实证），temperature 同样要走白名单裁剪，不能假设全渠道支持。
3. **入库质量链**：温度本身不触文件、不增调用次数；真实风险链是"高温→低质回答/自主联想入库→经验库污染"。该库有污染前科（83.1% 摘要模板化，见《经验库防污染机制_v1.0》），夜间自主链路（梦境/创造→胃消化）无人审核，高温会放大污染。
4. **误改文件**：不直接成立——补丁有 PatchManager 三档审批（risk≤2 且 trust≥40 才自动）与核心文件护栏兜底；但 scope 隔离是前提。
5. 实际生效温度须入 lung trace（现有 llm_trace_fields 断言），否则不可审计。

### 2.4 最小可落地步（183-184）

1. 观测级：心跳输出 `energy/mood_stability/focus → suggested_temperature` 纯函数结果到日志，不进任何请求。
2. 收敛两处硬编码 0.7 为 config 单一来源 `LLM_TEMPERATURE_BASE`（先统一、不动态）。

### 3.2 与共振引擎的关系：复用，不新建

- 现有护栏可复用：`_is_system_busy()` 跳过（:762）、新颖度历史去重、双腿冷却 `_cooldown_until`。

### 3.4 最小可落地步（183-184）

## §4 优先级排序与裁定项
