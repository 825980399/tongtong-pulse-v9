## 二、各刀落点与机理

### 刀1 · 262刀1去毒（最紧急，先于任何验收）
- **病根**（263§0）：血管 v24.0 共振条件 `event_types:["*"]` ⇒ `InfoField._match_condition` 恒 True ⇒ publish 时 `matched_organs` 恒非空 ⇒ `_event_unmatched_count` 恒 0 ⇒ `audit_ghost_listeners` 的 `dead_events` 永远空表，`ghost_listeners` 侧同理——V 窗一开拿到 `dead_events=[]` 被误读成"没有死数据"。
- **修法**（在 `audit_ghost_listeners` 内重算，不动 publish 热路径）：
  - `_cond_is_universal(cond)`：`event_types` 为空或含 `"*"` → 万能。
  - 把 `_conds` 拆成 `_real_conds`（非万能）/`_universal_conds`（万能）两类。
  - `_event_has_real_consumer(et)`：遍历 `_real_conds` 用 `self._match_event` 匹配（静态方法，直接调用）。
  - `dead_events`：`_real_unc = 0 if _has_real else _cnt`（万能命中不算数），`universal_only = (not _has_real and _has_univ)`。
  - `ghost_listeners`：每条加 `universal_only: _cond_is_universal(_cd)`。
- **效果**：去毒后 `dead_events` 不再恒空——无真条件匹配的事件类型（263§0 估全仓 94 个事件类型仅 8 个模式有真条件）将显形为死数据；"只有血管在看"的候选带 `universal_only=True` 单列，而非被算作健康。

### 刀2 · 丙-1判据红线（防永零复发）
- **红线**（写进注释与变量名，防后来者接回 `matched_count`）：
  ```
  real_matched_count > 0            → 平反（当场权威）
  real_matched_count == 0 且 有万能命中 → 不平反，标 universal_only（"只有血管在看"真孤儿候选，价值最高）
  real_matched_count == 0 且 无命中     → 真孤儿候选
  ```
- **实现**：`_detect_orphans` 不再以 `evt.get("matched_organs")` 非空判平反，改为 `_real_matched_count = len([o for o in matched_organs if o not in _UNIVERSAL_ONLY_ORGANS])`；`>0` 才平反。`_UNIVERSAL_ONLY_ORGANS = frozenset({"血管"})` 基于 263§0 实证（血管是唯一 `"*"` 条件器官）。
- **route_matched 分支**：263 任务1 的 InfoField publish 返回体回填（`real_matched_count`/`universal_only`，六处）不在 264 范围，故本批无 `route_matched` 字段——判据自然走"matched_organs 剔除万能 ＋ subscription_provider（已剔除 observer）＋ 白名单"的保守回退路径，与任务书刀2.2 第4条（缺失则退回 matched_organs＋白名单）一致。

### 刀3 · 直调族入白名单
- `pattern_prewarm`/`pattern_prediction` 加入 `_REPORT_ENDPOINT_WHITELIST`，每项注释写明"进程内直调消费，出处260刀3，消费方 `InfoField.py:2637`"，符合 263⑥"白名单不加注释就是回归遮罩"的警示。

### 刀4 · 血管万能条件打observer
- `PulseBloodVessel.get_resonance_conditions` 的 cond dict 加 `"observer": True`，让"万能观测者"显形。本批 `InfoField` 匹配/审计逻辑未读该标记（刀1 已用 `event_types` 含 `"*"` 先行覆盖），故零行为影响，符合"先打标记，再考虑改为显式窄订阅"的语义。
