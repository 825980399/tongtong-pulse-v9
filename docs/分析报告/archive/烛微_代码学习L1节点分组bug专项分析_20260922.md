## 0. 结论一句话链（先给星轨最想知道的答案）

## 3. Task-2 · 分组逻辑走查（`PulseLiver.py:935-956`，18:26 版）

星轨 v19 代码逐行读毕，用事前快照 1525 条**真实路径精确重放**（非估算）：

```python
_parts = _path.rstrip('/').split('/')
if len(_parts) >= 4:  _group_key = '/'.join(_parts[-2:])   # 深路径→后两段
else:                 _group_key = _parts[-1]              # 平路径→末段
```

## 4. Task-3 · 根因定位（任务书五问五答 + 一个新发现的双跑机制）

**Q1 为何积累到 1500+？** 两层：①胃消化通道每次代码自学习产出都新建 L1 挂平路径，**无按"类.方法"幂等 upsert**——实测 1483 条里同标识重复 888 份；②12 天只进不出（created_at 09-11~09-22 每日累积）。此前"总量压缩跳过（保护独立路径）"的旧设计使它们从不参与常规压缩（:905-910 分流），只靠 v18 独立通道，而独立通道一跑就是整组倾覆。

**Q2 为何改了分组还有超大组？** 见 §3：97.2% 的节点路径零分化，任何路径段数法必退化为单组；22 组中 21 组是脏路径噪声。

**Q3 超大组该被压缩吗？** **不该被"这样"压缩，但该被"分类"压缩。** 组内是 134 个类×各自方法的文档集合（值前缀天然给出 `类名.方法名` 两级键），一次压成 1 个 3 句样本 L2 等于丢弃 99.8% 内容。合理终态是每类一个（或每类每 ≤40 条一个）L2。

**Q4 设计初衷？** L1=细粒度情节记忆、L2=语义摘要、压缩=提炼而非销毁；`PulseCodeLearner:1268` 的 `/自我理解/代码/{器官名}` 才是设计形状。胃的平路径硬编码 + L2 落库用相对键，都是对设计的执行走样。

**Q5 阈值合理吗？** 组阈值 8 对"类粒度"是合理的，对"整平路径一组"必然瞬间击穿（1483≫8）。**阈值不是病灶，粒度才是**；但需补"单次压缩组大小上限"（如 40）兜底，防任何粒度失衡时重演一次性雪崩。

**★新发现：5 分钟内的"自产自删"双跑（本次真丢失的直接机制，任务书未预见）**
时间线存证 `gb_incident_timeline.txt`：
1. 19:44:46 重启时 `L1快照恢复 1593`（19:36/19:40 有人工替换 L1 快照文件的痕迹：`.bak_before_restore` ×2——推测为找回 17:18 事故删掉的语料，**复活动作本身是对的**）；
2. 19:45:55 **runA**：`_compress_group('代码',1483)` → 建 L2 后进入 **频率编码分支 `:1419-1449`，`return True` 早退，跳过 `:1500-1515` 的清理段**——所以 19:47:08 的 INFO 说"1组→L2"却**没有任何"清理"行**（bak1947 里 1483 条俱在即为证）；且该 L2 的 `space_path=prefix='代码'`（相对路径 bug，`:1371`）；
3. 19:49:15 **runB**：同一心跳周期再进同组，`_try_merge_duplicate_l2` 用 `space_path_prefix='代码'` 查询，**精确命中 runA 4 分钟前自产的那个 L2**（同一批节点、同一套采样关键词→重叠率必然 100%）→ 走 `:1262-1266`"完全重复，跳过"→ `merged=True` → `:1313-1335` **把 1483 条源 L1 全部删除，而"跳过"分支对既有 L2 一个字都没追加**。
净结果：知识库没变多，1483 条方法级知识变没了。**"去重跳过"≠"内容已覆盖"**——runA 那个 3 句 L2 根本不代表 1483 条的内容，把 merged=True 直接等价于"可删源"是本 bug 的丢失引擎。

## 5. Task-4 · 修复方案设计（按优先级，全部只给方案不动码）

**P0-1 止血：去重跳过分支禁止删源**（`PulseLiver.py:1262-1266`）
`overlap_ratio>=1.0` 分支改为：记 WARNING"重复跳过但源未覆盖"并 `return False`（既不建重复 L2 也不删 L1），或保留 merged=True 但在 `:1313` 删除段加条件 `if _dedup_confirmed_covered(existing, nodes)`——最小实现：existing 的 `evidence_chain`/来源 node_id 集合与本次 `nodes` 有交集才许删。**验收含义：任何"完全重复，跳过"行之后 5 秒内不得再出现同波次的"清理被压缩L1"行。**

**P0-2 L2 落库路径归一**（`:1371` `space_path=prefix`）
代码学习通道的组键必须回写全路径 `'/自我理解/代码/'+key`；同时 `_try_merge_duplicate_l2` 的查询前缀同步用全路径——否则修完 P0-1，runB 仍会靠相对键把自己人当"已有知识"。runA 遗留的那个 `space_path='代码'` L2 是坏数据，恢复时一并清理或改路径。

**P0-3 codec 分支补齐清理或明确不计数**（`:1419-1449 return True`）
早退分支要么执行与 `:1500-1515` 相同的清理，要么返回 False 让主路径接管；当前形态（计数 +1、日志"→L2"、但不清理）使同一组在下一心跳被完整重压——这是"5 分钟双跑"的调度根源。

**P1-1 分组键换信息源**（`:935-956`，星轨 v19 的正解续步）
平路径（len<4）时不再取 `_parts[-1]`，改从 value 前缀提取：`[自我理解·类.方法]`→类名；`[器官职责说明书·自动生成] X是`→`DOC:X`；提取失败再回落 `_parts[-1]`。实测该键可把 1483 拆成 **≤134 组、最大组 688（说明书类）→再叠加 P1-2 分块**。深路径维持后两段不变。

**P1-2 分块上限**：`_compress_group` 单次入参 >40 条时切片逐块处理，每块一个 L2、`evidence_chain` 记录成员 node_id——保证任何分组失准时都不可能一次性吞噬全组。

**P1-3 写入侧幂等（治本）**：`PulseStomach.py:449` 按 value 前缀写 `/自我理解/代码/{类名}`，并在同路径同"类.方法"标识已存在 L1 时更新（activation_count++/value 覆写）而非新建——按实测 594 唯一标识，稳态 L1 应从 1483 降到 ~600 以下。

**P2 卫生项**：①`_path_index` 的 `prefix.startswith(path_key)` 反向匹配（`PulseNodePool.py:2017`）会让短相对键命中一切深路径，建议路径查询要求段边界匹配；②21 组聊天残词路径节点（你好呀/中午好/梦境…混进 /自我理解/代码）属胃路径治理的存量脏件，随 P1-3 一并清理口径；③runA L2 关键词含模板标签，`get_top_valuable_keywords` 应过滤 `[...]`/`（...）` 形结构词。

**数据挽回（比修复更急，供星轨/用户决策）**：`.20260922_195153.bak`（13,052 节点）内含被删前 1485 条 L1 完整原文。趁轮转备份未被继续覆盖（今日已见 3 份 .bak 且命名含时间戳滚动），**应在下次框架启动前用受控脚本从该 bak 恢复 code_L1**（恢复即触发重删的风险由 P0-1/2/3 先落地解除，或恢复后先停肝压缩心跳）。17:18 已丢过一轮 1484 条（幸有 L1 快照被人工救回），19:49 这轮 1483 条若不主动恢复，重启后不会自动回来。

## 6. 验收标准（机检，逐条可跑）

1. **事件对禁现**：重启后任意时间窗内，日志 `知识去重: '代码' …完全重复，跳过` 与同行波次 `清理被压缩L1` 不得共存（grep 同秒即 FAIL）；
2. **单行删除上限**：任何 `清理被压缩L1: N条` 的 N ≤ 40（P1-2 生效代理指标）；
3. **路径分布**：census 复跑 `gb1_path_census.py`，深度2 的 code_L1 占比 → 0（P1-3 迁移完成）；组键最大组 ≤40；
4. **幂等**：连续两次全量代码扫描后，`唯一标识数 == L1 总数`（当前 594≠1483 即 FAIL 基线）；
5. **L2 形状**：新增 L2 全部满足 `space_path.startswith('/自我理解/')` 且 evidence_chain 非空、keywords 不含模板标签；
6. **回归冷启动**：从 195153.bak 恢复语料后首个人工心跳观察窗（30 分钟），code_L1 计数不得出现断崖（>10% 单波次下降）。

## 7. 与前两轮审计的谱系关系

本案是"**修复判据假设了数据里不存在的形状**"家族新实例（与第3期"豁免名≠追踪名"、日志分析"UA 配置写了没人读"同构：改的是符号，没对过实物）。同时是"**只写不读/只删不验**"缺陷类的加重版——`merged=True` 删除源前无任何覆盖性校验，与昨日 §5 的"写键无读取点"同源不同型：**写操作无后置验证**。建议并入星轨的"只写不读横向债务工单"口径，新增子型"**删前不验覆盖**"。
