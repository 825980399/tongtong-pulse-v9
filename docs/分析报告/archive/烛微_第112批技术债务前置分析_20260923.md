## §1 候选1：L0 看门狗启动超时（P2 → 建议按 P1 处理，因含确定性缺陷）

### 1.1 根因定位（机制先纠偏）
- **8.0s 是 `nucleus/field/InfoField.py:386` 硬编码字面量，无 config 键**（09:09 实测 config 无 `l0_timeout`）；`PulseDeviceManager.py:78` 注释"2s 看门狗"已漂移。计时起点=handler **开始执行**（`:865`），**不含排队等待**：它防的是"开跑未跑完"，测不到积压（注释 `:387`"入队时间戳"亦漂移）。
- **超时处置不是丢弃 handler，而是重建 L0 池**（`:980`→`:2084` `shutdown(wait=False, cancel_futures=True)`）：卡死 handler **继续跑**（孤儿线程破坏 L0 单线程不变式），**真正损失的是旧池排队中的生命线脉冲被静默作废**（`[P2-87]归零` 日志：08:32:57 `{'血管':1,'指标采集器':1}`、08:39:26 `{'血管':4,'紧急处理':1}`、08:38:53 九器官）。
- **"每次重启都出现"证伪（表述放大）**：现存日志窗口 31 次重启、24 条超时，boot 类仅 4 条且全部落在 09-22 19:34 后的最近 4 次重启（+39~43s 高度一致）→ **09-22 晚引入的新回归**，前 27 次重启 0 命中。
- **boot 超时调用链**：`main.py:2397` 发射 → **5 个器官订阅方**（心脏/潜意识/设备管理器/系统管理器/触觉，09:36 实测）全部 submit 到 **1-worker L0 池串行**（`InfoField.py:401`，且 `l0_threads` config 键未被读取）→ `PulseSystemManager._on_system_boot:148` `_check_and_repair_services`：最坏预算 `5s(:362 subprocess) + 2s(:378 sleep) + 5s(:379 复查) = 12s > 8s`；`_check_hardware:406` 另有固定 0.1s。08:32 实锤栈停在 `subprocess.run(['ollama','list'])` 的 `communicate`（服务未就绪时吃满），对应 11.7s 日志空窗（08:32:34→08:32:46）。

- **08:39:26 血管超时与 boot 不同根因**：栈停 `BasePulseOrgan.py:479 → pulse_tracer.py:115 → DataAccessLayer.py:72`（等锁），业务代码未进入；发生在 99.95s 全量快照窗口内。此族 19/24=79% → 归候选5 统一治理。
