### 2.2 三个沉默器官是谁、为何永久沉默（S 型）
1. **`企业微信`**：`nucleus/wecom_chat_bridge.py:268/342/376` 仅在真实企微消息到达时 `emit(source_organ="企业微信")`——被动接收型，夜间/无消息=必然"沉默"。**误报**（血管注释自己承认："低频器官在巡检窗口内无动作是正常现象"）。
2. **`framework_self_modify_gate`**：`main.py:2139-2142` 注册的**约束监听器**（organ_name 直赋字符串），只有"自我修改被禁止"约束脉冲到达才被派发——正常运行几乎不触发。**误报**，且它**不是器官**（不在 `framework.organs` 注册表，main.py:839 才是）。
3. 全仓 `.py` 中 `framework_self_modify_gate` 仅 main.py 4 处（注册+回调），无独立实现体——正控：`grep -arln "framework_self_modify_gate" --include="*.py"` 命中 main.py 本身。

### 2.3 为什么豁免没接住：追踪名≠豁免名，第 4 次复发（S+V）
`nucleus/const.py:242` `SILENCE_EXEMPT_ORGANS`（90 条）。python 成员判定实测（14:0x）：`企业微信`=**False**、`framework_self_modify_gate`=**False**、`Web对话`=False、`FunctionLoader`=False；而 `企业微信桥接器-回复监听`=**True**、`Web对话-人脸监听`=True。
——豁免表收的是**子监听器注册名**，血管 `_organ_last_active` 记的是**桥 emit 时的 source_organ**，两个名字空间从未对齐。const.py 注释自证此类 bug 已修三轮（W2：胸腺/白细胞中文名缺失致 140/72 次误判；R2：11 器官补中文名，判据链写明"血管按中文 organ_name 追踪…白名单只有英文类名时永远匹配不上"；v9.5：肝）。**今日两器官 = 同一错误模式第 4~6 次复发**；根因是"逐个补名的白名单跑步机"，缺一个身份归一化函数（第50批 `PulseMetricsCollector._LINK_ALIASES` 已有现成别名设计可抽取复用——它本身就是同类 bug 的产物）。

### 2.4 刷屏为何修不掉：批95~98 的"修复"是层级搬家（S）
`organs/body/PulseBloodVessel.py:209-216`：注释自述"原 WARNING 每次巡检无条件打印，7 小时刷屏 819 次"——修复手段=**降级为 DEBUG**；而 `LOG_LEVEL_FILE=DEBUG`（键名判据，13:42 实测）⇒ DEBUG 全量落盘，**文件层刷屏原样保留**（:216 无任何节流/去重，F4 去重 :218-241 只覆盖 emit 升级路径）。git 312ee17（批95~98"日志刷屏"专项）即此修复。**控制台降噪达成、文件层未治理、且 696 条 gate 误报还在被 WARNING 化 300s 一次**。

### 2.5 最重发现：自愈闭环对非器官实体静默空转（S）
链路：血管算分级（:221-241，restart 阈=2/degrade 阈=4 连续告警）→ level≥2 emit `ORGAN_ESCALATION`（:266-287）→ `PulseSystemManager._on_organ_escalation`（订阅 :437，`ORGAN_ESCALATION_ACTION_ENABLED=True` 键名实测）→ `_dispatch_organ_action` :280-281：`organ = self.framework.organs.get(name)`；**非注册器官 → 返回 "not_found" 且该分支零日志**。
企微告警已 29~31 次 ≫ 阈值 4 ⇒ 必然持续发升级脉冲 ⇒ 必然每次 not_found 蒸发 ⇒ 全窗 `[自愈审计]` 0 条与代码路径**双向吻合**。边界诚实声明：0 条审计对"其他真器官从未升 level≥2"不能反证——仅对企微/gate 两名字判"处置必然空转"（S），其余器官证据不足。
消费端另一实锤：`PulseEmergencyHandler.py:66` `silence_details = payload.get(...)  # noqa: F841`——血管算好的分级/时长/建议**接收即弃**，只 log 器官名；`_silent_organ_alerts`（:38/:75-77）内容零消费者（唯一读取 :186 报个数）。**告警链现状=只播报、不处置、还丢数据。**

### 2.6 修复建议（短/中/长期）
- **短期止血**（任一立竿见影）：①豁免表补 `企业微信`/`framework_self_modify_gate`/`Web对话`/`FunctionLoader`（4 行，但是第 7 次打补丁）；②:216 DEBUG 行加"与上次巡检集合相同则跳过"节流（去重逻辑现成，复制即可）。
- **中期**：③一个 `resolve_organ_key()` 归一化函数统一追踪/豁免/注册三名空间（复用 _LINK_ALIASES 设计）；④`not_found` 分支加一次性 WARNING（"处置目标不在器官注册表=豁免/注册错位"）——让空转可见；⑤EmergencyHandler 停止丢弃 silence_details，至少把 level 打进日志。
- **长期**：⑥器官注册时**声明活跃度模型**（脉冲型/被动监听型/约束型），沉默检测按模型分档（约束型根本不进检测池）；⑦"同一原因告警重复率"纳入日志健康巡检——三轮修而不止的共同原因是没人度量它。
- **与第105批关系**：105 批任务书覆盖 T1/T3/T4/百科T5，实测 `grep -c 沉默|血管|企微` = **0** ⇒ 今日 Task-5 **零重叠、纯增量**，建议立为第106批候选（T-106x，P1）。
