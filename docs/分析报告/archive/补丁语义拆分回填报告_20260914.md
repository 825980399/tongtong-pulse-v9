## 三、实施内容

### 3.1 新增字段（60 条全部回填）

| 字段 | 类型 | 说明 |
|---|---|---|
| `no_regression` | `bool \| None` | 语法/导入/回归是否通过 |
| `problem_fixed` | `bool \| None` | 目标问题是否真消失（**None = 不可判定**） |
| `verification_granularity` | `str` | `static_only` / `reproduction` / `effectiveness` |
| `effectiveness` | `float \| None` | 真实效果（**不可算时为 None，不再默认 0.97**） |
| `verified` | `bool` | **保留**（= `no_regression`），标注 deprecated |
| `verification_split_version` | `int` | = 1 |
| `verification_split_reason` | `str` | 人类可读判定理由 |

### 3.2 ★语义合流的确切修复点

`nucleus/reasoning/PatchManager.py` 原文：

```python
_verdict = _verifier.verify(
    patch, {...},
    problem_gone=bool(_verify_result.get("passed")),   # ← 复用 No-Regression
    function_ok=bool(_verify_result.get("passed")),    # ← 同一个值
)
```

**同一个 `passed` 被同时赋给"问题消失"与"功能正常"** —— 这就是语义合流。
注释里其实自承了：*"真正的业务探针由调用方（SafeEvolutionExecutor）补充上报"*。

改为：

```python
problem_gone=None,                                 # ★无法判定 ≠ 已修复
function_ok=bool(_verify_result.get("passed")),    # No-Regression
```

### 3.3 附带修复：无法判定不再被扣分

`nucleus/evolution/EvolutionEffectVerifier.py` 原 `else` 分支对
「`_d1 is None`（缺少问题复查探针）」与「确实失败」**一视同仁扣 10 分** ——
把"不知道"惩罚成"做错了"。已改为：无法判定 → `passed=None, trust_delta=0`（不奖不罚）。

### 3.4 展示层接入

`nucleus/evolution/patch_quality_evaluator.summarize()` 新增（纯新增字段，零回归）：

| 新字段 | 含义 |
|---|---|
| `no_regression_rate` | 无回归率（旧口径） |
| `real_fix_rate` | ★**真实**修复率 |
| `verifiable_rate` | 可判定率 |
| `fix_rate_gap` | 虚高幅度（= 无回归率 − 真实率） |

展示标签由 `display_label()` 统一产出，区分
`✅ 无回归 · ✅ 问题已修复` / `✅ 无回归 · ❓ 修复效果未验证` / `❌ 存在回归`。
