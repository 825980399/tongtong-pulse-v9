## 一、执行摘要（修订版）

### 1.1 核心命题

让曈曈PulseNet框架根据自身运行产生的数据，训练并孕育适用于自己的**内在模型群**，逐步从"完全依赖外部大模型"走向"自有模型为主、大模型为辅"。

### 1.2 ★现状痛点（修订后，基于实测）

| 指标 | 当前值 | 问题 | 数据来源 |
|------|--------|------|---------|
| 大模型依赖度 | **96.96%** | 但**98.8%来自进化循环，对话=0（未埋点）** | 路灯实测llm_dependency.json |
| 本地推理占比 | **3.1%** | 66次本地推理 vs 2103次大模型调用 | 双方一致 |
| LLM调用留存率 | **2.4%** | 2103次调用仅保存50对输入输出 | 第三方实测inference_trace.json |
| 进化验证 | **空转** | 56个已应用补丁baseline_errors=0，100%假通过 | 双方一致 |
| 数据规模 | **4.8GB** | 含1.98GB ONNX模型、2.7GB知识目录、1273个损坏文件 | 路灯实测 |
| 经验库污染率 | **79.9%** | 1501条中1199条polluted | 第三方实测 |

### 1.3 ★核心结论（修订版）

> **可行，但必须"先测量、再修根因、后建模型"三步走。**

1. **先测量**：当前"依赖度97%"只覆盖4个埋点（98.8%是进化循环），对话类未埋点 → **必须先补全埋点、重算基线**，否则所有目标都是错的靶子
2. **再修根因**：依赖度的真实根因是「进化验证空转（56补丁baseline=0）→重复修复→重复调LLM」。**修好真实基线比建任何模型都更直接地降低依赖度**
3. **后建模型**：在真实数据基础上，**按"作用于多少比例调用"排序**建模，首期从「补丁质量评估器」与「经验检索器（复用已有bge模型）」入手

## 二、★依赖度指标的真实构成（路灯致命发现）

### 2.1 实测构成

`data/metrics/llm_dependency.json` → `counters.llm_call_count`：

| 场景 | 次数 | 占比 |
|------|------|------|
| **自主进化（SCENE_EVOLUTION）** | **2,077** | **98.8%** |
| 其他（SCENE_OTHER） | 26 | 1.2% |
| 肺回答（SCENE_LUNG） | **0** | 0% |
| 代码学习（SCENE_CODE_LEARN） | **0** | 0% |
| **合计** | **2,103** | 100% |

### 2.2 为什么对话=0不是"没触发"，而是"没埋点"

全库检索`record_llm_call(...)`的调用点，**只有4处**，全部在进化循环：
- `nucleus/evolution/LLMEvolutionEngine.py:45`
- `nucleus/evolution/SelfReflectionEngine.py:35`
- `nucleus/reasoning/SafeEvolutionExecutor.py:722`
- `organs/brain/PulseSemanticComprehension.py:574`

而`SCENE_LUNG`虽然在`LLMDependencyMetrics.py:32-36`有定义，**但全库没有任何一处在对话出口调用**。

⇒ **"大模型依赖度"这个指标，从设计上就不包含对话。**

### 2.3 依赖度真实根因链

```
进化验证空转（56条applied补丁baseline_errors全为0，100%假通过）
        ↓
补丁"假通过" → 问题并未真正修好
        ↓
下一轮自主进化又发现同样问题 → 再次调用LLM生成补丁（含多轮追问）
        ↓
2,077次进化LLM调用（占依赖度分子的98.8%）
        ↓
"大模型依赖度97%"
```

⇒ **要降低依赖度，先要打断"假通过→重复修复→重复调LLM"这个循环。**

## 五、★关键设计补全（第三方评估）

### 5.1 置信度校准机制（路由地基）

**问题**：没有校准的模型会"自信地犯错"——输出概率80%但实际准确率只有50%。

**方案**：
- 训练后做**温度缩放**（Temperature Scaling），最小化NLL
- 上线前验证**ECE（Expected Calibration Error）< 0.05**
- 路由层只在**置信度>阈值且ECE达标**时才放行本地模型
- 否则降级到LLM

### 5.2 自我蒸馏退化防护（铁律）

**问题**：如果把内在模型的输出记入训练数据，下一代模型会在自己的输出上学→错误固化放大（AutoGPT式自我污染的模型版）。

**铁律**：
- 训练数据**只收教师（LLM）直答样本**
- 内在模型命中结果**永不**入训练集
- 可记录"内在模型vs LLM"的差异用于监控，但不作为训练标签

### 5.3 InnerModelRouter集成位置（路灯建议）

**推荐位置**：`PulseLung._call_via_channels()` **之前**（渠道选择的上游）

**依据**：PulseLung是全部LLM调用的统一出口，在此拦截可覆盖100%调用（含进化路径）。

**协同方式**：
```
调用方 → PulseLung._call_via_channels()
             ↓ 新增前置钩子
        InnerModelRouter.route(scene, payload)
             ↓ 高置信度
        本地模型结果（不发起网络请求）
             ↓ 低置信度 / 场景不支持
        原渠道流程（零改动）
```

**红线**：
- 路由只做"前置短路"，不改动既有渠道逻辑 → 天然零回归
- 首期只放行`SCENE_EVOLUTION`（占98.8%，收益最大、风险最可控）
- 默认关闭，`ENABLE_INNER_MODEL_ROUTING=False`兜底

## 八、风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 埋点补全后依赖度构成剧变 | 中 | 阶段零先重算基线，再设定目标 |
| 真实基线建立后发现大量补丁实际无效 | 高 | 这是好事——说明根因找到了，后续修复更有针对性 |
| 训练数据不足（<10万对） | 中 | 阶段零管道跑起来后，按2103次/4天速率，2周可积累7000对，3个月可达5万对 |
| 本地模型质量不稳定 | 高 | 置信度校准（ECE<0.05）+ 影子模式（≥3天对比）+ 降级保护 |
| 自我蒸馏退化 | 致命 | 铁律：内在模型输出永不入训练集 |
| 与现有缓存冲突 | 低 | L0精确缓存（已有）+ L1语义泛化（新建），两层互补 |
