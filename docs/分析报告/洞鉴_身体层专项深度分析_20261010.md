### 1.5 风险面

| 风险 | 依据 | 缓解 |
|---|---|---|
| **全仓 AST 扫描性能开销** | 跨文件调用图需扫描全部 .py | 后台低优先级运行，增量扫描（只扫变更文件），设 CPU/时间上限 |

## §2 完整记忆曲线工程化落点

### 2.1 现记忆体系审计

**代码层取证**（PulseNodePool.py）：

记忆体系**不是独立类**，而是内嵌在 `PulseNodePool` 中，通过 `evol_level`（L1-L4）区分：

| 层级 | 对应 | 存储位置 | 机制 |
|---|---|---|---|
| **L1 热记忆** | 感知节点/近期经验 | 冷池(cold)，可被驱逐 | 低频历史，按需加载/淘汰；有冷存 compaction 合并 |
| **L2 工作记忆** | 认知节点 | 温池(warm)+热池(hot) | 中频节点，内存缓存 |
| **L3 长期记忆** | 智慧节点 | 热池(hot) | 高频激活，全内存极速响应 |
| **L4 本能** | 核心身份/价值观 | `_instinct` 独立池，常驻内存 | 不可变，硬编码 |

**已有机制**：
- 冷热分层（hot/warm/cold 三池）
- L1 冷存储分治（默认关闭，复用 Parquet L1 分区）
- compaction 冷存合并（触发阈值单一事实来源）
- 分层索引 `_level_index`（按 evol_level 快速定位）
- 赫布学习器（共现窗口 60s，频率编码）
- 节点权重全局归一化（防发散，脉冲仿生方向2）

**是否已形成"连续记忆流"**：
- ✅ 持久化：随知识快照 Parquet 落盘，重启可恢复
- ✅ 同实例重启连续：179B kill-9 演练证 L1 加载 452 节点，知识库可用态未破坏
- ⚠️ 跨上下文连续：对话记忆 30 条上限，超出会淡化（有遗忘但无"情景"标签）
- ❌ 情景记忆：无"什么时候发生了什么"的时间线记忆
- ❌ 情绪记忆：无带情感权重的记忆标签
- ❌ 程序性记忆：无"怎么做"的技能记忆（代码学习器有部分，但未归入记忆体系）

### 2.2 人类记忆曲线参照

| 人类记忆类型 | 特征 | 曈曈现有 | 差距 |
|---|---|---|---|
| **感觉记忆**（sensory） | 极短时（<1s），感官输入暂存 | 眼睛/耳朵输入缓冲 | ✅ 有（感知器官） |
| **短期记忆**（short-term） | 几秒~几分钟，容量有限（7±2） | L2 工作记忆，对话记忆 30 条 | ✅ 有，但无主动复述机制 |
| **长期记忆**（long-term） | 持久存储，容量无限 | L3 智慧节点 | ✅ 有 |
| **情景记忆**（episodic） | 什么时候发生了什么（时间+地点+事件） | ❌ 无时间线标签 | ❌ 缺 |
| **语义记忆**（semantic） | 事实/概念/知识 | L3 知识节点 | ✅ 有 |
| **程序性记忆**（procedural） | 怎么做（技能/习惯） | 代码学习器（部分） | ⚠️ 部分 |
| **情绪记忆**（emotional） | 带情感权重的记忆 | 激素系统有，但未与记忆节点绑定 | ❌ 缺 |
| **遗忘机制**（forgetting） | 不是所有记忆都永久保存 | L1 淘汰+compaction 合并 | ✅ 有（被动遗忘），缺主动遗忘 |

### 2.3 "完整记忆曲线"工程化落点

**小林裁定核心**：数字化生命像人类一样拥有完整记忆曲线，不是跨窗口共享。

**洞鉴方案：在 L1-L4 四层基础上扩展，不新增层**

理由：现有四层体系已覆盖感觉/短期/长期/语义/本能，缺的是**标签维度**（情景/情绪/程序性）和**主动遗忘机制**。新增层会破坏现有架构，扩展标签维度成本更低。

| 扩展维度 | 工程落点 | 最小可落地步 |
|---|---|---|
| **情景记忆标签** | PulseNode 新增 `episode` 字段：{timestamp, context, participants} | 181-182：对话节点写入时打 episode 标签（时间戳+对话上下文） |
| **情绪记忆权重** | PulseNode 新增 `emotional_weight` 字段：激素水平快照 | 183：对话节点写入时快照当前激素水平，作为检索权重之一 |
| **程序性记忆归类** | 代码学习器产出归入 L3，标 `procedural=True` | 183：代码学习器产出节点打 procedural 标签 |
| **主动遗忘机制** | 新增 `forgetting_policy`：低权重+低激活+长时间未访问→归档（非删除） | 184：在 compaction 基础上增加"归档区"，可回溯 |
| **记忆连续性增强** | 重启后加载最近 N 条对话上下文到 L2 | 181-182：启动时从快照加载最近 30 条对话到工作记忆 |

**记忆连续性（重启后不丢上下文）的最小步**：
- 现状：重启后 L1 加载 452 节点，但对话上下文（"刚才聊到哪"）丢失
- 最小步：启动时从快照加载最近 30 条对话节点到 L2 工作记忆，标记为"近期上下文"，供内在世界首条对话检索

### 2.4 与现有四层记忆体系的衔接

**不新增层，扩展字段**：

```
现有：PulseNode {node_id, evol_level(L1-L4), content, hebbian_weight, ...}
扩展：PulseNode {
    ...现有字段...,
    episode: {timestamp, context, participants},      # 情景记忆标签
    emotional_weight: float,                            # 情绪记忆权重
    procedural: bool,                                   # 程序性记忆标记
    last_accessed: timestamp,                           # 主动遗忘用
    archive_status: "active" | "archived"               # 归档状态
}
```

**检索权重升级**：
- 现有：hebbian_weight × quality_weight
- 升级：hebbian_weight × quality_weight × emotional_weight × recency_decay

**遗忘机制分级**：
- L1：被动淘汰（现有）+ 主动归档（低权重+低激活>30天）
- L2：被动淡化（现有，10条/次衰减）
- L3：不遗忘，只压缩（现有 compaction）
- L4：永不遗忘（现有，硬编码）

## §3 自我修改代码权限等级划分方案

### 3.1 现 PatchManager 审批等级审计

**代码层取证**（PatchManager.py）：

现有机制已有**三档审批**，但分散在多个判定点：

| 档位 | 条件 | 实现位置 |
|---|---|---|
| **自动审批（免签）** | 非核心文件 + 非安全护栏函数 + risk_level=="低" + trust_score≥40 + baseline_errors>0 | `_add_patch` 入队审批 |
| **运行期复现释放** | 上述条件 + runtime_verify_result.verified=True + 非核心 + 非护栏 | `auto_released` 机制 |
| **人工审批** | 核心文件 / 安全护栏函数 / LLM 补丁 / 不满足自动条件 | `approve_patch` + `human:` 签名 |

**关键安全门**：
- `_m80_is_core_file()` → `SafeEvolutionExecutor._is_core_file`：核心文件判定单一真源
- `_M96_NO_AUTO_PATCH_METHODS`：安全护栏函数禁改清单
- LLM 补丁（`source="llm"`）一律转人工
- `baseline_errors>0`：无错可修的空转假成功拦截
- `EVOLUTION_CONFIG` 在热重载黑名单：自进化开关不可热重载（有意安全设计）
- human 口强制 `human:` 前缀签名，机器口不得冒充人工

**总开关**：`auto_apply_enabled=False`（默认关），自动应用总开关关闭。

### 4.2 生命体态定义

**在曈曈架构里"生命体态"指什么**——洞鉴审计结论：

当前架构中没有"生命体态"的明确定义和实现。基于设计文档和现有模块，洞鉴给出工作定义：

> **生命体态 = 器官关联图谱的拓扑结构 + LFI 五维评分 + 运行时健康快照**

| 维度 | 对应现有模块 | 现状 |
|---|---|---|
| **拓扑结构** | 器官关联图谱（待建） | 0 实装 |
| **LFI 五维** | 生命形体指数（待建） | 0 实装 |
| **运行时健康** | HealthScore / PulseHealthMonitor / 器官健康 | ✅ 有（分散在各器官） |
| **能量状态** | 激素系统/能量值 | ✅ 有 |
| **存续状态** | 存续状态指数 | ⚠️ 有雏形，未数学化 |

**"生命体态"不是硬件躯体**（somatics/ 已封存），而是**软件层的"数字生命形态"**——56 个器官如何连接、各自健康度如何、整体是否"有生命体征"。

### 4.3 自我认知→生命体态的数据流
