### 2.2 `dual` 的合并语义（核心，必须写死优先级）

| 规则 | 内容 | 理由 |
|---|---|---|
| R1 | 以 `node_id` 为键取并集 | 现网双向差为 0，并集成本仅一次 dict 合并 |
| R2 | 同 id 双源都有时，**逐字段**取"更新者"：`source_time/acquired_time/updated_at/version` 大者胜 | 不能用"整节点 JSON 优先"，否则 Parquet 新增字段（`:2544-2545 conflict_count/last_conflict_at`）会被旧 JSON 覆盖 |
| R3 | **质量标记例外**：`quality_flag` 只要任一侧为**非 clean**，即取非 clean 侧（连同其 `quality_reason`）；两侧都非 clean 时按 `placeholder_alias > polluted > suspect` 严重度取高 | 这一条就是"重启不再抹标记"的全部机制；顺序固定，避免实现者另造优先级 |
| R4 | `trust_score` 同理：任一侧为 `0.0`（159上B 的隔离值）→ 取 `0.0` | 否则 §一 刀① 会以另一副面孔复现 |
| R5 | 并集后计数与任一单源之差 > 0 → `WARNING [A案dual] 双源计数分歧 parquet=%d json=%d union=%d`，**只告警不阻断** | 分歧是常态（本轮实测 27/25），阻断会导致启动失败 |
| R6 | 全池上限：并集结果 > `SNAPSHOT_MAX_NODES`（若存在）时按 `updated_at` 截断并告警 | 防止 dual 把已 purge 节点复活成无上界增长 |

> ⚠️ **R6 是"复活风险"的唯一防线**：刀③ 删掉的 25 个节点全部还在 `.bak` 里；`dual` 若无上界会把它们请回来。实施时请以"现网 node_id 集合 ⊆ 并集"为不变式自检。

### 2.4 双源同步路径：`--apply` 之后如何重建 Parquet

**唯一写入口已存在**：`PulseSnapshot._save_parquet_locked()`（`:2644`，内部 `:2712 pq.write_to_dataset(...)`）。因此**不要在 `--apply` 脚本里另起 `write_to_dataset`**，而是复用：

```python
# nucleus/mnemosyne/PulseSnapshot.py（新增，放在 :2644 _save_parquet_locked 之后）
def m160_rebuild_parquet_from_nodes(
    self,
    nodes: list[dict[str, Any]],          # 通常 = 刚被 --apply 改过的 saved_nodes
    *,
    dry_run: bool = True,                 # ★默认干跑
    verify: bool = True,                  # 复用 _m68_verify_parquet() :1383
    keep_prev: str | None = None,         # 传入目录名则旧分区改名保留，否则删除
) -> dict[str, Any]:
    """★第160批下 A案：JSON→Parquet 单向重刷（原子、可回滚、干跑默认）。
    Returns {ok, src_count, out_count, tmp_dir, prev_dir, verify_rc, error}"""
```

**原子写盘策略（防中途崩溃半写）**——Windows 下**目录级 `os.replace` 不安全**，故用"分片文件级替换 + 保留 prev"：

1. 目标目录 `parquet/`（`_m68_parquet_dir()` `:1247`）；先 `pq.write_to_dataset(..., root_path="parquet.m160tmp-<ts>/")`，即**现目录之外**；
2. `verify=True` → 调 `_m68_verify_parquet()`（`:1383`）对 **tmp 目录**校验行数与 schema（该函数现校验正式目录，施工时须加 `root` 形参，勿复制第二套校验）；
3. 校验通过后，逐分区把旧文件 `os.rename(parquet/evol_level=Lx/*.parquet → parquet.m160prev-<ts>/...)`，再逐文件 `os.replace` tmp → 正式（**文件级** replace 在 NTFS 上是原子的）；
4. 任一步异常 → 把 `parquet.m160prev-<ts>/` 原名放回，返回 `ok=False`；tmp 目录留下不删（供事后取证）；
5. **全部成功后**才写 JSON（`_m67_write_snapshot_streaming()` `:870` / `_atomic_write_with_rotation()` `:1560`）。

> **写序必须是 Parquet 先、JSON 后**：加载默认吃 Parquet（刀①）。若先写 JSON 后崩，重启读旧 Parquet → 标记照样丢，且日志会显示"一切正常"。

**与 `--apply` 的接线**：`tools/archive/cleanup_alias_placeholder_nodes.py` 的 `--apply` 分支在写 JSON 完成后追加一次 `m160_rebuild_parquet_from_nodes(...)`（或在 `dual` 落地后降为可选）。若不便改旧工具，则新增 `tools/rebuild_parquet_from_snapshot.py` 独立调用同一函数——**禁止**两处各写一份 Parquet 逻辑。
