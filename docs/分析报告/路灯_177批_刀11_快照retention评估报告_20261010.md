## 一、现状与机制

`config.py:4352`：
```
KNOWLEDGE_BACKUP_KEEP = 3                # ★备份保留份数（原硬编码 5 → 现 3）
ENABLE_KNOWLEDGE_BACKUP_ROTATION = True  # 轮转总开关（关闭 → 回到旧值 5，零回归）
```

**读取与回退**（`nucleus/mnemosyne/PulseSnapshot.py`）：
- `:116` `_n = int(getattr(config, "KNOWLEDGE_BACKUP_KEEP", 3) or 3)`
- `:114` 若 `ENABLE_KNOWLEDGE_BACKUP_ROTATION=False` → 回退旧值 **5**（零回归保障）。
- `:246` `self._max_backups = _m41_backup_keep()` 注入。

**轮转语义**（`PulseSnapshot.py:1750-1757` 与 `:2547-2554` 两处对称）：
```python
backups.sort(reverse=True)              # 按 mtime 倒序，最新在前
for _, fpath in backups[self._max_backups:]:
    os.remove(fpath)                    # 仅删超出 N 的最旧 .bak
```
- 即 **KEEP=N 保留每个快照基名下最新 N 份 `.bak`**（按 mtime 倒序），其余删除。
- 删除面受严格限定：`fname.startswith(base_name) and ".bak" in fname`（精确前缀 + `.bak` 后缀），`silent_exc` 兜底，与"只清特定前缀"安全范式一致。

**复用同一键的旁路**：
- `tools/data_governance_m41.py:235` 一次性治理工具读同一键（默认 3）。
- `tools/snapshot_retention_audit.py:51` 审计脚本动态读键（默认 3）；其 `:6` 注释写死"3 件"，逻辑不写死——降值后该注释会变陈旧（**非功能性，仅文档待同步**，见第六节）。

**既有测试覆盖**（`tests/test_data_governance_m41.py`）：已显式验证 `KEEP=2 / 1 / 0 / -5` 四档边界，机制对降值鲁棒。

## 二、恢复链影响分析

| 档位 | 保留回退深度 | 估算磁盘占用* | 恢复链安全边际 | 备注 |
|---|---|---|---|---|
| 5（旧值/关轮转） | 5 份 | ~2.19GB | 最高 | 原始状态 |
| **3（现状）** | 3 份 | ~1.31GB | 高 | 当前默认 |
| **2（建议）** | 2 份 | ~0.88GB | 中高 | 省 ~438MB |
| **1** | 1 份 | ~0.44GB | 中 | 省 ~876MB；仅保留上一轮 |
| 0 / 负值 | 0 份（测试验证边界处理） | ~0 | 最低 | **不建议**：轮转安全保障失效 |

\* 估算依据 `config.py:4349` 注释"单份 ~438MB"（5 份 × 438MB = 2.19GB）。实际随快照体积浮动。

**语义要点**：
- 降值**不改变删除安全属性**（前缀/后缀限定、mtime 倒序、silent_exc 兜底均不变），仅缩小"可回退历史窗口"。
- KEEP=1 时：仅在两次连续写入之间保留一份上一状态；若损坏发生在轮转窗口内（当前写即损坏），则可能无可回退副本——恢复链对边际事故的抗性下降。
- KEEP=2 较 KEEP=1 多一层缓冲，且仍省 438MB，为**性价比最优**。

## 四、建议值

- **推荐 KEEP=2**：恢复链保留 2 层回退 + 省 ~438MB，安全/成本均衡。
- 若磁盘进一步吃紧且可接受单级回退，可 KEEP=1；不建议 KEEP≤0。
- 维持现状 KEEP=3 亦可（安全优先）。
