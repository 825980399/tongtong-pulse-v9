## 三、刀2 · dead_code 判据升级为「图上入边」（P0）

**为什么必须升级**：303 刀2 用「字符串在场即豁免」把 638 压到 27，代价是 `nucleus/`、`base/`、`tools/`、`config.py` **整目录豁免** ⇒ 框架层与配置面从此**结构性不被检查**。本批把它换掉。

**新判据（四类存活来源）**：

1. **静态边（static）**：落盘图中同名节点**有入边** ⇒ 活（权威判据，替代目录豁免）；
2. **按名边（byname）**：`getattr(self, "x")` 字面名；
3. **事件边（event）**：字符串常量事件名（`a.b` 形态取末段）；
4. **注册入口（entry）**：`on_/handle_/do_/signal_` 等总线反射调用的处理器；
5. **图域外（out_of_graph）不判**：见下。

**关键补充判据（本次最重要的自我约束）**：调用图只扫 `config.CALL_GRAPH_SCAN_DIRS`（实测：`nucleus / organs / functions / base / utils / somatics / main.py`）⇒ **`tools/`、`hardware/`、`config.py` 不在图内**。对图域外文件，入边判据**不可用**（等价于「没测」）；按判据纪律——**分不清「没有病」与「没测」时不许判死** ⇒ 新增 `_m304_graph_covered_files()`，域外文件一律不判。

**实测**（`_detect_dead_code` 直调）：

| 指标 | 303（在场即活） | **304（有边即活）** |
|---|---|---|
| dead_code 条数 | 27 | **541** |
| nucleus/ 条数 | 0（盲区） | **470（可判）** |
| tools/ 条数 | 0（目录豁免） | **0（图域外，判据不可用 ⇒ 不判）** |
| 耗时 | 1.9s | 1.9s |

豁免来源由 INFO 日志可审计：`静态入边 / 按名边 / 事件边 / 注册入口 / 图域外` 五项计数 + 判死数。

## 五、刀4 · growth 出口：假设进 hub（P1）

- 新增 `PulseSubconscious._m304_growth_to_hub(growth_topic)`：把 growth_topic 结构化为**三行内可判真伪**的假设（主体／验证方法／预期观测），`hub.record(organ="潜意识", task_type="growth_hypothesis", ..., origin="growth")`（复用 301 刀3 的 origin 字段）。

## 六、刀5 · 自动分诊前置：牵连数查询（P1）

- 新增 `patch_execution_dispatch.blast_radius_of(method, max_depth=3)`：读最新落盘调用图，从同名节点沿 `caller → callee` 做 BFS（限深 3），返回**下游可达节点数**；图缺失/方法不在图中 ⇒ 返回 0（**不拦**，零回归）。

实测：`blast_radius_of('get_stats') = 75`（真实可取数）；不存在的方法名 = 0 ⇒ 放行（不误拦）。
