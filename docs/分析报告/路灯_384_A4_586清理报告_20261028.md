## 一、先说一个必须知道的前提：现成工具在新快照上失效了

票面给的方向是「与 `cleanup_alias_placeholder_nodes` 同纪律」，我直接跑它，得到：

```
[结果] 占位符污染节点共 0 个
[dry-run] 未做任何修改。
```

**这个 0 是假的。** 追下去是 `tools/mark_duplicate_nodes.py::_locate_nodes_array`
有两个缺陷：

| # | 缺陷 | 实测证据 |
|---|---|---|
| ① | `find(b'"nodes"')` 会命中**字符串值** | 快照里调用图有 `"args": "nodes"`（偏移 1045416），定位器把它当字段名 |
| ② | 搜索窗口只有 1MB | 真字段 `"nodes":` 在偏移 **1251714**（`freq_index` 把字段推到后面） |

定位错之后，`iter_node_spans` 从一个**不是节点数组**的位置开始扫，`json.loads`
全部失败，而 `iter_snapshot_nodes` 对失败是 `continue`（静默）⇒ **扫出 0 个节点
却一声不响**。

修法（已落，2 处）：匹配带冒号的 `"nodes":`（字段名形态，不会被值命中）+ 窗口
1MB → 4MB。修完**同一个工具**再跑：

```
修复前：[结果] 占位符污染节点共 0 个
修复后：[结果] 占位符污染节点共 360 个
        [分组] 裸父路径 309 个 | 器官别名子路径 0 个 | 其他路径 51 个
```

守卫：`tests/test_m384_d1_snapshot_locate.py`（7 例，含「旧实现确实会定位错」的反向证明）。

> 这类「0 与没采到读数一样」的坑，383 批已经踩过一次（`llm_total=0` 分不出
> 「没对话」与「埋点坏了」）。本次是同一族问题的第二个实例。
