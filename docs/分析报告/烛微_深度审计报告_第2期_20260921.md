### 2.2 N5 · F3 聚合器：标准库语义级死机制 + 4 项同源缺陷

- **死因（S 型，3 通道）**：`Logger.handle` 只查**发起 logger** 的 filters；`callHandlers` 上溯祖先时**从不调祖先 logger.filters**（`inspect.getsource` 源码证）。5 行演示：子 logger `.info()` → 父挂 filter 收 **0**；父本体 `.info()` → 收 1；同 filter 改挂 **handler** 即收到子记录——排除级别/propagate 混淆变量。生产印证（V/T 型双通道）：`logs/pulse.log` 可聚合行 63,408（cw2 15:2x）/65,491（主线程 16:0x 复测）→ 聚合标记行 **0/0**。
- **同源缺陷**：F3-b 尾窗计数只活在内存，实测 1,000 条→落盘 1 行、999 计数随进程蒸发；F3-c `self._max_suppressed` 全文件仅赋值 1 处**从未被读**（主线程 grep 复核），注释声称的"超阈值输出摘要"未实现；F3-d 键用渲染后完整消息 → 现状 60s 折叠率 **7.03%** vs 数字归一模板键 **16.12%**（同一份日志双算）；**F3-e 新发现**：生产码 10 处定义 `getLogger(__name__)`（主线程全量 grep 复核；cw2 统计口径为 16 处含变体/工具目录），其 logger 名不在 `pulse` 树下且真 root 无 handler（`basicConfig` 生产 0 命中，主线程复核），实测 **14 处调用点 DEBUG/INFO 完全丢失**（含 `VectorStore.py:193/425/503/817`、`PulseLung:404/2343/2358`、`fast_ops:157/174`、`PulseCortex:646/2146`、`QICA:521/1320`、`PulseInnerWorld:9091`）。
- **改法（实测对比）**：推荐 **A′（每 handler 独立 filter 实例）+ record 拷贝后改写（现 `:478-480` 就地改共享 record，实测多 handler 摘要被追写 2 次且 `args` 被清空）+ 模板化键 + atexit/rollover flush + 树外 logger 改挂 `pulse.` 前缀**。性能：A′ 17.71µs/条、增量 ≈0.63s/全量日志（可忽略）；**A-共享实例有致命正确性 bug**（第二 handler 连首条都收不到、计数×N 放大 500→998），照抄最自然写法会中招。二次聚合死循环风险实测不存在。

### 2.3 N6 · 悬空边与孤儿向量：先纠偏"幽灵知识"恐慌，再分边/向量两案
