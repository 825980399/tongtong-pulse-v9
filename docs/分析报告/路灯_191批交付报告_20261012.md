## 二、逐刀自证

### 刀1：SUBAGENT 刀B 沙箱串联 + status 错标修正（commit `7eda726`）

**改动**（均仅真起支路，默认 `dry_run=True` 生产行为零变化）：

1. **`build_child_wrapper` 包裹命令行**（`:161`）：生成含 RLIMIT 四维 + CPU 信号兜底的包装器源码，子进程以 `python -c <wrapper_src> <launcher> input output stderr` 启动，把沙箱限制套到真起的 SUBAGENT 子进程上。launcher 文件透传实参 `sys.argv[1:]`（worker `main()` 自身再剥一层 `[1:]`）。
2. **status 错标修正**（`:129`）：`CHEAP_MODEL` 空 → `refused`（原错标 `budget_exceeded`，语义错位）。
3. **伴生修正 A — 去 `-I`**：`build_child_wrapper` 文档约定 `python -I -c`，但 `-I` 隔离模式把 site-packages/cwd 排除，导致受控内部 worker 无法 `import nucleus`（`ModuleNotFoundError`）。实测改为 `python -c`（与原 `python -m` 调用一致），资源上限仍由 wrapper 施加（Windows 层为空串→父进程看门狗兜底，限制真生效留 Linux 窗）。
4. **伴生修正 B — `proc.pid` 崩溃兜底**：`subprocess.CompletedProcess` 无 `.pid` 属性，原始成功/失败返回均写 `pid=proc.pid`，真实真起会 `AttributeError` 崩溃。改为 `getattr(proc, "pid", None)`。

**实测验证（Windows 真实真起）**：
- `run_subagent({"task":{"op":"echo","payload":"hello-191"}}, dry_run=False, ENABLE 全开, CHEAP_MODEL="cheap-llm")` → `STATUS=success`，`echo="hello-191"`，`deterministic=True` ✓（端到端证明 wrapper 串接 + argv 透传可用）。

**单测**：`tests/test_m191_blade1_subagent_sandbox_wrap.py`（wrapper 串证 + timeout 生效 + 真实端到端 echo）。并更正既有 `tests/test_subagent_runner_m183.py::test_cheap_model_required` 断言 `budget_exceeded`→`refused`（该断言即被修正的错标本身；最小改动，否则门禁失败——见偏差 D#1）。
