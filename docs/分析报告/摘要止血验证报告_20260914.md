## 一、问题回顾（第46批根因）

`_summarize_experience()` 原实现把 `summary` **直接覆盖**成模板句：

```python
_summary = f"我曾因{_motivation[:30] or '某种动机'}而行动，获得了{_reward_type}奖赏"
if _emotions:
    _summary += f"，感受到{_emotions}"
experience["summary"] = _summary[:150]        # ★覆盖原文
experience["motivation"] = _motivation[:50]   # ★截断
experience["field_frequency_snapshot"] = {}   # ★清空
```

**实测后果**：1179 条污染中 **980 条（83.1%）** 是这套模板的产物，
且三项指标 100% 重合（模板句匹配 980 **==** `is_summarized` 980）。

> 污染不是"写入时灌水"，而是**维护侧压缩**造成的，且原文**永久销毁**。

### 证据链

1. 框架最后一次「初始化 曈曈」= **09-13 23:12:33**，**早于** T2 代码落地（09-14 07:40）
   → **框架从未在止血代码之后重启过**
2. 生产库 `raw_summary` 覆盖率 **0.0%**、`summary_version=2` 计数 **0**
   → 新实现**从未被调用过**
3. 止血后新增记录数 **0** → 连观察样本都没有

> ★ **代码实施 ≠ 生效**。`_summarize_experience()` 是运行时逻辑，
> 必须**重启框架**后才会对新记录生效。

**这恰好是任务书 §六 检查点要拦住的场景**：
「如果 T2 止血效果未确认，不要执行清洗 —— **先洗后改 = 白洗**」。
本批按设计**正确地**判定 T3 延后。
