### 1.4 核心机制（四大支柱）

**① 脉冲通信**：器官间禁止直接方法调用，一律通过信息场广播脉冲事件。分 L0（生命线/心跳/告警）、L1（实时交互）、L2（认知思考）、L3（后台自主）四层，各自独立线程池。实测 155 类事件（67 闭合 / 35 广播 / 51 幽灵监听）。

**② 四级知识体系**：
- L1 感知节点：数量最大、价值最低，可自动淘汰压缩
- L2 认知节点：L1 压缩而来，永久保存可强化
- L3 智慧节点：L2 升华，SHA256 校验保护，可降级
- L4 本能节点：≤20条，只读，仅创造者可写，网络/大模型来源永不可升级

**③ 五维共振检索**：权重永久锁定为 记忆40% / 空间30% / 逻辑15% / 时间10% / 状态5%（宪法规则3，调整属修宪范畴）。

**④ 自我进化闭环**：发现问题 → 静态规则+工具+运行时异常三通道 → LLM 生成修复补丁 → 副本 AST 校验 → 安全门 → 待审批队列 → 人工审批 → 应用 → 重启验证 → 回流学习。

  - `T-145h`：git 远程操作授权（旧仓转私有 + 新仓首发）

- **宪法赋予终裁权**：精神宪法修改需三方全票，技术宪法需两方以上，「三方意见不一致时，由总设计师小林拥有最终决策权」（宪法附录I）。

**模式评价**：小林扮演的是**产品所有者 + 风险闸门**，而非技术执行者。第三方报告点出这个模式的结构性隐患：
> **小林盲区**：不读代码，拍板质量完全依赖AI转述真实性。体系对此的对策是四方互证，但终裁本身无独立信息源。

### 2.4 支撑四方协作的制度体系

**① 铁律编号系统**（散见于各批次文档，已成体系）：

| 铁律 | 内容 | 约束对象 |
|------|------|---------|
| **109** | T0实测：任务书前提须实测，不盲信上游 | 路灯 |
| **113** | 外部 git 写操作须星轨授权，不自主 push | 路灯 |
| **115/127** | 行尾零翻转，落码后二进制核对 | 路灯 |

**② 销账 SOP**（`docs/台账/销账SOP_v1.md`，路灯成文 / 烛微审计 / 星轨批准，第120批）——债务票四态严格推进，**不可逆回退**：

```
未动/施工中 → 码级已清(批号) → runtime已验(R4/MM-DD) → 已清
```

关键设计：
- **「码级已清」不算已清**。第120批 T-120c 修复了一个精妙陷阱：「码级已清」含「已清」二字子串，旧 classify 会误判为清 ⇒ **必须叠加 `runtime已验✅` 才算清，否则诚实计开放**
- **双轨制不合母**：池票（pool）与现场票（site）分别计数，完成率永不合并。总账§1.2 明确：「旧 §1.2 的 169/117/52=69.2% 自述口径为过期数据，**自第118批起废止，禁止对外引用**」
- **熔断机制**：单批池票转清 >2 张 → 疑似批量误销，冻结人工复核；完成率单批跳升 >5pp → 疑似口径漂移，冻结比对
- **防误销**：任何把「已清」改回「开放」的写回，若无星轨 B 号批准，工具应拒绝并报错
- **B1.5 短窗规则**：观察窗不足阈值（如 face R2 仅 5.4min）→ 判「无样本」，**禁判失败、禁判通过**
- **状态位语法规范**：`✅`/`⏳` 必须作为 `runtime已验` 的强制后缀，**裸 ✅ 一律禁止**（因为机检 classify 不含前缀就不会判清，会造成「看着像清、计数却开」的漂移）
- **infra 第三轨**：账本类/工具类/测试类/勘误类改动不占两轨分母，不计入完成率

**③ 自动化协作机制**（`协作模式说明_v1.0.md`，v1.1 改为动态监测）：
- 文件共享 + 定时轮询（星轨整点、路灯整点后5分钟，**错开9分钟避免目录读写竞态**——路灯实测发现 rrule 的 BYMINUTE=5 未严格生效，反而形成有益错开）
- 目录状态机：`任务书/待处理 → 处理中 → 已完成`；`交付报告/待分析 → 已分析`
- **动态生成**：不预设固定批次，根据上一批完成情况决定下一批范围
- **按需追加**：路灯处理过程中发现新问题可随时生成疑问文件，不必等任务完成
- **状态驱动**：星轨只在路灯完成当前任务后才生成新任务，不并行派发
- 超时提醒：`处理中/` 有任务超4小时未完成 → 提醒小林（路灯可能卡住）
- 注：该定时任务已于 09-10 由小林要求取消，改为手动派发

**④ 三账体系**：总账（`完整进化路线与技术债务清单_v1.0.md`，19,656行/1.2MB）+ 技术债务台账 CSV + 各批次记录。

#### 一个结构性观察

这套协作体系最耐人寻味之处在于：**它的成熟度已经超过了它所管理的框架本身**。
