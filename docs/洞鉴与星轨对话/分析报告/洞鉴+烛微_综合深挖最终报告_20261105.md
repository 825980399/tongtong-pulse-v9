## 一、烛微关键论断逐条实测（90%+ 正确）

### 1.1 三套并行控制器公式独立、预算不统一 ✅ 正确

**代码实锤**（全部来自运行中代码）：

| 控制器 | 公式 | 位置 |
|---|---|---|
| `parallel_scheduler._calc_base_parallelism` | `_physical * 1.5`（有物理核时）；无物理核则 `logical * 0.6`；内存 >90% 再 ×0.5 | [parallel_scheduler.py](file:///d:/xinrenlei/tongtong-pulse-v9/nucleus/parallel_scheduler.py) |
| `HybridParallelScheduler._calc_target_processes` | `int(self._physical_cores * 0.5)` ~ `int(self._physical_cores * 0.8)` 区间；`<8GB→min(2), <16GB→min(4)` 内存闸 | [HybridParallelScheduler.py](file:///d:/xinrenlei/tongtong-pulse-v9/nucleus/HybridParallelScheduler.py) |
| `ReasoningWorkerPool` | `max_workers = max(2, int(global_parallelism * 0.75))` | [ReasoningWorkerPool.py](file:///d:/xinrenlei/tongtong-pulse-v9/nucleus/reasoning/ReasoningWorkerPool.py) |

**实测**：16 逻辑 / 8 物理 / 6245MB RSS 机器上，三套控制器会分别算 12/4/8（理想值），但**没有任何代码把这三者相加约束**。

**洞鉴之前完全没碰这一层**。

### 1.2 磁盘 I/O 完全不在自适应回路 ✅ 正确

**代码实锤**：

- PulseTouch 磁盘告警阈值 90%/95% 是**容量百分比**，不是 I/O 压力

**洞鉴之前完全没碰这一层**。

### 1.11 ParallelScheduler._calc_base_parallelism 完整公式 ✅ 已补证

```python
_physical = getattr(self, "_physical_cores", 0) or 0
if _physical > 0:
    _base = max(2, int(_physical * 1.5))   # 物理核 × 1.5
else:
    _base = max(2, int(_logical * 0.6))    # 逻辑核 × 0.6 保底
if _mem_pct is not None and _mem_pct > 90.0:
    _base = max(2, int(_base * 0.5))       # 内存余量校准防 OOM
if getattr(self, "_tier", "high") == "minimal":
    _base = max(2, _base // 2)
return min(_base, self._HARD_FUSE_MAX_PARALLELISM)  # 安全熔断上限
```

**注意**：parallel_scheduler 的 `_physical_cores` 是**外部注入的**（从 hardware_snapshot 里来），不是自己读 psutil。但 HybridParallelScheduler 自己又读 `psutil.cpu_count(logical=False)`。**两套物理核来源**。

### 1.12 活体 memory.is_leak_signal=True ✅ 新发现

**健康快照**：`process_rss_mb=6245.1, growth_mb_per_min=179.667, steady_growth_mb_per_min=6.126, is_leak_signal=True`。这个洞鉴之前没注意过——**活体自报内存泄漏信号**，steady_growth 仍在 6MB/min。
