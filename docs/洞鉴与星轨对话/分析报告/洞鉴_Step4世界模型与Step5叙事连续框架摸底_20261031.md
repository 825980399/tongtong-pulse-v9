### 1.3 预测能力边界（不引入生成模型、不新造分类器）

**方法学适配表**（按事件类型分型，而不是一刀切）：

| 事件 | 节律形态（实测） | 可行方法 | 预测目标（下一分钟粒度） | 判定"预测对"的口径 |
|---|---|---|---|---|
| touch.hardware_snapshot | 严格周期 30s | 周期拟合（均值+漂移） | 下一分钟发生 2 次（±1） | 次数命中 |
| energy.metabolism_snapshot | 严格周期 30s | 同上 | 2 次（±1） | 同上 |
| spinal.inspection_report | 严格周期 40s | 同上 | 1–2 次 | 同上 |
| heart.alive | 准周期 13.4s | 周期拟合 | 4–5 次 | 同上 |
| heart.beat（按"心脏"过滤后） | 待复算（H-01） | 周期拟合 | 次数区间 | 同上 |
| eyes.stream_frame | 0.5s 密集流 | **活跃态二态马尔可夫**（活跃/静默）或计数 | 下一分钟帧数 ∈ [μ−2σ, μ+2σ]，或"流活跃"布尔 | 区间/状态命中 |
| digest.knowledge | 突发批式 | **计数统计**（分时段泊松/均值区间） | 下一分钟条数区间 | 区间命中 |

**关于"预测什么"的裁定建议**：设计文档原文"下一分钟（这些事件周期 30s–300s，不要预测下一秒——只有噪声）"——方向对，但 0.5s 的 eyes 帧和批式的 digest 在"下一分钟"粒度上恰恰**不是噪声而是可统计量**。⇒ Step4 的预测目标应分两型：**周期型预测"次数"，事件型预测"区间/活跃态"**，统一换算成 hit/miss 入台账。

**hit_rate 算法与阈值（建议，均有现成件）**：
1. 算法：`hit_rate(type) = hits(type) / predictions(type)`，滚动 24h 窗口；**直接复用** StreamMiner `_pattern_quality` 的 `{predictions, hits}` 结构（StreamMiner.py:477-503）与 ledger `prefix_hit_rate` 的前缀分桶思路。
2. 容差分级：周期型容差 = ±20% 标称周期（touch/energy ±6s、spinal ±8s、alive ±2.7s），**废弃现 60s 一刀切**（60s 对 0.5s 帧是 120 倍周期，恒命中、无信息）。【矛盾·待修】
3. 阈值三级：样本线 `min_predictions=5`（沿用 config.py:531）；**失配告警线 0.5**（连续 24h hit_rate<0.5 → 发 InsightBoard 告警，类型 `world_model.mismatch`）；模式淘汰线 0.3（沿用 config.py:530 `min_hit_rate`）。告警线高于淘汰线，避免"刚告警就淘汰"。
4. 停机洞处理：空洞段（七事件同步消失）不计 hit 也不计 miss，记 `unverifiable`——与 ledger 三态 verdict 对齐。

**边界外（明确不做，与设计文档 §六一致）**：不做秒级预测、不做 payload 内容预测（只预测"来不来/来几次"，不预测"带来什么"）、不做跨事件因果预测（那是 L4 因果链的领域，见 §1.2-F1）。

## 五、施工路线建议（四批，含依赖关系）

> 与设计文档 §四（批408=F/世界模型、批409=G/叙事连续）兼容；此处把 F/G 各拆两批，给出可验收的最小单元。

### 批410【Step4a · 数据面基线】（无依赖，可立即开工）
1. pulse_pairs 预处理件：organ 过滤（beat 只认"心脏"）、停机洞自动切段、七事件逐日"周期档案"落盘 `data/world_model/event_profiles.json`（标称周期/分桶均值/活跃占空比）。
2. 验收：七事件基线表产出；处理 10/28 全日文件峰值 RSS 增量 <500MB（流式验证）。

### 批411【Step4b · 预测对账上线】（依赖 410 的周期档案）
1. 预测分型：周期型（touch/energy/spinal/alive/beat）预测"下一分钟次数"；事件型（eyes/digest）预测"条数区间/活跃态"。
2. 容差分级 + 按事件类型 hit_rate 滚动 24h 报表 + `world_model.mismatch` 告警入 InsightBoard。
3. 对账点位：分钟级挂 TimeCore 现有 tick；日级并入 04:00 night_orchestration 现有 ledger 段。
4. 验收：连续 48h 七事件 hit_rate 可计算、可落盘、告警通路实测触发一次（可用停采样演练）；violated 零入队（红线回归）。

### 批412【Step5a · 叙事落盘】（与 410/411 可并行）
1. PulseNarrativeSelf 增 persist/load：`data/narrative/narrative_YYYYMMDD.jsonl` append-only；启动回放；连续天数计数器。
2. 阶段判定改"落盘条数+连续天数"（替换 narrative_events<20/<50）。
3. 验收：重启两次，叙事条数与连续天数不归零；jsonl 格式与 ledger 同构可审计。

### 批413【Step5b · 三字段与自我对账】（依赖 412；intent 升级依赖 411）
1. headline 选分器（InsightBoard top1 + 兜底链）、delta 差分器、三句模板摘要。
2. intent：先接 learning_goals（412 后即可）；411 上线后接入预测产出升级内容。
3. intent 次日对账（prev_intent_verdict 三态）+ evidence_refs 全链。
4. 验收：连续 7 天每日 1 条、每条三字段齐、每句有 evidence_ref；阶段三门票"叙事连续≥7天"可读数。
