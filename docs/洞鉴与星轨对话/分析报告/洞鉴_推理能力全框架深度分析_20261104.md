## 二、八个维度逐项分析

### 维度 1｜多步推理链的显式化

**现状（代码证据）**

框架里确实存在"多步"的壳，但都是**固定模板串联**：

1. **深度思考三轮**（[PulseInnerWorld.py#L16397-L16409](file:///d:/xinrenlei/tongtong-pulse-v9/organs/brain/PulseInnerWorld.py#L16397-L16409)）：
   当知识命中时，第一轮"本质追问"直接写死为
   `"从我的知识体系中检索到相关信息：{知识}。从这些知识出发，这个问题的核心涉及以下几个层面的概念交织。"`
   第二/三轮"换个视角""跨领域来看"同样是写死句子（"从框架架构、认知演化、以及实际运行效果三个角度分别审视"）。**无论问什么，三轮内容一字不差**，只是把知识片拼进去。
2. **真多步 v2**（[#L14577](file:///d:/xinrenlei/tongtong-pulse-v9/organs/brain/PulseInnerWorld.py#L14577)、计划日志在 [#L14643](file:///d:/xinrenlei/tongtong-pulse-v9/organs/brain/PulseInnerWorld.py#L14643)）：计划是 `_generate_task_plan` 生成的 **3–4 步固定模板**（理解→检索→整合），每步执行的是"知识检索"而不是"推理变换"；步与步之间只做结果拼接，没有依赖表达式。
3. **主链路出口**（[#L1772-L1828](file:///d:/xinrenlei/tongtong-pulse-v9/organs/brain/PulseInnerWorld.py#L1772-L1828)）：
   `_ir_plan_tools` 的全部决策逻辑 = "复杂度 > 0.4 → 直接推给大模型"，日志 `复杂问题推给大模型: 复杂度=x.xx`。**规划即放弃**。

**现状（日志/数据证据）**
- `真多步推理·计划` 全日志 0 次；`推理 trace` 50 条中 `reasoning_steps` 非空 0 条。
- 真实对话 final method 为 `inference_fallback_to_lung`，一次 LLM 调用返回全文。

**对标差距**
- GPT-4o / Claude 3.5：不显式输出步骤，但能在隐空间完成多跳；曈曈的"多跳"是模板跳。
- DeepSeek-R1：数千 token 的显式长链 + 自我验证；曈曈最多 4 个"检索步"，且不产生中间结论。
- Devin/Claude Agent：plan→act→observe；曈曈有 plan 结构，但 observe 缺失、plan 不驱动 act。

**真实缺陷 vs 设计内**
- 设计内：`ENABLE_TRUE_MULTI_STEP=True`（[config.py#L538](file:///d:/xinrenlei/tongtong-pulse-v9/config.py#L538)）确实开了 v2。
- **真缺陷**：v2 的"步"不是推理步，是检索步；且深度思考文本写死 → 属于"伪 CoT"。

**优先级：P0**

**具体改法**
1. `_generate_task_plan` 改成"由 LLM 生成计划 + 结构校验"，输出每步 `{goal, depends_on, expected_evidence}`；至少 1 步必须是"变换"（比较/排除/量化），不能全是检索。
2. `_deep_think` 三轮改为真正调用一次模型，prompt 强制："先给 3 条候选解释→逐条找反证→再给结论"，并把三阶段结果分别写进 trace。
3. `_ir_plan_tools` 在"推给大模型"前，先跑一次本地链（Symbolic→Causal→Analogy），把本地候选作为提示注入，而不是直接放弃。
