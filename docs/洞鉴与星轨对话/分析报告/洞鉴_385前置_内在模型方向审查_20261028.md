## 一、结论（先看这七条）

1. **L3 现在不存在，但不是空白**。全仓无 `DecideResult`、无决策器实体（A）；但「谁决定做什么」这件事，已经被 **9 个局部决策点**分散承担（第五节）。缺的不是"决策能力"，是**统一结果对象＋统一账本＋跨域仲裁**。
2. **L3 的正确形态是"仲裁者＋记账者"，不是"第二个分类器"**。若按"再做一个意图分类器/再做一套路由"开工，必然长成第二套 QICA（B，烛微 382 同判）。
3. **QICA 不是 L3**：它是 L2 的意图分类器，输出 `intent_type/suggested_method/knowledge_paths`（`nucleus/qica/QICA.py:254、650-660`），PulseCortex 拿它做**单轮对话路由**（`organs/brain/PulseCortex.py:744、931-952、2312-2322`）。它没有跨域、没有预算、没有账本。
4. **PatchManager 自动审批与派单分诊是 L4 的执行策略，不是 L3**：它们的判据写死在补丁域内（`config.py:1370/1376`；`patch_execution_dispatch.py:1526-1536、2532-2533`），L3 只能**调用**它们，不能重写它们。
5. **O3 观察池是"观测仪"，不是"决策器"**：`WATCH_IDS` 只做四条件判定与留痕（`zero_break_judge.py:924、50-111`），它不产生"要不要执行"的决定；把 O3 当 L3 会把观测与裁决混为一谈（A）。
6. **资源面已经有一个"事实上的 L3"**：InfoField 的 L0–L3 分层队列、背压拒绝、降级放行、动态扩缩（`nucleus/field/InfoField.py:276-396、1049、1445-1477`）。**注意撞名**——此 L3 是"脉冲层"，不是"决策层"；新层必须改名（建议 `DL3` / `DEC`），否则日志与代码检索会持续互误（A）。

## 三、重复建设风险：L3 会撞上的五个"已有轮子"

| 已有轮子 | 它在决定什么 | 若 L3 重造会怎样 | 正确关系 |
|---|---|---|---|
| **QICA**（`nucleus/qica/QICA.py:254`） | 一句话属于哪种意图、建议用哪个方法 | 出现"两套意图分类"，阈值/权重/反馈学习分叉 | L3 **只消费** `CLASSIFY_RESULT`（意图＋置信度＋建议方法），不重分类 |
| **PatchManager 自动审批**（`config.py:1370/1376`；`test_corefile_no_autoapprove_m80.py`） | 补丁能不能进池（trust≥40、runtime_verified、核心文件永不自批） | 出现"两套准入"，同一补丁一处过一处不过 | L3 把"是否允许执行"作为**约束输入**，不重判准入 |
| **派单分诊**（`patch_execution_dispatch.py:1526-1536、2360-2388、2532-2533`） | 这一拍选哪一条补丁执行 | 出现"两套派单"，O3 观察位可能被绕开 | L3 可**排序建议**，执行仍走既有分诊闸 |
| **O3 观察池**（`zero_break_judge.py:924`） | 四条件是否同立（观测，不决策） | 把观测当裁决，破零口径被污染 | L3 **订阅**观测结果，不回写判据 |
| **InfoField L0–L3 队列/背压/扩缩**（`InfoField.py:276-396、1445-1477`） | 脉冲排队、拒绝、降级放行、扩缩容 | 两套限流互相打架；且"L3"名称互撞 | L3 **读遥测**（队列深度/拒绝计数/streak），不重造队列 |

**一句话**：这五个轮子都在"做决定"，但都只在**自己的域内**、只输出**布尔或排序**、都**不留统一账本**。L3 的价值就在这三个缺口上，而不是再造一个分类/审批/限流。

## 四、L3 的定位与命名

### 4.1 定位（三句话）

- **域内不夺权**：聊天路由归 QICA/PulseCortex，补丁准入归 PatchManager，派单归 dispatch，限流归 InfoField——L3 不替换它们。
- **跨域才出场**：当两个域**争同一份资源**（LLM 调用预算、CPU/线程、磁盘 IO、用户注意力）或**互相阻塞**（补丁执行 vs 对话响应 vs 审查周期）时，由 L3 仲裁。
- **每次仲裁都留痕**：输出统一 `DecideResult` 并写入决策账本；没有账本的"决定"不算 L3 的决定。

### 4.2 命名（必须改）

`L3` 在本仓已被 `InfoField._PULSE_LAYER_L3` 占用（`InfoField.py:44`，硬上限 100/300）。新层建议命名 **`DL3`（Decision Layer 3）** 或 **`DEC`**，代码前缀 `dec_`，日志前缀 `[DEC]`。**不改名 = 后续每一次 grep「L3」都会同时命中队列与决策，复盘成本翻倍**（A）。

## 六、L3 接口定义草案（2–3 页）

### 6.1 五条设计原则

1. **单写者**：每个 `scope`（chat / patch / resource / schedule）同时只有一个 L3 仲裁者，禁止并行写同一域。
2. **默认拒绝（fail-closed）**：输入缺失、策略版本不明、账本不可写 ⇒ `DEFER`，不得默认放行。
3. **只建议、不执行**：`DecideResult` 是**指令信封**，由既有执行器消费；L3 自身不调 LLM、不改文件、不启停进程。
4. **可解释枚举**：`action` 与 `reason_code` 都是闭集枚举，禁止自由文本，便于统计与回放。
5. **可回放**：同一输入 + 同一 `policy_version` + 同一随机种子，必须复现同一 `DecideResult`（影子模式验收靠这条）。

### 6.2 输入：`DecisionRequest`

| 字段 | 类型 | 必填 | 说明 | 来源 |
|---|---|---|---|---|
| `request_id` | str | 是 | 幂等键（同请求重放不产生第二次决策） | 调用方 |
| `ts` | float | 是 | 决策时刻（epoch 秒） | 调用方 |
| `proc_gen` | str | 是 | `pid@YYYYMMDD-HHMMSS`，用于账本按实例切片 | 框架 |
| `scope` | enum | 是 | `chat` / `patch` / `resource` / `schedule` | 调用方 |
| `candidates` | list | 是 | 候选动作（≥1）；每项含 `id/kind/cost/risk/evidence_ref` | 各域适配器 |
| `signals.l2` | dict | 否 | `intent_type/confidence/suggested_method/knowledge_paths`（取自 QICA） | QICA/PulseCortex |
| `signals.l4` | dict | 否 | `patch_status/applied/trust/risk/blast_radius/evidence_state` | PatchManager/365 链 |
| `signals.resource` | dict | 否 | `queue_depth_by_layer/rejected_count/backpressure_streak/rss_mb/tick_lag_ms` | InfoField/监控 |
| `signals.pool` | dict | 否 | `open_by_severity/oldest_age_s/claimed_last_1h` | 问题池/消费口 |
| `constraints` | dict | 是 | 硬约束：`llm_budget`（本拍允许的调用数）、`forbidden_files`、`max_latency_ms`、`user_override` | 策略/用户 |
| `policy_version` | str | 是 | 策略集版本（如 `dec.v1`）；不同版本的结果**不可混统** | 配置 |
| `epoch` | str | 是 | 决策纪元（按停机窗/重启分代），用于账本分区 | 框架 |

### 6.3 输出：`DecideResult`（唯一结果对象）

| 字段 | 类型 | 说明 |
|---|---|---|
| `decision_id` | str | `dec_<scope>_<ts>_<hash8>`，全局唯一 |
| `request_id` | str | 回指输入，保证 1:1 |
| `action` | enum | **`EXECUTE` / `DEFER` / `REJECT` / `ESCALATE` / `DEGRADE`**（闭集） |
| `target` | str | 被裁决的候选 id（`EXECUTE`/`REJECT` 时必填） |
| `priority` | int 0–100 | 越大越先做；跨域比较只用此字段 |
| `budget` | dict | 放行时授予的预算：`llm_calls / time_ms / max_bytes` |
| `expires_at` | float | 过期即失效（防"陈年决定"被执行） |
| `evidence` | list[str] | 引用证据（日志行号／台账 id／指标键），**不允许为空** |
| `reason_code` | enum | `INTENT_MATCH` / `RESOURCE_PRESSURE` / `BUDGET_EXHAUSTED` / `POLICY_BLOCK` / `EVIDENCE_MISSING` / `STALE_INPUT` / `USER_OVERRIDE` 等 |
| `degrade_policy` | enum | `NONE` / `LOCAL_ONLY` / `DEFER_ONE_TICK` / `DEFER_UNTIL(next_ts)` |
| `rollback` | dict | 回滚句柄（`flag_key` 或 `revert_ref`），`EXECUTE` 必填 |
| `policy_version` | str | 与输入一致；不一致即视为无效结果 |
| `shadow` | bool | 影子模式标记（为 `true` 时，执行器**必须忽略**该结果） |

**示例（影子模式）**：

```json

  "request_id": "req_1792818652_o3",
  "action": "DEFER",
  "target": "o3_b31b31fee790d6e9",
  "priority": 30,
  "budget": {"llm_calls": 0, "time_ms": 0, "max_bytes": 0},
  "expires_at": 1792818722.0,
  "evidence": ["pulse.log:5402", "patch_history:o3_b31b31fee790d6e9"],
  "reason_code": "POLICY_BLOCK",
  "degrade_policy": "DEFER_ONE_TICK",
  "rollback": {},
  "policy_version": "dec.v1",
  "shadow": true

```

### 6.4 决策账本（append-only）

- 路径：`data/decisions/dec_<epoch>.jsonl`（一行一个 `DecideResult` + 输入摘要哈希）。
- 三键索引：`decision_id`（幂等）、`request_id`（1:1）、`target`（可反查某个补丁/条目被裁决过几次）。
- **不可改写**：只允许追加；纠正走"新决策 + `supersedes` 字段"，不删旧行。
- 落盘纪律沿用铁律 182（先算 data → `.tmp` → `os.replace`），写失败即 `DEFER`。

### 6.5 三个域适配器（只包既有函数，不重写）

| 适配器 | 输入 | 内部调用的既有函数 | 输出 |
|---|---|---|---|
| `chat_policy` | QICA 结果 + 置信度 | 现有策略映射（`PulseCortex.py:2535`）＋置信度守卫 | 建议 `LOCAL_ONLY` 或 `EXECUTE`（LLM），带 `llm_budget` |
| `patch_policy` | 候选补丁 + 证据 + 分诊结果 | `select_patch_for_execution` / `select_for_auto_triage`（只读调用） | `priority` 排序建议；执行仍走 dispatch 闸 |
| `resource_policy` | InfoField 遥测 + 内存/RSS | 现有 `_resize_layer_pools_by_level`、`_maybe_memory_restart` 判据（复用阈值，不新造） | `DEGRADE` / `DEFER` 建议；动作仍由原执行器做 |

### 6.6 明确"不做"的红线（反重复建设）

- ❌ 不新写意图分类/关键词通道/语义向量（QICA 已有 8 通道融合，`config.py:333-359`）
- ❌ 不新写补丁准入/证据闸/风险闸（PatchManager 与 338 刀 4 已在做）
- ❌ 不新写破零判据/对账（356 与 O3 已在做）
- ❌ 不新写队列/限流/扩缩（InfoField 已有 L0–L3 与动态扩缩）
- ❌ 不新写进程重启判据（`main.py:3814`）
- ❌ 不引入任何"本地小模型"（小林已裁定不适合曈曈；且显存/延迟墙）
- ✅ 只新写：`DecisionRequest/DecideResult` 两个数据结构、一个账本、三个薄适配器、一个影子开关

## 七、演进路线图（3 步走，从 0.6382 出发）

> 每步都写死：**做什么、验证什么、什么算失败、怎么回滚、谁签字**。三步之间是**串联**，上一步不达标不进下一步。

### Step 1 · 影子 DL3（不改任何行为）

- **做什么**：新建 `dec_shadow` 开关（默认关）；在 3 个点挂只读影子调用——`patch`（每次派单）、`resource`（每 N 拍）、`chat`（每 100 次回答抽样）。只写账本，不改变任何执行。
- **验证（全 A 级可复现）**：
  1. 账本行数 ≥ 影子调用次数（1:1，无丢行）；
  2. `DecideResult` 与既有实现的**一致率**（同 target、同 action 方向）≥ **90%**；
  3. 控制面零写入：开关打开前后，`patch_history`/`pending`/`audit` 的写入计数**完全相同**；
  4. 进程开销：决策耗时 P99 ≤ **5ms**、内存增量 ≤ **20MB**。
- **失败判据**：一致率 < 80% ⇒ 说明我们对既有策略的理解是错的，回到取证，不得进 Step 2。
- **回滚**：关 `dec_shadow` 即归零（无执行面改动，无需重启）。
- **指标**：0.6382 **不要求下降**（噪声 ±0.02 视为持平）；只要求 `overall_llm_share` 不升。
- **签字**：星轨看账本与一致率，小林看"零写入"证据。

### Step 2 · 单域接管：消费口优先级（低风险、有对照）

- **做什么**：`patch_policy` 先只接管**问题池消费口的排序与截断**（现成对照：`audit_problem_pool_consumer.py:128-147` 的 severity→first_seen→dedup_key）。L3 给 `priority`，执行仍由消费口完成；`dec_live_patch` 开关默认关。
- **为什么先选它**：①不碰补丁准入与破零判据；②产出可观测（认领条目数）；③已有排序可做 A/B 对照；④失败了只影响"先做哪条"，不影响"做不做"。
- **验证**：
  1. 认领重复率 = **0**（同一 `dedup_key` 不被两拍重复认领）；
  2. `claim → candidate 工单` 产出率**不低于**接管前的同窗口基线；
  3. 决策可回放：抽 20 条手动重放，`action/priority` 完全一致；
  4. 每拍决策耗时 P99 ≤ **10ms**。
- **失败判据**：重复率 > 0 或产出率下降 > 10% ⇒ 立即关开关，回 Shadow。
- **指标**：0.6382 → **≤ 0.60**（附 `overall_llm_share` 不升）；若下降但 `overall_llm_share` 同升，判"口径搬移"而非进步（B，沿用 338 刀 5 纪律）。
- **签字**：星轨验收，小林批"开 live"。

### Step 3 · 跨域仲裁 + 预算（真正"有内在模型"的门槛）

- **做什么**：把 `chat/patch/resource` 三域纳入同一仲裁：当 LLM 预算、CPU/线程、磁盘 IO 发生冲突时，L3 用统一 `priority` 出 `EXECUTE/DEGRADE/DEFER`；`DEGRADE` 只允许走既有降级面（本地规则通道／`LOCAL_ONLY`／延后一拍）。
- **验证**：
  1. 三域账本覆盖率 **100%**（每次受控动作都能反查到一条 `DecideResult`）；
  2. 越权动作 = **0**（L3 不得直接改文件/启停进程/调 LLM，审计用代码静态检查 + 账本比对）；
  3. 回滚演练 1 次：一键关 `dec_live` 后 60s 内回到 Step 2 行为；
  4. 双指标齐降：`llm_dependency_ratio` **≤ 0.55** 且 `overall_llm_share` **≤ 0.18**；
  5. 决策解释率 100%：每条 `reason_code` 都能指向一条 `evidence`。
- **失败判据**：出现 1 次越权动作即判失败（不是"记一笔警告"）；双指标只降一个 ⇒ 视为口径改善而非能力改善，退回 Step 2 复核。
- **回滚**：`dec_live=0` + 保留账本（账本不删，便于事后复盘）。
- **签字**：小林终裁"是否承认进入内在模型第二阶段"。

### 三个"别做"

1. **别用 0.6382 单指标验收 L3**——它剔除自主进化、且语义判定埋点零计数（383），单看它会把"规则通道变强"误读成"L3 有效"。
2. **别在 Step 1 就接 `chat` 主链**——聊天是用户可感知面，影子阶段只抽样，不进入回答路径。
3. **别把 O3 / 356 对账改成 L3 的输出**——观测与裁决必须分离，否则破零口径会被"仲裁"污染。
