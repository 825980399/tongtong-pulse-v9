## §〇 执行摘要（先给结论）

1. **星轨的六项改造清单存在两处与实态不符的重大信息差**：
   - 改造①"脉冲加时间戳"——**已落地**。`Pulse` 契约已含 `timestamp_ns`（纳秒级）[已查证：nucleus/pulse/PulseCore.py:171, nucleus/pulse_types.py:89]。星轨需要补的只有**幅度字段**。
   - 改造⑤"定时轮询改事件驱动"——**表述失准**。分发层（InfoField）本来就是纯事件驱动（publish→匹配→L0-L3 四线程池异步分发）[已查证：nucleus/field/InfoField.py:109-114]；真正的"轮询"只存在于两处：心跳定时任务表的每拍线性扫描 + TimeCore 周期广播。且 **TimeCore 主动调度接管预留已存在**（`ENABLE_TIMECORE_ACTIVE_SCHEDULE`，心脏已写好让位逻辑）[已查证：organs/body/PulseHeart.py:841-850]。
2. **六项改造不是平行关系，而是一条依赖链**：①幅度/时间戳（脉冲契约）→ ②突触权重表（连接结构）→ ③STDP（基于前两者的在线学习）→ ④LIF（神经元行为模型）。顺序颠倒会造成返工。
3. **④（LIF）与⑥（本地存储）是六项中真正的高风险项**，其余四项均为低风险增量改造。
4. **战略前提必须先钉死**：曈曈 96.94% LLM 依赖度（认知在云端 API），类脑芯片的优势区间（毫秒级事件响应/片上学习/极低功耗静态监听）对"感官-反射弧"层收益最大、对"认知-推理"层收益近零。**类脑化改造的价值锚点在底座，不在大脑。**
5. 建议优先级：**P0 = ①补幅度 + ②权重表空壳；P1 = ⑤任务调度事件化；P2 = ③STDP 实验模块（离线回放）；缓议 = ④LIF（先做影子观测）+ ⑥本地存储（跟随 DataAccessLayer 演进）**。详见 §5。

### 1.1 五维差距对标（曈曈现状 → 类脑目标）

**维度一：神经元模型——差距最大（黑盒规则引擎 vs LIF）**

- 曈曈现状：57 器官全部继承 `BasePulseOrgan`，业务逻辑是 `on_pulse()` 内的 `if/elif` 事件类型分发（黑盒规则引擎）[已查证：base/BasePulseOrgan.py:216-229 抽象方法契约；organs/body/PulseHeart.py:162-196 典型实现]。
- 类脑目标：LIF 模型 = 膜电位随输入电流积分、按时间常数泄漏、越过阈值发放脉冲后进入不应期。
- 差距评估：**这是语义层的差距，不只是参数差距**。把"器官"映射为"类神经元"需要回答：器官的"膜电位"是什么物理量？（待激活任务量？情绪强度？能量水位？）"阈值"是什么？——星轨清单里没有这层映射定义，这是改造④的最大空洞。
- 已有的近似物：器官熔断机制（连续 3 次异常→熔断 60s×指数翻倍冷却）在功能上类似"不应期"的工程实现 [已查证：base/BasePulseOrgan.py:50-56, 518-526]；`on_field_oscillation(frequency, amplitude, phase, field_strength)` 已为 v10.0 振荡场预留接口 [已查证：base/BasePulseOrgan.py:233-236]。
- 改造难度：★★★★★（57 器官行为模型重写）

**维度二：突触权重——结构差（事件类型匹配 vs 权重寻址）**

- 曈曈现状：器官间路由是 `InfoField._match_condition`——优先级过滤 + `event_types` 模式 any 匹配 [已查证：nucleus/field/InfoField.py:2536-2544]；器官通过 `get_resonance_conditions()` 声明订阅 [已查证：base/BasePulseOrgan.py:227-229]。**匹配是二值的（匹配/不匹配），没有权重（强/弱）**。
- 类脑目标：突触权重决定信号传递强度与路由概率——两个神经元连接权重高，一个脉冲更易引发另一个发放。
- 已有的雏形：`HebbianLearner` 已实现 `(node_a, node_b) → weight` 连接表（max 5000 连接，共现窗口 60s 内增强 +0.15、超窗衰减 ×0.0005、低于 0.01 剪枝）[已查证：nucleus/genesis/HebbianLearner.py:47-88]——**但默认关闭（`_enabled=False`）**，且作用于知识节点对，不作用于器官对。`Pulse.memory_dim.hebbian_weight` 字段已预留但恒为 0.0 [已查证：nucleus/pulse/PulseCore.py:177, nucleus/pulse_types.py:46]。`nucleus/synapsys/` 目录 4 文件中 OrganProtocol 已被 157 批封存（"预留-多机/协议未启用"）[已查证：nucleus/synapsys/OrganProtocol.py:2-4 deprecated 标注]。
- 改造难度：★★☆☆☆（空壳权重表 = 纯增量新文件 + 订阅声明处挂权重读口）

**维度三：脉冲编码——雏形已有（JSON 结构化 vs 时间/频率编码）**

- 曈曈现状：脉冲是 JSON dict（`Pulse` TypedDict，15 字段契约）[已查证：nucleus/pulse_types.py:77-97]。payload 承载结构化语义（content/message/emotional_tone 等）。
- 类脑目标：spike 是稀疏离散事件，信息编码在**发放时刻**（时间编码）或**发放频率**（频率编码），幅度只有一维模拟量（Graded 脉冲）。
- 已有的雏形：`FrequencyCodec` 已实现"语义→[0,100] 频率签名"编码（相似语义→相近频率→共振更强），含共振记忆、层级共振统计、Cython 加速 [已查证：nucleus/pulse/FrequencyCodec.py:196-243, 250-326]；`timestamp_ns` 纳秒时间戳已在脉冲契约中 [已查证：PulseCore.py:171]。**缺失的是：时间戳差的消费方（谁在用 Δt 做决策？）和幅度字段本身。**
- 关键判断：**曈曈不应、也不需要放弃 JSON payload**。JSON 语义承载是 LLM 认知层的刚需；类脑编码只需作为**旁路镜像**（同一脉冲同时提取 Δt/幅度喂给权重表），而不是替换。这一判断直接决定改造①的设计形态。
- 改造难度：★☆☆☆☆（加字段）

**维度四：事件驱动——差最后一步（分发已事件化，调度是节拍扫描）**

- 曈曈现状拆解（星轨"heartbeat 定时轮询"的表述需要修正）：
  - **分发层已是纯事件驱动**：`InfoField.publish → 幂等检查 → TTL 校验 → 匹配共振条件 → 风暴检测 → 按 L0-L3 分层线程池异步分发` [已查证：InfoField.py:109-114 类文档与主流程]；器官基类明令"禁止 while True / time.sleep / 长连接" [已查证：BasePulseOrgan.py:26]。
  - **心跳本身也不是 while True 轮询**：`PulseHeart` 用 threading.Timer 自触发脉冲链（beat→处理→再设 Timer），无阻塞循环 [已查证：PulseHeart.py:60-72]。
  - **真正的"轮询"是两处**：(a) `_check_scheduled_tasks()` 每拍线性扫描 21 个定时任务表（knowledge_purge 3600s / immune_scan 600s / metrics_collect 300s 等）[已查证：PulseHeart.py:493-511, 708-840]；(b) TimeCore 每 60s 广播 `time.tick` 并触发托管任务 [已查证：nucleus/chronos/TimeCore.py:25,43,96-119]。
- 类脑目标：无全局时钟，事件到达即计算（LIF 的"无脉冲无计算"）。
- 已有的预留：`ENABLE_TIMECORE_ACTIVE_SCHEDULE` 开关下心脏主动让位托管任务 [已查证：PulseHeart.py:841-850]；`pattern_prediction`/`pattern_prewarm` 周期模式预测预调度已实现（灰度 `ENABLE_STREAMMINER_CONSUMPTION` 默认关）[已查证：InfoField.py:2546-2630]。
- 改造难度：★★☆☆☆（任务表线性扫描换最小堆到期调度 = 局部替换，不动分发层）

**维度五：STDP 在线学习——雏形缺一半（共现增强有，时间差符号无）**

- 曈曈现状：学习体系 = HebbianLearner（赫布共现，默认关）+ 经验池 + 反思器官（事后批量规则提炼）（前序 182-187 批复盘结论，凭记忆摘要·原报告文件已由用户清理）。STDP/LIF/membrane 关键词**全仓 .py 零命中**[已查证：2026-10-13 Grep 全仓扫描]。
- 类脑目标：STDP = 脉冲时间依赖可塑性——pre 先于 post 且 Δt 小→增强，反序→抑制，增强量随 |Δt| 指数衰减。
- 关键洞察：**HebbianLearner 的共现窗口机制在数学结构上是 STDP 的"二值化退化版"**（窗口内=增强、窗外=衰减，丢失了 Δt 的符号与幅度）。从 HebbianLearner 到 STDP 的距离 = 给 `_recent_activations` 记录加上精确 Δt 计算 + 符号分支 + 指数核。**它的数据结构（node_id → last_activation_time）已经为 STDP 铺好了路** [已查证：HebbianLearner.py:64-66]。
- 改造难度：★★★☆☆（实验模块本身不大，难在"在线"——需要脉冲流持续喂入与效果评估闭环）

## §2 六项改造逐项可行性评估

> 改动量口径：批（曈曈现行施工批次单位）；风险口径：对现有 5,336 测试用例与活体运行的影响面。

### ① 脉冲加时间戳+幅度字段
- **实态修正**：时间戳**已完成**（`timestamp_ns` 纳秒 + `time_dim.created_at` 双字段）[已查证：PulseCore.py:171-173]。剩余工作仅**幅度字段**。
- **改动量**：≤½ 批。`Pulse` TypedDict 加 `amplitude: float`（建议进 `state_dim` 或顶层，默认 1.0），`PulseCore.emit` 加可选参数填充，`BasePulseOrgan._emit/_send` 透传。契约声明处已写明"任何新增字段须先在此声明，再改 emit"[已查证：pulse_types.py:80-81]——照既定流程走即可。
- **风险**：低。TypedDict 是编译期检查零运行时开销 [已查证：PulseCore.py:35]；新增可选字段不破坏现有消费方。唯一注意点：`_business_fingerprint` 去重键不含新字段——**是否纳入指纹需裁定**（纳入会改变去重语义，不纳入则幅度不参与幂等）[已查证：PulseCore.py:265-283]。
- **价值**：中。它是③STDP 和④LIF 的**前置契约**——没有幅度，Graded 脉冲语义无从谈起；单独看则对现有行为零增益。**建议与②同批做，避免"只加字段无人消费"的悬空状态。**

### ② 突触权重表（空壳）
- **改动量**：1 批。新建权重表模块（建议落 `nucleus/synapsys/`，与既有 ResonanceEngine 同域），结构 `(source_organ, event_type) → (target_organ, weight)` 或复用 HebbianLearner 连接表形态；读写 API + 持久化挂点（落 data/ 还是内存首版需裁定）+ InfoField._match_condition 处挂**只读旁路**（首版只记录不干预路由）。
- **风险**：低（首版"只写不读"即观测件，不改路由行为——与 199 批影子件同款手法）。
- **价值**：中高。它是③的前置，也是未来"权重寻址路由"的唯一数据基础。空壳阶段的**表结构设计决定未来迁移成本**——建议直接对齐 Lava 突触连接的 (pre, post, weight, delay) 四元组形态，为 §3 第二阶段留接口。
- **⚠️ 待核**：`nucleus/synapsys/ResonanceEngine.py` 未深读（本批未读），其与赫布权重的间接关系标「待核」（HebbianLearner 文档自述"P2阶段通过 ResonanceEngine 间接使用赫布权重"[已查证：HebbianLearner.py:43]）。

### ③ STDP学习实验模块
- **改动量**：1-2 批。核心算法 ≤300 行（Δt 符号分支 + 指数核 + 权重更新），但**实验闭环是大头**：需要离线脉冲回放数据集（pulse_tracer 已有追踪能力 [已查证：BasePulseOrgan.py:309-317 引用 utils/pulse_tracer]）、对照实验设计（STDP 权重 vs HebbianLearner 权重 vs 随机基线）、效果指标定义。
- **风险**：中低。建议**纯离线回放实验**起步（读历史脉冲 trace，不接活体），零运行时风险。在线灰度是后续裁定项。
- **价值**：中。实验性质——验证"曈曈脉冲流里存在可被 STDP 提取的因果结构"。若验证失败（权重无区分度），④LIF 的立项依据将大幅削弱——**它同时是④的可行性探针，这是它真正的战略价值**。
- **依赖**：①（时间戳精度已够，纳秒级）、②（权重表落点）。

### ④ 器官抽象成类神经元（LIF模型）
- **改动量**：**无法整批估**。57 器官逐一回答"膜电位/阈值/不应期映射什么"后才知道。这不是改造，是**建模工程**——先要有 §1.1 维度一说的映射定义文档，才谈施工。
- **风险**：高（六项中最高）。行为模型替换直接改变活体行为节奏；57 器官中 L0 生命线器官（心脏/系统管理）行为变化会全框架放大。
- **价值**：长期高，短期低。LIF 化的收益（毫秒响应/低功耗）只在类脑硬件上有意义，纯 Python 模拟 LIF 只增加计算开销。
- **洞鉴立场**：**建议不立项施工，立项"影子观测"**——选 2-3 个高频器官（心脏/内分泌/兴趣模型）做 LIF 影子模型并行运行（只记录"若 LIF 会何时发放"，不接管行为），用影子数据反推映射定义是否成立。与 199 批影子 v2 手法同源，风险归零。
- **依赖**：③的实验结论（STDP 能否从脉冲流学到有效权重）。

### ⑤ 定时轮询改成事件驱动
- **实态修正**：见 §1.1 维度四——真目标是"任务调度事件化"：`_check_scheduled_tasks` 的 21 任务线性扫描 → 最小堆到期调度；TimeCore 托管任务从"60s tick 触发"→ "到期定时器直接触发"。
- **改动量**：1 批。PulseHeart 任务表 + TimeCore 调度器局部替换，不动 InfoField 分发层、不动器官。
- **风险**：低中。定时语义（错峰 jitter [已查证：PulseHeart.py:698-706]、RUNTIME_PARAMS 热加载 [已查证：PulseHeart.py:74-86]）需原样保留；`ENABLE_TIMECORE_ACTIVE_SCHEDULE` 双路径并存需回归验证。
- **价值**：中（独立于类脑化的普适工程收益）——消除每拍 O(n) 扫描、秒级精度到期。**但要说清：这一刀与"类脑化"关系最弱，即使不搞类脑也值得做。**
- **⚠️ 施工冲突提醒**：工作区已有 200 批 DailyScheduler 挂载刀施工中（git status 可见 nucleus/self_awareness/DailyScheduler.py 改动）[已查证：2026-10-13 git status]——本刀排期须避开 200 批施工面，防止同文件冲突。

### ⑥ 集中式存储改成本地存储

## §3 长远性分析：未来迁移路径

### 3.0 战略前提（必须先裁定）

**曈曈的认知主体是云端 LLM（96.94% LLM 依赖度，前序 197 批口径·凭记忆摘要），类脑芯片无法承载 LLM 推理**。因此"曈曈迁移到类脑芯片"的真实含义只能是：**感官-反射弧层（事件感知→条件反射→节律调度→状态维护）迁移到类脑硬件，认知层留在 LLM**。这恰好与天机芯"混合范式"（SNN 反射 + ANN 认知）的架构哲学同构。

这个前提决定了：所有改造投入的验收锚点应设在**底座层指标**（事件响应延迟、无 LLM 时的自主行为完整度、模拟能耗），而不是"更像大脑"的修辞。

### 3.1 第一阶段：软件模拟类脑（现在-中期）

**最适合先迁移的模块**（按"事件性纯度"排序）：
1. **突触权重表 + HebbianLearner/STDP**——纯数值结构，无 LLM 依赖，Lava 有直接对应物（Process 中的突触连接）。②③做完即自然形成。
2. **心跳节律系统**——心率 7 因素调制 [已查证：PulseHeart.py:514-589] 本质就是"神经元兴奋性调制"的工程版，映射清晰。
3. **反射弧器官**（感官→内分泌→本能反应，器官子集待圈定）——事件驱动度高、无深度认知链。

**工具选型**：Lava（Intel 开源，CPU/GPU 模拟 Loihi 2 语义，免费）为首选；不碰 nxsdk（Loihi 1 时代已弃）。「外部资料·待核」

### 3.2 第二阶段：类脑开发板验证（远期，外部条件依赖）

现在要做的准备（全部是软件侧动作，零硬件采购）：
- **权重表四元组化**（pre/post/weight/delay，见 §2②）——保证 Lava 网络导出零翻译成本。
- **脉冲契约稳定**——①做完后 Pulse 结构冻结版本号，未来硬件侧按契约消费。
- **反射弧子集的最小闭环**——圈定 3-5 个器官组成"可整体上片"的最小系统，而非 57 器官全量幻想。
- **硬件路径预研**（只读调研批）：Loihi 2 走 Intel 研究合作申请（INRC 计划）；国内备选 KA200（灵汐）/ Darwin 系列（浙大）。「外部资料·待核」**该路径需小林拍板是否启动对外接触，洞鉴不越权。**

### 3.3 第三阶段：大规模类脑集群（远期愿景，仅做架构设计预留）

- 器官-神经元分区映射：57 器官 → Loihi 2 的 1024 核分区，需"器官簇"中间抽象（建议以 organs/ 九分区为簇边界 [已查证：微光总览 §1.2]）。
- 跨芯片脉冲 = 网络包：脉冲契约需加网络序列化形态（JSON→二进制脉冲包），**契约里预留 wire format 位是现在唯一值得做的**。
- 认知层（LLM）与反射层（SNN）的接口 = 现在的 InfoField 层级路由——L0/L1 层未来对应硬件侧，L2/L3 层留在云端。**现有分层设计 [已查证：PulseCore.py:39-63] 恰好是未来软硬边界的天然分割线，这是曈曈当前架构对类脑未来最友好的一个特征。**

### 3.4 关键里程碑

| 里程碑 | 内容 | 前置 | 出口判据 |
|---|---|---|---|
| M1 脉冲契约 v2 | 幅度字段 + 契约冻结 | 无（①） | 测试全绿，`Pulse` 版本号落档 |

## §4 风险与隐患分析

### 4.1 改造风险（对现有功能的影响）
- ④LIF 是唯一可能破坏现有功能的改造（行为模型替换）；①②③⑤⑥按本报告设计（增量字段/只读旁路/离线实验/局部替换/DAL 层下切换）均不触碰活体行为主链路。
- 隐患一：**六项并行开工的返工风险**。②权重表若不先定四元组结构，③STDP 和 M6 Lava 导出都要返工。**依赖链纪律比速度重要。**
- 隐患二：脉冲去重语义（`_business_fingerprint`）与新增字段的交互未被星轨清单提及 [已查证：PulseCore.py:265-283]——若幅度参与指纹，同业务事件的去重行为改变。

### 4.2 迁移风险（未来架构不兼容）
- **JSON 语义 → 脉冲编码的信息截断是原理性损失**：spike 只有时刻+幅度，payload 里的 content/emotional_tone 等语义无法上片。混合架构（底座上片+认知留云）是唯一现实解，任何"整体迁移"的预期都应被否定。
- Lava 模拟器与真机存在已知的行为差异（浮点 vs 硬件定点）「外部资料·待核」——M6 的模拟结论不能直接等价 M7 硬件预期。

### 4.3 成本风险（投入产出比）
- 六项全做估算 ≥6-8 批施工 + 实验评估；其中对当下产品力的直接增益接近零（⑤调度事件化除外，它有独立工程价值）。
- 类脑开发板/集群是真金白银 + 对外接触成本，**且第二阶段里程碑 M7 之前所有投入都买不到硬件侧任何回报**——投入曲线与回报曲线的错位期长达数月（按批次节奏推算），小林须在知情前提下拍板。
- 缓解方案：P0 两刀（①②）合计 1.5 批，换取"类脑路径是否继续"的第一手判据（M2 权重表数据 + 后续 M3 实验设计就绪），**先花小钱买决策信息，再决定要不要花大钱**。

### 4.4 技术生态风险（现在投入未来用不上）
- Loihi 2 硬件不对公众零售（研究合作制），Lava 模拟层开源可保软件投入不贬值。「外部资料·待核」
- 国内替代（KA200/Darwin/BrainChip Akida 商用件）存在，但各家工具链互不兼容——**软件侧唯一保值策略是把自家权重表与脉冲契约做成"芯片无关"的中间表示**（这正是 §2② 四元组设计的理由）。
- 类脑芯片商业化进程不确定；若三年内生态仍不成熟，P0+P1 的投入（约 2.5 批）作为架构治理（契约规范/调度优化/权重数据）仍有独立残值，沉没成本可控。**④⑥ 若在 M3 结论前强行开工，沉没风险最大。**

### 4.5 洞鉴补充：星轨清单未覆盖的第五类风险
- **验收标准缺失风险**：六项改造没有一条定义了可测指标（什么叫"更类脑"？）。建议每刀附可测出口判据（见 §3.4 里程碑表），否则类脑化会沦为修辞工程。此风险与 182-187 批复盘发现的"排期表超前一批"倾向同源（前序结论·凭记忆摘要·原报告已清理）。
