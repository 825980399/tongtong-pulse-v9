### 1.3 根因修正（推翻前轮"环挤出"）

**真根因：发射路径双轨制，打点只铺了一条轨。**
- 轨 A（已打点）：`BasePulseOrgan._send` → `pulse_core.emit` →（DEBUG_PULSE_TRACE 门控内）`log_emit` → `info_field.publish`
- 轨 B（**未打点**）：器官直接 `pulse_core.emit(...)` → `info_field.publish(...)`（PulseEyes 实锤；heart.beat 高度疑似同类）——绕过 BasePulseOrgan，自然无 log_emit
- 接收侧打点挂在 `BasePulseOrgan._handle_pulse_safe`（[:502](file:///d:/xinrenlei/tongtong-pulse-v9/base/BasePulseOrgan.py#L502)），**全接收路径覆盖**——所以 receive 全、emit 缺，join 天然断裂。

**对"假孤儿率 8/8=100%"的再解释**：孤儿判定看 emit 的 matched_organs 回填。轨 B 事件本来就不打 emit 点、不进孤儿判定集；真正被判孤儿的是轨 A 低频事件——其 receive 回填依赖环内查找 emit（[pulse_tracer.py:304-317](file:///d:/xinrenlei/tongtong-pulse-v9/utils/pulse_tracer.py#L304-L317)），环容 200 在 7.6/s 速率下驻留仅 ~26s，迟于 26s 的 receive 回填落空 → 假孤儿。**环容对假孤儿有贡献（时延维度），但对 85.8% 未命中无贡献（覆盖维度）**——两个问题的机制不同，需分开修。

## §3 方向三：血管万能接收者之谜

**已破解，性质反转：不是冗余，是设计。**

- **机制**：[PulseBloodVessel.py:132](file:///d:/xinrenlei/tongtong-pulse-v9/organs/body/PulseBloodVessel.py#L132) `"event_types": ["*"]` ——血管**显式通配订阅全部事件**，注释明示"★v24.0修复：订阅所有事件以追踪各器官活跃"。
- **职责**：全器官活跃追踪（[:139-154](file:///d:/xinrenlei/tongtong-pulse-v9/organs/body/PulseBloodVessel.py#L139) `_track_organ_activity`）、沉默器官巡检（[:190-226](file:///d:/xinrenlei/tongtong-pulse-v9/organs/body/PulseBloodVessel.py#L190)，SILENT_ORGAN/ORGAN_ESCALATION 上报）。[:140](file:///d:/xinrenlei/tongtong-pulse-v9/organs/body/PulseBloodVessel.py#L140) 排除心脏/血管/main 自追踪，防自循环。
- **结论：血管 = 系统总线监视器（循环系统承载巡检职能），隐喻与职能自洽，判定为"设计语义明确的万能接收"，非双写冗余。**
- **但对对账口径有真实污染**：167 三元组中几乎每个 (emitter,event) 都被血管 +1，导致——
  1. "消费端频次表"中血管的接收数 ≈ 全部事件数之和，淹没真实业务接收者排名；
  2. 广播扇出统计被虚增 1；
  3. 若未来用三元组做 weight_map 训练源，血管的权重会被系统性高估。
- **建议（选项）**：A——对账/判读工具侧将血管（及同类通配订阅者，若有）列为"系统级接收者"单列剔除，业务扇出按非系统接收者统计；B——维持现状，仅在报告口径中注明；C——改造血管为旁路 tap（不动订阅，改打点归类）。
- **星轨建议：A（工具侧剔除，零代码改动，只动判读口径）。**
