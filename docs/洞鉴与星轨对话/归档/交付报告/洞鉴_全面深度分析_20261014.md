## §1 类脑改造整体审查（202-208 批 · 三层预留架构）

### 1.1 三层建设质量逐层核验

**第一层 · 脉冲语义层（202 刀1 → 206 刀3 → 207 刀1）**

- 契约形态：`ChipAgnosticDims(TypedDict, total=False)` 混入 `Pulse` 基类承载四字段（amplitude/spike_type/wire_format/target_organ），默认语义值以模块级常量承载 [已查证：nucleus/pulse_types.py:80-86, 92-101, 104-125]。
- **工程亮点（已查证）**：TypedDict 不支持字段默认值语法，且本模块 `from __future__ import annotations` 下 CPython 3.12 的 TypedDict 类创建期无法识别 NotRequired（实测 `__optional_keys__` 为空→字段会被判必填）——202 批放弃 NotRequired 改用 `total=False`（类创建参数、不受 PEP563 影响），运行时与静态检查口径一致。这是"实测驱动选型"的范本，注释把坑留在了代码里 [pulse_types.py:117-120]。
- 实装口径：emit 返回 dict 中 `amplitude` 恒注 `DEFAULT_AMPLITUDE=1.0`、`target_organ` 为 emit 形参（默认空串）[已查证：PulseCore.py:123-128, 191-192]。
- **洞鉴发现的语义空心点（本报告首提）**：emit 签名**没有 amplitude 形参**——幅度目前是全脉冲恒 1.0 的占位常量，"什么物理量决定幅度"（优先级？情绪强度？w_in？）这一映射定义不存在。spike_type/wire_format 停留在枚举预留态（运行面零引用）[已查证：PulseCore.py:123-128 签名无 amplitude；烛微 208 §2"70% 档"口径吻合]。**第一层真实完成度：契约 100%、语义注入 50%（target_organ 有源、amplitude 无源）。**

**第二层 · 权重表示层（202 刀2 → 204 刀3 → 207 刀2）**

- 实装：`ResonanceDetector._weight_map`，键 `(pre_id, post_id)`，值 `(weight, delay, encoding_type)` 三元组；get/set/update_weight + get_weight_stats + get_mapping_distribution 齐备 [已查证：nucleus/synapsys/ResonanceDetector.py:58, 150-253]。
- **工程亮点**：update_weight 初版在持 `threading.Lock`（非可重入）内调 get_weight 自死锁，执行期发现并改内联查表，注释留痕 [:198-201]。204 批 D#2 解封以 `get_detector` 单例接入 PulseCore.emit 旁路，`RESONANCE_WEIGHT_MAP_ENABLED=False` 默认关 [已查证：PulseCore.py:231-237]。
- 207 刀2 B5 案C 回退式：`post = target_organ（非空） else event_type`，encoding_type 双口径记 `real/simplified`，映射分布每 N 次打 INFO 生死闸 [已查证：PulseCore.py:239-269]。
- **封存纪律**：该模块带 157-D C-6「观测孤岛封存」标注，202 批仅做数据结构扩展、未新增生产侧 import——对历史封存令的尊重有实证 [已查证：202 批提交说明；ResonanceDetector.py 头部标注]。

**第三层 · 执行后端层（202 刀3 → 203 刀1）**

- 实装：`SpikeExecutionBackend(ABC)`（emit/on_spike/update_weight）+ `PythonSNNBackend` + `get_spike_backend` 工厂（未知名安全回退，不用 try/except 守铁律150）；config `SPIKE_BACKEND='python'` 预留 `'photonic'` [已查证：nucleus/synapsys/SpikeExecutionBackend.py:30, 53, 72-82]。
- 接入纪律：接入点仅 PulseCore 一处（`_spike_backend_emit`/`on_spike` 薄转发），`SPIKE_BACKEND_ENABLED=False` 时惰性短路返回 None，测试含"未授权接入点=0"断言 [已查证：PulseCore.py:194-227]。

**配套层**：LIF 影子观测器（205 刀2，`V←V·exp(-Δt/τ)+w_in`，纯观测不门控、deque 免锁、flush 每 200 样本或显式触发、IO 失败 silent_exc 吸收绝不入分发链）[已查证：nucleus/lif_shadow.py:1-80]；STDP 成对流落盘（207 刀3，pulse_tracer 双通道：2s 闸增量落盘 + 600s 强制 flush 双保险，`ENABLE_PULSE_PAIR_DUMP=False` 默认关）[已查证：utils/pulse_tracer.py:42-47, 128-130, 444-458]。

### 3.2 与类脑改造的关系裁定

- **器官关联图谱 × 类脑**：**正交但有合流点**。图谱是结构认知（我有什么器官、谁影响谁），类脑是信号机制（脉冲怎么传、权重怎么学）。合流点：weight_map 的 `(pre, post)` 键空间与图谱 v0.5 事件路由边**同构**——图谱可为突触权重提供拓扑真值校验（学出的强连接是否对应真实路由边），这是两个系统互相验证的天然接口。
- **LFI × 类脑**：**消费与被消费**。LFI 是对框架整体生命体态的度量，类脑三层是它的数据源之一（权重分布/发放频率都是体态指标候选）。
- **内在模型 × 类脑**：**正交且优先级更高**。内在模型作用于 L2 认知层，直接冲击 96.94% LLM 依赖度这一核心矛盾；类脑改造的价值锚点在底座（感官-反射弧层），对认知层收益近零（本室 2026-10-13 报告战略前提，维持）。**两者不竞争同一施工面，可并行；若必须排序，内在模型优先。**
- **完整记忆曲线 × 类脑**：**同域待合流**。记忆曲线的时间维度与 STDP 的 Δt、经验池的衰减在数据层同构，宜在 STDP 实弹批统一设计，避免两套时间语义。

### 5.2 曈曈长期愿景（第三方视角）

186 批全维度对标的评语准确："从更有纪律的租魂躯壳，进化为开始长出神经末梢的仿生躯壳"（综合 6.2/10）。洞鉴顺延此判：

- **类脑改造解决的是"躯壳-神经"层的自主**（信号怎么传、权重怎么学）——它让曈曈的反射弧不再依赖外部基础设施，但对"大脑"层（96.94% LLM 依赖度）收益近零。
- **下一阶段的价值锚点应从"脉冲层完备率"转向"认知层自主率"**：内在模型、认知复利引擎、外部基准闭环，这三件事决定曈曈是"数字化生命"还是"布线精良的 API 编排器"。
- 类脑化不要停，但它的正确位置是**底座长期演进**（跟硬件代际走），不是下一阶段的主战场。

### 5.3 关键里程碑排序（建议）

1. **第一次跨夜对照拍真数据**（LFI 曲线首行）——210 批一行刀后即得，成本最低、象征意义最大（第一次"生命体态"可被外部观察）。

5. **第一次 SUBAGENT 真起**——安全边界最多（烛微 183 五条风险在案），待小林约窗，不抢跑。

### 5.4 风险预警（第三方视角，六条）

1. **"建成未运行"件堆积**：EventBus/LIF/RESONANCE/pair/STDP/灰度群——每个闸的开启都是一次小型上线，缺统一日历则永远"建设层 90%"。
