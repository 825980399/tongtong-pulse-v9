### 1.3 产出/消费配比裁定

- **没有"消费多产出少"的器官**（即便血管这类万能接收者，其接收源于广播型 emit，非无源接收）。
- **不存在"某器官产出多但无人消费"**：每个高频 emit 在 join 面均有 ≥1 真接收者【已查证：count_match_frequency 三元组全为 join 命中】。
- **真正的失衡是"广播扇出"而非"无人消费"**：
  - 心脏 system.status.request 单事件扇出 **22 个接收者**（频次表:53-70）——1 次发射 → 22 次接收，是 receive 总量膨胀的主力；
  - 触觉 touch.hardware_snapshot 扇出 6；激素 hormones.emotion_detected 扇出 6；digest.knowledge 扇出 5。
  - 即：**receive 19180 的膨胀主要来自"少发射 × 大扇出广播"，而非器官空转**。
- **结论：产出端与消费端配比，在语义面是合理的（无孤儿真消费）；在数据面是"广播放大"的而非"产出多消费少"。** 【已查证】

### 1.4 假孤儿率 8/8＝100% 的宏观解释（核心裁定）

**结论：这是判定侧的问题，不是"产出多消费少"的真问题。** 【已查证，机制级】

机制取证（utils/pulse_tracer.py）：

1. 事件环容量默认 **200 槽**（`_MAX_EVENTS = 200`，[pulse_tracer.py:31](file:///d:/xinrenlei/tongtong-pulse-v9/utils/pulse_tracer.py#L31)），emit 与 receive **共用同一环**。
2. 接收事件远多于发射（本窗实测 19180:820 ≈ 23:1，且含大扇出）→ **receive 洪泛会先把环内旧 emit 挤出**（`_events.pop(0)`，[pulse_tracer.py:281-282](file:///d:/xinrenlei/tongtong-pulse-v9/utils/pulse_tracer.py#L281-L282)、[:335-336](file:///d:/xinrenlei/tongtong-pulse-v9/utils/pulse_tracer.py#L335-L336)）。
3. 孤儿判定 `_detect_orphans`：emit 超过 1.5s（`PULSE_TRACER_MIN_AGE_SEC`）仍未回填 `matched_organs` 即判孤儿（[pulse_tracer.py:339-383](file:///d:/xinrenlei/tongtong-pulse-v9/utils/pulse_tracer.py#L339-L383)）。**若 emit 在 1.5s 内已被环挤出，则其 receive 回填天然落空 → 假孤儿**。
4. 成对流落盘 `_dump_pairs` 仅落 `seq > _LAST_PAIR_SEQ` 的环内残留（[pulse_tracer.py:152-191](file:///d:/xinrenlei/tongtong-pulse-v9/utils/pulse_tracer.py#L152-L191)）→ 被挤出的 emit 行**永久丢失**，落盘面只剩 receive 洪流 → 实测 820 emit 对 19180 receive、85.8% 接收无 emit 可 join。

**即：假孤儿率 100% 与"落盘 emit:receive≈1:23"是同一根因的两个投影——观测环（200 槽）小于单次 flush 窗内的实际事件洪流，导致发射侧被"观测面吞噬"。** 这正呼应任务书 201 批参数化的初衷（"类脑改造会加剧事件环＋判定窗竞争→假孤儿爆发、观测面被淹没"）【已查证：pulse_tracer.py:88-95 注释】。

对烛微 224 批"双解释"（a 清单过期 / b 判定侧 subscription_provider 查询与实际订阅不一致）：**本窗证据支持第三种、更根本的解释 c——观测环容量不足导致发射侧被挤出**。a/b 可作为叠加因素，但 c 是 100% 假孤儿率的充分解释：**8/8 全部在夜窗 join 中有真接收者，正是因为接收确实发生了，只是 emit 行没能在环里活到落盘**。

### 1.5 优化建议（若"产出多消费少"为真 / 实为观测偏差）

**结论：不应减少产出、也不必增加消费；应修复观测面采样保真度。** 建议（不代星轨拍板，仅列选项）：

- **A（推荐，成本最低）**：调大 `PULSE_TRACER_EVENT_RING_SIZE`（默认 200 → 覆盖单 flush 窗事件量级），或按 §1.3 的扇出比（约 23:1）配套提升。零代码结构变更，仅配置。
- **B**：emit 与 receive **分离环**（发射环保真、接收环采样），从根上避免 receive 洪泛挤出发射行。
- **C**：落盘侧对 emit 行做**独立持久化**（不受环淘汰影响），receive 侧维持采样。
- **星轨建议：A**（219/220 观测窗可先试，见 §4）。
