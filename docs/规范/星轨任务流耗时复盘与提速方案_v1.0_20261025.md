# 星轨任务流耗时复盘与提速方案 v1.0（2026-10-25）

> 起因：小林提问「近几次任务完成耗时这么久」，要求星轨整理自己的任务流、归因并给出提速方案。
> 本件由星轨基于**本会话实测产物**（探针脚本、结果件、git 提交链、两轮时间戳）自省形成，不是泛泛检讨；必要纪律耗时与可压缩冗余分开列，不甩锅、也不砍事故防线。
> 定位：`docs\规范\` 体系件，与《星轨任务流自检规范 v1.0_20261024》配套；本件只改星轨自己的工作方式，不触碰生产代码、不进 CI 门禁链。

## 一、数据口径（先讲清楚怎么算的，避免误读）

- **统计窗口**：本会话 workspace 临时探针与结果件，时间跨度 10-24 13:19 → 10-25 12:39；git 近 30 笔提交链分类对照。
- **时间口径**：`git commit` 时间戳＝入库点，**不含**提交前的准备、回读、返工；探针件时间戳＝准备动作发生点。窗口内包含路灯施工等待、小林裁决等待、夜间停机，**不等同纯工作时长**，本报告只比较星轨动作内部的结构冗余，不计算"人效工时"。
- **边界**：364 事故（误带他方件入库、锚点漂移、状态机不同步）固化下来的纪律动作属于**必要耗时**，本报告明确保留；只压缩重复、碎化、返工、上下文膨胀四类冗余。

## 三、归因（六条；3.1–3.5 为可压缩冗余，3.6 为必要纪律）

### 3.1 工具零沉淀：同类动作每批从零拼探针（主因）

- **证据**：375 个 .py 中，台账分布/到期未裁/逾期/九列异常、三门禁复跑、BOM/CRLF/表格列数校验、git 暂存隔离核对这四类动作，每批都重新写一遍；`tools/ci/` 下只有生产门禁脚本，**星轨自用的台账快照、体例校验、隔离提交工具为空白**。
- **机制**：铁律要求"临时脚本一律写 .py 再跑、不 heredoc"，方向正确；但执行上把"一次性临时脚本"当成了唯一形态，没有把重复出现的动作沉淀成可复用工具，导致 101 件只读探查＋95 件校验回读＝约 196 个"写脚本 → 跑 → 落 txt → Read"四步循环。
- **可压缩度**：高。同类只读与校验动作一次工具化后，每批只传参数调用，不再写脚本。

### 3.2 T0 与成文割裂：先成文后发现问题，53 件返工修补

- **证据**：fix_draft363 a–d 共 4 轮；fix365 a–f 共 6 轮；另有 fix_evidence/fix_backlog/fix_ledger/fix_blank/fix_order/fix_refs 等。返工内容集中在四类：体例（BOM/LF/CRLF）、表格列数不一致、字段真名写错（risk/trust 旧名 vs risk_level/trust_score 真名）、锚点行号漂移。
- **机制**：自检规范 C2 要求"写任务书前先自己做 T0 核对 HEAD 行号/现状"，执行上 T0 探针与成文割裂——先凭记忆/前序摘要生成草案，成文后才回读发现锚点、字段、体例不对，再逐轮回炉。365 冻结轮 36 分钟里返工 7 轮占约 5 分钟，且每轮返工都要重跑一遍校验链。
- **可压缩度**：高。T0 快照在草案生成前一次完成、结果直接进草案证据段；成文后只做终检，不再返工锚点与字段。

### 3.3 校验链分散重复：同一批门禁/回读跑多轮，无一体化收尾

- **证据**：gates 前缀 8 轮、verify_ledger 6 轮、final_check 3 轮；365 冻结轮内 gates365_freeze → gates365_refresh → final365_freeze → final365_check → final365_verify → final365_gate 共 6 轮门禁/回读；364 核验轮 gates364 → gates364b → gates364c 共 3 轮。
- **机制**：规范要求"改前备份、改后校验、提交前后双核对"，方向正确；但缺少一个排发轮/核验轮一体化收尾脚本，台账写入、备份、三门禁、体例校验、映射回读、终检报告各自单独跑、单独落结果、单独 Read，同一事实被校验 3–6 遍。
- **可压缩度**：中高。合并为两轮：写入前 1 轮只读基线、提交后 1 轮终检汇总；中间步骤不再单独复跑。

### 3.4 大结果件全量落盘再回读：上下文膨胀 → 交接 → 重新探查的恶性循环

- **证据**：结果件 6.2 MB 中，log356c.txt 约 2.5 MB、deep10_out 641 KB、deep3_out 208 KB、deep5_out 164 KB、deep11_out 161 KB；10-24 16 时 51 件/3.78 MB、18 时 83 件、19 时 69 件，10-25 11 时 89 件，均为上下文变重后的反复定位窗口；11:43、11:45 两笔交接件即窗口过重被迫交接。
- **机制**：日志/台账类探针默认把原始大表全量 dump 到 txt 再 Read 进上下文，没有"先聚合统计（计数/分布/异常样本截断 N 行）"的默认口径；上下文灌满后触发交接，新窗口又从头探查一遍，形成循环。
- **可压缩度**：高。默认只回聚合结论与截断样本；原始大表落临时件备查，需要细节再定点取段。

### 3.5 轮次切分过细：裁决轮与冻结轮台账两遍读写

- **证据**：365 生命周期中，12:00–12:07 裁决轮已做台账快照、入册 406 行、门禁复跑；12:25–12:30 冻结轮又回读 18 条在册票全字段、改 L339 到期批次、新立 T1、重锚两基线、门禁再复跑。
- **机制**：E1/E2 避让纪律（施工方在工不撞车、文件级核销让到核验轮）本身正确；但在"小林同一轮连续拍板（三项裁决 → 生成正式书）"的场景下，裁决轮与冻结轮之间没有施工方介入，两遍扫描属于重复劳动。基线也在两轮各重锚一次。
- **可压缩度**：中。同轮连续拍板时台账状态推进一次完成、基线只重锚一次；施工方在工场景仍按 E1 避让，不放松。

### 3.6 必要纪律耗时（保留，不纳入压缩指标）

以下动作是 364 事故与规范固化的防线，**不得为提速砍掉**：

- 改登记册/基线前 `git status` 避让在工件、改前备份、改后校验记录数＝期望值；
- CSV 与基线 JSON 不同笔提交、基线走 `[ci-gate-change]` 独立 commit、docs 业务件隔离 commit；
- 提交前 `git diff --cached --name-only` 核对、提交后 `git show --stat HEAD` 复核；
- 完成态三态区分（static_verified / fixed / live verified）、跨批遗留逐条三选一、停机项醒目标注提前告知小林；
- 台账结论独立回读，不看路灯/烛微报告自称。

## 四、提速方案（P0 立即见效 / P1 流程收敛 / P2 上下文治理）

### 4.1 P0 · 沉淀五个星轨自用工具（消除 3.1、3.3 的重复写脚本）

新建 `tools/xingrui/` 目录（**自用辅助工具，不进 tools/ci 门禁链、不被生产代码 import、不写 data/、不改 config**）：

| 工具 | 替代现状 | 输出口径 |
|---|---|---|
| `ledger_snapshot.py` | 台账分布/到期未裁/逾期/九列异常/在册票全字段等 101 件只读探针 | 一次输出结构化结论；P 级/批次/状态分布＋异常清单＋指定票号全字段 |
| `gates_run.py` | gates 前缀 8 轮分散复跑 | M1/M2/M3 顺序执行，汇总 PASS/FAIL 与关键计数，非零退出码 |
| `doc_style.py` | csv_style/final_check 等体例探针 | BOM 标记、CRLF/LF、表格列数、行数/字节数一键校验，返回不符项清单 |
| `isolate_commit.py` | commit 前后 status 来回核对、手工退暂存 | 入参为本笔文件清单 → 退暂存他方件 → 精确 add → cached 核对 → 提交 → show --stat 复核，落实 E5 双保险 |
| `freeze_round.py` | 冻结/核验轮 6 轮分散收尾 | 台账状态推进 → 改前备份（sha/行数落账）→ 三门禁 → 体例校验 → 映射回读 → 终检报告，一轮跑完 |

### 4.2 P1 · 流程收敛（消除 3.2、3.5）

1. **T0 前置合并**：草案生成前先跑 `ledger_snapshot.py`＋锚点/开关/池台账只读快照，结果一次写入草案证据段；成文后只终检，不再返工锚点行号与字段真名。单批返工件目标 ≤10 件（本轮 53 件为基线）。
2. **轮次合并口径**：同一轮内小林连续完成"裁决 → 拍板方案 → 生成正式书"且施工方未在改台账时，台账状态推进一次完成、基线只重锚一次；施工方在工场景仍按 E1 避让不放松。
3. **日志探针默认聚合**：只输出计数、分布、Top 异常样本（截断 50 行）；原始大表写临时件备查，需要细节再定点取段，不 Read 进上下文。

### 4.3 P2 · 上下文治理（消除 3.4 恶性循环）

1. **每轮收尾清场**：本批 .txt 结果件中，证据件复制入库 `docs\路灯与星轨对话\交付报告\证据件\`，其余临时件当轮删除，workspace 不跨批堆积；工具脚本留在 `tools/xingrui/` 长期复用。
2. **提前交接**：长窗/多角色批次上下文接近饱和时，按自检规范第七节主动建议新窗口；交接件只带 `ledger_snapshot.py` 输出的一页状态＋规范指针，不复制大段报告，新窗口不重跑全量探查。
