# 逻辑断链与逻辑冲突防控规范 v1.0

> 签发：星轨 ｜ 2026-09-30 ｜ 依据：小林拍板"后面无论技术债偿还/新功能推进/设计文件落地，都须落实真实情况，尽量减少逻辑断链与逻辑冲突"
> 触发背景：全框架断链审查（烛微/微光双轨）确认 21 项"机制齐全但生产零调用"断链——主因：先建机制后接线被遗忘、重构替代未清理、标注封存成常态、测试面不校验调用链

## 一、总原则（三选一，禁止灰色地带）

**任何机制（类/引擎/注册入口/工具/脚本/配置开关），在任何批次被引入或触碰时，必须处于且仅处于三种状态之一：**

| 状态 | 判定 | 处置 |
|---|---|---|
| **① 已接线** | 有生产调用点 + 消费方 + 触发路径 | 正常维护 |
| **② 已删除** | 确认无价值/冗余 | 随批次删除（走迁移归档原则） |
| **③ 明确弃用标注** | 规划中/测试专用/暂缓 | 代码注释 + 总账登记，**标注"弃用-原因-拟接线批次"**，不得只标"封存"了事 |

**禁止**：机制存在、既无调用点、又无弃用标注的"灰色地带"（本次 21 项断链的成因）。

## 二、五条可执行规则

### R1 · 设计文件必须声明接线点（新功能/设计落地）
- 任何设计文档在描述机制时，**必须同时声明**：生产接线点（谁调用）、消费方（谁受益）、触发路径（何时触发）
- 无接线点的机制，文档中必须标注"规划中"或"弃用"，不得以"预留"模糊带过
- 落地验收时，**按文档接线点逐项核对调用链**（diff + grep 实证），接线点缺失即验收不通过

### R2 · 触碰即修（技术债偿还）
- 批次施工**改到任何机制时**，必须顺手核对该机制的调用链：
  - 发现断链 → 当场三选一（接线/删除/标注），**不得原样放过**
- 偿还类批次的交付报告增加一栏：**"本批触碰机制的调用链核对结果"**

### R3 · 断链零增量（批次门禁）
- 每批交付报告自证：**"本批引入的机制断链增量 = 0"**（新机制无接线点 = 违规）
- 星轨验收时对关键机制做调用点抽查（`grep 定义 vs 调用`），发现断链增量 → 打回补接或标注

### R4 · 职责重叠先裁决再实施（冲突防控）
- 新机制与既有机制职责重叠时（如 OrganCoordinator vs main.py 器官生命周期），**必须先裁决"取代/并存/弃用旧"再实施**，不得并存含混
- 裁决结果写入任务书与交付报告，避免同类重复建设

### R5 · 测试补"调用链维度"
- 关键机制（调度/工具/脚本/注册入口）的测试，除行为单测外，**增加"生产接线测试"**（断言存在生产调用点或明确弃用标注）
- 防止"机制单测全绿、生产零调用"通过全部门禁（本次 21 项断链的门禁盲区）

## 三、验收清单（星轨验收固定项）

每批交付报告必须包含：
1. 本批引入/触碰机制清单
2. 各机制三选一状态（接线点/删除/弃用标注）
3. 断链增量自证（=0 或逐项说明）
4. 职责重叠裁决记录（如有）

## 四、与现有机制的衔接

- 断链修复批：21 项初判配额（12 接 + 3 删 + 6 标）经 157 前置分析实测修订为 **①接线 6 + ②删除 4 + ③标注 14**（2026-10-01 星轨裁决 Q158-4：以实测为准）；按本规范三选一执行
- 156 批任务书模板：加入本规范"验收清单"四项
- 后续所有任务书：固定章节"逻辑断链防控"（引用本规范）
