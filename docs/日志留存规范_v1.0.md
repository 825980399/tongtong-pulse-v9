# 日志留存规范 v1.0

**编制**：路灯　**依据**：第42批 T1 根因分析（P1 级裁决）　**日期**：2026-09-13
**适用范围**：`logs/` 目录下的全部日志文件（重点 `pulse.log`）

---

## 一、为什么要立这条规范

第42批 T1 取证结论（三项证据）：

1. `logs/pulse.log` 的 **`ctime` 自 09-03 起未变** —— 对照实验证明
   `truncate`（原地清空）**不改** ctime，而 `delete` + 重建**会改**；
2. 文件内 **22190 条时间戳全部属于当日**（无任何旧内容残留）；
3. 框架代码（AST 全库扫描）、项目脚本、计划任务**三处均无**清理逻辑，
   `RotatingFileHandler(maxBytes=10MB/backupCount=5)` 经模拟实验验证**完全正常**。

⇒ **日志内容是被「外部原地清空」的**（典型形态：`> logs/pulse.log` 重定向、
PowerShell `Clear-Content`、编辑器"另存"覆盖）。

**直接后果**：第41批 T1 的历史回填率仅 **1.8%**（因为补丁窗口内的日志已不存在），
所有依赖日志的离线分析（进化真实基线、日志级别统计、错误归因）**全部失真**。

---

## 二、★核心规范：不要手动清空 `pulse.log`

| 做法 | 评价 |
|---|---|
| ❌ `> logs\pulse.log` / `type nul > logs\pulse.log` | **禁止**（原地清空，ctime 不变，历史无法追溯） |
| ❌ PowerShell `Clear-Content logs\pulse.log` | **禁止**（同上） |
| ❌ 用编辑器打开后"保存" | **禁止**（等价于原地重写） |
| ❌ `del logs\*.log` | **禁止**（连轮转备份一起删） |
| ✅ 什么都不做，让框架自己轮转 | **推荐**（`maxBytes=10MB` / `backupCount=5` 已配置好） |
| ✅ 需要"只看本次运行"时，用 `grep`/时间过滤，或**重命名**旧文件（`mv pulse.log pulse.old1`） | **推荐**（保留证据） |

## 三、框架侧的留存机制（已实现）

### 3.1 轮转（既有，第42批验证）

```
RotatingFileHandler(pulse.log, maxBytes=10MB, backupCount=5)
```

实测日志速率约 **0.5 MB/小时** → 约 **20 小时**触发一次轮转，
产生 `pulse.log.1 … pulse.log.5`，第 6 次轮转时淘汰最旧的 `.5`。

### 3.2 超期清理（第42批 T1 新增）

| 配置 | 默认 | 说明 |
|---|---|---|
| `ENABLE_LOG_RETENTION_CLEANUP` | `True` | 启动时清理超期日志 |
| `LOG_RETENTION_DAYS` | `7` | 只删除 **mtime 超过 7 天**的 `*.log` / `*.log.N` |
| `LOG_RETENTION_PROTECT` | `["pulse_crash.log"]` | 保护名单，**永不自动删除** |

★ **只按 mtime 判定** —— 正在写入的文件 mtime 恒为当下，**永不会被删**。

### 3.3 ★完整性留痕（第42批 T1 新增，关键取证能力）

启动时比对 `logs/.log_state.json`（上次的 size / ino）：

| 现象 | 判定 | 动作 |
|---|---|---|
| 当前 size < 上次 size | `truncated`（★被原地清空） | 写留痕 + WARNING |
| ino 变化 | `replaced`（被删除后重建） | 写留痕 + WARNING |
| 文件不存在 | `missing` | 写留痕 + WARNING |

事件写入**独立文件** `logs/log_integrity_events.log`（独立是为了不随主日志一起被清空）。

**⇒ 下次再发生"日志消失"，可精确定位到「时刻 + 幅度」。**

## 四、发现日志异常时的处置流程

1. **查留痕**：`type logs\log_integrity_events.log`
   - 有 `truncated` 事件 → 确认被外部清空，事件里的 `time` 即发生时刻
   - 无事件 → 可能是首次运行（状态文件尚未建立）或 `logs/` 被整体删除
2. **查同目录其他文件**：若 `param_reports/`、`config_changes.log` 完好
   → 说明**只清了 pulse.log**（不是整体清理）
3. **查 ctime**：
   ```python
   import os, time
   st = os.stat("logs/pulse.log")
   print(time.ctime(st.st_ctime), time.ctime(st.st_mtime))
   ```
   `ctime` 远早于首行内容时间 ⇒ 原地截断
4. **登记债务**并在下次批次复核
