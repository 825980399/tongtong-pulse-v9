## 第一章 模型到底是什么

### 1.1 一句话定义

**模型 = 一个"输入→输出"的计算函数，函数里的参数不是人写的，而是用数据自动调出来的。**

对照着理解您项目里的三种"会回答问题的东西"：

| 类型 | 例子 | 规则谁定的 | 会不会学习 |
|------|------|-----------|-----------|
| **规则代码** | 情绪检测：句子含"高兴"就判为喜悦（PulseHormones.py:844） | 人写死的 | 永远不变 |
| **统计小模型** | 您计划孕育的意图分类器 | 数据里"学"出来的 | 可以随新数据重训 |
| **大模型** | DeepSeek | 海量数据训练+昂贵算力 | 您这边不能训，只能调用 |

一句话记住区别：**规则是"人告诉它答案"，小模型是"从例子里猜规律"，大模型是"读了整个互联网后什么都会一点"**。

### 1.2 为什么要"孕育"小模型（回顾您的计划）

您项目的智能97%租自外部大模型——每次思考都要付钱、要联网、要等十几秒。小模型的价值：**把高频、简单、重复的判断收回到本地**，毫秒级、零成本、断网也能活。就像人：思考用大脑（慢、贵），但"手碰到烫的会缩回"用脊髓反射（快、免费）——您计划的正是给曈曈造**反射弧**。

### 1.3 一个最容易搞混的概念：缓存不是模型

您的孕育计划里，"语义缓存器"（相似问题直接返回历史答案）**不是模型**——它不学习，只是"查找+比对"。它更像您经验库的升级版。分清这个很重要，因为：

- 缓存：实现容易、见效快、不会变聪明 → **先做**
- 小模型：需要数据训练、会随数据变聪明 → **缓一步做**

## 第二章 数据结构——模型的"粮食"长什么样

### 2.1 最基本的结构：样本

模型吃的每一口粮食叫一个**样本（sample）**，标准结构是三件套：

```
样本 = { 特征(X) + 标签(Y) + 元信息 }
```

用您的意图分类器举例，一条真实样本长这样：

| 部分 | 内容 | 说明 |
|------|------|------|
| **特征 X** | "你是谁" | 输入：用户的原话 |
| **标签 Y** | `identity_query`（身份询问） | 输出：这句话属于哪类意图 |
| 元信息 | origin=user_query, ts=... | 来源、时间——**用于过滤和追溯** |

一批样本摞在一起，就是**数据集（dataset）**——您可以想象成一张Excel表：一列是输入，一列是答案，几万行。**模型的全部本领都来自这张表，表里没有的东西模型永远学不会。**

### 2.2 计算机怎么"读"文字：向量化

计算机不认识汉字，只认识数字。所以喂给模型前，文字要先变成**向量（一串数字）**。您项目里已经有两个现成的例子：

**方式一：TF-IDF（词袋子数数）**——适合小模型
> 把"你是谁呀"拆成词：`你/是/谁/呀`，然后数每个词出现了几次、这个词在所有样本里是否罕见。每个样本变成一个很长的数字串，比如 `[0, 0, 1, 0.8, ...]`。
> 缺点是它不懂词序和语义——"我不高兴"和"我很高兴"会被看成很像（这就是审查报告说情绪检测会误判的原因）。

**方式二：语义嵌入（您的向量库正在用的）**——bge-small-zh-v1.5
> 一个专门训练过的"翻译器"把整句话变成**512个数字**，并且**意思相近的句子，数字也相近**。"你是谁"和"你叫什么名字"的向量距离很近，"今天天气如何"就离得远。
> 您的知识库（14,418×512）就是1.4万个句子各自的512个数字。语义缓存器的原理就是：**新问题变成512个数字 → 在历史问题里找数字最近的 → 近到超过阈值就直接返回那个问题的答案**。

### 2.3 模型本体长什么样：参数

模型文件（通常是 `.pkl` 或 `.bin`）内部核心就是**一大堆数字（参数）**：

- 意图分类器：几百到几万个数字（TF-IDF词汇表 + 每个词对每类意图的"投票权重"）
- bge嵌入模型：约3,300万个数字
- DeepSeek大模型：数千亿个数字

**训练 = 自动调这些数字的过程**。所以"模型文件"您要理解成：一张存了参数的表格 + 一份说明书（这些参数怎么用）。这也是为什么模型文件必须配`metadata.json`（记录它是什么时候、用什么数据、练到什么水平）——没有说明书的参数表是废铁。

## 第三章 训练的逻辑——"调旋钮"的比喻

### 3.1 训练在干什么

想象一台老收音机有100个旋钮，您想调到某个电台（正确答案）。训练过程就是：

1. 拿一条样本，输入进去，看模型现在猜的答案
2. 猜错了？**根据错的方向，微调每个旋钮**（往让它下次更接近正确答案的方向拧一点点）
3. 换下一条样本，重复
4. 所有样本过完一遍叫**一个轮次（epoch）**，通常重复几个轮次
5. 最后停下，锁死旋钮位置 → 保存成模型文件

那个"根据错误方向拧旋钮"的算法，您只需要记住名字：**梯度下降**。误差的度量叫**损失（loss）**——训练顺利的标志就是loss持续下降，像考试错题越来越少。

### 3.2 为什么必须留一部分数据不参与训练（关键！）

**训练集/测试集分离**是机器学习第一铁律：

```
1000条样本 = 800条训练（喂给模型学） + 200条考试（藏起来，最后测它）
```

为什么？**用学过的题考它，得100分也不能说明它会了**（可能只是背下来了）。只有用没见过的题测出的成绩才可信。这个"背题不等于学会"的现象有个名字——**过拟合（overfitting）**：

> 孩子把乘法表背得滚瓜烂熟，但见到"7个盒子每个装6个苹果一共几个"就不会了 = 过拟合
> 训练集准确率99%，测试集准确率70% = 过拟合，这个模型是虚的

**您的验收口诀：看模型成绩，只认测试集（留出集）的数字，训练集的数字没有意义。** 路灯或大模型汇报"准确率95%"时，您要问的第一句话永远是："这是测试集还是训练集？"

### 3.3 训练一个模型实际需要多少数据

经验法则（针对您要做的轻量任务）：

| 任务类型 | 最低启动量 | 舒适量 |
|---------|-----------|--------|
| 意图分类（几十个类别） | 300条 | 1000-3000条 |
| 语义缓存（不需要训练） | 0（只要历史问答对） | 越多命中率越高 |
| 补丁质量评估 | 300条**真实标签** | 1000条 |
| 微调0.5B小模型（远期） | 5万对 | 10万对+ |

这就是为什么优化分析里说您当前的50条问答对不够——**巧妇难为无米之炊，先建数据管道再谈训练**。

## 第四章 模型的创建全流程（8步清单）

这是您将来验收模型类任务的**标准检查清单**。任何"我训练好了XX模型"的交付，逐项对照：

### 第1步：明确任务定义
- 输入是什么？（用户的一句话）
- 输出是什么？（几十个意图类别之一）
- **验收标准是什么？**（测试集准确率>85%）
> 坑：任务定义模糊是最常见的失败根源。"判断用户意图"太模糊，"把输入分为这15类，列出类别表"才合格。

### 第2步：收集数据
- 从哪来？（LLM调用留存管道、日志挖掘、大模型辅助标注）
- 每条要带**origin标记**（用户真实输入 vs 系统内部产生）
> 坑：把系统自己生成的文本混进训练数据 = 学生抄自己的作业（这是优化分析里说的"自我蒸馏退化螺旋"防护）。

### 第3步：清洗数据
- 去重（Jaccard/指纹去重，您经验库已有现成代码）
- 去噪（SERP页脚、乱码——您知识库的4.6%污染就是反面教材）
- **类别均衡检查**（如果"闲聊"类有800条、"身份询问"只有5条，模型会学成偏科生——见下方说明）
> **类别不均衡**：模型会躺平——"反正大多数都是闲聊，我全猜闲聊也能得80%分"。解决：给少数类补样本或加权。

### 第4步：切分数据
- 训练集/测试集 分开（80/20），**切分必须随机且固定种子**（否则每次测的成绩不可比）
- 切分代码用现成的 `train_test_split`，一行搞定

### 第5步：特征工程
- 文本→数字（TF-IDF或嵌入，见第二章）
- 小任务用TF-IDF足够，别上来就用重的

### 第6步：训练
- 选算法：**分类任务起步用逻辑回归或LinearSVC**（简单、快、概率可解释）
- 这一步代码量极小（sklearn十几行），**训练本身是最简单的一步**

### 第7步：评估（最重要的一步）
必须同时看四个数字：

| 指标 | 含义 | 您要问的问题 |
|------|------|-------------|
| 准确率 | 测试集上对了多少 | 这是测试集的数吗？ |
| 混淆矩阵 | 错都错在哪 | 哪两类最容易互相认错？ |
| 置信度分布 | 它"多有把握" | 是不是无脑自信？ |
| ECE校准误差 | 有把握的程度是否属实 | 说90%把握时真有90%对吗？ |

> **校准**用白话讲：一个学生说"这题我有九成把握"——如果他说九成把握的题十次错一次以上，他就是"虚胖自信"。路由体系用置信度决定"自己答还是交给大模型"，虚胖自信的模型会自信地放错答案。修复方法（温度缩放）只需在训练后加一步，成本几乎为零——**但缺了它整个路由就是沙滩上的楼**。

### 第8步：部署与守护
- 模型存 `data/inner_models/{任务}/v{n}/`，配metadata（训练数据hash、测试成绩、日期）
- **golden set快照测试**：固定100条输入，每次重训后跑一遍，成绩倒退超2%就自动拒绝上线
- 灰度接入（先放50%流量试，没问题再全量）
- 监控漂移（每周对比实际表现，连续下滑自动回滚）

## 第六章 常见坑字典（验收时对照用）

| 坑 | 表现 | 一句话本质 |
|----|------|-----------|
| 数据泄露 | 训练/测试集混了重复样本，成绩虚高 | 提前偷看了考卷 |
| 过拟合 | 训练集99分测试集70分 | 背题没学会 |
| 类别不均衡 | 准确率85%但少数类全军覆没 | 偏科生靠主科拉分 |
| 虚胖自信 | 置信度0.9的错误答案很多 | 没校准 |
| 自我蒸馏退化 | 用模型自己的输出再训练自己 | 近亲繁殖，越生越弱 |
| 数据污染 | 训练集里有SERP垃圾/系统自造文本 | 吃了发霉的粮食 |
| 标签错误 | "标准答案"本身是错的（如baseline_errors=0的假通过） | 老师教错了，学生越认真错越深 |
| 漂移 | 上线时85分，三个月后70分 | 世界变了，模型没跟上（需定期重训+监控） |

## 第七章 三条学习心法（给项目Owner的定位）

1. **您不需要会拧旋钮，但必须会看仪表盘。** 训练代码让大模型写；但"测试集还是训练集""ECE多少""类别均衡吗"这三个问题，是您的方向盘——问出这三个问题，没人能在您面前糊弄一个坏模型。

2. **数据和标签的质量 > 算法的精妙。** 业界共识：垃圾数据+高级算法 < 干净数据+朴素算法。您项目当前的一切模型问题，根子都在数据（留存率2.4%、标签全是假的、80%污染）——所以路线图把数据治理排在一切之前，这不是保守，是本分。

3. **每个模型都要有"死法"。** 上线前先问：它坏了怎么发现（监控）、发现后怎么救（回滚）、回滚后谁来修（重训流程）。您框架的ParamPatchManager已经有现成的灰度/回滚基建——**让新模型复用这套机制，等于给每个新生儿配了心脏除颤器**。
