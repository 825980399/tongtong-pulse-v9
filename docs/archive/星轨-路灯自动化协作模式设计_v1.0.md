# 星轨-路灯自动化协作模式设计

**版本**：v1.0
**日期**：2026-09-10
**设计人**：星轨
**定位**：曈曈PulseNet框架技术债务清理的自动化协作闭环设计

---

## 一、背景与目标

### 1.1 当前工作模式

当前的技术债务清理采用"人工驱动"模式：
1. 星轨分析问题，生成任务书
2. 用户（小林）手动转发给路灯
3. 路灯执行任务，生成交付报告
4. 用户手动转发给星轨
5. 星轨分析报告，更新技术债务清单
6. 循环

### 1.2 目标

构建**星轨-路灯自动化协作闭环**，减少人工干预，提高效率：

```
星轨（定时监测） → 生成任务书 → 路灯（定时轮询） → 执行任务 
    → 交付报告 → 星轨（定时分析） → 更新清单 → 生成新任务书 → 循环
```

## 二、整体流程设计

### 2.1 自动化协作循环

```
┌─────────────────────────────────────────────────────────────┐
│                    自动化协作循环                              │
│                                                             │
│  ┌──────────┐    任务书     ┌──────────┐    交付报告     ┌──────────┐
│  │  星轨    │ ───────────→ │  路灯    │ ───────────→ │  星轨    │
│  │ (定时)   │              │ (定时轮询)│              │ (分析)   │
│  └──────────┘              └──────────┘              └────┬─────┘
│       ↑                                                    │
│       │              新任务书                               │
│       └────────────────────────────────────────────────────┘
│                                                             │
│  人工干预点：任务书审核 / 重大决策 / 异常处理                   │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 通信机制

通过`docs/路灯与星轨对话/`文件夹作为共享存储，采用文件命名约定状态：

```
docs/路灯与星轨对话/
├── 任务书/
│   ├── 2026-09-10_星轨任务书_第7批_待处理.md    ← 路灯待领取
│   ├── 2026-09-10_星轨任务书_第7批_处理中.md    ← 路灯已领取，正在处理
│   └── 2026-09-10_星轨任务书_第7批_已完成.md    ← 路灯已完成
├── 交付报告/
│   ├── 2026-09-10_路灯交付_第7批_待分析.md      ← 星轨待分析
│   └── 2026-09-10_路灯交付_第7批_已分析.md      ← 星轨已分析
└── 状态/
    └── current_batch.json                       ← 当前批次状态（JSON）
```

**状态流转**：
- 任务书：`待处理` → `处理中` → `已完成`
- 交付报告：`待分析` → `已分析`

### 2.3 定时任务触发逻辑

**星轨侧定时任务**（每30分钟或每小时）：
```
1. 检查 docs/路灯与星轨对话/交付报告/ 下是否有"待分析"的报告
2. 如果有 → 分析报告 → 更新技术债务清单 → 生成新任务书 → 标记"已分析"
3. 如果没有 → 检查是否有"待处理"超过24小时的任务书（路灯可能卡住了）
4. 记录监测日志
```

**路灯侧定时任务**（每30分钟或每小时）：
```
1. 检查 docs/路灯与星轨对话/任务书/ 下是否有"待处理"的任务书
2. 如果有 → 重命名为"处理中" → 开始执行任务
3. 完成后 → 生成交付报告到"交付报告/待分析" → 任务书重命名为"已完成"
4. 如果没有 → 等待下一轮
```

## 三、人工干预点

不能完全自动化，需要保留人工干预：

| 环节 | 是否需要人工确认 | 说明 |
|------|----------------|------|
| 任务书生成 | ⚠️ P0任务需要 | P0级别的重大修改需要用户审核后再发给路灯 |
| 路灯交付报告 | ✅ 不需要 | 星轨可以自动分析 |
| 新任务书生成 | ⚠️ 重大方向需要 | 如果涉及架构级变更，需要用户确认 |
| 异常处理 | ✅ 需要 | 路灯失败/超时/质量不达标时，需要用户决策 |

## 四、质量门禁

星轨分析路灯交付报告时，需要有明确的质量门禁：

```
质量检查清单：
□ 1. 任务书要求的所有任务是否都完成了？
□ 2. 测试用例是否全部通过？
□ 3. ruff错误是否为0？
□ 4. 是否有备份文件（.bak）？
□ 5. 是否引入了新的问题？
□ 6. 预埋点是否按要求产出？

如果不通过 → 生成"补充任务书"退回路灯修改
如果通过 → 更新技术债务清单 → 生成下一批任务书
```

## 五、分阶段实施方案

### 阶段1：半自动模式（先跑通流程）

- 星轨：定时任务监测路灯交付报告，自动分析并生成新任务书草稿
- 用户：审核任务书草稿，确认后手动重命名为"待处理"
- 路灯：手动轮询（或定时任务），领取任务并执行
- 优点：风险低，有人工审核
- 适合：先跑1-2个批次验证流程

### 阶段2：自动化模式（P1/P2任务全自动）

- 星轨：定时任务全自动（分析报告→更新清单→生成任务书→标记待处理）
- 路灯：定时任务全自动（轮询→领取→执行→交付）
- 用户：只在P0任务和异常时介入
- 优点：效率高，持续推进
- 适合：流程验证稳定后

### 阶段3：智能协作模式（远期）

- 星轨：根据技术债务清单自动规划批次，不需要用户指定
- 路灯：根据任务难度自动评估工时，遇到困难主动提问
- 双方：通过文件系统进行多轮对话（不只是任务书→报告，还可以有追问→澄清）
- 优点：真正的自主协作

## 六、需要确认的问题

1. **通信方式**：通过`docs/路灯与星轨对话/`文件夹共享文件，是否可行？路灯那边能访问这个文件夹吗？

2. **定时频率**：星轨和路灯的定时任务间隔多久合适？
   - 建议：每30分钟检查一次（既不会太频繁，也不会等太久）

3. **人工审核**：哪些环节需要你审核？
   - 建议：P0任务书需要审核，P1/P2可以全自动
   - 每批结束后给你一个简短汇总

4. **路灯侧能力**：路灯那边能设置定时任务吗？还是需要人工轮询？
   - 如果路灯不能设置定时任务，可以改成"星轨生成任务书后通知你，你转发给路灯"

5. **异常处理**：如果路灯超过X小时没有响应，怎么办？
   - 建议：超过4小时未响应，星轨给你发提醒，由你决策
