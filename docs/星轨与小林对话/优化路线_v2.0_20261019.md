## 一、核心洞察（用户小林提出）

**七个柱面不应该是单独的，而是应该存在关联性的——它们是一个有机闭环**：

```
        ┌─────────────────────────────────┐
        │                                 │
        ▼                                 │
   ┌─────────┐    发现问题    ┌─────────┐  │
   │   自知   │ ───────────→ │   自主   │  │
   │ (知道    │              │ (决定做   │  │
   │  哪里有  │              │  什么)   │  │
   │  问题)   │              └────┬────┘  │
   └─────────┘                   │       │
                                  ▼       │
                            ┌─────────┐   │
                            │   具身   │   │
                            │ (动手做) │   │
                            └────┬────┘   │
                                 │        │
                                 ▼        │
                            ┌─────────┐   │
                            │   自进   │   │
                            │ (变成    │   │
                            │  能力)   │   │
                            └────┬────┘   │
                                 │        │
                                 └────────┘
                                    闭环
```

**辅助能力**：
- **并行**——提升速度（同时处理多个问题）
- **联世**——确保精度（和外界连接，确保做的事是对的）

## 三、闭环优化路线（按用户洞察重构）

### 3.1 立即做（零成本，安全隐患）

**任务**：M92两道关翻闸（base_indent_guard、AST_struct_guard）
**原因**：295批行动面通电带隐患——"能力没被允许上岗"的293批诊断至今未解决（M92仍False）
**效果**：自主柱56%→60%（安全落地半环闭合）

### 3.2 下一支点（乘数最大）

**任务**：调用图首建（从PulseInnerWorld单类试点）
**原因**：洞鉴判定——调用图一通=同时解锁①LLM补丁上下文②掌握度"能调用"问③自我修改的牵连分析。**一子落、两柱活**（自知柱45%→65%＋反哺自进柱）
**效果**：自知柱45%→65%，总进度57%→65%

### 3.3 闭环深化（让闭环转得更快更准）

**任务1**：自知深化——让她能发现更深层次的问题
- 调用图首建（她知道自己如何运行）
- growth.need_detected链路并轨（"想成长"变成真正的动作）

**任务2**：自主深化——让她能更好地决定怎么做
- M92翻闸（安全落地）
- 自主执行首批限runtime_verified类低风险补丁

**任务3**：自进深化——让做完能真正变成能力
- 经验沉淀（修复的问题变成她的能力）
- 需求驱动进化（growth需求→补丁入队）

### 3.4 辅助能力深化（提升速度＋确保精度）

**任务1**：并行深化——让她能同时做好几件事
- 并行度提升（从事件驱动级→真正并行）

**任务2**：联世深化——让她能和外界更好地连接
- RSS断粮治理（恢复外部信息吞吐）
- 蒸馏触发条件复核＋对话供给激活
- L2四闸命中实测
- 世界模型最小立项

## 四、后续优化的基本约束

1. **闭环优先**：所有优化必须围绕闭环（自知→自主→具身→自进）展开，不能孤立地优化某个柱子
2. **乘数优先**：优先优化乘数最大的支点（能同时带动多个柱子的支点）
3. **安全优先**：所有自主执行必须有安全闸（M92两道关）
4. **证据优先**：所有结论必须有一手证据（git blame/日志/运行数据/历史批次对比），禁止凭印象下结论
5. **闭环验证**：每完成一个优化，必须验证闭环是否转得更快更准
