## 三、建议增补 4 条（每条都带本轮实测教训）

**建议 10 · 行尾与编码纪律（来自微光本轮真实踩坑）**
- 写盘一律 `newline=''` **显式控制换行**，不依赖平台默认翻译
- 提交前核对行尾；**`.gitattributes` 实测约定**：`*.md / *.txt / *.json / *.yaml / *.yml` = **LF**；`*.py / *.pyi / *.bat / *.cmd / *.ps1` = **CRLF**（第 94 批事故即"checkout 静默改行尾"）
- 微光本轮**两次**把 `.md` 由 LF 翻成 CRLF（Python 默认换行翻译、`csv.writer` 默认 RFC 4180 CRLF）→ 已归一

**建议 11 · PII 打码与「产出物终检」（来自微光本轮真实踩坑）**
- 涉及真实姓名/手机号/邮箱/生日：报告与交付物内**一律打码**（沿用现有约定 `<真实姓名>` / `生日（占位）`）
- **自查脚本必须含"产出物 PII 终检"**：对自家交付物跑正则（手机号/身份证/真身邮箱/真名）
- 微光本轮初稿曾把 remote URL 的**真身标识未打码**写入正文 → **自检脚本抓到并已改**；另 `docs\分析报告\微光_GitHub推送失败诊断_20261001.md:24` 的手机号真值**系微光 10-01 写入**（已列入待清）

**建议 12 · 大文件阈值量化**
- **>100MB 一律流式分块（建议 8MB）**；整读**仅限确认框架停止后**
- 好处：把「先查框架」从**前置条件**变成**仅在整读时才需要**，减少只读方与施工方的相互等待

**建议 13 · 删锁 / 删文件权限归属**
- `.git/index.lock` 删除权、任何文件删除权**只归提交方**（星轨/路灯）
- 只读方（烛微/微光）**只报不删**（微光按 **Q13** 全程不执行删除）
