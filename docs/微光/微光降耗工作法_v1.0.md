# 微光 · 降耗工作法 v1.0

> **产出人**：微光 | **日期**：2026-09-29 | **起因**：业主反馈 Credits 消耗偏大
> **目标**：在**不降低**发现质量与证据完整性的前提下，压缩工具调用次数与 stdout 体量
> **约束**：只读原则不变；产出仍落 `docs\审查报告\微光巡检\`、`docs\微光\`

---

## 一、成本模型（先认清钱花在哪）

微光任务的计费 ≈ **（工具调用次数 × 固定开销）+（每次回灌上下文的 stdout 字符数）**。
**结论：不是"读得太多"计费，而是"打印得太多"——凡进上下文的 stdout 都计费。**

上轮（首巡任务）实测消耗大头：
| 源 | 量级 | 可避免度 |
|---|---|---|
| `data/` 递归清单一次性 ~36k 字符 stdout | 高 | 可避免 90% |
| 单行巨 JSON（vectors_meta/cold.index）被 grep 整段打印 | 高 | 可避免 100% |
| PII 全量扫描跑了 3 次（OOM 1 + 超时 1 + 成功 1） | 中 | 可避免 66% |
| 整读长文档（总账 20333 行等） | 中 | 可避免 70% |
| 串行碎步调用（~30+ 次） | 中 | 可避免 50% |

## 二、六条硬规则

### 规则1 · 只打摘要，不打明细
- 清单/日志/目录树 → **落文件**，stdout 只打 `TOP-N`、`计数`、`体积合计`、`hash`。
- 反例（禁）：`Get-ChildItem -Recurse | Format-Table`（数千行）
- 正例：`... | Select-Object -First 10`；`... | Measure-Object | Select Count`

### 规则2 · 禁打印巨 JSON
- `data/**` 下 `.json/.jsonl` 单行大文件 → **只用 python 聚合**（键名 + 条数 + 抽样打码），**严禁 grep / 整读**。
- 若必须看值：`python -c` 取字段 + 只 `print` 前 N 条。

### 规则3 · 一次成扫描，结果落盘复用
- 全量扫描（PII、体积、编码）→ 写成**脚本一次跑完**，输出 JSON 摘要落 `.aionclaw-tmp/`，会话内**复用**不再重扫。
- 首次跑就设 `timeout` + 排除大目录（如 `models/`、`.bak`），避免 OOM/超时重跑。

### 规则4 · 批量并跑，减少往返
- 独立命令合并到**一条** exec（用 `;` 串联固定步骤）；每轮工具调用有固定开销。
- 目标：单任务工具调用 **≤15 次**。

### 规则5 · 读文档先看目录
- 长 md 先 `Select-String -Pattern "^#"` 抓标题+行号，**只精读需要的段落**（`-TotalCount` / `-Skip N -First M`）。

### 规则6 · 预算闸 + 自我熔断
- 单次任务预算：**≤15 次工具调用、单条 stdout ≤2k 字符**。
- 触闸即**改策略**（换脚本聚合/降范围/分片），**不硬刷**。

---

## 三、标准作业模板（微光巡检）

1. **一次性采集**：一个脚本同时产出「体积 TOP-N + 计数 + PII 摘要」→ 落 JSON。
2. **摘要回读**：只 `print` 关键数字（≤2k 字符）。
3. **证据链**：需要逐条 stdout 佐证时，才输出**单条**（非批量）短输出。
4. **落盘**：报告写文件，**对话里只给路径 + 结论表**，不粘贴全文。

## 五、不牺牲项（红线）

- 发现仍须带「**路径 + 实测证据 + 时刻 + 责任角色 + 整改建议**」。
- 只读原则、可写区边界**不变**。
- 降耗 = 少打印，**不是**少查证。

## 六、v2.0 成本模型与量化优化（2026-09-29 业主反馈：上轮 ~2500 Credits）

### 6.1 根本模型
总成本 ≈ **Σ(每一轮上下文长度) ≈ 轮数 × 平均上下文**。
**关键杠杆**：任何大输出一旦进入上下文，会在**之后每一轮被反复重发计费**。故——
> **大输出 × 越早出现 = 越贵（通胀系数 ≈ 其后轮数）**

### 6.2 上轮 2500 Credits 拆解（按实际调用结构估算）
| 驱动源 | 占比 | 性质 |
|---|---|---|
| 早期巨输出（`data/` 36k 字符，出现在前 1/3）被后续 ~30 轮反复重发 | ~30% | 最低效 |
| 轮数过多（~50–60 次调用，含 ~15 次 poll 空转） | ~25% | 每轮重发全上下文 |
| 中后段大输出（60k/30k/27k blob，grep 巨 JSON） | ~20% | 单条贵且污染后续 |
| PII 扫描跑 3 次（OOM+超时+成功） | ~12% | 纯浪费 2/3 |
| 整读长文档 + 碎步单值调用 | ~13% | 可合并 |

**结论：约 2/3 消耗源于「上下文卫生」而非「查证深度」→ 质量可不降。**

### 6.3 v2.0 量化目标（硬指标）
| 维度 | 上轮 | v2.0 目标 |
|---|---|---|
| 工具调用轮数 | ~50–60 | **≤12** |
| 等待方式 | 15 次 poll 空转 | **0 次空转**（单次长 yieldMs 或跑完查一次） |
| 单条 stdout 上限 | 36k 字符 | **≤2k 字符** |
| 巨 JSON | grep 整段打印 | **禁止**，只 python 聚合 |
| 全量扫描 | 3 次 | **1 次** |
| 临时结果 | 反复打印 | **落盘复用**（不进上下文） |

### 6.4 核心改造
把「数据 → 上下文」改为「**数据 → 文件 → 一行摘要进上下文**」。大输出一律重定向到文件，只回 digest。
**预期：2500 → 800–1100 Credits（降 55–65%），证据完整度不变。**

### 6.5 标准动作序列（v2.0 版）
1. **一次侦察**：单个脚本同时产出体积/计数/PII 摘要，落 JSON。
2. **只回 digest**：stdout ≤2k，只给 TOP-N + 计数 + hash。
3. **需逐条证据时才单条短输出**（不批量）。
4. **对话只给结论表 + 路径**，全文在落盘报告。
5. **全程零 poll 空转**：脚本跑完一次性返回。

## 七、省耗模式 v2 · 十条（星轨 2026-09-29 下发，**最高执行纪律**）

### 输入侧（消耗大头，最优先）
1. **大输出落盘+摘要**：任何命令输出 >2KB 先落盘工作区，上下文只放 ≤5 行摘要。
2. **大文件带行号抽样**：>100KB 文件用 `Select-String` 带行号，**禁止整文件 Read**。
3. **采集脚本化一次跑**：全量统计合成一个脚本一次执行，脚本留工作区复用。
4. **已采数据复用**：首巡/二巡/烛微已采数据直接引用「见 XX 报告」，**禁止重扫**。

### 输出侧
5. **报告两层结构**：主报告只写结论+证据（`路径:行号`）+关键数字；完整命令/大表落盘附件。
6. **复用已有结论**：不重复推导已定论数字。

### 流程侧
7. **命令批量合并**：独立查询合成一条命令，减少轮次。
8. **任务书一次读完**：先通读+提炼必答清单，执行中不回翻。

### 精度保持（省耗不降质的关键）
9. **结论数字双检**：每个关键数字带一行复现命令+注明「已复测」；统计 JSON 前先输出字段名清单再计数（防字段口径误读）。
10. **偏差零容忍自报**：数字与预期不符立即自报并注明「已订正」，不掩盖。

**执行对照（首巡→二巡→三巡）**：二巡已落实 1/3/5/6/7；三巡起强制落实 2/4/8/9/10。
