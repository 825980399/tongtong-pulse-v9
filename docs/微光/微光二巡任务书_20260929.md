## 二、任务子项（7 项，按执行顺序）

### T1（核心）自主进化全链路还原
从「问题被发现」到「补丁应用+验证」画出完整数据流：谁写入 calls_*.jsonl → 谁读取 → 谁调度 → 谁生成补丁 → 谁审批 → 谁执行 → 谁验证 → 谁回写。
**输出**：链路图（文字版，每环节标注 写入方:行号 → 读取方:行号）+ 一张「每环节真实消费」表。

### T2（核心）逐环节漏斗量化——主断点定位
用 `data\calls_*.jsonl` 201 件真实数据 + 补丁目录实勘，量化：
发现数 → 记录数 → 调度数 → 补丁生成数 → 审批通过数 → 应用成功数 → 验证通过数 → 保留数。
**输出**：漏斗表（每级真实数字+口径）+ 断点结论（哪一级损耗最大、为什么）。

### T3 数据实勘
- `data\calls_*.jsonl`：201 件里多少被真读过、多少死数据（近30天无消费）
- `data\patches\`：成功/失败/搁置分布，抽样 3 份看真实质量
- 与 149（旧口径）vs 201（实测）的差异原因

### T4 LLM 依赖结构分析
97% LLM 依赖的结构性原因：哪些环节**本可本地完成却依赖 LLM**（对照"外物是拐杖不是腿"原则，总账核心原则）。
**输出**：本地可替代环节清单（环节:现状:本地替代方案:依赖度降幅预估）。

### T5 名实不符取证（D008/D009/D011/D014）
四票对应的「壳」（call_recorder/calls文件/调度器/审批器）与「实」（自主修复率 1.8%）的差距证据链——每条给出 文件:行号 级证据，证明"壳在跑、实没产出"或"壳也在空转"。

### T6 降级后的正确姿势（决策建议，最重要）
给 **3-5 条可执行方向**，每条含：方向名 / 修·改口径·停线 三选一 / 优先级（P0-P2）/ 依据（本次实测）/ 预计影响 / 不写码。
候选方向示例（可替换可增补）：接上断点接线、砍壳改口径、数据面清洗、本地规则补丁替代 LLM 补丁、整线停用留档。

### T7 只读自证（同首巡格式）
