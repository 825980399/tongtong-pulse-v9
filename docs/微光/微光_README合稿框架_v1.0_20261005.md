### 2-2 贡献流程（对外简化版 · 供「七、参与」或 CONTRIBUTING）

1. **Issue** 描述问题/需求 → 2. **PR** 提交前本地跑通门禁 → 3. **评审合入**。
- 门禁五道：ruff `F`=0 ／ 导入冒烟 ／ 相关 pytest **0 failed** ／ 静默异常只降不升 ／ 行尾与 `.gitattributes` 一致
- ⚠️ **实测现状**：`.github/` 全目录**仅 1 个文件**（`PULL_REQUEST_TEMPLATE.md`），**无 GitHub workflow**；CI 现存在于 **`.gitee/workflows`** → 对外须以**文档列出门禁命令**（或按小林二选一拍板补 workflow）

### 2-3 批次/票体系（对外简化版）

> 项目以「**批次**」迭代：任务书 → 施工 → 交付报告 → 验收；问题以 **issue** 跟踪，以 **PR** 参与。问题分级保留 **P0-P3** 语义（**不公开分级规则与裁决机制**）。

### 2-4 隐私与导出（含必写说明）

- 运行数据（`data/`、`logs/`）**不在开源范围**；对外包由 `tools/export_public.py` 生成
- ⚠️ **必写**（烛微 §3.2 实证）：接收方 clone 后**拿不到 `.owner_pii.json`**（属主私有），其复扫**只剩静态规则** → 会给出**"偏乐观的 0 命中"**；复扫前须自备 `PULSE_OWNER_NAMES / PULSE_OWNER_PATHS` 等属主规则
- 建议口径：导出复扫须走 **tracked-only**（烛微 §3.3：`iter_public_files` 增 `--source tracked|fs`，默认 tracked → **天然排除 `.aionclaw-tmp/`、`tmp/`、`data/`、`logs/`**），并配合包体复扫（`T-导出器公开渲染与包体复扫-1` P0）
