> 触发：星轨反馈"代码仓推不进去" + 业主反馈"GitHub 网页打开非常慢"

---

## 〇、结论（一句话）

**不是代码问题、不是权限问题、不是凭据问题——是本机到 `github.com:443` 的网络链路被阻断。**
`git push github master` 卡 **21 秒后直接 `Could not connect to server`**；同一台机器上 **gitee / openi 秒连**。病根与"网页打开慢"同源。

---

## 一、实测证据（全部为只读命令，可复现）

### 1. 三个远程镜像可达性对照

| 远程 | 仓库地址 | ls-remote 结果 | 判定 |
|---|---|---|---|
| **github** | `github.com/825980399/tongtong-pulse-v9.git` | ❌ `Failed to connect to github.com port 443 after 21194 ms: Could not connect to server` | **不可达** |
| gitee (origin) | `gitee.com/tongtongkaiyuan/tongtong-pulse-v9.git` | ✅ 862 ms，`refs/heads/master` = `b4a7ae1` | 可达·已同步 |
| openi | `openi.pcl.ac.cn/18737489636/tongtong-pulse-v9.git` | ✅ 889 ms，远程 HEAD `8d9b95f3` | 可达·**落后 164 提交** |

### 2. GitHub 推送 dry-run（无副作用）

```
$ git push --dry-run github master
fatal: unable to access 'https://github.com/825980399/tongtong-pulse-v9.git/':
       Failed to connect to github.com port 443 after 21215 ms: Could not connect to server
```
**→ 连接在"认证之前"就失败了**，凭据/权限根本没机会参与。

### 3. 链路层检测

| 检测项 | 实测 |
|---|---|
| DNS 解析 `github.com` | `20.205.243.166`（正常，非污染） |
| ICMP ping `github.com` | 3 次**全部超时** |
| HTTPS HEAD `https://github.com` | **15,092 ms**（≈15 秒） |
| SSH `ssh.github.com:443` | **通** ✅ |

### 4. 排除项（省得白查）

| 嫌疑 | 实测 | 结论 |
|---|---|---|
| 提交有问题 | 本地 HEAD `b4a7ae1`，暂存区无堆积 | ❌ 排除 |
| ahead 卡住 | `master` ahead(origin) = **0** | ❌ 排除 |
| 大文件 | 已跟踪文件无 >50MB | ❌ 排除 |
| 凭据失效 | `credential.helper = manager`(GCM)，连接前即断 | ❌ 排除 |
| postBuffer/代理配置 | 均为空（无异常配置） | ❌ 排除 |

## 二、根因

**跨境链路阻断/拥塞**：到 `github.com:443` 的 TCP 连接被丢弃（21s 超时），ICMP 也被丢。这与"网页打开慢（15s 握手）"是同一个成因。

本机存在 `MicrosoftTun` 虚拟网卡（Clash/Mihomo 类代理，TUN 模式），**但 GitHub 流量极可能走了"直连"规则，未吃到代理加速**。

---

## 三、解决方案（按性价比排序）

### ① 最快：让代理接管 GitHub（本机已装 TUN）
在代理客户端把以下域名加入**代理组**（或临时切"全局"）：
```
github.com
api.github.com
codeload.github.com
github.io
githubusercontent.com
raw.githubusercontent.com
objects.githubusercontent.com
githubassets.com
gist.github.com
```
**复测**：`git ls-remote --heads github` 应 **<1 秒**返回 `refs/heads/master`。

### ② 不动代理：GitHub 改走 SSH 443（端口已验证通）
`C:\Users\Administrator\.ssh\config`：
```
Host github.com
  HostName ssh.github.com
  Port 443
  User git
```
远程地址改 `git@github.com:825980399/tongtong-pulse-v9.git`；
测试：`ssh -T -p 443 git@ssh.github.com`。

### ③ 兜底（立即可行）
- **急推 GitHub** → 先做 ① 或 ②；
- **不急** → `git push openi master` 补 **164 个提交**（openi 可达）；gitee 已同步至 `b4a7ae1`。

---

## 四、给星轨的结构性建议

1. **推送主目标建议切到 gitee/openi**（国内稳定可达），GitHub 仅作镜像；否则每批都吃 **21s 超时**，是隐性拖累。
2. **openi 落后 164 提交**，建议单独安排一次补推。
3. **远程可达性应纳入每批验收前置检查**（一行命令即可判绿灯）：
   ```
   git ls-remote --heads github   # >5s 或报错 = 红
   git ls-remote --heads origin
   git ls-remote --heads openi
   ```
