## 一、目标

对 reports/ 全部报告（388 份 JSON，09-14→09-30）做**消费契约审计**，交付：
1. **报告分类表**（三类 + 每类消费期望）
2. **真空转清单**（事件驱动但无消费方 → 正确消费方建议）
3. **存档型标注清单**（从空转统计剔除）
4. **口径修正后的真实空转率**
5. 与 v1 审计对照（71.1% → 修正后 X%）

## 二、分类规则（每份报告必归一类）

| 类 | 判定 | 消费期望 | 处置 |
|---|---|---|---|
| **① 事件驱动** | 产出目的 = 驱动下游行为（触发修复/决策/降频/知识入库/调度/器官联动）；字段或语义声明了行为意图 | 必须有消费方 | **真空转** → 找正确消费方接线（建议 + P 级）；已接 → 验证 |
| **② 存档型** | 产出目的 = 留痕/审计证据/运行观测/快照（探针记录、历史归档、健康快照） | 无即时消费，按需可查 | 标注"存档"，**剔除空转统计** |
| **③ 观测型** | 指标/度量子集（metrics 类），供查询与趋势分析 | 查询入口存在即可 | 核查询入口；无入口 → 补或标 |

## 三、真空转判定（②③之外的核心动作）

对每份 ①类报告：
1. 声明消费方（`consumed_by` 字段 / register_builtin_consumers 订阅表 / 事件名订阅）
2. 代码级核查消费方**真实读取路径**（不只查字段声明，查实际调用链）
3. 无真实消费方 → **真空转**，给：
   - 正确消费方建议（哪个器官/机制应该读它 + 接线点位置）
   - P 级（按驱动行为的重要性）
4. 有消费方但 `consumed_by` 字段空（被动读取/订阅未记账）→ **口径修正**，非空转

## 四、口径与交付

- **真实空转率** = ①类真空转数 / ①类总数（不再用 388 做分母）；同时报告 ①/②/③ 各自占比
- **与 v1 对照**：71.1%（全局 consumed_by 空）→ 修正后真实空转率，并解释差量去向（存档/口径/真空转）
