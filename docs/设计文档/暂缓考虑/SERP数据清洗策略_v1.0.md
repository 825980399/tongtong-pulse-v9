## 一、★先修正一个易错判断：`is_summarized` 不等于"不可删"

初步分析曾把 980 条 `is_summarized=true` 的污染记录判为"不可逆 → 不可删"。
**这个判断是错的**，必须修正：

| 问题 | 正确理解 |
|---|---|
| "不可逆"指的是什么？ | **该经验条的原始内容已被模板覆盖销毁**（信息损失**已经发生**） |
| 这是否意味着**不能删除**它？ | ❌ 否。删与不删，**已丢失的信息都不会回来** |
| 删冗余副本会额外丢信息吗？ | **不会** —— 被删的是**逐字相同的副本**，保留 1 条原型即保留全部现存信息 |

> ★★ **正确结论**：
> - **可安全删除 = 1179 条（全部冗余副本），信息损失 = 0**
> - **不可逆损失 = 980 条经验的原文**（**已经发生**，与清洗动作无关，清洗无法使其更糟）
>
> 把"不可逆"误读为"不可删"，会让 78.5% 的垃圾被永久保留 —— 这正是污染锁死 L3 的机制本身。

## 四、清洗顺序（严格串行，每步可独立回滚）

```
S0  停机 + 完整备份（sha256）          ← 前置，失败即中止
 │
S1  D1 删除 L1 完全重复冗余副本        ← 收益最大（1179 条），风险最低
 │      （逐字相同，无边界判断）
 │
S2  校验：总数守恒 / 原型齐全 / 无孤儿 ← 任一项失败 → 回滚 S1
 │
S3  （可选，本批不做）L2 模板化归并
 │      需人工定义"模板等价"规则，风险中
 │
S4  （可选，本批不做）L3 高度相似聚类（Jaccard ≥ 0.8）
 │      5853 对，需人工抽样确认阈值，风险高
 │
S5  检索效果验证（清洗前后对比）        ← 不通过则回滚
 │
S6  落盘 + 归档被删记录（不物理销毁）
```

> **本批只做 S0–S2 + S5**（收益 95%+、风险最低）；S3/S4 延后至有人工审核资源时。

## 五、安全措施

### 5.1 备份（S0，强制）

| 项 | 要求 |
|---|---|
| 位置 | `data/_archive/serp_clean/YYYYMMDD_HHMMSS/` |
| 内容 | 完整 `experience_pool.json` + `sha256` 校验文件 + MANIFEST |
| 校验 | 备份完成后**立即**校验 sha256，**不匹配则中止整个清洗** |
| 保留 | **永久保留**（不放进任何自动清理策略） |

### 5.2 删除方式：归档而非销毁

**绝不使用物理删除**。所有 D1 记录移入：

```
data/_archive/serp_clean/<ts>/removed_records.jsonl
```

→ 任何时刻可原样恢复。

### 5.3 停机窗口（强制）

| 项 | 要求 |
|---|---|
| 前置条件 | **框架必须完全停止** |
| 判据 | `logs/pulse.log` mtime 距今 **> 5 分钟** 且无 Python 进程持有该文件 |
| 理由 | 经验库由 `ExperiencePool` 持续写入（`check_decay` 周期触发）→ 在写进程与清洗进程竞争会损坏文件 |

> ★ 第44批教训：框架在线时只能"只读取证 + 拷贝校验"，**任何重写都必须停机**。

### 5.4 回滚

任一校验失败 → 直接从备份整体还原，并**保留失败现场**（不清理临时文件）供诊断。

## 七、清洗效果验证方法

### 7.1 结构校验（必须全通过）

| 校验 | 判据 |
|---|---|
| 总数守恒 | `before.total - removed == after.total` |
| 原型齐全 | 22 条 D2 全部存在且 `id` 不变 |
| 无孤儿 | 所有 `deduplicated_origin` 标记可追溯到原组 |
| 污染率 | 从 78.5% → ≤ 7% |
| 干净记录不变 | 322 条 `id` 集合完全一致 |

### 7.2 检索效果对比（核心指标）

构造 **30 条标准查询集**（覆盖各 motivation 类别），对比清洗前后：

| 指标 | 定义 | 目标 |
|---|---|---|
| **Top-10 唯一文本数** | 返回 10 条中不同 summary 的数量 | **≥ 8**（清洗前预计 ≤ 3） |
| **Top-10 同质率** | 返回中占比最高的文本比例 | **≤ 30%**（清洗前 ≈ 100%） |
| 命中相关性 | 人工标注 30 条查询的相关性（0/1/2） | 不下降 |
| 检索耗时 | P95 | 下降（数据量 −77%） |

> ★ 唯一文本数与同质率是**最能反映 L3 训练信号质量**的两个指标——
> 同质率 100% 意味着无论检索多少次，模型只看到同一句话。

## 八、风险评估

| 风险 | 影响 | 缓解 |
|---|---|---|
| 停机判断失误（框架其实在跑） | 文件损坏 | 强制 mtime + 进程双重校验；失败即中止 |
| 备份不完整 | 无法回滚 | sha256 校验；不匹配即中止 |
| 误删原型（保留错记录） | 信息损失 | 保留组内 `timestamp` 最小者；S2 校验原型齐全 |
| 干净记录内部重复未处理 | 清洗后仍有噪声 | 已识别（3 组 + 84.2% 零权重），登记 P0-4，不在本批范围 |
| **污染再生** | 清洗白做 | ★**必须同步改 `_summarize_experience`**，否则下次 `check_decay` 重演 |

## 九、★与根因修复的依赖关系（关键）

```
                  ┌─────────────────────────┐
                  │  改 _summarize_experience│  ← 治本（阻止再生）
                  └───────────┬─────────────┘
                              │  必须先于（或同步于）
                              ▼
                  ┌─────────────────────────┐
                  │     执行数据清洗          │  ← 治标（清除存量）
                  └─────────────────────────┘
```

**若只清洗不改摘要机制**：
- 清洗后 344 条干净
- 下一次 `check_decay()` 大规模触发 → 衰减摘要 → 模板化
- **污染以相同机制再生**（实测：09-09 一天就产生了 1179 条）

> **建议第47批执行顺序**：改摘要机制 → 观察 1～2 天确认无新增污染 → 再停机清洗。
