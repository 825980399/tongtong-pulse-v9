## 一、问题与目标

### 1.1 现状痛点

节点关联网络当前存在每个节点的 `linked_nodes` 字段（列表）：

- 查 **多跳关联**（A→B→C→D）需逐个加载节点再逐层展开 —— O(N^depth)
- 12295 节点尚可接受，**千万级节点时多跳查询完全不可用**
- 无法做社区发现、中心性分析、最短路径等图算法

### 1.2 目标

| 能力 | 现状 | Neo4j |
|---|---|---|
| 1 跳关联 | O(1) 读字段 | O(1) |
| 3 跳关联 | 逐层展开，极慢 | 毫秒级（Cypher 原生） |
| 最短路径 | 不支持 | `shortestPath()` |
| 共同邻居 | 需手动求交 | 原生 MATCH |
| 社区发现 | 不支持 | 可扩展 |

## 二、设计

### 2.1 数据模型

```
(:KnowledgeNode {node_id, evol_level, space_path, ...})
        │
        └──-[RELATED]->(:KnowledgeNode)
```

- 节点标签：`KnowledgeNode`，主键 `node_id`（建唯一约束）
- 关系类型：`RELATED`（默认），后续可扩展 `DERIVED_FROM` / `CONFLICTS` 等
- 属性：仅存**查询需要的**元数据，大字段（value）仍留在 Parquet/节点池

### 2.2 接口

**连接管理**
```python
connect(uri, user, password) -> bool
close()                      -> None
is_available()               -> bool
```

**节点 CRUD**
```python
add_node(node_id, properties)      # MERGE 幂等
update_node(node_id, properties)
remove_node(node_id)               # DETACH DELETE（连关系一起删）
get_node(node_id) -> Optional[dict]
```

**关系 CRUD**
```python
add_relationship(from_id, to_id, rel_type, properties)
update_relationship(...)
remove_relationship(from_id, to_id, rel_type)
get_relationships(node_id, direction="both")  # out / in / both
```

**图查询**
```python
query_multi_hop(node_id, max_depth, top_k) -> List[str]
query_shortest_path(from_id, to_id)        -> List[str]
query_common_neighbors(id1, id2)           -> List[str]
execute_cypher(query, parameters)          -> List[dict]
```

**批量同步**
```python
sync_from_nodes(nodes) -> (node_count, rel_count)
```

### 2.3 渐进式迁移策略

```
阶段0（第70批·当前）：封装完成，开关关闭
    └─ 现有代码完全不受影响，linked_nodes 仍是唯一事实来源

阶段1（第71批）：双写过渡
    ├─ 写入：同时写 linked_nodes 和 Neo4j
    ├─ 查询：优先 Neo4j，失败回退 linked_nodes
    └─ 开关：ENABLE_NEO4J_GRAPH_STORE = True

阶段2（第72批）：全量同步 + 只读切换
    ├─ sync_from_nodes() 批量导入存量关联
    └─ 灰度读流量，验证结果一致性

阶段3（第73批+）：Neo4j 为关联主存储
    └─ linked_nodes 降级为缓存/备份
```

### 2.4 降级与容错

- **驱动未安装**：`is_available()` 恒 False，所有方法返回安全空值，**零副作用**
- **连接失败**：捕获异常 + WARNING 日志，不向上抛
- **Cypher 失败**：返回空列表，调用方自动回退 `linked_nodes`
- **总开关关闭**：`connect()` 直接返回 False

**核心原则：图库是增强项，绝不能拖垮主流程。**

### 7.2 双读接口

**节点池（`PulseNodePool`）**
- `get_relationships_neo4j(node_id, direction)`：读取优先走 Neo4j `store.get_relationships`，
  不可用时回退 `node.linked_nodes`；统计 `neo4j_hit` / `pool_fallback` / `fail`。
- `get_read_stats()`：返回 `{enabled, neo4j_hit, pool_fallback, fail, last_error}`。

**KAL（`KnowledgeAccessLayer`）**
- `neo4j_read_enabled()`：三开关总闸。
- `query_relationships(node_id, direction)`：优先 Neo4j，回退 `linked_nodes`。
- `query_multi_hop(node_id, max_depth)`：优先 `store.query_multi_hop`，回退节点内 BFS。
- `query_common_neighbors(id1, id2)`：优先 `store.query_common_neighbors`，回退集合交集。
- `get_neo4j_read_stats()`：委托节点池统计。

## 八、第73批状态（双读一致性实时比对机制，2026-09-17）

第72批遗留项「双读与双写一致性实时比对」已落地（T4，默认关闭）。目标：生产负载下抽查 Neo4j 读结果 `neo4j_hit` 与节点内 `linked_nodes` 的一致性，异常时自动告警并回退，确保图库零风险接管。

### 8.1 新增配置（默认关闭，全部带默认值）

```python
NEO4J_READ_COMPARE_RATE = 0.1                  # 抽样比对比例
NEO4J_READ_COMPARE_WARN_THRESHOLD = 0.05       # 不一致率告警阈值（5%）
NEO4J_READ_COMPARE_FALLBACK_THRESHOLD = 0.10   # 不一致率自动回退阈值（10%）
NEO4J_READ_COMPARE_MIN_SAMPLES = 10            # 触发告警/回退前的最小抽样数（防止首样本误判）
```

### 8.2 比对机制（节点池 `PulseNodePool`）

- `get_relationships_neo4j(node_id, direction)` 在走 Neo4j 读取后，按 `NEO4J_READ_COMPARE_RATE` 概率抽样，将 Neo4j 返回的关系目标集合与节点内 `linked_nodes` 目标集合做集合比对。
- `_m73_compare_stats()` 惰性维护统计：`sampled / mismatch / mismatch_rate / inconsistent_nodes / force_fallback / last_warn`。
- **告警**：`mismatch_rate > WARN_THRESHOLD` 且 `sampled >= MIN_SAMPLES` → 日志 WARNING（不阻断）。
- **自动回退**：`mismatch_rate > FALLBACK_THRESHOLD` 且 `sampled >= MIN_SAMPLES` → `force_fallback=True`，后续 `get_relationships_neo4j` 直接走节点内 `linked_nodes`，图库读取被旁路（零风险）。
- `reset_read_compare()`：清零统计与 `force_fallback`（如人工修复后恢复比对）。

### 8.3 修复接口

- `repair_inconsistent_node(node_id)`：将节点及其关系经 `_m71_neo4j_store()` 的 `add_node` / `add_relationship` 重新同步到 Neo4j，并从 `inconsistent_nodes` 移除。用于确认不一致根因后定向修复图库侧。

### 8.4 KAL 委托

`KnowledgeAccessLayer` 暴露 `get_neo4j_read_compare_stats()` / `reset_neo4j_read_compare()` / `repair_inconsistent_node(node_id)`，均委托节点池实现，保持 KAL 单一入口。

`tests/test_faiss_index_fix_m73.py` 的 `TestT4DualReadCompare` 覆盖（第73批 T5）：关闭零开销 / 不一致检出 / 自动回退 / 告警阈值 / 修复 / KAL 委托 / 重置 / KAL 重置委托，共 9 例，全部通过。所有新功能默认关闭，零回归。
