## 一、设计目标

把"验证通过"从**单一布尔值**拆成**两个独立判定**，并让"修复前基线"从**历史日志考古**改为**主动复现测量**。

| 目标 | 现状 | 目标态 |
|---|---|---|
| 基线来源 | 历史日志文本匹配（命中率 9.0%） | **主动复现探针**（可复现即能量到） |
| 通过语义 | `verified=true`（"没弄坏"=="修好了"） | `no_regression` 与 `problem_fixed` **分离** |
| 不可判定时 | 落 `0`，伪装成"修复前 0 错" | 落 `unknown`，**显式不可判定** |
| 有效率 | `claimed 97.66%` / 可判定 3% | 可判定率 ≥ 70%，且声称值 = 实测值 |
| 验证失败 | 不触发任何动作（`backup_path` 空置） | **自动回滚** |

## 二、架构总览

### 2.1 三层验证模型

```
┌────────────────────────────────────────────────────────────────┐
│  L0 静态验证（现有，保留）                                        │
│    syntax / import / signature / behavior                       │
│    → 输出 no_regression: bool                                   │
│    → 语义："改完没弄坏"                                           │
├────────────────────────────────────────────────────────────────┤
│  L1 主动基线（★本方案新增）                                       │
│    补丁应用【前】对目标位置执行复现探针 → before_errors           │
│    探针形态（按可行性降序）：                                      │
│      P1 定向单测   —— 存在针对该方法的测试，直接跑                  │
│      P2 复现脚本   —— 用 issue 快照构造最小复现（LLM 生成+沙箱）    │
│      P3 静态缺陷检出 —— AST/规则扫目标位置，计数缺陷项              │
│      P0 无探针     —— 记为 unavailable                           │
│    → 输出 baseline{before_errors, source, probe_id, confidence}  │
├────────────────────────────────────────────────────────────────┤
│  L2 效果验证（改造现有）                                          │
│    补丁应用【后】用【同一探针】重跑 → after_errors                 │
│    → 输出 problem_fixed: before>0 and after<before               │
│    → 输出 effectiveness = (before-after)/before  (before>0 才可算)│
└────────────────────────────────────────────────────────────────┘
                              │
                              ▼
                   ┌────────────────────┐
                   │  ConfidenceGrader  │  → high/medium/low/none
                   └────────────────────┘
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
        high/medium      low            none + 回归失败
         → 接受          → 标记观察        → 自动回滚
```

### 2.2 为什么"主动基线"能解决 R1

当前链条：`补丁(09-04~09-11) ──读──> pulse.log(仅 09-13 11:30 起)` → **时间轴不相交 → 必然 0**

改造后：**基线不再依赖"过去发生过什么"，而依赖"现在能不能复现出来"**。

```
旧：baseline = f(历史日志)      ← 日志没了就没了，不可逆
新：baseline = f(当前代码 + 复现探针)  ← 代码在，随时可测，可重跑、可对拍
```

即使补丁已应用，也仍可用 `backup_path`（现存 56/60）临时还原代码重跑探针 → **回填可行**。

## 三、接口定义

### 3.1 核心数据结构

```python
@dataclass
class BaselineResult:
    """修复前基线（★新增，取代裸 int）"""
    before_errors: int | None      # None = 未知（★禁止落 0）
    source: str                    # "unit_test" | "repro_script" | "static_scan" | "log_archive" | "unavailable"
    probe_id: str | None           # 可重跑的探针标识
    probe_spec: dict | None        # 探针规格（沙箱可复现）
    measured_at: float             # 测量时刻
    runnable: bool                 # 探针是否真的跑了（False = 仅为推断）
    note: str = ""                 # 人类可读说明

@dataclass
class VerificationResult:
    """★取代现有单布尔 verified"""
    no_regression: bool            # L0：没弄坏（原 verified 语义）
    problem_fixed: bool | None     # L1+L2：修好了（None = 不可判定）
    effectiveness: float | None    # (before-after)/before，before=0 或 None 时为 None
    confidence: str                # "high" | "medium" | "low" | "none"
    baseline: BaselineResult
    after: BaselineResult
    rollback_triggered: bool = False
```

### 3.2 补丁记录字段变更

| 字段 | 现状 | 目标 | 兼容 |
|---|---|---|---|
| `verified` | `bool` | **保留**（= `no_regression`，向后兼容） | ✅ |
| `baseline_errors` | `int`（0 表未知） | `int \| None`（未知 = `None`） | ⚠️ 需迁移 |
| `baseline_source` | — | **新增** `str` | ✅ |
| `baseline_confidence` | — | **新增** `str` | ✅ |
| `problem_fixed` | — | **新增** `bool \| None` | ✅ |
| `runtime_verify_result.effectiveness` | `float`（可能为假值） | `float \| None` | ⚠️ |
| `verification_confidence` | — | **新增** `str` | ✅ |

> **迁移原则**：只增不改语义。旧 `baseline_errors=0` **不自动改写**为 `None`（无从区分），
> 而是新增 `baseline_source="legacy_unknown"` 标记，让下游能识别"这是老数据，不可信"。

### 3.3 探针接口

```python
class ReproProbe(Protocol):
    """复现探针：给定代码快照，测出目标位置的错误数。"""
    def probe_id(self) -> str: ...
    def is_applicable(self, issue: dict) -> bool: ...
    def measure(self, code_root: str, issue: dict,
                timeout_s: float = 30.0) -> BaselineResult: ...
```

三个内置实现（优先级降序）：

| 探针 | 判据 | 成本 | 可信度上限 |
|---|---|---|---|
| `UnitTestProbe` | `tests/` 中存在覆盖该方法的用例 | 中（跑 pytest 子集） | high |
| `ReproScriptProbe` | 用 `issue` 快照 + LLM 生成最小复现，**沙箱执行** | 高 | medium |
| `StaticScanProbe` | AST + 规则扫目标位置，计数缺陷项 | 低 | medium |
| （无） | — | — | **none** |

> ★ **沙箱约束**：`ReproScriptProbe` 必须在**隔离目录 + 子进程 + 超时 + 无网络**下执行，
> 与第44批 `nucleus/data/write_guard.py` 协同（禁止写生产 `data/`）。

## 四、可信度评级（Confidence Grader）

| 等级 | 判据 | 含义 | 下游动作 |
|---|---|---|---|
| **high** | `before > 0` 且 `after < before` 且 `after == 0` 或 `effectiveness ≥ 0.5`，且探针 `runnable=true` | 确证修复：错误消失 | 接受；写入经验库（正样本） |
| **medium** | `before > 0` 且 `after < before`（部分改善）；或探针为静态扫描 | 大概率有效 | 接受；标记观察 |
| **low** | `before > 0` 且 `after >= before`；或 `before == 0`（只能证"没变差"） | 无法证伪也无法证实 | **不得计为有效**；纳入观察名单 |
| **none** | 无可用探针（`unavailable`）；或探针执行失败 | 不可判定 | **不得计为有效**；建议人工复核 |

**★硬性规则**：

1. `confidence ∈ {low, none}` 的补丁，**一律不计入 `claimed_effectiveness`**
2. 只有当 `confidence ∈ {high, medium}` 时，`problem_fixed` 才允许为 `True`
3. `before is None` 时 `effectiveness` **必须为 `None`**，禁止取 0 或 1
4. 评级结果**必须落盘**，不允许"算完就丢"

## 五、回滚机制

`backup_path` 已存在于 **56/60** 条补丁 → **回滚基础设施已具备，只是从未被验证失败触发**。

### 5.1 触发条件

| 条件 | 动作 |
|---|---|
| `no_regression == False` | **立即回滚**（现有回归失败语义） |
| `problem_fixed == False` 且 `confidence == "medium"` | 回滚 + 标记 `rejected` |
| `confidence == "low"` | 保留但降级为 `quarantined`，**不计入有效率** |
| 探针执行超时/异常 | 不回滚，标记 `none`，转人工 |

### 5.2 回滚流程

```
验证完成
  │
  ├─ 需要回滚？ ──否──> 记录结果，结束
  │
  是
  │
  ├─ 1. 校验 backup_path 存在且 sha256 匹配（★不匹配则中止并告警）
  ├─ 2. 当前文件二次备份 → data/patches/_rollback/<patch_id>/
  ├─ 3. 原子替换（tmp + os.replace）
  ├─ 4. 用【同一探针】重测，确认回到 before 水平
  ├─ 5. 落盘 rollback_result{ok, restored_from, verified_before, verified_after}
  └─ 6. 写审计日志 + 记入经验库（负样本）
```

**★安全约束**：
- 回滚前必须校验备份完整性（sha256），**校验失败不回滚**（避免二次损坏）
- 回滚自身也要**可回滚**（步骤 2 的二次备份）
- 回滚失败 → 立即告警并置框架为 `degraded`，不静默继续

## 七、风险评估

| 风险 | 影响 | 缓解 |
|---|---|---|
| 复现探针本身不可靠（LLM 生成的脚本测不出问题） | 假 high 可信度 | 探针需**自校验**：在"未修复代码"上必须测出 `before > 0`，否则降级 `none` |
| 沙箱执行带来安全/稳定性风险 | 破坏生产 | 隔离目录 + 子进程 + 超时 30s + 无网络 + `write_guard` 拦截 |
| 每次验证跑探针 → 进化循环变慢 | 吞吐下降 | 探针结果**缓存**（同 file+method+code_hash 复用）；异步执行 |
| `UnitTestProbe` 覆盖率低 → 多数落到 `none` | 可判定率仍低 | 分批建设：先接 `StaticScanProbe`（覆盖率高、成本低），再补定向单测 |
| 老数据 `0` 与 `None` 无法区分 | 统计污染延续 | 不改写原值，打 `legacy_unknown` 标记，统计时**单独口径** |
| 自动回滚误伤有效补丁 | 有效修复被撤 | 仅 `no_regression=False` 才自动回滚；其余降级为 `quarantined` 交人工 |
