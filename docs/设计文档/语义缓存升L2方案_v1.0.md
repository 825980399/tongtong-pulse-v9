## 一、背景与目标

### 1.1 现状（L1 观测级）

`nucleus/llm/semantic_cache.py`（第41批 T3 落地）目前是**内在模型 L1 层的第一个实现**：

| 维度 | 现状 |
|---|---|
| 语义模型 | 复用 `nucleus/semantic/VectorEncoder`（BAAI/bge-small-zh-v1.5，512 维 ONNX，禁 torch） |
| 触发点 | `PulseLung._call_via_channels()` 成功回包后 `observe_call(prompt, response)` |
| 写入 | `SemanticCache.add()` → `data/cache/semantic_cache.jsonl`（含 512 维向量） |
| 查询 | `SemanticCache.lookup()` 返回**命中统计**（相似度/命中次数），**绝不返回缓存内容** |
| 线程模型 | daemon 后台线程 + 有界队列（2000），主推理路径零阻塞 |
| 容量/时效 | `SEMANTIC_CACHE_CAPACITY=10000`（LRU 淘汰）／`SEMANTIC_CACHE_TTL_DAYS=7` |
| 阈值 | `SEMANTIC_CACHE_THRESHOLD=0.92`（**第41批拍定，从未用真实语料校准**） |

**★L1 红线的实质**：`lookup()` 只回统计，调用方**结构上无法**据此替换回复 → 因此可以安全地在生产常开。

### 1.2 目标（L2 返回级）

**让"命中"真正省下一次大模型调用**：命中且通过安全校验时，**直接返回缓存响应**，跳过渠道调用。

**量化目标**（与第43批 T2 分析对齐）：

| 指标 | 目标 | 依据 |
|---|---|---|
| 重复 prompt 削减 | **≥18%** | 第43批 T2 实测：冗余重复 prompt 16 条 / 总 87 条 = 18.4% |
| 命中准确率 | **≥99%** | 缓存误命中 = 把 A 的答案给 B，代价远高于漏命中 → precision 优先 |
| 主链路额外延迟 | **≤ +8 ms**（P95） | 编码 512 维向量 + 10k 条余弦比对需实测；超限则降级为哈希精确匹配 |
| 回退可逆性 | **秒级** | 任一开关关闭即回到 L1 行为，零代码改动 |

### 1.3 与 L3 调用精简器的边界（★任务书要求说明）

| | **T2 语义缓存（L1→L2）** | **T3 调用精简器（L3）** |
|---|---|---|
| 处理对象 | **单条 prompt** 与历史 prompt 的**语义相似** | **调用链 / 调用序列**（重复检测、退避、追问合并） |
| 决策粒度 | 一次调用：**返回 / 不返回** | 一串调用：**复用 / 新发 / 退避 / 合并** |
| 判定依据 | 余弦相似度 ≥ 阈值 | 幂等性 + TTL + 失败历史 + 链结构 |
| 状态 | 无状态（单条比对） | 有状态（跨调用、跨轮次） |
| 失效场景 | 上下文敏感问题 | 非幂等任务、追问链断裂 |

**互补关系**：语义缓存处理"**同一条问题问了两次**"；调用精简器处理"**为同一目标问了一串**"。二者可叠加（精简器判定的"可复用"仍会先过语义缓存）。

## 二、架构设计：L1 观测 → L2 返回

### 2.1 升级路径（三阶灰度，不是一次跳）

```
阶段 A（现状 L1）        阶段 B（L2-shadow）           阶段 C（L2 生效）
─────────────────      ──────────────────────       ────────────────────
observe_call()          observe_call()               observe_call()
   ↓                        ↓                            ↓
命中 → 只记统计         命中 → 记统计                命中 → 记统计
                         + 附上"本应返回什么"          + 安全校验(§4)
                         （写入 audit 旁路文件）        + 通过 → 直接返回
                                                              ↓ 不通过
                                                         正常渠道调用
```

* **阶段 B（shadow）是必需的**：L2 最大的风险是"**命中但答错**"，而 L1 阶段**永远看不到这个风险**（因为不返回）。Shadow 模式把"如果返回会返回什么"落盘，用**离线审计 + 人工抽样**先量化准确率，再放流量。**没有 B 就直接上 C = 拿生产对话做实验。**

### 2.2 模块改造点（设计，不在本批实施）

| 位置 | 改动 | 兼容性 |
|---|---|---|
| `semantic_cache.py` | `lookup()` 增加 `with_content: bool = False`；`True` 时返回 `{"response": ...}` | 默认 `False` → **旧调用方行为完全不变** |
| `semantic_cache.py` | 新增 `SemanticCacheL2`（或同模块 `_l2_decide()`），只做**决策**不做 IO | 新类，零侵入 |
| `PulseLung._call_via_channels()` | 在**渠道轮询之前**插入 L2 查表；命中且放行 → 直接 `return` | 由开关 `ENABLE_SEMANTIC_CACHE_L2` 包裹，默认 **False** |
| `call_recorder` | 新增 `origin="cache_hit"` 或字段 `cache_hit: true` | 便于统计"省下的调用数" |

★**插入位置选 `_call_via_channels()` 之前**（与《大模型调用精简方案》一致）——这是**唯一 100% 覆盖**的出口（对话/补救/语义理解全走这里；策略链只覆盖 `PulseInnerWorld`，够不到进化循环）。

### 2.3 为什么不做"进化循环"的缓存

进化循环（占 LLM 调用 98.8%）的 prompt 含**随机上下文**（代码片段 / 错误现场），重复度低；且补丁生成是**创造性任务，天然幂等性差**。**L2 首期只放行 `origin=user_query`**，进化/消化链路继续走 L1 观测。

## 三、阈值校准（★本批实测，非拍脑袋）

### 3.1 校准方法

工具：`tools/calibrate_semantic_threshold.py`（本批新增，**只读**）。

1. **标注探针集**：10 组「同义改写对」（语义相同 → **应命中**）+ 10 组「不同话题对」（语义不同 → **必须不命中**）。
2. 用**真实 bge-small-zh-v1.5** 编码，算每对余弦。
3. 在阈值区间上扫 precision / recall / F1。**缓存场景 precision 优先**（误命中代价 > 漏命中）。
4. **真实语料**：从 `data/llm_traces/calls_*.jsonl` 取去重 prompt，做 leave-one-out 最近邻相似度分布。

### 3.2 实测结果（`docs/分析报告/m44_阈值校准报告.json`）

**探针集（20 对）**

| 类别 | 相似度区间 |
|---|---|
| 同义改写对（应命中） | **0.8602 ~ 0.9673** |
| 不同话题对（不应命中） | **0.1048 ~ 0.3883** |

⇒ **可分离带 = (0.3883, 0.8602)**，宽度 **0.4719**，两族**完全不重叠**。

| 阈值 | precision | recall | F1 | 判定 |
|---|---|---|---|---|
| **0.85** | 1.0000 | **1.0000** | **1.0000** | ★ 推荐 |
| 0.88 | 1.0000 | 0.8000 | 0.8889 | 漏检 20% |
| 0.90 | 1.0000 | 0.7000 | 0.8235 | 漏检 30% |
| **0.92（当前值）** | 1.0000 | **0.6000** | 0.7500 | ★ **漏检 40%** |
| 0.95 | 1.0000 | 0.1000 | 0.1818 | 近乎失效 |

全区间扫描：**precision=1.0 且 recall=1.0 的阈值区间 = [0.60, 0.86]**。

**真实语料（66 条去重 prompt）**

| 统计量 | 值 |
|---|---|
| 最近邻相似度 min | **0.7193** |
| p25 / 中位 / p75 | 0.9584 / **0.9649** / 0.9736 |
| max | 0.9917 |
| 分布直方 | `[0.7,0.8)` 1 条；`[0.9,1.0)` 65 条 |

命中率曲线：`0.60~0.70 → 100%`｜`0.72~0.92 → 98.48%`｜`0.94 → 95.45%`｜`0.96 → 69.7%`｜`0.98 → 18.2%`

### 3.3 ★结论与推荐

> **当前阈值 0.92 过高，必须下调。推荐 `SEMANTIC_CACHE_THRESHOLD = 0.85`。**

理由：
1. **0.92 会把 40% 的同义改写挡在门外**（探针集 recall 0.60），而它恰好是设计文档里"为了安全"拍的保守值 —— **保守的方向错了**：0.92 距离真正该防的"异类上界 0.3883"有 0.53 的冗余，却距离"同类下界 0.8602"只剩 −0.06（**已经在同类下界之上，直接漏检**）。
2. **0.85** 位于可分离带内、贴近同类下界上沿，探针集 **P=1.0 / R=1.0**；真实语料命中率 **98.48%**（与 0.92 持平），但**召回从 0.60 提升到 1.00**。
3. **安全带 [0.75, 0.86]**；**硬下限 0.70**（真实语料 min 0.7193，再低就会把"最近邻 0.7193 的那条"也判为命中，风险上升）。
4. ★**校准结论随语料演进**：探针集只有 20 对，同类下界 0.8602 是**样本相关的**。Phase C 前应把探针集扩到 ≥100 对，并**每季度重跑本工具**。

## 四、缓存策略

| 策略 | 设计值 | 理由 / 与现状对比 |
|---|---|---|
| **最大条目数** | `SEMANTIC_CACHE_CAPACITY = 10000`（沿用） | 单条约 512×4B ≈ 2 KB 向量 + 文本；10k 条 ≈ 30–60 MB 内存，可控 |
| **LRU 淘汰** | 沿用 `_evict()`（按 `ts` 最旧优先） | ★**L2 需升级为"按 `last_hit_ts`"**：当前 `ts` 是写入时间，会把"经常命中但很旧"的热条目先淘汰 |
| **TTL** | `SEMANTIC_CACHE_TTL_DAYS = 7`（沿用） | 对话类问题时效性弱；知识类需更短。**建议按 origin 分档**（见下） |
| **TTL 分档（新增建议）** | `user_query` 7 天；`system_internal` 1 天；`evolution_task` 不缓存 | 系统内部 prompt 常含时间戳/运行态，跨天复用危险 |
| **单条文本上限** | `SEMANTIC_CACHE_MAX_TEXT = 4000`（沿用） | 控制文件体积 |
| **持久化** | JSONL 追加（沿用） | ★L2 需补**压缩**：10k 条 × 2KB ≈ 20 MB/文件，7 天 TTL 下会持续增长 |
| **多进程** | 现状为**进程内单例** | ★若框架多进程，各进程缓存独立 → 命中率被稀释。**首期接受**，记录为已知限制 |

## 五、安全机制（★L2 的核心，缺一不可）

L1 之所以能生产常开，是因为**结构上不可能返回内容**。升 L2 后这条结构性保证消失，必须用**显式校验链**替代。

### 5.1 四道闸门（全部通过才返回）

```
命中候选 (sim ≥ 阈值)
   │
   ├─ ① 置信度闸：sim ≥ 0.85 且 (最近邻与次近邻之差) ≥ δ
   │               （δ 建议 0.05；差距过小说明"分不清"，宁可不用）
   │
   ├─ ② 时效闸：now - entry.ts ≤ TTL(origin)  且  条目未被标记 invalidated
   │
   ├─ ③ 幂等闸：origin ∈ {user_query} 且 prompt 不含时间/随机/会话私有标记
   │              （正则剔除："今天/现在/刚刚"、日期串、UUID、user_id）
   │
   ├─ ④ 质量闸：缓存响应非空、长度 ∈ [min_len, max_len]、未被下游标记 rejected
   │
   └─ 全部通过 → 返回缓存响应（并记 `cache_hit=true` 到留存）
        任一失败 → **静默回落到正常渠道调用**（不报错、不影响用户）
```

### 5.2 低置信度不返回

**明确不做"低置信度也返回、只是标注一下"** —— 对话场景里，用户无法感知"这答案是缓存的"，标注等于自我安慰。**低置信度 = 当作未命中。**

### 5.3 上下文敏感问题

相同 prompt 在不同上下文应有不同回答（如"继续"、"再来一个"、"上面那个怎么改"）。缓解：

1. **会话私有标记剔除**：命中前检查 prompt 是否含指代词（"这个/那个/上面/刚才/继续"）→ 含则**跳过缓存**。
2. **短 prompt 不缓存**：长度 < 8 字直接不进缓存（指代/寒暄的高发区）。
3. **prompt 拼接上下文时用完整串**：`_build_chat_prompt()` 已把 memory_context 拼进去 → 上下文不同则完整串不同 → **天然不命中**。★这条是最强的结构性保障，需在实施时确认拼接**发生在缓存查询之前**。

## 六、灰度策略

| 阶段 | 开关 | 流量 | 判定标准（进入下一阶段的门槛） | 时长 |
|---|---|---|---|---|
| **A（现状）** | `ENABLE_SEMANTIC_CACHE_OBSERVE=True`<br>`ENABLE_SEMANTIC_CACHE_L2=False` | 0% | 基线：采集命中率分布 | — |
| **B（Shadow）** | `ENABLE_SEMANTIC_CACHE_L2_SHADOW=True` | 观测 100%，**返回 0%** | 「若返回」的响应与真实响应的**语义一致率 ≥ 99%**（离线审计，抽样 ≥ 200 例） | ≥3 天 |
| **C1** | `ENABLE_SEMANTIC_CACHE_L2=True`<br>`SEMANTIC_CACHE_L2_RATIO=0.05` | **5%** | 命中准确率 ≥99%、无用户可见异常、P95 延迟 +≤8ms | ≥2 天 |
| **C2** | `..._RATIO=0.20` | 20% | 同上 | ≥2 天 |
| **C3** | `..._RATIO=0.50` | 50% | 同上 + 节省调用数达成 ≥15% | ≥3 天 |
| **C4** | `..._RATIO=1.00` | 100% | 节省调用数 ≥18% | 常开 |

**流量比例实现建议**：用 `hash(trace_id/prompt) % 100 < ratio*100` 做**确定性分桶**（同一 prompt 稳定进同一桶），避免"这次命中、下次不命中"的抖动。

## 七、回滚机制

**三层回滚，全部"零代码改动、秒级生效"：**

| 层 | 触发条件 | 动作 | 生效方式 |
|---|---|---|---|
| L-1 自动 | 滑动窗口（≥100 次命中）准确率 < 95% | `SEMANTIC_CACHE_L2_RATIO` **自动置 0**，写 WARNING + 事件留痕 | 进程内即时 |
| L-2 人工 | 监控面板命中率异常 / 收到用户投诉 | 关闭 `ENABLE_SEMANTIC_CACHE_L2` | 改 config 后**需重启**（构型类开关） |
| L-3 兜底 | 缓存文件损坏 / 异常增长 | 重命名 `semantic_cache.jsonl`（**不删除**，遵守《日志留存规范》同一原则） | 即时 |

★ **自动回滚必须是"降比例"而非"全关"**：全关会掩盖问题；降到 0% 保留观测，便于定位。

## 八、监控指标

| 指标 | 定义 | 目标 | 落盘位置 |
|---|---|---|---|
| **命中率** | `hits / (hits + misses)` | 观测（无阈值） | `stats()` → 每日报告 |
| **命中准确率** | shadow 期：缓存响应 ⊕ 真实响应 语义一致率；生效期：**抽样人工审计** | ≥99% | `data/cache/l2_audit_YYYYMMDD.jsonl` |
| **节省调用数** | `cache_hit=true` 的调用条数（来自 `call_recorder`） | ≥18% 的 `user_query` 调用 | `data/llm_traces/` |
| **平均延迟变化** | 命中路径 vs 渠道路径的 P50/P95 差值 | 命中 P95 ≤ 渠道 P50 | 留存 `duration` 字段 |
| **误命中率** | 用户重问率 / 显式否定反馈 | <1% | `record_feedback` 旁路 |
| **缓存体量** | 条目数 / 文件字节 | ≤ capacity / ≤100 MB | `stats()` |

**接入自我认知引擎**（PHASE18 已收官）：新增 `inner_models` 维度的 `semantic_cache_l2` 项，纳入每日画像 —— 与《内在模型孕育计划》的"模型健康监控"建议一致。

## 九、风险评估与缓解

| # | 风险 | 等级 | 影响 | 缓解措施 |
|---|---|---|---|---|
| R1 | **缓存污染**（错误结果被缓存并反复返回） | 🔴 高 | 用户收到错误答案，且**持续复现** | ①只缓存 `status=success` 且响应非空；②**不缓存**下游标记 rejected 的响应；③L-1 自动回滚；④支持按 `entry_hash` 精确 invalidate |
| R2 | **上下文敏感** | 🔴 高 | 答非所问 | §5.3 三条（指代词跳过、短 prompt 不缓存、完整串比对） |
| R3 | **语义漂移误命中**（阈值过低） | 🟠 中 | 相似但不同的问题被误判同义 | 阈值 0.85 + 双近邻差 ≥0.05 + 季度重校准 + 探针集扩充 |
| R4 | **延迟不达预期**（10k 条线性扫描） | 🟠 中 | 主链路变慢 | ①向量已 L2 归一化 → 余弦退化为点积；②**分批 top-k 剪枝**；③超 8ms 自动降级为"仅哈希精确匹配"；④预留 ANN 索引（hnswlib）扩展点 |
| R5 | **缓存命中导致"进化学不到东西"** | 🟠 中 | 命中越多，真实调用越少 → 训练语料管道变稀 | 缓存不改变**留存**（`observe_call` 仍记调用对）；命中单独标记，训练时排除 |
| R6 | **多进程缓存不共享** | 🟡 低 | 命中率被稀释 | 首期接受；记录为已知限制，后续可换 SQLite/共享内存 |
| R7 | **隐私/合规**（缓存含用户私有内容） | 🟠 中 | 跨会话泄露 | ★缓存条目需过 `call_recorder.sanitize_text()` 同一套脱敏；TTL 到期硬删 |
