# 177批 · T-LLM调用复用器-1 设计稿（在途调用去重/合并）

> 状态：设计稿（不实装）｜ 来源：星轨 177批 任务书 刀9 ｜ 关联票：T-LLM调用复用器-1

## 一、目标
对「尚未算出结果但在途」的同质 LLM 调用做去重/合并，降低并发重复花费。与**语义缓存 L2（已建）显式划界**：缓存管「同问命中已算结果」，复用器管「未算在途调用的去重/合并」——**互补不重叠**。

## 二、新键（四键，现 0 命中，全部待建）
| 键 | 默认 | 作用 |
|---|---|---|
| ENABLE_CALL_REUSE | False | 主开关 |
| ENABLE_CALL_REUSE_OBSERVE | False | 观察模式（只记不合并） |
| CALL_MERGE_MIN_GAP_SECONDS | 0.05 | 合并窗下限 |
| CALL_MERGE_MAX_BATCH | 8 | 单批最大合并数 |

**不建** `ENABLE_L3_BACKOFF`（与复用器语义无关，避免混淆）。

## 三、聚合网关层
- 所有 LLM 调用经统一聚合网关；网关按 `(model, prompt_hash, correlation_id)` 判定在途复用。
- 已算结果 → 走 L2 语义缓存命中（不进复用器）。
- 在途 → 同窗内后续同质调用挂同一 future，合并返回。

## 四、分阶段落地
1. 先落 `*_OBSERVE`：只记录潜在可合并对，不实际合并，灰度默认 False。
2. 观察窗确认安全后，翻 `ENABLE_CALL_REUSE=True` 启用合并。
3. 合并窗参数保守（MIN_GAP 小、MAX_BATCH 小），防 starvation。

## 五、与 A1 留痕的相互抑制（★关键）
- A1（`_last_deep_think_partial` 每步写）与复用器同开时，复用器合并可能跳过某些步骤写点 → 相互抑制。
- 裁决：**两特性同开时以 A1 留痕为先**（复用器不得吞并 A1 的步骤写点）。
- 建议：观察模式同窗跑一次，确认 A1 每步写点完整后再决定并开。
