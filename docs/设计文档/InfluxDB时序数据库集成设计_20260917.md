## 一、问题与目标

### 1.1 现状痛点

节点的访问次数、激活时间、修改时间等时序数据当前存在**节点字段内**
（`activation_count` / `last_activated` 等）：

| 能力 | 现状 | 需要 |
|---|---|---|
| 当前累计值 | ✅ 有 | — |
| 过去 7 天访问频率趋势 | ❌ 只有快照值，无历史 | 趋势分析 |
| 访问量突增异常检测 | ❌ 无法计算 | 滑动窗口 + 阈值 |
| 查询耗时 P95 | ❌ 无 | 性能治理 |
| 历史数据保留 | ❌ 无限增长 | 自动降采样 + 过期 |

**根本问题**：字段只能存"当前状态"，存不了"随时间变化的过程"。

### 1.2 目标

- 高吞吐写入（节点激活/访问/修改/查询事件）
- 高效时间范围查询与聚合
- 趋势分析 + 异常检测
- 自动降采样保留策略

## 二、设计

### 2.1 数据模型（measurement 设计）

| measurement | tags | fields | 语义 |
|---|---|---|---|
| `node_activated` | node_id, evol_level | source, count | 节点被激活 |
| `node_accessed` | node_id, access_type | duration_ms, count | 节点被访问 |
| `node_modified` | node_id, field | old, new, count | 节点字段变更 |
| `query_executed` | query_type | duration_ms, result_count | 查询执行 |

- **tag** 用于过滤（低基数：node_id 除外，实际部署需评估基数）
- **field** 用于聚合计算（数值型）

### 2.2 接口

**连接**
```python
connect(url, token, org) -> bool
close()                  -> None   # 先冲刷缓冲区
is_available()           -> bool
```

**写入（带缓冲 + 批量）**
```python
write_point(measurement, tags, fields, timestamp) -> bool
write_points(points)  -> bool
flush()               -> bool

# 语义化预封装
node_activated(node_id, evol_level, source)
node_accessed(node_id, access_type, duration_ms)
node_modified(node_id, field, old_value, new_value)
query_executed(query_type, duration_ms, result_count)
```

**冲刷触发条件**（满足其一）：
- 缓冲区达 `INFLUXDB_BATCH_SIZE`（默认 5000）
- 距上次冲刷超 `INFLUXDB_FLUSH_INTERVAL`（默认 5 秒）
- 显式调用 `flush()` / `close()`

**查询**
```python
query_range(measurement, tags, start, end, aggregation) -> List[dict]
query_latest(measurement, tags, limit)                  -> List[dict]
query_count(measurement, tags, start, end)              -> int
query_trend(measurement, tags, start, end, interval)    -> List[dict]
query_top_k(measurement, tags, start, end, k, order_by) -> List[dict]
query_anomaly(measurement, tags, window_size, threshold)-> List[dict]
```

### 2.3 异常检测算法

**纯客户端实现**（不依赖 InfluxDB 插件）：

```
1. 取窗口内 N 条数据（默认 N=10）
2. 计算 mean 与 stdev
3. 判定：|x - mean| > threshold × stdev  →  异常
4. 输出附带 z_score，便于排序与调参
```

- 数据不足 3 条时返回空（避免误报）
- stdev = 0（数据全等）时返回空（无法判定）

### 2.4 降采样与保留策略

| 层级 | 粒度 | 保留期 |
|---|---|---|
| 原始数据 | 事件级 | 7 天 |
| 1 分钟聚合 | mean | 30 天 |
| 1 小时聚合 | mean | 365 天 |

第70批为**策略设计**（`get_retention_policy()` 返回策略字典）；
第71批+落到 InfluxDB 的 Task / 连续查询。

## 五、降级与容错

- **客户端未安装**：`is_available()` 恒 False，写入/查询返回安全值
- **连接失败**：捕获 + WARNING，不抛给调用方
- **写入失败**：缓冲区保留（不清空），下次冲刷重试
- **查询失败**：返回空列表，调用方降级到节点字段

**核心原则：时序库是增强项，绝不能拖垮主流程。**
