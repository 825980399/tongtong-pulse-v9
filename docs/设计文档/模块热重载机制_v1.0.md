## 一、问题：一次真实事故

### 1.1 事故原文（`logs/pulse.log`，2026-09-13 20:45:16）

```
[代码学习] WARNING: 异常已忽略（需关注）: ImportError: cannot import name
    'trace_evolution_call' from 'nucleus.llm.call_recorder'
[代码学习] ERROR: 代码修复蒸馏异常: ImportError: cannot import name
    'trace_evolution_call' from 'nucleus.llm.call_recorder'
[代码学习] DEBUG: 进化执行链模块未加载，跳过补丁生成: cannot import name
    'trace_evolution_call' from 'nucleus.llm.call_recorder'
```

### 1.2 因果链（★根因是"模块缓存"，不是"代码写错"）

```
第44批 T1 在 call_recorder.py 新增 trace_evolution_call()      ← 磁盘已更新
        ↓
运行中的框架进程早已 import 过 call_recorder（旧版，无该函数）  ← sys.modules 命中缓存
        ↓
[代码学习] 触发「重新导入 SafeEvolutionExecutor」              ← 该模块顶层 import 了新函数
        ↓
Python 解析 SafeEvolutionExecutor 的 import 语句时，
从 **已缓存的旧版 call_recorder** 取 trace_evolution_call
        ↓
ImportError → SafeEvolutionExecutor 整个模块加载失败
        ↓
代码修复蒸馏跳过 / 进化执行链未加载 / 跳过补丁生成
        ⇒ **自主进化闭环受阻（连续 5 轮修复率 < 10%）**
```

**★关键结论**：**改对了代码，却因为"进程内存里还是旧版"而失效**。这不是编码错误，
是**缺失的运行时能力**——框架只能热重载「配置值」，不能热重载「代码」。

### 1.3 现状盘点（实测）

| 能力 | 现状 | 证据 |
|---|---|---|
| **配置热重载** | ✅ 已有 | `config.py` 的 `_COVERABLE_CONFIGS` + `data/config_override.json` + 后台 watcher 线程（`_config_watcher_thread`）；支持 `TTP_` 前缀环境变量覆盖 |
| **模块热重载** | ❌ **完全没有** | 全库 `def reload_config` / `hot_reload` / `ConfigWatcher` 调用点 **0 处**；`pulse.log` 中「热重载」关键词 **0 次** |
| 事故机制 | — | `sys.modules` 缓存已导入模块；再次 `import` 命中缓存 → **新旧不一致** |

**重启成本**：约 30 秒启动时间 + 运行态丢失风险（`up=29m` 的框架重启即丢失全部会话/自省上下文）。

## 二、目标与非目标

### 2.1 目标

在**不重启框架**的前提下，安全地重新加载**被修改过的 Python 模块**，
使代码修复**立即生效**，消除"改对代码却失效"这一类空洞。

### 2.2 非目标（明确不做）

* ❌ **不是**"任意热更新" —— 不做 `.py` → 字节码的运行时替换（那是 `reload` 的能力边界）。
* ❌ **不是**"替代重启" —— 涉及 `main.py` 启动逻辑、类结构变更的场景**仍必须重启**。
* ❌ **不是**"生产自动改代码" —— 触发方仍是**人**（或显式的管理命令），不接自动进化链。
* ❌ **不是**"热补丁" —— 不修改磁盘文件，只重新加载**已存在的**新版本。

## 三、范围界定（★三级分类，本设计核心）

### 3.1 ✅ 可热重载（低风险）

| 类别 | 举例 | 理由 |
|---|---|---|
| **纯函数 / 工具函数** | `tools/*.py`、`nucleus/data/write_guard.py` | 无状态、调用方按名调用 |
| **常量 / 配置值** | `config.py` 的标量项 | 已是既有能力（`config_override.json`） |
| **非核心器官的方法体** | 叶子器官（如 `PulseThymus`）的内部实现 | 实例状态少、耦合低 |
| **新增函数** ★本次事故场景 | `call_recorder.trace_evolution_call` | 只增不改，不破坏既有契约 |

### 3.2 ⚠️ 谨慎热重载（需状态迁移，中风险）

| 类别 | 风险 | 必要条件 |
|---|---|---|
| **核心器官的类定义** | 已实例化对象仍指向**旧类**（`type(obj)` 不变） | 必须做**实例 `__dict__` 迁移** + 类对象替换 |
| **模块级单例** | 单例持有旧类实例 | 单例重建 + 状态回填 |
| **被大量模块 `from X import Y` 的符号** | 其他模块已绑定**旧引用** | 需级联 reload（见 §4.2 拓扑序） |

### 3.3 ❌ 不可热重载（明确禁止）

| 类别 | 理由 |
|---|---|
| `main.py` 启动逻辑 | 执行一次性的进程初始化，reload 会重复建线程/端口 |
| `config.py` 的**基础配置**（如开关初值） | 需在进程早期生效；已有 `config_override.json` 覆盖路径 |
| **已实例化的核心对象**（含锁/线程/文件句柄） | reload 会制造"两个同名类"，锁与句柄语义崩坏 |
| **C 扩展 / `.pyx`** | 需重新编译，非 `importlib.reload` 能力范围 |
| **改了 `__init__` 签名的类** | 既有实例无法安全迁移 |

## 四、安全机制（五道防线）

### 4.1 ① 语法检查（reload 前）

```
新文件 → py_compile.compile(doraise=True) → 失败则不 reload（保持旧版，报错）
```
★ **绝不允许"把语法错误的模块装上"** —— 那会让整个进程进入半损坏状态。

### 4.2 ② 依赖检查 + 拓扑序（reload 顺序）

```
模块依赖图（由 AST 扫描 `import` / `from ... import` 构建）
        ↓
找出「目标模块 ∪ 其下游依赖者」的传递闭包
        ↓
按**拓扑序**（被依赖者先 reload）逐批执行
```
★ **为什么必需**：若先 reload 消费者、后 reload 提供者，消费者的 `from X import Y`
会重新绑定到**旧版提供者** → 这正是本次事故的镜像。

### 4.3 ③ 状态保留（`__dict__` 迁移）

```python
# 伪代码（仅接口定义，本批不实施）
old_cls = sys.modules[mod].__dict__[cls_name]
new_cls = new_module.__dict__[cls_name]
for inst in live_instances_of(old_cls):
    inst.__class__ = new_cls              # 切类
    merged = dict(new_cls.__init__defaults())
    merged.update(inst.__dict__)          # ★既有实例属性优先（不丢状态）
    inst.__dict__.clear(); inst.__dict__.update(merged)
```
* ★**类变量同步**：新类新增的类级常量需注入实例（否则 `__getattr__` 找不到）。
* ★**不可迁移项**（锁 / 线程 / 文件句柄）→ 保留旧值**不做替换**，并在报告里标注。

### 4.4 ④ 回滚（事务式）

```
快照旧模块对象（sys.modules[mod]）
        ↓
执行 reload（可能失败/部分成功）
        ↓
失败 → sys.modules[mod] = 快照；实例 __dict__ 回填；报告 rollback
```
★ **事务式语义**：一批依赖闭环内**要么全部成功、要么全部回滚** ——
不允许"reload 了一半"的中间态（会制造更难排查的不一致）。

### 4.5 ⑤ 灰度策略

| 阶段 | 范围 | 门槛 |
|---|---|---|
| G1 | 只允许 `tools/*` + 纯函数模块 | 连续 N 次 reload 后框架无异常 |
| G2 | 扩展到「叶子器官」（无下游消费者的模块） | reload 后 1 小时内 0 异常 |
| G3 | 谨慎档（核心器官类定义，需状态迁移） | 每次**人工确认** + 单独记录 |
| G4 | ❌ 不可热重载清单**永久禁止** | — |

## 五、触发方式

| 方式 | 形态 | 说明 |
|---|---|---|
| **手动** | 控制台命令 `reload <module_name>` | ★**首期唯一放行方式** —— 可审计、可回退 |
| **自动** | 监听文件变化（watchdog），**延迟 5 秒批量** reload | 延迟用于合并"编辑器多次保存"的抖动 |
| **定时** | 每小时检查一次文件变化 | 兜底（自动方式不可用时的降级路径） |

★ **自动/定时方式必须可开关，且默认关闭** —— 无人值守时自动 reload 生产进程风险过高。

## 六、监控指标

| 指标 | 定义 | 目标 |
|---|---|---|
| **reload 成功率** | 成功次数 / 总次数 | ≥99%（G1/G2 阶段） |
| **reload 耗时** | 单模块 reload 的 P50/P95 | 单模块 < 200ms；整批 < 2s |
| **reload 后异常率** | reload 后 N 分钟内该模块相关异常数 | **0** |
| **状态保留成功率** | `__dict__` 迁移成功实例数 / 应迁移实例数 | ≥99%；不可迁移项单独计数 |
| **回滚次数** | 触发事务回滚的次数 | 观测（**持续为 0 也要报** —— 铁律 #25：防"判据恒假"） |
| **等效重启避免数** | 因 reload 而省下的重启次数 | 目标 ≥80% 的代码修复场景 |

★ **落盘**：`logs/module_reload_events.log`（独立留痕，与 `logs/log_integrity_events.log` 同一套思路），
每条含：时刻 / 模块 / 依赖闭环 / 耗时 / 结果 / 回滚原因 / 迁移实例数。

## 七、风险与缓解（★7 项，超出任务书要求的 ≥5 项）

| # | 风险 | 等级 | 影响 | 缓解措施 |
|---|---|---|---|---|
| **R1** | **循环导入** | 🔴 高 | reload 死锁 / 半加载 | 依赖图**拓扑排序**；检测到环 → 拒绝该闭环并将**整个环**一起 reload（同批事务） |
| **R2** | **实例状态丢失** | 🔴 高 | 运行态（会话、自省上下文）清零 | `__dict__` 拷贝（既有属性优先）+ 类变量同步；不可迁移项显式标注并保留旧值 |
| **R3** | **线程安全** | 🔴 高 | 主线程正用旧类、reload 线程替换类对象 → 竞态 | **全局锁 + reload 队列**：reload 只在"安全点"执行；执行期间业务线程阻塞在锁上 |
| **R4** | **部分 reload 导致不一致** | 🟠 中 | 最难排查的中间态 | **事务式**：闭环内全成或全回滚（§4.4） |
| **R5** | **消费者持有旧引用**（★本次事故） | 🔴 高 | `from X import Y` 仍指向旧函数 | 依赖**下游闭包**必须一起 reload；把 `from ... import` 现场替换为 `module.attr` 延迟取值（结构性根治） |
| **R6** | **C 扩展 / 编译产物无法 reload** | 🟠 中 | 误以为生效、实则未生效 | reload 前扫描目标模块是否含 `.so`/`.pyd`/`.pyx` → **拒绝并提示重启** |
| **R7** | **回滚不彻底** | 🟠 中 | 旧模块对象已释放，无法真正恢复 | reload **前**先 `copy` 旧模块对象的 `__dict__` 关键项；回滚只恢复引用与关键状态，**其余提示重启** |

## 八、最小可行原型（MVP）接口定义（★仅接口，不实现）

```python
# nucleus/reload/module_reloader.py  —— 设计草案，本批不创建该文件
from typing import Sequence

class ModuleReloader:
    """事务式模块热重载器（设计接口）。"""

    def plan(self, modules: Sequence[str]) -> dict:
        """只读：返回 {'order': [...], 'cycle': [...], 'forbidden': [...], 'instances': N}。

        不修改任何状态 —— 供人工审阅。
        """

    def reload(self, modules: Sequence[str], *, dry_run: bool = True) -> dict:
        """执行（或演练）一次事务式 reload。

        Returns:
            {'ok': bool, 'reloaded': [...], 'rolled_back': [...],
             'instances_migrated': N, 'elapsed_ms': F, 'reason': str}
        """

    def rollback_token(self) -> str:
        """返回本次 reload 的回滚令牌（供审计留痕引用）。"""

# 控制台入口（设计）
#   reload --plan <module>     列出依赖闭环与风险
#   reload --apply <module>    执行（默认 dry-run，需显式 --apply）
```

**调用流程（设计）**：

```
reload --plan  → 人工审阅 order/cycle/forbidden/instances
      ↓ 确认
reload --apply → [语法检查] → [依赖闭环] → [快照] → [拓扑序 reload]
                 → [实例 __dict__ 迁移] → [验证] → 成功 / 回滚
      ↓
logs/module_reload_events.log 留痕
```
