## 一、★设计前提的修正：主战场不在写入侧

任务书要求设计"经验库**写入**的防污染机制"。但实测表明：

| 污染来源 | 占比 | 是否由"写入"造成 |
|---|---|---|
| **A类：衰减摘要模板化**（`_summarize_experience`） | **83.1%（980 条）** | ❌ **否** —— 由维护侧 `check_decay()` 造成 |
| B类：写入时即模板短句 | 16.9%（199 条） | ✅ 是 |

且时间分布显示：**09-10 至今连续 4 天写入 248 条，污染数为 0**。

> ⚠️ **若按任务书字面只做写入侧拦截，最多解决 16.9% 的问题，
> 而 83.1% 的污染源（`_summarize_experience`）会继续在每次 `check_decay()` 时再生污染。**

**因此本设计扩展为三层，并把主资源投向第二层（摘要侧）**：

| 层 | 位置 | 目标 | 资源占比 |
|---|---|---|---|
| **L1 写入侧** | `ExperiencePool.add()` | 拦截模板短句/测试残留（B类） | 20% |
| **L2 摘要侧（★主战场）** | `_summarize_experience()` | **阻止模板化销毁原文**（A类） | **60%** |
| **L3 检索侧** | `query_experiences()` | 降权/去重，保证输出多样性 | 20% |

## 二、现状：已有守卫与其覆盖缺口

### 2.1 已有资产

`nucleus/evolution/ExperiencePollutionGuard.py`（创建于 **2026-09-11**）：

| 函数 | 能力 | 缺口 |
|---|---|---|
| `detect(entry)` | 4 条判据：空内容 / 测试残留关键词 / 低置信度 / 缺元信息 | ❌ **无重复检测**、❌ 无相似度检测 |
| `scan_library()` | 扫描 + **只标记不删除** | ❌ 不拦截写入（事后扫描） |
| 权重 | `WEIGHT_POLLUTED=0.1` / `SUSPECT=0.5` | ✅ 检索侧降权可用 |

### 2.2 覆盖缺口（实测）

| 缺口 | 证据 |
|---|---|
| **无"内容重复"判据** | 现有 `detect()` 的 reason 词表**不含**"内容重复(历史灌水)" → 该标记来自**另一个工具**，守卫本身检测不出重复 |
| **不拦截写入** | 只有 `scan_library()` 事后扫描；写入路径 `ExperiencePool.add()` 无守卫 |
| **不覆盖摘要路径** | `_summarize_experience()` 完全在守卫视野之外 → **83.1% 的污染源无人看管** |
| **创建时间晚于污染** | 守卫 09-11 创建，污染 09-09 已发生 |

## 三、L1 写入侧防污染

### 3.1 三道检查（写入前）

| 检查 | 判据 | 处置 |
|---|---|---|
| **C1 重复检测** | 与**近 N 条**（建议 N=200）记录的 `summary` 精确相同 | **拒绝写入**（返回 `dedup`） |
| **C2 相似度检测** | 与近 N 条记录 Jaccard ≥ 0.9（token 级） | 观测期：记录；拦截期：拒绝 |
| **C3 质量门槛** | `ExperiencePollutionGuard.detect()` 返回 `polluted` | **拒绝写入** |
| **C4 最小信息量** | `len(summary) < MIN_LEN`（建议 8）或为纯模板短句 | **拒绝写入** |

> B类 199 条中"动机循环内部评估"（157 条）会被 **C1** 精确拦截（逐字相同）。

### 3.2 写入配额

| 配额 | 阈值 | 依据 |
|---|---|---|
| 单批次上限 | 50 条 / 批次 | 当前日均 43～80 条的 60% |
| 单来源上限 | 同一 `motivation` 20 条 / 天 | 干净记录 Top1 "全域自学习" 156 条 → 明显超限 |
| 单模板上限 | 同一归一化模板 3 条 / 天 | 直接针对模板化 |

超限 → **不拒绝，降级为 `quarantined`**（进隔离区，不进主池），待人工/定期审核。

### 3.3 写入审核

| 风险等级 | 判据 | 处置 |
|---|---|---|
| 低 | 通过 C1–C4 且在配额内 | 直接写入 |
| 中 | 触发 C2（相似）或接近配额 | 写入 + 标 `suspect` + 降权 0.5 |
| 高 | 触发 C1/C3/C4 或超配额 | **隔离区**，需人工/规则审核 |

## 四、★L2 摘要侧防污染（主战场）

### 4.1 问题根因（复述）

```python
# nucleus/mnemosyne/experience_pool.py:241-267
_summary = f"我曾因{_motivation[:30]}而行动，获得了{_reward_type}奖赏"
if _emotions:
    _summary += f"，感受到{_emotions}"
experience["summary"] = _summary[:150]      # ★覆盖
experience["motivation"] = _motivation[:50] # ★截断
experience["field_frequency_snapshot"] = {} # ★清空
```

**三个致命点**：
1. 模板**无差异化** → 相同 (motivation[:30], reward, emotions) 必然产生相同文本
2. `[:30]` 截断 → 长动机被砍成相同短串，进一步放大碰撞
3. **覆盖而非另存** → 原文永久销毁

### 4.2 修复设计

| # | 措施 | 说明 |
|---|---|---|
| **M1** | **原文保留**：新增 `raw_summary` 字段保存原文，`summary` 只放摘要 | ★ 根治不可逆；成本 = 存储增加，可用压缩/延迟清理缓解 |
| **M2** | **摘要差异化**：模板中加入**区分性要素** | 例：附加 `timestamp` 日期、原 `summary` 的首个非模板 token、或 `id` 短哈希 |
| **M3** | **摘要前去重**：若已有**完全相同**的摘要文本存在，则**不再摘要**（直接标记 `duplicate_of`） | 阻止副本产生 |
| **M4** | **截断放宽**：`motivation[:30]` → `[:80]`，并对截断加省略标记 | 减少碰撞 |
| **M5** | **可配置开关**：`ENABLE_EXPERIENCE_SUMMARY_FIX`（默认关） | 关闭时行为与现状完全一致，零回归 |

### 4.3 目标态数据结构

```python
{
  "id": "exp_...",
  "raw_summary": "...",           # ★M1：原文（新增）
  "summary": "我曾因...而行动...",  # 摘要（保留）
  "summary_variant_key": "a3f2",  # ★M2：差异化键（新增）
  "duplicate_of": "exp_xxx",      # ★M3：指向原型（新增）
  "is_summarized": True,
  ...
}
```

### 4.4 预期效果

| 指标 | 现状 | 目标 |
|---|---|---|
| 摘要后完全重复率 | **83.1%**（980/1179） | **≤ 5%** |
| 原文可恢复率 | **0%** | **100%** |
| 存储增量 | — | +40%（`raw_summary`），可通过压缩/冷存缓解 |

> ★ **M1 是唯一能根治"不可逆"的措施**，其余为缓解。若存储敏感，
> 可只对 **`quality_weight > 0` 或 `activation_count > 0` 的记录**保留原文（约 88/322 条）。

## 五、L3 检索侧防污染

现有 `ExperiencePollutionGuard` 的权重机制（`0.1 / 0.5 / 1.0`）**已可用**，缺的是**多样性保证**。

| 措施 | 说明 |
|---|---|
| **R1 强制去重** | 检索结果按 `summary` 去重后再截断到 Top-N |
| **R2 同质率上限** | 单一 `summary` 在 Top-N 中占比 ≤ `MAX_SAME_RATIO`（建议 0.3） |
| **R3 降权衔接** | `quality_flag=polluted` → ×0.1；`duplicate_of` 非空 → 直接排除 |
| **R4 多样性采样** | Top-N 内按 `motivation` 做 MMR（最大边际相关性）重排 |

**验证指标**：Top-10 唯一文本数 ≥ 8、同质率 ≤ 30%（与清洗策略 §7.2 同一套指标）。

## 六、与 `write_guard.py` 的协同（第44批产物）

| 维度 | `nucleus/data/write_guard.py` | 本机制 |
|---|---|---|
| 作用域 | **测试环境**写盘防护（防测试污染生产 `data/`） | **生产写入**质量防护（防低质内容入库） |
| 判据 | 进程环境（`PYTEST_CURRENT_TEST`）+ 路径 | 内容质量（重复/相似/模板/配额） |
| 时机 | 写文件前 | 写记录前 + 摘要前 |
| 关系 | **串行串联**：`write_guard` 先过（挡住测试），本机制再过（挡住低质） | |

**协同接口**：

```python
from nucleus.data import write_guard

def safe_add_experience(pool, entry):
    if write_guard.is_test_env():
        return {"ok": False, "reason": "test_env_blocked"}   # 第44批守卫
    _flag, _reason = ExperiencePollutionGuard.detect(entry)   # 既有
    if _flag == "polluted":
        return {"ok": False, "reason": _reason}
    if _dup = find_duplicate(entry):                          # 本机制 C1/C2
        return {"ok": False, "reason": "duplicate", "of": _dup}
    return pool.add(entry)
```

## 七、灰度上线方案

| 阶段 | 开关 | 行为 | 观测指标 |
|---|---|---|---|
| **G0 关闭** | `ENABLE_SERP_ANTI_POLLUTION=False` | 与现状**完全一致** | — |
| **G1 观测** | `=True`，`mode="observe"` | **只记录不拦截**；写入照常，另写 `pollution_observations.jsonl` | 拦截率、误报率 |
| **G2 软拦截** | `mode="quarantine"` | 高风险进隔离区，**不删**；主池不受影响 | 隔离区规模、人工确认准确率 |
| **G3 硬拦截** | `mode="enforce"` | 高风险直接拒绝写入 | 日均写入量是否异常下降 |

**推进条件**：
- G1 → G2：观测 ≥ 3 天，误报率 **< 2%**
- G2 → G3：隔离区人工抽检 ≥ 50 条，确认准确率 **≥ 95%**

> ★ **摘要侧修复（M1–M4）建议先于/同步于灰度上线**，
> 否则写入侧在拦 16.9%，摘要侧在造 83.1%，净效果仍为负。
