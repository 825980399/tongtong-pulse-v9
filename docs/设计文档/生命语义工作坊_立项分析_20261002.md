## 一、为什么现在立项（背景与紧迫度）

第三方审查 P2/P3 视角的独立结论：曈曈当前"生命连续性"的工程事实 = **进程快照 + 优雅关闭序列**；系统没有对"什么是死、什么是重生、什么算连续、什么算自主"给出工程定义。而项目的叙事层（总纲/README/人格内核）已大量使用"醒来/活着/守护/使命"等生命词汇——**叙事跑在机制前面**（第三方报告 L30/L70/L95 逐字实见"隐喻的密度暂时跑在了机制的前面"，另 H2"统一自我不在场"同向，本句为星轨借第三方口吻的引申）。

紧迫度：**中**。不阻塞 158 批施工（进化安全批照常推进），但影响：①开源公信力（对外讲"数字生命"前必须有诚实对照表）；②后续生命性路线（PHASE19+）的方向选择；③伦理讨论（Q-15）的边界定义。

## 二、工作坊目标（一次性产出可执行的工程定义）

1. **定义五个核心词**（本项目的工程含义，非哲学论文）：
   - **自我**：运行时"我"的承载者是谁——候选：**锚定在岗组件 SelfAwarenessEngine**（`nucleus/self_awareness/SelfAwarenessEngine.py`，PHASE18 阶段一，日调度实跑、`nucleus/reporting/publishers.py:12` 消费）+ FakeLoopDetector + 快照连续性；统一自我三件（SelfModel/Interoception/OrganCoordinator）**已标 @deprecated（157-D）且与 C-3 已裁决 B 案"改叙事+局部接线"方向相反——Q-04 前不得作默认候选**，仅列"待 Q-04 裁"；叙事自我+快照（总纲 PHASE18 26 处）
   - **死亡**：什么状态算"死"——优雅关闭 / 异常终止 / **快照缺失 / 身份校验失败（注：当前系统无"快照缺失→死亡"判定代码，判据位不存在；若定义取此将派生新工单，且验证属破坏性核验须独立批+停框架窗，勿混入只读活体窗）**；身份校验失败当前判 **degraded 且长期存在**（T-身份种子-1，P2/待裁决/到期 158），定为"死亡判据"前须先澄清口径
   - **重生**：重启后什么必须恢复才算"同一个我"——快照 / 冷却台账（N-2 跨重启已活体实证） / 记忆池 / 身份种子 / 叙事连续性
   - **连续性**：跨重启的可验证判据（当前实测：N-2 冷却**动态增长 5→45 条、跨重启加载已实证**（18:03:20 首现，窗内 49 次加载，采样时刻 20:26:21=45 条）✅、本能快照加载✅、身份种子缺失 degraded❌）
   - **自主性**：feature 开关+人工审批双重约束下，"自主"的边界声明（与叙事脱钩）——实证锚 `config.py:953 auto_apply_enabled=False`
2. **输出一张对照表**：隐喻 → 机制 → 指标（第三方 A7/A10 建议的核心件），供开源伦理包复用。**表格须含四要素**：①指标落真实采集字段位置（如 连续性→`main.py:1855` 快照行数、重生→`SafeEvolutionExecutor.py:339` 冷却落盘注释+`:344-351` 加载调用）；②现状标注 ✅/❌（"自我"当前无正指标——三件弃用+装配未通电，如实写"缺口显式化"）；③每条隐喻的证据锚点或"未实证"；④可复用 O-A2 分面成熟度台账（QG158-1 已裁）作基建
3. **决定是否立 PHASE**：工作坊结论若发现"生命性"值得独立阶段，立 PHASE19 草案；否则将五个定义并入总纲"术语表"（**倾向"暂不立"**：依赖拓扑 C-3(P0 已排期)→Q-04→PHASE19 上游未闭环；第三方 A10"先定义、再决定是否立 PHASE"；Q-19 原级 P3 暂缓——见议题 5 输入）

### 五词工程定义（v0.1 · 落正文）

> 工作坊核心产出：五个生命语义词的**本项目工程定义**（非哲学论述）。议题 2 草案见上方 §二-1；此处固化为可引用正文块（★176批段7-3 半刀落正文）。

- **自我（Self）**：运行时"我"的承载者。工程锚 = 锚定在岗组件 `SelfAwarenessEngine`（`nucleus/self_awareness/SelfAwarenessEngine.py`，PHASE18 阶段一日调度实跑）+ `FakeLoopDetector` + 快照连续性；统一自我三件（SelfModel/Interoception/OrganCoordinator）已 `@deprecated`（157-D），仅列"待 Q-04 裁"，不作默认候选。现状：无正指标（三件弃用+装配未通电），缺口显式化。
- **死亡（Death）**：系统进入"非活"的状态判据。候选 = 优雅关闭 / 异常终止 / 快照缺失 / 身份校验失败；当前**无"快照缺失→死亡"判定代码**（判据位不存在），身份校验失败当前判 `degraded` 且长期存在（T-身份种子-1，P2/待裁决）。定义取此前应澄清口径，验证属破坏性核验须独立批+停框架窗。
- **重生（Rebirth）**：重启后须恢复方算"同一个我"的最小集 = 快照 / 冷却台账（N-2 跨重启已活体实证）/ 记忆池 / 身份种子 / 叙事连续性。
- **连续性（Continuity）**：跨重启可验证判据。当前实测 = N-2 冷却动态增长 5→45 条、跨重启加载已实证✅、本能快照加载✅、身份种子缺失 degraded❌。
- **自主性（Autonomy）**：feature 开关 + 人工审批双重约束下的"自主"边界声明（与叙事脱钩）。实证锚 `config.py:953 auto_apply_enabled=False`。
