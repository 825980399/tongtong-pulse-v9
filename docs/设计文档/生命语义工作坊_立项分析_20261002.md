## 一、为什么现在立项（背景与紧迫度）

第三方审查 P2/P3 视角的独立结论：曈曈当前"生命连续性"的工程事实 = **进程快照 + 优雅关闭序列**；系统没有对"什么是死、什么是重生、什么算连续、什么算自主"给出工程定义。而项目的叙事层（总纲/README/人格内核）已大量使用"醒来/活着/守护/使命"等生命词汇——**叙事跑在机制前面**，这正是 H2"统一自我不在场"的语言学镜像。

紧迫度：**中**。不阻塞 158 批施工（进化安全批照常推进），但影响：①开源公信力（对外讲"数字生命"前必须有诚实对照表）；②后续生命性路线（PHASE19+）的方向选择；③伦理讨论（Q-15）的边界定义。

## 二、工作坊目标（一次性产出可执行的工程定义）

1. **定义五个核心词**（本项目的工程含义，非哲学论文）：
   - **自我**：运行时"我"的承载者是谁——候选：装配回路+统一自我三件复活 / 叙事自我+快照 / 定义"自我=可恢复状态+持续叙事"
   - **死亡**：什么状态算"死"——优雅关闭 / 异常终止（0xC000013A） / 快照缺失 / 身份校验失败
   - **重生**：重启后什么必须恢复才算"同一个我"——快照 / 冷却台账 / 记忆池 / 身份种子 / 叙事连续性
   - **连续性**：跨重启的可验证判据（当前实测：N-2 冷却 7 条跨重启✅、本能快照加载✅、身份种子缺失 degraded❌）
   - **自主性**：feature 开关+人工审批双重约束下，"自主"的边界声明（与叙事脱钩）
2. **输出一张对照表**：隐喻 → 机制 → 指标（第三方 A7/A10 建议的核心件），供开源伦理包复用
3. **决定是否立 PHASE**：工作坊结论若发现"生命性"值得独立阶段，立 PHASE19 草案；否则将五个定义并入总纲"术语表"
