> **批次**：主线第44批 T3（P1-256）　**编制**：路灯　**日期**：2026-09-13
> **性质**：**纯设计文档 —— 本批不实施**。不新建调用精简器模块，不新增任何生产开关。
> **上游**：
> - `docs/设计文档/大模型调用精简方案_v1.0.md`（第43批 T2，A/B/C 三档）
> - `docs/设计文档/语义缓存升L2方案_v1.0.md`（第44批 T2，L1→L2）
> **定位一句话**：**L1/L2 是"感知与认知"，L4 是"迭代进化"，L3 是把两者粘起来做"这次调用到底发不发"的决策器。**

## 一、为什么需要 L3

### 1.1 内在模型四层架构现状（v3.0）

| 层 | 定位 | 已落地 | 数量 |
|---|---|---|---|
| **L1 数据感知** | 数据是否可信 / 有无重复 | 语义缓存器、数据质量评估器 | ✅ ×2 |
| **L2 推理认知** | 历史经验是否可复用 | 经验检索器 | ✅ ×1 |
| **L3 决策协同** | **这次调用发不发 / 怎么发** | —— | ❌ **0（本设计补齐）** |
| **L4 迭代进化** | 上述模型自身是否在退化 | 补丁质量评估器、模型自更新器 | ✅ ×2 |

### 1.2 缺 L3 的后果（**实测证据**）

第43批 T2 实测：`data/llm_traces` 剔污染后识别出 **4 类可优化模式**，但**没有任何代码据此做决策**：

| 实测现象 | 数据 | 当前处置 |
|---|---|---|
| 重复 prompt 冗余 | 16 条 / 87 条 = **18.4%** | 无（只统计，不动手） |
| 失败未记原因 | 9 / 9 全空 | 无（本批 T1 已补 `error`） |
| `prompt_version` 缺失 | **100%** | 无（本批 T1 已补） |
| 渠道分散 | 6 渠道 / 6 模型 | 无 |

⇒ **模型层"看得见"，但没有"手"** —— 这正是 L3 要补的位置。

### 1.3 L3 的边界（不做什么）

* **不做**语义相似判定 —— 那是 L1 语义缓存的职责（L3 只消费它的结论）。
* **不做**经验内容检索 —— 那是 L2 经验检索器的职责。
* **不做**补丁效果评估 —— 那是 L4 的职责。
* **不改变**渠道选择 / 熔断 / 并发策略 —— 那是 `PulseLung` 既有能力，L3 只决定"**要不要进 `_call_via_channels`**"。

## 二、核心功能（4 项）

### 2.1 重复调用检测

**输入**：待发调用 `(prompt, origin, caller, ts)` + 近期调用窗口。

**判定（三层，成本递增）**：

| 层 | 判据 | 成本 | 适用 |
|---|---|---|---|
| D1 精确 | `sha256(prompt)` 命中在飞/近期记录 | O(1) | 全部 |
| D2 规范化 | 去空白/标点/大小写后哈希命中 | O(1) | 全部 |
| D3 语义 | 交 L1 语义缓存（superseded by T2） | 编码 + 比对 | 仅 L2 放行后 |

**输出**：`{is_duplicate, level: D1/D2/D3, matched_trace_id, similarity}`

### 2.2 结果复用

对**幂等任务**直接复用上次结果，跳过调用。

**幂等白名单（首期，按 `origin` + 任务类型）**：

| 幂等（可复用） | 非幂等（禁止复用） |
|---|---|
| 代码分析 / 静态审查 | **对话回复**（用户期待变化） |
| 知识检索 / 分类判别 | **创造性写作 / 补丁生成** |
| 搜索意图分类（`nucleus/SearchIntentClassifier`） | 反思 / 自我评估（结果依赖运行态） |
| 语义理解 JSON 抽取 | 含时间/随机/会话上下文的 prompt |

**复用前置校验（缺一不可）**：
1. 任务在幂等白名单内；
2. 上次结果 `status=success` 且响应非空；
3. 在 **TTL** 内（默认 `REUSE_TTL_SEC=600`，10 分钟）；
4. 上次**未被下游否定**（无 `feedback=rejected`）；
5. 双近邻置信度足够（复用 T2 §5.1 ① 的口径，避免"分不清"）。

### 2.3 失败退避

同一 prompt（按 D2 规范化键）连续失败 → 熔断，避免无效重试烧额度。

| 参数 | 建议值 | 说明 |
|---|---|---|
| 失败计数键 | `sha256(normalized_prompt)` | 同 prompt 同一键 |
| 触发阈值 | **3 次**连续失败 | 与框架既有"连败 3 次熔断 300s"渠道级策略**同口径**（`_channel_health`） |
| 退避时长 | 指数：`60s → 300s → 900s` | 上限 **900s（15 分钟）** |
| ★**最大退避时间（硬上限）** | **900s** | **避免"永久熔断"** —— 到期必放行一次探测 |
| 成功即清零 | 是 | 任一成功立刻清计数 |
| 失败类型区分 | 仅对**可重试类**（timeout / 429 / 5xx）退避 | 400/401/403（配置/权限错）**不退避**，立即表面失败 |

**★为什么必须有硬上限**：若失败根因是"渠道临时挂了"，熔断 300s 合理；但若根因是"prompt 本身有问题"（如超长），无限退避会让**该问题永远得不到诊断**。硬上限保证"每 15 分钟至少有一次真实尝试 → 失败样本持续进入留存 → 可诊断"。

### 2.4 追问链合并

继承《大模型调用精简方案》**C 档**（风险中）：

1. **识别追问链**：同一 `trace_id` 谱系，或同一 `origin` + 60s 时间窗内的连续调用。
2. **合并**：K 个「system+user」对拼成**单次多轮**，要求模型**分段输出**（带分隔标记）。
3. **拆分**：按分隔标记切分 → 回填各自 `trace_id`（**保持可观测性不丢**）。
4. **回退**：解析失败 → **降级为逐条调用**（只损失收益，不损失正确性）。
5. **开关**：`ENABLE_LLM_CALL_BATCH_MERGE`（默认 False）。

**实测前的冷静判断**：第43批已定性 —— **依赖度的真正来源是进化循环的重复发现问题（98.8%）**，`_call_llm_with_followup` 的失败根因是"补丁没真生效"。因此**追问链合并的收益上限有限**，应排在"让补丁真正生效"之后。**L3 首期只做 2.1/2.2/2.3，2.4 明确延后。**

## 三、与其他内在模型的协作

### 3.1 数据流

```
                    ┌───────────────────────────────┐
   L1 语义缓存器 ───▶│                               │
   （命中率/相似度）   │                               │
                    │        L3 调用精简器           │
   L2 经验检索器 ───▶│  (决策协同层 · 无副作用)       │──▶ 决策：复用 / 新发 / 退避 / 合并
   （相似历史经验）    │                               │
                    │                               │──▶ 反馈：命中/复用/退避 事件
   L1 数据质量评估器 ─▶│                               │
   （数据可信度）      └───────────────────────────────┘
                                     ▲
                                     │ 效果数据（复用的结果好不好）
                            L4 补丁质量评估器
```

### 3.2 逐层接口约定（设计）

| 方向 | 来源/去向 | 接口 | 用途 |
|---|---|---|---|
| **输入** | L1 语义缓存器 | `get_semantic_cache().lookup(prompt)` → `{similarity, hit, entry_hash}` | D3 重复检测 / 复用置信度 |
| **输入** | L2 经验检索器 | `ExperienceRetriever.search(query, top_k)` | 判断"这类任务历史上复用是否踩过坑" |
| **输入** | L1 数据质量评估器 | `quality_report.json` 的 `purity` | 数据污染高时**收紧**复用（宁可不复用） |
| **输出** | `PulseLung` 调用链 | `DecideResult(action, reason, matched)` | 唯一的决策出口 |
| **输出** | `call_recorder` | `record(..., decision="reuse"/"backoff"/"new")` | 可观测 + 可统计 |
| **反馈** | L4 补丁质量评估器 | `real_effectiveness()` / 假通过列表 | ★**复用是否造成"假通过"上升** → 若是则自动收紧 |

### 3.3 与 T2 语义缓存升 L2 的关系（★任务书要求说明）

| 维度 | **T2 语义缓存（L1 层实现）** | **T3 调用精简器（L3 层决策器）** |
|---|---|---|
| 架构位置 | L1 数据感知 | L3 决策协同 |
| 处理对象 | **单条 prompt** 与历史 prompt 的**语义相似** | **调用链 / 调用序列**（时间窗、谱系、失败历史） |
| 决策粒度 | 一次调用：**返回 / 不返回** | 一串调用：**复用 / 新发 / 退避 / 合并** |
| 核心算法 | 余弦相似度 ≥ 阈值 | 幂等白名单 + TTL + 失败计数 + 链结构识别 |
| 状态 | 无状态（单条比对） | **有状态**（跨调用、跨轮次、跨失败） |
| 处理的问题形态 | "**同一条问题问了两次**" | "**为同一个目标问了一串**" |
| 首期范围 | 只放行 `origin=user_query` | 只做观测 + 建议 |

**协同而非重叠**：
* L3 判定"这条调用**可以复用**"后，**仍会先过 L1 做语义比对**拿相似度与置信度 —— 即 **L3 是决策者，L1 是证据提供者**；
* 反过来 L1 命中（L2 生效）时，**不经过 L3**（单条已经能解决，无需链级决策）；
* 两者叠加顺序：`L3 决策 → (若决定"新发") → L1 查表 → (命中则返回) → 渠道调用`。

★**一句话区分**：**L1 管"内容像不像"，L3 管"这条调用该不该发"。**

## 四、安全机制

| # | 机制 | 规则 |
|---|---|---|
| S1 | **非幂等任务不做结果复用** | §2.2 白名单；白名单**外**一律视为非幂等（**默认拒绝**，不是默认放行） |
| S2 | **复用必须过时效校验（TTL）** | 默认 600s；TTL 外一律重新调用 |
| S3 | **失败退避必须有最大退避时间** | 硬上限 900s；到期强制放行一次探测，防止永久熔断 |
| S4 | **不复用"被否定过"的结果** | 有 `feedback=rejected` 或用户重问标记 → 该条目 `invalidated` |
| S5 | **决策失败必须静默降级为"新发"** | L3 任何异常 → `action="new"`，绝不影响主链路（与 `call_recorder` 同一纪律） |
| S6 | **不改变既有渠道策略** | 退避是"跳过一次调用"，**不是**"修改渠道池/熔断器状态"—— 后者是 `PulseLung` 职责，避免双写冲突 |
| S7 | **可观测不可省** | 每次决策都落盘 `decision` 字段；无观测的"省调用"无法验收 |
| S8 | **复用结果不得进入训练集** | 与 L4 铁律一致（防自我蒸馏退化螺旋）；复用命中单独标记，训练时排除 |

## 五、灰度策略：观测级 → 建议级 → 决策级

| 阶段 | 名称 | 行为 | 开关 | 判定门槛 |
|---|---|---|---|---|
| **G1** | **观测级** | 只记录"若按规则会怎样"（会复用/会退避/会合并），**不改任何调用行为** | `ENABLE_L3_CALL_REDUCER_OBSERVE=True` | 采集 ≥3 天：复用候选率、退避触发率、误判率基线 |
| **G2** | **建议级** | 决策写入日志与留存标记，**仍不拦截**；离线审计"若执行会省多少、会错多少" | `ENABLE_L3_CALL_REDUCER_ADVISE=True` | 复用候选的**离线准确率 ≥99%**（抽样 ≥200 例） |
| **G3** | **决策级（分项放行）** | 按**功能分项**独立灰度，**不做一次性全开** | 见下 | 各项独立门槛 |
| G3-a | 失败退避（**风险最低**） | 仅可重试类失败，硬上限 900s | `ENABLE_L3_BACKOFF=True` | 无用户可见异常 ≥3 天 |
| G3-b | 结果复用（风险中） | 仅幂等白名单 + TTL + 置信度 | `ENABLE_L3_REUSE=True` + `L3_REUSE_RATIO` | 复用准确率 ≥99%；5%→20%→50%→100% |
| G3-c | 追问链合并（风险高） | **本设计不启动**，需专项评估 | `ENABLE_LLM_CALL_BATCH_MERGE=False` | 另立批次 |

★**灰度原则（与 T2 一致）**：**先观测、后建议、再决策；风险低的分项先放行；每一步都能"关开关即回退"。**

## 六、监控指标

| 指标 | 定义 | 目标 | 落盘 |
|---|---|---|---|
| **复用率** | `reuse 决策数 / 总调用数` | 观测 → 目标 ≥18%（对齐 T2） | `data/llm_traces/`（`decision` 字段） |
| **退避次数** | 触发熔断的调用数 | 观测；**持续为 0 也要报**（防止"判据恒假"，铁律 #25） | 同上 |
| **合并次数** | 追问链合并成功次数 | 延后（G3-c 未启动） | — |
| **节省调用数** | `reuse + backoff` 实际拦下的调用数 | ≥18% 的 `user_query` 调用 | 同上 |
| **误判率** | 复用后用户重问 / 显式否定 / 离线审计不一致 | **<1%** | `record_feedback` 旁路 + 离线审计 |
| **退避误伤率** | 退避后探测即成功（说明本不该退避）的比例 | <5% | 探测记录 |

★**验收纪律**：指标必须**同时报"分子/分母"**，不接受只报比例 —— 第42批教训（`effectiveness=1.0` 是 0/0 除法的产物，62 条虚假满分）。

## 七、风险评估与缓解

| # | 风险 | 等级 | 影响 | 缓解 |
|---|---|---|---|---|
| R1 | **误复用非幂等调用** | 🔴 高 | 用户收到陈旧/错误答案 | 白名单默认拒绝（S1）+ TTL（S2）+ 观测级先行（G1/G2） |
| R2 | **退避掩盖真问题** | 🟠 中 | 问题不再被发现 | 硬上限 900s（S3）+ 退避必留痕 + 监控"退避次数恒 0 也报" |
| R3 | **与既有渠道熔断双写冲突** | 🟠 中 | 状态不一致 / 死锁 | S6：L3 只"跳过本次调用"，不写渠道状态 |
| R4 | **省下的调用让依赖度指标"变好看"但无实益** | 🟠 中 | 指标游戏 | ★与第43批判断绑定：**最高杠杆是"让补丁真正生效"，不是省调用**；L3 收益必须与 `patch_quality` **联合看** |
| R5 | **决策本身的开销超过收益** | 🟡 低 | 引入延迟 | D1/D2 用哈希（O(1)）；D3 复用 T2 缓存结果，不重复编码 |
| R6 | **无观测就上线** | 🟠 中 | 无法验收、无法回滚 | S7：`decision` 字段强制；G1 观测期不足 3 天不得进 G3 |
| R7 | **复用结果进训练集** | 🟠 中 | 自我蒸馏退化 | S8 + 复用 L4 `model_self_updater.training_guard` 的既有拦截 |
